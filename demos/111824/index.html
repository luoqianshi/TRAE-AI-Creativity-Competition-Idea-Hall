发现一个被忽视的浪费

想解决什么问题

缓存静默失效

DeepSeek / OpenAI / Anthropic 都支持 Prompt Caching，但大量"非语义性"结构差异 （换行符、JSON 键序、消息顺序）会让缓存静默失效，用户白白多花 API 费用却毫不知情。

为什么会想到做这个

从一张超预期的账单开始

深度使用 DeepSeek / Claude Code 时发现 API 账单远超预期。排查后震惊地发现根因是缓存命中率几乎为 0—— 不是模型贵，而是请求"长得不够像"。进一步研究发现这是普遍问题，但无工具能自动修复。

大概是什么产品

HTTP 透明代理 + 可视化诊断工具

一个轻量 HTTP 透明代理，插在 AI 框架与模型 API 之间，自动优化消息结构最大化缓存命中； 配套可视化诊断工具，让用户看到"为什么没命中"并定位到具体 token。

pip install poptimize → popt run -- claude
// 问题的本质：前缀缓存块（每块 128 tokens）
稳定前缀（命中） padding 补齐 可变区（每次不同）

缓存命中只取决于一件事：前缀中跨请求字节不变的完整块数。 一个字节差异 → 该块及之后全部 miss。popt 做的就是扩大绿色区域、消除意外位移。

变异类型 示例 为什么 miss 严重度
换行符 "hi\r\n" vs "hi\n" 字节不同 → 块内差异 MAJOR
JSON 键序 {"a":1,"b":2} vs {"b":2,"a":1} token 序列不同 MAJOR
消息顺序 system 在第 0 位 vs 第 3 位 整段前缀变化 CRITICAL
