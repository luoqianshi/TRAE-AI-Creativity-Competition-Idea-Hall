1 创意名称 & 介绍

创意名称：一阅了之 AI 阅卷

想解决什么问题：

中小学教师每天需要批改成百上千份试卷，重复性劳动强度大、耗时长、评分标准难以统一。现有阅卷系统虽然数字化但仍是"人眼+手动输入"模式，效率瓶颈明显。

为什么会想到做这个：

团队成员中有在职教师亲属，亲眼目睹了期中、期末考试后连续数天熬夜批改试卷的辛苦。同时，大语言模型和视觉 AI 的快速发展让我们意识到——通过截图 + AI 视觉理解，完全可以实现"看卷给分"的自动化闭环。

产品形态：桌面端应用（Windows .exe），通过 AI 视觉 API 实现批量阅卷自动化。

🎯

2 目标用户 & 痛点

面向用户：

  • 中小学教师 — 尤其承担语文、数学、英语等大量主观题阅卷工作的教师
  • 教育培训机构 — 需要批量批改学员作业、模拟试卷的教培老师
  • 考试组织方 — 学校教务处、区县教研室等统一阅卷场景

使用场景：

  • 期中/期末考试后，老师需要批改数百份试卷
  • 日常单元测验，老师希望在课堂上快速出分讲评
  • 教培机构模拟考试后，需要短时间内完成大量阅卷
  • 线上教学平台已有答题卡图片，需要自动识别给分

当前痛点：

  • 耗时巨大：一位老师批改50份语文作文平均需要4-6小时
  • 标准不一：不同老师评分标准不同，同一老师不同时间评分也不一致
  • 身心疲惫：长时间专注阅卷导致视觉疲劳、颈椎问题，且容易出现漏判、错判
  • 反馈滞后：阅卷周期长，学生无法及时得到反馈，教学时效性差
  • 数据孤岛：阅卷结果散落在各个系统中，难以统一分析学情

关键特性：

  • ⚡ 批量自动化：设置好批改份数和每批数量，全自动循环阅卷，无需人工干预
  • 🎯 灵活选取：支持元素选择器（CSS）和拖拽框选两种方式定位答题区域
  • 🔌 多模型兼容：兼容 OpenAI 协议的大模型 API（通义千问、DeepSeek、智谱等）
  • 📝 自定义标准：可配置学段、学科、阅卷标准（评分细则），AI 严格按照标准评分

3 价值与意义

📈 效率提升

  • 阅卷速度提升 5~10 倍：原来需要 4 小时的阅卷任务，现可在 30~60 分钟内完成
  • 7×24 小时 不间断批改，老师下班后应用可继续运行
  • 支持 几百份 试卷的批量处理，一次设置即可自动完成

🎯 评分标准化

  • AI 严格按照预设评分标准打分，消除不同老师间的主观差异
  • 同一标准贯穿所有试卷，确保 公平公正
  • 每次评分附带 评分理由，可追溯、可复核

🌱 社会价值

  • 将教师从重复机械的劳动中解放出来，回归教学本质——备课、辅导、教研
  • 缩短阅卷周期，学生 及时获得反馈，提升学习效果
  • 普惠教育：农村及欠发达地区学校的教师同样能享受到 AI 辅助阅卷的便利
  • 数字化阅卷数据可沉淀为 学情分析 的基础，辅助教学决策

💼 商业价值

  • 面向学校、教培机构提供 卡密授权 的 SaaS 模式
  • 低门槛：用户只需有浏览器和 AI API Key 即可使用
  • 可扩展：未来可接入更多 AI 模型，支持更多科目和题型
🔧

— 技术实现亮点

  • Playwright CDP 控制：通过 Chrome DevTools Protocol 直接连接已有浏览器，无需注入脚本
  • 视觉大模型评分：利用多模态 AI 直接"看懂"答题卡图片，输出结构化评分结果（JSON）
  • 智能选择器：动态生成 CSS 选择器，支持元素拾取和区域框选两种截图模式
  • PyWebView 桌面 UI：HTML + CSS + JS 构建现代界面，PyWebView 封装为原生桌面应用
  • 离线授权体系：硬件指纹绑定 + 心跳验证 + 文件完整性校验，打击软件盗版
