需求背景

业务背景

企业基层员工在日常工作中频繁与直属领导、跨部门负责人沟通，但缺乏系统化的工具来记录、分析领导的沟通模式与情绪倾向。当前员工只能依靠主观经验"猜"领导意图，导致汇报材料反复修改、任务方向偏差、频繁挨批。语音作为领导沟通的主要载体，蕴含大量非文字信息——语速变化、停顿节奏、语调起伏、用词偏好——这些信息若能被结构化提取，将大幅降低沟通摩擦成本。

用户痛点

痛点一：主观解读偏差

员工对同一条语音反馈的理解差异巨大，新人尤其容易误读领导的"客气话"与"真实不满"，导致交付物方向错误。

痛点二：多领导风格混淆

在矩阵式组织中，员工常向多位领导汇报。每位领导的沟通风格、决策偏好、情绪触发点各不相同，员工难以建立清晰的"领导档案"。

痛点三：情绪信号被忽略

文字转写丢失了语调、停顿、重音等关键情绪线索。领导说"挺好的"时，语调的细微差别可能意味着"需要大改"或"基本满意"。

痛点四：反复修改成本高

因理解偏差导致的返工，平均每次消耗 2–4 小时。频繁返工不仅影响效率，还加剧职场焦虑与心理压力。

不解决的后果

若继续依赖人工经验解读，基层员工的沟通失误率将维持在高位，团队整体执行效率受限。对企业而言，高返工率意味着人力成本浪费；对员工个人而言，长期处于"猜不准"的状态会导致职业倦怠、离职倾向上升。市场上尚无专门针对"领导沟通分析"这一细分场景的职场工具，存在明确的空白窗口。

证据强度标注：上述痛点基于用户访谈假设 [PM hypothesis]，需在 MVP 阶段通过用户调研验证痛点严重度排序。

核心使用场景

  1. 会议复盘：线上/线下会议结束后，上传录音，系统自动区分发言人、标记领导发言片段、生成情绪趋势图。
  2. 语音反馈解读：收到领导单独语音消息后，上传分析，获取情绪评级与意图预判。
  3. 汇报前准备：撰写工作汇报或项目方案前，查看目标领导的画像与偏好，调整汇报结构、措辞与详略。
  4. 模糊任务拆解：被领导临时布置模糊任务时，结合历史沟通数据，推测领导的真实期望与验收标准。

使用前提

  • 用户拥有可上传的会议录音或语音消息文件（支持 mp3、m4a、wav 格式）。
  • 录音质量满足基本识别要求：采样率 ≥ 16kHz，信噪比可接受（非嘈杂环境）。
  • 用户已授权麦克风/文件读取权限（微信小程序标准权限）。

产品定位

不做通用的"录音转文字"工具，而是聚焦"领导沟通分析"这一垂直场景。核心差异点在于：区分不同领导的声线，建立个人化的沟通档案，并基于档案给出可执行的汇报建议。

差异化机会

  • 声线区分 + 领导档案：现有竞品均未提供"为特定领导建立长期档案"的能力，这是核心壁垒。
  • 意图预判 + 行动建议：不仅告诉用户"领导不高兴"，还要告诉用户"下一步怎么改"。
  • 微信小程序载体：降低使用门槛，无需下载独立 App，贴合微信办公生态。
结论：市场上尚无直接竞品，存在 6–12 个月的窗口期。核心壁垒在于用户持续沉淀的领导档案数据，而非单次转写能力。

模块详细设计

5.1 录音上传模块

上传页原型

页面布局：顶部导航栏（返回 + 标题"上传录音"）；中部大区域为上传入口区，包含三个并列入口：① 从微信聊天选择 ② 从手机本地选择 ③ 立即录音；底部为最近上传记录快捷列表。

业务逻辑：

  • 文件格式校验：仅接受 mp3、m4a、wav，其他格式提示"暂不支持该格式，请转换后重试"。
  • 时长限制：单次上传 ≤ 60 分钟，超限提示"音频过长，建议裁剪至 1 小时内以提升分析速度"。
  • 大小限制：单文件 ≤ 500MB，超限提示压缩或分段上传。
  • 实时录音：最长支持 30 分钟连续录音，后台自动保存为 m4a。

交互逻辑：点击上传入口 → 拉起微信文件选择器/录音界面 → 选择/录制完成后 → 进入"分析中"页面（显示进度条与预计剩余时间）→ 分析完成后自动跳转结果页。

边界与异常：网络中断时暂停上传，恢复后自动续传；分析服务繁忙时进入排队状态，提示"当前排队 N 人，预计等待 M 分钟"。

5.2 声线区分模块

声线标记页原型

业务逻辑：

  • 系统自动将录音切分为发言片段，按声线聚类为 Speaker A、Speaker B……
  • 用户需手动标记哪个 Speaker 是"领导"，可设置领导姓名、职位、部门。
  • 同一领导的历史声纹数据自动关联，后续录音若匹配到已知声纹，自动标注该领导。
  • 声纹匹配置信度低于 70% 时，提示用户确认身份，避免误判。

规则约束：单条录音最多识别 8 位不同发言人；超过 8 人时，系统提示"发言人数过多，建议分段上传"。

5.3 语音转写模块

业务逻辑：仅转写被标记为"领导"的发言人内容，过滤其他无关发言（降低噪音）。转写结果按时间轴展示，支持点击文字跳转对应音频位置播放。关键词自动高亮（如"但是""不过""需要改"等转折/否定词）。

交互逻辑：用户点击某句转写文字 → 底部弹出迷你播放器，从该句起始时间播放 → 播放时对应文字高亮跟随。

5.4 情绪识别模块

业务逻辑：基于声学特征（基频、语速、能量、停顿模式）与文本特征（否定词、程度副词、命令句式）进行多模态融合分析。输出维度包括：

  • 整体情绪标签：满意 / 中性 / 不满 / 愤怒（四分类）。
  • 情绪置信度：0–100%，低于 60% 时标注"结果不确定，建议结合上下文判断"。
  • 情绪趋势图：按时间轴展示录音过程中领导情绪的波动曲线。
  • 关键情绪节点：自动标记情绪发生剧烈变化的时间点，附前后文摘要。

5.5 领导画像模块

画像页原型

画像组成：

  • 沟通风格雷达图：五个维度——直接性、细节关注度、情绪外露度、决策速度、反馈频率。
  • 高频词汇云：该领导最常使用的词汇/短语（排除通用词后），字号大小代表使用频率。
  • 情绪分布饼图：历史录音中各情绪标签的占比统计。
  • 决策偏好标签：基于历史数据自动推断的标签，如"数据驱动型""结果导向型""过程管控型"。
  • 敏感词/雷区提示：该领导历史上表达不满时高频出现的触发词或话题。

5.6 意图预判模块

业务逻辑：将当前录音的转写文本、情绪分析结果，与该领导画像中的历史模式进行比对。若当前沟通模式与历史上"满意"场景相似度高，则输出"倾向满意"；若与"不满"场景相似度高，则输出"存在风险"并附具体风险点。

输出格式：

风险等级：中风险

核心判断：领导对当前方案的方向基本认可，但对执行细节和交付时间存在顾虑。

依据：① 情绪趋势在讨论"时间节点"时出现明显下滑；② 使用了 3 次"但是"转折；③ 历史画像显示该领导对"延期"话题敏感度极高。

建议行动：补充详细排期表，预留缓冲时间，下次汇报优先展示时间节点。

5.7 汇报建议模块

业务逻辑：用户选择目标领导 + 汇报类型（周报/项目方案/问题同步）后，系统基于该领导画像生成定制化建议。建议包括：

  • 结构建议：该领导偏好的汇报结构（如"结论先行型""背景铺垫型"）。
  • 措辞建议：推荐使用的表达方式与需避免的表达陷阱。
  • 详略建议：该领导关注的核心数据/细节点，以及可简略带过的部分。
  • 模板生成：一键生成适配该领导的汇报模板（付费会员功能）。

评估体系

离线评估

  • 标准样本：收集 200+ 条真实职场录音（覆盖不同行业、职级、场景），人工标注说话人身份、情绪标签、意图判断。
  • 边界样本：刻意收集情绪模糊、多人同时说话、口音重、音质差的困难样本，测试模型下限。
  • 回归样本：每次模型迭代后，在固定回归集上验证，确保新模型不劣化旧能力。

人工审核

  • 审核员：3 名有 5 年以上职场经验的产品/运营人员。
  • 审核维度：情绪标签合理性、意图预判可信度、汇报建议实用性。
  • 一致性机制：双人独立审核，分歧率 > 20% 时引入第三人仲裁。

在线反馈

  • 行为指标：分析结果页停留时长、建议复制率、报告分享率。
  • 质量反馈：每份报告底部提供 thumbs up/down，差评需选择原因标签（情绪判断错/意图预判不准/建议没用/其他）。
  • 效率指标：从上传到出结果的平均耗时、用户重试分析的频率。

降级机制

  • 低置信度提示：情绪识别置信度 < 60% 时，不输出明确标签，改为"情绪复杂，建议结合上下文判断"。
  • 声线区分失败：若录音质量过差或人数过多导致区分失败，提示用户手动标记说话人身份。
  • 服务不可用：AI 分析服务故障时，仅提供基础转写功能，情绪与意图分析显示"暂时无法分析，请稍后重试"。
  • 人工复核入口：所有 AI 分析结果旁提供"我觉得不对"按钮，用户可提交修正意见，用于模型迭代。

迭代计划

MVP 阶段（第 1–2 月）

  • 核心闭环：录音上传 → 声线区分 → 转写 → 情绪识别 → 报告输出。
  • 支持 1 位领导的单条录音分析，暂不建立长期画像。
  • 免费使用，收集用户反馈与 bad case。
  • 目标：验证用户是否愿意上传录音、分析结果是否有用。

Beta 阶段（第 3–4 月）

  • 上线领导画像功能：聚合历史数据，生成雷达图与词汇云。
  • 上线意图预判与汇报建议。

风险与依赖

技术依赖

  • 语音识别引擎（ASR）：可选用讯飞、阿里云、腾讯云等第三方 API，或基于开源 Whisper 模型自建。
  • 声线区分模型：开源方案包括 pyannote.audio、Resemblyzer，需评估自研与接入的成本差异。
  • 情绪识别模型：需自研或微调多模态模型（声学 + 文本），暂无成熟第三方 API 可直接满足"领导情绪"这一细分场景。
