为什么不挑食

当下主流 Coding Agent 普遍"挑食"：

  • 挑模型：绑定自家模型，或仅支持少数厂商，换模型等同于换工具。
  • 挑场景：简单问题强行用"深度推理"，白耗 token；复杂任务用"快速模式"，又难以胜任。
  • 挑任务：工具链残缺，能读不能改、能改不能搜、能搜不能跑。
  • 过度设计：堆砌 sub-agent、MCP 等复杂机制，实际承担核心任务的往往只是一个工具。

产品定位开源 CLI

panda 采用 Go 语言编写，依赖非常少，TUI 采用手搓的框架（[fasttui](https://github.com/yeeaiclub/fasttui)）。

我们要做一只"不挑食的熊猫"：模型自由、模式可调、工具齐备。

灵感来自 pi-mono（极简）与 oh-my-pi（极致工具效率）的碰撞。真正的"开发者主权"，是让工程师自己决定用哪个模型、花多少 token、跑哪条工具链——而不是被某家 Agent 绑架。

使用场景

模型自由切换

同一个项目里，写代码用 GLM（便宜量大），复杂推理用 MiniMax（深度强），/model 一键切。

模式按需加速

日常问答用 fast（32 轮工具，省 token），中等任务用 normal（64 轮，平衡），长链路重构用 complex（128 轮，深度执行）。

全工具链一气呵成

read → search → edit → bash → fetch，一只在手，全部搞定。

当前痛点

  • 模型锁定焦虑：用 Cursor 只能用其内置模型，用某 Agent 就要买其订阅。
  • 模式单一：所有 Coding Agent 似乎只有一种"深度模式"，简单任务空转 token。
  • 工具残缺：很多 Agent 只能生成代码片段，不能直接 edit、不能跑 bash、不能 fetch 文档。
  • IDE 臃肿：插件式 Agent 装多了 IDE 变慢，不如一个轻量 CLI 来得直接。
