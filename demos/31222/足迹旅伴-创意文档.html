The Problem

我们做攻略时 其实是在 重复三件事

01

信息在多个 App 间跳转

攻略平台、地图软件、笔记应用。我们在不同的应用间来回切换，复制粘贴，整合一份完整的行程。

02

路线与预算反复调整

改一个打卡点的顺序，可能要重算全部路线和时间。手动规划常常绕路、超时、超预算。

03

记录与分享止于相册

旅行中拍了大量照片，回来后散落在相册，难以串联成完整的回忆。分享给朋友，也只是一串图片。

The Solution

一个小程序，
覆盖旅行的全部阶段

从出发前告诉你去哪里、怎么去，到旅途中自动记录你的足迹，再到回来后把记忆整理成可分享的故事。

Three Pillars

AI ROUTE PLANNING

告诉 AI 你想去哪个城市、玩几天、预算多少、偏好什么类型的体验。几秒钟后，一份带地图的路线就生成了。你可以继续调整，或者直接使用。

02
TRAVEL CHECK-IN

旅行打卡记录

在旅途中，一键拍照打卡。小程序自动记录你所在的位置、到达时间。照片不再是相册里的一堆文件，而是带着时间和地点的记忆节点。

拍照 + GPS 定位 + 时间戳，自动完成

地图 + 照片 + 时间线，自动排版成分享卡片

Technology

技术实现

层级 技术选型 说明
前端 微信小程序 + 腾讯地图 SDK 地图渲染、定位、UI 交互
后端 Node.js / Python 轻量服务 转发请求、调用大模型、缓存路线数据
AI 模型 主流大语言模型 API 根据用户输入生成结构化路线 JSON
数据源 腾讯地图 API + 人工标注 POI 精选城市用人工标注保证初期推荐质量
存储 小程序本地存储 + 轻量云数据库 用户打卡记录和行程数据
DATA FORMAT

AI 路线数据格式

AI 返回结构化的 JSON 数组，每个打卡点包含：地点名称、经纬度、到达时间、停留时长、简介、推荐理由、预估花费。前端拿到后可直接在地图上渲染。

FALLBACK

规则引擎兜底

当 AI 调用失败、超时、或返回异常格式时，本地规则引擎快速返回一条保底路线。确保用户在任何情况下都能看到结果，不会卡在空白页面。

Risks

风险，
与对应的策略

AI 推荐质量不稳定

大模型可能推荐已关门的店铺或不合理的路线。

→ 初期精选城市使用人工标注数据，AI 结果做字段校验和兜底规则

数据来源依赖地图 API

免费额度用完后会产生费用，成本可能失控。

→ MVP 阶段限制在少数热门城市，用户量小成本可控

功能太多做不完

大赛有时间限制，贪多容易烂尾。

→ 严格执行 MVP 优先级，第一阶段只保留 4 个核心功能

用户冷启动困难

小程序天然难获得流量。

→ 设计 1-2 个明确的冷启动渠道，不以用户量作为考核指标
