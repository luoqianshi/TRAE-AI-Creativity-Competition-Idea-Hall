Core Original Model

OpenRhythm Engine 开律叙事引擎

追忆节奏引擎 · 网文爽点编排模型。它把“读者为什么继续看下一章”拆成可设计、可检测、可增强的叙事脉冲。

不是写作模板，而是追读控制系统

OpenRhythm 不替作者决定怎么写，而是把章节追读信号可视化：有没有信息差、冲突是否有效、爆点有没有过早释放、反馈是否分层、收益是否回收。作者保留最终判断。

  • 把章节爽点从经验判断变成可视化指标。
  • 把连载节奏从事后返工变成写前提醒。
  • 把作者个人手感沉淀成可复用、可反驳、可修订的创作资产。

Why IDE

长篇网文不是一篇文章，而是一个复杂工程

作者真正需要的不是更多零散文本，而是一套能管理项目、记忆、节奏、校验和发布风险的创作基础设施。它从小说起步，但天然可以扩展到短剧、视频脚本和 AI 视频分镜。

上下文分散

总纲、章纲、角色卡、世界观、伏笔、正文和平台规则散落在多个文档与聊天记录中。

连载节奏漂移

已写章节可能提前消费后续场景，爽点堆叠或断裂，导致剧情返工。

Prompt 无法沉淀

作者反复复制写作规则，缺少版本管理、变量注入和调用预览。

发稿检查低效

字数、敏感词、术语、角色一致性与平台合规仍依赖人工反复核对。

角色设定易跑偏

长篇中后期人物关系、能力边界、口癖和阵营状态很容易前后冲突。

AI 文字同质化

通用模型容易写出“像 AI 的小说”，缺少创作者自己的语感、节奏、偏好和不可替代的表达习惯。

多 Agent 易越权

没有权限体系时，AI 容易越权改核心设定、污染知识库或打乱创作者的个人流程。

Product System

从聊天助手升级为 AI 原生创作操作系统

AI 小说 IDE 把作者的方法、记忆、节奏和校验流程工程化，而不是替代作者做决定。

项目级小说工作台

打开一个小说项目，自动识别 core、kb、pipeline、chapters、skills、memory 等目录。左侧项目树，中间正文编辑器，右侧章纲、角色、世界观、伏笔与校验面板。

项目记忆中枢

维护角色、世界观、伏笔、时间线、势力关系、关键物件和平台规则。写作时按需召回相关上下文，减少反复喂资料。

Prompt 资产加载器

把写作 Skill 当作系统级资产管理，支持 System Prompt、Reference、变量注入、调用预览和版本记录。

章纲校准引擎

检测已写章节是否提前消费后续章纲，输出红、黄、绿三级冲突报告，解决长篇连载剧情漂移和大纲返工。

多 Agent 循环自进化系统

规划、草稿、润色、风格、校验、合规、伏笔和反馈 Agent 形成闭环。每次创作者确认、驳回或修改，系统都会沉淀为个人风格清单和流程规则，但最终控制权始终属于创作者。

Human-in-Control

创作者主导，AI 辅助，共同成长

所有 AI 能力默认是可选择的辅助层。创作者可以随时开启、关闭、采纳、驳回或改写建议，系统只记录经创作者确认的经验。

作者决策队列

AI 不直接接管正文，只把风险、机会和可选方案送到作者面前。每一条建议都需要作者明确表态。

Creator-Centered Evolution

多Agent循环自进化系统，以创作者为本

系统不追求把作者抹平成统一模板，而是在作者授权和确认的前提下学习个人表达，把“只属于这个作者的写法”变成可调用、可校验、可进化的资产。

01 INPUT

作品样本分析

读取创作者已确认可用的章节、改稿记录和风格偏好，只从授权样本中提炼叙事习惯、句式密度、转折方式、对话节奏和高频禁忌。

02 PROFILE

个人风格清单

生成“应该保持什么、应该避免什么、什么时候允许突破”的风格清单，区分硬规则、软偏好和实验项，避免把个人风格写成空泛标签。

03 LOOP

创作者反馈闭环

每次作者接受、重写、删除或批注，系统都会记录原因，形成下一轮 Agent 调用的约束，并把可复用经验返还给作者。

04 IDENTITY

反同质化保护

生成前先加载个人风格清单，生成后再由风格 Agent 检查“是否像作者本人”。AI 做放大器，不做替身。

采样从作者授权作品、改稿和批注中提取风格证据。
提炼生成句式、节奏、意象、冲突、对话和禁忌清单。
注入经作者确认后，将个人风格清单注入 Prompt 与 Agent 任务。
进化根据作者反馈更新规则，保持个人独特性持续增强。

Detail Engineering

严格的细节工程：让 AI 创作从“能生成”走向“可控、可追踪、可复用”

项目的技术优势不是堆 Agent 数量，而是用 harness engineer 工程和 Loop engineer工程，把权限、上下文、输出格式、反馈闭环和质量验收工程化。

harness engineer 工程

任务安全带工程

实施成果：为每个 Agent 定义输入包、可读范围、禁用动作、输出 Schema 和验收标准。分析型 Agent 默认不写文件、不调用外部工具，避免越权改设定和上下文污染。

Loop engineer工程

循环进化工程

实施成果：把“建议、作者反馈、风格归因、规则更新、下一轮提醒”做成闭环。系统记录每次修改背后的偏好证据，逐步形成作者专属风格模型。

Strict Detail Engineering

严格细节工程

实施成果：章节状态、字数、风险词、伏笔状态、章纲冲突、Prompt 版本和 Agent 输出都有结构化记录，方便复盘、回滚和持续优化。

Context Capsule

按任务组装最小上下文，避免一次性塞入无关资料。

Agent Harness

锁定职责、权限、工具、输出格式和拒绝条件。

Author Review

作者确认、驳回、重写和批注进入反馈队列。

Loop Memory

把反馈沉淀为风格规则、禁忌规则和流程经验。

Next Prompt

下一轮调用只注入作者确认过的个人风格和质量约束。

Architecture

把小说项目文件变成可调用的 AI 创作系统

核心不是“生成一段文字”，而是让每次写作都能读取正确上下文、调用正确 Prompt、经过正确校验。

小说项目
