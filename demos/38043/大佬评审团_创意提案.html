01 / 创意介绍

评审是个黑盒，我们把它打开

为什么输、差在哪、怎么改——参赛者理应拿到答案

每年数万个项目参赛，评委几分钟注意力换几句笼统评价。
"为什么输"全是猜——我们想把"大佬评委辩论一个项目"这个过程本身做成产品。

想解决什么问题：黑客松、创业大赛、路演活动的评审环节长期存在三个痛点——评委人力不足导致评审粗糙、评审标准主观随意、参赛者拿不到具体可改进的反馈。

为什么会想到做这个：我自己参加过几场黑客松，最深的感受是评审环节像个黑盒。后来观察各类大赛评审现场，发现真实评审其实是有"对抗"的——评委之间会争论、会为一个项目的亮点辩护、也会被另一个评委的质疑反驳倒。这个"辩论"过程才是评审价值最高的部分，但参赛者完全看不到。

大概是什么产品：一个网页应用。用户粘贴项目介绍/链接，90 秒内生成一份"大佬评审团评审报告"——模拟 8 位行业大佬从七个维度对项目做对抗式评审，输出评分、亮点、红旗、改进建议，以及"评委之间的辩论实录"。

04 / 三 Agent 对抗

不是同一个模型换温度，是真辩论

Defender / Attacker / Auditor 三方博弈，争议分级触发多轮乒乓交锋

Defender · 辩护律师
为项目辩护
找出项目亮点，反驳 Attacker 的攻击。看到红旗会承认，看到盲区会补位。R2+ 轮看 Attacker 上轮攻击做针对性辩护。
Attacker · 公诉人
找红旗盲区
挑项目漏洞、夸大宣传、套壳风险、Vibe Coding 主导等红旗。R2+ 轮看 Defender 当轮辩护做二次攻击，乒乓式双向交锋。
Auditor · 质询官
高争议介入
当争议度 ≥ 0.7 时介入，质询双方立场，防止辩论陷入立场固化。输出质询记录，影响最终评分融合权重。
