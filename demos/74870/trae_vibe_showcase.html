想解决的问题

技术面试和项目复盘经常停留在“我做过什么”的描述层面，缺少对真实代码事实的追问。候选人、面试官和团队成员都需要一种更快、更可信的方式，把复杂仓库转化成可讨论、可验证的面试材料。

为什么想到做这个

灵感来自日常研发中反复出现的场景：接手陌生仓库、准备项目面试、做技术复盘时，需要花大量时间翻代码、整理架构和找关键证据。TRAE 的 Agent 工作流适合把这类重复理解过程自动化。

目标用户

1

准备技术面试的工程师希望把项目经历转化成更有深度的回答和追问准备。

2

面试官与技术负责人需要基于真实代码快速设计有区分度的问题。

3

新加入项目的成员需要快速理解仓库结构、关键链路和风险点。

当前痛点

A

问题泛泛而谈传统题库脱离候选人的真实项目，难以考察工程判断。

B

证据整理成本高手动翻仓库、截图、整理代码位置非常耗时。

C

复盘难以沉淀项目经验散落在代码、文档和口头表达中，不容易形成可复用资产。

产品形态

一个面向研发场景的 Web 系统 / AI Agent 工作台：输入代码仓库，输出仓库画像、证据链、面试题、追问路径和风险点摘要。

扫描仓库

识别路由、模型、配置、依赖和关键文件。

抽取证据

为每个发现生成稳定 evidence id 和代码引用。

规划问题

围绕接口设计、数据流、异常处理和扩展性生成问题。

形成展示

输出可复盘、可追问、可分享的面试准备材料。

效率价值

把“读仓库、找证据、组织问题”的过程从数小时压缩到分钟级，让候选人更快准备项目表达，让面试官更快构造贴近真实工作的技术讨论。

商业价值

可延展为面向企业招聘、内部晋升评审、项目交接和研发培训的智能工具，帮助团队把代码资产转化为人才评估和知识传承资产。

让面试不再只依赖记忆和套路，而是回到 真实代码、 真实证据 和真实工程判断。
