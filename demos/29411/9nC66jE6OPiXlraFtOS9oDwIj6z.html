FlowLink 连接的不是「关键词」和「接口文档」，而是企业里的流程、对象、指标、字段与系统能力。NL2SQL 擅长查数据，普通 API 搜索擅长找接口——企业能力调用却常受流程节点、权限与状态约束。FlowLink 用轻量业务本体注入流程语义，让开发者和智能体理解「业务动作」，而不只是匹配接口名称。

Approach

FlowLink 的方法：给 API 加上流程语义

它不是一个更大的接口搜索框，而是一层能把业务动作、流程节点和系统能力连起来的语义基础设施。

01

轻量级业务本体

用最小必要概念统一描述流程、活动、对象、指标、API 与字段，避免陷入庞大的本体工程。

02

流程语义图谱

表达业务如何运转：哪些活动先后发生，输入输出对象是什么，状态和规则如何变化。

03

API 能力图谱

把 API 文档变成可查询、可推理的能力结构，包括资源、方法、字段、导航关系与调用边界。

创意来源：传统 NL2SQL 解决「查数据」，普通 API 搜索解决「找接口」——而「审批采购订单」等活动还涉及流程节点与状态变更。FlowLink 通过跨域语义联接，让 AI 沿业务流程发现并编排 API 能力。

Architecture

打通业务本体、流程图谱与 API 能力图谱

FlowLink 从元数据接入开始，把 API 元数据与流程知识整理成图谱，再通过跨域语义联接生成调用计划。

1
元数据接入API 文档、流程文档、字段说明、业务规则
2
语义建模流程—对象—指标—字段—API 的统一表达
3
能力发现向量检索 + 图谱查询，从业务目标定位可用能力
4
调用编排生成 API 调用顺序、字段路径和解释依据
业务本体定义核心概念与关系
流程图谱描述业务链路与节点
API 图谱描述系统可调用能力

跨域语义联接

通过业务对象、实体类型、字段语义和导航关系，把“采购申请 → 审批 → 下单 → 收货”这样的流程语言，映射到具体 API 服务、资源、字段和调用路径。

输出结果不是一堆接口列表，而是一份可以解释、可以下钻、可以交给智能体执行的调用方案。

Use Cases

适合放在企业智能化改造的中间层

FlowLink 可以作为企业 API 接入大模型前的语义治理层，也可以作为智能体系统里的能力发现层。

“我要开发一个采购订单异常分析功能，需要调用哪些 API？”

系统返回采购订单服务、采购申请服务、供应商主数据服务、订单行项目资源，以及金额、状态、供应商、物料、日期等字段，并解释采购申请到采购订单的对象关联路径。
