核心架构设计

六大创新支柱，构建融合生态

从内核空间到用户态守护进程，每一层都经过精心设计，确保双生态无缝协同与系统级安全

🖥️

统一内核空间

单内核实例运行 Linux 与 Android 两大生态，所有进程共享 PID / NET / IPC 命名空间，消除容器虚拟化开销。

  • 全共享进程命名空间
  • cgroup 系统级资源统一调度
  • 零虚拟化开销，原生性能
⚙️

双 Init 共存

aether-init (PID 1) 统一协调 systemd 与 aosp-init，实现 Linux 服务与 Android 服务的并行初始化。

  • aether-init 智能协调器
  • systemd 管理 Linux 守护进程
  • aosp-init 管理 Android 服务链
💾

OverlayFS 统一视图

合并 /system 与 /usr 的文件系统视图，两边应用透明访问对方库文件、配置与数据目录。

  • lowerdir: /usr + /system
  • permLevel 权限级别挂载
  • 路径遍历防护与 TOCTOU 修复
🛡️

统一权限模型

Android Permission ↔ Linux Capability ↔ SELinux 三元映射，提供跨生态一致的权限管理体验。

  • Binder + D-Bus 双 API 接口
  • 默认拒绝 + 白名单策略引擎
  • 审计日志 chattr +a 不可篡改
👑

Root 可视化管理

四级 Root 权限分级管控，从临时授权到硬件物理确认，Wayland GUI 授权，全程审计追踪。

  • Wayland GUI 授权弹窗
  • 动态 PIN + TPM 硬件绑定
  • PAM 认证 + 60 秒超时回收
🧠

AI 辅助调度

sched_ext eBPF 调度器 + LSTM 模型预测，根据应用场景动态调整调度策略，优化能效比。

  • 7 种场景调度模式
  • LSTM 负载模式预测
  • 大小核智能分配

权限架构 · 三层模型

默认拒绝，白名单策略引擎

从内核态 BPF-LSM 钩子到用户态 GUI 授权，每一层都经过交叉审查确保安全

L1

内核态 BPF-LSM

内核安全模块钩子，拦截所有敏感系统调用，实现最低层的权限管控

task_alloc → 进程创建拦截
file_open → 文件访问控制
socket_create → 网络权限检查
capable → Capability 验证
mmap → 内存映射审计
bpf() → eBPF 程序加载限制
L2

三元映射层

Android Permission、Linux Capability、SELinux 域三者的智能映射与转换引擎

CAMERA → CAP_SYS_RAWIO
INTERNET → network domain
aether_android_t 域类型强制
neverallow 规则自动生成
白名单策略引擎 (默认拒绝)
SO_PEERCRED 调用者身份验证
L3

用户态服务层

GUI 授权界面 + 双生态 API 接口 + 不可篡改审计日志

IAetherPerm Binder 接口
org.aetheros.PermissionManager D-Bus
Wayland GUI 授权弹窗
SQLite 权限持久化存储
chattr +a 审计日志保护
JSONL 审计日志 (P3-3 规格)
Root 可视化 · 四级权限

透明可控的超级权限体验

从单次临时授权到硬件物理按键确认，每一级都有独立认证方式与审计策略

L1

临时 Root

单次操作授权，应用申请临时 Root 权限，操作完成或超时 60 秒后自动回收

Wayland GUI + PIN 验证
L2

会话 Root

登录会话期间有效，支持脚本执行与命令行操作，锁屏或退出会话自动失效

PAM 认证 + Wayland GUI
L3

系统 Root

系统级配置修改权限，需要设备 IP + 时间绑定的动态 PIN 二次确认 (防远程攻击)

动态 PIN + TPM 硬件绑定
L4

硬件 Root

最高权限等级，需物理按键确认 + TrustZone TA 验证，操作写入 OTP 区域不可撤销

物理按键 + TrustZone 确认

构建与开发流程

Windows 原生构建 · 多轮代码审查

从源码同步到镜像产出的完整流程，辅以系统化的交叉审查与修正机制

📦 构建流程 (v3.0)

  • repo sync → 同步 AOSP 15 源码 (约 100GB)
  • gen_config.py 生成白名单模式 .config
  • Linux 7.0.12 内核配置 + 交叉编译
  • aether_*.ko 内核模块编译与集成
  • 用户态 20+ 守护进程 (C/Rust) 编译
  • Android 框架层定制 (device/aether/aether_arm64)
  • Bazel 7.5.0 + Soong 联合构建
  • init.aether.rc → 定义服务启动顺序
  • 生成 system.img / vendor.img / boot.img
  • 最小集构建仅需白名单中 130+ 配置项
# Windows 原生构建示例 cd /d C:\CCC bash build_windows.sh # → 自动检测 LLVM/Clang/Make # → 产出 arch/arm64/boot/Image # → 产出版本 v2.0-20260621

🔍 交叉审查流程 (R1–R19)

  • P0 (致命): 互斥锁死锁、NULL 指针崩溃、Socket 0666 权限、GUI 失败自动允许
  • P1 (重大): neverallow 规则不完整、速率限制表溢出、TOCTOU 竞态
  • P2 (中等): 剪贴板数据未清零、信号处理不规范、sleep+poll 轮询
  • P3 (建议): 审计日志结构化、Wayland 协议 XML、Binder AIDL 接口
  • 内核驱动审查: 13 个子系统，覆盖 sched / perm / root / dmabuf / tee
  • 安全模块审查: BPF-LSM 钩子正确性、权限白名单覆盖率
  • 构建系统审查: Bazel BUILD 文件完整性、Kconfig/Makefile 依赖
  • 交叉验证: 同一问题在不同代码位置的一致性检查
  • 修复验证: 每处修改需通过编译、单元测试、集成测试三层验证
