01.

想解决什么问题

找工作时，90% 的人其实并不擅长"翻译"自己的经历。同一段工作，写成"负责 XX 业务"和"主导 XX 项目，季度 GMV 提升 37%"，HR 的筛选结果天差地别；跨行转岗的人，更是连目标岗位的 JD 关键词都识别不准。

市面上的"AI 简历助手"大多停留在句子润色层面——它们不知道 HR 在 10 秒内会先看什么、ATS 会过滤什么、哪些风险项会被一票否决。它们也不识别专业大类，所以一个医学博士的简历可能被塞进互联网黑话，一个工程师的经历可能被翻译成运营腔。

THE REAL GAP

简历优化的本质，不是"写得更好听"，
而是"让经历按 HR 的筛选顺序重新组织成可识别的证据"。

02.

为什么会想到做这个

我自己投过 200+ 简历，也帮数十位同学改过简历。发现一个反复出现的规律：

80% 的"被刷"，不是能力不够，而是经历没被翻译成 HR 视角的语言。有人有真本事却写成了职责清单，有人转行时不会解释 transferable skills，有人有空白期但不知道如何策略化包装。

我意识到这是一个工程问题，而不是写作问题。于是决定做一个真正"按 HR 筛选顺序体检 + 按目标岗位专业术语重写"的 Agent——不是另一个润色工具，而是一个能解释每一处改动为什么必要的优化系统。

MARGINALIA · 手记

"这个产品的灵感，来自一次真实的改简历经历：一位药学博士做过完整的临床协调、SOP 撰写、IRB 对接，但简历里只写了'负责临床事务'。

目标岗位是 Clinical Operation Specialist——HR 一眼看过去，看不到 protocol · IRB · SOP 任何一个关键词。

这不是她能力不够，是语言错位。OfferFlow 就是来修这个错位的。"

03.

大概是什么产品

基于 LangGraph 9 阶段工作流的 Web 应用，配合 Vue 3 前端。用户上传简历 PDF / DOCX + 粘贴目标 JD， 30 秒内输出：匹配度体检报告 → 重写简历 → 面试考点预测。全程 SSE 实时推送每个节点的处理状态。

04.

三大差异化特色

I
真 · HR 视角
先体检，再动手改

按"10 秒初筛 + 面试资格细筛"顺序识别硬门槛、关键词缺口、成果密度与风险项——而不是直接重写。

II
自修复校验
Fact-Check 闭环

校验节点比对原文，幻觉 / 造假 / 冗长会自动打回重写，最多 3 轮——保证不编造数据。

III
术语动态注入
领域自适应

LLM 判定专业大类（engineering / humanities / business / medical / arts ...），自动加载数据库术语词库——Prompt 里不写死任何行业。

PIPELINE · 9 STAGES LangGraph StateGraph self-healing loop

九个阶段。
一份可信简历。

整个流程不是一个线性 prompt，而是一个有状态、有回路、有护栏的状态机。 校验失败会自动打回上一阶段重写，最多 3 轮，直到满足 HR 审核标准。

NODE · 01 I

normalize_input

用 markitdown 把 PDF / DOCX 转成 LLM 友好的 Markdown。

NODE · 02 II

parse_resume

提取经历、技能、项目、教育；标记表达弱项与稳定性风险。

NODE · 03 III

parse_jd

提取核心职责、必备技能、加分项、高频关键词、隐含能力。

NODE · 04 · v2 NEW
IV

classify_profession ★

LLM 基于结构化简历输出 domain_code / confidence / rationale / detected_terms， 从 profession_domains 表动态加载启用中的专业大类。

→ engineering / humanities / business
→ medical / arts / interdisciplinary
→ fallback: other (通用模式)
NODE · 05 V

match_analysis

模拟 HR 初筛（10 秒）与细筛（面试资格），产出风险项与弥补策略。

NODE · 06 VI

generate_strategy

生成 Rewriting Plan：Summary 方向、经历排序、量化法则、术语植入。

NODE · 07 VII

rewrite_resume

按模块重塑：标题 / Summary / 经历 / 项目 / 技能 / 教育。

NODE · 08 · GUARDRAIL VIII

validate_result

三维交叉检查：真实性（防幻觉）/ 匹配度（JD+ATS）/ 质量（冗长、逻辑）。

↻ 失败打回 §06 · 最多 3 轮
NODE · 09 IX

format_output

输出完整优化包：重写简历 + Why 说明 + 匹配报告 + 面试盲点。

STATE

所有节点共享 ResumeOptimizerState TypedDict。

flow definition

从一个想法
到一份可信简历

整个工作流定义在 graph.py 中， 通过 LangGraph 的 StateGraph 把 9 个节点串成一条带回路的状态机。 校验节点的 is_valid 字段决定是继续向前还是打回重写。

已就绪 · 校验回路开启 · MemorySaver checkpointing
workflow/graph.py 
# LangGraph StateGraph · 9-stage closed loop
optimizer_app = StateGraph(
    state_schema=ResumeOptimizerState,
    checkpointer=MemorySaver(),
)

optimizer_app.add_node("normalize_input",     normalize_input)
optimizer_app.add_node("parse_resume",        parse_resume)
optimizer_app.add_node("parse_jd",             parse_jd)
optimizer_app.add_node("classify_profession",  node_classify_profession)
optimizer_app.add_node("match_analysis",       match_analysis)
optimizer_app.add_node("generate_strategy",    generate_strategy)
optimizer_app.add_node("rewrite_resume",       rewrite_resume)
optimizer_app.add_node("validate_result",      validate_result)
optimizer_app.add_node("format_output",        format_output)

optimizer_app.add_edge(START, "normalize_input")
optimizer_app.add_conditional_edges(
    "normalize_input",
    lambda s: ["parse_resume", "parse_jd"],
)
optimizer_app.add_edge("parse_resume", "classify_profession")
optimizer_app.add_edge("parse_jd",      "classify_profession")
optimizer_app.add_edge("classify_profession", "match_analysis")
optimizer_app.add_edge("match_analysis",      "generate_strategy")
optimizer_app.add_edge("generate_strategy",   "rewrite_resume")
optimizer_app.add_edge("rewrite_resume",     "validate_result")
optimizer_app.add_conditional_edges(
    "validate_result",
    # Self-healing loop
    lambda s: "generate_strategy" if s.is_valid is False else "format_output",
)
optimizer_app.add_edge("format_output", END)

§ 08 / 09

差异化与护栏
我们不做什么

一个产品的边界，
比它的能力更能定义它。

Principles Safety First Explainable

不编造、不夸大、不跨行乱套。

这些"不做"比"能做"更重要——它们是 OfferFlow 在 validate_result 节点强制执行的护栏， 也是这个产品与"AI 润色工具"最根本的区别。

GUARDRAIL · 01

绝不编造经历

不新增未提供的项目、不捏造工作时间、不虚构学历。 Fact-Check 节点会比对原文与重写版本，发现"幻觉"自动打回重写。

GUARDRAIL · 02

绝不夸大级别

不把"参与"改成"主导"、不把"初级经验"包装成"高级主导"。 允许把弱表达转为强表达，但事实层级必须保持一致。

GUARDRAIL · 03

绝不硬塞行业词

不把商业运营词塞进医学简历，不把工程术语塞进人文简历。 术语来源严格限定在 classify_profession 识别到的大类词库。

PRINCIPLE · 04

每一处改动都可追溯

交付物包含 Why it changed 说明，绑定 JD 关键词或风险项； 用户知道哪里改了、为什么改、哪些仍需自己补充。
