Section 01

项目总览

1.1 项目定位

"忆路相伴"是一款面向认知症（痴呆症）长者的智慧照护平台。平台以"数字疗法 + 智慧照护"为双核驱动，通过 AI 智能体、物联网感知、语音交互和数字化怀旧疗法，构建覆盖安全监护、认知干预、健康管理、亲情连接四大场景的全链路解决方案。产品采用双端模式——家属/护工小程序端与老人智能屏终端，兼顾照护效率与长者尊严。

"这个方案将'智慧助老'从一句口号变成了具体的、可执行的代码和功能，既照顾了老人的尊严与安全，也解决了院方的管理难题。"

1.2 核心痛点与解决思路

🔴 痛点一：安全风险高

老人易走失、跌倒、误食，存在严重安全隐患。认知症长者游走行为发生率高达 60%，跌倒风险是普通老人的 3 倍。

✅ 数字化围栏 + AI 行为异常监测（骨骼点隐私保护方案）

🔴 痛点二：沟通与情感缺失

语言能力退化、难以表达需求，容易产生焦虑和攻击性行为（BPSD）。60-90% 的认知症患者会出现 BPSD 症状。

✅ AI 语音交互 + 方言识别 + 数字化怀旧疗法（时光相册）

🔴 痛点三：护理记录繁琐

护工工作量大，难以实时记录老人的细微变化，导致照护质量难以量化和追溯。

✅ 语音录入日志 + 智能归类 + 自动化健康报表

🔴 痛点四：康复训练枯燥

传统认知训练难以坚持，缺乏趣味性和个性化，导致干预效果不佳。

✅ 游戏化认知训练 + AI 个性化难度调节 + 康复趋势图

1.3 全球市场背景

据 WHO（2025）数据，全球约有 5,700 万人患有痴呆症，预计到 2050 年将增至 1.52 亿。中国认知症患者已超 1,500 万，占全球近 1/4。数字疗法（DTx）领域，EndeavorRx（Akili Interactive）已获 FDA 批准，Cognito Therapeutics 的 Spectris（40Hz γ波视听刺激）获 FDA 突破性设备认定，BrainHQ（Posit Science）积累了 100+ 同行评审研究——非药物数字干预正成为全球养老产业的确定性趋势。

🌅

温暖陪伴者

如夕阳余晖般温暖而不刺眼，始终在侧，安静守护。非临床感、非幼稚化——专业而有温度。

🛡️

可信守护者

深潭般的沉稳与可靠，传递安全感和信赖感。每一个交互都经过安全设计的考量。

🌿

科技善行者

科技不可见但可感知——技术隐于温暖体验之后。以数字疗法延缓病情，用科技向善。

5.2 七大智能体详细设计

💬 语音陪伴智能体（Companion Agent）

🎙️

核心能力

方言识别（粤语/四川话/上海话/闽南话等）+ 拟人化对话 + 情绪感知 + 话题引导（怀旧/日常/天气/音乐）

🛡️

安全护栏

严禁医学建议；严禁承诺；检测到老人焦虑/激动时自动切换安抚模式并通知护工；所有对话本地处理优先

工具：讯飞方言 ASR API（云） / Whisper.cpp（端侧备选）、TTS 语音合成（温暖女声/男声可选）、情绪识别模型（语音韵律分析）

记忆：短期对话上下文（会话内）、长期偏好（老人喜欢的话题、音乐类型、家庭成员称呼）

🚨 行为异常监测智能体（Safety Monitor Agent）

👁️

核心能力

端侧 MediaPipe Pose 骨骼点提取（33关键点）→ 跌倒检测、长时间静止检测、游走路径分析、夜间离床频次统计

🔒

隐私保护

原始视频帧在端侧即时销毁，仅上传骨骼坐标序列；异常事件触发时加密保存 15 秒短视频，需双重授权才能查看

工具：MediaPipe BlazePose（端侧 NPU）、自定义跌倒分类器（加速度 + 姿态变化率）、蓝牙信标 RSSI 三角定位

📸 怀旧疗法智能体（Reminiscence Agent）

🖼️

核心能力

家属上传照片 → AI 自动标注年代/人物/场景 → 按时间线生成"时光故事" → 每日定时推送配乐幻灯片 → 老人语音互动"这是谁？"

📊

效果评估

记录老人观看时的情绪反应（面部表情分析）、互动频次、主动回忆成功率，生成怀旧疗法效果报告

工具：照片年代推理模型、人脸聚类（家庭相册自动分组）、老歌推荐算法（年代匹配）、情绪评估（观看反应分析）

科学依据：基于 Gui et al.(2026) AI 增强生活故事结构化方法 + Asano et al.(2026) 大屏幕团体 RT 减少 BPSD 方案

💊 用药提醒智能体（Medication Agent）

工作流（基于 VoltAgent Workflow + Human-in-the-Loop）：

Step 1: 校验用药计划（Zod Schema 验证剂量/时间/禁忌） ↓ Step 2: 到点触发 → 智能音箱语音播报："张奶奶，该吃降压药了" ↓ Step 3: 等待老人确认（语音"好的"/触摸屏幕按钮）—— timeout 5分钟 ↓ (未确认) Step 4: suspend() → 升级通知 → 值班护工人工介入 ↓ (确认) Step 5: 记录服药时间 → 写入用药日志（AES-256-GCM 加密 + 哈希链完整性校验）

📝 护理记录智能体（Care Logger Agent）

护工按住录音按钮口述 → ASR 转文字 → LLM 结构化提取（饮食/情绪/睡眠/排泄/活动）→ 自动填入健康档案对应字段 → 生成交班摘要。支持离线录音、WiFi 恢复后自动同步。

🎮 认知训练游戏智能体（Game Coach Agent）

根据老人 MMSE/MoCA 评估基线 + 日常游戏表现，自适应调节：切水果（手眼协调）、拼图（视觉空间）、找不同（注意力）、记忆翻牌（短期记忆）。后台生成康复趋势图，供医生参考。

🔔 告警通知智能体（Alert Agent）

三级递进升级链（Workflow 模式）：轻度异常（AI 标记）→ 中度异常（推送家属）→ 重度异常（推送护工+管理员）→ 紧急（声光全屏+短信+自动呼叫）。每次升级前执行 suspend() 等待上一级确认/超时。

5.5 可观测性

全链路 OpenTelemetry 追踪 + Pino 结构化日志。关键指标：智能体响应延迟（P50/P95）、ASR 识别准确率（分方言统计）、跌倒检测误报率/漏报率、用药提醒确认率、训练游戏完成率。异常检测规则：连续 3 次 ASR 失败 → 自动切换端侧模型；跌倒检测阈值动态调整（基于个体步态基线）。

安全与隐私架构

6.1 安全审查总览

经专项安全审查（Security Review），识别出 4 项 CRITICAL、4 项 HIGH、3 项 MEDIUM 级别的安全设计要点。以下为关键发现与对策：

6.2 关键安全发现与对策

级别编号领域威胁描述对策
CRITICAL C1 隐私架构 跌倒检测原始视频若传输至云端处理，每帧都是完整面部图像，违背"仅传输骨骼点"的隐私承诺 强制端侧姿态估计：MediaPipe BlazePose 在摄像头 NPU 上运行，逐帧提取骨骼点后立即丢弃原始帧；仅在上传异常事件时加密存储 15 秒短视频，访问需双重授权 + 审计日志
CRITICAL C2 合规 老人语音录音属于敏感个人信息（个保法第28条），需单独明示同意；认知症长者可能缺乏同意能力 监护人授权 + 本人异议权：建立同意管理模块，记录监护人对每种数据类型的授权；语音数据转录后自动删除原始录音；最长保留 30 天；实现"被遗忘权"API
CRITICAL C3 IoT 安全 蓝牙信标位置数据以明文传输，攻击者可读取/伪造信标 ID BLE 5.2 加密通道 + mTLS 网关：信标→网关使用 AES-CCM 加密连接；网关→云启用 mTLS 证书固定；信标加入需签名握手防伪造
CRITICAL C4 数据完整性 用药计划数据若仅做静态加密（如AES-CBC），攻击者可通过篡改密文块改变剂量/时间，导致致命不良事件 AES-256-GCM 认证加密 + 哈希链审计日志：每条用药记录使用 AEAD 加密（保证机密性+完整性）；每次变更生成 SHA-256 哈希链，防篡改可追溯
HIGH H1 访问控制 短视频文件未按老人隔离存储——护工可查看非自己负责老人的视频 单元级加密 + KMS 封装的 RBAC：每个老人的视频使用独立密钥加密；KMS 基于 RBAC 策略发放解密密钥；所有视频访问记录查看人+时间+原因
HIGH H2 数据跨境 调用讯飞/阿里 ASR API 时语音数据可能跨境传输，违反数据安全法 签署 DPA + 端侧 ASR 优先：与第三方 AI 供应商签署数据处理协议；优先使用 Whisper.cpp/PaddleSpeech 端侧识别；云 ASR 仅为未识别语句的备选，确保服务器位于中国大陆
HIGH H3 权限模型 四种角色（家属/护工/管理员/老人）无权限边界定义，存在越权风险 RBAC 矩阵（见下表）
HIGH H4 视频通话 WebRTC 未强制端到端加密，视频通话可能被中间人窃听 WebRTC E2EE + DTLS-SRTP：强制 Insertable Streams API 端到端加密；信令服务器仅做路由，不解密媒体流

7.2 核心数据流

【跌倒检测数据流】 摄像头(RTSP) → MediaPipe NPU 提取 33 骨骼关键点 → 丢弃原始帧 → 坐标序列 JSON → 本地跌倒分类器（TFLite） → (正常) 仅上传统计指标到云端 → (异常) 加密 15s 视频 + 骨骼序列 → 云存储 → 告警智能体触发通知 【语音交互数据流】 老人语音 → 端侧 VAD（语音活动检测） → 优先：端侧 Whisper.cpp ASR → (未识别) 加密上传云 ASR → 大模型 NLU → 本地 TTS 合成回复 → 原始语音转录后即删，不留存 【位置追踪数据流】 手环 BLE 广播 → 房间网关 RSSI 采集 → EMQX MQTT → 定位引擎（三角定位） → 电子围栏判断 → 正常轨迹写入 TimescaleDB / 越界触发告警

7.3 部署架构

采用私有化部署 + 边缘计算混合模式：每家养老院部署一台边缘网关服务器（运行 MediaPipe NPU 推理 + MQTT Broker + 本地缓存），确保断网情况下安全监测不中断。云端提供 AI 训练、数据备份、跨院数据分析和家属小程序服务。符合等保 2.0 三级要求。

商业与社会价值

9.1 社会价值

🤲

减轻护工负担

强调工具属性——不是为了监视老人，而是让护工少跑腿、少写字。语音录入日志可将文书工作时间减少 60%，让护工回归照护本身。

🧪

非药物干预

通过"数字疗法"延缓病情发展，减少精神类药物使用。符合国际推崇的"以人为本"养老理念，为医保减负提供新路径。

🏛️

政策契合

响应"十四五"健康老龄化规划、智慧养老产业发展行动计划。量化照护数据可为政府补贴发放提供客观依据。

Section 10

风险管理与项目治理

10.1 风险矩阵

风险概率影响缓解措施
隐私泄露事件中致命端侧处理优先、最小数据采集、定期渗透测试、安全事件响应预案
跌倒检测误报/漏报高严重多传感器融合、持续模型迭代、人工复核兜底
老人/家属接受度低中严重渐进式上线、家属引导培训、护工先行试用反馈
硬件供应链不稳定中中等多供应商策略、关键器件备货、纯软件备选方案
政策法规变化低中等法务持续跟踪、架构灵活适配、合规顾问团队

10.2 设计原则（Do's & Don'ts）

✅

Do（应当）

  • 端侧处理优先，云端仅为补充
  • 老人端字号 ≥28px，对比度 ≥7:1
  • 所有语音数据转录后即删
  • 用药记录使用 AEAD 认证加密
  • 告警三级递进，人机协同
  • 每个功能提供语音和触摸两种操作路径
  • 功能渐进开放，避免一次性过载
  • 定期进行安全渗透测试和隐私合规审计
❌

Don't（不应）

  • 原始视频流出端侧设备
  • 二级以上菜单层级
  • 低于 28px 的字体用于老人端
  • 纯图标无文字标签的按钮
  • AI 提供医学建议
  • 语音数据用于模型训练（除非明确授权）
  • 单一故障点——所有关键路径需冗余
  • 冷冰冰的临床感设计语言
