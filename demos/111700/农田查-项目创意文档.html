01
项目核心摘要

🌾 一句话介绍

农田查是一款面向广大种植户与基层农技推广人员的农业病虫草害智能诊断工具。覆盖7大类作物场景：① 粮食作物（小麦、水稻、玉米、大豆等）② 经济作物（棉花、花生、油菜、烟草等）③ 蔬菜（叶菜、茄果、瓜类、根茎等）④ 果树（苹果、梨、葡萄、柑橘、桃等）⑤ 中药材（人参、三七、金银花、枸杞等）⑥ 园林绿地/非耕地（公园、绿化、路边杂草等）⑦ 家庭种植/阳台园艺（盆栽蔬菜、观赏花卉、窗台果树等）。在"双层异构多模型交叉校验"原创AI架构基础上，进一步实现作物品种识别 + 生长阶段感知 + 多杂草/多病虫同时识别 + 地域用药习惯匹配 + 用药安全优先的五维决策链。拍照即可输出综合考虑作物安全性、草龄/虫龄、当地用药习惯、作用机理互补的完整防治方案，助力科学用药，减少农药不合理施用。

🔥 项目解决的核心痛点

当前农业生产场景下，广大种植户在田间病虫草害识别与防治方面面临多重困境：

  • 识别只看病虫草、不识别作物：通用AI工具只识别病虫草本身，完全忽略"这是什么作物"，而同一除草剂/杀虫剂在不同作物上的使用差异极大，直接输出方案极易造成药害。
  • 杂草场景识别困难：田间一张照片往往包含作物+多种杂草，现有工具可能难以同时准确识别所有种类，导致农户漏防部分恶性杂草，降低整体防除效果。
  • 缺乏生长周期概念：作物苗期、拔节期、花期、灌浆期对农药耐受度完全不同。缺乏生长阶段判断的用药建议极易导致苗期药害或农残超标。
  • 忽略地域用药习惯：不同省份、不同产区对同一种病虫草害的用药选择与抗药性差异很大（如华北麦田 vs 江南稻田），"一刀切"的方案既不高效也不安全。
  • 照片质量直接影响识别准确度：农户拍摄的照片常常出现光线昏暗、画面模糊、杂草群落过密不易分辨、病害叶片局部特写缺少作物整体参照等问题，AI据此输出结果极易误判，用户却被"自动忽略"，得不到任何提示。
  • 植保方案缺少专业校验：现有AI工具生成的用药建议常出现农药混用冲突、安全采收间隔期缺失、推荐禁限用农药等专业疏漏，带来合规风险与作物药害。

智能引导重拍

当系统检测到照片模糊、光线不足、杂草群落混杂、缺少作物整体参照等影响判断的问题时，主动弹出文字+语音引导用户重新拍摄，并给出具体拍摄建议（如"请拍一张作物整体照片""请离杂草20-30厘米拍摄"）。

📚

公共案例数据库

用户完成诊断后，系统自动将案例信息（地域、时间、作物品种、病虫草害名称）存入后台公共数据库。同地域/临近用户使用时，系统可参考已有案例提升识别效率与准确度，无照片、无用户隐私信息。

🌿

病虫草害精准识别

基于双模型交叉核验架构，对上传的图片进行病虫草害精准识别，每次识别结果经两套模型交叉验证后输出，降低误判风险。

📋

双初稿+多维合规校验

基于作物品种+生长阶段+草龄/虫态+地域用药习惯四要素，双LLM独立生成方案，经合规大模型融合校正后输出。

📍

地域用药习惯匹配

基于用户所在地区（省/市/县）匹配当地常用药械、抗药性特征、作物种植习惯，输出更贴近实际的用药建议。

🔬

双模型交叉核验

两套农业视觉模型并行独立识别病虫草，结论一致直接采信，分歧调用多模态推理模型终审裁决。

📱

智能补全交互

当图片中未识别出作物或作物信息不完整时，智能引导用户选择作物品种或补拍作物全貌，不缺失关键决策因子。

项目目的与意义

🎯 项目设立的核心目的

农田查项目的设立，旨在通过人工智能与农业植保知识的深度融合，解决"田间病虫草害识别难、用药方案不规范、农技资源下沉不足"三大核心问题，具体目标包括：

  • 降低识别误差：通过多模型交叉核验架构，将田间病虫草害识别置信度提升至可接受水平，减少因误判造成的减产损失。
  • 规范科学用药：输出的植保方案严格匹配农业农村部最新农药管理规范，标注药剂稀释比例、喷施窗口、安全间隔期、混用禁忌等关键信息。
  • 填补农技资源缺口：以数字化工具弥补基层农技人员数量不足的问题，将专业植保服务的"虚拟触角"延伸到每一块农田。
  • 降低种植成本：精准识别+对症用药，减少农户因盲目喷药造成的农资浪费、药害减产、农残超标等多重损失。
  • 服务中老年农户：以极简操作、大字号界面、通俗化语言等设计，让不擅长使用智能手机的银发种植群体也能享受AI带来的便利。

🌍 三重价值与意义

🌱 经济价值：直接减少种植损失

病虫草害是造成农作物减产的最主要因素之一。据统计，我国主要作物因病虫草害年均损失率达 15%-25%。精准识别与对症用药可将这一损失率降低 5-10个百分点，对应每亩粮食作物挽回损失约 50-150元，果蔬作物效益提升更为显著。按项目覆盖10万亩农田保守估算，潜在经济价值可达 500万-1500万元/年。

🌿 生态价值：推动农药减量与生态保护

我国农药使用量长期居于世界前列，不合理施用带来土壤污染、水源污染、农产品农残超标、生物多样性受损等多重生态问题。农田查通过精准识别+合规用药指导，推动农户从"广谱大量喷药"转向"精准靶向用药"，助力国家"农药使用量零增长"行动方案落地，从生产源头减少化学投入品对生态环境的压力。

👨‍🌾 社会价值：赋能基层农业现代化

粮食安全是国计民生的压舱石。农田查以极低的边际成本，将专业植保知识下沉到广大基层，助力个体种植户向"科学化种植"升级。项目尤其关注中老年农户这一当前劳动力主体的数字融入能力，以极简设计降低技术使用门槛，让银发种植群体也能享受科技红利。同时，为基层农技推广体系提供标准化辅助工具，提升公共服务效率与覆盖范围。

📸 病虫草害识别链路（双模型交叉核验 · 精调拍摄引导话术）

核心设计：用户上传田间照片后，系统通过双模型交叉核验架构完成病虫草害识别。两套模型并行独立识别，结论一致直接采信，分歧调用多模态推理模型终审裁决，最大程度降低误判风险。

📷 三类场景差异化拍摄引导（上传前提示）：

  • 🌿 识别草害："请把作物和杂草一起拍进来哦！" — 作物+杂草同框可同时识别作物品种和杂草种类；建议距离作物 30-50 cm 拍摄，确保画面中既有作物主体（如小麦株/玉米株），也有杂草清晰的叶片和整体形态，便于识别杂草种类（如播娘蒿、野燕麦、荠菜等）和草龄。
  • 🐛 识别虫害：请对准害虫聚集的部位（如叶片背面、茎秆、穗部）拍摄；系统会通过叶片形状、叶脉特征、株型来识别作物品种；建议同时包含一张作物整体长势的照片，便于推断作物生长阶段。
  • 🍂 识别病害：请对准病斑最明显的部位（如叶片病斑、穗部病变、茎秆病斑）拍摄；系统通过叶片形状、叶脉走向、作物整体形态识别作物品种；建议同一场景拍摄 2-3 张不同角度的照片，便于综合判断。
  • 💡 通用拍摄建议：自然光线下拍摄，避免逆光/强光直射；拍摄距离 20-60 cm 较为适宜；保持镜头与目标大致平行；画面中尽量包含作物主体信息，如仅有病虫草害而无作物信息，系统会自动引导补全。

🌱 生长阶段信息的差异化使用策略：

  • 🌿 草害/除草剂方案（生长阶段信息至关重要）：除草剂必须精确匹配作物生长阶段才能安全有效使用。苗前封闭除草（作物播种后出苗前，如小麦播后苗前用异丙隆封闭）、苗后早期（作物2-5叶期，杂草2-4叶期为最佳用药窗口）、苗后中期（作物拔节/分蘖期后，部分除草剂禁用或需降权）、作物生长后期（多数除草剂禁用，仅允许行间定向喷雾）四个阶段的方案完全不同。生长阶段信息缺失时，系统强制要求用户补全（选择/输入作物+生长阶段）。
  • 🐛 虫害方案（生长阶段信息相对次要）：杀虫剂方案的关键是虫龄（低龄幼虫 vs 高龄幼虫 vs 成虫）和作物品种，而非作物生长阶段。作物生长阶段主要用于两个安全约束：① 花期/幼果期标注"对蜜蜂/天敌风险提示"；② 安全采收间隔期（PHI）标注——方案中明确"距采收期不足XX天时禁用/建议选用更安全的替代药剂"。生长阶段信息不足时，方案仍可输出，但会在开头提示"若能补全作物生长阶段，方案的用药安全建议可更精准"。
  • 🍂 病害方案（生长阶段信息中等重要）：不同生长阶段易发生的病害类型不同（苗期易感猝倒病/立枯病、分蘖期易感纹枯病、抽穗期易感锈病/赤霉病、穗期易感稻瘟病等）。识别到生长阶段时，可更精准推荐病害防治方案和预防措施；如未识别到生长阶段，方案以"通用防治建议+药剂轮换建议+作用机理说明+安全采收期"为主。方案尾部标注："花期/幼果期用药请注意生态安全，避免杀伤蜜蜂和天敌昆虫。"

🔁 用药安全前置校验（与方案生成同时进行，由同一大模型完成）

⚠️ 安全第一原则 · 高风险药剂主动降权/不推荐：

  • 甲基二磺隆：小麦田对节节麦有特效，但对春性小麦/低温环境/拔节后用药药害风险极大。除非确诊为严重节节麦危害且温度条件适宜，否则不做首推，优先推荐异丙隆/精恶唑禾草灵等更安全的替代方案。
  • 2,4-滴丁酯 / 2甲4氯：小麦拔节后使用存在显著药害风险（弯曲畸形/空秕粒）。对小麦拔节后自动标记为"不推荐"，优先推荐双氟磺草胺/唑草酮等更安全的阔叶除草剂。
  • 高毒/剧毒药剂：如甲胺磷、对硫磷、氟虫腈等一律禁用，即使当地习惯使用也必须以红色"不推荐"替代为低毒药剂。
  • 蔬菜/果树上的药剂：严格检查安全采收间隔期，花期/幼果期用药必须标注"对蜜蜂风险""对天敌影响"等生态安全提示。

⚠️ 除草剂漂移与熏蒸风险 · 对邻近作物的详细警示：

  • 2,4-滴丁酯、2甲4氯（激素型除草剂）：挥发性强、漂移距离远，即使在小麦田正常施用，若风向附近存在棉花、大豆、花生、蔬菜、果树等阔叶作物，极小剂量的雾滴漂移即可造成叶片扭曲、畸形、落花落果甚至整株死亡。输出方案时必须单独以红色醒目提示："本方案含2,4-滴/2甲4氯类挥发性除草剂，严禁在有棉花、大豆、蔬菜、果树等阔叶作物邻近的风向位置施用！若周边100米内有上述作物，请改用非激素类除草剂（如双氟磺草胺+唑草酮）"。
  • 草甘膦（灭生性除草剂）：任何作物田都不能直接喷雾，只能在行间定向喷雾且必须加装防护罩。方案中需红色警示："草甘膦对所有绿色植物均有灭杀作用，严禁喷到作物茎叶！仅可在作物行间进行定向喷雾，且必须加装塑料防护罩，喷雾量以杂草叶片湿润不滴水为宜。"
  • 精喹禾灵/高效氟吡甲禾灵（芳氧苯氧丙酸酯类）：对禾本科作物（小麦/水稻/玉米）有致命药害，仅能用于阔叶作物田除禾本科杂草。方案中需明确标注："注意：本药仅适用于大豆/花生/棉花/蔬菜等阔叶作物，小麦/水稻/玉米等禾本科作物绝对禁用！"
  • 莠去津（三嗪类）：持效期长，对后茬敏感作物（小麦、水稻、大豆、蔬菜）有残留药害风险，方案中标注："本药剂残效期长，下茬作物仅能种植玉米、高粱等耐药作物，严禁计划下茬种植小麦、水稻、蔬菜的田块使用。"
  • 二氯喹啉酸（稻田杀稗草特效）：对后茬番茄、茄子、马铃薯、甜菜、西瓜等作物有极高药害风险，方案中红色标注："本药剂在土壤中残留时间长，下茬/下一年严禁种植番茄、茄子、马铃薯、西瓜、甜菜等敏感作物！建议使用安全性更好的五氟磺草胺/氰氟草酯替代。"
  • 咪草烟/咪唑乙烟酸（豆田除草剂）：残留期长，对后茬小麦、水稻、玉米、蔬菜均有药害风险，方案中标注："本药土壤残留期长达12-24个月，施用过本药的地块，18个月内不建议种植小麦、水稻、玉米、蔬菜等作物。"
  • 施用气象条件提示：所有除草剂方案尾部增加一条环境提示："建议风速≤2米/秒、气温15-30℃的早晨或傍晚喷施。高温大风天气药剂蒸发快，易造成漂移药害；低温则药效发挥缓慢且可能加重作物敏感。"

🧠 五维感知专属提示词体系（作物×阶段×虫龄/草龄×地域×安全等级）

🌿 病害类提示词（嵌入作物品种+生长阶段+抗性特征）：识别病害成因（温湿度/水肥/通风诱因）、病害传播规律；基于作物品种与生长阶段输出①农业/物理防治措施（如通风降湿、清除病残体、合理密植、平衡施肥、高畦栽培等）；②生物防治手段（如木霉菌、枯草芽孢杆菌、多抗霉素等低风险生物农药）；③保护性杀菌剂（如代森锰锌、百菌清、吡唑醚菌酯，优先推荐）+ 治疗性杀菌剂（氟硅唑、戊唑醇等，需标注作用机理FRAC代码）；④精准稀释倍数、每亩用药量、最佳喷施时段（发病初期喷雾，7-10天后复喷）；⑤该生长阶段下的安全采收间隔期（PHI）和每季最多使用次数；⑥抗性管理：明确标注"本次使用FRAC XX作用机理，下次建议改用FRAC YY作用机理，避免连续使用同类药剂超过2次"；⑦该作物敏感药剂提醒（如铜制剂在桃/李上禁用、波尔多液在水稻孕穗期慎用）；⑧后期田间预防管控要点。

🐛 虫害类提示词（嵌入作物品种+虫龄+抗药性+可购买性）：基于虫害生活史与当前虫龄输出①物理诱杀方案（黄板/蓝板高度密度、性诱剂诱芯+粘虫板组合、杀虫灯部署）；②生物防治手段（Bt、白僵菌、绿僵菌、核型多角体病毒等）+ 天敌保护与利用（瓢虫、草蛉、捕食螨）；③低毒/微毒化学杀虫剂的完善配方（两种不同IRAC机理组药剂复配，如吡蚜酮+噻虫嗪、氯虫苯甲酰胺+噻虫嗪、溴氰菊酯+吡虫啉等市面上常见、农民容易买到的常规组合）；④精准稀释倍数（如10%吡蚜酮WP 1500-2000倍液，即每亩7.5-10克药对水45-60公斤喷雾）、最佳喷施时段（清晨或傍晚，害虫活动旺盛但药液不易蒸发）、喷药液量标准（叶片湿润不滴水，田间虫体部位重点喷雾）；⑤作用机理标注（明确本次使用的IRAC代码组）+ 下次轮换用药建议；⑥该区域高抗性药剂警示（如"吡虫啉对本区域烟粉虱已报道高抗性，建议改用氟啶虫胺腈/溴氰虫酰胺替代"）；⑦该作物上的安全用药限制（标注安全采收间隔期PHI、每季最多使用次数）；⑧用药禁忌与田间管理方案（如吡蚜酮对蚕高毒、开花期严禁喷雾）；⑨非化学防治前置：每一个虫害方案开头先给出综合防治措施清单，再给出化学防治方案，倡导"综合防治、预防为主"。

🌾 杂草类提示词（嵌入作物品种+草龄+地域+抗性+漂移风险）：基于杂草生长习性、当前草龄、伴生作物类型、所在省份的抗性情况输出①农业防除措施（深翻整地抑制杂草出苗、人工除草最佳窗口期、合理轮作倒茬、覆盖作物抑草）；②苗前封闭/茎叶处理除草剂差异化推荐（严格区分禾本科/阔叶杂草用药差异，标注每一种药剂在当前作物上的登记标签是否涵盖此作物）；③高风险药剂（甲基二磺隆/2,4-D类）标注适用条件并优先推荐更安全替代方案（甲基二磺隆需满足冬性小麦+气温5℃以上+拔节前三项条件才可推荐，2,4-D类标注周边100米内有阔叶作物时禁用）；④该省常用药剂推荐与轮换用药建议（如河北小麦区推荐双氟磺草胺+唑草酮为基础组合，根据抗性情况轮换使用炔草酯/精恶唑禾草灵/啶磺草胺等）；⑤除草剂漂移与邻近作物风险（激素型除草剂对棉花/大豆/蔬菜/果树的漂移风险、草甘膦必须定向喷雾且加装防护罩、芳氧苯氧丙酸酯类对禾本科作物的致命药害风险）；⑥后茬作物药害风险（莠去津/二氯喹啉酸/咪草烟等长残效除草剂的下茬作物限制清单）；⑦气象条件提示（风速≤2m/s、气温15-30℃、清晨或傍晚喷施）；⑧精准稀释倍数+亩用药量+施液量（如75%苯磺隆WG 1.5-2.0克/亩，对水45公斤均匀喷雾）。

  • 安全建议或替代方案：如何规避风险，或推荐更安全的替代药剂（如"若节节麦危害严重必须使用，需满足冬性小麦+气温5℃以上+拔节前三个条件；否则建议改用精恶唑禾草灵+人工拔除"）
  • 风险等级：1（普通提醒） / 2（重要提醒） / 3（红色警示，必须标注）

  • 命中计数（可选）：该风险信息被检索到的次数，用于后台评估哪些风险条目最常被用户遇到，便于优化排序权重

⚡ 两层存储：服务器主数据库（集中管理） + 用户手机本地缓存（快速查询）

→ 【服务器端主库】集中管理所有风险记录（几千条仅几十MB）；人工审核、新增、修改全部在服务器端进行
→ 【用户手机本地缓存】用户手机本地存放一份轻量级风险数据库（约几MB），供日常查询使用
→ 【启动时增量同步】用户每次打开应用时，后台静默请求服务器："我的本地版本号是 X，服务器最新版本是多少？"
→ 【增量更新】如服务器版本高于本地，则推送"增量更新包"（仅当前版本到最新版本的差异记录，通常几KB到几十KB级别），用户手机本地在后台自动更新到最新版本

→ 【查询时读手机本地】方案查询时，风险数据库直接从手机本地读取，响应时间 <1ms，断网也可以正常使用
→ 【版本号机制】每一条风险记录都带有版本号，服务器通过版本号管理"新增 + 修改 + 删除"
→ 【同步失败保护】如更新时网络失败，不覆盖原本地缓存，用户下次打开时再次尝试同步
→ 【服务器端仍保留内存加速】主数据库在服务器端加载到内存中（Hash索引），供用户查询到的增量更新包生成

🔴 病害预警（急性风险，周度高频分析）

触发条件：某省/市 + 某作物在近7日内特定病害查询量环比上升200%以上或绝对数量超过15例（阈值可根据地域大小调整）。

推送内容示例："【预警·小麦条锈病】您所在的河北省邯郸市近7日小麦条锈病查询量上升320%，当前为小麦拔节-抽穗期，发病条件适宜。建议立即检查田间叶片中部是否出现黄色粉斑，如有发现请参考系统中的防治方案及时用药。"

🟠 虫害预警（急性风险，周度高频分析）

触发条件：某省/市 + 某作物在近7日内特定虫害查询量环比上升200%以上或绝对数量超过15例。

分析维度：虫害名称 + 虫龄结构（低龄/高龄）+ 当前气候条件（温度/降雨）+ 历史发生规律

推送内容示例："【预警·小麦蚜虫】您所在的山东省德州市近7日小麦蚜虫查询量上升250%，当前虫龄以低龄若虫为主，气候条件适宜繁殖。建议及时查虫，可参考系统方案选用吡虫啉/啶虫脒等药剂。"

🟡 草害预警（慢性长期风险，年度差异分析）

触发条件：某省/市 + 某作物在本年度某杂草查询量较上一年显著上升30%以上，或新增出现本地历史不常见的恶性杂草（如长江流域出现豚草、黄河流域出现假高粱等）。

分析维度：杂草名称 + 抗药性变化趋势 + 除草剂防效反馈 + 与上一年同月份的差异

推送内容示例："【预警·播娘蒿】您所在的河北省石家庄市，2026年度播娘蒿查询量较2025年上升42%，且用户反馈双氟磺草胺防效下降。建议今年调整用药策略，重点关注苗后早期防除，可参考甲基二磺隆相关方案。"

🔐 数据安全与合规设计

  • 全链路国内部署：所有视觉识别、文本问答推理、数据存储均位于国内机房，不存在跨境数据传输。
  • 原图不留存：田间实拍作物图片仅用于实时AI推理运算，识别完成后不长期上传存储原图。
  • 用户标识匿名化：采用本地生成随机UUID作为用户唯一标识，不收集手机号、IMEI、MAC地址等个人信息，用户可随时在设置中重置UUID。
  • 作物信息用户主动选择：种植作物信息由用户主动勾选，可随时修改或清空，不强制、不默认推断。
  • 本地持久化：全部农事诊断记录仅保存在用户本地设备，用户完全拥有数据控制权。
  • 合规用药：内置农药禁限用名录校验，严格区分不同作物、不同地区的合规用药范围。
  • 预警用户授权：预警推送通过微信小程序"订阅消息"机制实现，每次推送需用户主动订阅，用户可随时取消订阅。

🔑 API Key 安全架构设计（避免泄露造成损失）

核心原则：前端零 Key · 云端中转 · 频率限制 · 用量告警 · 定期轮换

📱 【用户小程序端】

→ 完全不存储任何 API Key
→ 仅向自己的云函数发送请求（携带本地生成的 UUID 作为会话标识）
→ 所有推理调用对用户完全透明，用户无感
➜
☁️ 【云函数中转层】（安全核心）

→ API Key 仅存储在云函数环境变量中（或密钥管理服务 KMS），不在任何代码中硬编码
→ 频率限制：单一 UUID 每日最多 50 次诊断请求 / 每分钟最多 3 次，超出自动返回"今日已达上限"
→ 会话短令牌：云函数为每次用户会话生成 5 分钟有效的短令牌，过期失效，避免令牌复用
→ 请求签名：关键请求附带时间戳 + 签名，防止重放攻击
➜
🤖 【AI 服务提供方】（阿里/火山/百度等第三方 API）

→ 云函数持有合法 API Key，以服务端身份调用
→ 响应直接返回给用户小程序，Key 始终在云端不暴露
↧
🚨 【运维监控告警】

→ 单日费用告警：当单日调用费用超过预设阈值（如 100 元），立即短信/邮件通知管理员
→ 异常流量告警：10 分钟内请求量飙升超过正常范围，自动触发临时限流
→ Key 定期轮换：每月在云平台生成新 Key 替换旧 Key，操作在云端完成，前端完全无感
→ 紧急 Kill 开关：管理员可一键禁用所有云函数调用，防止 Key 泄露后的大规模损失

安全层级总结：① 物理层（前端零 Key）→ ② 逻辑层（频率限制+短令牌） → ③ 监控层（用量告警） → ④ 管理上（定期轮换+紧急开关）。四层纵深防护，最大限度降低潜在损失风险。

第一步 · 打开农田查 · 选择作物并上传照片

第二步 · 照片质量预检（自动）

系统调用图像质量评估模型，对照片的清晰度/光线/构图/目标完整性进行快速检测。若发现照片模糊、光线不足、杂草群落混杂等问题，弹出文字+语音引导用户重新拍摄（语音可关闭，适应中老年用户使用习惯）。用户可选择按引导重拍，也可选择继续使用当前照片。

第三步 · AI双模型交叉核验识别

系统后台同时运行两套农业视觉模型进行并行独立识别：①模型A（飞桨 PaddleClas）→ 识别结果；②模型B（阿里魔搭）→ 识别结果。两套模型结论一致时直接采信；结论分歧时调用火山引擎多模态模型进行终审裁决。约5-12秒完成全部识别。作物信息由用户手动选择，确保用药安全边界准确。

第四步 · 智能信息补全（风险等级+生育期双参数）

4.1 风险等级获取（明确交互，不假设）：系统弹出三张卡片（轻度/中度/重度），由用户主动选择，按钮大、颜色区分（绿/黄/红），让系统不做AI自动假设。选择后，方案的化学农药部分按轻/中/重度分层推荐。

4.2 growStage 生育期获取（动态匹配所选作物）：系统根据用户选择的作物品种，动态展示该作物专属的生长周期阶段（例如小麦显示：出苗期→分蘖期→越冬期→返青期→拔节期→孕穗期→抽穗期→开花期→灌浆期→成熟期；水稻显示：出苗期→分蘖期→拔节期→孕穗期→抽穗期→灌浆期→成熟期）。如用户未主动选择或跳过，系统默认为"主要生长季（非花期/非临近采收）"，避免大模型随意假设导致用药偏差。

// 🔍 第一步：双模型并行识别（模型A飞桨 + 模型B魔搭）
async function dualModelRecognize(imagePath, locationProvince) {
  // 模型A（飞桨 PaddleClas）独立识别
  const resultA = await paddleClas.recognize(imagePath);
  // 模型B（阿里魔搭）独立识别
  const resultB = await modelscope.recognize(imagePath);
  
  // 双模型一致性判定
  const isConsistent = resultA.name === resultB.name && resultA.confidence > 0.6 && resultB.confidence > 0.6;
  
  if (isConsistent) {
    return { pest: resultA, confidence: Math.round((resultA.confidence + resultB.confidence) / 2), model: '双模型一致' };
  } else {
    // 分歧时触发火山引擎终审裁决
    const finalResult = await volcengine.finalJudge(imagePath, resultA, resultB);
    return { pest: finalResult, confidence: finalResult.confidence, model: '终审裁决' };
  }
}

// 🗣️ 第二步：智能文字+语音引导模块（语音完全本地执行，零费用，跨平台一致）
function showGuidance(recognitionResult, voiceEnabled) {
  if (recognitionResult.hasQualityIssues) {
    showPopupWithText(recognitionResult.qualityIssues.join('\n'));
    if (voiceEnabled) localChineseTTS.speak(recognitionResult.qualityIssues.join('。'));
  }
  if (!recognitionResult.hasCropInfo) {
    if (recognitionResult.weeds.length > 0) {
      // 🌿 草害场景：强制要求用户补全作物信息（作物品种+生长阶段是除草剂安全使用的关键）
      const cropChoice = showCropSelectionModal(locationProvince);
      if (cropChoice) {
        recognitionResult.crops.push({ name: cropChoice.name, growthStage: cropChoice.stage || '待确认', userSupplied: true });
      } else {
        recognitionResult.missingCropWarning = true;
      }
    } else {
      // 🐛/🍂 虫病场景：建议补全，非强制
      const cropChoice = showCropSelectionModal(locationProvince, { required: false });
      if (cropChoice) recognitionResult.crops.push({ name: cropChoice.name, growthStage: cropChoice.stage || '默认', userSupplied: true });
    }
  }
  // 草害场景附加引导语：建议用户下次把作物和杂草一起拍
  if (recognitionResult.weeds.length > 0 && !recognitionResult.hasCropInfo) {
    const tip = "提示：下次拍摄时，将作物和杂草一同纳入画面，有助于系统同时识别作物品种和杂草种类，给出更精准的用药建议";
    if (voiceEnabled) localChineseTTS.speak(tip);
  }
}

// 🧠 第三步：对低置信度目标触发 Qwen3-VL 终审裁决（可选调用，多数场景不触发）
async function optionalFinalJudge(imagePath, recognitionResult) {
  if (recognitionResult.needFinalJudge.length === 0) return recognitionResult;
  const finalJudgeResult = await qwen3VL.judge(imagePath, recognitionResult.needFinalJudge);
  for (const target of finalJudgeResult) {
    const key = target.type + 's';
    const idx = (recognitionResult[key] || []).findIndex(x => x.name === target.originalName);
    if (idx >= 0) {
      recognitionResult[key][idx].name = target.finalName;
      recognitionResult[key][idx].confidence = target.confidence;
      recognitionResult[key][idx].finalJudgeReason = target.reason;
    }
  }
  return recognitionResult;
}

// 🚨 后台定时预警引擎
async function runAlertEngine() {
  const today = new Date();
  const sevenDaysAgo = new Date(today.getTime() - 7*24*60*60*1000);
  const prevYearStart = new Date(today.getFullYear()-1, today.getMonth(), today.getDate());
  const prevYearEnd = new Date(today.getFullYear()-1, today.getMonth()+2, today.getDate());

  const diseaseAlerts = await publicCaseDB.aggregate([
    { $match: { diagnosisDate: { $gte: sevenDaysAgo }, "pestTargets.type": "病害" } },
    { $group: { _id: { province: "$province", city: "$city", crop: "$crop", pestName: "$pestTargets.name" }, count: { $sum: 1 } } },
    { $match: { count: { $gte: 15 } } }
  ]);

  const insectAlerts = await publicCaseDB.aggregate([
    { $match: { diagnosisDate: { $gte: sevenDaysAgo }, "pestTargets.type": "虫害" } },
    { $group: { _id: { province: "$province", city: "$city", crop: "$crop", pestName: "$pestTargets.name" }, count: { $sum: 1 } } },
    { $match: { count: { $gte: 15 } } }
  ]);

  const weedAlerts = await publicCaseDB.aggregate([
    { $match: { diagnosisDate: { $gte: prevYearStart, $lte: prevYearEnd }, "pestTargets.type": "杂草" } },
    { $group: { _id: { province: "$province", city: "$city", crop: "$crop", pestName: "$pestTargets.name" }, count: { $sum: 1 } } },
    { $match: { count: { $gte: 20 } } }
  ]);

  return { diseaseAlerts: diseaseAlerts, insectAlerts: insectAlerts, weedAlerts: weedAlerts };
}

  • 作物+生长阶段感知的五维决策链："作物品种 × 生长阶段 × 病虫草害精准识别 × 地域用药习惯 × 用药安全等级"的五维决策体系，是本项目与通用AI工具的最本质区别。

  • 智能引导重拍（文字+语音）：面对中老年种植群体，通过照片质量预检+火山引擎语音引导，主动降低误判风险，适应田间真实复杂的拍摄场景。
  • 公共案例数据库（无隐私）：每一次诊断自动匿名入库，让广大种植户的田间经验形成可积累、可复用的公共植保知识资产，系统价值随用户使用不断提升。
  • 用户识别机制（最小必要原则）：采用本地生成随机UUID，不收集手机号/IMEI等个人信息，作物信息用户主动选择，可随时修改/清空，在实现个性化服务的同时最大程度保障用户隐私。
  • 原创架构设计："双模型初审 + 多模态终审裁决 + 双LLM方案生成 + 用药安全校验融合"的多层异构多模型交叉校验体系。
  • 用药安全的强约束：独立于方案生成的前置安全校验模块，对作物敏感期、禁限用农药、安全采收间隔期等关键信息做严格审查。
  • 垂直场景深耕：完全剥离非农业冗余功能，聚焦大田、果蔬、经济作物的病、虫、草三类诊断，专业度远超通用大模型。
  • 面向银发种植群体的极简设计：零门槛操作、大字清晰展示、通俗化语言，结合田间实景与本地用药习惯，让中老年农户也能轻松使用。
  • 零门槛的用户体验：极简操作路径与面向银发群体的设计理念，让最需要植保知识的人群也能轻松使用。
  • 极低的落地与运营成本：全云端API架构，零硬件投入，可随业务规模灵活扩容，具备可持续运营的经济性。
