创意名称 + 创意介绍

关于"装修小助手"的一切，从这里开始

想解决什么问题

装修小白面对复杂的装修流程，没有系统化的进度管理工具，靠备忘录和微信群记录，容易漏项、延误工期、花费失控

首次装修的业主通常需要面对 20+ 个施工节点，持续 3-6 个月。他们不清楚每个工序的标准要求、不知道什么时候该做什么、算不清花了多少钱——信息全靠碎片化记录，最终导致工期延误、验收无依据、预算超支。装修小助手希望用最简单的工具，帮他们把"一团乱麻"梳理成清晰的进度线和花费账本。

为什么会想到做这个

灵感来源于身边朋友的真实装修经历——"如果有装修地图，我也不会被坑了"

身边多位朋友在装修时都遇到了同样的问题：施工方说"该做防水了"，自己不知道标准是什么；结账时才发现一共花了多少钱，但每一笔花在哪完全回忆不起来。装修行业信息不对称严重，而市面上缺乏一款面向装修小白的轻量级进度管理工具。结合 Trae AI 的辅助开发能力，从零打造一款"装修新手的通关地图"成为一个自然的选择。

大概是什么产品

一款移动端优先的 H5 Web App，无需安装、无需注册、无需网络，打开即用

基于 Vue 3 + Vite 构建的单页应用，采用 Claymorphism 3D 粘土拟态设计风格。纯本地存储（localStorage），打包后仅 3 个文件（HTML + JS + CSS），支持 file:// 协议双击打开，可离线运行。手机端全屏适配，桌面端以居中 430px 手机框展示。产品形态上既可以是独立打开的网页，也可以嵌入小程序或 App 的 WebView 中使用。

目标用户及痛点

每一个装修小白都会遇到的真实困境

面向哪些用户

首次装修房屋的业主（25-40 岁），对装修流程不熟悉，缺乏系统化的管理手段

核心用户画像是"装修小白"——他们可能是买了人生第一套房的年轻夫妻，也可能是帮父母翻新旧居的子女。共同特征是对装修行业不了解、没有施工经验、预算有限、时间紧张。他们需要的是一个"装修导航"，告诉他们在每个阶段该做什么、注意什么、花多少钱，而不是一本厚厚的装修手册。

在什么场景下使用

施工现场、建材市场、家居城、下班后在家——随时打开，随时记录

用户在开工前创建房屋，录入装修节点清单；施工过程中，每完成一个工序就在手机上勾选步骤、拍照记录；逛建材市场时随手记录花费金额；晚上回家和家人一起查看进度百分比和花费汇总。真正的"随手记、随时看、随地用"。

当前痛点

没有装修小助手，用户现在会遇到什么不方便？

装修涉及 20+ 个施工节点、数十项花费、持续 3-6 个月——如果没有系统化的管理工具，用户只能靠备忘录、微信群聊天记录、纸质清单来记录，信息分散、容易遗漏、无法追溯。施工方说"该验收了"，用户不知道标准是什么；月底算账，花在哪、花了多少一片模糊。最终结果往往是：工期延误、验收扯皮、预算超支，整个过程充满焦虑和不确定。

😵

进度不可视

装修节点全凭记忆或零散记录，无统一视图，容易漏项、重复施工、工期延误

📋

节点无标准

不清楚每个工序的标准要求和注意事项，验收无依据，容易被施工方糊弄

💸

花费无统计

花费散落在各处，无分类汇总，预算失控，超支了才发现

🏠

多房难管理

多套房屋同时装修时无法切换，信息混乱，经常串户记录

价值与意义

从效率提升和社会价值两个维度，看装修小助手能带来什么改变

⚡

效率提升

将装修进度管理从"碎片化记忆"升级为"系统化时间轴"，用户可在 5 分钟内完成房屋创建并查看全部标准节点清单。进度百分比实时可见，花费自动分类汇总，省去人工对账时间。部分勾选自动触发状态流转，减少手动操作步骤。

❤️

社会价值

装修行业信息不对称严重，装修小白是信息弱势群体。装修小助手内置基于国家标准（GB 50210、GB 50300）的施工节点和验收标准，让普通业主也能了解每个工序的规范要求，降低被施工方糊弄的风险。同时，家庭协作功能让伴侣、父母可以共同参与装修管理，减少因为信息不同步导致的家庭矛盾。

核心价值主张：不是让用户成为装修专家，而是让他们在装修这件"人生大事"上，不再手忙脚乱、不再任人鱼肉、不再花冤枉钱。用最低的门槛（双击即用）、最轻的方案（纯本地存储），解决最重的痛点（进度管理 + 花费控制 + 标准参考）。

功能与实现

6 个核心功能 + 5 大创新点，覆盖装修全流程管理

🏠

登录与创建房屋

3 步表单引导式创建房屋（名称 → 小区户型 → 确认），路由守卫保护未创建房屋的用户无法访问 Tab 页面

  • 一键登录，写入 localStorage 标记
  • 3 步进度指示器，表单未填全时按钮置灰
  • 创建成功动画 + 自动跳转硬装页
🔨

硬装/软装节点进度管理

基于国家标准（GB 50210、GB 50300）预设 13 个硬装节点 + 7 个软装节点，时间轴展示，支持完整的状态机流转（正向 + 逆向）

  • PENDING → IN_PROGRESS → COMPLETED / SKIPPED 四态状态机
  • COMPLETED 取消勾选自动退回 IN_PROGRESS，全部取消自动退回 PENDING
  • 注意事项确认机制：进入节点先确认注意事项，再操作步骤
  • 节点跳过/删除操作，COMPLETED 状态不可跳过
  • 骨架屏加载动画 + 空状态组件 + 3D 粘土角色场景
💰

花费记录与分类统计

记录每笔装修花费（金额、日期、分类、描述），自动汇总总额，按硬装/软装分类查看

  • 金额汇总卡片——实时显示总花费
  • 花费表单页——金额/日期/分类/描述完整录入，表单校验
  • 分类价格参考——按硬装/软装分组展示
👨‍👩‍👧

家庭管理

多房屋切换与删除、成员权限管理、邀请协作、文字大小调节、恢复初始化

  • 多房屋切换：当前房屋标记"当前"标签，非当前房屋可删除
  • 成员权限：可编辑/仅查看开关，创建者不可移除
  • 文字大小调节：小/标准/大三档，即时生效 + localStorage 持久化
  • 恢复初始化：清除所有数据，二次确认后回到首次使用状态

五大创新点

创新 1：完整的状态机驱动的进度管理

不是简单的 TODO 勾选，而是设计了 PENDING → IN_PROGRESS → COMPLETED / SKIPPED 四态状态机，支持正向流转和逆向退回。全部步骤取消勾选时自动退回 PENDING，取消任意步骤时从 COMPLETED 退回 IN_PROGRESS。

创新 2：Claymorphism 3D 粘土拟态设计

采用国际前沿的 Claymorphism 设计风格：大圆角（24px）、多层柔和阴影模拟 3D 体积、弹性动画（bounce easing）、哑光暖色系。配合企鹅/小熊 IP 角色 3D 场景组件。

创新 3：零依赖纯本地架构

无后端、无数据库、无账号、无第三方 API。打包后仅 3 个文件，支持 file:// 协议双击打开，离线运行，复制即用。真正做到"零门槛分发"。

创新 4：设计 Token 系统 + 动态字体调节

完整的 CSS 自定义属性 Token 体系（6 级字体、5 级圆角、5 级阴影），支持运行时动态修改全局字体大小，即时生效并持久化。

创新 5：移动端 + 桌面端双适配

max-width: 430px / max-height: 932px 限制，移动端全屏，桌面端以居中手机框展示（40px 圆角 + 黑色边框 + 阴影），规避 100vh 溢出问题。

AI 辅助开发全程纪实

阶段 1：需求分析与 PRD 撰写

通过 Trae 内置的 PRD Writer 技能，按标准流程完成需求诊断、页面结构确认、概念版对齐、范围冻结，最终输出包含 6 大功能完整规格的落地版 PRD 文档（含用户流程、状态机、字段规范、文案规范、异常处理）。

阶段 2：组件开发与状态机设计

从零搭建 Vue 3 + Vite 项目，开发 14 个通用组件。核心挑战是节点状态机的设计：PENDING → IN_PROGRESS → COMPLETED / SKIPPED 的完整流转及逆向路径的自动触发逻辑，通过多轮迭代调试实现闭环。

阶段 3：UI 打磨与设计系统升级

从基础样式到 Claymorphism 3D 粘土拟态风格的全面升级：建立设计 Token 系统、添加进入动画、骨架屏加载、Toast 提示、弹性按钮交互。引入企鹅/小熊 IP 角色 3D 场景。

阶段 4：Bug 修复与用户体验优化

通过多轮用户反馈迭代修复：双 slot 重复渲染、路由守卫流程、状态机逆向路径缺失、100vh 溢出、移动端适配、字体动态调节、房屋删除等。体现"发现 → 分析 → 修复 → 验证"的完整闭环。

阶段 5：打包与发布

配置 Vite 打包参数（base: './' + inlineDynamicImports），输出 3 个文件（HTML + 单 JS + 单 CSS），支持 file:// 协议双击打开、离线运行、零门槛分发。通过 vite preview 提供局域网预览，支持手机端体验。
