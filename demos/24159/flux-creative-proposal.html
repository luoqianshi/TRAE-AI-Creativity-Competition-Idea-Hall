二、灵感来源

LangGraph的启发

LangGraph是当前最火热的AI工作流框架之一，它的核心思想是：多智能体工作流本质上是图结构，而非线性链。 通过状态图的方式，AI可以在执行过程中自主决策、动态调整、循环优化。

但LangGraph也有其局限性：

  • 多Agent协调复杂：多个Agent之间需要复杂的通信和协调
  • 标准不统一：每个Agent可能有自己的偏好和标准
  • 质量保证缺失：流程完成≠质量达标

Flux的创新

Flux从LangGraph汲取灵感，但走出了一条不同的路：

"单一Agent多角色 + 智能评分 + 上下文驱动 = 可控的质量保证"

Flux的核心洞察是：质量不是自然产生的，而是通过"轮转优化"打磨出来的。 就像一个演员演完一场戏，需要经过评分官的审查，只有达到80分的标准，才能进入下一场。

三、语言故事：Flux的觉醒

序章：混乱的团队

小明是个产品经理，他手下有一群AI助手：调研员AI、设计师AI、工程师AI、测试员AI...

但问题来了，这些AI各干各的，没有统一标准。调研员做完需求，设计师觉得不够详细；设计师做完设计，工程师说实现不了；工程师写完代码，测试员发现一堆bug...

"你们能不能先统一一下标准再干活？！" 小明很头疼。

第二章：一人多角的演员

有一天，小明请来了一位全能演员。这位演员很特别，他可以在不同的场景中扮演不同的角色：

  • 在调研阶段，他扮演需求收集员
  • 在设计阶段，他扮演设计师
  • 在开发阶段，他扮演工程师
  • 在测试阶段，他扮演评分官

"你是唯一的主角，" 小明说，"但你得学会在不同阶段扮演不同角色。每个角色都有自己的一套标准，你得严格遵守。"

第三章：角色的评分标准

评分官角色有一套严格的评分标准，这套标准是从团队的Skill规范中提取的。比如：

调研员的评分标准：

  • 需求是否完整？
  • 是否覆盖了所有用户场景？
  • 描述是否清晰无歧义？
  • 是否考虑了边界情况？

全能演员在做完需求收集后，会切换到评分官角色，给自己打分。只有分数达到80分，才能切换到设计师角色继续工作。

第四章：上下文和规则

小明告诉演员："你做决策的依据只有两个：上下文和规则。"

上下文（Context）包含：

  • 老板的原始需求
  • 当前项目的所有历史信息
  • 每个人的产出和反馈

规则（Rules）包含：

  • 每个角色的评分标准（从Skill规范中提取）
  • 最佳实践规范
  • 常见问题清单

从此，这位全能演员不再凭感觉工作，而是严格按照上下文和规则来执行和评估。

第五章：Flux的诞生

就这样，小明有了一支特殊的团队：

唯一的Agent，他扮演不同的角色，但始终是同一个人：

  • 理解上下文：理解老板到底要什么
  • 遵守规则：按照Skill规范执行每个角色
  • 自我评分：每个角色完成后，给自己打分
  • 不达标就重做：分数不够就继续优化，直到达标
老板需求 → 读取上下文 → 扮演角色执行 ↓ 切换到评分官打分 ↓ ┌─────────────┐ │ 分数≥80? │ └─────────────┘ ↓ ↓ 是 否 ↓ ↓ 下一角色 优化 ↓ 全部完成? ↓ 交付老板

只有确认所有环节都达标了，才会把结果交给老板。否则，老板看到的就是半成品，会骂人的！

结局：上下文驱动的智慧

从此以后，这位全能演员再也没有返工不断的问题。每个角色都知道自己要做到什么程度（规则），演员知道现在是什么情况（上下文）。

这就是Flux的核心：

上下文驱动 + Skill规则 + 单一Agent = 质量保证

Agent就是这个系统的核心，他通过上下文理解当前状态，通过Skill规则扮演每个角色，通过自我评分确保质量。

从此，老板再也没骂过人。

四、核心功能

1

单一Agent多角色系统

Flux的核心是单一Agent，这个Agent可以扮演多个角色：需求收集员、设计师、规划师、工程师、评分官。

创新点：不需要多个Agent之间的复杂协调，一个Agent通过角色切换完成所有工作。

2

智能评分系统

每个角色完成后，都必须经过评分官角色的审查：评分标准从Skill规范中提取，80分为"足够好"的标准。

创新点：将"评分"这个关键环节内置到工作流中，确保每个环节的质量。

3

上下文驱动决策

Agent的决策完全基于上下文：用户需求、项目历史、当前状态、反馈信息。

创新点：Agent不依赖记忆，只依赖上下文，确保决策的可追溯性和一致性。

4

Skill规则引擎

每个Skill都定义了严格的评分规则：检查清单、最佳实践、常见错误。

创新点：将Skill规范与评分规则统一，减少重复定义，保持一致性。

五、技术架构

单一Agent核心

class FluxAgent {
  async execute(userRequest: string) {
    // 1. 初始化上下文
    await this.context.init(userRequest);
    
    // 2. 定义角色映射
    const roleMapping = {
      'spec': '需求收集员',
      'design': '设计师',
      'plan': '规划师',
      'dev': '工程师',
      'review': '评分官'
    };
    
    // 3. 循环执行直到完成
    while (!this.context.isComplete()) {
      const phase = this.context.getCurrentPhase();
      const role = roleMapping[phase];
      
      // 切换到对应角色
      this.context.setCurrentRole(role);
      
      // 调用对应Skill执行
      const skill = this.getSkill(phase);
      const output = await skill.execute(this.context);
      
      // 切换到评分官角色
      this.context.setCurrentRole('评分官');
      
      // 自我评分
      const rules = this.getRules(phase);
      const score = await this.selfScore(output, rules);
      
      // 根据评分决策
      if (score.passed) {
        this.context.updateHistory(phase, role, output, score);
        this.context.nextPhase();
      } else {
        this.context.addFeedback(phase, score.feedback);
      }
    }
    
    return this.context.getFinalOutput();
  }
}

  4. 轮转优化：不达标就不交付
