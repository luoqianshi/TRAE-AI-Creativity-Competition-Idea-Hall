# PhotoSelect — 轻量级图片筛选工具

## 目标

Windows 原生图片筛选工具。核心功能：

1. **导入文件夹** — 弹出文件夹选择对话框，递归扫描所有图片（jpg/jpeg/png/webp/bmp/gif/tiff）
2. **缩略图网格浏览** — 响应式列数（2-8 列），虚拟滚动
3. **大图浏览模式** — `Space` 键切换，等比缩放适配窗口，支持翻页和筛选
4. **键盘快捷键筛选** — `←→` 切换选中/翻页、`↓` 标记移除、`↑` 恢复、`0-5` 评分（支持主键盘 + 数字小键盘）
5. **工具栏操作** — 通过工具栏按钮可打开文件夹、保存、排序、切换视图、清空
6. **按星级排序** — `R` 键或工具栏"排序"按钮，按评分降序排列
7. **保存留存图片** — `S` 键或工具栏"保存"按钮，弹出文件夹选择对话框选择目标路径
8. **（规划中）AI 分组** — 颜色直方图 + 余弦相似度聚类（`core/grouping.rs` 已实现，暂未接入 UI）

## 技术路线

| 层 | 技术 | 选择原因 |
|---|---|---|
| UI 窗口 | Win32 API (`CreateWindowExW` + 消息泵) | 零中间层，直接创建原生窗口 |
| 渲染 | GDI 双缓冲 (`CreateCompatibleBitmap` + `BitBlt`) | 离屏绘制后一次性输出到屏幕，消除闪烁 |
| 缩略图 | EXIF 内嵌缩略图优先 | 读取 KB 级数据、毫秒级完成，而非解码完整原图再缩小 |
| 大图 | 完整原图解码 + Lanczos3 缩放 | 独立 4 线程解码池，最大 4096px，保持宽高比 |
| 后台线程 | `std::thread::spawn` + `mpsc::channel` | 文件扫描、缩略图解码、大图解码均不阻塞 UI |
| 语言/Bindings | Rust + `windows-rs` 0.61 | 性能好、类型安全，Microsoft 官方 Win32 绑定 |

## 失败过的方案

| 方案 | 问题 |
|---|---|
| egui + wgpu | GPU 纹理生命周期验证严格，引用已销毁纹理 → `Validation Error` → panic 崩溃 |
| egui + glow | OpenGL 宽容不崩溃，但纹理槽管理和延迟释放代码复杂度高，布局不灵活 |

## 架构

```
main.rs           — 7 行，crate 入口
window.rs         — ~1500 行，Win32 窗口 + 消息泵 + GDI 双缓冲渲染
  core/
    thumbnail.rs  — EXIF 缩略图提取 + 回退解码缩放（`generate_thumbnail`），以及全分辨率解码（`decode_full_image`）
    image_data.rs — ImageItem / ImageState 数据结构
    file_ops.rs   — 文件扫描、复制、磁盘列表
    grouping.rs   — 颜色直方图 + 余弦相似度分组
```

### 工具栏布局

工具栏按钮位置通过 `toolbar_layout()` 函数统一计算，渲染（`paint_toolbar`）和点击检测（`on_click`）共用同一套布局逻辑，保证点击区域与可视按钮完全对齐。

```
[F 选文件夹] [S 保存] [R 排序] [Space 大图/网格] [点击清空]   共 N 张 | 留存 M 张
```

### 消息处理

```
WM_CREATE     → 初始化状态、创建缩略图 worker 池 + 大图解码 worker 池、启动 30fps 定时器
WM_SIZE       → 重新计算网格列数和单元格大小
WM_ERASEBKGND → 返回 1，阻止系统擦除背景（消除闪烁关键措施之一）
WM_PAINT      → 双缓冲渲染：离屏 DC → 绘制 → BitBlt 一次性到屏幕
WM_TIMER      → 收集扫描/缩略图/大图解码结果，按需设脏标记触发重绘（不再每帧强制刷新）
WM_KEYDOWN    → 键盘快捷键处理（视图模式感知分发，全局快捷键优先于模式分发）
WM_LBUTTONDOWN→ 工具栏按钮 / 网格选中 / 滚动条 / 大图左右半区翻页
WM_MOUSEWHEEL → 网格模式垂直滚动 / 大图模式翻页
WM_DESTROY    → 清理 GDI 资源、退出
```

## 关键设计决策

### 为什么用 GDI 双缓冲而不是直接绘制

**问题**：原实现直接在屏幕 DC 上先 `FillRect` 擦除背景再绘制内容，产生经典的"擦除-重绘"闪烁。叠加 `CS_HREDRAW|CS_VREDRAW` 窗口样式和 30fps 无条件 `InvalidateRect`，闪烁在图片导入阶段尤为严重。

**解决方案（四重防御）**：

1. **`WM_ERASEBKGND` 返回 1**：阻止系统自动用背景刷擦除窗口，避免系统级擦除与手动绘制的竞态闪烁。
2. **双缓冲渲染**：`WM_PAINT` 中创建与屏幕兼容的内存 DC 和位图（`CreateCompatibleDC` + `CreateCompatibleBitmap`），所有绘制操作在内存 DC 上完成，最后一次性 `BitBlt` 到屏幕 DC。用户看到的是完整帧，而非逐步绘制过程。
3. **脏标记 + 按需刷新**：`WM_TIMER` 不再每 33ms 无条件调用 `InvalidateRect`。仅在缩略图/大图解码完成、扫描结果到达、或用户操作时设置 `dirty = true`，timer 发现脏标记后才触发重绘。
4. **窗口样式改为 `CS_OWNDC`**：替代 `CS_HREDRAW|CS_VREDRAW`，窗口大小变化时不再强制全窗口擦除。

### 为什么用 GDI HBITMAP 而不是 GPU 纹理

- **GDI 位图**：`CreateDIBitmap` → 系统内存/显存透明管理 → `DeleteObject` → 立即释放。即使渲染命令引用了已删除的位图，GDI 静默忽略，不会崩溃。
- **GPU 纹理 (wgpu)**：`create_texture` → 显存 → 渲染队列引用 → 验证层严格检查 → 任何引用失效 → panic。图片浏览器场景天然频繁创建/替换纹理，与 wgpu 设计冲突。

### 为什么读 EXIF 缩略图（网格模式）

JPEG 文件头 APP1 标记中通常内嵌 160×120 缩略图（仅几 KB）。直接读取 + 解码这段数据，耗时为毫秒级。传统方案解码 6000×4000 完整原图再缩小到 200px，耗时几百毫秒/张，差距 100 倍以上。

实现：`kamadak-exif` 解析 APP1 → `JPEGInterchangeFormat` 定位缩略图偏移量 → `image` crate 解码小 JPEG → 若尺寸不足则回退到全图解码。

### 大图浏览模式设计

大图浏览模式与缩略图网格共享同一 `ImageState`，通过 `ViewMode` 枚举切换：

- **视图切换**：`Space` 键或工具栏按钮在 `Grid` 和 `FullImage` 间切换。`ESC` 键在大图模式下退回网格视图。
- **大图渲染**：调用 `decode_full_image()` 解码原始全图（最大 4096px），使用 `HALFTONE` 拉伸模式等比缩放适配窗口区域，居中显示。缩放不设上限（`scale` 不 clamp），确保在高分辨率屏幕上填满视图。
- **预加载策略**：切换到大图模式时，预加载当前图片及前后各 2 张（`FULL_PRELOAD_AHEAD = 2`），翻页时触发新一轮预加载。
- **缓存管理**：大图缓存独立于缩略图缓存，容量上限 16 张，超出清理一半。
- **解码线程**：独立的大图解码 worker 池（4 线程），与缩略图 worker 池隔离，避免相互阻塞。
- **翻页方式**：`← →` 键盘键 / 鼠标点击左/右半区 / 鼠标滚轮，均跳过已移除图片。
- **信息叠加**：底部显示文件名、解码分辨率、显示分辨率、评分星级（诊断用，便于区分解码端与渲染端问题）。

### 评分键位设计

评分通过 `key_to_rating(k)` 辅助函数统一解析，同时支持主键盘数字键（`0x30`-`0x35`）和数字小键盘（`0x60`-`0x65`），返回 0-5 的评分值。星级显示公式为 `"★".repeat(rating) + "☆".repeat(5 - rating)`，始终显示 5 颗星，rating=0 为全空、rating=5 为全满。

### 清空操作

工具栏"清空"按钮点击后弹出 `MessageBoxW` 二次确认框（是/否），显示待清空图片数量，默认选中"否"防止误操作。确认后执行 `clear_all()`：重置图片列表、清空缩略图和大图缓存、回到网格视图。

### 导出操作

按 `S` 键或点击工具栏"保存"按钮后弹出文件夹选择对话框（`IFileOpenDialog` + `FOS_PICKFOLDERS`），用户选择目标文件夹后，后台线程复制所有留存图片到该目录。

### 线程模型

- **扫描线程**：文件对话框选择路径后，`thread::spawn` 递归遍历目录，完成后通过 `mpsc::channel` 将路径列表发送给 UI 线程。
- **缩略图 worker 池**：8 个常驻线程，共享请求队列（`Arc<Mutex<Receiver>>`），每个 worker 调用 `generate_thumbnail()` 后将结果发回。
- **大图解码 worker 池**：4 个常驻线程，独立的请求/响应队列，调用 `decode_full_image()` 解码原图（最大 4096px），与缩略图 worker 互不干扰。
- **UI 线程（主线程）**：WM_TIMER 中非阻塞收集所有结果，创建 HBITMAP，按需设脏标记触发重绘。

## 限制

- 单文件最大 100MB
- 最多加载 10,000 张图片
- 文件夹扫描深度最大 5 层
- 缩略图缓存最多 256 张（超出则清理一半旧条目）
- 大图解码最大尺寸 4096px（平衡画质与内存，覆盖 4K 屏幕）
- 大图预加载缓存最多 16 张（超出则清理一半旧条目）
