1创意概述

想解决什么问题

在使用 TRAE、Cursor、GitHub Copilot / Codex 等 AI 编程工具进行 VibeCoding 时，开发者需要频繁在 IDE 与 AI 侧边栏之间切换窗口、重复输入相似提示词（如"优化代码"、"生成测试"、"解释报错"），严重打断编码心流。传统键盘输入长提示词效率低，且缺乏物理反馈，难以进入深度沉浸状态。

灵感来源

日常开发中发现，与 AI 助手的交互 80% 都是重复性的固定指令——每次遇到报错要手动输入 "explain this error"，写完函数要输入 "write tests for this"。这些重复操作本应像 IDE 快捷键一样一键直达，而不是在键盘上敲半天。我们想把"提示词工程"从打字变成按按钮。

产品形态

一款基于 ESP32-S3 的桌面硬件终端，通过 USB / 蓝牙与电脑连接，搭载 OLED 屏幕与四颗实体按键。配套一个轻量级电脑端 Hook Agent，将物理按键映射为预设 Prompt 模板，一键注入 TRAE / Cursor / Codex 等工具的输入框，屏幕实时显示当前连接状态与按键功能。

2目标用户与痛点

核心用户群体

① 使用 TRAE、Cursor、GitHub Copilot / Codex 等工具进行 VibeCoding 的开发者；② 需要频繁与 AI 对话的全栈 / 前端 / 算法工程师；③ 追求极致心流体验、希望减少键盘输入的技术创作者；④ 手部有重复性劳损（RSI）、希望减少打字量的开发者。

使用场景

日常放在键盘旁或显示器底座上，作为 AI 编程的物理控制台。写代码时遇到报错一键发送解释指令；写完函数一键生成单元测试；重构时一键优化性能；屏幕常显当前 IDE 上下文与按键映射。

当前痛点

VibeCoding 时需要在代码编辑器与 AI 侧边栏之间反复切换焦点，平均每次交互耗时 5-10 秒；重复输入相似提示词（refactor / add tests / explain / document）浪费大量时间；提示词工程需要记忆大量模板，新手难以快速上手最佳实践；纯键盘鼠标交互缺乏物理反馈，开发者难以进入并维持深度心流（Flow State）；长时间高频打字导致腕管综合征等重复性劳损。

添加注释选中代码 → 切侧边栏 → 打字 "add JSDoc comments" → 回车（约 9 秒）按一下「文档」键（0.5 秒）

5典型应用场景

1

深夜 Debug：一键解释复杂报错

凌晨两点，项目突然抛出一段晦涩的 Rust 生命周期报错。开发者无需离开编辑器去搜索错误码，直接按下「解释」键，VibeKey 自动捕获终端输出并发送给 AI，3 秒后得到带修复建议的详细解释。

2

重构日：批量性能优化

技术债清理日，开发者需要逐个优化 20 个老旧函数。传统方式每次都要输入 "refactor for performance"。使用 VibeKey 后，选中函数 → 按「优化」键，AI 自动给出性能改进版本，单手操作，全程不离开主编辑器。

3

Code Review 前：补全测试与文档

提交 PR 前发现测试覆盖率不足、文档缺失。按下「测试」键生成 Jest 用例，再按「文档」键补齐 JSDoc。原本 30 分钟的机械劳动，5 分钟完成，且质量稳定。

4

RSI 康复期：减少打字负担

开发者因腕管综合征需减少键盘使用。VibeKey 将高频 AI 交互从"敲 50 个字符"变为"按 1 个键"，单日减少约 5000 次键盘敲击，显著缓解手部压力，同时保持高效产出。
