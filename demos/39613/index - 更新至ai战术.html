📜 游戏规则

🏆

胜负判定

  • 战术胜利：率先赢得5路的一方，游戏结束，获得胜利
  • 战略胜利：双方都无法出牌时，比较双方场上所有牌的最大牌型
  • - 场上所有牌包括：场牌、叠牌、中立区归属卡牌
  • - 中立区归属：某路中立区卡牌数量多的一方获得该路所有卡牌
  • - 双方最大牌型相同时，比较最大牌型中的最大牌点
  • - 还是相同时，双方平局
⚖️

拼点规则

  • 每路比较双方的最大牌点（场牌和叠牌中的最大值）
  • 点数大的一方赢得该路
  • 点数相等时，该路为平局
  • 每次放置卡牌后自动进行拼点判定
🃏

卡牌值系统

  • 3=3点 | 4=4点 ... | 10=10点 | J=11点 | Q=12点 | K=13点 | A=1点 | 2=2点
  • A和K是相邻关系（A可拖K，K可拖A）
🃏

📍

区域规则

  • 路牌区：游戏界面中央区域，从左到右分为5条路，在此区域放置的牌统称为：路牌
  • - （我方路牌按照从上到下顺序排列，对方路牌则是从下到上顺序排列）
  • - （每条路排序第一的路牌，另称为场牌，其他排序的路牌，另称为叠牌）
  • - （每条路≥9张牌时，无法在此路再打出牌）
  •  
  • 中立区：界面中央右侧区域，分为7条路，在此区域放置的牌统称为：中立牌
  • - （每条路双方各自最多放置4张中立牌）
  • - （每条路的中立牌数量多于对方时，那一条路的双方中立牌，全部算入己方牌面，参与牌型组合）
🎯

出牌规则

  • 出牌：双方每回合必须选择一种功能牌打出，完成放置后，自动转入对方回合。
  • - （打出的功能牌算作放置，但在触发匹配操作时，只有取消/执行匹配操作后，才算作放置）
  • - （打出的功能牌无论放置在哪，都在本回合其打出的那一路重新计算拼点）
  •  
  • 手牌：6张，仅己方可见，点击即打出
  • - （手牌只能按照路牌区从左到右的空位顺序打出）
  •  
  • 牌堆：初始26张，双方不可见，点击即抽牌打出
  • - （从牌堆抽取的牌只能按照路牌区从左到右的空位顺序打出）
  •  
  • 明牌：3张，双方可见，点击选择一路空位打出或叠加打出
  • - （明牌可以选择路牌区从左到右的空位顺序打出，也可以选择在已有牌的路后叠加打出）
  •  
  • 暗牌：5张，双方不可见，点击选择一路叠加打出
  • - （暗牌只能在已有牌的路后叠加打出）
  •  
  • 终止出牌：在己方回合可选择终止出牌
  • - 条件：没有可打出的牌
  • - 效果：终止后轮到对方出牌，双方都终止时按战略胜利判定
⚔️

匹配操作规则

  • 拖牌：拖取对路的相邻牌点
    • 条件：刚打出的牌点与对路牌点相邻（差1），A与K相邻
    效果：双方匹配的那两张牌点都移入各自的中立区
    示例：打出6拖7、打出J拖Q、打出A拖K、打出K拖A
  • 撞牌：与对路的相同牌点对撞
    • 条件：刚打出的牌点与对路牌点相同
    效果：双方匹配的那两张牌点都移入各自的中立区，该路剩余所有卡牌消失
    示例：打出8撞8、打出K撞K
  • 援牌：将打出的相邻/相同牌点移入中立区
    • 条件1：刚打出的牌点与我方中立牌点相邻（且那一路，对方没有其他同点的中立牌）
    条件2：刚打出的牌点与我方中立牌点相同（且那一路，对方没有其他不同点的中立牌）
    效果：从路牌区去除刚打出的牌，移入我方中立区
    示例1：打出8，移入（6-7）那一路形成（6-7-8）
    示例2：打出Q，移入（Q-Q）那一路形成（Q-Q-Q）
  • 围牌：用相邻/相同牌点转移中立牌
    • 条件1：刚打出的牌点与对方中立牌点相邻（且那一路，我方没有其他同点的中立牌）
    条件2：刚打出的牌点与对方中立牌点相同（且那一路，我方没有其他不同点的中立牌）
    效果：清空中立区该路双方卡牌，全部移入玩家刚打出的牌的同一路
    示例1：打出5，转移（6-7）至5的那一路
    示例2：打出A，转移（A-A）至A的那一路

    • 【路牌匹配流程】：
    • 1. 用户点击手牌/明牌/暗牌/牌堆 → 选择放置位置
    • 2. 卡牌移动动画完成 → 调用 updateUI() 更新界面
    • 3. 调用 checkRoadMatchCards(card, roadIndex) 检测匹配
    • 4. 遍历 GameState.opponentField[roadIndex] 和 GameState.opponentStack[roadIndex]
    • 5. 对每张对方路牌调用 checkMatchType(card.value, opponentCard.value)
    • 6. 收集匹配机会 → 调用 showRoadMatchOpportunities() 显示光环
    •  
    • 【点数匹配判定（checkMatchType）】：
    • - 拖牌'drag'：Math.abs(v1-v2) === 1 || (v1===1 && v2===13) || (v1===13 && v2===1)
    • - 撞牌'crash'：v1 === v2
    •  
    • 拖牌（performRoadMatch → 'drag'）：
    • - 条件：刚打出的牌与对方同一路的牌点数相邻（A-K相邻）
    • - 数据操作：GameState.playerField[ri] = null（移除在场牌区的匹配牌），从 playerStack[si] 移除在叠牌区的匹配牌
    • - 数据操作：对方同理，从 opponentField/opponentStack 移除匹配牌
    • - 数据操作：双方匹配牌 push 进各自的 playerNeutralCards/opponentNeutralCards[findEmptyNeutralSlot()]
    • - 后续：updateUI() → checkRoadResult(roadIndex) → safeSwitchTurn()
    •  
    • 撞牌（performRoadMatch → 'crash'）：
    • - 条件：刚打出的牌与对方同一路的牌点数相同
    • - 数据操作：双方匹配牌 push 进各自中立区
    • - 数据操作：GameState.playerField[ri] = null; GameState.playerStack[ri] = [];（清空我方该路）
    • - 数据操作：对方同理清空 opponentField 和 opponentStack
    • - 后续：updateUI() → checkRoadResult(roadIndex) → safeSwitchTurn()
    •  
    • 匹配光环显示（showRoadMatchOpportunities）：
    • - 选择器：'.card, .card-small, div[style*="background"]'
    • - 查找策略：优先按内容匹配（textContent === card.display），其次按位置索引
    • - 样式：.match-glow 金色双圈闪烁，box-shadow: 0 0 0 3px #ffd700, 0 0 30px 10px rgba(255, 215, 0, 0.5)
    • - 悬停：animation-play-state: paused + transform scale(1.05)
    • - 点击：performRoadMatch(matchType, opponentCard, playerCard, roadIndex, location, stackIndex)
    • - 取消：document.addEventListener('click') 检测点击非光环区域时 clearRoadMatchHighlights() → confirmCardPlacement()
    •  
    • 【中立区匹配流程（checkNeutralAdjacentCards）】：
    • - 触发时机：路牌匹配后无匹配机会，则检测中立区（checkRoadMatchCards 后调用）
    • - 遍历范围：7路中立区（i=0-6），分别调用 canSupportCard 和 canSurroundCard
    • - 匹配标记：调用 showNeutralAura() 在我方/对方中立区该路位置显示金色光环
    •  
    • 援牌条件（canSupportCard → support）：
    • - 前置：playerNeutral[i].length > 0 且 playerNeutral[i].length < 4
    • - 条件A（相邻援）：刚打出牌与中立区顶牌点数相邻 && opponentNeutral[i] 无相同点数
    • - 条件B（相同援）：刚打出牌与中立区顶牌点数相同 && opponentNeutral[i] 无不同点数（或 opponentNeutral 为空）
    • - 通用条件：[...playerNeutral[i], ...opponentNeutral[i]] 所有 value 集合无重复
    •  
    • 围牌条件（canSurroundCard → 'surround'）：
    • - 前置：opponentNeutral[i].length > 0
    • - 条件A（相邻围）：刚打出牌与对方中立区顶牌点数相邻 && playerNeutral[i] 无相同点数
    • - 条件B（相同围）：刚打出牌与对方中立区顶牌点数相同 && playerNeutral[i] 无不同点数（或 playerNeutral 为空）
    • - 通用条件：[...playerNeutral[i], ...opponentNeutral[i]] 所有 value 集合无重复

    • 【执行操作（performNeutralAction）】：
    • - 'support' 援牌：根据 lastPlayedCard.index 和 card.id 定位刚打出的牌位置
    • - 若在 playerField[targetRoadIndex].id === card.id：playerField[targetRoadIndex] = null
    • - 若在 playerStack：splice 移除。然后 card push 进 playerNeutralCards[neutralIndex]
    • - 后续：updateUI() → checkRoadResult(roadIndex) → safeSwitchTurn()
    •  
    • - 'surround' 围牌：根据 lastPlayedCard.index 定位玩家打出牌的路
    • - playerNeutralCards[neutralIndex] 和 opponentNeutralCards[neutralIndex] 所有牌 push 进 playerStack[targetRoadIndex]
    • - 然后 playerNeutralCards[neutralIndex] = []; opponentNeutralCards[neutralIndex] = [];（刚打出的牌仍留存在路牌区）
    • - 后续：updateUI() → checkRoadResult(targetRoadIndex) → safeSwitchTurn()

    • - 中立区取消：neutralCancelHandler 类似全局监听，非 neutral-aura 则 clearNeutralAuras() → checkRoadResult(lastPlayedCard.index) → safeSwitchTurn()

    【总原则】
    • 1. ai方的路牌区存在空位时，每次出牌始终从手牌策略1.0开始执行条件
    • 2. ai根据优先级顺序执行策略，1.0、2.0、3.0、4.0是阶，1.1、1.2、1.3...是级
    • 3. ai方当前优先级条件不满足时，自动转入下一级策略；最后一级策略无法执行时，自动转入下一阶策略
    • 4. ai方自动转入下一阶策略时，从X.1策略开始执行（如：自动转入牌堆策略时，从2.1策略开始执行）
    • 5. ai方每次出牌根据上回合打出/放置的功能牌类型，从同类策略X.0开始执行（如：上回合打出的是明牌，则此次从明牌策略3.0开始执行）
    • 6. ai方任意一种功能牌=0时，不影响转入策略，继续按照优先级执行即可
    1.0 【手牌策略】
    防守： （ai方劣势路=3时，且明牌数>0时，转入明牌3.5策略）
    隐忍： （ai方优势路=3时，且路牌区空位=1时，且手牌保留"花牌"时，转入明牌3.1策略）"花牌"：JQK
    1.1： ai方即将出牌的位置，其对路无牌时，随机放置≥8点的手牌
    1.2： ai方即将出牌的位置，其对路有牌时，"放置"可以让此路获胜的手牌；"放置"：不执行匹配操作
    1.3： ai方即将出牌的位置，其对路有牌时，打出可以触发匹配操作的"手牌"；此"手牌"需要具备以下条件之一，否则跳过此策略
    • 拖走对方此路的最大牌点
    • 围牌增加我方此路最大牌点并获得优势
    • 撞牌
    1.4： （ai方优势路=4时，且明牌数>0时，转入明牌3.1策略）
    2.0 【牌堆策略】
    2.1： ai方的路牌区有空位时，抽取牌堆打出（此牌堆未使得此路获胜时，转入下方备注）
    备注：此牌堆可以触发匹配操作时，具备以下条件之一则执行匹配操作，没有则不执行
    • 拖走对方此路的最大牌点
    • 围牌增加我方此路最大牌点
    • 撞牌
    3.0 【明牌策略】
    防守： （ai方劣势路≥3时，转入明牌3.5策略）
    3.1： ai方在未获胜的那些路中，选择对方牌点最大的一路，放置可以让此路获胜的明牌
    3.2： ai方在未获胜路，打出可以执行匹配操作的明牌；此明牌需要具备以下条件之一，否则跳过此策略
    • 围牌增加我方此路最大牌点并获得优势
    • 拖走对方此路的最大牌点
    • 撞牌
    3.3： ai方有暗牌时，转入暗牌4.1策略
    3.4： ai方在未获胜路中，放置明牌
    3.5： ai方在劣势路中，选择对方最大牌点中最小的一路，放置可以让此路平势/优势的明牌
    3.6： ai方在劣势路中，打出可以执行匹配操作的明牌；此明牌需要具备以下条件之一，否则跳过此策略
    • 拖走对方此路的最大牌点
    • 围牌增加我方此路最大牌点并获得优势
    • 撞牌
    3.7： ai方转入暗牌4.3策略（无条件）
    3.8： ai方在劣势路中，放置明牌
    4.0 【暗牌策略】
    防守： （ai方劣势路≥3时，转入暗牌4.3策略）
    进攻： （ai方优势路≥3时，转入明牌3.1策略）
    4.1： ai方在未获胜路中选择对方牌点最大的一路，打出暗牌（若此暗牌可以触发匹配操作，则转入备注）
    备注：此暗牌未使得此路获胜时（暗牌点数 ≤ 对方此路最大牌点），检查以下条件，满足其中之一则执行匹配操作，没有则不执行
    • 围牌增加我方此路最大牌点
    • 拖走对方此路的最大牌点
    • 撞牌
    4.2： ai方转入明牌3.1策略
    4.3： ai方路牌区空位≥1时，转入手牌1.1策略
    4.4： ai方在劣势路中优先选择对方最大牌点≤6的一路/次选不同牌点数量≥5的一路/末选最大牌点中最小的一路，打出暗牌（此暗牌未使得此路平势/优势时，转入下方备注）
    备注：此暗牌可以触发匹配操作时，具备以下条件之一则执行匹配操作，没有则不执行
    • 拖走对方此路的最大牌点
    • 围牌增加我方此路最大牌点
    • 撞牌
    4.5： ai方转入明牌3.8策略

    1阶(手牌) → 2阶(牌堆) → 3阶(明牌) → 4阶(暗牌)
