AI · PRD · Protocol

PRD 写得再用心，
AI 也读不懂。

AI 进入开发工作流的真正卡点，不在 AI 本身，在 PRD——准确地说，在 PRD 中「逻辑」与「页面元素」未结构化关联的那一层。

看 60 秒对比 → 了解修正层

核心命题

如何解决开发流程中，AI无法正确理解产品经理的上下文的问题

PM 脑子里的上下文——为什么这么设计、为什么这么改、为什么是这个流程——写不进文字里。AI 拿到的只有字面，于是只能猜。猜出来的答案，因模型、prompt、上下文而完全不同。
60 秒对比 · 同一段需求

散文 PRD vs 结构化协议

下面是一个真实的 PM 写得"已经很认真"的 PRD 段：登录页。同一段输入，左右并列看两种工作流下 AI 给出什么。

A · 无 SolarWire

PM 写的需求 · 散文版

自然语言 · 无结构 · AI 只能猜

页面登录页，包含账号、密码输入框和登录按钮。

逻辑点击登录后进行账号密码校验，校验通过则登录成功，跳转到首页；校验失败给出错误提示。

样式风格简洁，符合公司主品牌色。

AI 拿到的"输入"长这样
  • "点击登录"——指的是页面上哪一个按钮？登录 / 忘记密码 / 注册，三选一
  • "校验通过"——AI 怎么知道什么时候调后端、什么时候只读前端？
  • "错误提示"——显示在密码框下方、表单顶部、还是全屏 toast？
  • "风格简洁"——AI 怎么还原 PM 脑子里的主品牌色？
结果：同一段散文 PRD，三个 AI 给出三份不同代码——这不是 AI 不行，是输入里没有机器能读的结构。
B · 有 SolarWire

同一段需求 · 协议化

.md 内嵌协议代码块 · 元素与逻辑一一对应

结论：同一段需求，写成结构化协议之后，元素 ID、行为触发条件、错误显示位置、API 端点全部结构化。AI 不再"猜"，直接基于源文件生成代码。1 份源文件 = 1 份实现。
工作流 · 3 步

从需求到代码的最短路径

PM 写一份带结构化代码块的 .md，AI 读、AI 改、AI 生成代码——三步闭环。

STEP 01

PM 写带结构的 PRD

在 .md 中嵌入协议代码块，把元素、坐标、行为用结构化的 note 写清。

  • 不切换工具，沿用 Markdown
  • 行为挂在元素上，无歧义
  • 逻辑、状态、异常分支结构化
STEP 02

AI 读懂 + 改对

AI 不再"猜按钮挂哪"。协议让「逻辑」和「元素」在机器可读的层面强绑定。

  • 存量项目：代码反推 PRD
  • 增量更新而非全量重写
  • 三方对"哪个按钮"理解一致
→
STEP 03

产出代码 / 测试

基于结构化源文件，AI 直接生成对齐设计稿的代码、测试用例与组件。

  • 三方对"哪个按钮"理解一致
  • PRD 成为可执行文档
修正层 · The Correction Layer

协议够用吗？不够。中间还差一层修正工具

AI 写协议化 PRD 时会自己"出问题"。PM 手写协议又太技术化。这一层修正工具，让人和 AI 能在同一份源文件上协作，互相修正。

AI 原生问题

把协议丢给 AI 写时，AI 会自己出错
  • 1省略元素

    复杂页面里 AI 会漏画部分元素，文件能解析但视觉残缺。

  • 2简化 note

    把 EARS 风格的精确约束写成一句笼统的话，关键边界条件丢失。

  • 3编造属性

    AI 会写出协议里根本没有的属性，文件直接解析失败。

  • 4语法错误

    偶尔直接生成不合法的语法错误的代码，整页都打不开。

→

可视化编辑器如何修正

把人和 AI 拉回同一份源文件上协作
  • 1漏画 → 一眼看见

    AI 写完直接打开在编辑器里，漏掉的元素在画布上肉眼可见，PM 补上即可。

  • 2简化的 note → 结构化模板

    note 用结构化表单填，逼出 AI 容易漏写的边界条件与异常分支。

  • 3编造的属性 → 实时校验

    编辑器严格校验协议允许的属性集合，错的属性实时标红，PM 一秒定位。

  • 4语法错误 → 错误面板 + 可视化拖拽

    错误集中到错误面板；PM 也可以用拖拽和点击直接组合页面，绕开手写语法这道坎。

三件套 · 围绕协议的三层

协议 + 修正工具 + 协作版

三件套彼此独立：协议是机器读得懂的文档，编辑器是人和 AI 协作的修正层，协作版让团队共用同一份源文件。任何一层都可以被第三方重新实现。

协议 / Protocol

线框图 + 逻辑 = 同一份文件

让"逻辑"和"页面元素"在机器可读的层面强绑定。AI 不再"猜按钮挂哪"。

  • 写在 .md 的协议代码块
  • 行为挂在元素上
  • 人、AI、开发三方同源
修正工具 / Editor

可视化编辑器

人和 AI 之间的修正层。PM 拖拽组合页面，系统产出合法协议；AI 写的草案被可视化呈现，PM 一眼看见问题、快速修正。

  • 拖拽即写，绕开学语法
  • 错误实时标红
  • note 结构化表单
协作版 / Server

团队共用同一份源文件

把协议+编辑器的能力放到团队层面：本地与远程部署都支持，适合 demo、评审、分享。

  • 本地 / 远程均可
  • 团队共用 workspace
  • 适合 demo / 评审 / 分享
