CORE CONCEPT · 核心理念

让 AI 像人一样
看屏幕 · 想策略 · 动手操作

视觉 AI 理解当前画面场景与可交互元素 → 操作 AI 基于场景和目标决策下一步 → 执行器模拟键盘鼠标完成操作。
全程不触碰游戏内存，完全基于屏幕图像和 UI 控件树进行外部观测。

👁️ 视觉 AI → 🧠 操作 AI → ⚙️ 执行器 → 🎮 游戏
ARCHITECTURE · 系统架构

双 AI 协同 · 四层管线

// 01
👁️

视觉 AI

截图分析 → 场景识别（12 种界面类型：大世界 / 战斗 / 对话 / 菜单 / 地图 / 加载 / 商店 / 设置等）+ 可交互元素坐标提取。返回标准化 JSON 结构，驱动后续决策。

// 02
🧠

操作 AI

基于场景和任务目标 → 输出操作指令序列（键鼠操作 / 等待 / 脚本调用 / 操作包 / 寻路 / 操作队列）。支持操作计划制定与验证，每步注入计划进度避免偏航。

// 03
⚙️

执行管线

操作队列批量执行 + 条件检查链（dHash 变化 / 场景切换 / 时间间隔）+ 自适应截图延迟（画面稳定即继续，省 50–70% 等待）+ 预截图管线（AI 处理时后台预截下一帧）。

// 04
📦

记忆与缓存

N-gram 操作模式预测（高置信度直接执行跳过 AI）+ 子 Agent 异步并行派发（路径规划 / 战斗反应不阻塞主循环）+ AI 脚本工厂（自主设计 / 生成 / 优化脚本）+ 安全数据层。

CONTINUITY · 操作连续性

操作管线 + 预截图 + 预测缓存

AI 处理耗时 3–8 秒，期间玩家只能干等。我们用四重机制把等待压缩到极限：

截图 → 视觉 AI → 操作队列 → 条件检查 → 执行

SAFETY · 安全第一

不碰内存，也能拿到游戏数据

  • ✦
    UIAutomation 控件树通过 ctypes 调用 Windows 辅助功能 API，读取游戏窗口的控件属性树，获取按钮 / 面板 / 文本等 UI 元素信息
  • ✦
    像素探针系统在屏幕固定坐标设置虚拟探针，监控血量条颜色、加载条进度、任务标记高亮等关键 UI 状态变化
  • ✦
    OCR 文字识别使用 Tesseract OCR 识别屏幕文字，提取任务目标、坐标、对话内容、物品数量等文本信息
  • ✦
    小地图 SIFT 匹配使用 OpenCV SIFT 特征点匹配小地图截图与预存地图区块，精确定位玩家在世界中的坐标
  • ✦
    游戏日志解析读取游戏输出日志文件（如 output_log.txt），获取战斗数据、掉落记录等结构化信息
🛡️

安全数据层

完整的内存抓取替代方案，已在项目中实现并集成测试。五种数据获取方式全部基于外部观测，100% 不触碰游戏进程内存。

符合游戏公平原则，不触发反作弊系统。
