创意介绍

从"单轮工具调用"向"多轮有状态对话智能体"的架构升级

🎯

想解决什么问题

求职者在简历优化和面试准备环节缺乏即时、个性化、多轮对话式的智能辅导——现有工具多为单轮模板生成，无法理解上下文、无法追问、无法模拟真实面试闭环。

💡

为什么会想到做这个

在构建企业级 Agent 系统的过程中，深刻体会到"有状态多轮对话"相比"单轮 API 调用"的质变优势。将这套多智能体工程能力降维到求职场景，可以让每个求职者拥有一位 7×24 在线的 AI 面试官和简历顾问。

📱

大概是什么产品

一个 Web 应用（FastAPI 后端 + 原生 HTML/JS 前端），用户通过浏览器上传简历/PDF/图片，粘贴岗位 JD，系统自动进行结构化提取、匹配分析、模拟面试，全程 SSE 流式输出，支持多轮对话与历史会话恢复。

⚙️

核心技术亮点

Supervisor + Expert 多智能体编排引擎、RAG 检索智能降级、分层上下文裁剪（token 开销降低 60%）、模拟面试有状态闭环、多级缓存体系、Docker 一键部署 + PostgreSQL 双层持久化。

八大核心能力

从检索增强到面试模拟的全链路覆盖

🧠

多智能体编排引擎

基于 LangGraph StateGraph 构建"意图识别→专家分发→结果审查→循环控制"有向图执行引擎，受控 ReAct fallback 层处理非标准组合请求，支持工具白名单与 handoff 回切。

🔍

RAG 检索与智能降级

KB 语义检索→相关性评估→自动降级 Web Search 的自适应链路。多查询 JD 召回策略（岗位+技能组合/技能子集/语义补充三层查询）与全局去重排序。

⚡

全链路 SSE 流式输出

所有分析路径统一为 SSE 事件流，extracted→sources→token*→done 分阶段事件协议。asyncio.to_thread() 桥接同步阻塞调用，解决事件循环阻塞问题。

✂️

分层上下文裁剪

System Prompt 保留 + 早期消息规则化压缩为摘要 + 最近 N 条完整保留，摘要跨轮次累积注入 system prompt，长对话上下文以摘要形式保留，token 开销降低 60%。

💾

多级缓存体系

Expert 级结果缓存（task_type + question_signature + question_hash 复合键）与 ReAct tool-cache 两层缓存，追问场景响应效率显著提升。

🎤

模拟面试有状态闭环

LangGraph Checkpointer 跨轮次持久化，出题→用户回答→实时评分→逐题反馈→下一题→总结复盘完整状态机，支持语音输入与面试进度追踪。

📄

多模态文档解析

文件类型路由器自动分发 PDF/图片/文本，PyMuPDF 提取文本，GLM-4V 视觉模型实现图片简历 OCR + 语义理解，结构化提取作为下游标准化输入。

🗄️

PostgreSQL 双层持久化

AsyncPostgresSaver 持久化 checkpoint + 知识库元数据/Expert 缓存独立存储，Docker 部署下容器重启数据零丢失，支持会话历史恢复。
