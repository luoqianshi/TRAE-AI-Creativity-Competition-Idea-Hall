一项目概述

1.1 产品愿景

一款面向创作者的智能写作工具，将专业码字体验与AI智能辅助深度融合。用户不仅可以用它完成日常写作，还能灵活地为AI"换装"——挂载不同的提示词与技能，让AI成为可以讨论章节、梳理人物、完善世界观的智能创作伙伴。

1.2 核心特性

📝
码字编辑器
作品管理、章节组织、大纲视图、人物/世界观资料卡、字数统计、草稿/修订模式
🤖
AI聊天
单聊模式（与一个AI对话）、群聊模式（多个AI角色圆桌讨论）
🎛️
AI配置
多API提供商切换（OpenAI / DeepSeek / 通义千问 / 本地Ollama等）、模型选择、参数调节
💡
提示词系统
预设提示词模板库、用户自定义提示词、分类管理、一键挂载
🔧
Skills系统
AI技能包（角色塑造、情节推演、风格润色等）、可组合挂载、JSON配置驱动
📖
章节扫描
AI扫描指定章节内容，生成摘要、提取关键信息、提出改进建议
💬
章节讨论
基于扫描结果，用户与AI就该章节进行讨论式创作

1.3 目标用户

  • 网络小说作者（主力用户）
  • 剧本/编剧创作者
  • 自媒体文案撰稿人
  • 需要AI辅助的内容创作者

五AI服务插件化接入层设计

5.1 核心接口抽象（位于 core-network 模块）

/**
 * AI聊天服务统一接口
 * 所有API提供商必须实现此接口
 */
interface AiChatService {

    /** 提供商类型标识 */
    val providerType: AiProviderType

    /** 获取该提供商支持的模型列表 */
    suspend fun getSupportedModels(): List<AiModel>

    /**
     * 发送消息并等待完整响应（非流式）
     */
    suspend fun sendMessage(
        messages: List<ChatMessage>,
        config: AiGenerationConfig
    ): Result<ChatResponse>

    /**
     * 发送消息并返回流式响应（SSE）
     * 返回Flow，每一个item是一段增量文本
     */
    suspend fun sendMessageStream(
        messages: List<ChatMessage>,
        config: AiGenerationConfig
    ): Flow<StreamChunk>

    /** 测试API连接是否正常 */
    suspend fun testConnection(config: AiProviderConfig): Result<Unit>
}

/**
 * AI服务工厂 - 运行时动态创建服务实例
 */
interface AiServiceFactory {
    fun createService(provider: AiProviderConfig): AiChatService
}

5.2 数据传输对象（DTOs）

/** 聊天消息结构（与API格式无关的内部表示） */
data class ChatMessage(
    val role: MessageRole,      // SYSTEM / USER / ASSISTANT
    val content: String,
    val name: String? = null    // 多角色对话时的身份标签
)

/** AI生成配置 */
data class AiGenerationConfig(
    val model: String,
    val temperature: Float = 0.7f,
    val topP: Float = 1.0f,
    val maxTokens: Int = 2000,
    val stream: Boolean = true
)

/** 流式响应片段 */
data class StreamChunk(
    val deltaText: String,      // 本次增量文本
    val isFinished: Boolean,     // 是否结束
    val finishReason: String?    // 结束原因
)

/** AI服务提供商类型枚举 */
enum class AiProviderType {
    OPENAI, DEEPSEEK, QWEN, GLM, OLLAMA, CUSTOM
}

5.4 提示词处理管道（Prompt Pipeline）

流程：用户输入 → 变量解析 → Skills注入 → 上下文拼接 → 发送到AI

用户消息 "帮我分析第三章的情节节奏" │ ▼ [步骤1] 变量占位符替换 ├─ ${book.title} → "《星河彼岸》" ├─ ${chapter.title} → "第三章 风暴前夕" └─ ${character.xxx} → 人物信息 │ ▼ [步骤2] Skills注入（按优先级排序） ├─ Skill "角色一致性检查" → 在system prompt追加片段 ├─ Skill "情节节奏分析" → 追加分析框架 └─ Skill "风格保持提醒" → 追加风格约束 │ ▼ [步骤3] 上下文拼接（章节扫描结果） └─ 将 chapter.content / chapter.summary 拼接到消息上下文 │ ▼ [步骤4] 构建 ChatMessage 列表 ├─ SYSTEM: (组合后的系统提示词) ├─ USER: (处理后的用户消息 + 上下文引用) └─ 发送 → AiChatService.sendMessageStream()

5.5 本地加密存储

API Key 等敏感信息使用 AndroidX Security Crypto 加密存储：

  • 加密算法：AES-256-GCM
  • 密钥存储：Android Keystore（系统级安全）
  • 存储位置：EncryptedSharedPreferences 或 Room 字段级加密

  • 大文本性能优化：使用 BasicTextField 而非 TextField，自定义 TextRange 处理，避免长文本重绘

  • 字数统计：CJK字符 + 英文单词混合统计（对中文作者友好）

七AI聊天与群聊模块设计

7.1 模块目标（feature-chat）

提供类 ChatGPT 的对话体验，支持单聊（一个AI角色）和群聊（多个AI角色同台讨论）两种模式。

7.2 单聊模式（SINGLE）

UI设计：

ConversationScreen (单聊) ├── TopAppBar │ ├── AI角色头像 + 名称（显示当前挂载的Prompt） │ └── 当前模型信息 │ ├── LazyColumn (消息列表) │ ├── MessageBubble (用户消息 - 右侧/浅色) │ └── MessageBubble (AI消息 - 左侧/深色 + 流式打字效果) │ └── InputBar ├── 文本输入框（支持多行） ├── 📎 按钮（挂载章节/人物/设定为上下文） └── 发送按钮

核心交互：

  • 流式输出：每收到一个 token 增量，立即更新UI（通过 Flow.collectAsState）
  • 上下文引用：点击📎可选择将作品、章节、人物卡片作为上下文注入
  • 消息操作：长按复制 / 重新生成 / 删除 / 转发到其他会话

7.3 群聊模式（GROUP）

设计思路：一个用户 + 多个AI角色，每个AI角色有独立的Prompt/Skills配置。

核心数据结构：

data class GroupChatConfig(
    val aiAgents: List<AiAgent>,    // 群聊中的AI角色列表
    val discussionTopic: String,    // 讨论主题
    val turnStrategy: TurnStrategy  // 发言策略：轮流/自由/指定
)

data class AiAgent(
    val name: String,               // 角色名称（如"主编"）
    val avatar: String,             // 头像
    val promptId: Long,             // 使用的提示词
    val skillIds: List<Long>,       // 挂载的Skills
    val persona: String             // 人设描述（"你是一名资深网络文学编辑…"）
)

enum class TurnStrategy {
    ROUND_ROBIN,    // 轮次发言
    FREE,           // 自由（用户指定谁发言）
    CHAIRMAN        // 主持人模式（一个AI主持，调用其他AI发言）
}

群聊消息流示例：

[用户] → "大家讨论一下第三章的结尾是否需要调整" │ ▼ (ROUND_ROBIN 模式) [AI-主编-张编辑] → "第三章节奏偏慢，结尾悬念不足…" │ ▼ [AI-角色顾问-小林] → "主角在第三章的动机不够明确，建议增加内心戏…" │ ▼ [AI-情节规划师] → "如果把第三章结尾改为伏笔，第四章揭示…"

7.4 消息持久化与加载策略

  • 分页加载：消息列表使用 Paging 3，默认加载最新50条，向上滚动时追加历史
  • 流式消息临时状态：正在生成的消息不立即写入DB，待完整接收后持久化
  • 上下文截断：当消息历史超过模型token上限时，自动裁剪早期消息（保留System Prompt和最近N条）

8.2 Skills系统设计

概念定义：Skills是可组合的提示词片段，比完整Prompts更轻量，用于给AI增加特定"能力"。

核心数据结构：

@Entity(tableName = "skills")
data class Skill(
    @PrimaryKey(autoGenerate = true) val id: Long = 0,
    val name: String,                          // "时间线一致性检查"
    val description: String,                   // "确保情节符合已设定的时间线"
    val promptFragment: String,                // 注入的提示词片段
    val triggerCondition: SkillTrigger? = null, // 触发条件
    val category: String,                      // "时间线/人物/情节/风格"
    val enabled: Boolean = true,
    val priority: Int = 0                      // 注入顺序
)

/** 触发条件 - 可扩展 */
sealed class SkillTrigger {
    object Always : SkillTrigger()             // 总是触发
    data class Keyword(val keywords: List<String>) : SkillTrigger()  // 含关键词时触发
    data class ContextHas(val type: String) : SkillTrigger()        // 上下文包含某类型数据时触发
}

发送消息前执行 Pipeline: System Prompt (来自选中的Prompt模板) + [Skill 1 - 角色一致性守卫] prompt_fragment + [Skill 2 - 时间线检查] prompt_fragment + [Skill 3 - 结构化输出] prompt_fragment + 用户消息（经变量替换后的内容） + 上下文章节内容（如有） ↓ 合成 → 发送给 AI API

9.4 上下文引用与动态注入

当用户在讨论中追问时，系统自动将章节扫描结果和相关资料拼接到消息上下文，让AI"记得"正在讨论的内容。

/** 讨论场景下的消息构建器 */
class DiscussionMessageBuilder {
    fun buildMessages(
        chapter: Chapter,
        discussion: Discussion,
        userMessage: String,
        attachedPrompts: List<Prompt>
    ): List<ChatMessage> {
        return buildList {
            // 1. 系统提示词（组合Prompt + Skills）
            add(ChatMessage(role = SYSTEM, content = buildSystemPrompt(attachedPrompts)))

            // 2. 注入章节内容
            add(ChatMessage(
                role = USER,
                content = "当前讨论的章节：\n标题：${chapter.title}\n内容：${chapter.content}"
            ))

            // 3. 注入扫描结果（如果已扫描）
            discussion.scanSummary?.let {
                add(ChatMessage(role = USER, content = "章节分析：$it"))
            }

            // 4. 用户的当前问题
            add(ChatMessage(role = USER, content = userMessage))
        }
    }
}
