痛点场景

多 Agent 协作的三重困境

AI 编程进入多 Agent 并行阶段。开发者可能同时让不同 Agent 编写功能、修复 Bug、审查代码， 但任务分散在终端和 IDE 窗口中——人往往不能及时发现某个 Agent 正在等待。

⏳

看不见的等待

Agent 已停止推进，等待权限批准、问题回答或工具确认，但开发者正盯着另一个窗口写代码，协作实际已经停滞。

$ agent-b --fix login ⚠ awaiting permission: rm -rf node_modules ⠋ [等待中...已 4 分 12 秒]
🔀

找不到的失败

某个 Agent 工具执行失败、被异常阻塞或长期无响应，错误埋在终端滚动日志里，开发者完全没察觉。

[ERROR] tool_call_failed ✗ src/auth.ts → permission denied （这条错误出现在 200 行日志中间）
🪟

切不完的窗口

5 个终端 Tab + 3 个 IDE 窗口 + 多个子 Agent 会话，恢复一个任务要先回想"它在哪个窗口"，心流反复被打断。

⌘ Tab → ⌘ 1 → ⌘ 2 → ⌘ 3 "刚刚那个权限请求，到底在哪个标签页？"
Agent Flow 任务流

以工作目录聚合的协作状态视图

Agent Flow 以工作目录为单位聚合主 Agent 与子 Agent， 把"工作中、等待人工输入、等待权限、工具失败、已完成"转化为清晰的协作状态， 并按优先级给出阻塞清单，支持一键跳转至对应会话恢复任务。

核心功能

从窗口混战到可干预的任务团队

Agent Flow 不止是状态展示，而是一套围绕"阻塞优先"的协作干预机制： 让你优先处理真正阻塞项目推进的事项，在不打断心流的情况下恢复协作。

01

工作目录级聚合

以工作目录为单位聚合主 Agent 与子 Agent，不再按终端窗口或 IDE 标签页散落。同一项目的所有并行任务在一张视图内呈现。

目录聚合主子 Agent
02

五态协作状态

把"工作中、等待人工输入、等待权限、工具失败、已完成"统一映射为清晰的协作状态，颜色与图标即看即懂。

状态机视觉映射
03

优先级阻塞清单

所有阻塞事项按优先级排列，标注阻塞原因（权限 / 问题 / 失败 / 无响应），让你一眼看见"接下来最该处理什么"。

优先级阻塞归因
04

一键跳转恢复

点击清单条目或会话卡片，直接跳转至对应终端 Tab 或 IDE 窗口的精确位置，免去回忆与查找，立即恢复任务。

窗口跳转Tab 级精度
05

子 Agent 嵌套

主 Agent 派生的子 Agent 以缩进形式显示在父会话下，支持展开收起，呈现真实的任务派发与依赖关系。

嵌套视图派生关系
06

无响应探活

对长期无事件输出的 Agent 进行探活，主动提示"疑似卡死"，避免错误埋在日志深处被忽略。

探活卡死预警
使用流程

四步走完一次协作干预

从看见全局到恢复任务，开发者无需离开当前思路，即可在数秒内完成一次跨 Agent 的协作干预。

1

瞥见全局

鼠标悬停灵动岛展开面板，看见当前项目所有 Agent 的协作状态。

2

识别阻塞

查看优先级阻塞清单，明确哪一项最影响项目推进。

3

一键跳转

点击清单条目，自动跳转至对应终端 Tab 或 IDE 窗口位置。

4

恢复协作

在原会话上下文中批准权限或回答问题，Agent 继续推进。

价值总结

让多 AI Agent 从窗口混战升级为任务团队

Agent Flow 让 macOS 顶部那颗小小的灵动岛，承担起整个 AI 编程工作流的指挥台角色。

01

全局可视

从多个终端和 IDE 窗口中，快速看见当前项目的全局任务状态与阻塞分布。

02

阻塞优先

优先处理真正阻塞项目推进的事项，而不是被无关日志或已完成任务干扰注意力。

03

心流不打断

在不切换思维上下文的前提下，一键恢复某个 Agent 的协作，保持当前编码节奏。

04

任务团队化

让多个 AI Agent 从零散的工具调用，升级为可观察、可干预、可恢复的协作任务团队。
