THE PROBLEM

为什么 现在的 AI 搞不定工业软件？

AI Agent 能写代码、能调工具，但面对 SolidWorks、Abaqus、Ansys 这类专业工业软件，核心语言、行业规范、经验设计这三道坎，让它只能"做表面功夫"。

⚠ 现状：AI 直接操控工业软件

  • 不懂核心语言：Abaqus 的 INP / Python、Ansys 的 APDL、SolidWorks API 语法频频出错
  • 不懂行业规范：生成的脚本违反网格质量、收敛容差、本构选择等 GB/ASTM/ISO 约束
  • 不懂经验设计：网格密度、载荷步长、材料参数靠"猜"，资深工程师才知道怎么选
  • 流程割裂：CAD→CAE→后处理靠手工搬运，AI 无法编排多软件协同
  • 无法交付：生成的内容需工程师逐行纠错，"提效"被大量返工抵消

⚡ 工仿智连：把"规矩"显式喂给 AI

  • 核心语言库：预置各软件 API 映射、脚本模板、命令手册，AI 一次生成即合规
  • 行业规范引擎：内置 GB/ASTM/ISO 标准 + 用户自主上传，硬约束自动校验
  • 经验设计库：参数化模板 + 经验规则，把"老师傅"的 know-how 沉淀为可复用资产
  • 流程编排器：多软件协同自动化，从建模到结果交付一条龙
  • 直接交付：仿真结果 + 标准化报告一次产出，工程师只需复核

TECHNICAL

技术 实现路径

基于 MCP 协议 + Skills 组合，可扩展、可私有化。

连接协议
基于 Model Context Protocol (MCP) 标准协议，AI Agent 通过统一接口调用各工业软件，支持 Trae 及其他主流 Agent 框架接入。
知识注入
三层知识结构化：核心语言库（API/脚本映射）+ 行业规范库（GB/ASTM/ISO + 自定义）+ 经验设计库（参数模板 + 规则集），均支持热更新与团队共享。
软件适配
首期覆盖 Abaqus（Python/INP/UEL）、Ansys（APDL/ACT）、SolidWorks（API）、CATIA（VBA），后续按需扩展 UG/NX、Hypermesh 等。
部署形态
双模式：SaaS 订阅（个人/中小企业，云端知识库）+ 私有化部署（大型企业，沉淀专属规范与经验资产，数据不出域）。
交付产物
仿真结果文件 + 标准化报告（含规范合规性说明）+ 可复用脚本模板，支持一键导出与团队复用。
