SoundSwich

前台应用感知 · Windows 音频设备自动切换助手

一句话介绍

SoundSwich 常驻系统托盘，监听当前前台应用。当用户切换到指定程序（如 Zoom、游戏、音乐播放器）时，自动把 Windows 默认播放/录音设备切到预设设备，让音频切换完全无感。

发现的问题

Windows 没有“按应用自动切换音频设备”的能力。用户每次切换场景，都要手动点击音量图标 → 选输出/输入设备，平均花费 5–10 秒，还会打断当前心流。
  • 远程会议开始，才发现声音还外放在音箱里。
  • 打开游戏想戴耳机，却忘了切换，错过队友语音。
  • 音乐、播客、语音通话频繁交错，反复手动切设备令人疲惫。

解决方案

通过规则驱动的方式，把“应用 → 音频设备”映射一次，以后全程自动：

前台感知 监听系统前台窗口事件，准确识别用户正在使用的应用，过滤任务栏、桌面等误触发。
输入/输出双切 同时切换默认播放设备（Console + Communications 角色）和默认录音设备，覆盖会议与娱乐。
规则配置 可视化设置：为每个应用绑定耳机、扬声器、麦克风，支持备注与重复规则检测。
托盘轻量运行 单实例、开机自启、低资源占用，设置一次后无需再管。

典型使用场景

  • 混合办公：打开 Teams/腾讯会议/Zoom → 自动切到耳麦，离开会议回到浏览器 → 恢复音箱。
  • 游戏语音：启动游戏 → 自动切到游戏耳机，打开 Discord/YY → 切到带麦耳机。
  • 内容创作：打开 OBS/Audacity → 自动切到专业麦克风和监听耳机，减少开播前检查步骤。
  • 辅助使用：听障用户或需要固定助听设备的群体，可降低设备管理门槛。

技术亮点

基于 WPF + Windows Core Audio API / IPolicyConfig 实现默认端点切换；使用 SetWinEventHook 高效监听前台窗口；COM 调用集中在专用 STA 线程，避免公寓状态冲突；文件日志与托盘状态实时反馈，便于排查。

价值与意义

  • 效率提升：把每次手动切换的点击和注意力中断，变成完全自动的后台行为，让多任务工作流更顺畅。
  • 可访问性：帮助依赖特定音频设备的用户减少操作步骤，提升 Windows 使用体验。
  • 社会价值：远程协作普及的背景下，减少因设备未切换导致的沟通尴尬和时间浪费。

后续规划

  • 支持按时间/地理位置等更多触发条件的规则。
  • 增加切换时的声音/气泡提示，让用户感知设备变化。
  • 提供进程白名单、规则导入导出、多设备配置文件等高级功能。
  • 考虑开源发布，吸引社区贡献更多设备驱动适配。
