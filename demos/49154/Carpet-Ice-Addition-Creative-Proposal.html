痛点分析

为什么需要 Carpet Ice Addition？

很多 Minecraft 服务器，尤其是长期运行的生存服、红石服、生电服，会遇到很多"小但高频"的维护问题。

💎

掉落物管理困难

服务器中掉落物过多导致管理困难或性能压力，缺少灵活可控的清理工具和保护机制。

⚙️

生电机器状态检查麻烦

生电服中机器数量多，关机和运行状态难以逐一确认，回档前容易遗漏机器关闭。

🛡️

误操作影响机器

玩家误操作可能影响机器或建筑，如误拆脚手架、误碰展示框、误攻击驯服生物等。

🧊

原版机制不够灵活

特殊方块采集、珊瑚块合成、幻翼行为等原版机制不够灵活，玩家体验有优化空间。

📦

整合型插件过重

服务器想要细粒度控制，但不想安装过重的整合型插件，希望按需开关功能。

🔄

多版本维护成本高

不同 Minecraft 版本之间维护成本高，功能移植和适配需要大量重复工作。

核心能力

更多规则
🗑️
/killitem
掉落物清理指令

按半径、维度或全局清理掉落物，支持黑名单与命名掉落物保护配置，清理结果可分页查看明细。

/killitem range 64 清理半径内掉落物
/killitem dimension minecraft:overworld 清理指定维度
/killitem all 清理所有已加载维度
/killitem config blacklist add minecraft:diamond 添加物品黑名单
📊
/machineStatus
机器状态检查命令

保存生电机器关机时的目标方块状态，查询当前哪些机器未处于保存的关机状态，支持回档前警告。

/machineStatus add minecraft:overworld 100 64 -20 刷铁机 添加机器记录
/machineStatus list 列出所有机器状态
/machineStatus list running 只列运行中机器
💡 配套规则：命令功能需要通过对应 Carpet 规则开启权限控制： commandKillItem（默认 ops）和 commandMachineStatus（默认 ops）， 支持 false / true / ops / 0~4 等权限级别。 machineStatusRollbackWarning 规则可在回档命令前检测运行中的机器并发出警告。

使用方式

四步上手，即刻体验

从安装到使用，简单几步即可让你的服务器拥有更丰富的管理能力。

1

安装 Mod

确保服务器已安装 Fabric Loader 和 Fabric API，然后安装 Carpet Mod 和 Carpet Ice Addition。

// 服务器 mods 目录放入
fabric-api-x.x.x.jar
carpet-x.x.x.jar
carpet-ice-addition-x.x.x-mcXXXX.jar
2

按需开启规则

在游戏中使用 /carpet 命令或在 carpet.conf 配置文件中按需开启功能规则。大多数布尔规则默认关闭；命令类和字符串类规则按文档默认值生效，服主可按需配置。

// 按需开启需要的规则
/carpet safeScaffoldingBreak true
/carpet phantomSpawnWarning true
/carpet invisibleItemFrames true
3

使用命令工具

使用 /killitem 清理掉落物，使用 /machineStatus 管理生电机器状态。

// 清理当前维度所有掉落物
/killitem dimension minecraft:overworld
// 添加刷铁机状态监控
/machineStatus add minecraft:overworld 100 64 -20 刷铁机
4

享受按需优化的体验

启用对应规则后，在不破坏原版体验的前提下获得更顺手的玩法和更高效的管理工具。

// 启用对应规则后
启用 neutralPhantoms 后：幻翼不再主动攻击玩家
启用 invisibleItemFrames 后：展示框可以隐形
启用 machineStatusRollbackWarning 后：回档前可提示机器状态风险
