01

核心原则

六条规则，防止进化引擎偏移方向、自我刷分或引入退化。

01

单一可编辑资产

每轮进化只针对一个任务配置文件。一次修改，一次测量，一次决策。不做跨文件编辑，避免归因模糊。

02

双重评估

静态结构分析捕捉格式和完整性问题。实测执行捕捉行为退化。两者缺一不可。

03

棘轮机制

提升总分的改进被 commit。降低分数的修改自动 revert。分数只能上升或持平，永远不会下降。

04

独立评分

编辑任务配置的 Agent 永远不为自己打分。由独立的子 Agent 评估输出质量，防止自我表扬偏差。

05

全自主进化

无需人类确认，自动执行优化循环。通过每周复盘验证效果，效果回退自动回滚，不降低进化效率。

06

目标导向

不看任务配置写得多漂亮，看实际执行后是否真正达成目标。配置写得再漂亮，实际执行不达标也是白搭。

# 维度 权重 评分标准
1 任务元数据质量 8 任务名规范，描述包含做什么+何时触发+目标产出，不超过1024字符
2 执行流程清晰度 12 步骤有编号、可执行，每步都有明确的输入/输出，定时触发条件明确
3 失败模式编码 10 显式编码已知失败路径，不是简单「别犯错」式叮嘱
4 自动化完备度 10 任务可全自动执行、无需人工干预、异常自动处理
5 可执行具体性 12 禁用「建议/可以考虑/根据情况/灵活把握/视情况而定」等模糊措辞
6 资源整合度 5 所有引用的脚本/资产路径存在且可访问
7 反例与黑名单 3 高风险操作（rm/git reset --hard/force push）必须显式列为禁止

03

进化循环

从初始化到成果卡片的五个阶段。系统全自主运行，无需人类确认，通过每周复盘验证效果。

0 初始化

范围与分支设置

确定进化范围，创建版本控制基础设施，加载历史记录。

  1. 确认范围：全部任务还是用户指定子集
  2. 扫描任务配置目录获取目标列表
  3. 创建 git 分支：auto-evolve/YYYYMMDD-HHMM
  4. 初始化或加载 results.tsv 用于历史追踪
0.5 设计

测试场景工程

在任何评分之前，先设计用于衡量效果的测试场景。没有好的测试，进化引擎就是盲飞。

  1. 阅读每个任务配置，理解其声明的目标
  2. 为每个任务设计2-3个测试场景：一个正常路径，一个异常场景
  3. 保存到每个任务目录下的 test-scenarios.json
  4. 自动进入下一阶段，无需人类审批
1 基线

全维度评分

为每个任务建立起始分数。结构评分由主 Agent 完成，效果评分由独立子 Agent 完成。

  1. 阅读任务配置，为维度1-7评分并附理由
  2. 启动子 Agent：分别在启用和未启用任务配置的情况下运行测试场景
  3. 对比输出，为维度8-9评分（如子 Agent 不可用则标记 dry_run）
  4. 计算加权总分，记录到 results.tsv
  5. 输出评分卡，自动进入优化循环
2 进化

Hill-Climbing 循环

按分数从低到高处理任务。每轮：诊断最弱维度，提出一个针对性修复，执行，重新评分，做出决定。

  1. 找出该任务得分最低的维度
  2. 生成一项具体改进（改什么，为什么改，预期分数变化）
  3. 编辑任务配置，用结构化消息 git commit
  4. 重新评分：结构由主 Agent，效果由独立子 Agent
  5. 新分 > 旧分：保留。否则：git revert，进入下一个任务
  6. 每个任务完成后：自动继续下一个任务，无需人类确认
3 复盘

每周复盘与成果卡片

将所有结果汇总为进化报告，包含进化前后分数、实验次数、关键改进和成果卡片。

  1. 统计总实验次数、保留次数、回滚次数和测试模式
  2. 生成每个任务的进化前后分数对比表
  3. 列出影响最大的改进及其对应维度
  4. 归档 results.tsv 供未来 baseline 参考
  5. 生成可视化成果卡片（进化任务数、分数变化、核心改进、周度趋势）
04

分数只能上升。每轮要么改进任务，要么干净地回滚。不会随时间积累局部退化。

为什么需要
双重评估

单看结构无法判断任务是否真正好用。单看效果无法判断它为何失败。

传统方法

纯结构审查

  • 检查任务元数据是否存在且格式正确
  • 验证步骤是否有编号和描述
  • 确认文件路径和引用是否有效
  • 无法检测任务是否真正提升了执行效果
  • 无法检测看似正确实则产生差结果的误导性配置
  • 无法检测弊大于利的过度约束

双重评估

  • 结构评分捕捉格式、完整性和可读性问题
  • 实测执行揭示真实场景下的行为影响
  • 基线对比衡量任务配置是增值还是减值
  • 独立子 Agent防止自我表扬的评分偏差
  • 测试场景设计确保评估针对真实用户场景
  • 每周复盘持续验证改进效果，回退自动回滚
