01 / PROBLEM

痛点：收藏了，再也找不到

GitHub 重度用户的共同困境——Star 的项目越多，真正能用上的越少

🔍

找不到想找的项目

几百个 Star 项目堆在一起，GitHub 翻页要翻半天。想找个之前收藏的库，关键词搜不到、记不清项目名、分类太弱，最后干脆放弃。

💭

记不清为什么 Star

当时觉得这个项目好厉害，点了 Star。过几个月再看到，完全想不起来「我当时为什么要 Star 它？它解决了什么问题？」

📦

无法批量管理

GitHub 原生 Star 功能太简单：没有标签、没有状态、没有评分、没有备注。想批量整理？只能一个个手动操作，效率极低。

⏱️

评估项目成本高

每个项目都要点开 README 看半天才能判断价值。几十个项目看下来，时间全花在阅读上，真正用于决策和实践的时间所剩无几。

🗑️

Star 只进不出

看到好项目就 Star，但从来不会主动清理。Star 列表越来越像个信息黑洞——只进不出，价值密度越来越低。

🤖

缺少 AI 辅助

面对海量开源项目，没有 AI 帮你总结摘要、识别技术栈、推荐标签、语义搜索。纯靠手动管理，效率天花板太低。

03 / FEATURES

核心功能

从同步到管理，从搜索到 AI 理解，全方位提升你的 Star 管理体验

01

一键 Star 同步

通过 GitHub CLI 全量同步所有已 Star 项目，包括名称、描述、语言、Topics、Star 数、Fork 数、更新时间等完整信息。支持增量同步和进度展示。

全量同步 增量更新 GitHub CLI
02

表格化管理视图

类似 Airtable / Notion Database 的表格体验，支持排序、筛选、搜索、批量操作。一眼看尽所有项目的关键信息，告别 GitHub 翻页痛苦。

表格视图 多维筛选 批量操作
03

FTS5 全文搜索

基于 SQLite FTS5 的高性能全文搜索，支持项目名、描述、Topics、标签、备注、AI 摘要等多字段检索。几百个项目里秒级定位。

全文搜索 FTS5 秒级响应
04

个人标签与状态

自定义标签体系（技术方向 / 使用状态 / 价值判断），为每个项目设置状态（待研究 / 试用中 / 已集成 / 已放弃）和评分，建立属于你的分类系统。

标签系统 状态管理 评分系统
05

AI 智能摘要

读取项目 README，调用 AI 模型自动生成中文摘要、识别技术栈、提取安装命令、推荐标签、判断项目价值，大幅降低阅读成本。

AI 摘要 技术栈识别 标签推荐
06

语义搜索

用自然语言找项目：「找适合做 MCP Server 的项目」「找可以和 Claude Code 配合使用的工具」，基于 Embedding + 向量检索实现智能匹配。

自然语言 向量检索 智能推荐
07

Star / Unstar 管理

在 Web UI 中直接管理 GitHub Star 状态，支持批量取消低价值项目 Star。取消 Star 前保留本地记录，不用担心误删，随时可以重新 Star。

Star 管理 批量操作 二次确认
08

本地优先 · 数据自主

所有数据存在本地 SQLite，无需注册、无需云端、隐私安全。支持 CSV / JSON / Markdown 导出，可备份、可迁移、可接入 Obsidian 等工具。

本地优先 数据自主 多格式导出
09

灵活模型接入

支持 OpenAI Compatible API 格式，可接入 Claude、OpenAI、DeepSeek、Qwen 等云端模型，也支持 Ollama / LM Studio 本地模型，完全自主选择。

多模型支持 本地模型 灵活配置
