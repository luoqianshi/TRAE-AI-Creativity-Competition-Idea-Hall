TRAE AI CREATOR CHALLENGE

RoleForge

AI NPC 角色卡平台 — 用一张 JSON 让任何游戏拥有会思考的 NPC

开发者只需编写一张 JSON 角色卡，就能让 NPC 拥有独立的世界观、推理链和行动能力。接入任何游戏，无需修改游戏本体代码。
参赛人：殷鼎喆  |  技术栈：FastAPI + DeepSeek + Godot 4  |  开发工具：Trae AI
01

核心问题与解法

传统 NPC 的困境

  • 行为是写死的脚本或有限状态机 — 换一个 NPC 性格 = 改一堆代码
  • 行为僵化，玩家很快摸透套路
  • AI 接入成本高，一个游戏一套专用方案

RoleForge 的解法：角色卡驱动 + 三层 Agent 架构

NPC 的所有行为，都由一张角色卡 JSON定义。游戏只管调用 HTTP API，不关心 AI 内部怎么运转。

  • · API 绑定
  • · 游戏适配
层次类比变化频率作用

学习层经验与判断每局更新识别对手模式
执行层肌肉记忆按需调用映射到游戏 API
03

Agent Loop：NPC 每次决策的完整流程

P

_perceive() — 感知

从游戏状态提取关键信号

T

_think() — 推理：LLM CoT 三步思维链

观其势（分析局面） → 断其理（引用角色卡原则 + 禁忌裁决） → 定其策（给出行动方案）

V

verdict_engine.evaluate() — 裁决

硬约束过滤（程序保底，LLM 不能绕过）

D

_decide() — 决策

生成结构化 AgentAction

E

_execute() — 执行

通过 Adapter 调用游戏 API

M

_memorize() — 记忆

写入 DecisionRecord，更新对手模型

04

已实现的核心模块

BaseAgent + VerdictEngine

app/base_agent.py 实现了 Agent 的完整生命周期。VerdictEngine 提供三级裁决体系：

  • hard_constraints：程序化硬拦截，LLM 无法绕过（如"金币不足时禁止投资"）
  • tactical_hints：战术倾向建议，影响决策权重
  • soft_preferences：软偏好，作为推理上下文参考

AgentFactory：角色卡 → Agent 实例

  • 动态类加载：根据角色卡 agent_class 字段反射加载 Python 类
  • DynamicAgent：无专用子类时的通用兜底，纯 JSON 驱动
  • 禁忌翻译器：将自然语言禁忌自动转译为程序化约束
  • 开闭原则：新增角色类型不需要修改工厂代码
# 一行代码，从角色卡创建可运行的 Agent
agent = create_agent_from_card("data/capitalist/capitalist_card.json")
result = await agent.step(game_state)

LLMCoTEngine：可配置思维链

  • 步骤配置化：思维链步骤写在角色卡 JSON 里，不同角色有不同的推理风格
  • 上下文链传递：每一步的推理结论自动传给下一步（真正的 Chain-of-Thought）
  • 降级机制：无 API Key 时自动切换到规则推理，保证系统可用
步骤孙膑（战争）资本家（商业）
Step 1观其势：分析粮道/兵力/地形观其势：分析市场/资金/竞争
Step 2断其理：引用兵法铁律断其理：生存法则/利润优化
Step 3定其策：给出战术命令定其策：给出投资行动

CardGeneratorV2：四种角色卡生成模式

MODE 1

structured

结构化表单输入，精确控制每个字段

MODE 2

from_template

原型标签快速创建（aggressor / strategist / defender）

MODE 3

from_knowledge

知识库 ID → RAG 检索 → LLM 提取

MODE 4

llm_assist

自然语言描述，一段话生成完整角色卡

05

核心设计：AI 如何从文本中学会思维方式

这是 RoleForge 最核心的技术洞察，也是区别于传统 NPC 脚本系统的关键。

问题的本质

"让 AI 学会某种思维方式"，实际上是一个知识表征问题。孙膑读过《孙子兵法》，学会了"以奇制胜"的思维——他的思维方式藏在那些文字里。AI 不能像人一样"理解"，但可以通过结构化提示词，强迫它按特定步骤推理。

三类输入，三种提炼方式

输入类型代表内容提炼结果RoleForge 落点
叙事型文本兵法原典、战役复盘、商战故事行为模式 + 情境条件CoTStep.prompt_template
规则型文本禁忌、原则、约束条件不可违背的边界VerdictEngine.hard_constraints
对话/行为型文本角色语录、历史决策记录Few-shot 风格示例system_prompt 人格锚定

思维链的工作机制：上下文链传递

关键机制不是让 LLM "学习"，而是强制它按照目标角色的认知框架逐步推理：

STEP 1

感知

你是孙膑，分析当前形势的五个维度

STEP 2

推理

引用兵法铁律，判断哪些行为被禁止/推荐

STEP 3

决策

给出可执行的命令，而非建议

# 链传递的关键代码（来自 llm_cot_engine.py）
context["previous_steps"] = "\n\n".join(
    f"【{p['name']}】\n{p['reasoning']}"
    for p in previous_outputs
)
# 每一步推理的结论，都作为下一步的输入

如何"教会"AI 一个新角色

STEP 1

收集原始材料

找到目标角色的原始文本（传记、语录、案例、规则）

STEP 2

提炼认知框架

他关注什么？他的禁忌是什么？他怎么表达决策？

STEP 3

写入 CoT 步骤

将认知框架转为 prompt_template，每步对应一个认知维度

STEP 4

固化边界约束

将禁忌转为 hard_constraints，程序保底，LLM 无法绕过

孙膑 vs 资本家：同一引擎，不同思维

// 孙膑的认知框架（来自《孙膑兵法》）
"cot_steps": [
  { "name": "观其势", "prompt_template": "分析：粮道状况/兵力对比/地形优劣/士气状态/主动权归属" },
  { "name": "断其理", "prompt_template": "引用兵法铁律，判断哪些行动被禁止，哪些应优先考虑" },
  { "name": "定其策", "prompt_template": "以孙膑口吻，给出最多3条可执行命令，注明优先级" }
]

// 资本家的认知框架（来自商战逻辑）
"cot_steps": [
  { "name": "观市场", "prompt_template": "分析：资金流/市场份额/竞争态势/行业风口" },
  { "name": "断利弊", "prompt_template": "核算：利润预期/风险敞口/对手反应" },
  { "name": "定投资", "prompt_template": "给出具体投资动作，注明金额和时机" }
]

两个完全不同的思维方式，驱动同一套 CoT 引擎——角色卡 JSON 就是思维方式的"编码格式"。

为什么这比 Fine-tuning 更实用

方案实现成本更换角色透明可调试适合游戏场景
Fine-tuning极高（标注数据+训练）需重新训练黑盒不适合
RAG 注入中等（建向量库）切换知识库部分可见一般
CoT 步骤编码（RoleForge）低（写 JSON）换 JSON 文件完全透明非常适合

用提示词工程替代训练，用JSON 配置替代代码修改，用约束裁决替代 LLM 道德自觉。

06

Trae 在本项目中的关键作用

ARCHITECTURE

三层架构设计

整个"灵魂层/学习层/执行层"的设计模式，是与 Trae 多轮对话中逐步演化出的结果。从单一 Agent 类到工厂模式 + 适配器模式 + 裁决引擎。

SAFETY

禁忌翻译器

将自然语言禁忌自动转译为 VerdictEngine 可执行的 hard_constraint 格式，解决了"LLM 可能无视禁忌"的安全漏洞。

COMPATIBILITY

MiMo 兼容适配

MiMo 推理模型的决策内容在 reasoning_content 而非 content 字段中，Trae 帮助实现了双字段自动 fallback 解析。

INTEGRATION

Godot 全链路对接

RoleForgeClient.gd 和 NPCActionExecutor.gd 的完整对接代码，包括月结算集成、超时降级、信号系统。
