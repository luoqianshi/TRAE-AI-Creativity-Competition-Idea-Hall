网文作者面临的五大痛点

通用AI工具无法满足长篇小说创作的工程化需求

📝

记忆缺失

通用AI没有长期记忆，写到第100章时已经忘记第10章的设定，导致剧情自相矛盾。

👤

人设崩塌

人物性格、能力、关系随章节推进逐渐变形，读者强烈吐槽"OOC"（Out Of Character）。

🔗

伏笔丢失

前期埋下的伏笔在后期忘记回收，支线写飞、主线丢失，作品结构松散。

🤖

AI味过重

AI生成文本机械感明显，缺乏人味，平台审核容易被判定为"AI文"而限流。

📉

烂尾率高

百万字级别作品的结构性把控困难，超过60%的网络小说无法正常完本。

⏱️

效率低下

作者在文档、AI聊天、笔记软件之间反复切换，创作流频繁中断，日更压力大。

核心创新

多层记忆系统

工作记忆 + 短期记忆 + 长期记忆 + 知识图谱四层架构，配合遗忘曲线算法，让AI真正"记得"前面写了什么。

  • 自动提取关键设定、人物关系、伏笔状态
  • 智能召回与当前章节最相关的历史信息
  • 实体-动作语义去重，避免冗余
核心创新

叙事契约系统

为每个角色建立"ability契约"，AI在生成时承诺遵守设定，系统实时检测违约行为并自动修正。

  • 角色能力、性格、关系契约化管理
  • 实时违约检测与修复
  • 契约关联性验证，确保逻辑自洽
核心创新

7维约束大纲

废弃传统摘要式大纲，采用"必须达成、必须禁止、伏笔管理、情绪方向、节奏齿轮、叙事驱动、因果承接"七维约束，给AI明确的创作边界而非剧本。

  • 增量生成模式，每批10-15章动态规划
  • 废弃子弧层，结构更扁平高效
  • 主弧包含startState/endState/milestones长程指引
质量保障

AI味检测与消除

通过safe-words检测、陌生化检查、文风铁律注入、参考片段模仿等技术，从根源上消除AI生成痕迹。

  • 8-10条关键AI味检测规则
  • 段落级精准修复，非全文重写
  • 题材专属文风参考片段注入
质量保障

智能审计引擎

黄金三章评估、签约潜力分析、联动规则校验、流畅度与认知负荷分析，用工程化手段保障作品质量。

  • 问题清单式审计报告（位置+摘录+问题+修复）
  • 润色审计循环机制
  • 付费/免费平台差异化评估策略
工程化

增量生成架构

针对长篇小说的特殊需求，采用"基于已写内容动态生成后续"的增量模式，确保百万字级别的连贯性。

  • 动态计算max_tokens防止输出截断
  • 章节生成最多2次LLM调用（前半+后半）
  • 异步补全机制保障人物不空壳

技术架构

Electron桌面应用，完全本地运行，数据不出本机

桌面端框架

Electron 33 主进程CJS + 渲染进程ESM，打包为.deb/.AppImage/.exe，支持Windows/macOS/Linux三平台。

前端技术栈

React 19 + TypeScript 6 + Vite 8 + Tailwind CSS v4，Zustand分域状态管理，组件化架构。

数据存储

better-sqlite3本地数据库约30张业务表，WAL模式；electron-store加密存储LLM API Key。

AI引擎

统一llm-service封装，支持DeepSeek/OpenAI/Anthropic/通义千问/月之暗面等多厂商API。

数据安全

完全本地运行，所有创作数据存储在用户本机，无需注册账号，无云端同步，杜绝内容泄露。

质量保障

Vitest单元测试 + Playwright E2E测试，Zod IPC参数校验，TypeScript全类型覆盖。
