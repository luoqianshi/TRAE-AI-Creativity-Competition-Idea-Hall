# 酒店评价智能分析评分系统 - 功能描述文档

## 一、系统概述

### 1.1 项目背景

酒店目前对住客评价的分析与打分完全依赖人工判断，存在效率低、标准不统一、人力成本高、难以快速复盘等问题。本系统旨在通过接入国内主流大模型 API，基于预设的评分标准，对住客评价进行自动化的维度识别与量化打分，实现评价分析的智能化、标准化和高效化。

### 1.2 系统目标

- **自动化**：将人工判断评价内容并打分的流程，转为 AI 模型自动识别与量化
- **标准化**：统一评分标准，消除人工评分的主观偏差
- **可追溯**：每次评分均记录原始评价、AI 原始返回、最终得分，支持人工复核
- **可配置**：评分标准和 AI 模型均可灵活调整，适应不同酒店/业务需求
- **可统计**：自动生成各维度的得分汇总，支持管理层决策分析

### 1.3 适用范围

适用于各类酒店（连锁/单体/高端/经济型）的住客评价分析场景，支持来自OTA平台（携程、美团、飞猪等）、自有渠道、问卷调查等多来源评价数据。

---

## 二、核心业务流程

```
评价数据导入/输入
      ↓
评价预处理（清洗、格式化）
      ↓
AI 模型调用（基于评分标准 Prompt）
      ↓
AI 返回结构化评分结果
      ↓
评分结果解析与校验
      ↓
得分存储与汇总统计
      ↓
评价分析报表/明细查看
```

## 三、功能模块详细设计

### 模块一：评分标准管理

#### 1.1 评分维度配置

管理评价分析的维度类别，每个维度对应酒店服务的一个方面。

**功能说明：**

| 配置项 | 说明 | 示例 |
|--------|------|------|
| 维度名称 | 评价维度的中文名称 | 客房、前台、餐饮、卫生、设施、位置、服务态度 |
| 维度标识 | 维度的唯一英文标识符（用于系统内部和 Prompt 引用） | `room`, `front_desk`, `restaurant`, `cleanliness`, `facility`, `location`, `service` |
| 维度描述 | 对该维度的详细说明，帮助 AI 理解判断边界 | "客房维度包括：床品舒适度、房间面积、隔音效果、空调温度、热水供应、装修风格等" |
| 关键词提示 | 该维度常见的评价关键词列表，辅助 AI 识别 | "床、被子、枕头、空调、热水、隔音、房间、卫生间、淋浴" |
| 状态 | 启用/停用 | 启用 |

**操作：**
- 新增维度
- 编辑维度信息
- 删除维度（已有评分记录的维度建议停用而非删除）
- 调整维度显示顺序
- 批量导入/导出维度配置

#### 1.2 评分等级与分值配置

为每个维度定义多级评分等级及对应分值，支持自定义档位数量和每档分值。

**设计原则：**
- 评分等级支持多档位，不局限于"好评/中评/差评"三级，用户可根据业务需要自由定义档位数量和名称
- 分值支持正分、零分、负分，负分用于惩罚严重问题
- 不同维度可配置不同的分值体系（如"卫生"维度差评惩罚更重，"位置"维度差评惩罚较轻）
- 档位之间应合理过渡，避免分值跳跃过大，确保评分区分度

**功能说明：**

| 配置项 | 说明 | 示例 |
|--------|------|------|
| 等级名称 | 评分等级的名称 | 强好评、好评、弱好评、中性、弱差评、差评、强差评 |
| 等级标识 | 等级的唯一标识 | `strong_positive`, `positive`, `mild_positive`, `neutral`, `mild_negative`, `negative`, `strong_negative` |
| 分值 | 该等级对应的得分（支持自定义任意数值） | +10、+5、+2、0、-2、-5、-10 |
| 分值说明 | 该等级的判定条件详细描述，指导 AI 精准判断 | 见下方示例 |
| 等级颜色 | 用于前端展示的标识颜色 | 深绿、浅绿、黄绿、灰色、浅红、红色、深红 |
| 排序权重 | 用于确定等级从高到低的排列顺序 | 7、6、5、4、3、2、1 |

**推荐七级评分体系示例（默认模板，可自定义修改）：**

| 等级 | 分值 | 判定条件描述 | 颜色 |
|------|------|-------------|------|
| 强好评 | +10 | 客人明确且强烈地赞扬，使用"太好了""非常满意""超赞"等强烈正面词汇，或主动推荐 | 深绿 |
| 好评 | +5 | 客人表达满意或认可，语气较为正面但无强烈情绪词 | 浅绿 |
| 弱好评 | +2 | 客人提及该维度且倾向正面，但表述含糊或只是附带提及（如"还行""可以"） | 黄绿 |
| 中性 | 0 | 客人提到该维度但未表达任何明显的正面或负面倾向，或评价内容与该维度无关 | 灰色 |
| 弱差评 | -2 | 客人提及该维度且倾向负面，但表述轻微或只是附带抱怨（如"有点吵""一般般"） | 浅红 |
| 差评 | -5 | 客人明确表达不满，指出具体问题但不涉及严重体验损害 | 红色 |
| 强差评 | -10 | 客人强烈表达不满或愤怒，涉及严重体验损害（如"太差了""再也不来了""恶心"） | 深红 |

**操作：**
- 新增/编辑/删除评分等级
- 自由调整档位数量（如简化为5级或扩展为9级）
- 自定义每个等级的分值（如将弱差评从 -2 改为 -3）
- 为不同维度设置不同的分值体系（如"卫生"维度强差评 -10，"位置"维度强差评 -5）
- 批量导入/导出评分等级配置
- 提供预设模板（5级、7级、9级）一键生成，再微调

#### 1.3 评分标准模板

将维度 + 等级 + 分值组合为完整的评分标准，用于生成 AI Prompt。

**功能说明：**

- 系统自动将所有维度配置和等级配置组装为结构化的评分标准文本
- 支持预览最终生成的评分标准（即会发送给 AI 的参考标准）
- 支持手动编辑/微调 AI 参考标准文本（高级用户可自定义 Prompt）
- 支持保存多个标准模板版本，便于切换和回溯

**模板示例（预览，以七级评分体系为例）：**
```
请根据以下标准对酒店住客评价进行分析打分：

【评分等级定义】
- 强好评(+10)：客人明确且强烈地赞扬
- 好评(+5)：客人表达满意或认可
- 弱好评(+2)：客人提及且倾向正面，表述含糊
- 中性(0)：未表达明显好恶，或未提及该维度
- 弱差评(-2)：客人提及且倾向负面，表述轻微
- 差评(-5)：客人明确表达不满，指出具体问题
- 强差评(-10)：客人强烈不满或愤怒，涉及严重体验损害

【评分维度及判定标准】
1. 客房(room)
   - 强好评(+10)："房间太棒了，床超级舒服，住得不想走"
   - 好评(+5)："房间不错，很干净，住着挺舒服"
   - 弱好评(+2)："房间还可以""凑合能住"
   - 中性(0)：未提及客房相关内容
   - 弱差评(-2)："隔音不太好，有点吵""热水来得比较慢"
   - 差评(-5)："房间有异味，空调不太制冷"
   - 强差评(-10)："房间太脏了，床单有污渍，恶心死了"

2. 前台(front_desk)
   - 强好评(+10)："前台小姐姐特别热情，帮我升级了房间，太感动了"
   - 好评(+5)："前台服务态度很好，办理入住很快"
   - 弱好评(+2)："前台还行，正常办理"
   - 中性(0)：未提及前台相关内容
   - 弱差评(-2)："前台排队等了一会儿""态度一般"
   - 差评(-5)："前台态度冷漠，问个路都不耐烦"
   - 强差评(-10)："前台服务太差了，订的房型没有，还态度恶劣"

3. 餐饮(restaurant)
   ...（各维度同上结构，判定描述根据维度特性自定义）

【输出格式要求】
请以 JSON 格式返回评分结果...
```

#### 1.4 评价来源配置

配置评价数据的来源渠道信息。

| 配置项 | 说明 | 示例 |
|--------|------|------|
| 来源名称 | 评价渠道名称 | 携程、美团、飞猪、大众点评、酒店自有问卷 |
| 来源标识 | 唯一标识 | `ctrip`, `meituan`, `fliggy` |

### 模块二：AI 模型接入配置

#### 2.1 模型供应商管理

管理系统可接入的 AI 大模型供应商。

**支持的国内主流大模型：**

| 供应商 | 模型 | 说明 |
|--------|------|------|
| 阿里云 | 通义千问(Qwen) | 支持通义千问系列各版本 |
| 百度 | 文心一言(ERNIE) | 支持 ERNIE 系列各版本 |
| 智谱AI | GLM-4 | 支持智谱 GLM 系列 |
| 月之暗面 | Kimi | 支持 Moonshot 系列 |
| 讯飞 | 星火大模型 | 支持讯飞星火系列 |
| DeepSeek | DeepSeek | 支持 DeepSeek 系列 |
| 百川智能 | 百川大模型 | 支持百川系列 |
| MiniMax | MiniMax | 支持 MiniMax 系列 |

**功能说明：**

| 配置项 | 说明 |
|--------|------|
| 供应商名称 | 供应商/模型的显示名称 |
| API 接口地址 | 模型的 API Endpoint URL |
| 认证方式 | API Key / AK-SK / Token 等认证方式 |
| API Key | API 密钥（加密存储） |
| 模型版本 | 具体使用的模型版本标识 |
| 请求协议 | API 调用的协议类型（OpenAI 兼容/原生/自定义） |
| 最大 Token 数 | 单次请求的最大输出 Token 数 |
| 温度参数 | 模型输出的随机性控制（0-1） |
| 超时时间 | API 请求超时时间（秒） |
| 状态 | 启用/停用 |
| 备注 | 补充说明信息 |

**操作：**
- 新增模型供应商配置
- 编辑配置信息
- 删除配置
- 测试连接（验证 API Key 有效性和网络连通性）
- 查看调用日志
- 支持配置多个供应商（可设置主备模型，主模型调用失败时自动切换备模型）

#### 2.2 Prompt 模板配置

配置发送给 AI 模型的提示词模板。

**功能说明：**

| 配置项 | 说明 |
|--------|------|
| 模板名称 | Prompt 模板的名称 |
| 系统提示词(System Prompt) | 设定 AI 角色和行为规则的系统级提示 |
| 用户提示词模板(User Prompt) | 包含评分标准和评价内容的用户级提示模板，其中评价内容以占位符 `{{review_content}}` 表示 |
| 输出格式要求 | 指定 AI 返回的数据格式（JSON Schema） |
| 关联评分标准 | 该 Prompt 模板对应的评分标准版本 |
| 状态 | 启用/停用 |

**Prompt 模板示例：**

```
【System Prompt】
你是一位专业的酒店服务质量评估专家。你的任务是分析住客评价内容，根据提供的评分标准，识别评价涉及的服务维度，并给出量化的评分。请严格按照要求的输出格式返回结果。

【User Prompt 模板】
请根据以下评分标准，对这条酒店住客评价进行分析打分：

{{scoring_criteria}}

【待分析评价内容】
{{review_content}}

请以如下 JSON 格式返回结果：
{
  "overall_sentiment": "strong_positive/positive/mild_positive/neutral/mild_negative/negative/strong_negative",
  "identified_dimensions": [
    {
      "dimension": "维度标识",
      "dimension_name": "维度名称",
      "rating": "等级标识",
      "score": 分值数字,
      "reason": "判定理由简要说明",
      "evidence_text": "评价中支持该判定的原文片段"
    }
  ],
  "summary": "一句话概括评价核心内容"
}
```

**操作：**
- 新增/编辑/删除 Prompt 模板
- 预览完整 Prompt（将评分标准和示例评价代入后查看实际发送内容）
- 从评分标准配置自动生成 Prompt（一键生成，再手动微调）

#### 2.3 调用策略配置

控制 AI 模型调用的行为策略。

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| 主模型 | 默认使用的模型 | 第一个启用的模型 |
| 备用模型 | 主模型失败时的切换模型 | 无 |
| 重试次数 | API 调用失败后的重试次数 | 3 |
| 重试间隔 | 重试间隔时间（毫秒） | 1000 |
| 并发数 | 同时调用的最大并发请求数 | 5 |
| 速率限制 | 每分钟最大调用次数 | 60 |

### 模块三：评价测试与分析

#### 3.1 单条评价测试

提供交互式界面，输入单条评价内容进行实时评分测试。

**功能说明：**

| 功能项 | 说明 |
|--------|------|
| 评价内容输入 | 支持多行文本输入，建议支持最大 2000 字 |
| 评价来源选择 | 可选填评价来源（携程/美团等），用于后续统计 |
| 订单号关联 | 可选填订单号，用于关联业务数据 |
| 模型选择 | 可选择使用哪个模型进行测试（用于对比不同模型效果） |
| Prompt 模板选择 | 可选择使用哪个 Prompt 模板 |
| 提交分析 | 点击按钮后调用 AI 模型进行分析 |
| 结果展示 | 展示 AI 返回的结构化评分结果 |

**结果展示区域：**

- **原始评价内容**：显示输入的评价原文
- **AI 返回原文**：展示 AI 模型的原始返回（JSON 或文本），支持折叠/展开
- **解析后的评分结果**：
  - 整体情感倾向（七级：强好评~强差评）
  - 各维度评分详情表格：

    | 维度 | 判定等级 | 得分 | 判定理由 | 原文依据 |
    |------|----------|------|----------|----------|
    | 客房 | 好评 | +5 | 客人称赞床品舒适，表达满意 | "床很舒服，枕头也软" |
    | 前台 | 中性 | 0 | 未提及前台服务 | - |
    | 餐饮 | 弱差评 | -2 | 客人提到早餐偏少，表述轻微 | "早餐种类有点少" |

  - 总分汇总
  - AI 生成的评价摘要
- **人工复核**：支持对 AI 评分结果进行人工修正（修改维度、等级、分值），修正记录会保存
- **保存结果**：将评分结果保存至评价汇总明细

#### 3.2 批量评价导入与分析

支持批量导入评价数据进行自动分析。

**功能说明：**

| 功能项 | 说明 |
|--------|------|
| 文件导入 | 支持 Excel (.xlsx)、CSV 格式导入，文件中需包含评价内容列 |
| 字段映射 | 导入时配置文件列与系统字段的对应关系（评价内容列、来源列、订单号列等） |
| 数据预览 | 导入前预览数据，确认字段映射正确 |
| 批量分析 | 确认导入后，系统逐条调用 AI 模型进行评分 |
| 进度展示 | 显示批量分析进度（已处理/总数、成功/失败数、预计剩余时间） |
| 失败重试 | 对分析失败的记录支持一键重试 |
| 导出结果 | 分析完成后可将结果导出为 Excel 文件 |

**批量导入文件格式要求（示例）：**

| 评价内容 | 评价来源 | 订单号 | 评价时间 | 评分(可选) |
|----------|----------|--------|----------|------------|
| 房间很大很干净... | 携程 | ORD20240101 | 2024-01-15 | 5 |
| 前台态度很差... | 美团 | ORD20240102 | 2024-01-16 | 2 |

### 模块四：评价得分汇总与明细

#### 4.1 评价明细列表

查看所有已分析的评价记录及其评分详情。

**功能说明：**

| 功能项 | 说明 |
|--------|------|
| 列表展示 | 以表格形式展示所有评价记录 |
| 搜索筛选 | 按关键词、来源、时间范围、得分范围、情感倾向、维度等筛选 |
| 排序 | 按时间、总分、各维度得分排序 |
| 详情查看 | 点击记录可查看完整评分详情（含 AI 原始返回、判定理由、原文依据） |
| 人工修正 | 支持对 AI 评分结果进行修正，修正记录保留 |
| 单条重分析 | 支持选择不同模型/Prompt 重新分析单条评价 |
| 导出 | 支持导出筛选后的明细数据为 Excel/CSV |

**列表字段：**

| 字段 | 说明 |
|------|------|
| 序号 | 自增序号 |
| 评价内容（截取） | 评价原文前 100 字 + 展开查看全文 |
| 评价来源 | 评价来源渠道 |
| 订单号 | 关联的订单号 |
| 评价时间 | 评价发布时间 |
| 整体情感 | 强好评/好评/弱好评/中性/弱差评/差评/强差评 |
| 总分 | 各维度得分之和 |
| 各维度得分 | 以标签形式展示各维度得分（如：客房+5, 前台0, 餐饮-2） |
| 分析状态 | 已完成/分析失败/待分析 |
| 人工修正标记 | 是否经过人工修正 |
| 操作 | 查看详情/导出/重分析/删除 |

#### 4.2 得分汇总统计

提供多角度的评分统计数据和可视化图表。

**功能说明：**

- **汇总面板（Dashboard）**
  - 总评价数、已分析数、待分析数、分析失败数
  - 平均总分、好评率（强好评+好评+弱好评占比）、差评率（弱差评+差评+强差评占比）
  - 各维度平均得分对比图（柱状图/雷达图）
  - 评价来源分布（饼图）
  - 时间趋势图（按天/周/月的得分趋势线图）

- **维度分析**

### 4.3 AI 模型调用方案（核心架构）

**问题说明：** 国内主流大模型 API（通义千问、文心一言、智谱GLM、Kimi、讯飞星火、DeepSeek 等）均存在浏览器跨域限制，纯前端 HTML 直接调用 `fetch` / `XMLHttpRequest` 会被浏览器 CORS 策略拦截，导致请求失败。

**解决方案：** 搭建一个极简的本地代理服务（零依赖，仅用 Node.js 内置模块），HTML 前端将请求发送到本地代理，由代理转发至大模型 API。

#### 方案架构图

```
用户浏览器                          本地代理服务(Node.js)                大模型 API
(打开 index.html)                  (node proxy.js)                     (云端)
   │                                │                                    │
   │  POST http://localhost:3000     │                                    │
   │  /api/analyze                   │  POST https://xxx/v1/chat/        │
   │  {                             │       completions                  │
   │    model: "deepseek",          │  {                                 │
   │    system_prompt: "...",       │    model: "deepseek-chat",        │
   │    user_prompt: "...",         │    messages: [                     │
   │    review_content: "..."      │      {role:"system",content:".."}, │
   │  }                             │      {role:"user",content:".."}   │
   │ ──────────────────────────────> │    ],                            │
   │                                │    api_key: "从配置文件读取"        │
   │                                │  }                                 │
   │                                │ ─────────────────────────────────> │
   │                                │                                    │
   │                                │ <───────────────────────────────── │
   │  返回 AI 评分结果 JSON          │  返回模型响应                       │
   │ <────────────────────────────── │                                    │
   │                                │                                    │
```

#### 代理服务实现

**唯一推荐方案：Node.js 零依赖代理**

```
文件：proxy/proxy.js
代码量：约 80 行
依赖：仅 Node.js 内置模块（http, https, fs, path, url）
启动命令：node proxy.js
监听地址：http://localhost:3000
```

**代理服务提供的接口：**

| 接口路径 | 方法 | 功能 | 说明 |
|----------|------|------|------|
| `/api/analyze` | POST | 转发 AI 模型调用 | 前端发送评价内容 → 代理拼接 Prompt → 调用大模型 API → 返回评分结果 |
| `/api/test-connection` | POST | 测试模型连接 | 验证 API Key 有效性和网络连通性 |
| `/api/data/save` | POST | 保存数据到本地文件 | 将评价评分数据写入 `data/reviews.json` |
| `/api/data/load` | GET | 从本地文件读取数据 | 读取 `data/reviews.json` 中的历史数据 |
| `/api/config/load` | GET | 读取代理配置 | 返回 `proxy-config.json` 中的模型配置列表（不返回 API Key） |
| `/api/config/save` | POST | 保存代理配置 | 更新 `proxy-config.json` 中的模型配置 |

#### 前端调用流程

```javascript
// 前端调用示例
const PROXY_URL = 'http://localhost:3000';

async function analyzeReview(reviewContent) {
    const response = await fetch(`${PROXY_URL}/api/analyze`, {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({
            model_key: 'deepseek',         // 使用的模型标识（对应配置中的 key）
            system_prompt: systemPrompt,     // 系统提示词
            user_prompt: userPrompt,         // 用户提示词模板（含评分标准）
            review_content: reviewContent    // 待分析评价内容
        })
    });
    const result = await response.json();
    return result; // AI 返回的评分结果 JSON
}
```

### 4.4 数据存储方案

**存储策略：localStorage（运行时） + 本地 JSON 文件（持久化）**

#### 运行时存储（localStorage）

| 存储项 | 存储键 | 说明 |
|--------|--------|------|
| 评分标准配置 | `config_dimensions` | 维度配置数据（预置默认值，支持修改） |
| 评分等级配置 | `config_ratings` | 等级与分值配置（预置默认值，支持修改） |
| AI 模型配置 | `config_models` | 模型供应商配置（从代理读取，不含 Key） |
| Prompt 模板 | `config_prompts` | 提示词模板配置（预置默认值，支持修改） |
| 评价评分记录 | `reviews_data` | 所有已分析的评价及评分结果 |
| 操作日志 | `operation_logs` | 关键操作记录 |

#### 持久化存储（本地 JSON 文件，通过代理服务读写）

| 文件 | 路径 | 说明 |
|------|------|------|
| 评价数据文件 | `data/reviews.json` | 所有评价评分记录，每次分析后自动保存 |
| 系统配置文件 | `proxy/proxy-config.json` | 模型 API 地址和密钥配置（仅代理服务读写，前端不可直接访问） |

#### 数据保存机制

- **自动保存**：每次评价分析完成后，前端自动调用 `/api/data/save` 将数据写入本地 JSON 文件
- **自动加载**：页面打开时，前端自动调用 `/api/data/load` 从本地 JSON 文件恢复历史数据到 localStorage
- **手动导出**：提供"导出数据"按钮，浏览器下载 JSON 文件作为备份
- **手动导入**：提供"导入数据"按钮，支持导入之前导出的 JSON 备份文件
- **批量导入评价**：Excel/CSV 导入的评价数据同样自动保存

| 数据安全 | API Key 等敏感信息需加密存储，不得明文展示 |

| 可扩展性 | 预留接口，后续可接入更多 AI 模型供应商 |
| 操作可追溯 | 所有关键操作、AI 调用均记录日志 |
| 评分透明 | AI 评分需提供判定理由和原文依据，支持人工复核与修正 |

## 七、后续扩展方向（可选）

以下功能不在一期范围内，但可作为后续迭代方向：

1. **多用户与权限管理**：支持管理员和普通操作员角色，不同权限范围
2. **自动定时采集**：对接 OTA 平台 API 自动拉取最新评价
3. **情感深度分析**：不仅识别好评/差评，还能识别具体情绪（愤怒、失望、惊喜等）
4. **问题预警**：当某维度连续多次出现差评时，自动触发预警通知
5. **回复建议生成**：基于评价内容和评分结果，AI 自动生成回复建议
6. **多酒店/多门店支持**：支持连锁酒店按门店分别管理和统计
7. **评分标准训练优化**：通过人工修正数据反向优化 Prompt 和评分标准
