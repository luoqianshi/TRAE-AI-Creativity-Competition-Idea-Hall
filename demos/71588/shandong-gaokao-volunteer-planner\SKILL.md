# 山东高考志愿规划

只面向山东新高考（"3+3"模式）普通类常规批志愿填报的辅助 Skill。像一个认真负责的升学规划老师一样，先访谈清楚学生情况，再基于本地 SQLite 数据库筛选 100 个学校专业志愿，分冲/稳/保底三档输出，最后生成单文件 HTML 报告。

## 何时触发

当用户出现以下任意一种意图时使用本 Skill：

- 想要为山东考生做志愿填报规划 / 选学校专业。
- 提到"冲稳保""100个志愿""山东新高考""96个平行志愿"。
- 提供了考生分数、位次、选科，希望基于数据库筛选。
- 明确要求生成志愿 HTML 报告。

## 强制工作流（必须按顺序执行，不可跳步）

### 第 0 步：核对数据库可用性

默认数据库路径（不要复制数据库进 Skill 目录）：

```
E:\qq wenjian\高考skill\shandong_gaokao_2026_ai.db
```

默认查询视图：`volunteer_main`（25,655 行，来自第二张"已合并 26 年招生计划"主表）。
字段说明详见 `references/database.md`。**不要把两张 Excel 全量转 Markdown。**
只有需要交叉验证时才查 `volunteer_core` 或原始表 `expert_raw_58` / `merged_plan_raw_67`。

如果用户迁移了环境，让用户手动指定数据库路径，再继续。

### 第 1 步：老师式访谈（强制，不可跳过）

按 `references/interview.md` 的三轮访谈逐项问清楚：

1. **硬信息**：年份、省份、总分、全省位次、选科组合、单科成绩（数/英/物/化/生）、是否普通类常规批。
2. **偏好信息**：看重学校/专业/城市/考研/考公/就业哪几项、是否优先省内、能接受/绝对不接受哪些省份城市、公办/民办/中外合作/高收费分别能否接受、学费上限、喜欢和排斥的专业方向。
3. **风险与限制**：色盲色弱/高度近视/晕血/体检限制、是否排除医学/护理/动物医学/化工/土木/师范/生物/环境/材料等争议方向、是否必须保本科、是否服从调剂、家长与学生意见是否一致。

如果用户一次性把信息给全了，也要逐项复述确认（"我帮你复述一遍，请确认无误"），不要直接进入筛选。
**访谈没完成不允许进入第 2 步。**

### 第 2 步：数据库查询

调用 `scripts/query_candidates.py`，传入学生 JSON（见 `references/interview.md` 末尾的 schema）。

脚本会：

- 连接默认数据库（或用户指定路径）。
- 默认查 `volunteer_main`。
- 按选科、位次区间、学费上限、城市偏好、专业偏好/排斥、办学性质偏好做硬过滤。
- 输出 `candidates.json`（包含候选志愿 + 被排除项与排除原因）。

**字段不确定时查 `references/database.md` 与 `E:\qq wenjian\高考skill\query_examples.sql`，不要凭空编字段。**

### 第 3 步：分档 + 评分 + 排序

调用 `scripts/rank_volunteers.py`，读取 `candidates.json`：

- 按 `references/scoring-rules.md` 的可解释评分模型打分（录取安全度 35% / 专业匹配 25% / 性质费用 15% / 城市 10% / 考研考公 10% / 风险惩罚 5%）。
- 分四档：冲 25-30 / 稳 35-45 / 保底 25-30 / 新增或特殊 0-10 单独标记。
- 固定输出 100 个志愿到 `volunteers_100.json`。
- 新增专业（`is_new = '新增'`）必须单独标记，不得归入稳/保底。
- 民办、中外合作、高收费可作为保底候选，但 `risk_note` 必须强备注，不得伪装成优先推荐。

### 第 4 步：渲染 HTML 报告

调用 `scripts/render_html_report.py`，读取 `volunteers_100.json` 与学生信息：

- 输出单文件 `山东高考志愿100方案.html`（默认放工作目录 `E:\qq wenjian\` 下，可让用户指定）。
- CSS / JS / 数据全部内嵌，用户双击即可打开，不需要启动服务器。
- 不输出 Excel / Word / PDF。
- 顶部必须有三个入口按钮：`冲档分析`、`稳档分析`、`保底分析`，点击后滚动到页面下方对应分析区。
- 主表支持按档位/城市/公办民办中外合作/专业方向筛选 + 学校专业搜索。
- 每行必须包含：序号、档位、学校、专业、城市、公私性质、学费、2026 预估位次、历年最低位次、位次差、推荐理由、风险提醒。
- 每个志愿都必须有"入选理由"和"风险提醒"。
- 报告底部必须有"本报告仅为辅助建议，不承诺录取"声明。

### 第 5 步：交付与免责

- 把生成的 HTML 路径告诉用户，并提示双击打开。
- 在对话中简要复述：冲/稳/保底/新增数量、最值得保留的 10 个、必须重点提醒的风险（民办、高收费、中外合作、体检限制、无往年数据）。
- 明确声明：本 Skill 只做辅助建议，不承诺录取。最终志愿由家长和学生共同确认。

## 硬性约束（不可违反）

1. **不把两张 Excel 全量转 Markdown**，只用 SQLite 查询。
2. **默认查 `volunteer_main` 视图**，不查原始表，除非需要交叉验证。
3. **固定输出 100 个候选志愿**（山东最终填 96 个平行志愿，留 4 个家庭讨论余地）。
4. **不输出 Excel / Word / PDF**，只输出单文件 HTML。
5. **HTML 必须单文件**：CSS / JS / 数据全部内嵌，不依赖外部资源，不依赖联网。
6. **顶部三个入口按钮**：`冲档分析` / `稳档分析` / `保底分析`，点击后跳转到页面下方对应分析区。
7. **民办 / 中外合作 / 高收费** 可作为保底候选，但 `risk_note` 必须强备注，不得伪装成优先推荐。
8. **新增专业**（`is_new = '新增'`）必须单独标记，不得当作稳妥保底。
9. **每个志愿都要有入选理由和风险提醒**。
10. **不承诺录取**，只做辅助建议。
11. **访谈未完成不许进入筛选**。
12. **字段不确定时查 `references/database.md` 与 `query_examples.sql`**，不要凭空编字段。
