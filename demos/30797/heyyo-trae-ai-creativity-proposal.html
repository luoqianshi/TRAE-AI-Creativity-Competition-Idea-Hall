0一句话概括

HeyYo 是一款计划中的 AI 语音整理助手：按下快捷键即录音，松手后自动转写、去口语、补上下文、按个人词典润色，输出可直接用于学习与工作场景的干净文本，并希望覆盖桌面与移动端的高频输入时刻。

1创意名称 + 创意介绍

创意名称：HeyYo · AI 语音整理助手。

对于每天需要在文档、邮件、即时通讯、代码注释、学习笔记、需求文档中频繁打字的用户来说，打字本身是认知负担之外的第二层负担——思路被键盘打断，口语表达的速度远高于文字输出速度，但口语录音又无法直接粘贴使用。HeyYo 希望做一个「说话即出稿」的小工具：用户在任意应用中用快捷键唤起录音，说话结束后立刻得到一段可直接使用的文本，而不是未经整理的原始转录。

我们计划通过如下流程把语音变为可粘贴文字：

① 快捷录音

全局快捷键或一键唤起，支持桌面（Windows / macOS / Linux）与移动端（移动端 App 或系统分享）。

② 语音转写

在本地或低延迟服务端完成实时 ASR，优先保证中文普通话与常见中英混场景的准确度。

③ AI 整理

去除「呃、那个、然后」等口语填充词，保留关键信息，自动补充上下文、术语与标点。

Demo 将验证：快捷键录音 → 一键整理 → 直接粘贴到任意编辑器的完整链路，并尝试给出不同场景下的差异化输出风格。

2目标用户及痛点

目标用户：在学习或工作中进行高频文字输入的人群。

典型用户画像：

  • 需要频繁写文档、邮件、汇报的职场人士；
  • 在会议中记录要点、会后整理纪要的团队成员；
  • 需要撰写代码注释、PR 描述、需求文档的工程师与产品经理；
  • 需要记笔记、写论文或整理学习资料的学生与研究者；
  • 偏好口述思考、但希望结果以文字沉淀的知识工作者。

核心痛点：

  • 打字速度跟不上思路，写长文档时反复在「想」与「打」之间切换；
  • 语音转写工具只给「原文」，口语化严重、有错别字、缺结构，仍需重写；
  • 术语、缩写、专有名词（人名、项目名、内部代号）常被转写错误；
  • 不同场景（会议纪要 / IM / 邮件 / 代码注释）需要不同风格，但工具不分场景；
  • 跨设备与跨应用使用不便：桌面编辑器里还要切到另一个 App 才能录音。

3价值与意义

我们希望 HeyYo 能为学习者与工作者带来三层价值：

  • 效率价值：把语音直接变为可用文本，显著缩短「说话 → 成文」的时间；
  • 认知价值：降低文字输入的摩擦，让注意力停留在思考本身而非打字动作；
  • 个人化价值：通过个人词典与上下文感知，让输出「像自己写的」而不是机器腔。

它的意义在于：让「语音」真正成为一种通用输入方式，而不只是录音或原始转写的副产品。对高频文字输入的用户而言，HeyYo 计划成为像剪贴板、输入法一样的基础设施级工具。

5核心能力（创意方案展示）

⌨快捷录音

计划提供全局快捷键（如 Fn / 自定义组合键）与托盘按钮，录音无需切换应用。

🎙语音识别（ASR）

优先支持中文普通话，兼容中英混场景，Demo 阶段在常见安静环境验证准确率。

✂AI 清理口语

去除冗余填充词与重复表达，保留关键信息，形成简洁、通顺的句子。

🧩上下文感知回填

结合当前应用、当前文档片段与历史记录，自动补齐指代、术语与默认语境。

📖个人词典

用户可自定义人名、项目名、技术术语、缩写规则，避免反复纠错。

🖥跨桌面 / 移动输入场景

桌面端覆盖主流编辑器与办公软件；移动端通过分享或系统入口接入常见 App。

6Demo 计划

我们计划在本次大赛期间，使用 TRAE Work / TRAE IDE 搭建一个可运行的 Demo，用于验证上述核心链路是否可行。Demo 的目标不是交付产品，而是证明创意中最关键的那一步：

「语音 → 干净文本 → 可直接粘贴」。

阶段内容验证点
阶段一 在 TRAE Work / TRAE IDE 中搭建最小 Demo：桌面端录音 → ASR → 文本整理 → 复制到剪贴板。 端到端可跑通；用户可用快捷键触发并粘贴到任意文档。
阶段二 接入场景模板（会议 / IM / 邮件 / 代码注释 / 笔记 / 需求）与个人词典雏形。 同一语音输入在不同场景模板下产出不同风格的文本。
阶段三 打磨交互：可视化录音窗口、一键重写、多段结果对比与选择。 交互流畅，且可在现场演示中稳定复现。
Demo 阶段仅用于验证创意可行性，后续会实现跨平台细节、更丰富的场景模板以及个人词典的长期维护机制。

7与 TRAE 的关系

HeyYo 与 TRAE 的关系定位如下：

  • 开发工具：我们计划使用 TRAE Work / TRAE IDE 完成 Demo 的原型搭建与代码管理；
  • 灵感来源：TRAE 作为面向开发者与知识工作者的 AI IDE，让我们对「高频输入场景」感同身受——写作、代码注释、需求文档都是 HeyYo 的目标场景；
  • 可组合的能力：希望在 HeyYo 的 Demo 中体现「AI 增强日常输入」的思路，这与 TRAE 面向编码与知识工作的增强方向一致；
  • 长期目标：如果 HeyYo 获得进一步推进的机会，不排除与 TRAE 生态在「代码注释 / 需求文档」等场景做更深的结合。

8风险与边界

在推进 Demo 与后续计划时，我们也会主动关注以下风险与边界：

  • 语音识别准确度：嘈杂环境、口音、行业术语、中英混等场景下 ASR 可能出现偏差；Demo 会把场景控制在安静环境与常见术语范围内；
  • AI 整理后的信息失真：AI 可能过度改写或丢失关键细节，我们计划在 Demo 中保留「原文 / 对比模式」，让用户可回退与人工复核；
  • 隐私与数据处理：录音内容往往涉及工作与学习中的敏感信息，Demo 阶段会尽量减少数据留存，并在正式阶段明确数据处理与存储策略；
  • 跨平台与系统权限：全局录音、剪贴板读写等行为需要系统权限支持，不同操作系统之间的差异会影响体验，后续会实现分平台适配；
  • 性能与响应：高频输入场景对延迟敏感，后续会实现端侧 / 本地模型等加速方案，避免打断用户思路。

我们希望通过 Demo 阶段对这些边界形成真实的体感，为后续的产品化决策提供依据，而不是过早下结论。
