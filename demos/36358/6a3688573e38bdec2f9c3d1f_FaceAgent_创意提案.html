FaceAgent

面向 Agent 生态的多模态实时交互中间件

创意名称 + 创意介绍
想解决什么问题

当前 Agent 产品的人机交互模式主要依赖纯文本和少量图片，信息传递效率有限，用户难以直观、高效地表达复杂需求——例如"帮我看看这个视频的色调对不对""这个页面的交互手感怎样"。而多模态大模型（如 Seed 2.0、Qwen 3.5 Omni 等）的实时交互能力正在快速成熟，"口喷编程"等新型交互范式初现曙光，但尚未形成面向 Agent 生态的标准化交互方案。

为什么会想到做这个

随着 Computer Use 和实时多模态模型的突破，"像和人视频通话一样和 AI 协作"正在从想象变为现实。然而，目前这些能力大多停留在模型层面，缺少一个将实时多模态交互与现有 Agent 工作流（MCP 工具调用、本地知识库等）有机串联的中间层，导致用户无法在"视频通话"的自然交互中，同时享受 Agent 生态已有的强大工具能力。

大概是什么产品

FaceAgent 是一款面向 Agent 生态的多模态实时交互中间件（软件形态），以支持实时音视频交互的多模态大模型为核心，向上提供"视频通话式"的自然交互体验，向下通过 MCP/ACP 协议与本地 Agent 及工具链双向协作，让用户能够像打视频电话一样，直观地提出需求、反馈效果、完成复杂工作流。

目标用户及痛点
面向哪些用户

工作流涉及较复杂多模态数据（视频制作、前端交互设计、UI 审稿等）的专业人群，以及需要强人机交互能力的知识工作者（模拟面试练习的求职者、远程协作团队等）。

在什么场景下使用

通过"视频通话"直观展示视频成片或网页交付物，口头描述调整意见；发起模拟面试时实时调用私有知识库；在视频交互中引导 Agent 操作电脑，形成高效闭环。

当前痛点
  • 现有 Computer Use 方案尚不成熟，操作可靠性不足，且缺乏实时反馈通道，用户难以在 Agent 执行过程中及时干预和纠正。
  • 普通实时视频交互虽然自然，但受限于模型自身的知识边界，无法调用用户本地的知识库和工具链，能力天花板明显。
  • 文本交互在处理多模态内容（视频效果、页面交互、视觉设计）时表达效率极低——"说不如看，看不如指"。
价值与意义

FaceAgent 将人机交互从"打字-等待-看结果-再打字"的低效循环，升级为"视频通话式"的实时协作模式。用户可以用最自然的方式（语言 + 视觉展示）表达需求，Agent 可以实时理解多模态信息并调用工具链执行，大幅缩短从"想法"到"交付"的路径。

特别是在视频制作、前端开发、设计审稿等重度多模态工作流中，沟通成本可降低 50% 以上，迭代效率显著提升。

具体实现思路

FaceAgent 以 Seed 2.0 等具备多模态实时交互能力的大模型为核心"感知与表达层"，作为用户交互的第一入口。在此基础上构建双向协议适配层：

MCP 调用

本地 Agent → FaceAgent

本地 Agent 通过 MCP 协议向 FaceAgent 发起需求——例如"帮我审阅一下用户制作完成的视频效果""帮我优化当前的 Computer Use 操作流程""让我与用户直接进行实时对话"等。FaceAgent 利用多模态实时交互能力，将视频、网页等复杂交付物转化为直观的视觉反馈，或在对话中充当用户与本地 Agent 之间的实时交互桥梁。

ACP 调用

FaceAgent → 本地 Agent

FaceAgent 通过 ACP 协议向本地 Agent 发起请求——例如用户发起模拟面试时，FaceAgent 将实时对话中的需求传递给本地 Agent，由本地 Agent 查阅用户私有知识库，再将检索结果回传给 FaceAgent 进行口语化表达，让用户享受到比模型本身更强的知识增强能力。

用户（语音 + 视频）
↔
多模态大模型
感知与表达层
↔
MCP / ACP 协议适配层
↔
本地 Agent & 工具链

既能被本地 Agent 调用提供实时交互，又能主动调用本地 Agent 的知识与工具——双向连接实时多模态交互与 Agent 生态的桥梁
