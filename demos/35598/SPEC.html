1. 项目概述

OCR 桌面工具是一个基于 Tauri 框架开发的桌面应用程序，用于从图像和 PDF 文档中自动识别文字并进行翻译。

技术栈

  • Tauri 2.x 桌面应用框架
  • Rust 后端核心逻辑
  • React + TypeScript 前端界面
  • SQLite 本地数据存储
  • ocrs Rust OCR 引擎

项目结构

ocr-desktop-tool/
├── src/                    # React 前端源码
│   └── main.tsx           # 前端入口
├── src-tauri/             # Rust 后端源码
│   ├── src/
│   │   ├── domain/        # 领域层：核心业务实体和接口定义
│   │   ├── infrastructure/# 基础设施层：外部服务适配器

│   │   ├── interface_layer/# 接口层：Tauri 命令定义

2. 技术架构

2.1 整体架构

采用五层架构设计（洋葱架构），实现关注点分离和依赖倒置：

interface_layer (接口层)
Tauri 命令定义，处理前端请求和事件推送
application (应用层)
用例编排，协调领域服务和基础设施
domain (领域层)
核心业务逻辑，定义实体、值对象和服务
infrastructure (基础设施层)
外部技术适配：OCR、PDF、数据库、缓存、API客户端
model (模型层)
机器学习模型训练和管理

2.2 依赖关系

interface_layer → application → domain ← infrastructure
                                               ↓
                                          model

关键原则：领域层不依赖其他层，通过接口抽象实现依赖倒置。

3. 后端架构规范 (Rust)

3.1 领域层 (domain/)

文件职责
entities.rs核心实体定义：Document, FileItem, Mapping, OcrResult 等
value_objects.rs值对象：ProcessingStatus, FileType 等
traits.rs接口定义：OcrEngine, PdfProcessor, TranslationModel 等
services.rs领域服务：InvoiceParser 发票解析
errors.rs领域特定错误类型

实体定义规范

// 实体必须实现 Clone + Send + Sync
#[derive(Clone, Debug)]
pub struct Document {
    pub id: String,
    pub file_path: String,
    pub file_name: String,
    pub file_type: FileType,
    pub pages: Vec<PageResult>,
    pub status: ProcessingStatus,
}

Trait 接口规范

// 所有 trait 必须标注 Send + Sync 以支持并发
pub trait OcrEngine: Send + Sync {
    fn recognize(&self, image_path: &Path) -> Result<String, String>;
    fn recognize_with_confidence(&self, image_path: &Path) -> Result<(String, f32), String>;
}

3.2 基础设施层 (infrastructure/)

文件职责实现接口

3.3 应用层 (application/)

包含 6 个用例：

  • FileUseCase - 文件管理（添加、删除、查询）
  • OcrUseCase - OCR 处理（单文件/批量）
  • TranslationUseCase - 翻译处理（优先本地模型，备选 API）
  • MappingUseCase - 映射表管理（CRUD、导入导出）
  • ExportUseCase - 文档导出（DOCX/Markdown）
  • StatisticsUseCase - 统计数据获取

3.4 接口层 (interface_layer/)

命令定义规范

// 命令必须使用 #[tauri::command] 属性
// 参数必须实现 Deserialize，返回值实现 Serialize
#[tauri::command]
pub fn file_add(paths: Vec<String>, state: State<'_, AppState>) -> Result<Vec<FileItem>, String> {
    state.file_usecase.add_files(paths)
}

事件推送规范

// 使用 app.emit() 推送异步事件
let _ = app.emit("ocr:complete", OcrComplete { file_id, result });

// 事件 payload 必须实现 Clone + Serialize
#[derive(Clone, serde::Serialize)]
pub struct OcrComplete {
    pub file_id: String,
    pub result: OcrResult,
}

3.5 模型层 (model/)

负责翻译模型的加载和训练，模型文件存储在用户数据目录下的 weights/model.zip。

7. 错误处理规范

7.1 错误传播

  • 使用 Result<T, String> 作为标准错误返回类型
  • 错误信息必须是人类可读的字符串
  • 基础设施层错误应转换为领域错误

7.2 错误码规范

// 错误格式：类别: 详细描述
Err("FILE_NOT_FOUND: 文件不存在")
Err("OCR_FAILED: 图片识别失败")
Err("TRANSLATION_ERROR: 翻译服务不可用")

7.3 日志规范

  • 使用 log::info!, log::warn!, log::error!
  • 生产环境使用 env_logger
  • 关键操作必须记录日志

8. 编码规范

8.1 Rust 编码规范

  • 遵循 Rust API Guidelines
  • 模块级文档使用 //! 注释
  • 公共 API 必须编写文档注释
  • 使用 Arc<T> 实现共享所有权
  • 所有 trait 对象必须 Send + Sync
