Problem

传统健身的三大痛点

当健身变成"凭感觉"，进步就变成了玄学。

01
🏋️
动作不标准，无从知晓
深蹲膝盖内扣、硬拉腰部代偿……错误动作日复一日重复，轻则无效，重则受伤。传统方式下用户完全无法感知自己的动作质量。
02
📉
训练凭感觉，缺乏量化
没有实时心率、没有力量分布、没有动作轨迹。训练强度全靠体感判断，难以科学地渐进超负荷，训练效果无法量化评估。
03
🤷
计划靠搜索，千人一面
网上找的"通用计划"无法适配个人体质和恢复状态。私教费用高昂且质量参差，普通健身者缺乏个性化、持续性的专业指导。

Protocol Design

三通道异构协议设计

不同数据类型走不同通道，各有最优解。

B
BLE 5.0 心率通道
低功耗 · 小数据 · 持续连接
服务 UUID: 0000180d-...-00805f9b34fb
特征 UUID: 00002a37-...-00805f9b34fb
数据包: 13字节 小端序
├─ seq UInt16 序号
├─ timestamp UInt32 时间戳(ms)
├─ heartRate UInt8 心率(BPM)
├─ spo2 UInt8 血氧(%)
├─ signal UInt8 信号质量
├─ battery UInt8 电量(%)
└─ wearFlags UInt8 佩戴/充电
U
UDP 运动数据通道
高频 · 低延迟 · 局域网
频率: 50Hz (20ms/帧)
数据包: 24字节 小端序
├─ header UInt8 0xAA 起始
├─ deviceId UInt8 设备标识
├─ timestamp UInt32 时间戳(ms)
├─ accelX/Y/Z Float 加速度(g)
├─ gyroX/Y/Z Float 角速度(°/s)
├─ pressure Float 压力值(N)
└─ checksum UInt8 校验和
M
MQTT 云端备份通道
可靠 · JSON · 降级备份
Broker: MQTT over WebSocket
Topic: gymPal/{userId}/sensor
格式: JSON
{
  "seq": 1024,
  "timestamp": 1718236800000,
  "accel": [0.12, -0.03, 9.81],
  "gyro": [1.2, -0.5, 0.3],
  "pressure": 45.2,
  "spo2": 98, // 仅MQTT有
  "signalQuality": 92 // 仅MQTT有
}
AI Pipeline

AI 分析全流程

从传感器原始数据到个性化报告，4步闭环。

1
训练数据采集
ESP32 双设备并行采集：S3 以 50Hz 采集 IMU 运动数据（加速度+陀螺仪+压力），C3 通过 BLE 持续传输心率+血氧+佩戴状态。所有数据实时上传至后端。
ESP32 × 2 50Hz 采样
2
数据聚合与结构化
后端将30秒窗口内心率、压力数据批量缓冲上报，动作数据实时上报。训练结束时，汇总为完整的结构化 Prompt：用户画像 + 训练摘要 + 动作明细 + 心率区间。
30s 缓冲窗口 结构化 Prompt
3
Coze AI 流式分析
通过 Coze Chat API (SSE) 调用预配置的 AI Bot，Bot 按模板输出4大板块：训练代谢分析、动作技术分析、个性化恢复建议、科学训练计划，以及整体评级(A-F)。
SSE 流式 4大板块
4
报告解析与展示
后端正则提取 AI 输出的结构化标签（【训练代谢分析报告】等），存入 PostgreSQL。前端在报告页以卡片化 UI 呈现，支持历史报告回溯和对比。
正则提取 持久化存储
Innovation

五大创新点

不是简单拼凑，而是系统级创新。

1
UDP/MQTT 双通道自动降级
业界首创的运动数据传输降级机制。实时监控丢包率，5秒采样窗口，>30% 自动切换 MQTT 云端通道，<10% 恢复 UDP 直连。在局域网抖动环境下仍能保证数据完整性，实现零数据丢失。
2
异构传感器数据融合
IMU 运动数据（50Hz UDP）与 心率/血氧数据（BLE 通知）两条异构数据流，在 APP 端实现时间戳对齐和数据融合，构建完整的"运动-生理"双维度训练画像。
3
AI 驱动的训练闭环
不仅"采集数据"，更"理解数据"。Coze AI 将原始传感器数据转化为4大结构化分析报告 + 整体评级，自动生成下一阶段训练计划，形成"训练→分析→调整→再训练"的智能闭环。
4
24字节极简二进制协议
针对 MCU 有限算力设计的 24 字节 UDP 包格式：Header + DeviceID + Timestamp + 6轴IMU + 压力 + 校验和。在 50Hz 采样率下仅占用 ~12Kbps 带宽，ESP32 即可轻松处理。
5
跨端统一体验
Expo 54 + React Native 一套代码同时覆盖 Android / iOS / Web。利用 Metro 平台分流（.native.ts / .web.ts）解决 BLE 等原生模块的 Web 兼容问题，真正实现"写一次，跑三端"。
