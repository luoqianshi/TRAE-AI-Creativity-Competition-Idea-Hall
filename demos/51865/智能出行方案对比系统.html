1 项目背景与痛点

日常规划出行时，用户普遍面临三大痛点。

🔗 痛点一：信息割裂

火车票在12306、飞机票分散在各OTA平台，来回切换搜索费时费力。查完火车再查飞机至少需要切换 3-5 次页面，不同平台的界面和操作逻辑完全不同，学习成本高。

🧠 痛点二：决策困难

面对几十趟高铁和多个航班，价格从几百到几千不等、时长从2小时到20小时不等，人工比对几乎不可能做到全面客观。普通用户只能凭感觉选"差不多"的方案，很可能错过真正最优的选择。

🔄 痛点三：中转盲区

中国大量城市间（如牡丹江到长沙、青岛到昆明等）没有直达车次或航班。普通用户不知道该经哪个城市中转最省钱最省时，自行规划换乘方案门槛极高——需要查阅铁路线路图、航班时刻表、计算换乘时间，对绝大多数人来说是不可完成的任务。

💡 小结：传统方式下完成一次跨城出行决策往往需要 30分钟以上 的反复搜索和记录，且结果未必最优。

2 解决方案与核心功能

本系统以WorkBuddy技能形式部署，提供一句话触发、全方案输出的智能出行对比能力，涵盖四大核心功能。

🚄 火车票实时查询

对接12306官方API，支持按日期/出发站/到达站查询全部车次信息，包括高铁/动车/普速列车类型、各席别票价、实时余票及购票状态，同时支持成人票与学生票切换。

✈️ 飞机票查询

通过OpenSky Network开源API获取全国主要机场的航班时刻表（覆盖50+城市机场），基于城市间距离建立多舱位票价估算模型（经济舱约0.8元/公里），提供航班号、航空公司、机型等完整信息。

🔄 中转方案引擎

内置七大区域枢纽城市库，自动识别最优中转路径，支持纯火车中转、纯飞机中转、混合中转三种模式，自动校验换乘时间合理性，输出含两段行程明细和总价的完整方案。

⭐ 智能推荐评分

多维度加权归一化算法，综合价格、时间、舒适度三维度评分，默认均衡模式(40%+35%+25%)，支持价格/时间/舒适度优先切换，以5星制直观展示，同步输出四类推荐。

模块详解

模块职责关键技术点
travel_compare.py 主调度器 argparse参数解析，支持10+选项（日期/城市/学生票/预算/优先级/中转开关/输出格式），统一协调各子模块调用并汇总结果
query_train.py 火车票查询 ① curl直连12306 REST API
② 正则解析3000+车站名→电报码映射
③ 解码12306特有10字符位票价编码（座位码+5位角单位价格+4位余票）
④ 模拟浏览器UA+Cookie维持会话
query_flight.py 机票查询 ① OpenSky Network API获取航班状态
② 预置40+城市对距离矩阵
③ 距离×单价系数模型：经济舱×0.8/超经×1.3/公务×2.5/头等×4.0
query_transfer.py 中转引擎 ① 七大区域枢纽智能匹配
② 笛卡尔积式两段行程组合
③ 三类换乘时间校验：火车≥30min、飞机≥120min、混合≥120min
recommend.py 推荐算法 ① min-max归一化消除量纲差异
② 四档权重预设（均衡/价格优先/时间优先/舒适度优先）
③ 舒适度复合模型（车型+座位+时长衰减）
④ 星数转换：score×5 取整+半星判定

核心算法公式

综合评分 = 价格权重 × 价格得分 + 时间权重 × 时间得分 + 舒适度权重 × 舒适度得分

模式价格权重时间权重舒适度权重
均衡模式（默认）40%35%25%
价格优先60%25%15%
时间优先25%60%15%
舒适度优先25%15%60%

三个维度得分均经过 min-max 归一化映射到 [0, 1] 区间，再按权重加权求和，最终通过 score × 5 转换为★星级。

使用示例

# 基础查询（含直达+中转）
python travel_compare.py 2026-05-20 北京 上海

# 价格优先模式
python travel_compare.py 2026-05-20 青岛 长沙 --priority price

# 学生票 + 预算限制
python travel_compare.py 2026-05-20 成都 昆明 --student --budget 500

# 只查中转方案
python travel_compare.py 2026-05-20 牡丹江 长沙 --transfer-only
