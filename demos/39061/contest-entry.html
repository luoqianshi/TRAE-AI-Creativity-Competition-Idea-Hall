Playwright Script Recorder（PWSR）是一整套面向 AI Agent 的浏览器自动化 harness：让 AI 自主完成浏览器任务，把执行过程作为证据自动沉淀为可回放、可修复、可批量运行的工作流；稳定、重复的步骤交给脚本执行，复杂、需要判断的环节仍保留 AI 介入，从而同时获得更高效率和更强灵活性。

产品形态 一套可被 AI Agent 调用的浏览器自动化 harness —— 录制器、证据管线、可恢复工作流运行器、脚手架与 Skill 集成协同成完整闭环，开发者与 AI 都能直接驱动。

PWSR 聚焦的两个核心痛点

// CORE PROBLEMS

这个项目并不是再做一个“能点浏览器”的 AI，而是解决浏览器自动化真正落地时最容易卡住的两件事：重复任务依然低效，以及脚本仍然高度依赖人工逐站编写。

痛点一 · 效率

AI 已经能执行浏览器任务，但重复流程仍然成本很高

当前 AI Agent 已经可以完成登录、查询、填表、截图等操作，但在面对相似任务时，往往仍要重新理解页面、重新规划步骤、重新逐项执行。任务越固定、执行次数越多，这种“每次从零开始”的方式就越浪费时间、token 和上下文预算。

PWSR 的回答 把 AI 一次真实完成任务的执行过程自动沉淀为脚本，让后续同类流程中的重复步骤直接回放，只把少数需要判断的环节留给 AI 介入，而不是每次从头重新推理。
痛点二 · 开发成本

现有浏览器自动化仍然主要依赖人工写脚本，换任务就要重写一套

今天当然已经可以通过手写脚本去操作浏览器，但这件事本身依然繁琐：面对不同网站、不同任务、不同表单流程，往往都要重新分析页面、重新组织步骤、重新维护一套脚本。脚本能力很难规模化，核心瓶颈不只是执行，而是脚本的生产方式仍然过度依赖人工。

PWSR 的回答 提供一套让 AI 自主研究页面、自主完成任务并自动沉淀脚本的通用 harness；复用的不是同一份脚本，而是同一套探索、执行与沉淀流程，让每个网站都能生成自己的可复用工作流。

进一步的价值：脚本会在复用中继续进化

当脚本在未来执行时遇到页面变化、字段差异或异常中断，PWSR 会继续记录新的问题和证据，并把这些信息带回脚本优化过程，让工作流不是一次性产物，而是能够持续修复、持续变稳的长期资产。

目标用户与使用场景

// WHO & WHEN

PWSR 同时服务两类使用者：需要把重复浏览器劳动自动化的业务/技术人员，以及直接驱动浏览器去完成任务的 AI Agent（如 Codex 类编码/操作 Agent）。它的价值在「同一类任务要反复做很多次」时最明显。

核心用户一

需要批量重复操作后台的运营 / 数据 / 测试人员

每天在电商后台、ERP/OA、招聘或内容平台上重复登录、查询、填表、改状态、巡检。这些动作高度固定却必须人工逐条点选，耗时且容易出错。

使用场景 同一套表单 / 流程每天要跑几十上百次时，让 AI 自主跑通一次，之后由 PWSR 沉淀的工作流批量回放，人只在异常时介入。
核心用户二

需要可靠操作浏览器的 AI Agent 自身

AI Agent（如 Codex 类编码 / 操作 Agent）在执行真实浏览器任务时，最难的不是「点一次」，而是在重复任务中既稳定又省 token，并能在页面变化、流程中断时可恢复地继续。

使用场景 Agent 直接把 PWSR 作为浏览器操作 harness 调用：录制即证据，证据即工作流，复用工作流而非每次从零推理，并保留 pause/resume 接口在异常时交回人或 AI 介入。

没有它的时候：要么纯人工，要么纯脚本，二者都难规模化

纯人工重复操作低效易错；纯手写脚本则换一个网站就要重新分析、重新编写、重新维护，且脚本一旦遇到页面变化就直接失败。PWSR 用「录制证据 → 沉淀可恢复工作流」填上了中间这段断层。

03 / 05

它怎么工作：一套 harness，四个环节

// HOW IT WORKS

PWSR 不是「点浏览器」这一个动作，而是把录制、证据沉淀、工作流生成、可恢复回放串成一条闭环。复用的不是某一份脚本，而是这整套探索→执行→沉淀的 harness。

01 · RECORD

录制一次真实执行

AI 或人通过录制 CLI 真实驱动浏览器完成任务，每个 snapshot、click、fill 都被原样记录为证据。

02 · EVIDENCE

沉淀为证据链

raw.jsonl 保留完整动作保真度，clean-recording 再产出可读的执行记录、稳定 locator 与可复用步骤体。

03 · WORKFLOW

生成可恢复工作流

基于稳定证据生成分步、可检查点、可恢复的工作流，而不是一条易碎的线性脚本。

04 · REPLAY

批量回放 + 人机协同

通过统一入口批量执行；遇到差异时 pause/resume，由 AI 或人介入后从断点继续，而非整段重跑。

pwsr · record → run
# 1) 录制一次真实执行，每步都成为证据 $ pwsr record --dir runs/task -- -s=task open https://example.com $ pwsr record --dir runs/task -- -s=task --raw snapshot $ pwsr record --dir runs/task -- -s=task fill e5 "user@example.com" # 2) 沉淀证据并生成可复用工作流 $ pwsr review runs/task $ node clean-recording.js --dir runs/task # 3) 批量回放，paused 时介入后从断点 resume $ pwsr run --run-dir runs/task --input data/item.json workflows/task/task.workflow.js

价值与意义

// VALUE
效率提升

把重复任务从“每次都让 AI 逐步推理”变成“重复步骤由脚本回放，复杂环节由 AI 决策”，既显著缩短执行时间，也避免在简单操作上反复消耗推理资源。

所有网站通用

它不是把同一份脚本复用到所有网站，而是提供一套通用 harness，让 AI 在不同网站上都能沿着同样的探索、执行与沉淀流程，生成各自可复用的脚本和工作流。

越用越稳

当页面变化或流程中断时，系统会保留现场证据并把问题带回脚本中继续优化，让脚本不是“一次性”，而是能持续进化的生产工具。

它的意义不只是“让浏览器自动跑起来”，也不是在脚本和 AI 之间二选一，而是让两者协同分工：重复动作交给脚本，复杂判断留给 AI，再把整个过程持续沉淀为可复用、可修复、可放大的工作资产。

典型应用场景

// USE CASES
电商后台

批量上架、改价与巡检

让 AI 自主跑通一次完整的商品操作流程，之后把大部分重复步骤交给脚本批量回放，仅在选品判断、异常处理等复杂环节保留 AI 介入，适合多 SKU 上架、定期巡检、跨店铺维护等工作。

企业后台

ERP / OA / 报销重复填报

针对每天都要重复填写的业务表单，让 AI 先自主完成一次标准路径，之后由脚本执行大部分固定填报步骤，在少数需要判断的字段上再由 AI 介入，减少大量人工点选和重复录入。

招聘平台

批量处理简历与候选人状态

让 AI 先自主完成一次标准招聘流程，后续在简历筛选、状态更新、通知发送等环节稳定批量回放，减少人工逐条处理。

内容平台

多平台发布与结果校验

让 AI 先自主跑通一次内容发布流程，之后在多个平台重复执行，并在发布后做自动检查，适合运营和内容团队的日常批量工作。
