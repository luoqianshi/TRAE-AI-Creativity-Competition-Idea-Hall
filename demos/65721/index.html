核心能力

Product
Capabilities

页面展示的不只是“能搜岗位”，而是一套真正可落地的岗位搜索 Agent 该如何理解用户、连接来源、判断有效性并输出结果。

01 / INPUT LAYER

简历与意向理解

用户可以上传简历，也可以只输入“我想找上海 AI 产品经理实习”这样的描述。Agent 先把技能、城市、岗位方向、行业偏好和排除条件结构化，再生成搜索计划。

简历解析 · 自然语言意向
02 / SOURCE LAYER

多源岗位聚合

目标覆盖招聘网站、企业官方招聘站和公众号实习信息。系统不会只盯一个来源，而是通过连接器统一抓取、标准化字段，再汇聚成一个搜索结果工作台。

招聘网站 · 官网 · 公众号
03 / FILTER LAYER

有效性过滤与匹配排序

这一步决定产品是否真的有价值。系统会结合发布时间、来源可信度、职位描述完整度、重复度和用户画像做过滤与排序，优先保留仍有投递价值的岗位。

时效判断 · 去重 · 匹配评分
04 / OUTPUT LAYER

可投递 Excel 输出

最终结果不是只停留在页面上，而是形成用户真正能使用的投递清单，包含公司、职位、地点、发布时间、来源、链接、匹配度和备注等字段。

结构化表格 · 投递管理
Agent 工作流

How It Runs

它不是单点搜索，而是一条完整的理解、召回、过滤、输出链路。重点是先把用户需求表达清楚，再让不同来源的岗位数据变得可比较、可操作。

01

输入简历或描述

上传 PDF/Word 简历，或者直接写出岗位方向、城市、行业、公司偏好与排除条件

02

配置模型与搜索源

用户填入自己的大模型 API Key，并选择要覆盖的平台、官网招聘页或公众号来源范围

03

自动检索并过滤

连接多源岗位信息，完成字段标准化、发布时间过滤、重复岗位合并和匹配度排序

04

输出结果并辅助投递

网页中查看结果卡片与推荐理由，同时导出 Excel，用于后续手动投递、跟进和记录

项目定位

Can This
Actually Work?

能做，而且很适合作为项目。真正的难点不是“搜岗位”本身，而是多源连接、信息标准化、时效过滤和匹配排序。只要把系统拆成输入理解层、来源连接层、规则过滤层和导出层，第一版就能做出可验证的 MVP。

更合理的路线不是一开始就做“全自动代投”，而是先把高质量岗位发现 + Excel 管理 + 推荐解释做扎实。这样产品价值更明确，也更容易在比赛、答辩和真实用户测试里站得住。

落地方案

Product Roadmap

这个项目最适合先从 Web 形态切入，再根据使用场景扩展桌面端。下面这些模块对应的是这类产品真正需要的落地路径。

01

Web First

推荐首发形态

建议先做网页应用。浏览器上传简历、配置 API Key、查看结果与导出 Excel 的链路最短，也最适合项目展示与答辩。

02

Desktop Later

第二阶段扩展

如果后续要做更强的本地文件管理、缓存与长期任务，可以再用 Electron 或 Tauri 包成桌面端，而不是一开始就增加复杂度。

03

LLM API

需求理解与排序

支持 OpenAI、DeepSeek、通义千问等模型接口，用户自带 Key，用于简历解析、查询生成、岗位摘要和匹配理由生成。

04

Connector Layer

来源连接器

按招聘网站、官方招聘页和公众号信息拆分连接器，统一抽取职位名、公司、地点、发布时间、链接等字段。

05

Filter Engine

有效性判断

用规则与模型结合做发布时间过滤、重复岗位合并、低质量招聘剔除和结果排序，这是产品能否有用的关键所在。

06

Excel Workspace

最终交付物

结果页 + Excel 文件 + 搜索记录，是最直接能体现产品价值的交付物，也比单纯聊天问答更适合作为第一版产品。
