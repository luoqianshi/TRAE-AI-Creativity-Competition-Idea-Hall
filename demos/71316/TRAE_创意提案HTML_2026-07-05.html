1创意介绍

1.1 这是一个什么样的项目

我们做了一款双鲲鹏 920 模组载板——CPU 模组 + 载板架构。两个鲲鹏 920 模组插在自研载板上， 引出 3 个 X16 物理 PCIe slot，目标是跑 PCIe GEN4 x16 高速通道。

调试时撞上一个经典工程问题：PCIe GEN4 x16 通道不稳定。 用 serdestool 调 ffe（feed-forward equalization，前馈均衡）参数怎么都调不通，link training 在 Polling 阶段反复 fail。

找华为 PAE 排查，根因锁定了：模组 BIOS 对 PCIe 的配置和载板实际配置对不齐。这是个软件配置问题， 但——改 BIOS 必须找 IBV（Independent BIOS Vendor，独立 BIOS 供应商），要给钱、要走流程、要等版本。

我们决定绕开 IBV。方案是这样的：

"协议层 hack" 方案
用载板侧 CPLD（国产安路 Anlogic EF3L90CG400B）通过 Hisport 协议和鲲鹏 920 模组通讯， 改模组内部 Hilink 寄存器的配置（PCIe 通道类型 / 带宽 / 速率 / Lane 翻转 / PN 翻转）， 让模组自己重新配置 PCIe 通道——和载板实际配置对齐。 然后再上 serdestool 调 ffe，通道就稳了。

协议层 hack 是临时方案，最终量产还是要烧 BIOS（让 IBV 写）。但这给了我们研发阶段的临时通道—— 不用等 BIOS 改版，不用付 IBV 费用，调通的参数值最终同步给 IBV 烧进 BIOS 即可。

1.2 7 步工作流：从 0 到跑通 PCIe 通道

  1. 摸清模组寄存器手册 8 份 S920 模组资料（5 份 .pdf + 3 份 .md）共 14 MB。 真读完寄存器手册第 2.2.2 节，60+ 字节 Hilink 寄存器的地址、含义、配置流程全部落地。
  2. 查 ANlogic IP 核 API ANlogic 自家的 sgpio_over_hisport_tx_top / rx_top IP 核使用方式（md + pdf）全读。 真值参数：clk_sys=25M, clk_tx=50M, clk_rx=100M, buffer_count_max=8（每帧 8 字节）。
  3. 写 CPLD 端 Verilog 代码 在主程序 gm_920_920s_2p.v（1496 行 / 30+ 已例化模块）上增量开发： 新增 4 个文件 —— hilink_cfg_rom.v（60 字节 ROM）、 hisport_tx_top.v（IP 核 wrapper）、 smc_data_ram.v（BMC 通信 RAM）、 顶层例化 5 行。
  4. 主程序顶层 patch 把 4 个新模块接到 localbus_bmc.hisport_tx / hisport_rx（端口名已存在但未接，前人规划过此路径）。 PLL_50M 已产生 Hisport 专用 25/50/100 MHz 时钟，不用动时钟树。
  5. 调测 PCIe 通道 上板 → CPLD 加载 → Hilink 配置下发 → PCIe link training → serdestool 调 ffe。 通道稳定后用 lspci + ethtool 验证速度。
  6. 录屏 + 文档化 飞书自带录屏（首选）+ OBS（备用），录完整调测过程 + 速度测试。 输出 4 份导读 + 项目全貌图 + 5 件事清单 + 系统 prompt 模板 = 完整资料链。
  7. 开源给鲲鹏社区 完整寄存器真值表 v3（从硬件设计指南 105-107 页真读推导） + ANlogic IP 核使用方式 + 主程序 patch diff。 不烧 BIOS 改 PCIe 的开源方案，给同样踩坑的硬件工程师。

2.3 痛点：硬件工程师"孤独的 4 个时刻"

① 没人帮写代码
寄存器手册 200+ 页、IP 核 API 文档 50 页，主程序 1500 行没人讲解—— 硬件项目调试常常是"一个人 vs 一摞手册"。没有 AI 的时候，靠的是"老法师"经验传承，新人要走 2-3 年弯路。
② 资料分散难查
鲲鹏 920 模组一个项目就有 8 份 S920 资料 + 11 份 ANlogic 资料 + 43 份 Verilog 代码， 跨 14 MB / 79 个文件。"我那个寄存器在哪份 PDF 第几页" 是日常的灵魂拷问。
③ 英文 datasheet 慢
国产芯片越来越多，但很多底层文档英文 + 翻译腔 + 命名混乱， 查"type 字段编码"翻 30 分钟没找到是常态。
④ 寄存器无参照
寄存器手册给你位域定义，但"实际项目该填什么真值"手册不写。 典型应用得自己推、自己试、自己 debug。

660 字节 ROM 真值表（核心交付物）

6.1 KP920 + GEN4 x16 = Hilink7+8+10 组合

本项目 = KP920（不是 KP920S）。GEN4 x16 = Hilink7 + Hilink8 + Hilink10 三个 Hilink 拼出 3 个 X16 物理 slot。 典型应用：m7 / m10 / m8 各接 X16 slot，PN 不翻转。

6.2 Hilink 寄存器位真值（2 个 32 bit word = 4 个 8 bit 寄存器）

字段位域真值本项目
PCIe/SerDes 模式 (type) [2:0] 0h=默认, 1h=PCIe, 2h=HCCS, 3h=SATA+PCIe, 4h=SAS, 5h=CXL, 6h=ETH, 7h=USB, 8h=GPIO, FFh=关闭 1h=PCIe
带宽配置 (width) [10:8] 0h=默认, 1h=X16, 2h=X8, 3h=2*X4, 4h=4*X2, 5h=X4+X2+X2, 6h=X2+X2+X4 1h=X16
速率限制 (speed) [19:16] 4h=Gen4 (16G), 3h=Gen3, 2h=Gen2, 1h=Gen1 4h=Gen4
热插拔使能 [20] 0=不支持, 1=支持 0
Lane 翻转 [21] 0=不翻, 1=翻 0（典型应用）
RX 极性反转 (RX PN) [31:24] 按位使能（每 bit 一 lane） 0x00（典型应用）
TX 极性反转 (TX PN) [39:32] 按位使能（每 bit 一 lane） 0x00（典型应用）

6.3 60 字节 Hilink 配置 ROM Verilog 模板

ROM 模板由 AI 生成，工程师只需填 5 件事的真值（5 个 case 分支）。 下表是 KP920 + GEN4 x16 典型应用下的初版真值： 

// hilink_cfg_rom.v - 60 字节 Hilink 配置 ROM
// 适用：KP920 + GEN4 x16（Hilink7+8+10 组合）
// 真值源：S920X08 硬件设计指南 105-107 页 + Hilink 简介 docx 全 88 段

module hilink_cfg_rom (
    input  wire [7:0]  addr,    // 寄存器序号 0-60
    output reg  [31:0] data     // 4 字节（低字节先传）
);

always @(*) begin
    case (addr)
        // ============= 控制寄存器（序号 0-4）=============
        8'd0: data = 32'h00000000;  // RSV0
        8'd1: data = 32'h00000000;  // RSV1
        8'd2: data = 32'h00000000;  // NIC 电源状态
        // 序号 3 = HCCS 控制寄存器（传给 CPU2_HISPORT）
        // KP920 = 01110100 (bit6=1 hccs_configure_hisport
        //                  + bit5:4=11 lane 翻转
        //                  + bit3:0=0100 组网)
        8'd3: data = 32'h00000074;  // HCCS = 2Px16 非交叉 + lane 翻转
        8'd4: data = 32'h00000000;  // 控制寄存器 2

        // ============= CPU1 Hilink4 = BMC PCIe 0/1 + SATA =============
        8'd5:  data = 32'h00_00_00_01;  // type=PCIe (1h)
        8'd6:  data = 32'h00_00_00_02;  // speed=Gen2 (BMC)
        8'd7:  data = 32'h00_00_00_00;  // RX PN=0
        8'd8:  data = 32'h00_00_00_00;  // TX PN=0

        // ============= CPU1 Hilink7 = X16 slot (m7) ★ GEN4 x16 =============
        // type=PCIe(1h) + width=X16(1h) + speed=Gen4(4h) + Lane翻=0 + 热插拔=0 + RX/TX PN=0
        8'd17: data = 32'h00_00_10_01;  // cfg1=0x01, cfg3 width=X16
        8'd18: data = 32'h00_00_00_04;  // cfg2 speed=Gen4
        8'd19: data = 32'h00_00_00_00;  // RX PN=0
        8'd20: data = 32'h00_00_00_00;  // TX PN=0

        // ============= CPU1 Hilink8 = X16 slot (m10) ★ =============
        8'd21: data = 32'h00_00_10_01;
        8'd22: data = 32'h00_00_00_04;
        8'd23: data = 32'h00_00_00_00;
        8'd24: data = 32'h00_00_00_00;

        // ============= CPU1 Hilink9 = M.2 PCIe 4.0 X4 =============
        8'd25: data = 32'h00_00_08_01;  // type=PCIe, width=待 5 件事 ②
        8'd26: data = 32'h00_00_00_04;
        8'd27: data = 32'h00_00_00_00;
        8'd28: data = 32'h00_00_00_00;

        // ============= CPU1 Hilink10 = X16 slot (m8) ★ =============
        8'd29: data = 32'h00_00_10_01;
        8'd30: data = 32'h00_00_00_04;
        8'd31: data = 32'h00_00_00_00;
        8'd32: data = 32'h00_00_00_00;

        // ============= CPU2 Hilink4 = SAS (4h=SAS) =============
        8'd33: data = 32'h00_00_00_04;  // type=SAS（5 件事 ③ 待确认）

        // ============= CPU2 Hilink5/7/8/10 = X16 slot =============
        8'd37: data = 32'h00_00_10_01;  // CPU2 Hilink5
        8'd45: data = 32'h00_00_10_01;  // CPU2 Hilink7
        8'd49: data = 32'h00_00_10_01;  // CPU2 Hilink8
        8'd57: data = 32'h00_00_10_01;  // CPU2 Hilink10

        default: data = 32'h00000000;
    endcase
end

endmodule
▍几个待实板确认的项
Hilink4 type（1h=PCIe 还是 3h=SATA+PCIe）、 Hilink9 width（X4 编码待查）、 CPU2 Hilink4 type（4h=SAS 是猜测）、 Lane 翻转（0/1）、 RX/TX PN 翻转（8 bit 中哪几位）—— 这 5 项"典型应用"给出的值是参考，最终真值要实板测试。
