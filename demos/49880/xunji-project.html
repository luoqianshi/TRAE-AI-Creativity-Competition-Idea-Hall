01 / 问题与痛点

当亲人走失，我们还有多少时间？

中国每年约有 50 万老人走失，儿童走失案件也时有发生。在发现走失后的黄金 1 小时内， 信息的传播效率直接决定了找回的概率。

信息整理耗时长

家属在情绪激动时难以组织有效信息，手动编辑寻人帖耗时 2-3 小时，内容往往不规范、不完整。

传播渠道分散

寻人信息散落在几十个微信群和朋友圈，无法追踪覆盖范围，重复转发与信息遗漏并存。

协同机制缺失

志愿者发现线索后没有统一上报通道，民警难以汇总比对，搜寻力量各自为战。

02 / 产品方案

从"人找信息"到"信息找人"

寻迹是一个基于 Web 和小程序的 AI 协同平台，通过智能信息提取、自动化内容生成和精准地理推送， 将传统数小时的信息扩散工作压缩至 10 分钟以内。

1

AI 智能信息采集

家属通过语音或文字描述走失者特征，AI 自动提取姓名、年龄、体貌特征、穿着、最后出现地点等关键信息，生成标准化档案。

2

多模态寻人内容生成

系统自动生成图文寻人海报、结构化数据卡片和语音播报稿，适配微信群、朋友圈、广播等多种传播渠道。

3

地理围栏精准推送

基于最后出现地点划定动态搜寻圈，向圈内社区志愿者、物业安保、沿街商户定向推送寻人信息。

4

线索协同上报与追踪

发现者一键上报线索（文字/图片/位置），系统自动聚类相似线索并推送给家属与民警，全程可追踪、可验证。

03 / 核心功能

四大核心模块，构建搜寻闭环

🔍

智能特征提取引擎

基于大模型 NLP 能力，从家属的非结构化描述中自动抽取关键特征（身高、衣着颜色、明显标记物等），准确率超过 90%，大幅减少信息整理时间。

📣

一键多平台发布

自动生成适配不同平台的内容格式：朋友圈长图、微信群卡片、公众号图文、广播口播稿，家属只需一键确认即可全网同步。

🌎

动态地理围栏

结合高德地图 API，根据走失时间、人员移动特征（老人/儿童/精神障碍患者）智能划定初始搜寻范围，并随时间自动扩展。

📈

线索智能聚类

对志愿者上报的线索进行时空聚类和可信度评估，自动排除重复和无效信息，向家属呈现高价值线索时间线。

04 / 技术实现

基于 TRAE 的全栈开发方案

整个项目使用 TRAE Work 和 TRAE IDE 完成从需求分析到部署上线的全流程开发， 充分利用 AI 辅助编程与 MCP 扩展能力。

TRAE Work

用于需求梳理、产品文档撰写、Prompt 工程设计和项目管理工作流搭建。

TRAE IDE

前端采用 React + TypeScript，后端使用 Node.js + Express，AI 辅助生成核心代码。

大模型能力

调用豆包大模型进行自然语言理解、信息抽取和内容生成，确保中文场景下的高精度。

MCP 扩展

通过 MCP 接入高德地图 API 实现地理围栏与路径规划，接入飞书实现消息推送。

数据库

PostgreSQL 存储结构化寻人档案与线索数据，Redis 缓存热点信息与地理位置索引。

部署

前端托管于 Vercel，后端服务部署在火山引擎云服务器，支持弹性扩容。
