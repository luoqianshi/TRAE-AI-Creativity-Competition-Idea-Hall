Origin

创意起源

一个看似跨界的灵感碰撞：当金融交易系统中的多智能体辩论架构（Bull↔Bear） 遇上网文作者日更万字的生存压力，会擦出怎样的火花？

01 / 发现
千亿市场的供给困局

中国网络文学市场规模超千亿，头部平台日更新以亿计。但优质内容供给严重不足——大量中腰部作者面临"不更没流量，更了没质量"的两难困境。日更 6000 字是生存底线，但也是质量崩塌的起点。

"一个网文作者同时是作家、编辑、架构师和运营——这太分裂了。"

02 / 灵感
从金融交易到文学创作

在研究 TradingAgents 项目时，我们发现金融交易中的多 Agent 辩论模式与文学评审惊人地相似——Bull（多头/乐观）对应读者视角（关注爽点代入感），Bear（空头/悲观）对应编辑视角（关注文学性结构）。将金融级的严谨注入创意领域，产生了独特的化学反应。

03 / 突破
多智能体"创作工坊"

LangGraph 有状态图框架的出现让一个设想成为可能：不再是单个 AI 的"单打独斗"，而是一个由 Supervisor 统一调度、Writer 创意写作、Editor 四维评分、Reader 读者视角、QualityPanel 辩论评审——各司其职的"AI 创作工坊"。

典型使用场景

SCENE 01
日更冲刺模式
作者设定当日写作目标 → 系统自动生成章节草稿 → 辩论式评审 → 质量达标后输出 → 同步到飞书文档。整个过程无需人工干预，作者只需在关键节点确认方向。日产能从 4000 字跃升至 20000-50000 字。
SCENE 02
长篇健康管理
创作到第 50 章时，系统自动触发伏笔回收检查 → 检测到第 12 章的伏笔尚未回收 → 提醒作者并自动生成回收方案。同时追踪角色弧线、节奏曲线，确保长篇结构不失控。
SCENE 03
批量生产管线
下一卷 30 个章节同时启动写作 → 并行分发到多个写作 Agent → 各章节独立创作+独立评审 → 汇聚后卷级整体评审。将一卷的创作周期从天级压缩到小时级，真正实现工业化生产。

架构创新亮点

⚡ Send Map-Reduce 并行分发
将一卷内所有章节并行分发到多个 Writing Crew 实例同步写作，完成后汇聚评审。Map 阶段并行生产，Reduce 阶段批量审校，大幅缩短卷级创作周期。
源于 TradingAgents Signal Processing
📋 NodeSpec 动态注册
质量检查节点按题材动态注册——悬疑题材自动注册伏笔回收检查，短篇题材跳过卷结构检查。无需修改图拓扑，通过配置驱动节点启停。
源于 TradingAgents Analyst Graph
🛡️ 熔断器保护机制
为每个 LLM Provider 独立配置熔断阈值（ARK/DeepSeek 最大5次失败/120s冷却），三态自动恢复（CLOSED→OPEN→HALF-OPEN），防止 API 雪崩效应。
源于 TradingAgents Circuit Breaker

评分与重试策略

Quality 分数操作上限说明
< 55完全重写3 次质量严重不达标，从头重写
55 – 79润色2 次基础过关但需较大改进
80 – 89润色1 次接近优秀，微调即可
≥ 90通过0 次直接通过，无需修改

双条件通过判定

判定流程
1. quality_score ≥ 题材阈值 AND composite_score ≥ 题材阈值 → 通过 ✅
2. quality ≥ 90 AND composite < 0.1 → 评分器故障，强制通过 🔧
3. quality ≥ 90 AND composite ≥ 0.5 → 优秀降级通过 ⭐
4. 重试次数 ≥ 3 → 强制通过 🔄
5. 其余情况 → 不通过，进入重试/润色 🔁

LG
LangGraph

Redis

MV
Milvus

N4

MO

FA
