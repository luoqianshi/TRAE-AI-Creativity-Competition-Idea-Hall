SafeLink

企业级跨平台双层加密私密聊天客户端

面向研发、财务、政企保密机房场景，基于 C# Avalonia 桌面端 + 自研 C# 服务端构建。 正常使用流程下聊天明文不落盘，采用 WebCrypto 前端 AES-GCM 加密、SQLCipher 加密 SQLite 索引库与独立二进制聊天正文文件两道独立爆破关卡， 客户端根密钥由 CPU、主板、硬盘、网卡多硬件复合哈希派生，服务端仅存储加密备份包、无对应解密密钥。

企业通用即时通讯工具在保密场景下存在结构性泄密风险：

  • highlight_off聊天明文写入本地 SQLite 或产生 WAL 临时日志碎片，硬盘直接可读。
  • highlight_off消息明文上传厂商云端，服务端拥有解密密钥，存在批量泄露与合规风险。
  • highlight_off单加密文件被破解即可读取全部对话，缺乏独立双层隔离关卡。
  • highlight_off无可靠硬件绑定与灾备恢复，换机、重装后历史记录难以找回。

layers

分层技术架构

web
① WebView 前端加密层

明文仅存内存 · 落盘即为密文

用户输入在 WebView 前端通过 WebCrypto AES-GCM 完成加密， 输出密文后销毁内存明文；收发以密文形式与 C# 服务端传输，服务端不解析消息内容。

desktop_windows
② C# Avalonia 客户端

跨平台桌面宿主 · 本地密文存储

基于 C# .NET 10 与 Avalonia Cross Platform 构建，自研 127.0.0.1 本地 HTTP 接口桥接 JS 与 C#。 本地保存全部聊天记录，兼容 Windows / macOS / Linux。

storage
③ 第一层：SQLCipher 加密 SQLite 索引库

仅存无敏感元数据 · 禁用 WAL 明文日志

客户端本地 SQLCipher AES-256 全文件加密，禁用 SQLite WAL 明文临时日志。 索引库不持久存储聊天原文，仅保留会话 ID、时间戳、消息哈希、正文偏移与次级密钥密文。

insert_drive_file
④ 第二层：独立二进制聊天正文文件

每条消息独立次级密钥 · 两道关卡物理隔离

每条聊天正文以随机命名二进制文件单独存放，使用独立次级 AES-GCM 密钥加密。 次级密钥经加密后写入索引库，两层密钥体系隔离，不存在单层破解连锁解密的路径。

vpn_key
⑤ 客户端根密钥 + C# 服务端备份

硬件复合哈希派生 · 服务端不解密

客户端采集 CPU、主板、硬盘、网卡序列号生成复合哈希，经 PBKDF2 高迭代加盐派生两套本地 AES 密钥（密钥 A / 密钥 B）。 自研 C# 服务端仅临时中转客户端 AES 消息密文，消息推送至接收客户端后立即清除密文缓存，不持久存储任何聊天内容；仅静态存放用户主动上传的加密密钥备份包。 服务端无对应解密密钥，无法解析备份包内密钥信息。

shield

核心安全机制

memory正常使用下明文不落盘

WebView 前端通过 WebCrypto AES-GCM 完成消息加密，明文仅在渲染会话弹窗时短时存在内存， 关闭会话页面立即清空；输出密文后销毁内存明文，正常使用流程下本地磁盘不会持久留存聊天明文。

layers双层独立加密关卡

第一层 SQLCipher AES-256 加密 SQLite 索引库仅留存无敏感元数据； 第二层 独立二进制正文文件使用次级 AES-GCM 密钥加密。 两层加密密钥体系完全隔离，不存在单层破解连锁解密的路径。

vpn_key硬件绑定根密钥

客户端采集 CPU、主板、硬盘、网卡多硬件序列号生成复合哈希，经 PBKDF2 高迭代加盐派生两套独立本地 AES 密钥。 加密密钥备份包上传自研 C# 服务端，服务端无对应解密密钥，无法解析备份包内密钥信息；异地拉取时强制校验客户端硬件哈希，不匹配拒绝下发。

screen_lock_portrait内存密钥防护

密钥分段拆分、分段加密存放，正常运行时内存中不保留完整连续密钥；客户端锁屏、退出、切换会话时自动擦除内存密钥缓存， 并锁定密钥内存区域降低写入 pagefile / hiberfil 分页与休眠文件的风险，定期轮转缩短完整密钥驻留时间窗口。

info 本双层加密架构可抵御离线硬盘窃取、暴力算力爆破、服务端沦陷批量泄密等常见风险；无法完全规避设备高权限进程劫持、冷启动物理硬件攻击、恶意木马篡改客户端等系统底层风险，项目配套内存分段加密、程序签名校验机制降低攻击成功率。
