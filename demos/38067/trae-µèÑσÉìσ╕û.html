1. 创意名称 + 创意介绍

创意名称

5xWord

想解决什么问题

程序员读英文文档、技术博客、报错信息时，往往大面积生词拦路——不只是个别单词，而是词形变形、不同时态、专业术语交织在一起。现有翻译插件只能帮你"读懂这一句"，却帮不了你"记住这些词"。下次遇到还是查，工作流反复被打断。

我们想做一个把"工作流里遇到的生词"自动变成"手机上能反复背的词库"的工具：工作时灭火，手机端防火——工作时专注解决问题，手机端循环复读把生词真正记住，下次工作流里少被打断。

为什么会想到做这个

我自己就是边做边学的开发者，读英文文档时反复查词、记了忘。身边很多人也这样——不是不想学英语，而是工作时注意力在解决问题上，不会分配给背单词。需要一个工具把"遇到生词"和"背生词"这两个动作分离到不同场景：工作场景只管提取，手机场景专注记忆。

大概是什么产品

一个跨端学习工具：Web 端粘贴任意能拷贝的英文文本（文档、代码注释、报错信息、博客），自动提取生词并翻译；手机 App（Flutter，覆盖 Android、iOS、鸿蒙）同步后按加入时间或遇到次数排序，支持点读发音和当前页循环复读，息屏也能听，靠听觉反复轰炸直到记住。

2. 目标用户及痛点

面向哪些用户
  • 英语薄弱的初中级程序员：一篇英文文档里大面积生词是常态，不是个别拦路虎
  • Vibe Coding 时代的开发者：大量使用 AI 编程工具，但读英文文档、报错、开源项目 README 仍需频繁查词
  • 想用碎片时间巩固技术英语的人：通勤、睡前、健身时想听单词复读
在什么场景下使用
工作场景（电脑端）
读英文文档/报错/博客时，把文本粘贴到 Web 端，系统自动提取生词并翻译。用户只管继续工作，不用分心去背。
碎片场景（手机端）
通勤、睡前、健身时打开 App，点耳机图标对当前页单词循环复读，息屏继续播放。一个词听 5 遍不够就听 50 遍、500 遍，直到记住。
下次工作流
之前背过的词不再拦路，查词频率下降，工作流更顺畅。
当前痛点
翻译插件只解决"读懂"，不解决"记住"
浏览器翻译插件（沉浸式翻译、DeepL 等）帮你过了眼前这关，但下次遇到同样的词还是不认识，工作流再次被打断。
翻译插件不会存在于任何软件当中
你在 IDE 里看报错、在终端看日志、在微信看技术分享、在 GitHub 看 Issue——这些场景下没有翻译插件可用，但都能拷贝文本。我们的工具可以接收任何能拷贝下来的文本，跨应用通用。
通用背单词 App 词库不贴合工作场景
扇贝、墨墨的词库是通用考试词库，不会按你实际遇到的顺序出现，也记不住单词是在哪篇文章里遇到的，背了用不上。
手动整理生词太费时
工作时遇到生词，查完意思就继续干活了，不会专门记到笔记本里。需要一个工具自动把工作流里遇到的词收集起来。

3. 价值与意义

效率提升

把「工作流遇到生词 → 自动收集 → 手机端循环复读 → 下次工作流少被打断」这条链路打通。用户工作时只管解决问题，不用分心整理生词；手机端按遇到次数排序，让复习时间花在最高频的词上。循环复读设计让一个词被听几十遍、上百遍，真正记进长期记忆，而不是查完就忘。

社会价值

降低程序员学习前沿技术的语言门槛。很多优质文档、论文、开源项目都是英文的，英语薄弱的开发者因为语言障碍不敢碰、碰了也效率低。帮助他们把工作流里遇到的生词自动沉淀成个人词库并反复记忆，相当于间接加速了技术普及和个人成长——让英语不再成为技术学习的拦路虎。
