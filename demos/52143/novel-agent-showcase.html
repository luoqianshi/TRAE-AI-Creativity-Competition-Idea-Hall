PAIN POINTS

创作者的困境

网文创作的路上，工具不该成为绊脚石。 我们调查了真实的创作痛点，发现问题比想象中更深刻。

01
🔒

封闭生态锁死

付费写作平台强制绑定自有模型，无法自定义 API。创作者被迫使用不擅长的模型，创作费用不透明，数据随时可能被锁死在平台内。

02
🔀

工具分散割裂

Word 写正文、Obsidian 管设定、Cursor 调 AI。数据来回迁移，世界观整理就要一周。工具越多，效率越低，注意力被严重分散。

03
📝

模板化严重

现有自动化 AI 小说工具产出模板化严重，质量依赖模型能力。缺乏对网文创作习惯的深度理解，更像是批量生成器而非创作助手。

CORE FEATURES

为创作而生的工作站

每一个功能都来自真实的创作需求。 不是在现有工具上加 AI，而是从零开始设计一个真正的创作工作站。

  • 智能导入引擎 RUST

    →

    UTF-8 / GBK / GB2312 三编码自动识别，单文件 500 章秒级导入。事务性回滚机制，确保数据安全无虞。旧手稿一键数字化。

  • 结构化作品管理 ORGANIZE

    →

    一键新建作品自动生成 12 个子目录——章节、角色、物品、世界观、地点、势力、功法、丹药…… 分门别类，条理清晰。

  • 自定义 AI 接入 FLEXIBLE

    →

    支持任何兼容 OpenAI 格式的 API。Claude、GPT、DeepSeek、通义千问……想用什么模型就用什么模型，Token 消耗完全透明。

  • 提示词仓库 PROMPT

    →

    内置润色、续写、对话、设定生成等多种提示词模板。支持自定义与分享，让好的提示词成为可复用的创作资产。

  • 章节批注学习 LEARN

    →

    在阅读优秀作品时逐段批注，拆解行文结构、节奏把控、人物塑造。积累属于自己的创作方法论，新手也能快速上手。

ORIGIN STORY

一个新手作者的自白

去年我在写一部仙侠小说时，遇到了严重的效率瓶颈。 我需要在 Word 里写正文、在 Obsidian 里管理人物设定、 在 Cursor 里调用 AI 润色，数据来回迁移， 光是整理世界观设定就花了一周时间。

更痛苦的是，当我想把旧的 TXT 手稿导入电脑时， 发现没有任何工具能智能按章节拆分。 那一刻我意识到——网文创作者需要的， 不是又一个 AI 聊天框，而是一个专为创作设计的集成工具。

于是我开始动手搭建 Novel Agent 的原型。 用 Rust 写后端，保证导入速度和数据安全； 用 Vue 3 做前端，打造流畅的编辑体验； 用 Tauri 打包成桌面应用，轻量且跨平台。 每一行代码，都来自真实的创作痛点。
