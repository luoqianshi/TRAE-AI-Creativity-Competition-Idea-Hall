01 我们发现了什么痛点？

年轻人在"精神内耗"时代，需要更酷、更高效的祈福方式

🔍

信息太分散

寺庙信息散落在小红书、公众号、攻略帖中，没有一站式地图。年轻人想知道"附近哪个庙求事业最灵"，要查 5 个 App。

🎨

体验太陈旧

现有祈福类 App/网站设计停留在 2010 年，暗红暗绿的传统配色对年轻人毫无吸引力，没有社交分享价值。

🎲

祈福没互动

去庙里只是拜拜、上上香，缺乏数字化互动。年轻人想要"抽签"、"抽盲盒"的游戏化体验，以及可分享的海报。

📱

移动端体验差

大部分寺庙地图都是 PC 端为主，手机端卡顿、手势冲突、加载慢。用户在手机上拖拽地图时页面还会跟着滚动。

02 产品核心功能

四大模块，从"找庙"到"祈福"到"分享"完整闭环

[ 全国寺庙地图截图 ]

全国寺庙地图 核心

100+ 寺庙数据覆盖北京、上海、杭州、成都、西安等热门城市。每座寺庙标注经纬度，点击灯笼图标即可查看详情。

  • 高德地图 SDK 暗黑主题底图
  • 自定义灯笼图标，赛博发光呼吸动画
  • 视野内分批渲染，避免大数据量卡顿
[ 分类筛选界面截图 ]

心愿分类筛选 筛选

按 9 大心愿领域一键筛选：综合祈福、求财、求学、求姻缘、求平安、求健康、求事业、化太岁、求子。

  • 每个分类配有专属 SVG 图标（莲花、元宝、葫芦等）
  • 赛博霓虹发光动画，选中高亮
  • 城市详情页复用公共组件，统一体验
[ 好运签海报截图 ]

好运签盲盒 玩法

每座寺庙根据其"灵验领域"，匹配专属祝语文案。用户点击"摇签"，随机生成好运签，可生成可分享的海报。

  • 按寺庙分类匹配祝语词库（9 类 × 4 条）
  • html2canvas 生成符箓风格海报
  • 海报包含二维码，扫码可直达寺庙详情
[ 移动端适配截图 ]

移动端深度适配 体验

从 CSS 手势优化到 Marker 触控事件，全方位提升手机端体验。大屏地图 + 底部抽屉，符合单手操作习惯。

  • 全局 CSS 阻止浏览器默认回弹和双击缩放
  • Marker 同时绑定 click + touchend，一点即开
  • 开启 AMap 惯性拖拽 + 双指缩放优化
  • 手机端视野剔除，只渲染屏幕内灯笼

05 用户场景

真实用户会在什么时候打开这个产品？

01

周末祈福出行

"这周末想去附近寺庙逛逛，看看哪个庙求事业最灵？"打开地图 → 筛选"求财" → 看到最近的雍和宫 → 查看详情卡片 → 出发。

02

考试/求职前的仪式感

"下周要考研面试了，想给自己一点心理暗示。"找到寺庙 → 点击摇签 → 生成好运签海报 → 保存到相册 → 发朋友圈。

03

陌生城市旅游

"去杭州旅游，想顺便拜拜。"搜索城市 → 看到灵隐寺、法喜寺 → 看分类标签（求姻缘/求学业）→ 决定去哪座。

04

情绪焦虑时的"电子祈福"

"工作压力大，想找个精神出口。"不用出门，打开 App 随机抽个好运签，看赛博禅意动画，获得片刻宁静。

06 价值与意义

为什么这件事值得做？

🌏

文化传承数字化

用赛博朋克美学重构东方祈福文化，让寺庙文化对 Z 世代更有吸引力。不是消灭传统，而是给传统一个"赛博皮肤"。

⚡

效率工具属性

整合分散的寺庙信息，按心愿分类筛选，节省用户 80% 的决策时间。从"查 5 个 App"到"1 秒找到目标寺庙"。

📤

社交传播价值

好运签海报自带二维码，用户分享 = 自然裂变。每张海报都是产品广告，传播成本趋近于零。

📱

移动端优先体验

针对手机端深度优化：手势、触控、加载、动画。让用户在地铁上、床上、咖啡厅里都能顺滑使用。
