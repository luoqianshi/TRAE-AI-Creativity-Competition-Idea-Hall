求职刷题的四大困境

01 // PROBLEM

题库体量庞大，无从下手

LeetCode 3000+、牛客万题、各公司题库分散，求职者不知道优先刷哪些，时间有限却陷入"选择困难"。

02 // PROBLEM

岗位差异被忽视

同一家公司，后端、前端、算法岗考察重点截然不同。统一刷题导致大量精力浪费在不考的知识点上。

03 // PROBLEM

JD与考题关联难判断

职位描述写得天花乱坠，但实际面试考什么？人工比对JD关键词和面试题耗时耗力，且准确率低下。

04 // PROBLEM

缺少真题映射数据

面经散落在各平台，无人系统整理"某岗位→考过什么题→考频如何"的映射关系，信息不对称严重。

Technology Stack

技术架构与核心亮点

多层AI技术栈，构建岗位-题目的精准映射

01 // NLP

JD语义解析与实体识别

采用BERT+BiLSTM-CRF模型对职位描述进行命名实体识别，精准提取技术栈（Java、Redis、Kafka）、技能要求（分布式、高并发）、业务领域（电商、金融）等关键实体。

BERT NER BiLSTM
02 // GRAPH

岗位-知识点知识图谱

构建包含5000+岗位节点、20000+知识点节点、50000+关系边的知识图谱，通过图神经网络（GNN）推理岗位间的隐性知识关联。

Neo4j GNN GraphSAGE
03 // MATCHING

语义相似度匹配引擎

基于Sentence-BERT将JD和题目嵌入同一向量空间，结合TF-IDF加权与BM25算法，计算岗位需求与题目考点之间的多维相似度得分。

Sentence-BERT BM25 Vector Search
04 // RECOMMEND

协同过滤与矩阵分解

利用历史用户刷题数据，通过SVD矩阵分解和ItemCF算法，发现"刷过A题的用户也刷了B题"的隐性关联，优化推荐列表的多样性。

SVD ItemCF Matrix Factorization
05 // DATA

面经数据挖掘与关联

爬取并结构化处理10万+条面经文本，通过主题模型（LDA）提取面试考察主题，建立"公司-岗位-时间-题目"四维关联数据库。

LDA Web Mining ETL
06 // FEEDBACK

强化学习持续优化

系统记录用户的刷题反馈（跳过、收藏、正确/错误），通过Bandit算法和DQN模型持续优化推荐策略，实现"越用越懂你"。

Bandit DQN RL
