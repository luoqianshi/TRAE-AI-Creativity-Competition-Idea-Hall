// Problem

开发者面临的痛点

AI Agent 项目往往只展示顺利样例，缺少系统化的可靠性测试

🚨

事实性错误

Agent 在知识库不足时编造答案，无法准确判断信息可信度

🔏

边界拒答缺失

面对超出能力范围的问题时，无法正确拒绝或引导用户

⚙️

工具调用失败

参数错误、API 异常时缺乏优雅的错误处理和降级策略

💬

上下文污染

多轮对话中历史信息干扰当前判断，导致回答偏离主题

🌌

幻觉生成

生成看似合理但实际不存在的内容，误导用户决策

⚠️

指令冲突

系统提示词与用户意图矛盾时，行为不可预测

// Workflow

核心评测流程

从配置输入到报告导出，形成完整的质量保障闭环

01

输入 Agent 配置

上传系统提示词、知识库片段、工具说明或对话记录

// agent_config.json { "system_prompt": "你是一位课程助手...", "knowledge_base": ["doc1.md", "doc2.md"], "tools": ["search", "calculate"] }
02

自动生成测试集

基于配置内容智能生成覆盖各维度的测试用例

// 自动生成 50+ 测试用例 generate_test_cases(config) for dim in [facts, boundary, tools, ...]: cases = create_cases(dim, config) test_suite.add(cases) // 覆盖 6 大评测维度
03

运行自动化评测

并行执行测试用例，收集响应结果和元数据

// 评测执行中... run_evaluation(agent, test_suite) results = [] for case in test_suite: response = agent.invoke(case.input) score = evaluate(response, case.expected) results.append(score) // 进度: 36/50 (72%)
04

失败归因分析

定位失败根因，分类到具体维度并给出证据

// 失败归因报告 FAIL: 事实性错误 问题: 回答与知识库矛盾 证据: "Python 3.12 发布于 2024" 实际: "Python 3.12 发布于 2023-10" 来源: knowledge_base/doc1.md
05

生成修复建议

基于失败模式输出可操作的提示词或配置修改建议

// 修复建议 SUGGESTION: 增强事实性约束 在 system_prompt 中添加: "如果你不确定答案，请明确 说明'我不确定'，不要编造。" 更新知识库: 补充 Python 版本信息
06

复测对比验证

应用修复后重新运行测试，量化改进效果

// 复测结果对比 BEFORE: 45% 通过率 AFTER: 87% 通过率 提升: +42% (事实性 +35%, 边界 +50%) 状态: ✅ 验证通过
07

导出评测报告

生成包含测试详情、失败证据和修复记录的专业报告

// 报告导出 report.generate({ format: "PDF", sections: ["summary", "details", "fixes", "comparison"], include_evidence: true }) // agentguard_report_2024.pdf
