云思

让云端 AI Agent 安全、可控地操控你的本地电脑——Shell 执行、文件读写、进程管理，一键桥接。

1创意与介绍

想解决什么问题

云端 AI Agent 越来越强大，却无法直接访问用户本地文件、运行本地命令或调用本地工具——远程协作与自动化因此断裂。 现有方案要么需要暴露本地端口（NAT 不友好、安全风险高），要么缺乏对高风险操作的审批机制，用户不敢让 AI「动手」。

为什么会想到做这个

灵感来自「Agent-to-Computer」开源项目：AI 不应只存在于浏览器对话框里，而应像一位远程助手，能帮你整理桌面文件、跑脚本、查进程——但每一步都必须在你授权之下进行。 结合 MCP 协议与 gRPC 双向流，我们设计了 Brain（云端）+ Body（本地）的轻量桥梁，让 Hermes 等 AI Agent 无缝调用本地能力。

大概是什么产品

🖥️ 分布式系统：云端 Brain 服务 + 本地 Body 守护进程 + Web 管理面板
Brain · 云端

gRPC Server、MCP Server、设备注册与工具桥接，供 AI Agent 统一调用

Body · 本地

主动 outbound 连接云端，执行 Shell / 文件 / 进程等 8 种工具能力

安全层

风险分级 + Web 面板审批，yolo_mode 可选；支持 frp 穿透部署

2目标用户及痛点

👩‍💻

面向哪些用户

  • 开发者与运维工程师
  • 需要 AI 辅助本地工作的知识工作者
  • 部署云端 AI Agent（如 Hermes）的技术团队
  • 在家/公司多台设备间需要远程自动化的用户
📍

在什么场景下使用

  • 对 AI 说「帮我看看桌面有什么文件」并自动列出目录
  • 远程让 AI 执行脚本、修改配置、排查进程
  • 出差时用云端 Agent 操作家里/工位上的 Windows/Mac
  • 通过 Web 面板审批每一次高风险 Shell 或写文件操作
😤

当前痛点

  • AI 只能「给建议」，无法真正在本地执行
  • TeamViewer / SSH 需人工逐步操作，无法与 AI 对话闭环
  • 开放本地端口或 RDP 暴露攻击面，家庭网络 NAT 也难以直连
  • 让 AI 跑命令担心误删文件，缺少分级审批与审计

3价值与意义

效率提升

从「口述步骤」到「一句话完成」

用户无需在 AI 聊天窗口与本地终端之间来回切换。AI 通过 MCP 直接调用 8 种本地工具——读文件、搜目录、跑 Shell、管进程—— 将「查问题 → 写脚本 → 执行 → 看结果」压缩为一次自然语言交互，显著缩短排查与自动化流程的时间。

商业价值

可嵌入的「本地执行层」基础设施

云思采用标准 MCP 接口与工具声明制，任何兼容 MCP 的 AI Agent 均可接入，具备 ToB 集成潜力： 企业可将云端智能助手与员工本地环境安全打通，按设备注册、会话管理与审批策略提供差异化 SaaS 能力， 同时 Body 主动连接 + frp 穿透降低部署与运维成本。

核心能力一览

  • 8 种本地工具：shell、read/write_file、list_dir、file_info、search_files、list/kill_process
  • 安全审批：高/中/低风险分级，Web 面板实时允许或拒绝
  • NAT 友好：Body 主动 outbound 连接，本地无需暴露端口
  • 协议开放：gRPC + MCP，与 Hermes Agent 等生态即插即用
