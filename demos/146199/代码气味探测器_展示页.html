Pain Points

团队代码质量的三大痛

⏰

Code Review耗时低效

每份PR需要人工逐行审查，一个中等规模的PR平均耗时30-60分钟。审查者需要同时关注业务逻辑和代码风格，精力分散导致很多坏味道被遗漏。

🤖

代码债务无人感知

超长函数、魔法数字、重复代码等问题每天都在产生，但开发者和管理者都"看不到"这些代码坏味道的累积，直到不得不花数周做技术重构。

👤

质量全凭"感觉"

管理者想知道团队代码质量如何，只能凭"感觉"和"印象"判断，缺乏量化数据。无法识别哪位成员需要指导，哪个模块是技术债务重灾区。

Solution

四步构建代码质量防火墙

01

静态扫描

AST语法树分析 + AI语义理解，自动识别12类代码坏味道，检测准确率92%+

02

实时诊断

VS Code插件红橙黄三色标记问题，鼠标悬停查看具体描述和修复建议

03

质量门禁

CI/CD流水线自动拦截低质量代码，未达阈值的PR无法合入主分支

04

数据看板

团队代码质量雷达图、个人排行榜、趋势分析，让质量成为"可看见"的KPI

Core Features

六大核心功能

🔌

12类代码坏味道检测

覆盖超长函数、魔法数字、重复代码、命名不规范、空引用等12类常见问题，基于AST语法树+规则引擎，检测准确率92%+。

💻

VS Code实时标记

插件端红橙黄三色波浪线标记问题代码，鼠标悬停即时显示问题描述、严重等级和一键修复建议，开发时边写边改。

⚙

CI/CD质量门禁

集成到GitLab/Jenkins流水线，提交时自动扫描。代码质量未达标自动阻断合并，确保"坏代码"不流入生产环境。

📈

代码质量雷达图

六维质量雷达图（可读性/可维护性/复杂度/耦合度/测试覆盖/文档完整），一眼看清代码"哪里不够好"。

🏆

团队排行榜

量化每位开发者的代码质量得分，形成排行榜和趋势曲线。发现需要指导的新人，识别质量退步的模块。

🔄

一键修复建议

不只是发现问题，更能给出具体的重构建议。VS Code一键应用修复，支持变量重命名、提取函数、去除魔法数字等。

Technical Architecture

技术架构与亮点

▶ 前端层（IDE + Web）

  • VS Code LSP协议插件，实时诊断与一键修复
  • React Web管理后台，ECharts可视化
  • WebSocket 实时推送扫描进度和结果

▶ 后端层（微服务）

  • Node.js 核心扫描引擎，AST解析与规则匹配
  • Go 高并发代码存储与质量计算服务
  • Redis 扫描缓存 + 实时状态

▶ AI层（语义分析）

  • CodeBERT 语义理解模型，识别命名质量
  • TreeSitter 多语言AST解析器
  • BERT 代码注释完整性检测

▶ 数据层（存储 + 分析）

  • PostgreSQL 代码快照 + 质量记录存储
  • ES 历史扫描日志全文检索
  • Git 对接GitLab/GitHub Webhook
