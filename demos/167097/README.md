# 休三招聘 Web 原型交接说明

## 使用方式

- 打开 `index.html` 即可查看可点击的桌面 Web 原型。
- 打开 `junior-pass.html` 可回看原型阶段确认过的页面分组、关键路径和占位假设。
- 本目录的 HTML 仅用于产品和视觉验证，**不是生产前端源码**。生产实现必须使用 React + TypeScript + Vite。

## 原型页面清单

- 访客与求职者端：P01 欢迎页、P02 登录、P03 数字人顾问首页、P05 职位搜索、P06 职位详情、P07 企业档案、P08 点评与福利、P09 社区、P10 求职中心、P11 简历偏好、P12 写点评、P13 举报、P14 设置。
- 企业端：P04 企业入驻、P15 认证申请、P16 工作台、P17 企业资料、P18 职位管理、P19 候选人、P20 口碑回应与申诉。
- 运营端：P21 审核总览、P22 企业认证审核、P23 职位审核、P24 内容与举报审核、P25 数据与审计。

## 关键组件

- 求职者顶栏、企业/运营工作台侧栏。
- 可信信号场：数字人资源未到位时的顾问首页占位；显示规则化筛选条件，不绘制人物。
- 职位卡、认证状态、作息与福利来源标签、企业可信档案、点评与企业回应。
- 简历、点评、举报、认证的结构化确认表单。
- 审核队列、审核决定面板、审计时间线。

## 已演示的关键交互

1. 首页顾问输入或建议问题 → 职位搜索结果，并显示可调整的条件解释。
2. 职位详情 → 投递确认弹窗 → 求职中心同步投递状态。
3. 员工点评 → 脱敏公开预览 → 提交确认。
4. 企业端的认证、职位、候选人和回应工作台切换。
5. 运营端的认证复核、职位一致性校验、内容审核与审计记录切换。

## 交互状态

- 搜索/顾问：建议问题、条件解释、刷新提示；生产版需补接口 Loading、请求错误、无结果状态。
- 表单：草稿保存、字段说明、提交确认；生产版需补完整字段校验、上传进度、幂等提交和服务端错误提示。
- 投递：确认后显示“已投递”并写入个人中心；生产版需调用投递接口。
- 审核：演示通过、补件、退回、复核等动作；生产版必须校验权限、审计操作、状态冲突和二次确认。
- 动效：信号场呼吸效果与按钮悬停；`prefers-reduced-motion` 下关闭循环和位移动画。

## Mock 数据结构

```text
企业：id、名称、行业、规模、地点、认证状态、作息制度、福利来源
职位：id、企业 id、名称、薪资、地点、经验、作息承诺、福利标签、状态
点评：id、企业 id、匿名昵称、就业状态、验证等级、维度评分、正文、审核状态、企业回应
投递：id、职位 id、用户 id、简历版本、投递状态、时间
认证申请：id、企业 id、作息类型、具体制度、例外岗位、材料引用、审核状态
举报/申诉：id、对象类型、对象 id、原因、说明、受限证据引用、状态、可见范围
审计记录：id、主体、动作、操作者、状态前后值、理由、案件、时间
```

## 需要真实 API 的位置

- Mock 手机号验证码、用户/角色会话和权限。
- 职位、企业、认证、福利、点评、社区、投递、通知、举报、申诉与审计的读写接口。
- 认证材料和举报证据的私有对象存储、签名访问、保存期限和删除策略。
- 企业、职位、内容和案件审核工作流，以及服务端幂等键、权限校验和审计写入。

## 生产实现要求

- 使用 React + TypeScript + Vite；原型单文件状态不应直接迁移到生产项目。
- 保留“聊天只能检索/筛选/比较/草稿，写操作必须用户确认”的边界。
- 认证、审核、举报、申诉和投递必须服务端校验权限、状态机和幂等性。
- 不向企业公开举报人身份、受限证据、匿名员工身份或平台内部风控规则。
- 数字人视觉资产、第三方动画与 LLM 均不在 V1 原型范围；接入前需确认授权、供应商、密钥、数据脱敏及成本。
