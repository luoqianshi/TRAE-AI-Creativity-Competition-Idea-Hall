AI 情感陪伴与叙事创作平台
#生活娱乐 #AI陪伴 #叙事创作
!创意介绍

想解决的问题：当前 AI 角色对话产品普遍存在人设跑偏、API 成本高、服务不稳定三大痛点——用户精心设定的角色聊几轮就"失忆"，付费 API 门槛劝退普通用户，服务挂了就彻底无法使用。

灵感来源：作为一个喜欢 AI 角色互动的用户，我发现每次和 AI 角色聊天，角色总会逐渐偏离设定，变成千篇一律的"AI助手"。我想要一个能始终记住自己是谁、有温度的 AI 伙伴，于是决定自己动手做。

产品形态：一个基于 Web 的 AI 情感陪伴与小说创作平台，包含角色对话、情感倾诉、RAG 小说工坊三大核心模块。

👤目标用户及痛点

核心用户：18–30 岁的 AI 角色互动爱好者、网文/轻小说创作者、需要情感倾诉的年轻人。

使用场景：深夜独处时想找人聊天、创作小说时需要 AI 辅助生成和保持设定一致、压力大时需要一个不会评判的倾听者。

当前痛点：没有本产品时，用户只能选择通用 AI 助手（人设无法锁定）、付费角色平台（月费高、角色不可定制）、或纯离线写作工具（无 AI 辅助）。三者割裂，无法在一个平台上同时满足"陪伴+创作"需求。

★价值与意义

效率提升：自研客户端 RAG 系统，纯前端实现 TF-IDF 向量化 + 余弦相似度检索，无需向量数据库即可完成"设定注入→大纲→逐章"三步创作法。实际验证：剧本创作周期从 7 天缩短至 2 天，效率提升 71%。

社会价值：三层降级架构（用户 Key → 服务器代理 → 离线回复）确保 99.9% 可用性，让经济条件有限的用户也能零门槛体验 AI 陪伴；情感倾诉模块为年轻人提供一个安全、无评判的情绪出口。

◆核心功能

三层降级架构

用户自带 Key 直连 → 服务器双 Key 池化代理 → 离线关键词回复，确保任何情况下都能响应

人设强约束机制

CORE_CHARACTER_RULE 系统提示注入，用户设定不可覆盖核心性格，角色永不跑偏

客户端 RAG 小说工坊

纯前端 TF-IDF + 余弦相似度，三步生成法从设定到成稿，无需向量数据库

SSE 流式 + 请求取消

实时逐字渲染打字机效果，AbortController 随时取消，体验丝滑

双 AI 提供商

智谱 GLM-4-Flash + DeepSeek Chat 双引擎，用户自由选择

全链路安全

IP 限流、来源白名单、时间戳防重放、Key 格式验证，多层防护

⚙技术栈

全栈使用 Trae Solo（AI 辅助开发工具）从零搭建，前后端分离架构：

Node.js + Express JavaScript SSE 流式通信 TF-IDF + 余弦相似度 Docker 容器化 Nginx 反向代理 腾讯云部署 智谱 GLM API DeepSeek API AbortController localStorage 记忆 Prompt Engineering
