一

报名帖标准内容 直接复制粘贴到大赛报名

1. 创意名称 + 创意介绍

创意名称：古籍翻译官

想解决什么问题： 很多人对古籍感兴趣，但文言文看不懂、生僻字不会读、典故不知道出处，翻半天注释还是一头雾水。去搜翻译又常常只有干巴巴的白话，看不到背后的历史故事和文化内涵，导致很多人买了古籍也束之高阁。

为什么会想到做这个： 平时喜欢逛博物馆、看文物纪录片，发现很多老祖宗的智慧特别有意思，但一翻开原著就被文言文劝退了。要是能有个"随身翻译"，像朋友讲故事一样帮我看懂古籍就好了。

大概是什么产品： 一个古籍智能解读网站（手机/电脑都能用）

2. 目标用户及痛点

面向哪些用户： 学生党（初高中语文学习文言文）、历史文化爱好者、喜欢逛博物馆的年轻人、想读经典但怕看不懂的上班族

在什么场景下使用：

  • 做语文作业遇到不会的文言文，拍一下题目直接看解读
  • 逛博物馆看到文物上的铭文/诗句，拍个照查出处和含义
  • 睡前想读几页《论语》《史记》，遇到难懂的句子直接查

当前痛点： 查文言文翻译只能搜百度，东拼西凑不完整；手机上查字典翻半天，查到了也不知道用在这句里对不对；想看深度解读还要另外买参考书，费钱又麻烦。

3. 价值与意义

社会价值： 降低古籍阅读门槛，让更多普通人能轻松接触传统文化。以前只有文史专业的人才能啃的经典，现在学生、上班族、老年人都能看懂，让老祖宗的智慧真正"活"起来，而不是躺在图书馆里落灰。

效率提升： 学生做文言文作业从"翻 3 本书查 5 个 App"变成"拍照 3 秒搞定"，省下的时间可以用来理解内容本身，而不是纠结字词意思。

三

技术实现方案 两套方案可任选

方案 A（推荐）基于现有技术栈 · 最省力

层级 技术选择 说明
前端 PbootCMS 模板改造 你已经熟悉的 CMS，直接改一个模板出来，省得从头写
核心功能 大模型 API（通义千问 / 文心一言 / 其他） 调用 AI 接口做翻译、解读、生成卡片，所有智能功能都靠它
后端逻辑 PbootCMS 自带 PHP + 简单接口封装 不用单独搭后端，CMS 本身就能处理表单提交和 API 调用
数据存储 PbootCMS 自带数据库 存名句卡片、古籍分类、用户搜索历史
部署 宝塔面板 你已经很熟了，直接放服务器上跑
💡 优点：90% 的技术你都会，不用学新东西，最快 1 周能出 MVP

方案 B 现代化方案 · 适合想多学点

层级 技术选择 说明
前端 React / Vue 3 + Vite 现代前端框架，做出来界面更漂亮，交互更流畅
核心功能 大模型 API（同上） 所有智能功能靠 AI 接口
后端 Node.js 轻量服务（可选） 封装一下 API KEY，防止前端直接暴露
部署 宝塔面板 + Nginx 前端静态文件放 Nginx，后端跑 Node 服务
数据存储 SQLite / MySQL 轻量项目用 SQLite 就行，不用单独装数据库
💡 优点：技术更前沿，简历加分；界面可以做得更精致

模型 优点 费用 推荐指数

文心一言 文言功底好，百度AI 有免费额度 ⭐⭐⭐ 备选

核心 Prompt 设计思路

你是一位资深的国学大师，精通文言文和中国历史文化。
请对用户输入的文言文进行以下处理：

1. 【白话文翻译】逐句翻译成通顺的现代汉语
2. 【生僻字注音】标出所有生僻字的拼音和声调
3. 【典故出处】说明这段话出自哪本书、哪个章节，作者是谁
4. 【历史背景】用讲故事的方式，讲讲这段话当时发生了什么事，为什么这么说
5. 【智慧启示】这段话对我们现代人有什么启发，能用到什么地方

要求：语言通俗有趣，不要太学术化，就像和朋友聊天一样。
