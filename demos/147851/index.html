核心功能

覆盖设备故障排查全链路的七大功能模块，从远程连接到报告输出，一站式解决运维需求

SSH 远程连接

基于 SSH.NET 实现安全的远程设备连接，支持连接池复用、超时重试、命令白名单防注入，确保远程操作安全可靠。

应用场景：TB3基站远程状态采集

知识库管理

统一管理故障码、设备手册、告警码映射三大知识体系，支持 CRUD 操作与去重验证，为智能诊断提供数据基础。

应用场景：故障码与告警码关联查询

智能故障诊断

核心功能模块，实现"状态采集→故障码匹配→原因分析→方案生成"全链路智能诊断，采用 Fastenshtein 模糊匹配算法（90%相似度阈值）。

应用场景：基站故障自动定位与方案推荐

告警管理

集中管理设备告警信息，支持按状态（待处理/已确认/已关闭）和级别（紧急/重要/次要）筛选，提供告警确认流程。

应用场景：实时告警监控与处理跟踪

设备管理

管理 TB3 基站设备信息，支持设备 CRUD、搜索筛选、按设备类型分类管理，记录 IP 地址、站点、频段等关键参数。

应用场景：基站设备台账与参数维护

报告生成

自动生成诊断报告，包含设备信息、故障详情、原因分析、处理方案，支持文本格式导出与历史报告查询。

应用场景：诊断结果归档与运维交接

安全鉴权

SHA-256 密码哈希校验、AES-256 加密存储、SSH 主机密钥验证、命令白名单防注入，四层安全防护体系。

应用场景：系统访问控制与数据保护

智能诊断全链路流程

01

状态采集

SSH 执行 ZZZKHA / ZZZKMU / status 命令，采集设备实时运行状态

02

故障码匹配

精确匹配 → Fastenshtein 模糊匹配（≥90%）→ 关联匹配，三级策略

03

原因分析

基于关键词概率分析（TTRX/风扇/驻波/时钟/供电/以太网）定位根因

04

方案生成

根据故障码关联知识库处理方案，生成可执行的维修建议

05

报告输出

自动生成诊断报告并支持文本导出，完成全链路闭环

模糊匹配算法

★★★★★

采用 Fastenshtein 编辑距离算法实现故障码模糊匹配，设定 90% 相似度阈值。设计"精确匹配 → 模糊匹配 → 关联匹配"三级策略，有效解决设备输出格式差异导致的匹配失败问题。

// 三级匹配策略 if (exactMatch) return result; if (levenshtein.Similarity >= 0.90) return fuzzyResult; return relatedMatch;

SSH 连接池与安全

★★★★☆

基于 SSH.NET 实现连接池复用，减少重复握手开销。集成命令白名单（CommandWhitelistService）防止命令注入，主机密钥验证（SshHostKeyVerifier）防止中间人攻击，三层安全防护。

// 命令白名单验证 if (!_whitelist.IsValid(command)) throw new SecurityException("命令不在白名单中");

AES-256 加密体系

★★★★☆

配置化 AES-256 密钥管理，PBKDF2 密码哈希（盐值+迭代），SecureStorage 加密文件存储。从配置文件读取密钥，未配置时拒绝启动，杜绝硬编码风险。

// PBKDF2 密码哈希 var hash = PBKDF2(password, salt, iterations); return $"{iterations}.{salt}.{hash}";

MVVM + DI 架构

★★★★☆

CommunityToolkit.Mvvm 实现 MVVM 模式，ViewModelFactory 工厂模式解决子 ViewModel 依赖注入。Repository 通用接口 + 依赖注入容器，实现层间解耦与可测试性。

// ViewModelFactory 创建子ViewModel public T Create<T>() where T : BaseViewModel => _services.GetRequiredService<T>();

使用说明

四步完成设备故障诊断，从登录到报告输出，全流程直观便捷

1

登录系统

启动应用后进入登录界面，输入用户名和密码。系统使用 SHA-256 + PBKDF2 算法验证密码，验证通过后进入主界面。未配置密码时系统拒绝访问，确保安全性。

[系统] 交通轨道设备故障排查系统
用户名: admin
密码: ********
[登录] 验证通过，欢迎 admin
2

选择设备

在"设备管理"页面查看设备列表，支持按名称搜索、按类型筛选。选中目标设备后，系统显示设备详情（IP地址、站点、频段、设备类型等关键参数）。

[设备列表] 共 5 台设备
TB3-001 | 站点A | 192.168.1.10
TB3-002 | 站点B | 192.168.1.11
→ TB3-003 | 站点C | 192.168.1.12 [已选中]
3

执行诊断

切换到"故障诊断"页面，输入 SSH 连接参数后点击"开始诊断"。系统自动执行状态采集、故障码匹配、原因分析、方案生成四步流程，实时显示诊断进度。

[诊断] 正在连接 TB3-003 (192.168.1.12)...
[采集] 执行 ZZZKHA 命令... ✓
[匹配] 故障码 TTRX_001 匹配度 95%
[分析] 原因: 发射机驻波比异常
[方案] 检查天线接口/馈线连接
4

查看与导出报告

诊断完成后自动生成诊断报告，在"报告管理"页面查看报告内容。支持选择输出目录并导出为文本文件，便于归档与运维交接。

常见问题

系统当前针对城市轨道交通 TB3 基站设备进行深度适配，支持通过 SSH 协议连接的兼容设备。知识库内置 TB3 系列故障码、告警码映射与处理手册，同时支持自定义扩展其他设备类型的知识库数据。
系统采用三级匹配策略：第一级精确匹配（告警码映射表完全匹配），第二级模糊匹配（Fastenshtein 编辑距离算法，相似度阈值 ≥90%），第三级关联匹配（基于关键词关联分析）。三级策略有效应对设备输出格式差异，综合匹配准确率达 95% 以上。
四层安全防护：① 命令白名单（CommandWhitelistService）仅允许预定义命令执行，防止命令注入；② SSH 主机密钥验证（SshHostKeyVerifier）基于 known_hosts 文件防止中间人攻击；③ AES-256 加密存储敏感配置；④ SHA-256 + PBKDF2 密码哈希鉴权。
不需要互联网连接。系统仅需局域网内 SSH 连接到目标设备，所有数据存储在本地 SQLite 数据库中。知识库数据通过种子数据导入器初始化，诊断报告导出为本地文本文件。完全离线运行，适合轨道交通机房的封闭网络环境。
诊断报告包含：设备基本信息（名称、IP、站点、类型）、诊断时间与状态、采集的设备状态数据、匹配的故障码及匹配度、原因分析结论、推荐处理方案。报告支持文本格式（.txt）导出，便于归档存查与运维团队交接。

开发背景与展望

直面轨道交通运维痛点，以智能化手段重塑故障排查流程

⚠ 传统痛点

  • 人工排查耗时漫长，单次故障平均 2-4 小时
  • 高度依赖工程师个人经验，知识难以传承
  • 无标准化诊断流程，排查步骤因人而异
  • 故障记录分散，缺乏系统化归档与追溯
  • 告警响应滞后，无法实时监控设备状态

✓ 智能方案

  • 自动化诊断流程，单次故障缩短至 10-15 分钟
  • 知识库固化专家经验，新员工也能高效排查
  • 标准化五步诊断流程，结果可复现可追溯
  • 诊断报告自动归档，历史记录随时查询
  • 告警实时管理，故障发现到响应分钟级
