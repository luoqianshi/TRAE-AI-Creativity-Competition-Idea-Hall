产品架构：地图 MCP + 算法 Skills

GPT 负责理解与调度，地图和算法负责计算，最终输出可解释的适老出行建议

核心 PM 判断：老人高温出行不是“找个纳凉点”这么简单，而是出门前、路途中、到达后都要管理风险。地图厂商已经做好“怎么导航”，但没有为老年人做好“今天适不适合出门、几点出门更安全、哪段路少晒、哪里能坐下、遇到不适谁能帮忙”。所以产品不重做地图，而是在地图 MCP 之上叠加热暴露图、适老策略和社区公益反馈。

1. GPT 理解从自然语言提取老人类型、时段、目的、身体限制和家属关注。
2. 地图 MCP高德/百度返回路网、候选路线、POI、天气和导航入口。
3. 热暴露重加权把太阳暴露、WBGT、HVI、遮阴、休息、饮水、药店与求助可达性写入边权。
4. Duan-SSSP 引擎在稀疏有向增强图上批量求源点到医院、避暑安全点、药店的最低风险路径。
5. GPT 解释把复杂结果翻译成老人提醒、家属提醒和社区补点建议。

研究融合

从论文方法转成可视化

  • 遮阴路径：借鉴 CoolWalks / Walking Smart 的 shaded routing 思路。
  • 行为模型：把“人在阴影中愿意多走一点”转成距离折扣。
  • 风险模型：使用 hazard × exposure × vulnerability 的 HVI 框架。

别人没做好的点

不是热力图，也不是普通导航

现有项目常停在“哪里热”或“哪里有避暑点”。这个原型把热风险嵌入老人每一次出门，直接回答：今天适不适合出门、几点走、哪条路少晒、哪里坐下休息、哪里能饮水求助、家属何时收到提醒。

公益闭环

老人端 + 家属端 + 社区端

老人得到当天可执行的避暑安全路线；家属获得风险提醒；社区获得热暴露盲区、避暑安全点覆盖缺口和适老设施建议，用于新增遮阴、座椅、饮水点和志愿者巡查。
