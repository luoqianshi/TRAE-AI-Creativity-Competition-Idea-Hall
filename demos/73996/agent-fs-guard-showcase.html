// 痛点问题

AI 编程代理很强大，但也很危险

当你把文件系统权限交给 AI 时，一次误操作就可能导致不可逆的损失。这些风险真实存在，且每天都在发生。

🗑️

误删重要文件

一条 rm -rf 命令可能清空整个项目目录，甚至波及系统文件，恢复成本极高。

🔐

凭证泄露风险

AI 可能无意中读取或修改 .env、密钥文件等敏感信息，导致 API Key、密码等凭证泄露。

🕳️

越界写入

通过符号链接或路径遍历，AI 可能写入项目目录之外的位置，破坏系统稳定性或植入恶意代码。

// 核心功能

全方位的文件系统防护

从实时监控到风险评估，从自动归档到一键恢复，agent-fs-guard 为你的 AI 工作流提供完整的安全网。

01

实时文件监控

基于 chokidar 的高效文件系统监控，追踪所有文件的创建、修改和删除事件，毫秒级响应。

02

7 条风险检测规则

覆盖大规模删除、凭证文件写入、工作区越界、符号链接逃逸、大文件写入等常见风险场景。

03

自动归档 & 恢复

文件被修改或删除前自动备份，支持 sha256 校验的归档清单，一条命令即可完整恢复。

04

审计日志

所有操作记录到 JSONL 审计日志，敏感路径自动脱敏，满足合规和追溯需求。

05

多工具适配

支持 Claude Code、Codex、Cursor、MCP 文件系统服务器等主流 AI 编程工具，供应商中立。

06

策略决策引擎

支持 observe/warn/quarantine/block 四种模式，按风险等级采取不同级别的防护措施。

// 风险规则
规则名称 风险等级 默认动作 说明
outside_workspace Critical block 写入工作区目录之外的路径
protected_path_write Critical block 写入 .env、密钥等敏感文件
symlink_escape Critical block 通过符号链接逃逸工作区
agent_config_mutation Critical block 修改 CLAUDE.md、SKILL.md 等代理配置
mass_delete High quarantine 短时间内大量删除文件
single_large_file High warn/block 单个文件超过大小阈值
large_write_burst Medium warn 短时间内大量写入数据

// 价值与意义

为什么 agent-fs-guard 很重要

AI 编程代理正在改变软件开发的方式，但安全永远不能妥协。

🚀 效率提升

  • 放心使用 AI 自动化编码，不用时刻担心误操作
  • 一键恢复误删文件，省去 Git 回滚或手动重建的麻烦
  • 审计日志让你快速了解 AI 做了什么改动
  • 降低 Code Review 中检查文件操作的心智负担

🌍 社会价值

  • 推动 AI 编程工具的安全标准建立
  • 开源项目，促进开发者社区安全意识提升
  • 为 AI Agent 安全研究提供参考实现
  • 降低企业和个人使用 AI 编程工具的安全门槛
// 发展路线图

从被动响应到主动防护

我们的目标是让文件系统防护从用户态监控进化到内核级强制，从被动归档进化到主动拦截。

v0.1 — MVP（当前）
基础能力：可见性 + 归档 + 建议性防护
  • pnpm + TypeScript monorepo（core、cli、adapters、skill）
  • 7 条规则风险引擎 + 策略决策引擎
  • JSONL 审计日志 + sha256 归档引擎
  • Claude Code 钩子、Codex TOML 配置、MCP 包装模板
v0.2 — 预防性加固
让适配器真正做到事前拦截
  • 强化 Claude Code PreToolUse 规则集
  • MCP 网关脚本，真正拦截写入/删除/重命名
  • 跨适配器会话 ID 串联，完整还原一次 AI 操作
v0.3 — 操作系统级监控
从用户态通知到内核级观察
  • Linux: fanotify + eBPF 高性能事件捕获
  • macOS: EndpointSecurity 系统级文件拦截
  • Windows: ETW + USN journal 变更追踪
v0.4 — 防篡改审计
让审计日志本身也值得信任
  • SQLite 审计存储，事务性追加
  • 哈希链：每条记录包含前一条的哈希
  • afg verify-audit 命令验证链完整性
v1.0 — 稳定 API + 插件系统
生产就绪，社区可扩展
  • 稳定的公共 API 和配置 schema
  • 第三方规则包和归档后端插件
  • 安全审计 + 外部代码审查
