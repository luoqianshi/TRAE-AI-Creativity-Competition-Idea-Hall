01 · INDUSTRY PAIN

⏱️

RTL 编码效率低

验证环境搭建耗时

验证滞后 · 周期长

调式周期长

03 · CORE FUNCTIONS

7 个专业 Agent 组成协作团队

每个 Agent 都是 ReactAgent · 复杂阶段被进一步拆为子 Agent · 粒度细到可追溯

🧭

PlannerAgent · 意图解析

分析用户自然语言，识别任务类型（设计/问答/验证/审查/分析），推断模块名与复杂度，自主决定调度哪些 Agent、以什么策略执行。

任务类型 · 模块名 · 子任务链
📚

KnowledgeAgent · 三通道知识检索

Qdrant 向量库（384 维语义匹配）+ BM25 文档检索（词频匹配）+ ripgrep 代码搜索（正则匹配），知识来源 CVA6/Ibex/OpenTitan/RocketChip + AXI/RISC-V ISA。

hybrid = 向量 + BM25 + grep
🔧

RTLAgent · 企业级 RTL 编码

需求 → Spec → 微架构 → 文件规划 → RTL 初稿。内置 9 条企业级规范：一模块一文件、命名例化、三段式 FSM、参数化设计、顶层只例化连线 …

S1 → S5 共 5 个子 Agent
🧪

VerificationAgent · Mini-UVM 验证环境

参考 UVM 方法论用 Python 实现轻量验证框架：Transaction / Sequence / Driver / Monitor / Scoreboard / Coverage 5 层组件，自动生成 Cocotb testbench + 三级测试。

V0 → V4 共 5 个子 Agent
▶️

SimulationAgent · 三级仿真回归

冒烟测试 → 边界功能测试 → 随机回归测试。Verilator 5.x + Cocotb 2.0 后端，多格式 PASS/FAIL 自动解析，FAIL < 10% 算通过。

V5 → V7 共 3 个子 Agent
🔍

ReviewAgent · 代码审查与归档

Verilator lint 自检、验证总结审查、最终归档。每个产物经过 Review 才能进入下一阶段。

S6 · V8 · S9
💡

ReflectionAgent · 失败反思介入

分析失败根因（root_cause），给出修复建议（fix_suggestions）与置信度（confidence）。低置信度时主动请求用户介入。

执行 → 检查 → 反思 → 修复

04 · TECH STRATEGY

六大核心技术策略

让 Agent 自主决策而非预置编排 · 让系统越用越聪明 · 让 AI 自主 + 人按需介入

🤖

Agent 自主决策非预置编排

每个 Agent 是 ReactAgent，自主观察 → 思考 → 行动 → 反思，决定调用哪些 MCP 工具、如何完成任务，而非被编排器硬编码调度。

ReactAgent 范式
🔗

MCP 工具协议驱动

30+ 工具通过 MCP 协议暴露，Agent �需自主调用，工具集可扩展。FastMCP Server 后台运行，AtomCode 作为执行智能体。

FastMCP · 30+ 工具
🧠

反思闭环 + ReflectionAgent

执行后自检是否达标，失败时 ReflectionAgent 介入分析根因、给出修复建议与置信度，形成"执行 → 检查 → 反思 → 修复"闭环。

root_cause + fix_suggestions
🤝

人机协同中断机制

Agent 在 6 个时机主动获取用户提示：子阶段完成/开始前、连续失败、反复卡死、长时间无进展、收到提示后必须调整策略。

get_current_tips · 非黑盒
📈

自动进化 Skills 系统

任务完成后自动总结：成功经验 → good-Skill（最佳实践），失败教训 → bad-Skill（避坑指南）。5 个预置 Skill + 动态进化。

evolve-good / evolve-bad
✅

Checker 自动验证框架

5 个内置 Checker：FileExists / VerilatorLint / SimulationPass / Markdown / IverilogCompile。Agent 调用 check_stage 时自动执行，全部通过才推进。

06 · ROADMAP

分阶段实施路线与未来演进

从单模块设计验证起步 · 逐步扩展到复杂模块、协议模块 · 最终成为可扩展的芯片设计平台

PHASE 1 · 当前

单模块设计验证

输入"设计一个 8 位 ALU" → Agent 自主完成需求 → Spec → 微架构 → RTL → 自检 → 验证 → 仿真 → 归档。产出可综合 Verilog + 仿真通过报告。

PHASE 2

复杂模块多文件设计

输入"设计一个异步 FIFO，深度 16，位宽 32" → Agent 自主拆分子模块：fifo_top + fifo_ctrl + fifo_mem。产出多文件 RTL + Mini-UVM 验证环境 + 三级测试通过。

PHASE 3

协议模块设计

输入"设计一个 AXI4-Lite Slave 接口" → KnowledgeAgent 检索 AXI 协议规范 → RTLAgent 参考规范生成 RTL。产出协议兼容的 RTL + 协议一致性验证通过。

PHASE 4 · 规划中

新 Agent 扩展

添加 PowerAnalysisAgent（功耗分析）、FormalVerifyAgent（形式化验证），继承 BaseAgent 实现 _run() 并注册到 Agent 映射。

PHASE 5 · 规划中

新 EDA 工具接入

通过 MCP 协议接入 yosys 综合、OpenSTA 时序分析、VCS+UVM 商用验证后端，扩展工具集与验证能力。

PHASE 6 · 远期

多 LLM Provider 与团队 Skills 沉淀

接入 DeepSeek / Qwen / GPT-4 等模型；Skills 持续积累团队经验（FIFO 设计规范、AXI 验证策略等），让系统真正越用越聪明。
