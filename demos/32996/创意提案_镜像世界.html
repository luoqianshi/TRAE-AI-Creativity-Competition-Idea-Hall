微观位置评价应用

为身边每个微观位置留下真实、匿名、及时的标签

💡 创意名称与介绍

想解决什么问题

现有地图应用只能评价"店铺"、"景点"等宏观位置，无法覆盖"自习室哪个座位有插座"、"小区哪栋电梯常故障"等微观位置的真实信息需求。用户依赖口口相传，效率低、真实性难辨。

为什么会想到做这个

在校园生活中，发现同学们经常在微信群里询问"图书馆哪个位置WiFi好"、"食堂哪个窗口人少"；在租房时想知道"哪栋楼的电梯经常坏"。这些微观位置信息时效性强，现有平台无法满足。

大概是什么产品

一款基于LBS的移动应用（Android + 后端API），用户可以创建和浏览"锚点"——任意GPS坐标上的标签式评价，类似于"微观位置的大众点评"。

⭐ 核心功能特性

📍

微观位置锚点

为任意GPS坐标创建标签，支持避坑、种草、提醒、打卡四种类型

🗺️

附近智能浏览

基于PostGIS空间查询，毫秒级返回500米内所有锚点

🎭

可信匿名机制

前台昵称/匿名代号，后台手机号可追溯，平衡隐私与责任

⭐

信用分体系

用户行为评分，影响发布权限，激励优质内容产出

😣 当前痛点分析

信息不对称

用户需要花费大量时间询问或搜索，才能找到某个微观位置的真实情况。微信群、朋友圈的信息分散且难以检索。

时效性差

现有平台的信息往往是长期有效的，无法反映"今天电梯坏了"这类时效性强的状态。

真实性难辨

口口相传的信息缺乏验证机制，容易被误导。而完全匿名的平台又容易滋生虚假信息。

🔧 技术实现方案

前端

Android端采用 Kotlin + Jetpack Compose 构建声明式UI，后端管理采用 Vue 3 + Element Plus

后端

Node.js + Express 提供RESTful API，PostgreSQL + PostGIS 处理地理空间查询，支持百万级LBS数据毫秒级响应

匿名机制

采用"抖音模式"：后台实名（手机号加密存储可追溯），前台昵称/匿名代号显示，平衡用户隐私与内容治理

技术栈

Kotlin Jetpack Compose Vue 3 Node.js PostgreSQL PostGIS 高德地图SDK JWT
