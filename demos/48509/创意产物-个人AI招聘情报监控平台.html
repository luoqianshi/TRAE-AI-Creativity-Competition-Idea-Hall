01 / 痛点

垂直招聘信息，藏在公众号的图文与长图里

金融、国企、央企的招聘公告几乎只发在特定公众号，没有聚合平台、没有提醒机制。求职者被迫成为"信息苦力"。

01

信息极度分散

一个方向的招聘信息分散在 20-30 个公众号里，每天逐个翻阅耗时 1-2 小时，大量重复滑动与无效浏览。

02

长图海报难处理

很多单位把整张岗位表做成几千像素的长图，肉眼逐条比对、手抄邮箱，极易串行、记错、漏看。

03

截止日期无提醒

投递截止日期藏在正文段落或图片角落，公众号没有提醒功能，漏看一次就错过一个机会。

04

主流平台覆盖盲区

体制内、垂直行业社招机会基本不在主流招聘 App 上架，信息获取能力直接决定机会均等性。

02 / 核心流程

五段式情报管道，从发现到推送全自动

低频定时触发（每日 08:30 / 20:30），单次任务 20-30 个公众号在 45 分钟内自动完成抓取、解析、过滤、提取与推送。

STEP 01
📡

文章发现

低频抓取目标公众号近 24-36 小时新文章，手动 Cookie 维护，防封频策略

STEP 02
📄

STEP 03
⚡

STEP 04
🧠

文本 LLM / OCR+LLM / 长图切片 VLM 三路按质量自动切换

STEP 05

用户规则匹配后，飞书/钉钉 Webhook 推送精准岗位表格日报

03 / 混合智能

不是无脑调 VLM，而是成本最优的分层策略

核心创新点：用关键词预过滤挡掉非招聘内容，用 OCR 质量评分决定走哪条路，只有长图复杂场景才调用 VLM，把昂贵调用控制在 20% 以内。

DUAL-PATH · 双路切换

文本 LLM 优先

当正文文本长度 ≥ 500 且包含岗位/投递信息时，直接走低成本文本 LLM 提取，不碰图片，不调 OCR，不花 VLM 的钱。

正文 ≥500 字 + 含投递信息
→ 文本 LLM 提取 (最低成本)
有图片 → 运行 OCR → 质量评分
→ score ≥ 0.72 OCR 文本 + 原文 → 文本 LLM
→ 0.45 ≤ score < 0.72 低成本 VLM 复核
→ score < 0.45 / 长图 长图切片 → VLM
COST CONTROL · 成本控制

VLM 调用 ≤ 20%

非招聘文章不进 LLM；OCR 优先本地跑；文本 LLM 用低成本模型；VLM 只处理关键切片，不整篇上传。每日预算上限可配（如 5 元/日），超限即停止 VLM 转入待复核。

候选文章 → 文本 LLM~60%
OCR + 文本 LLM~20%
长图切片 → VLM≤20%
LONG-IMAGE · 长图切片

切片 + 重叠 + 合并去重

最大切片高度 1800px，上下重叠 220px 防止岗位表格跨切片丢失上下文。每张切片带元信息，先提取局部岗位再做合并去重，底部含邮箱/二维码的切片强制保留。

原图高度 > 3000px 且 OCR < 300 字
→ 等比缩放至 1440px
→ 切片 1800px / 重叠 220px
→ 每切片局部提取
→ 合并去重 (公司+岗位+地点)
每篇最多 8 切片，超出先 OCR 找关键区
ACCURACY · 邮箱逐字符校验

不确定即复核，不猜不编

邮箱必须逐字符输出并额外输出 email_chars 数组，与正则校验双重比对；不一致标记 email_mismatch 进人工复核。截止日期早于发布时间、地点为空但表格含城市词等异常均二次校验。

LLM 输出 email + email_chars[]
→ 正则校验 [A-Za-z0-9._%+-]+@...]
→ email ≠ chars.join("") → mismatch
→ confidence < 60 → 待复核区
目标：邮箱提取准确率 ≥ 98%

05 / 价值与意义

效率提升 + 信息平权，两个角度的价值

EFFICIENCY · 效率提升

从 1-2 小时压缩到 2 分钟

关键词预过滤先剔除非招聘内容，OCR + 文本 LLM 优先的低成本策略结构化提取，只在长图复杂场景才调用 VLM 兜底。单次任务 20-30 个公众号在 45 分钟内自动完成，用户每天只需 2 分钟扫一眼日报。

1-2 小时手动刷号 → 2 分钟看日报
SOCIAL · 社会价值

抹平信息差，让机会更均等

金融、国企、央企的招聘信息往往只在特定公众号发布，"信息渠道资源"直接决定机会均等性。本产品让没有内部渠道的普通求职者也能平等、及时地获取这些机会，降低求职中的信息壁垒。

靠人脉找渠道 → 靠 AI 抹平信息差

07 / 技术架构

四层架构，低频、轻量、可人工维护

不是商业爬虫平台，不追求高并发、账号池、Cookie 池。本地 SQLite 存储，YAML 规则化配置，每个模块 CLI 可单独运行。

LAYER 01

配置层

  • accounts.yaml 公众号订阅
  • rules.yaml 匹配规则
  • cookie.env 凭证管理
  • Cookie 24h 失效检测
LAYER 02

采集解析层

  • 公众号文章发现
  • HTML / Markdown 抽取
  • 图片本地化 + 防盗链
  • 关键词预过滤评分
LAYER 03

智能提取层

  • RapidOCR / PaddleOCR
  • 文本 LLM 结构化
  • 长图切片 + VLM 兜底
  • 邮箱逐字符校验
LAYER 04

存储通知层

  • SQLite 去重存储
  • 用户规则匹配
  • 飞书 / 钉钉 Webhook
  • run_logs 运行留档
