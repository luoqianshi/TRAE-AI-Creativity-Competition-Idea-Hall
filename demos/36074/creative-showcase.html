PRODUCT POSITIONING

产品定位

不同于被动记忆与浅层 spec 规范，HexaCanopy 是面向 AI Agent 的完整软件工程管理体系。

是什么

软件工程管理体系 · CLI / 技能包

面向 AI Agent 的软件工程管理体系，目标覆盖软件开发全流程管理。 产品定义 → 需求分解 → 任务执行是当前已完成并验证的核心链路。

  • 断点续跑：换会话、换设备、换 Agent，工程上下文无缝接续
  • 评审对齐：各层嵌入正式评审环节，确保人机协作双向对齐
  • 全流程覆盖：产品、需求、任务管理的完整链路
  • 继承 Meta：基于 MetaCanopy 元技能体系，稳定可靠

解决什么问题

  • 需求只活在对话里，换会话就丢失
  • 方案没有评审就执行，方向错了无人知晓
  • 任务状态散落在会话窗口，不可追溯
  • 长周期项目必定丢失前置决策和业务背景

如何解决

  • 本地 Markdown 永久落盘：工程信息以结构化文件形式持久化
  • 标准流程协作：让 AI Agent 按软件工程流程执行
  • 跨会话断点续跑：换会话、换设备、换 Agent 无缝接续
  • 按需索引：Agent 无需记忆，按目录结构还原上下文

TARGET USERS · 4 TYPES

四类目标用户场景

从独立开发者到企业系统集成，每一类用户都有对应的模块化组合方案。

1

独立软件开发者

场景：多项目并行、需长期维护工程上下文
满足方案：提供所有典型软件工程管理场景支持，人机交互流畅，开发效率更高。
2

Vibe Coding 进阶者

场景：已入门 AI 辅助开发，希望工程实践更规范
满足方案：有序管理规模更大的软件工程，继承成熟工程方法论，快速提升实践水平。
3

小型团队

场景：角色分工协作（PM/研发/测试），需流程协同
满足方案：基于 Git 进行管理，逻辑同代码一致，0 学习迁移成本。
4

企业系统集成

场景：需与企业现有流程对接，对外输出服务
满足方案：依赖管理和文档管理接口支持企业集成；作为基础设施可被应用平台继承能力。

EXTERNAL EXTENSION INTERFACES

外部扩展接口

标准化接口设计，所有模块通过统一接口协作，支持灵活组合和企业级定制。

🔌
接口一 · 依赖管理

继承外部能力

外部能力通过标准接口接入，增强特定领域执行效果。企业可将已有能力（CI/CD、领域知识、规范库）接入 HexaCanopy 体系，形成自有流程闭环。

📑
接口二 · 文档管理

外部文档集成

企业文档模板可接入，支持渲染发布。与企业文档规范、变更日志、发布说明等流程打通，使工程管理成果可直接对接企业既有知识体系。

可扩展性说明：HexaCanopy 采用标准化接口设计，所有模块通过统一接口协作。 工程实践需要哪些模块，按需引入即可——支持灵活组合和企业级定制。 MetaCanopy 元技能体系为整个系统提供方法论基础。
