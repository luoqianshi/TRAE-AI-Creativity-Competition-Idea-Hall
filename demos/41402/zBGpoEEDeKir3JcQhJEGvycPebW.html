01 / Problem

AI 工具越来越多，但记忆仍然是孤岛。

当多个 AI 编程工具一起使用时，每个工具都有自己的局部上下文。项目结构、接口约定、历史决策和排查结果需要反复说明，协作体验容易变成“每次都重新开始”。

上下文重复解释

换一个工具，就要重新描述项目背景、当前任务和关键约束。

知识沉淀断裂

一次对话里的重要结论，很难自然流入下一个 AI 工作流。

企业知识难复用

规范、复盘、接口说明和最佳实践需要统一的存储与检索入口。

02 / Solution

用一个本地 MCP 记忆总线连接所有 AI 工具。

Local AI Memory Bus 提供统一的本地服务层，让不同 AI 客户端读写同一份记忆。工具之间不再各自保存孤立上下文，而是通过统一入口共享项目知识。

03 / Hybrid Retrieval

关键词找事实，向量找语义。

系统用 BM25 处理精确词项、文件名、接口名和错误码；用语义向量处理自然语言意图；最后把两类结果融合，提升记忆召回的稳定性。

BM25

适合召回项目名、文件名、函数名、接口名、错误码等精确信息。

Dense Vector

适合召回表达不同但语义相似的问题、经验和历史结论。

Hybrid Ranking

融合关键词和语义结果，减少纯向量漂移，也减少纯关键词漏召。

04 / Memory Layers

不是所有记忆都应该永久保存。

记忆需要按生命周期分层。短期上下文用于当前任务，关键项目信息进入结构化存储，长期知识进入 durable 层，历史材料进入 archive 层，避免噪声污染检索空间。

L0 Working 当前任务

当前会话的临时工作记忆，用于即时推理和任务执行。

L1 Session 近期上下文

面向短期协作的滚动上下文，保存近期任务和阶段性结论。

L2 Essential 关键项目信息

项目约定、接口约束、技术选型、稳定事实等重要信息。

L3 Durable 长期知识

长期有效的规范、经验、复盘、SOP 和可复用知识。

L4 Reference 参考资料

外部文档、说明材料、样例文件和可引用资料。

L5 Archive 归档内容

历史内容默认不进入主要检索空间，减少旧信息带来的干扰。
