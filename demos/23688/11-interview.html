Q
什么是 Linux？Linux 内核主要负责哪些功能？

Linux 是一套免费使用和自由传播的类 Unix 操作系统，是一个基于 POSIX 和 Unix 的多用户、多任务、支持多线程和多 CPU 的操作系统。它能运行主要的 Unix 工具软件、应用程序和网络协议，支持 32 位和 64 位硬件。

Linux 内核是系统的核心，控制着计算机上的所有硬件和软件，主要负责以下四大功能：

  • 系统内存管理 — 负责内存的分配、回收与映射
  • 应用程序管理 — 负责进程的调度、创建与终止
  • 硬件设备管理 — 管理和分配设备驱动资源
  • 文件系统管理 — 管理文件的存储、读写与权限

Linux 的体系结构是怎样的？

Linux 体系结构从大的方面分为两部分：

  • 用户空间 (User Space)：包括用户的应用程序 (User Applications) 和 C 库 (C Library)
  • 内核空间 (Kernel Space)：包括系统调用接口 (System Call Interface)、内核 (Kernel) 和平台架构相关的代码 (Architecture-Dependent Kernel Code)

用户空间的应用程序通过系统调用接口与内核空间进行交互，内核空间直接操作硬件资源。

Q
什么是 inode？硬链接和软链接有什么区别？
▶ 点击查看答案

inode（索引节点）：文件储存在硬盘上，硬盘最小存储单位是扇区 (Sector，512 字节)。操作系统一次读取一个"块" (block，通常 4KB)。文件数据存储在"块"中，而文件的元信息（创建者、日期、大小、权限等）存储在 inode 中。

每个文件都有对应的 inode，inode 节点表通过磁盘地址表将文件的逻辑结构与物理结构关联。

硬链接 vs 软链接：

特性硬链接软链接
跨分区不可以可以
inode指向同一 inode创建新的 inode
删除链接不影响原文件原文件可能被删除
目录链接仅 root 可创建任何用户可创建
移动原文件不受影响链接失效
Bash
# 创建软链接
ln -s slink source

# 创建硬链接
ln link source
Q
Linux 使用的进程间通信 (IPC) 方式有哪些？
  • 管道 (Pipe) — 用于具有亲缘关系的进程间通信，允许一个进程和另一个有共同祖先的进程之间进行通信
  • 命名管道 (FIFO) — 克服了管道没有名字的限制，允许无亲缘关系进程间通信，通过 mkfifo 创建
  • 信号 (Signal) — 比较复杂的通信方式，用于通知接收进程有某种事件发生
  • 消息队列 (Message Queue) — 消息的链表，支持随机查询，克服了信号承载信息量少的缺点
  • 共享内存 (Shared Memory) — 最快的 IPC 形式，多个进程访问同一块内存空间，通常与信号量配合使用
  • 信号量 (Semaphore) — 进程间及同一进程不同线程之间的同步手段
  • 套接字 (Socket) — 可用于不同机器之间的进程间通信，是最通用的 IPC 机制
Q
什么是交换空间 (Swap)？什么是 root 帐户？

交换空间：当 RAM 没有足够的内存来容纳所有正在执行的程序时，Linux 会使用一定的硬盘空间来临时保存并发运行的程序数据，这部分空间称为交换空间。

root 帐户：系统管理员帐户，拥有对系统的完全控制权。可以创建和维护用户帐户、分配权限、管理系统配置。每次安装 Linux 时都会自动创建。

Q
什么是 RAID？它有什么作用？

RAID（独立磁盘冗余阵列）的基本思想是将多个相对便宜的硬盘组合成一个硬盘阵列组，使性能达到甚至超过一个价格昂贵、容量巨大的硬盘。

RAID 通常用在服务器上，使用完全相同的硬盘组成逻辑扇区，操作系统只将其视为一个硬盘。不同的 RAID 等级在数据可靠性和读写性能上做了不同的权衡，可根据实际需求选择合适的方案。

什么是操作系统？它由哪些部分组成？

操作系统 (OS) 是管理计算机硬件与软件资源的程序，是计算机系统的内核与基石。它为用户提供一个与系统交互的操作界面。

操作系统分为内核和外壳两部分：

  • 内核 — 操作硬件的程序，负责管理系统的进程、内存、设备驱动、文件和网络系统，决定系统的性能和稳定性
  • 外壳 — 围绕内核的应用程序（Shell），是用户与内核交互的接口

Linux 系统由内核、Shell、文件系统和应用程序四部分组成。

  • 创建状态 (new) — 进程正在被创建，尚未到就绪状态
  • 就绪状态 (ready) — 已获得除处理器外的一切所需资源，等待 CPU 时间片

线程间的同步方式有哪些？
  • 互斥量 (Mutex) — 只有拥有互斥对象的线程才有访问公共资源的权限。因为互斥对象只有一个，保证了公共资源不会被多个线程同时访问
  • 信号量 (Semaphore) — 允许同一时刻多个线程访问同一资源，但控制同时访问的最大线程数量
  • 事件 (Event) / Wait-Notify — 通过通知操作来保持多线程同步，还可以方便地实现多线程优先级的比较操作

Q
操作系统的内存管理主要做什么？常见的内存管理机制有哪些？
▶ 点击查看答案

内存管理主要负责内存的分配与回收（malloc 申请 / free 释放），以及地址转换（逻辑地址转物理地址）。

常见的内存管理机制：

  • 块式管理（连续分配）— 将内存分为固定大小的块，每块只含一个进程。碎片严重
  • 页式管理（非连续分配）— 把主存分为大小相等的页，通过页表映射逻辑地址和物理地址。利用率高，碎片少
  • 段式管理（非连续分配）— 把主存分为有逻辑意义的段（代码段、数据段等），通过段表映射。更符合用户需求

分页 vs 分段：

  • 共同点：都是离散存储，提高内存利用率，减少碎片
  • 区别：页大小固定由 OS 决定；段大小不固定由程序决定。页无实际意义；段是逻辑信息单位
Q
什么是快表 (TLB) 和多级页表？

快表 (TLB)：一种高速缓冲存储器 (Cache)，内容为页表的一部分或全部内容，用于加速虚拟地址到物理地址的转换。查找流程：

  1. 根据虚拟地址中的页号查快表
  2. 命中则直接读取物理地址
  3. 未命中则访问内存中的页表，同时将映射表项添加到快表
  4. 快表满时按淘汰策略替换

多级页表：为避免全部页表常驻内存占用过多空间。多级页表属于时间换空间的典型场景。

Q
什么是虚拟内存？局部性原理是什么？
▶ 点击查看答案

虚拟内存：计算机系统内存管理的一种技术，它定义了一个连续的虚拟地址空间，并将内存扩展到硬盘空间。虚拟地址通过 MMU（内存管理单元）转换为物理地址。

虚拟地址空间的优势：

  • 程序可用相邻虚拟地址访问不相邻的物理内存
  • 可使用比物理内存更大的内存缓冲区
  • 不同进程的虚拟地址彼此隔离，互不影响

局部性原理是虚拟内存的理论基础：

  • 时间局部性 — 刚使用的指令/数据不久后可能再次被使用（循环操作导致）
  • 空间局部性 — 刚访问的存储单元附近的单元不久后也将被访问（顺序执行导致）
Q
页面置换算法有哪些？

当发生缺页中断且内存无空闲页面时，需要选择淘汰页面的规则：

算法原理特点
OPT (最佳)淘汰以后永不使用或最长时间不再被访问的页面缺页率最低，但无法实现，用作理论基准
FIFO (先进先出)淘汰最先进入内存的页面简单，但可能淘汰常用页面
LRU (最近最久未使用)淘汰最近最久未被访问的页面效果接近 OPT，实际广泛使用
LFU (最少使用)淘汰之前时期使用最少的页面可能误判早期常用但后期不再使用的页面
Q
为什么需要虚拟地址空间？

如果直接暴露物理地址会带来严重问题：

  • 用户程序可以访问任意内存，容易有意或无意地破坏操作系统，造成系统崩溃
  • 多个程序同时运行时，可能相互覆盖内存数据（如微信和 QQ 音乐同时写入地址 1xxx）

现代处理器使用虚拟寻址，通过 MMU（内存管理单元）将虚拟地址翻译为物理地址，实现进程隔离和内存保护。

Q
虚拟内存的技术实现方式有哪些？
  • 请求分页存储管理 — 在分页管理基础上增加请求调页和页面置换功能，是目前最常用的方式
  • 请求分段存储管理 — 在分段管理基础上增加请求调段和分段置换功能
  • 请求段页式存储管理 — 结合段式和页式的优点

实现虚拟内存一般需要：一定容量的内存和外存、缺页中断机制、虚拟地址空间（逻辑地址到物理地址的变换）。

Q
什么是虚拟存储器？

基于局部性原理，在程序装入时只需装入一部分，其余留在外存。执行过程中，OS 按需将数据调入内存，也可将暂时不用的内容换出到外存。这样计算机就好像提供了一个比实际内存大得多的存储器 —— 虚拟存储器。

本质上是一种时间换空间的策略：用 CPU 计算时间和页面调入调出的时间，换来一个虚拟的更大空间。

  • 逻辑地址（虚拟地址） — 由操作系统决定，是程序看到的地址
  • 物理地址 — 真实物理内存中的地址，是内存地址寄存器中的地址，是内存单元真正的地址

进程访问资源分为两个级别：用户态（可直接读取用户程序数据）和 系统态/内核态（可访问计算机任何资源）。

  • 文件管理 — 文件读写/创建/删除
  • 进程控制 — 进程创建/撤销/阻塞/唤醒
  • 进程通信 — 消息/信号传递
  • 内存管理 — 内存分配/回收/地址获取

HTTP 是什么？它有什么特点和缺点？
▶ 点击查看答案

HTTP (HyperText Transfer Protocol) 是超文本传输协议，专门在两点之间传输文字、图片、音频、视频等超文本数据的约定和规范。

Q
TCP 三次握手的过程是怎样的？为什么不能两次握手？
▶ 点击查看答案
客户端发送 SYN (seq=X)
→
服务端回复 SYN+ACK (seq=Y, ack=X+1)
→
客户端发送 ACK (ack=Y+1)

三次握手的目的是确保双方都能正确收发数据：

  • 第一次：客户端确认自己能发送，服务端确认自己能接收
  • 第二次：服务端确认自己能发送，客户端确认自己能接收
  • 第三次：客户端确认服务端能发送（防止已失效的连接请求到达服务端）

如果只有两次握手，服务端无法确认客户端是否收到了自己的确认，可能导致无效连接占用资源。

Q
TCP 四次挥手的过程是怎样的？
▶ 点击查看答案
1. 主动方发送 FIN
→
2. 被动方回复 ACK
→
3. 被动方发送 FIN
→
4. 主动方回复 ACK

详细说明：

  • 第一次：主动关闭方发送 FIN，告知不再发送数据（但仍可接收）
  • 第二次：被动方回复 ACK，确认收到
  • 第三次：被动方也发送完数据后，发送 FIN 告知对方
  • 第四次：主动方回复 ACK，进入 TIME_WAIT 状态等待一段时间后释放

需要四次而不是三次，是因为 TCP 是全双工通信，每个方向需要独立关闭。

  • 支持管道 (pipeline) 网络传输，可连续发送请求

  • 多路复用 — 一个连接并发多个请求，解决队头阻塞

Q
什么是拥塞控制？TCP 采用哪些算法？

拥塞控制是为了防止过多数据注入网络，使路由器或链路不至于过载。TCP 发送方维护一个拥塞窗口 (cwnd) 状态变量，采用四种算法：

  • 慢开始 — 初始 cwnd=1，每经过一个传播轮次 cwnd 加倍，由小到大探测网络
  • 拥塞避免 — 让 cwnd 缓慢增大，每经过一个 RTT 加 1
  • 快重传 — 收到三个重复 ACK 后立即重传丢失的数据段，而不等待超时
  • 快恢复 — 配合快重传，快速恢复发送窗口大小

注意区分：流量控制是端到端的（接收方速率限制发送方），拥塞控制是全局的（涉及所有主机和路由器）。

Q
HTTP 的报文结构是怎样的？

HTTP 报文由四部分组成：起始行 + 头部 + 空行 + 实体

  • 起始行：请求报文为 方法 路径 HTTP版本（如 GET /home HTTP/1.1）；响应报文为 HTTP版本 状态码 原因（如 HTTP/1.1 200 OK）
  • 头部：键值对形式，字段名不区分大小写，字段名后紧跟冒号
  • 空行：区分头部和实体，空行之后的内容全部视为实体
  • 实体 (Body)：具体的传输数据
Q
TCP 如何保证可靠传输？
▶ 点击查看答案
  • 数据分块 — 应用数据被分割成 TCP 认为最适合发送的数据块
  • 编号排序 — 每个包编号，接收方排序后传给应用层
  • 校验和 — 检测传输过程中的数据变化，有差错则丢弃
  • 流量控制 — 利用滑动窗口机制，控制发送速率不超过接收方处理能力
  • 拥塞控制 — 网络拥塞时减少数据发送
  • ARQ 协议 — 每发完一个分组等待确认，收到确认后再发下一个
  • 超时重传 — 未在定时器超时前收到确认，则重发报文段
  • 去重 — 丢弃重复的数据
Q
什么是 HTTP 长连接和短连接？
  • 短连接（HTTP/1.0 默认）— 每次 HTTP 操作都建立一次连接，任务结束就中断。页面中每个资源都需重新建立连接
  • 长连接（HTTP/1.1 默认）— 通过在响应头加入 Connection: keep-alive，网页打开后 TCP 连接不关闭，后续请求复用同一连接

长连接有一个保持时间，可在服务器软件中设定。HTTP 的长/短连接本质上是 TCP 的长/短连接。

Q
什么是滑动窗口？什么是流量控制？

滑动窗口：TCP 利用滑动窗口实现流量控制。接收方发送的确认报文中的窗口字段用来控制发送方的窗口大小，从而影响发送速率。将窗口字段设置为 0，则发送方不能发送数据。

流量控制的目的是控制发送方发送速率，保证接收方来得及接收。这是一个端到端的问题。

什么是 TLB？它在内存管理中起什么作用？

TLB (Translation Lookaside Buffer) 即页表缓存。当线性地址第一次被转换成物理地址时，会将线性地址和物理地址的对应关系放入 TLB 中，用于下次访问相同线性地址时加速转换速度。

TLB 本质上是一种高速 Cache，存储的是页表的部分或全部内容。

Q
Linux 中的浮点运算是由应用程序实现还是内核实现？

Linux 中的浮点运算由应用程序实现。Linux 利用数学库函数实现浮点运算，库函数能被应用程序链接后调用，但不能被内核链接调用。

如果内核需要进行浮点运算，需要在编译内核时选择 math-emu 选项，使用软件模拟浮点运算，但这会降低效率。

Linux 调度程序根据动态优先级还是静态优先级来调度进程？

Linux 调度程序根据动态优先级来调度进程。动态优先级是基于静态优先级通过算法计算出来的。

引入动态优先级的原因是：高优先级进程总是先被调度，为防止多个高优先级进程长时间占用 CPU 导致其他进程饥饿，需要动态调整优先级以保证公平性。

进程调度的核心数据结构是 struct runqueue（运行队列）。

Q
详细说明 keepalived 的故障切换工作原理。

Keepalived 的故障切换通过 VRRP 协议实现：

  1. 主节点按一定时间间隔发送心跳广播包，告知备节点自己的存活状态
  2. 当主节点发生故障时，备节点在一段时间内收不到广播包，判断主节点故障
  3. 备节点调用接管程序，接管主节点的 IP 资源及服务
  4. 当主节点恢复时，备节点主动释放资源，恢复到接管前状态

从而实现了主备故障自动切换，保证服务的高可用性。

  • A ACK → SYN → SYN+ACK
  • B SYN → SYN+ACK → ACK
  • C SYN → ACK → SYN+ACK
  • D SYN+ACK → SYN → ACK
解析：TCP 三次握手流程：客户端发送 SYN → 服务端回复 SYN+ACK → 客户端发送 ACK。这确保双方都能正确收发数据，第三次握手还可以防止已失效的连接请求到达服务端导致资源浪费。
3. 以下哪个不是 Linux 内核模块的特征？
  • A 运行在内核空间
  • B 通过 insmod 加载
  • C 可以使用标准 C 库函数
  • D 通过 rmmod 卸载
解析：内核模块运行在内核空间，不能链接和使用标准的 C 库函数（如 printf、malloc 等）。内核模块只能使用内核自身提供的函数（如 printk、kmalloc 等）。这是嵌入式开发和驱动开发中的重要概念。
