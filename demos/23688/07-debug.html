🔧 常用调试工具

JTAG / SWD 接口

🔌 JTAG 与 SWD 概述
  • JTAG（Joint Test Action Group）：标准调试接口，支持多设备级联，适用于复杂芯片（如 FPGA）调试。
  • SWD（Serial Wire Debug）：ARM Cortex 系列的简化调试协议，仅使用两根线（SWDIO, SWCLK），适用于资源受限的嵌入式 MCU（如 STM32）。

JTAG 与 SWD 接口对比

特性JTAGSWD
引脚数5 线（TMS、TCK、TDI、TDO、TRST）2 线（SWDIO、SWCLK）
速度中低速（典型 1-10MHz）高速（可达 50MHz 以上）
占用资源高（需多个 GPIO）低（仅 2 个 GPIO）
级联能力支持多设备（通过 TAP 控制器）不支持级联
适用场景复杂芯片调试（如 FPGA）嵌入式 MCU（如 STM32）
💡
在 STM32 项目中，推荐使用 SWD 接口以释放更多 GPIO 引脚。通过 __HAL_AFIO_REMAP_SWJ_NOJTAG() 可禁用 JTAG 同时保留 SWD 调试能力。
▶ SWD 调试配置示例（STM32CubeMX）
C
// 使能SWD接口（禁用JTAG以释放GPIO）
__HAL_RCC_GPIOA_CLK_ENABLE();
GPIO_InitTypeDef GPIO_InitStruct = {0};
GPIO_InitStruct.Pin = GPIO_PIN_13|GPIO_PIN_14;  // SWDIO, SWCLK
GPIO_InitStruct.Mode = GPIO_MODE_AF_PP;
GPIO_InitStruct.Pull = GPIO_NOPULL;
GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_LOW;
GPIO_InitStruct.Alternate = GPIO_AF0_SWJ;
HAL_GPIO_Init(GPIOA, &GPIO_InitStruct);
__HAL_AFIO_REMAP_SWJ_NOJTAG();  // 禁用JTAG，保留SWD

GDB + OpenOCD 调试

🖥 GDB 与 OpenOCD 简介
  • GDB：GNU 调试器，支持断点、单步执行、查看变量等核心调试操作。
  • OpenOCD：Open On-Chip Debugger，用于连接 GDB 和硬件调试接口（如 ST-Link），充当软件与硬件之间的桥梁。
📝
调试工作流：先启动 OpenOCD 连接硬件，再启动 GDB 连接到 OpenOCD 的 GDB Server（默认端口 3333），最后通过 GDB 命令控制程序执行。

GDB + OpenOCD 关键命令详解

Bash
# 1. 启动OpenOCD（连接ST-Link与目标MCU）
openocd -f interface/stlink.cfg -f target/stm32f4x.cfg

# 2. 启动GDB并加载ELF文件
arm-none-eabi-gdb path/to/firmware.elf

# 3. 连接到OpenOCD服务器
(gdb) target remote :3333  # 默认端口3333

# 4. 下载程序到Flash
(gdb) load

# 5. 复位并暂停CPU
(gdb) monitor reset halt

# 6. 设置断点
(gdb) break main  # 在main()函数入口设置断点
(gdb) break MyFunction  # 在自定义函数设置断点
(gdb) break file.c:123  # 在文件file.c的第123行设置断点

# 7. 执行控制
(gdb) continue  # 继续执行
(gdb) next  # 单步执行（不进入函数）
(gdb) step  # 单步执行（进入函数）
(gdb) finish  # 运行到当前函数结束

# 8. 查看变量
(gdb) print myVariable  # 打印变量值
(gdb) p &myArray[0]  # 打印数组地址
(gdb) x/10i $pc  # 查看当前执行的10条汇编指令

# 9. 查看寄存器
(gdb) info registers  # 查看所有寄存器
(gdb) p $r0  # 查看特定寄存器（如R0）

逻辑分析仪 / 示波器

📊 逻辑分析仪

用于捕捉数字信号波形，分析通信协议时序。

  • SPI 通信时序分析：验证 CPOL/CPHA 设置
  • I2C 总线竞争检测：查看 ACK/NACK 信号
  • UART 波特率校准：测量位宽计算实际波特率
📈 示波器

查看模拟信号、电压、电流变化，调试电源与 PWM。

  • 带宽：至少为信号最高频率的 3-5 倍
  • 采样率：至少为信号最高频率的 10 倍
  • 例：测量 1MHz PWM 需 5MHz 带宽、10MSa/s 采样率
▶ 调试 PWM 信号示例（TIM3 输出 1kHz/50%）
C
// 配置TIM3输出PWM（频率1kHz，占空比50%）
TIM_HandleTypeDef htim3;
htim3.Instance = TIM3;
htim3.Init.Prescaler = 72 - 1;  // 72MHz / 72 = 1MHz
htim3.Init.Period = 1000 - 1;   // 1MHz / 1000 = 1kHz
htim3.Init.CounterMode = TIM_COUNTERMODE_UP;
HAL_TIM_PWM_Init(&htim3);

TIM_OC_InitTypeDef sConfigOC;
sConfigOC.OCMode = TIM_OCMODE_PWM1;
sConfigOC.Pulse = 500;  // 占空比50%
sConfigOC.OCPolarity = TIM_OCPOLARITY_HIGH;
HAL_TIM_PWM_ConfigChannel(&htim3, &sConfigOC, TIM_CHANNEL_1);
HAL_TIM_PWM_Start(&htim3, TIM_CHANNEL_1);
💡
使用示波器测量：频率应为 1kHz，高电平时间 500us（占空比 50%）。如波形异常，检查预分频器和周期值配置。

printf / 串口调试

📨 串口调试输出
  • 常用 printf() 输出信息到串口，查看程序执行流程。
  • 可与 RTT（Real Time Transfer）配合实现非阻塞调试输出，不影响实时性能。
  • 在 IDE（如 STM32CubeIDE）中设置断点暂停程序运行，查看寄存器、内存、变量。
  • 适合调试初始化流程、外设配置错误等问题。
⚠
避免在中断服务程序（ISR）中使用 printf()，因其阻塞特性可能导致中断响应延迟甚至死锁。建议在 ISR 中使用 RTT 或标志位方式输出调试信息。
🧠 测验 1：SWD 接口相比 JTAG 的主要优势是什么？
  • A 支持多设备级联
  • B 引脚更少、速度更快，适合资源受限的嵌入式设备
  • C 支持更复杂的 FPGA 调试
  • D 可以同时调试多个 CPU 核心
SWD 仅需 SWDIO 和 SWCLK 两根线，占用 GPIO 更少，通信速度可达 50MHz 以上，远高于 JTAG。但 SWD 不支持级联，不适合复杂多芯片调试场景。

📈 性能与功耗优化

FreeRTOS Trace 与分析工具

🔍 FreeRTOS+Trace（Percepio）

使用 FreeRTOS+Trace 工具记录任务切换、上下文切换、CPU 占用率。通过 vTraceEnable() 开启追踪，在关键代码位置插入跟踪点（Trace Point）记录函数（如任务切换、中断处理）。

▶ 自定义跟踪点示例
C
// 自定义跟踪点示例
#define TRACE_TASK_SWITCH() do { \
    uint32_t current_task = (uint32_t)pxCurrentTCB; \
    uint32_t timestamp = xTaskGetTickCount(); \
    vTraceStoreEvent(EVENT_TASK_SWITCH, timestamp, current_task); \
} while(0)

跟踪数据存储配置

C
#define configUSE_TRACE_FACILITY 1  // 启用跟踪功能
#define configUSE_STATS_FORMATTING_FUNCTIONS 1  // 启用统计功能
#define TRACE_BUFFER_SIZE 1024  // 跟踪缓冲区大小（事件数）
📝
跟踪数据存储在环形缓冲区中，可避免内存溢出。当缓冲区满时，最旧的事件数据会被新数据覆盖，确保系统持续运行不受影响。

SystemView 分析工具

💻 SEGGER SystemView

SEGGER 提供的实时系统分析工具，与 FreeRTOS 集成，通过 SWO 接口获取任务执行时间、事件追踪等信息。

关键指标解读

  • 任务执行时间：各任务 CPU 占用百分比，帮助识别性能瓶颈。
  • 上下文切换频率：过高表示任务调度不合理，可能需要优化任务优先级或合并任务。
  • 中断响应时间：从中断触发到 ISR 执行的时间差，反映系统实时性。

低功耗模式优化

Cortex-M 支持三种主要低功耗模式

模式唤醒时间功耗保留内容
Sleep数 us几 mACPU 寄存器、SRAM 内容
Stop几十 us几 uASRAM 内容、部分寄存器
Standby几 ms几十 nA仅备份寄存器（如 RTC）
正常运行
→
Sleep（数 us 唤醒）
→
Stop（几十 us 唤醒）
→
Standby（几 ms 唤醒）
💡
选择低功耗模式时需要权衡唤醒时间和功耗。对于周期性采集传感器数据的场景，Standby + RTC 唤醒是最优选择；对于需要快速响应的事件驱动场景，Sleep 或 Stop 更合适。
▶ 外设时钟管理优化
C
// 禁用未使用的外设时钟
__HAL_RCC_GPIOA_CLK_DISABLE();  // 禁用GPIOA时钟
__HAL_RCC_SPI1_CLK_DISABLE();   // 禁用SPI1时钟

// 仅在需要时启用外设
void vReadSensor(void) {
    __HAL_RCC_I2C1_CLK_ENABLE();  // 启用I2C时钟
    // 读取传感器数据
    __HAL_RCC_I2C1_CLK_DISABLE(); // 读取完成后禁用时钟
}
▶ RTC 唤醒配置与 Standby 模式
C
// 配置RTC闹钟唤醒（每10秒唤醒一次）
RTC_TimeTypeDef sTime = {0};
RTC_DateTypeDef sDate = {0};
RTC_AlarmTypeDef sAlarm = {0};

sTime.Hours = 0;
sTime.Minutes = 0;
sTime.Seconds = 0;
HAL_RTC_SetTime(&hrtc, &sTime, RTC_FORMAT_BIN);

sDate.WeekDay = RTC_WEEKDAY_MONDAY;
sDate.Month = RTC_MONTH_JANUARY;
sDate.Date = 1;
sDate.Year = 0;
HAL_RTC_SetDate(&hrtc, &sDate, RTC_FORMAT_BIN);

sAlarm.AlarmTime = sTime;
sAlarm.Alarm = RTC_ALARM_A;
sAlarm.AlarmMask = RTC_ALARMMASK_DATEWEEKDAY | RTC_ALARMMASK_HOURS | RTC_ALARMMASK_MINUTES;
sAlarm.AlarmSubSecondMask = RTC_ALARMSUBSECONDMASK_ALL;
HAL_RTC_SetAlarm_IT(&hrtc, &sAlarm, RTC_FORMAT_BIN);

// 进入Standby模式
HAL_PWR_EnterSTANDBYMode();
⚠
进入 Standby 模式后，SRAM 内容将丢失，仅备份寄存器和 RTC 数据保留。在进入前需保存关键状态信息到备份寄存器中。

内存泄漏检测

🐛 静态检测工具
  • CppCheck：静态代码分析工具，检查内存分配与释放是否匹配。
  • Valgrind（需模拟器环境）：检测动态内存问题，如未释放的堆内存、越界访问等。
▶ 自定义内存管理钩子
C
// 记录内存分配/释放情况
void *pvPortMalloc( size_t xWantedSize ) {
    void *pvReturn = NULL;
    vTaskSuspendAll();
    {
        // 记录分配信息（如分配地址、大小、时间）
        pvReturn = prvHeapAllocateMemory( xWantedSize );
        vRecordMemoryAllocation(pvReturn, xWantedSize);
    }
    xTaskResumeAll();
    return pvReturn;
}

中断风暴处理

🚨
问题现象：CPU 占用率 100%，系统无响应。通常由某个 GPIO 引脚持续抖动导致中断反复触发引起。
🔍 排查步骤
调试器暂停 CPU
→
查看当前执行代码
→
检查中断触发条件
→
添加中断计数统计
→
定位问题 ISR
▶ 解决方案：软件消抖
C
static uint32_t ulLastInterruptTime = 0;
#define DEBOUNCE_TIME 50  // 50ms

void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin) {
    uint32_t ulCurrentTime = xTaskGetTickCount();
    if (ulCurrentTime - ulLastInterruptTime > DEBOUNCE_TIME) {
        // 处理有效中断
        vProcessButtonPress();
        ulLastInterruptTime = ulCurrentTime;
    }
}
🧠 测验 2：Cortex-M 的三种低功耗模式中，哪种模式功耗最低但唤醒时间最长？
  • A Sleep 模式
  • B Stop 模式
  • C Standby 模式
  • D Shutdown 模式
Standby 模式功耗仅几十 nA，但唤醒时间为几 ms，且 SRAM 内容会丢失，仅保留备份寄存器（如 RTC）。它适合电池供电且对唤醒延迟不敏感的场景。

💼 面试高频问题

Q1：JTAG 与 SWD 的优缺点？

JTAG：兼容性强，支持多设备级联，但占用引脚多；SWD：引脚少（仅 2 根），速度快，适合嵌入式设备。在 STM32 开发中通常优先选择 SWD。

Q2：如何优化 RTOS 系统的 CPU 使用率？
  • 减少空闲任务 CPU 占用（通过 configIDLE_SHOULD_YIELD 配置）。
  • 优化中断处理时间，避免长中断服务程序。
  • 使用低功耗模式，在空闲时进入 Sleep/Stop 状态。
  • 合理设置任务优先级和调度策略，减少不必要的上下文切换。
Q3：调试时发现程序跑飞，如何定位问题？
  • 设置看门狗定时器，捕获异常复位。
  • 使用硬件断点，检查关键函数是否被正确调用。
  • 添加断言（assert），验证关键条件。
  • 检查栈溢出：启用 FreeRTOS 的 configCHECK_FOR_STACK_OVERFLOW。
Q4：如何测量代码执行时间？
  • 使用高精度定时器（如 STM32 的 DWT_CYCCNT）。
  • SystemView 等工具通过 SWO 接口获取精确时间。
  • GPIO 翻转法：在代码段前后翻转 GPIO，用示波器测量脉冲宽度。
🧠 测验 3：以下哪个不是排查"程序跑飞"问题的常用方法？
  • A 设置看门狗定时器捕获异常复位
  • B 使用硬件断点检查函数调用
  • C 增大 Flash 容量
  • D 添加 assert 断言验证关键条件
增大 Flash 容量无法解决程序跑飞问题。跑飞通常由栈溢出、指针错误、中断异常等原因引起，需通过看门狗、断点、断言等调试手段定位根因。
