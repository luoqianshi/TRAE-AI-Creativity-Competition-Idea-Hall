第3章

驱动开发与外设编程

嵌入式驱动开发是连接硬件与上层应用的关键层，掌握寄存器操作、外设驱动编写及工具链使用是嵌入式工程师的核心技能。本章从底层原理到实践应用进行深度讲解。

🧠 寄存器级开发

地址映射与寄存器偏移

📌 总线架构

STM32 通过 AHB（高级高性能总线）连接高速外设，APB（高级外设总线）连接低速外设。

  • AHB 总线示例：GPIOA 位于 AHB1 总线，基地址 0x40020000
  • APB 总线示例：USART1 位于 APB2 总线，基地址 0x40011000
📌 寄存器偏移

每个外设包含多个寄存器，通过 基地址 + 偏移量 访问：

  • GPIOA_MODER（模式寄存器）偏移 0x00
  • GPIOA_ODR（输出数据寄存器）偏移 0x14

位操作技巧

原子操作宏

C 
#define SET_BIT(REG, BIT)     ((REG) |= (BIT))
#define CLEAR_BIT(REG, BIT)   ((REG) &= ~(BIT))
#define READ_BIT(REG, BIT)    ((REG) & (BIT))
#define TOGGLE_BIT(REG, BIT)  ((REG) ^= (BIT))

多位置位/清零

C 
// 同时设置PA5、PA6为输出（MODER[13:12]=01, MODER[11:10]=01）
GPIOA_MODER = (GPIOA_MODER & ~(0xF << 10)) | (0x5 << 10);
💡
位操作是嵌入式开发中最基础也最重要的技能。使用位掩码可以精确地修改寄存器中的特定位，而不影响其他位的状态。这在多任务环境中尤为重要，可以避免竞态条件。

🔌 通用外设驱动

GPIO（通用输入输出）

⚙️ GPIO 模式配置

输入模式：

  • 浮空输入 — 引脚电平完全由外部决定，内部无上拉/下拉
  • 上拉输入 — 内部连接上拉电阻，默认高电平
  • 下拉输入 — 内部连接下拉电阻，默认低电平
  • 模拟输入 — 用于 ADC 采样，关闭数字输入缓冲

输出模式：

  • 推挽输出 — 可输出高/低电平，驱动能力强
  • 开漏输出 — 只能拉低，需外部上拉电阻，适合线与逻辑

复用模式：用于 SPI、I2C 等外设功能，将引脚控制权交给外设控制器。

GPIO 中断配置步骤

1. 配置 GPIO 为输入模式
→
2. 配置 SYSCFG_EXTICR 选择中断源
→
3. 配置 EXTI 屏蔽与触发边沿
→
4. 在 NVIC 中使能并设优先级
C 
// 示例：配置PA0为上升沿触发中断
SYSCFG->EXTICR[0] &= ~SYSCFG_EXTICR1_EXTI0;  // 选择PA0
EXTI->IMR |= EXTI_IMR_IM0;                    // 使能中断线0
EXTI->RTSR |= EXTI_RTSR_TR0;                  // 上升沿触发
HAL_NVIC_SetPriority(EXTI0_IRQn, 0, 0);       // 设置中断优先级
HAL_NVIC_EnableIRQ(EXTI0_IRQn);               // 使能NVIC中断
⚠️
中断优先级数值越小，优先级越高。Cortex-M 内核支持优先级分组（抢占优先级 + 子优先级），同一抢占优先级内不会互相打断。

UART/USART（通用同步/异步收发器）

📡 波特率计算

波特率计算公式：

波特率 = 系统时钟 / (16 × USARTDIV)

示例：系统时钟 72MHz，目标波特率 115200，则：

USARTDIV = 72000000 / (16 × 115200) ≈ 39.0625

中断接收实现

C 
// 接收完成回调函数
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart) {
    if (huart->Instance == USART1) {
        // 处理接收到的数据
        process_data(rx_buffer, rx_length);
        // 重新开启接收中断
        HAL_UART_Receive_IT(&huart1, rx_buffer, 1);
    }
}
💡
在实际项目中，UART 常使用 DMA + 空闲中断（IDLE Interrupt）的方式接收不定长数据，避免逐字节中断带来的 CPU 开销。

SPI（串行外设接口）

🔄 SPI 模式配置
  • 时钟极性（CPOL）：0（空闲时 SCLK 为低）或 1（空闲时 SCLK 为高）
  • 时钟相位（CPHA）：0（第一个边沿采样）或 1（第二个边沿采样）
  • 数据位宽：8 位或 16 位
特性主模式（Master）从模式（Slave）
时钟控制控制 SCK 时钟，发起通信接收 SCK 时钟，被动响应
片选信号控制 NSS/CS 选择从设备被 CS 选中后响应
数据速率可配置分频系数由主设备决定
典型应用MCU 连接 Flash、传感器多 MCU 间通信

I2C（集成电路间总线）

🔗 I2C 寻址方式
  • 7 位地址：0x00 ~ 0x7F，其中 0x00 为广播地址
  • 10 位地址：扩展寻址，用于特殊设备，前 5 位为固定标识 11110
▶ I2C 多主竞争与仲裁机制

当多个主设备同时尝试控制 I2C 总线时，通过 SDA 线的电平检测 实现总线仲裁：

  • 每个主设备在发送数据时，同时监测 SDA 线的实际电平
  • 如果某主设备发送高电平，但检测到 SDA 为低电平，说明另一个主设备正在拉低总线
  • 先检测到 SDA 线被拉低的主设备退出竞争，释放总线控制权
  • 仲裁过程不会丢失已发送的数据，保证通信的完整性
📝
I2C 仲裁机制是基于"线与"逻辑（开漏输出 + 上拉电阻），因此低电平优先级高于高电平。这是 I2C 协议设计中的一个巧妙之处。

ADC（模拟-to-数字转换器）

📊 ADC 采样时间配置

采样时间越长，转换结果越精确，但转换速度越慢。STM32F4 的 ADC 采样时间可配置为：

3、15、28、56、84、112、144、480 个周期

多通道扫描模式

C 
// 配置ADC1扫描模式，采样通道0、1、2
hadc1.Instance = ADC1;
hadc1.Init.ScanConvMode = ENABLE;
hadc1.Init.ContinuousConvMode = DISABLE;
hadc1.Init.NbrOfConversion = 3;  // 3个转换通道

sConfig.Channel = ADC_CHANNEL_0;
sConfig.Rank = 1;
HAL_ADC_ConfigChannel(&hadc1, &sConfig);

sConfig.Channel = ADC_CHANNEL_1;
sConfig.Rank = 2;
HAL_ADC_ConfigChannel(&hadc1, &sConfig);

sConfig.Channel = ADC_CHANNEL_2;
sConfig.Rank = 3;
HAL_ADC_ConfigChannel(&hadc1, &sConfig);
💡
ADC 采样精度受多种因素影响：参考电压稳定性、采样时间、输入阻抗匹配、PCB 布线等。高精度应用中建议使用独立的电压参考源，并在 PCB 上对模拟地与数字地进行隔离。

🚀 复杂外设支持

DMA 控制器

⚡ DMA 通道选择

每个 DMA 控制器包含多个通道，不同外设对应不同通道：

  • USART1_RX 对应 DMA2 通道 5
  • USART1_TX 对应 DMA2 通道 4

双缓冲区模式

适合大数据量传输，一个缓冲区用于当前传输，另一个准备下一次传输：

C 
// 配置DMA双缓冲区模式
hdma_adc.Instance = DMA2_Stream0;
hdma_adc.Init.BufferSize = 2;  // 双缓冲区
hdma_adc.Init.Direction = DMA_PERIPH_TO_MEMORY;
hdma_adc.Init.PeriphInc = DMA_PINC_DISABLE;
hdma_adc.Init.MemInc = DMA_MINC_ENABLE;
// ...其他配置
📝
DMA 传输的核心优势是 零 CPU 开销：数据在内存和外设之间直接搬运，CPU 可以在此期间执行其他任务。传输完成后通过中断通知 CPU 处理结果。

看门狗（Watchdog）

特性独立看门狗（IWDG）窗口看门狗（WWDG）
时钟源专用低速时钟（LSI，约 32kHz）APB1 时钟
主时钟故障仍能工作无法工作
喂狗时间典型值 10ms ~ 16s必须在窗口范围内（上限值 ~ 下限值）

CAN（控制器局域网）

🚗 CAN 位时序配置

CAN 位时序由以下段组成：

  • 同步段（SYNC_SEG）：1 个时间量子
  • 传播时间段（PROP_SEG）：补偿信号传播延迟
  • 相位缓冲段 1（PHASE_SEG1）
  • 相位缓冲段 2（PHASE_SEG2）

示例：波特率 500kbps，系统时钟 42MHz

STM32CubeMX

▶ 时钟树配置详解

基于 PLL（锁相环） 生成系统时钟，需合理配置倍频系数和分频系数。

示例：配置系统时钟为 180MHz

HSE (8MHz) --> PLLM=8 --> VCO输入=1MHz --> PLLN=360 --> VCO输出=360MHz --> PLLP=2 --> 系统时钟=180MHz
📝
VCO 输入频率必须在 1~2MHz 范围内，VCO 输出频率有特定范围限制（如 STM32F4 为 100~432MHz）。配置时钟树时需查阅数据手册确认各参数的有效范围。
📦 中间件集成

STM32CubeMX 支持以下中间件一键配置：

  • FreeRTOS — 实时操作系统
  • LWIP — 轻量级 TCP/IP 协议栈
  • USB — USB 设备/主机/OTG 驱动
  • FatFS / File System — 文件系统支持

2. 中断处理优化

中断服务函数（ISR）应尽量简短，避免耗时操作。关键数据传递使用原子操作或关中断保护：

C 
// 示例：使用原子操作传递数据
volatile uint32_t g_flag __attribute__((aligned(4)));

void EXTI0_IRQHandler(void) {
    __disable_irq();
    g_flag = 1;  // 原子写操作
    __enable_irq();
    HAL_GPIO_EXTI_IRQHandler(GPIO_PIN_0);
}

💼 面试高频问题

Q1: HAL 与 LL 库的选择标准

快速开发选 HAL，性能敏感场景选 LL；需平衡开发效率与代码体积。HAL 封装了底层细节，降低了入门门槛；LL 更贴近寄存器，执行效率更高但需要深入理解硬件。

Q2: I2C 通信中 ACK/NACK 的作用

ACK（应答）：接收方正确接收到数据，发送低电平，表示可以继续传输。

NACK（非应答）：接收方无法继续接收，发送高电平，通常用于传输结束或设备忙。

Q3: ADC 采样时间对精度的影响

采样时间越长，对信号的积分效果越好，抗干扰能力越强，精度越高。但过长的采样时间会降低采样率，对于快速变化的信号可能产生失真。需要根据信号带宽和精度要求折中选择。

Q4: DMA 与 CPU 直接传输的优缺点

优点：释放 CPU 资源，实现高速数据传输，特别适合大数据量场景（如图像采集、ADC 连续采样）。

缺点：配置复杂，占用总线带宽，与 CPU 争用总线时可能影响 CPU 执行效率。

❓ 本章测验

1. 在 STM32 中，GPIO 的开漏输出模式有什么特点？
  • A可以输出高电平和低电平，驱动能力强
  • B只能拉低电平，需要外部上拉电阻才能输出高电平，适合线与逻辑
  • C只能输出高电平，用于电源供电场景
  • D内部集成上拉电阻，无需外部电路即可输出高电平
开漏输出（Open Drain）的 MOS 管只能将引脚拉低到 GND，无法主动输出高电平。需要通过外部上拉电阻连接到目标电压，这使得多个开漏输出可以共享一条总线（线与逻辑），I2C 通信就利用了这一特性。
2. 以下关于 SPI 和 I2C 总线的描述，哪项是正确的？
  • AI2C 的通信速率通常比 SPI 更快
  • BSPI 只需要两根线（SDA + SCL）即可完成通信
  • CSPI 是全双工通信，I2C 是半双工通信
  • DI2C 不需要地址寻址，SPI 需要地址寻址
SPI 使用 MOSI（主出从入）和 MISO（主入从出）两条独立数据线，支持全双工通信。I2C 仅使用一条 SDA 数据线（加上 SCL 时钟线），同一时刻只能单向传输，属于半双工。SPI 速率通常远高于 I2C（SPI 可达几十 MHz，I2C 标准模式仅 100kHz/400kHz）。
3. 使用 DMA 传输数据相比 CPU 直接传输，最大的优势是什么？
  • ADMA 传输不需要配置任何参数
  • BDMA 可以传输任意大小的数据，不受硬件限制
  • CDMA 可以在不占用 CPU 的情况下完成数据搬运，释放 CPU 执行其他任务
  • DDMA 传输速度比 CPU 慢但更稳定
DMA（直接内存访问）控制器的核心优势是数据搬运完全由硬件完成，无需 CPU 参与。CPU 只需配置好 DMA 通道、源地址、目标地址和传输大小，之后就可以执行其他任务。传输完成后通过中断通知 CPU 处理结果，极大提高了系统效率。
