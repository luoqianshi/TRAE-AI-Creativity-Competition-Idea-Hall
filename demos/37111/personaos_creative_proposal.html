少年多边形
PersonaOS

面向青少年的低熵自我组织系统

少年多边形 PersonaOS 是一款面向 13–18 岁青少年的 AI 自我组织系统，帮助他们从每日事件、情绪反应、学习状态、外界评价、生活环境和小作品中，逐步建立自己的多边形人格系统，并打造低熵生活与学习环境。

报名赛道：社会服务 附加方向：社会公益 / 青少年身心健康（如平台允许加选） 定位：不是诊断，而是自我组织 模式：Solo Mode + Safe Circle
13–18 核心目标用户是正在建立自我、但经常被外部评价打散的青少年。
7 轴 七条成长轴不是分数排名，而是持续被看见、被整理、被保存的能力证据。
0 监控 日常不监控，危机不陪聊，系统目标是帮助用户恢复自我组织，而不是延长停留。

30 秒看懂 PersonaOS

这是一个面向报名评审的快速理解区块，用最短路径说明 PersonaOS 究竟在解决什么、如何解决，以及它坚守哪些边界。

Quick View / 30 Seconds
把高熵拆成结构

它帮助青少年把高熵生活场景拆成可理解、可行动的结构，让混乱不再只能被感受，而可以被重新组织。

用七轴积累证据

它通过七轴星图积累自我证据，而不是给孩子贴人格标签，不把人成扁平化的分数或类型。

不监控，危机连现实

它不做家长监控；危机时停止陪聊，连接现实支持，把安全边界放在所有智能分析之前。

青少年为什么需要低熵自我组织系统

很多青少年并不是没有能力，而是长期被成绩、比较、父母期待、手机信息流、同伴关系和混乱环境打散。他们知道自己考了多少分，却很少知道自己真正擅长什么、会被什么反复吸引，又该如何从高熵状态里重新组织自己。

Pain / Context
被分数覆盖的自我认知

传统反馈只告诉孩子结果，不告诉孩子能力是怎样形成的，更不会帮他们保存成长证据。

被信息流打散的注意力

手机、群聊、桌面杂乱与任务堆积共同制造高熵，让行动启动变得越来越难。

被误解的兴趣与表达

短片、画画、写故事、小观察常被定义为“没用”，兴趣很难沉淀成自我证据。

被监控化的支持关系

不少工具把孩子变成被观察对象。PersonaOS 反过来，把青少年放回系统主人位置。

Scenarios / Click to Expand
Scene 01成绩 / 自责

考试后被成绩定义

考砸后被父母说“你就是不自律”，用户开始自责、回避与自我否定。

  • 识别高熵源：成绩打击、指责式评价、启动受阻。
  • 拆分外界评价：事实层是这次考试失利，压力层是父母焦虑，不应内化为“我就是差”。
  • 生成 10 分钟重启动作：关通知、收桌面、列 1 个最小复盘问题、保存 1 条努力证据。
Scene 02注意力 / 焦虑

手机信息流失控

本来想学习，却刷手机一小时，刷完更焦虑，行动阈值进一步提高。

  • 识别高熵源：信息流、拖延后羞耻感、学习入口过大。
  • 输出“低熵驾驶舱”：先断流 10 分钟，只保留计时器、纸笔和一个任务入口。
  • 保存自我证据：不是“今天又废了”，而是“我发现了自己会被什么触发失控”。
Scene 03兴趣 / 否定

兴趣被否定

想做短片、画画或写故事，却被说“这些没用”，兴趣逐渐失去正当性。

  • 作品种子库接住零散表达，把它转成表达轴与审美轴的能力证据。
  • 系统不争辩“有没有用”，而是记录观察力、叙事力、持续性等可迁移能力。
  • 支持者端只收到低冲突建议，不会看到孩子未分享的创作内容。
Scene 04关系 / 内耗

同伴关系内耗

群聊没人回复自己，就开始怀疑是不是自己不被喜欢。

  • 识别关系轴波动，不把沉默自动解释成“我不值得被喜欢”。
  • 系统提供关系边界提示，帮助用户区分事实、猜测和旧创伤投射。
  • 如果需要分享，只推荐低冲突表达，不制造关系依赖。
Scene 05空间 / 堆积

房间和书桌混乱

桌面杂乱、任务堆积、启动困难，用户迟迟无法进入学习状态。

  • 秩序轴与身体轴联动识别：空间高熵会直接抬高启动门槛。
  • 先做 10 分钟环境重启，不要求完美收纳，只重建“可开始”的界面。
  • 保存证据：今天我不是把一切做完，而是把系统从混乱拉回可执行状态。
Scene 06家庭 / 低支持

守旧单亲家庭

父母不愿使用支持端，甚至把心理工具说成“矫情”，系统仍需可独立运行。

  • PersonaOS 提供 Solo Mode，家庭支持是加分项，而不是生存条件。
  • 支持网络可以扩展到老师、亲戚、学校心理老师或其他可信成年人。
  • 孩子拥有记录权、分享权与撤回权，不以家长参与为前提。
Scene 07风险 / 边界

危机场景

当出现想自残、想伤害自己、不想活等风险信号，系统必须停止普通分析，切换安全优先模式。

  • 系统不再做人格分析、情绪复盘或关系建议，先保障现实世界中的安全。
  • 立即引导用户去有人的地方，联系可信成年人、学校心理老师、专业人员或当地紧急救助。
  • 向支持者只发送最小必要提醒，不暴露孩子原文全文。

多边形人格七轴

七轴不是标签，不是排名，也不是一张定型的人格报告。它更像成长轨道系统，持续记录用户如何从具体生活片段中长出自己的学习方式、表达方式、关系边界与低熵能力。

核心功能模块

点击模块展开说明。所有功能都围绕一个方向设计：让用户从生活碎片里建立自我证据，而不是被产品持续管理。

Modules / 9 Capabilities
Module 01Record

每日自我证据

记录今天发生的事、情绪、外界评价、高熵源和一个值得保留的成长证据。

  • 不是传统情绪日记，而是把事件、感受、环境和证据连接成可回看的成长条目。
  • 支持孩子拥有私密记录权、选择分享权与撤回权。
Module 02Star Map

多边形人格星图

从连续记录中识别七轴成长痕迹，展示多维能力如何在生活中逐渐出现。

  • 不输出分数排名，只保留成长轨迹、触发模式和能力证据。
  • 帮助青少年看到“我不是单一成绩维度的人”。
Module 03Cabin

低熵驾驶舱

当任务堆积、手机失控、房间混乱或学习启动困难时，生成 10 分钟重启方案。

  • 把“开始不了”拆成环境、注意力、身体状态和任务界面四个层次。
  • 行动目标不是完美，而是把系统拉回可执行状态。
Module 04Filter

外界评价过滤器

把伤人的评价拆成事实层、压力层和不应内化的自我定义。

  • 帮助用户在父母焦虑、老师批评、同伴反应中保留判断力。
  • 系统反对把外界情绪直接变成自我身份。
Module 05Seeds

作品种子库

把小作品、小观察、小灵感沉淀成能力证据，而不是让兴趣被简单否定。

  • 支持保存短片构思、片段文字、草图、主题联想等微型成果。
  • 把兴趣从“没用”重新命名为可迁移能力的起点。
Module 06Solo

Solo Mode 独立模式

父母暂时不可用、不理解或不愿使用支持端时，孩子端仍可独立运行。

  • 家庭支持是加分项，不是系统前提，也不是生存条件。
  • 避免让低支持家庭中的孩子被二次排除。
Module 07Support

Safe Circle 安全支持网络

支持者不一定是父母，也可以是老师、亲戚、学校心理老师或其他可信成年人。

  • 系统允许构建多节点支持，而不是把全部安全押在单一家庭关系上。
  • 危机状态下采用最小必要披露原则。
Module 08Translate

高熵语言翻译器

帮助支持者把比较、指责、控制式表达转化为低冲突支持性表达。

  • 支持者看到的不是“监控数据”，而是更好的沟通方式。
  • 目标是降低关系摩擦，保护孩子主体感。
Module 09Safety

危机边界协议

一旦出现自伤、轻生等风险表达，系统停止普通分析，切换安全优先模式。

  • 不继续陪聊，不提供一般情绪复盘，不输出普通任务推荐。
  • 马上引导现实求助，连接可信成年人、专业人员或当地紧急救助。

安全优先模式

当用户输入中出现“想死”“不想活了”“想自杀”“想自残”“想伤害自己”“活着没意思”“早恋分手后想结束生命”“抑郁到想伤害自己”“已经准备伤害自己”“今晚就结束”等风险表达时，系统必须停止普通分析，进入安全优先模式。

Crisis Boundary Protocol

触发风险表达

想死 / 不想活了 / 想自杀 / 今晚就结束
想自残 / 想伤害自己 / 已经准备伤害自己
活着没意思 / 抑郁到想伤害自己
早恋分手后想结束生命等情境性轻生表达

系统必须停止

1. 多边形人格分析
2. 关系建议
3. 情绪复盘
4. 低熵任务推荐
5. 作品种子分析

系统必须输出

1. 情绪承接：先回应痛苦真实存在。
2. 明确边界：这已超出普通自助范围。
3. 立即行动：不要独处，去有人的地方。
4. 现实求助：联系可信成年人、家长、老师、学校心理老师、专业人员或当地紧急救助。
5. 提供一键求助文案。
6. 启动最小隐私原则，只发送必要风险提醒。
一键求助文案示例：
“我现在状态很不好，可能有伤害自己的风险。我不适合一个人待着，请你现在陪我一下，并帮我联系可以马上提供现实帮助的人。”

最小隐私原则：不把孩子原文展示给支持者，只发送“当前可能存在自我伤害风险，需要立即陪伴和确认安全”的最小必要提醒。

如果用户已经处于即时危险、已经准备伤害自己或无法保证安全，应立即联系当地急救、报警、急诊或身边可信成年人。Demo 阶段不伪造具体热线，后续根据地区进行本地化配置。

支持者端 / Safe Circle 原则

支持者端不是家长监控后台，而是低冲突支持界面。系统默认保护青少年的记录边界，日常状态不监控，危机状态只做最小必要披露。

Supporters / Not Surveillance
支持者端不是监控后台

支持者不能查看孩子完整日记、恋爱内容、情绪原文、具体冲突或未分享作品。

只看低分辨率趋势

可见范围限于环境支持建议、低冲突沟通建议，以及孩子主动分享的成长卡片。

日常不监控，危机最小披露

危机状态下只提示“需要立即陪伴和确认安全”，不转发孩子原始表达全文。

支持者可以不是父母

Safe Circle 可包括父母、老师、亲戚、学校心理老师或其他可信成年人。

家庭支持是加分项

父母暂时不愿使用支持端时，孩子端仍可通过 Solo Mode 独立运行，不被系统排除。

高熵语言翻译器

把“你就是不自律”“别矫情”这类高压表达，翻译为更低冲突、更能承接的支持语言。

技术实现与初赛 Demo

初赛阶段以手机端优先的 Web App Demo 形式实现，重点展示一个闭环：从高熵输入，到结构化分析，到 10 分钟低熵行动，再到自我证据沉淀与星图更新。

TRAE Work + TRAE IDE
前端 React + Vite，构建手机端优先的深色未来感界面，包含星图、多边形雷达、低熵驾驶舱与卡片式日志。
数据 使用 localStorage 保存用户记录，确保初赛阶段低成本完成本地可运行闭环。
AI 分析 先采用 Mock AI 分析逻辑与结构化 Prompt，验证场景识别、输出结构与安全边界，再逐步替换为真实模型接口。
后续 未来可接入真实大模型 API，并建立高熵场景引擎、策略库和安全评测库。

初赛阶段安全声明

初赛阶段仅作为交互原型与安全边界演示，不采集真实未成年人隐私数据，不做心理诊断、治疗建议或真实危机通知。所有危机通知、Safe Circle、场景引擎功能均为 Demo 级模拟。后续若产品化，需要经过心理、教育、隐私与合规专家审核。

High-Entropy Scenario Engine 高熵场景引擎

PersonaOS 后续会建立受控自演化系统，但不是让 AI 自由学习青少年的痛苦，而是在权威知识底座、安全评测集、人工审核和版本控制下，进行证据闸门式演化。

Controlled Evolution
1. 权威知识底座

以公开权威体系建立安全边界、风险分级与产品评测基线。

2. AI 生成高熵场景

生成代表性、可评估的高熵案例，而不是直接学习真实青少年隐私文本。

3. AI 生成降熵方案

针对场景输出候选的低熵行动、支持建议与边界响应。

4. 多评审器自检

对安全性、可执行性、依赖性、误导风险进行多维自检。

5. 人工审核

关键策略必须经过人工审核，不让模型未经审查直接演化上线。

6. 入库

进入演示案例库、响应策略库与安全评测库，形成可追踪版本。

7. 匿名反馈

只收集匿名反馈与效果缺口，不收集不必要的私密全文。

8. 缺口发现

识别误判点、盲区与低效建议，明确下一轮补强方向。

9. 下一轮受控演化

在版本控制与安全门槛内进行迭代，确保每次演化都有证据与边界。

更准确识别高熵场景，更少误判危机风险。
更少制造 AI 依赖，更少暴露青少年隐私。
更能给出可执行低熵行动，更能保护主体性。

PersonaOS 不以“诊断谁有问题”为核心目标，而以“如何建立安全、克制、可追责的青少年自我组织产品”为目标。权威知识的作用是定义什么必须克制、什么必须升级、什么必须转介，而不是让系统越界扮演治疗者。这些权威体系目前作为产品建模参考与安全边界来源，后续将逐条核验和结构化为知识卡；它们不用于让产品进行诊断或治疗。

产品铁律

PersonaOS 的底层原则不是“更会聊”，而是“更少越界、更少依赖、更快帮助用户恢复自我组织能力”。

Product Principles
1. 日常不监控

系统默认尊重青少年的私密记录权，不将日常状态暴露给支持者端。

2. 危机不陪聊

一旦出现自伤、轻生等风险表达，立即切换安全优先模式并连接现实帮助。

3. 求助不暴露隐私全文

危机提醒采用最小必要披露，不转发孩子全部原始文本。

4. 家庭支持是加分项

不是生存条件。父母暂时不可用时，系统仍应保障孩子能独立运行。

5. 青少年是系统主人

他们不是被观察对象，不是被评分对象，而是自我组织系统的拥有者。

6. AI 不以延长停留为目标

AI 的目标是更快帮助用户恢复自我组织能力，并在必要时连接现实帮助。

7. 演化必须在证据与边界内

PersonaOS 可以演化，但只能在证据闸门、安全评测与人工审核的边界内演化。

核心理念总括

不是心理诊断，而是自我组织；不是人格标签，而是自我证据；不是家长监控，而是低熵支持。

“青少年不是被观察对象，而是系统的主人。
