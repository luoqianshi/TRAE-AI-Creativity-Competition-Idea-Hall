智识图文

零样本非标票据理解与自沉淀模板飞轮

TRAE AI 创造力大赛 学习工作赛道 开源 OCR 识别中台

一、创意介绍

想解决什么问题

报销场景中，发票有国标、大厂 OCR 能识别，但住宿水单、银行回单等"非标票据"格式碎片化、版式无限，只能靠人工录入，又慢又容易错。我们需要一款能"第一次就读懂任意格式水单，还能自己记住版式"的 AI 识别工具。

为什么会想到做这个

最近在做自动填报销单的需求，发现第三方发票识别只能解决"发票"这一部分，住宿费报销还必须上传住宿水单——入住时间、房间号、明细金额全在水单上。这部分没有国标、没有标准接口，员工只能手填，财务得逐单核对。市场上大厂不爱做这种苦活，但企业的真实痛点就在这里。

大概是什么产品

一款开源的 AI 图片识别中台，支持网页端直用、浏览器插件嵌入、API / 私有化部署，专攻大厂不做的非标票据识别。

二、目标用户及痛点

面向哪些用户

企业财务/行政/HR、有 OCR 集成需求的开发者、重视数据隐私的中小型企业。

在什么场景下使用

差旅报销（发票+水单）、财务审核批量录入、办公自动化（合同/身份证/名片），以及任何"图片提取文字并结构化"的场景。

当前痛点

  • 大厂 OCR 只管"标准票"：发票有国标，识别成熟；但水单、回单版式无限，大厂标准化 API 不划算、覆盖差；
  • 人工录入又慢又错：财务人员日均处理数十张票据，手误导致金额、日期填错，引发审批退回或合规风险；
  • 隐私顾虑阻碍使用：票据含姓名、税号、消费明细等敏感信息，用户不敢轻易上传到第三方黑盒服务；
  • 系统对接成本高：现有 OCR 输出格式不统一，下游解析开发量大。

三、价值与意义

效率提升

把"几分钟录一张"变成"秒级出结果"。更关键的是"一句话代执行"——员工告诉 AI "帮我填这张报销单"，系统自动识别发票+水单、提取字段、生成完整单据，人只需复核确认就能提交。

商业价值

走 Open Core 路线：识别引擎开源建立信任与开发者生态，增值服务（云 API、私有化部署、合规审计）收费。产品定位是"识别中台"——不抢钉钉/飞书/金蝶的位置，而是让它们来调用你，成为被集成的基础设施。水单识别是苦活、模板要长期养，大厂算过账不卷，正好是创业公司的护城河。

四、技术架构与创新点

三层识别架构

  • OCR 底座：传统 OCR + 版面检测，提取文字块与坐标（兼容表格/流水/中英文混排）；
  • 语义归一化层：LLM 做字段映射，将"房费/住宿费/客房消费"统一归一化到标准 schema；
  • 模板沉淀层：确认过的识别结果自动聚类为可复用模板，同版式直接走规则秒出，LLM 只兜底长尾 20%。

端云混合策略

模式 A：隐私优先

纯端侧识别，图片不出设备，接受略低准确率，靠人工复核兜底。

模式 B：效果优先

端侧做检测/矫正/去模糊，处理后的图送服务端精修，识别完即删。

端侧与服务端使用同一模型的不同规模版本，行为一致，精度按需取舍。

核心创造力：零样本非标票据理解 + 自沉淀模板飞轮。不训练专用模型，靠 schema + 同义词 + 版面理解，让任意新格式水单第一次上传就能被正确读懂，还自动记住版式。这同时是 AI 创造力（大模型理解非结构化长尾文档）和商业壁垒（越用越准）。

五、产品落地路径

六、成功标准与止损线

验证成功（Go）

  • 发票准确率 ≥ 98%，水单 ≥ 90%
  • 30 天内 ≥ 200 真实用户，次月留存 ≥ 20%
  • ≥ 3 家企业/开发者询问 API
  • 单张推理成本可控

止损放弃（No-Go）

  • 金额准确率死活 < 95%
  • 上线 2-3 个月用户 < 50
  • 大厂顺手补齐水单识别
  • 单位经济永远亏损
上传任何格式的水单，第一次就能读懂，还会自己记住版式——并且，你的票据数据可以永远不出设备。
