💡 创意介绍

想解决什么问题：经典 Game Boy 掌机正在老去——屏幕老化、按键失灵、硬件不可逆地衰退，而纯软件模拟器又缺少真实硬件的质感和零延迟的响应。

为什么会想到做这个：作为一个在 Game Boy 陪伴下长大的人，我深知那种按下按键瞬间响应、4 色绿屏上像素跳动的独特体验，是任何软件模拟器都无法复现的。FPGA 提供了在硬件层面精确还原芯片行为的能力——不是"模拟"，而是"重建"。我希望用现代低成本 FPGA 开发板，让每个人都能拥有一台永不老化的 Game Boy。

大概是什么产品：基于 Tang Nano 20K（售价约 180 元）FPGA 开发板的 Game Boy / Game Boy Color 硬件级复刻系统，通过 HDMI 输出至电视/显示器，支持 DS2 手柄操控，板载 I2S 功放输出原汁原味的 4 通道芯片音乐。

🎯 目标用户及痛点

面向哪些用户：复古游戏爱好者、FPGA/数字电路学习者、硬件创客/Maker、怀旧玩家群体。

在什么场景下使用：

  • 连接电视/显示器，用 DS2 手柄畅玩经典 GB/GBC 游戏
  • FPGA 学习者研究 CPU/PPU/APU 的硬件实现原理
  • 创客基于开源代码二次开发，添加新功能或移植到其他平台
  • 怀旧玩家用现代硬件重温童年经典，无需担心老机器故障

当前痛点：

原机老化不可逆

30 年前的 Game Boy 屏幕发黄、排线老化、按键导电橡胶失效，维修零件越来越少。

软件模拟器缺质感

软件模拟存在输入延迟、时序不精确、音频失真等问题，无法还原真实硬件手感。

FPGA 方案门槛高

现有 FPGA Game Boy 项目需要昂贵开发板（数百美元），普通爱好者难以入门。

学习资料分散

Game Boy 硬件架构资料散落各处，缺少一个完整、可运行、可修改的开源参考实现。

🛠️ 技术方案

GBCandy Nano 采用纯硬件描述语言（Verilog）实现 Game Boy 的全部核心芯片功能，运行在 Gowin GW2AR-18 FPGA 上：

LR35902 CPU PPU 像素处理 APU 4通道音频 Timer/DIV MBC1/3/5 HDMI 720p I2S 音频 SDRAM DS2 手柄 CGB 彩色模式
核心架构：CPU/PPU 运行在 21.6MHz（通过 CE 门控至 4.19MHz），SDRAM 控制器运行在 86MHz，HDMI 输出 74.25MHz。三时钟域协同工作，精确还原 Game Boy 的每一个时钟周期。

🤖 为什么用 TRAE 开发

FPGA 开发中调试是最耗时的环节。GBCandy Nano 项目中，APU Length Counter 的一个 NR52 寄存器格式错误（bits[6:4] 填充了调试数据而非 0），导致了 10 轮构建-烧录-测试循环才定位到根因。

TRAE 的价值：在 FPGA 开发中，TRAE 可以帮助快速分析波形数据、比对参考实现差异、生成调试代码、追踪信号路径。将"10 轮构建"的调试周期缩短到 1-2 轮，大幅提升硬件开发效率。

本项目的 APU 调试记录、PPU 时序对齐、Gowin 原语踩坑经验等，都是在 TRAE 辅助下完成的。TRAE 让硬件调试从"盲人摸象"变成了"有据可查"。
