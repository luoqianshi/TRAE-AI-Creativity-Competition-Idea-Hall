项目概述

光语的愿景：打造视障人士的"世界操作系统"——用大模型理解视觉世界，通过语音与空间提示音把环境信息"翻译"给视障人士，帮助他们更自主、高效地感知环境并操作身边物品。

比赛阶段聚焦：受比赛时间限制，我们先从最刚需、最高频的第一个场景——找东西——开始验证核心能力，后续逐步扩展更多场景，搭建完整的"光的语言"体系。

第一个场景：找东西

视障人士每天面临一个高频且痛苦的场景：找东西。药掉在地上、遥控器不知道放哪了、手机不知道搁在桌角还是沙发——这些对普通人几秒钟的事，对视障人士可能要摸索十几分钟。

光语通过智能眼镜获取环境画面；在设备能够开放同步双路视频并完成标定的前提下，利用双目立体视觉估算深度。系统实时追踪用户手部位置，计算手与目标物体的相对方向和距离，再通过眼镜左右开放式扬声器播放双声道空间提示音，引导用户把手伸向目标。

核心是空间深度感知 + 手部追踪 + 空间音频引导的完整算法链路，让视障人士不用看，就能更快"摸到"想要的东西。

核心问题：视障人士的"找东西"困境

情境痛点
药掉地上蹲下摸索，可能踩到或扫远
遥控器不见了翻遍沙发靠垫，耗时耗力
桌上的水杯伸手可能打翻
掉落的钥匙听到声音但定位不准，摸不到

传统方案（盲杖、导盲犬）无法解决"桌面/地面找小物体"的问题。现有 AI 眼镜多以间歇式语音描述为主（如"药在你左边"），但自然语言很难在不反复打断用户的情况下连续反馈手部偏差——"左边"是左多少？手正在靠近还是偏离？

光语要解决的就是这最后一公里：从"大概在那边"到"手精准拿到"。

1. 双目立体视觉获取深度

双摄像头不等同于可直接使用的双目深度系统。只有在两颗相机具备重叠视场、同步取流能力，并可完成内外参标定时，才能进行可靠的立体匹配。Demo 阶段优先使用已标定的外接双目相机验证；真机阶段再根据眼镜 SDK 能力迁移。

步骤说明
立体匹配左右画面计算视差图（SGBM / PSMNet / CRE-Stereo）
深度计算depth = focal × baseline / disparity，获得具有物理尺度的深度估计
使用前提双路视频同步、视场重叠、标定参数可用、SDK 支持实时取流
验证重点基线长度、近距离视差精度和手臂范围内的有效测距区间

2. 手部追踪

能力实现
手部检测MediaPipe Hands（实时，21个关键点）
手部3D坐标关键点深度从深度图读取，得到手部空间位置
追踪稳定性多帧平滑滤波，避免抖动

3. 目标物体检测

能力实现
物体检测YOLOv8（快速检测）或 千问 VL（语义理解）
用户说"找药"千问 VL 理解"药"是什么，在画面中定位
物体3D坐标从深度图读取对应位置深度
泛化能力不需要物体3D模型，优先支持常见、外观特征明确的物体

4. 双声道空间音频引导算法

核心：计算手 → 目标的方向向量和距离，将误差编码为左右声像、音高和提示音节奏。初赛使用普通双声道实时控制即可，后续再评估 HRTF 双耳渲染和头部追踪。

手相对目标的位置空间音频反馈
手在目标左侧右声道播放短促提示音，引导手向右移动
手在目标右侧左声道播放短促提示音，引导手向左移动
手在目标上方播放由高到低的提示音，引导手向下移动
手在目标下方播放由低到高的提示音，引导手向上移动
前后距离偏差较大用简短语音提示"向前"或"收回"，避免简单双声道产生前后混淆
接近目标（<5cm）左右同时快速提示
到达目标播放一次明确的成功音，并提示"可以抓取"

设计原则：

  • 左右声像 = 水平方向
  • 音高变化 = 上下方向
  • 提示节奏 = 距离（越近越快）
  • 前后方向优先使用简短语音，减少听觉歧义
  • 使用开放式扬声器、短促低音量提示，并支持一键暂停，尽量减少对环境声判断的干扰
  • 空间音频效果须通过视障用户测试验证；对听力受限用户保留外接手环等替代反馈通道

      ↓
用户拿到药

竞品分析

目前主流消费级视障辅助眼镜多以语音识别和场景描述为主；学术界已出现触觉或空间音频辅助抓取物体的研究原型，但尚未形成普及的日常消费产品。光语尝试将开放词汇目标理解、第一视角手部追踪与眼镜自带双扬声器整合为免手持闭环。

产品/方案做法与光语的差异
Sunu Band（声呐手环）距离障碍物越近震动越快主要用于障碍感知，不能语义搜索特定物体
微软 Soundscape3D 音频导航用声音占用听觉；适合室外导航不适合找东西
OrCam读取文字、识别人脸只做识别不做引导；纯语音反馈
Envision Glasses场景描述、物体识别只语音描述"物体在你左边"，无法精细引导手部
触觉/空间音频找物研究原型用腕带、手套或双耳音频引导手部验证了方向反馈的可行性，但通常需要额外穿戴或专用设备

光语的差异化：

  1. 可验证的空间深度方案：先用标定双目完成 Demo，再根据眼镜硬件能力迁移
  2. 视觉追踪手部 + 空间音频形成连续闭环
  3. 复用眼镜左右开放式扬声器，无需额外震动马达或手部穿戴设备
  4. 大模型理解目标物体（使用自然语言搜索常见物品，不局限于固定指令词）

技术实现方案

技术栈：

  • 深度感知：双目立体匹配（SGBM / PSMNet）
  • 手部追踪：MediaPipe Hands
  • 物体检测：YOLOv8 + 千问 VL（语义理解）
  • 语音：通义千问 ASR + TTS
  • 音频反馈：双声道声像控制 + 提示音节奏/音高编码；后续评估 HRTF 双耳渲染
  • 开发工具：TRAE IDE

硬件选型思考

本项目优先选择可开放相机画面和左右音频通道的智能眼镜。深度感知不默认绑定眼镜双摄：概念验证阶段使用已标定双目相机，真机阶段再确认设备能否提供同步双路视频、标定参数和实时取流能力。

概念验证阶段：千问 G1

千问 G1 硬件能力对视障场景的价值
双摄像头 + 1200 万像素具备潜在双目条件，但需确认同步、视场重叠、标定与 SDK 取流能力
无屏、约 40g 超轻全天佩戴无负担
麦克风阵列 + 开放式音频支持语音交互，并有机会通过左右声道输出方向提示
镜腿触摸板物理快捷操作入口
双电池热插拔外出可换电
通义千问多模态大模型理解"药"是什么，语义搜索目标物体

当前限制：需确认第三方 SDK、同步双路视频、左右声道独立控制和低延迟音频播放能力。在这些条件未确认前，不将千问 G1 作为双目深度能力已经成立的依据。

音频引导在 Demo 阶段可先用普通立体声耳机验证算法，但正式体验优先使用开放式扬声器或骨传导设备，避免遮挡环境声。耳机仅用于受控环境演示。

创新亮点

  1. 空间深度感知 + 手部追踪 + 音频闭环：不止描述物体位置，还持续计算手与目标的相对偏差
  2. 双声道提示音编码：左右声像表示水平方向，音高表示上下方向，节奏表示距离，到达时播放成功音
  3. 大模型语义搜索：用户可以自然表达要找的常见物品，不局限于预设指令词
  4. 复用现有眼镜硬件：优先利用常见的左右开放式扬声器，降低对定制震动马达的依赖；同时以短促、低音量和可暂停设计减少对环境听觉的占用
  5. 聚焦单一场景：受比赛时间限制，先把"找东西"这一个痛点做到极致，后续逐步搭建完整的光的语言体系
