WHY — 为什么做这个
三大核心痛点
🔒
隐私顾虑
使用云端 AI 时数据上传服务器，敏感文档、个人代码、商业信息面临泄露风险。很多人因此不敢用 AI 处理真正重要的事。
🤯
模型选择困难
面对代码模型、问答模型、视觉模型等众多选项，普通用户不知道哪个最合适。手动切换模型低效且易错。
💰
成本控制问题
云端 API 按量计费，频繁调用成本高。本地模型免费但功能单一。用户需要一种兼顾成本与能力的方案。
HOW — 怎么解决
三大核心方案
🏠
本地优先架构
所有数据处理在本机完成，基于 Ollama 本地推理引擎运行。数据不出电脑，无需网络连接即可使用。云端模型仅作为可选兜底，由用户自主决定何时启用。
🧠
多模型智能路由
Router 轻量模型常驻分析任务特征，通过硬规则匹配 + LLM 路由决策双重机制，自动将任务分配给最适合的专业模型执行。用户无需了解模型差异，一句话搞定。
⚡
ReAct 工具调用循环
Agent 采用 ReAct（Reasoning + Acting）模式执行任务：思考 → 行动 → 观察 → 再思考。支持文件读写、计算、命令执行等工具，内置危险命令拦截保障安全。最大 12 步迭代，逐步完成复杂任务。
🖥️
桌面原生应用
Tauri 2.0 + Vue 3 构建原生桌面 GUI，安装包仅 20-30MB，启动秒开。深色科技风界面，ChatGPT 式对话布局，支持历史记录和多轮对话上下文。同时提供 CLI 和 HTTP API 两种交互方式。

FEATURES — 核心功能
四大核心功能演示
01
多模型智能路由
Router 自动分析任务特征，将不同类型任务分配给最适合的专业模型。硬规则 + LLM 双重决策机制，确保路由准确高效。
# 代码任务 → 自动路由到 Coder $ python agent_runner.py "帮我写一个快速排序" [Router] → coder | 代码生成任务 [Coder] action=write_file | /tmp/quicksort.py ✓ 已生成带注释的快排函数 # 问答任务 → 自动路由到 General $ python agent_runner.py "解释什么是 RAG" [Router] → general | 通用问答 ✓ RAG = 检索增强生成，先查再答...
02
ReAct 工具调用循环
Agent 支持文件读写、时间获取、数学计算、命令执行等工具调用。ReAct 模式逐步推理和行动，最大 12 步迭代完成复杂任务。
$ python agent_runner.py "获取时间并写入文件" Step 1: [general] action=get_time → 2026-07-12 16:30:00 Step 2: [general] action=write_file | /tmp/time.txt|... → 文件已写入 Step 3: [general] action=final_answer ✓ 已获取时间并写入 /tmp/time.txt
03
桌面原生 GUI
Tauri + Vue 3 构建科技风原生桌面应用，安装包仅 20-30MB，支持深色主题、历史记录、多轮对话上下文。一键启动脚本同时运行后端和前端。
$ python start_gui.py [1/4] Ollama 状态检测 ✓ [2/4] 端口检测 ✓ [3/4] 依赖安装 ✓ [4/4] 启动服务... ✓ API: http://localhost:5000 ✓ GUI: Tauri 窗口已打开
04
三种交互方式
CLI 命令行适合开发者快速调用；HTTP API（Flask）提供 5 个 REST 接口支持第三方集成；Tauri GUI 适合普通用户使用。一套后端，三种入口。
# CLI 单次执行 $ python agent_runner.py "写一个二分查找" # HTTP API 调用 $ curl -X POST http://localhost:5000/api/agent/run \ -d '{"query": "现在几点？"}' → {"response": "当前时间 2026-07-12 16:30"} # 查看模型列表 $ curl http://localhost:5000/api/agent/models
INTERACTION — 交互方式
一套后端，三种入口
⌨️
CLI 命令行
开发者首选，一条命令完成任务。支持交互模式、单次执行、安静模式、图片输入。查看模型配置、路由统计、历史记录。

🖥️
Tauri 桌面 GUI
科技风原生桌面应用，ChatGPT 式对话布局。深色渐变背景 + 发光效果 + 网格纹理。支持历史记录和多轮对话上下文。

CHALLENGES — 技术难点与解决方案
开发中遇到的关键挑战
C1
Router 路由准确性
3b 小模型做路由决策偶尔不准。解决方案：采用硬规则 + LLM 路由决策双重机制。关键词匹配快速路由常见任务，Router 模型分析处理模糊边界。历史记忆学习成功模式优化后续路由。
C2
工具调用安全性
shell 工具可能执行危险命令（rm -rf、mkfs 等）。解决方案：内置危险命令黑名单拦截机制。calculate 工具使用安全解析器而非 eval()。所有工具执行结果回传模型继续推理，而非直接暴露给用户。
C3
Tauri 编译环境
Windows 编译 Tauri 需要 MSVC linker 和 Rust 环境。解决方案：安装 Visual Studio Build Tools，配置 Rust GNU toolchain。优化 start_gui.py 脚本自动检测端口、依赖、Ollama 状态。
C4
显存管理
RTX 3060 仅 6GB 显存，多个大模型无法同时加载。解决方案：Router 常驻 + 执行模型按需加载。Ollama 自动换入换出管理显存。coder 14b 使用量化版本降低占用。
