一项目概述

一句话描述

一个基于AI的古籍智能解读平台，支持任意古籍文本的白话翻译、背景知识补充和可视化呈现，让古籍"活"起来，让普通人也能读懂古文。

核心价值对比

对比维度 传统古籍阅读方式 本平台
门槛需要专业古文功底AI自动翻译，零门槛
效率逐字查字典、查注释一键获取翻译+背景+可视化
趣味性纯文字，枯燥可视化关系图、时间线
数据来源固定书籍开放古籍库 + 用户上传
传播性难以分享适合社交传播的可视化内容

社会价值

  • 降低古籍阅读门槛：让不懂古文的普通人也能理解古籍内容
  • 促进古籍活化传播：通过可视化让古籍内容更生动、更易传播
  • 开放平台生态：支持用户上传古籍，人人都是古籍传播者

二目标用户

  • 学生群体：语文学习、古文课辅助理解
  • 传统文化爱好者：日常阅读古籍、探索历史知识
  • 内容创作者：需要古籍素材用于文章、视频创作
  • 普通大众：对古籍感兴趣但古文基础薄弱的人

三核心功能

3.1 古文智能翻译（基础能力）

用户输入一段古文（手动输入/粘贴/从古籍库选择），系统返回逐字注释 + 整段白话翻译 + 生僻字词解释。

技术实现：调用大模型 API，使用专门设计的古文翻译 Prompt。对经典古籍内置参考注释，AI翻译后进行交叉校验。

3.2 背景知识补充（核心亮点）

AI自动识别古文中的人物、事件、典故、地名，关联展示人物简介、历史背景、典故出处、朝代信息，以卡片形式展示。

技术实现：使用大模型进行实体抽取（NER），建立本地知识库（历史人物表、朝代表、典故表），AI抽取后查询匹配。

3.3 可视化呈现（简单版）

可视化类型说明
人物关系图自动识别文中人物，展示人物之间的关系（父子、君臣、师徒等）
时间线按朝代/时间排列文中涉及的历史事件
知识卡片将关键信息生成可分享的图片卡片

3.4 古籍库（数据基础）

  • 内置部分经典古籍全文（《论语》《道德经》《孙子兵法》《史记》选段等）
  • 接入外部古籍 API（如 ctext.org 开放接口）获取更多内容
  • 用户可上传自定义古籍文本，AI自动解读

4.3 核心流程

1用户输入/选择一段古文
2Gateway 接收请求，创建解读任务
3AI解读服务调用大模型，同步执行三个任务：逐字翻译、实体抽取、背景知识生成
4实体抽取结果发送给知识库服务，查询本地已有数据
5本地已有数据 + AI生成数据合并，返回结构化结果
6前端根据结构化数据渲染：翻译文本 + 知识卡片 + 关系图/时间线

六技术实现要点

6.1 LLM 调用策略

System Prompt 模板：
你是一位精通中国古代文献的学者。请对以下古文进行解读：
1. 逐字注释（标注读音、含义）
2. 整段白话翻译
3. 识别文中的人物、事件、典故、地名，以JSON格式输出
4. 为每个人物和典故提供简要背景介绍
  • 输出要求结构化 JSON，便于前端解析和可视化渲染
  • 对经典古籍，在 Prompt 中注入已有的权威注释作为参考

八比赛策略

MVP 原则

  • 优先Web端，小程序暂不做（可作为后续扩展说明）
  • 优先核心AI能力（翻译+实体抽取），可视化做简单版
  • 内置3-5本经典古籍数据，确保演示时有充足内容

演示亮点

  1. 实时AI解读：现场输入任意古文，实时展示翻译+背景知识+可视化
  2. 知识关联：点击人物卡片，自动关联该人物的其他古籍出处
  3. 可视化呈现：人物关系图和时间线让古籍内容直观可感知
差异化问答：和百度百科/古诗文网有什么区别？
传统平台是"人找信息"，需要用户自己搜索和阅读。我们的平台是"AI主动解读"，输入任意古文即可自动翻译、自动关联背景知识、自动生成可视化，降低了古籍阅读门槛。同时支持用户上传任意古文，不局限于已收录的内容。
风险预案：AI翻译古文准确吗？
对经典古籍，我们结合权威注释进行交叉校验，准确率较高。对冷门古文，AI翻译作为辅助参考，同时标注"AI生成，仅供参考"。
