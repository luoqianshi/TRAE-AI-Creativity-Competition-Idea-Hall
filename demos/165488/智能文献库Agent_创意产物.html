§I

科研文献处理的四重困境

海量文献时代，研究者不是缺信息，而是被信息淹没。现有工具各管一段，真正打通"检索—阅读—分析—沉淀"闭环的方案缺位。

Pain 01：人工检索阅读，效率的天花板

传统文献调研需逐篇检索、通读全文、手工梳理核心观点。面对一个方向动辄上千篇文献，关键信息提取耗时耗力，极易遗漏重点研究内容。

检索 → 阅读环节断裂

Pain 02：信息过载与知识孤岛

海量文献下载后缺乏有效的数字化组织手段，跨学科知识壁垒导致"知识孤岛"。潜在的学科交叉趋势、合作机会、研究空白难以被人工发现。

缺少结构化挖掘

Pain 03：AI 幻觉引用污染科研

Nature 报道显示，AI 生成的虚假参考文献正污染科学文献——格式完整、作者可信，但 DOI 对不上，甚至文献根本不存在。科研需要的是能回到原文的可追溯证据，而非流畅的猜测。

通用大模型的致命短板

Pain 04：商业数据库昂贵，开放数据分散

Web of Science、Scopus 等商业数据库门槛高昂，中小高校经费有限难以全面订阅。OpenAlex 等开放数据源虽免费，却分散在多个 API，缺少统一、好用的整合工具。

普惠科研的障碍
§II

一个有图纸的产品，而非口号

不追求宏大叙事，聚焦科研文献处理的真实场景，每一层技术选型都有据可查、可验证、可落地。

集智能语义检索、PDF 结构化解析、RAG 辅助阅读、科学计量分析与数据挖掘于一体的文献库 Agent——为高校科研管理者、图书馆学科分析人员及进阶研究者提供全方位支持。

i.

查询解析

自然语言交互，Agent 自动拆解需求、优化查询，降低检索门槛，无需记忆复杂语法。

ii.

结果沉淀

元数据持久化存储，避免重复检索与重复 API 调用，知识资产本地积累、反复复用。

iii.

深度挖掘

内置科学计量与数据挖掘引擎，三网分析 + 主题演化 + PageRank 加权，提供专业级分析工具。

§III

五大模块，端到端闭环

从检索入口到分析出口，每一个环节都为学术场景深度优化，模块间数据流自然衔接，形成不可分割的工作流。

01

Semantic Retrieval — 智能语义检索

用户以自然语言描述研究需求，Agent 自动完成语义理解与查询优化。查询可精确到学者、机构、期刊、年份、引用量等维度，支持粘贴整段摘要自动提取关键词匹配。后台静默执行，设定条件后无需实时等待；所有元数据持久化存储，同一批文献可反复复用。

OpenAlex API
02

PDF Parsing & Vectorization — PDF 结构化解析与向量化

经 MinerU 2.5-Pro 精准解析为结构化 Markdown，还原标题层级、LaTeX 公式源码及表格 HTML 结构。专为学术论文优化，解决双栏排版错序、跨页表格断裂等典型难题。语义分块后存入向量数据库，使 RAG 系统的 Top-1 召回率提升约 25%。

MinerU 2.5-Pro
03

RAG Assisted Reading — RAG 辅助阅读

用户可像与专家对话一样直接提问文献细节。系统基于 RAG 检索增强生成，从本地向量库检索相关原文段落，调用大模型生成答案。答案附带原文引用来源，支持跳转查看上下文交叉验证，直击 AI"幻觉"问题，确保学术信息准确可信。

GLM-5.2 + Evidence Chain
04

Bibliometric Analysis — 科学计量分析

无缝集成 pyBiblioNet 专业分析库，构建三大网络：引用网络描绘知识流动、识别影响力关键节点；合作网络发现跨机构/学科核心枢纽学者；关键词共现网络追踪研究热点演变。支持 Louvain/Infomap 社区检测与聚类分析。

pyBiblioNet · 三网分析
05

Data Mining — 深度数据挖掘

联动 OpenAlex 全球学术图谱，基于 4500+ 标准主题体系自动归类，量化分析交叉程度与创新切入点。构建时序模型动态追踪主题演化，捕捉突现热点；基于 PageRank 算法构建加权评价指标，客观甄别被低估的高价值核心文献。

PageRank · Trend Detection

§V

为什么是这个方案？

社区同类项目多为单点工具，本方案是少数做到端到端闭环的。五大差异化壁垒，每一条都建立在成熟可验证的技术选型之上。

01

端到端闭环

检索→解析→RAG→计量→报告，6 阶全流程打通。竞品多为单点工具，本方案是少数闭环方案。

02

可追溯证据链

答案附 doc_id + 页码 + 原文片段，支持跳转核验。直击 Nature 报道的 AI 幻觉引用痛点。

03

科学计量分析

pyBiblioNet 原生集成 OpenAlex，三网分析 + 社区检测 + PageRank，参赛项目里独此一家。

04

中文场景优化

OpenAlex 全球数据 + 中文自然语言交互。对比纯英文工具，本地化优势显著。

05

本地持久化

元数据本地存储避免重复 API 调用，知识资产沉淀复用。竞品多为即查即弃。

§VI

四类核心用户场景

从科研管理到一线研究，覆盖文献计量分析的完整用户图谱。

01

高校科研管理部门

科研绩效 · 学科评估

跟踪本校各学科发文趋势与合作网络，多维度评估科研绩效，辅助制定科研发展与人才引进战略。

02

图书馆学科分析人员

学科建设 · 资源配置

深入分析学科研究热点与趋势，为院系提供专业领域发展报告，支持学科建设规划和资源精准配置。

03

硕博士研究生

开题调研 · 综述撰写

快速检索并定位领域内高价值核心文献，借助 RAG 技术快速构建知识体系，加速论文写作与文献综述。

04

跨学科研究者

交叉发现 · 创新突破

通过文献网络分析和多维度数据挖掘，打破学科壁垒，发现潜在交叉融合点与创新研究方向。

§VII

效率，与普惠

不只是更快地处理文献，更是让每一个研究者都能触及专业级的分析能力。

VALUE 1

效率提升 — Efficiency

Agent 自动完成检索→解析→向量化→问答→分析全流程，RAG 检索增强使 Top-1 召回率提升约 25%。科研人员从重复的文献整理工作中解放，将精力聚焦于真正的科学问题与创新思考。一篇文献从检索到深度理解，从数小时缩短至数分钟。

VALUE 2

科研普惠 — Accessibility

借助 OpenAlex 开放数据源 + 全开源工具链，实现商业数据库级别的分析能力，降低科研门槛。尤其让经费有限的中小高校和研究团队——那些无法负担 WoS/Scopus 订阅的机构——也能开展专业级文献计量分析，助力科研资源公平化。
