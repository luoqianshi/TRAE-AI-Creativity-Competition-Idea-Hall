01 / 创意介绍

大促尾款算不过来？
让算法帮你做决定

每年 618 和双 11，购物车里十几件商品、三四张优惠券、跨店满减、品类券、红包……规则复杂到人脑算不过来。很多人凭感觉下单，结果多花了几十甚至上百元。

🔍

自动读取购物车

插件自动抓取淘宝/天猫购物车中的商品名称、价格、店铺和数量，无需手动输入。

🧠

组合优化算法

贝尔枚举 + 贪心 + 动态规划，自动穷举所有订单分组方案，找出实际支付最少的那一个。

📊

多方案对比

输出 Top 3 方案，清晰标注每个方案的实付金额和节省金额，一目了然做决策。

💡

智能凑单建议

当某单还差一点点就能触发下一档满减时，自动提示"还差 ¥X 可再减 ¥Y"。

02 / 痛点分析

每年都感觉"亏了"，
但不知道亏在哪

我本人就是重度网购用户。每年大促我都认真算、反复凑单，但结算完总有种"好像还能更省"的遗憾。后来发现这不是我一个人的问题——几乎所有人都在用"感觉"而不是"计算"来做消费决策。

😵

规则太复杂，人脑算不过来

跨店满减、店铺券、品类券、红包、88VIP折扣……叠加规则让人头晕。12件商品、5家店铺，可能的分组方式有数万种。

💰

多花冤枉钱而不自知

两件商品分两单付 vs 合一起付，差价可能几十元。大部分人懒得试，直接一键全付，等于主动放弃了优惠。

⏰

手动凑单效率极低

在购物车页面勾勾选选、反复试算，不仅费时费力，还容易触发平台的频率限制甚至风控验证码。

03 / 灵感来源

从"凭感觉"到"靠算法"

2025 年双 11 我买了 12 件商品，花了一下午在纸上算方案。最后发现如果把一件 ¥89 的打底衫和一件 ¥899 的大衣放一单，刚好能多触发一档满减，多省 ¥50——但我是结算完才发现的。那一刻我意识到：这不是人干的活，应该交给算法。

于是有了这个 Chrome 插件。它像一个精明的"尾款军师"——你只管把想买的加进购物车，它来告诉你最优的支付方案。

05 / 目标用户与场景

谁在用？什么时候用？

👩‍💼

核心用户

22-35 岁大促期间的网购主力人群——每次大促购物车 8-20 件商品、涉及 3 家以上店铺、有多张不同类型优惠券的用户。他们想要省钱，但不愿意花太多时间手动凑单。

📅

使用场景

618 / 双 11 大促购物后、准备付尾款时；日常凑单满减时；或帮朋友 / 另一半算方案时。打开淘宝购物车页面 → 点击插件 → 查看推荐方案 → 按方案支付。

😤

没有它时

用户只能手动反复勾选试算（费时、容易漏算），或干脆全部一单付（放弃优惠），或凭感觉分组（很可能不是最优解）。结果是：每次都多花几十一两百元。

06 / 价值与意义

不只是省钱，更是效率

⚡

效率提升

将用户从 20-30 分钟的手动凑单中解放出来，压缩到 10 秒出结果。算法穷举所有可能的订单分组方案，不会漏掉任何一个省钱机会。平均每单节省 100-200 元，让凑单从"体力活"变成"一键的事"。

🌍

社会价值

大促优惠本质上是平台给用户的福利，但复杂的叠加规则让很多人没能充分享受到。这个工具帮助用户把已有的优惠"算清楚、用到位"，让平台的补贴和商家的让利真正落到每个消费者手里，提升大促的整体体验。

08 / 技术亮点

用 AI 辅助开发，
把不可能变成可能

这个项目全程使用 Trae IDE 开发，AI 辅助完成了 DOM 解析、贝尔数枚举算法、价格实测引擎、DP 优化等核心模块。从 PRD 到可运行的原型，AI 显著加速了开发流程。

🔢

贝尔数穷举算法

对 ≤5 件商品做全排列枚举，自动遍历所有可能的分组方式，确保找到全局最优解。

⚡

分层优化 + DP

商品超过阈值时切换贪心+动态规划，在精度和性能之间取得平衡。

📡

实测价引擎

不仅做数学估算，还会模拟勾选商品，从页面实时读取淘宝结算 API 返回的真实价格。

🛡️

智能防风控

拟人化延迟 + 动态频率调节，避免触发平台的风控验证码。
