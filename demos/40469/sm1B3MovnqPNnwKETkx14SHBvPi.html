01 / PROBLEM

用户在"抽卡"，而不是在创作

强大的闭源大模型就在眼前，但大多数人没办法精准描绘自己的审美需求。于是只能一遍遍试、一遍遍抽卡，靠运气逼近心中所想。

🎲

反复抽卡

改一个词、换一个说法，重跑一遍，结果仍不确定。时间被消耗在试错里。

🌫️

审美模糊

脑海里有画面和感觉，却说不清楚。自然语言到工程化提示词之间，缺一座结构化的桥。

🔁

无法积累

这次碰巧写对了，下次又从零开始。镜头、光影、色彩的审美素养没有沉淀。

02 / DEFINITION

什么是"工程化提示词"

LSPDS 的核心概念，需要先讲清楚。

工程化提示词 ≠ 普通提示词

普通提示词是自然语言的堆叠，依赖运气——"一个孤独的武士站在雨夜街头"。
工程化提示词是按生图模型的语义维度结构化拆解后的产物：每个词都落在对应的模块上（主体/场景/镜头/景别/焦距/构图/光影/色彩/材质/情绪/风格…），模块之间有联动关系、有冲突校验、可锁定、可单点修改、可评分迭代。

简言之：普通提示词是"说一段话"，工程化提示词是"填一张结构化表 + 理解每个字段为什么这么填"。LSPDS 做的，就是把前者转成后者，并在这个过程中教会用户审美。

🍔 一个生活化的类比：买汉堡

如果上面还是太抽象，用"买汉堡"来理解 LSPDS 在做什么。

❌ 普通提示词 = 笨老板的汉堡店

客人走进店里说"我要一个好吃的汉堡"，老板听不懂，只能一次次试：

"加肉？" → "不要" → "加菜？" → "不要" → "那加什么？" → "我也不知道，反正要好吃"

客人有模糊的需求，老板只能逐个问、反复试，做出来不对味，再重来。这就是"抽卡"。

✅ LSPDS = 懂食材的汉堡店老板

老板先听懂客人的真实意图，再把汉堡拆成模块，让客人按模块挑：

面包胚（必选） 肉饼（必选） 生菜（可选） 芝士（可选） 酱料（可选） 番茄（可选）

客人说"想吃点清爽的"，老板知道这意味着多生菜、少酱、不要芝士。客人还能锁定面包胚、只改肉饼的口味，不用重新点一遍。

对应关系：
• 汉堡 = 生图提示词
• 面包胚/肉饼/生菜/芝士 = 18 个模块（主体/场景/镜头/光影…）
• "想吃清爽的" = 用户的模糊审美概念
• 老板懂食材 = LSPDS 懂镜头心理、光影规则、色彩规则
• 锁定面包胚只改肉饼 = 模块锁定 + 单点修改
• 不强制填满所有模块 = 缺失模块自动补全，用户按需选择
• 单个模块二次加工 = 模块可编辑、可迭代

M01 主体 · 为什么用 lone samurai
主体规则：主体决定视觉焦点，需明确身份、数量、特征。"lone" 锁定单一主体，避免多人混乱。
关联：主体锚点决定后续所有模块的方向。
M02 场景 · 为什么用 neon street
场景规则：场景服务主体，不抢戏。"empty" 强调孤独，"neon" 为冷暖对比铺垫，"rainy" 为湿地反射铺垫。
关联：场景↔光影↔色彩三模块强绑定。雨夜决定湿地反射，霓虹决定冷暖对比。
M05 镜头 · 为什么用 low-angle
镜头心理：仰视=英雄、力量、权威、压迫。武士需要力量感与孤独英雄感，平视太弱，俯视会削弱气势。
关联：镜头↔景别↔焦距三模块强绑定。仰视常配广角+全身。
M09 光影 · 为什么用 neon rim light
光影规则：赛博朋克=neon lighting+wet reflections。rim light 让主体从背景分离，体积光增强雨夜空间感。
关联：光影↔色彩↔情绪三模块强绑定。红蓝霓虹=冷暖对比=孤独紧张。

06 / LINKAGE

模块联动规则

18 模块不是孤立的，存在强绑定关系。修改一个模块时，系统只联动相关模块，不全盘重写。

镜头 ↔ 景别 ↔ 焦距

low-angle + wide-angle + full-body

适合强冲击力。虫视常配超广角+远景；85mm+近景+平视适合高级人像。冲突组合（macro + aerial）会被校验器拦截。

情绪 ↔ 光影 ↔ 色彩

孤独 = 冷色 + 低饱和 + 俯视/远景

三模块强绑定。情绪决定光影方向和色彩策略：史诗=体积光+强逆光+金红；梦幻=柔光+粉紫+浅景深。

风格 ↔ 材质 ↔ 画质

写实摄影 = realistic skin + sharp focus

风格决定材质写法。写实摄影要真实皮肤纹理；油画风格不应过度强调 photorealistic skin pores。

主体 ↔ 动作 ↔ 负面词

holding sword → bad hands, extra fingers

人物有手部动作时，负面词必须加入手部错误词；多人互动需加 duplicate faces, merged bodies。

07 / FEATURES

核心功能

三栏模块化联动

左栏原文、中栏18模块拆解、右栏原理讲解，一屏完成"输入—结构化—理解"闭环。

高亮三方映射

标记左栏词句，中栏对应模块与右栏对应讲解同步高亮，建立"原文—模块—原理"映射。

5 锚点 + 混合流程

核心锚点线性确定 + 18模块并行补全 + 冲突校验整合。兼顾稳定性与创造性。

冲突校验器

7类冲突自动检测：镜头/风格/色彩/情绪/材质/密度/技术风险。矛盾组合会被拦截并提示。

模块锁定 + 单点修改

用户可锁定任意模块。改一个模块只联动相关模块（如改镜头只联动景别/焦距/构图），不全盘重写。

审美评分 + 迭代建议

11维评分（主体/构图/镜头/光影/色彩/材质/情绪/叙事/冲击力/技术稳定/商业可用），按用途加权，给出优化方向。

内置 LLM 自运转

插件内置模型，开箱即用，独立完成解析、补全、校验、生成全流程。

MCP 接入强大模型

通过 MCP 被 Trae Work 等外部 Agent 调用，对话直接调用插件能力，处理复杂需求。

09 / USERS

目标用户

本质是同一类人：需要用闭源大模型生图、对提示词精准度有要求、并希望提升自身审美素养的人。

同一群人的三个切面

他们大多是绘图创作者、AI 内容生产者、概念艺术爱好者，或频繁使用 Midjourney / SD / DALL·E 的工作者。共同特征：对画面有想法，但苦于无法用精准提示词表达，反复抽卡耗时耗力，同时希望理解镜头、光影、色彩的原理，长期内化审美能力。

切面一：要结果——把模糊变工程化 切面二：要稳定——可复现不靠运气 切面三：要成长——理解原理能内化
10 / VALUE

价值与意义

效率提升

将模糊概念一次性转化为工程化提示词，大幅减少抽卡次数。模块化结构使提示词可复现、可调试、可迁移。冲突校验器避免矛盾组合，提高出图成功率。

素养内化 · 拥抱 AI

右栏的镜头心理规则、光影选择规则、色彩选择规则讲解，让用户在每次使用中理解"为什么这么用"。素养在过程中持续生长，用多了即使脱离插件，也能独立写出高质量提示词。帮助大众更快拥抱 AI，体验科技乐趣。

11 / FLOW

使用流程

1

输入模糊描述

用户在左栏写下脑海中的原始想法，例如"一个孤独的武士站在雨夜街头"，无需精准。

2

总控建立 5 核心锚点

总控智能体解析输入，确定主体/情绪/风格/场景/用途五个锚点，作为后续所有模块的方向基准。

3

18 模块并行补全 + 冲突校验

18 个子智能体基于锚点并行补全缺失模块，冲突校验器检测 7 类冲突并修正，输出可编辑的模块化提示词。

4

三方映射学习

标记任意词句，三栏同步高亮，配合右栏镜头心理/光影规则/色彩规则讲解，理解"为什么这么用"。

5

单点修改 / 锁定迭代

用户可锁定模块、可单点修改。改一个模块只联动相关模块，不全盘重写。评分器给出优化方向。

6

获得成品 + 内化素养

拿到可复现的工程化提示词，同时镜头、光影、色彩的审美素养在过程中持续生长。
