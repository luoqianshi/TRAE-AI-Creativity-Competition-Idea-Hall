01
创意名称 & 介绍

一套面向上市公司董办 / IR 岗位的智能工作流

上市公司董办和投资者关系（IR）工作中，每天要处理大量重复性、高风险的事务——公告发布前的合规复核、股东名册的归类与趋势分析、媒体舆情筛选、会议纪要与 Q&A 整理等。这些事务既消耗大量人力，又不允许出错。

本套件基于 Claude Code 的 Agent 能力构建，包含 4 个协同工作的子系统：董办 AI 审核助手（披露文件预审）、股东分析 Pro（股东名册智能分类）、舆情监测系统（每日监测报告）、IR 工作库（飞书 + Agent 的双后台架构）。

想解决什么问题

  • 公告披露前的合规检查：规则复杂、人工易漏，错漏即被监管处罚
  • 股东名册分析：每期数百条记录，重复劳动且经验无法沉淀
  • 舆情监测：每天几十条新闻，人工逐条阅读效率极低
  • 知识管理：会议纪要、Q&A、口径散落各处，搜索与复用困难

为什么做这个

判断依据：以 Agent 为核心、配合确定性数据管线的混合架构，能把董办工作从「体力密集型」升级为「决策辅助型」。

04
目标用户 & 痛点

谁在做这些工作？他们面临什么困难？

① 董秘 / 证代

日常信息披露、三会运作、投资者关系管理的核心执行者

② IR 负责人

股东名册分析、机构沟通、业绩说明会准备

③ 合规 / 法务团队

公告与决议文件合规复核、关联交易等敏感事项

核心痛点

🚨 公告审核依赖人工，错漏即被监管处罚
一份董事会决议包含 10+ 个议案，人工审核既慢（每份需 1-2 小时）又不可靠（易疲劳遗漏）
📊 股东名册每期重复劳动，数据孤岛难以积累
每期数百条记录，人工逐条归类；期与期之间的股东变动难以追踪，分类经验无法沉淀
📰 舆情信息过载，每天数十条新闻难筛选
从 20+ 个监测源收集的新闻中，真正需要响应的可能只有 2-3 条
📚 知识分散，口径不一致
会议纪要、Q&A、业绩口径散落在不同文档和系统中，搜索成本高，口径易前后不一致
🤖 引入 AI 担心「不可控」
直接用大模型写公告有合规风险，但纯人工又低效
05
解决方案

痛点 → 方案 一一对应

「公告审核」→ 董办 AI 审核助手
千条规则 + 多角色 Agent 分层审核 + 证据绑定。系统只做预审和风险标注，最终决策权保留给人工。对高风险结论若无证据支撑，自动标记为「需人工确认」。
「股东名册」→ 股东分析 Pro
多层分类器，分类结果与置信度透明可见；知识库从 AI 经验中自动进化，越用越聪明。
「舆情监测」→ 舆情监测系统
浏览器自动化采集 20+ 监测源，Agent 按「公司 / 可比公司 / 行业」三层标准筛选，生成带链接的日报。
「知识分散」→ IR 工作库
飞书多维表格做前台（人类操作 + 正式口径），Claude Code 做后台（AI 处理 + 草稿建议）。严格分离「数据」与「判断」。
「AI 不可控」→ 三层安全架构
确定性 Python 管线负责 80% 常见场景；Agent 负责 15% 模糊判断；人工终审保留 5% 最高风险判断。

① 效率提升：从「体力密集型」到「决策辅助型」

原本需 1-2 天完成的股东名册分析，缩短为分钟级；原本需逐句核对的公告审核，变为「Agent 预审 + 人工复核风险项」模式。

② 商业价值：知识资产化，经验可传承

每一次审核发现、每一笔股东分类修正，都会沉淀为知识库条目。系统具备「知识库进化」机制——AI 发现的规律经验证后写入知识库，后续同类匹配自动走更高置信度路径。

③ 合规价值：降低信息披露风险

规则库覆盖《公司法》《证券法》《股票上市规则》等核心监管要求，以及公司内部章程条款。发现项绑定证据来源，监管问询时可快速回溯。

④ 投资者关系：从「被动响应」到「主动洞察」

股东趋势分析、机构持仓变化、舆情预警——IR 团队能在机构投资者来电、业绩说明会之前，提前做好准备。

07
安全边界

AI 辅助 ≠ AI 代答：明确的安全边界

❌ 绝对禁止：AI 直接生成正式披露口径

绝不允许 AI 生成正式公告文本、业绩指引数字、未披露经营数据的表述。正式口径永远在人工流程中受控。

高风险
⚠️ 需人工确认：重大风险结论

AI 预分类的股东类型、AI 标注的高风险审核项，必须经过人工复核确认。系统在证据不足时会自动降级为「需人工确认」状态。

中风险
✅ 允许自动：情报去重 / 摘要 / 结构化提取 / 周报初稿

确定性流程 + 低风险内容生成，由 Agent 自动完成。每周 IR 周报由子代理自动生成初稿，人工仅需校对。
