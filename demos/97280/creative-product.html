创作者的版本管理之痛

没有 drift 之前，你是怎么管理版本的？

📂

文件名越来越长

靠"另存为"管理版本，文件名越改越乱，根本分不清哪个是哪个版本。

作品_final.png
作品_final_v2.png
作品_final_真的最终.png
作品_final_真的最终_v3.png
💾

硬盘越来越满

每个版本存完整文件，一个 200MB 的文件存十几个版本，硬盘就满了。改了一个字节也要存整个文件。

v1: 200 MB
v2: 200 MB
v3: 200 MB
... × 20 = 4 GB
🔍

找不到之前的版本

想回到昨天的某个版本，但不知道它存在哪个文件里。没有历史记录，无法对比两个版本的差异。

🔧

Git 太难用了

程序员有 Git，但暂存区、提交、合并这些概念对创作者来说门槛太高，而且 Git 对图片、视频等大文件没有增量存储能力。

drift 怎么解决

智能分块 + 一键操作 + 文件类型感知

只存变化的部分

drift 把文件智能地切成小块，每次保存只记录有变化的块。不管存多少个版本，占用空间都很小。

已存储（跳过） 变化的块（只存这些）
200 MB → 2 MB
算法: FastCDC · 压缩: zstd · 哈希: BLAKE3

一条命令就够了

没有暂存区，没有合并，没有冲突。保存、查看、恢复、撤销，每一步都只需要一条命令。

drift — my-novel
$ drift save -m "第一章草稿"
snapshot a3f1b2 saved · 12 files · 48 chunks
$ drift status
3 files modified · 0 added · 0 deleted
$ drift restore id:12ab
restored to 12ab · backup saved
$ drift undo
undid save a3f1b2

分支实验，随时切换

想试试新方向？开一个分支随便改，改完随时切回来。两个方向的作品都保留着，永远不会有合并冲突。

drift switch -c rewrite-ending · drift switch main

核心功能

为创作者量身打造

SAVE

自动保存

打开监听模式后，文件有改动就自动存一个版本。你专心创作就行，不用惦记手动保存。自动保存的版本在历史记录中默认隐藏，不会打扰你。

SYNC

远程同步

通过 WebDAV 或 SMB 协议将作品推送到网盘或服务器，只传有变化的部分。支持推送、拉取、克隆。

WebDAV SMB
DIFF

文件类型感知

能识别不同类型的文件，对比版本时显示有意义的信息，而不是"二进制文件已更改"。

文本 · 逐行 diff PNGJPEGGIFWebPBMPTIFF MP4MOVAVIMKVWebM
SAFE

完整性校验 + 垃圾回收

一键检查所有存储数据的完整性，确保没有损坏。清理不再需要的旧版本数据，释放磁盘空间。

! 实事求是地说：目前 drift 对图片和视频的支持停留在格式识别和元信息对比的层面，还不能做像素级的图片对比和缩略图预览。这些功能未来可能根据项目实际使用情况进行开发。
