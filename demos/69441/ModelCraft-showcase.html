01 / 痛点

通用大模型
千人一面,不懂你的业务

通用 AI 谁都能用,但谁都觉得"不够懂我"。私有知识、个人文风、业务话术,始终进不去模型里。

"问 AI 合同问题,每次都要重新粘贴一堆内部规定;
让 AI 写稿,它总是用通用口吻,不像我。"
!

回答泛泛 · 不懂私有业务

通用模型没见过你的内部资料、产品文档、客户档案,回答停在"正确的废话"。

!

微调门槛高 · 普通人用不起

自建 LoRA 流水线要 GPU、要懂 PyTorch、要会部署——把 90% 的职场人挡在门外。

!

定制完进不了工作流

现有 AI 平台定制完是个孤岛,在 Trae 编码、写周报时还得切工具、反复粘贴。

02 / 方案

三层定制,
从性格到肌肉记忆

不必一次到位。先立人设,再喂数据,最后微调——每一层都可独立热改、热加、热切。

01
Persona · 人设层

立人设 · 即填即用

结构化设定卡:性格侧写、说话方式、行为准则、关系网络、世界观、外貌、背景——七维度分层注入 system prompt,模型把每一面当硬约束。OC 创作者向:专为角色扮演优化的设定卡,长 lore 还会进 RAG 按需检索,不撑爆上下文。

生效方式 · 热改
复现成本 · 0
门槛 · 填表
02
RAG · 知识层

喂数据 · 自实现混合检索

上传 PDF / 文档自动切片 + 向量化。检索走 BM25 + embedding 余弦相似度加权(0.4 / 0.6),无需独立向量库。无 API Key 时 embedding 退化为 hash,检索仍可走 BM25——评委零成本即可跑通。

生效方式 · 热加
外部依赖 · 无
门槛 · 拖文件
03
LoRA · 微调层

练肌肉 · 真 PEFT 骨架就绪

Q&A 样本训练专属 adapter。后台 Worker 异步驱动 pending→running→succeeded,产出 adapter_id + per-epoch loss 曲线。真 PEFT LoRA 骨架已实现(r=8 / alpha=16,延迟导入 torch/peft,GPU-gated),无 GPU 自动降级 mock 并记录原因。同模型 adapter 激活排他,可热切换做 A/B。

生效方式 · 热切
GPU · 可选
降级 · 优雅
03 / 闭环

在 Web 端定制,
在 Trae 里使用

这是 ModelCraft 区别于普通 AI 平台的关键:定制结果通过无状态 MCP Server 接入 Trae 全家桶,Agent 按任务调用你的专属模型。

STEP 01 · 定制

Web / 移动端填表

两分钟套用预设模板或自定义人设,拖入文档建知识库,可选训练 LoRA。无需写一行代码。

STEP 02 · 桥接

MCP Server 代理

Python mcp SDK,Streamable HTTP 无状态代理,透传 Bearer token 作为用户标识,Trae 侧只需配一个 URL。

STEP 03 · 使用

Trae Agent 调用

在 IDE 编码、Work 写周报、CLI 跑脚本时,Agent 按任务调用你的专属模型,带私有知识库回答。
