RallyTrace
一拍一成长

把固定机位正手训练视频，整理成可解释的个人指标和前后证据，让业余球员看见一个训练重点是否真的在变好。

目标用户
学球 0–3 年、会架手机录制训练、却难以复盘的网球爱好者
运行形态
纯浏览器 Web 应用，断网可运行，主链路无需 API Key
分析范围
固定机位、单人、正手训练；仅同一个人的纵向比较
真实问题

教练课上学了，自己练时却看不清

一个典型场景：球员刚上完一节正手课，带着一个明确的训练重点（比如"回位要更快"）自主练习一周。手机架在三脚架上录了 30–90 秒定点喂球，里面 8–20 次正手。

当下的复盘方式

手动拖动视频进度条，凭肉眼判断哪一次挥拍更好；几次之后就把视频堆在相册里，再也没打开过。一周后的复测视频，几乎不会被拿来做逐帧对比。

为什么这样不够

人眼无法稳定量化"回位时间""随挥完整度"这类时间结构；没有指标分布，单次好球坏球说明不了是否稳定改善；更没有前后证据自动对齐，所谓"进步"只能凭感觉。

产品核心流程

从一段视频到一份训练重点

输入、处理、结果三段式，全程在浏览器内完成。

输入

固定机位训练视频

  • 后侧约 45° 或侧位
  • 30–90 秒，8–20 次正手
  • 用户上传或体验示例球员
处理

浏览器端姿态提取与切分

  • MediaPipe 提取关键点
  • 自动检测候选击球片段
  • 计算 16 项个人动作指标
结果

可解释的变化与证据

  • 指标分布而非单一总分
  • 两次训练前后证据对比
  • 下次只关注一个重点
核心功能

三件事，闭环一个训练重点

1

自动整理候选击球

从一段训练视频中检测出候选正手片段，标记动作峰值代理点，支持标记有效或排除误检。每一次击球都可单独查看骨架重放与指标卡。

2

两次训练前后对比

比较基线与复测的中位数与离散程度，自动选择三组最能证明变化的前后证据，并明确标注每项指标的置信度与限制。

3

下一次训练卡

基于对比结果生成一条可测量的训练重点（目标行为、样本数、拍摄要求），把"练什么"收敛成只做一件事，闭环到下一次复测。

最大创新点

诚实可解释的个人纵向变化

RallyTrace 不输出"动作总分"，也不和职业选手对标。它只回答一个问题：同一个人、同样拍摄条件下，这个训练重点是不是稳定地变好了。每项指标都带置信度分级，低置信度数据前置免责说明，所有"击球时刻"统一表述为"动作峰值代理点"，避免把单目视频伪装成三维动捕。

无后端 无云模型 无 API Key 也能跑 断网可用 视频不出端
一个具体使用案例

一周回位训练，看回位时间是否变稳

背景：球员刚上完一节教练课，训练重点是"击球后回到准备姿势"。第一次录制基线视频，一周后用相同机位录制复测视频。

  1. 上传第一周视频，系统在浏览器内提取骨架，检测出候选正手片段，排除 1 个误检。
  2. 查看指标分布：回位时间中位数、随挥完整度、膝部屈曲二维趋势、肩髋分离代理。
  3. 一周后上传复测视频，同样完成提取与切分。
  4. 打开前后对比：系统指出回位时间更稳定、随挥完整度提高，但肩髋旋转代理的置信度一般，并附上限制说明。
  5. 生成下一次训练卡：在 10 个定点正手中，尝试让其中 8 次在目标时间内完成回位，并保持相同机位复测。
数据与边界

数据来源、隐私边界，以及产品不会做的事

数据来源与隐私

  • 训练视频在用户设备本地解码与处理，不上传到任何服务器。
  • 姿态提取由 MediaPipe PoseLandmarker 在浏览器内推理，骨架数据不离开本设备。
  • 训练记录与标记状态保存在浏览器本地存储，清除浏览器数据即清除。
  • AI 解读为可选功能，仅在用户自行配置 API Key 时启用，且只传入结构化指标数据，不传视频或图像。
  • 示例球员数据为公开演示用途的预计算数据，非真实用户运营数据。

产品不会做什么

  • 不会把单目视频等同于三维动作捕捉。
  • 不会把手腕速度峰值等同于真实触球时刻。
  • 不会输出精准球速、旋转、拍面角。
  • 不会做伤病诊断或医疗级生物力学判断。
  • 不会与职业运动员对标，不认为"越像职业越正确"。
  • 不会生成万能动作总分，不做人与人排名。
  • 不会在低置信度数据上强行给出结论。
