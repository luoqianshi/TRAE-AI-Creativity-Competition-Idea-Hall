GitLab MCP Server

专为 AI 客户端构建的 GitLab 议题追踪中间件，通过 MCP 协议将自然语言转换为 GitLab Issue / Milestone / Release 操作

🤖 AI-First 🔗 MCP Protocol 🎯 GitLab Integration ⚡ Zero Config 🚀 Production Ready

项目简介

让 AI 助手成为你的 GitLab 工作流协作伙伴

GitLab MCP Server 是一个专为 AI 客户端（opencode / Trae / Cursor 等支持 MCP 协议的工具）构建的中间件服务。它通过标准化的 MCP（Model Context Protocol）协议，将自然语言转换为 GitLab 的议题追踪操作，配合 gitlab-tracker Skill 提供完整的工作项追踪工作流。

无论是记录 Bug、管理需求、发布版本，还是初始化项目仓库，只需用自然语言描述，AI 助手就能自动完成 GitLab 上的所有操作。

MCP 工具清单

22 个精心设计的工具，覆盖 GitLab 议题追踪全流程

📋 Issue 操作

create_issue
创建 Issue（标题、标签、里程碑、描述、指派人）
update_issue
更新 Issue（状态/标签/里程碑/指派人）
add_issue_note
为 Issue 添加评论
get_issue
查询 Issue 详情
search_issues
检索 Issue（项目/里程碑/状态/类型/关键词）
close_issue
关闭 Issue（无删除权限时使用）

🔗 议题关联

link_issues
关联两个 Issue（relates_to/blocks/is_blocked_by）
link_issue_subitem
建立 GitLab 原生父子层级（子项转 Task 类型）

🚀 发布管理

create_release
创建 Release（标签、名称、描述）
get_milestone_issues
获取里程碑下所有 Issue

🏷️ 项目与标签

list_projects
搜索可访问的项目
list_project_labels
列出项目标签
create_project_label
创建标签（名称、颜色、描述）
list_project_boards
列出议题看板
create_board_list
在看板上创建列表（基于标签）

🎯 里程碑

list_project_milestones
列出里程碑
create_project_milestone
创建里程碑（标题、截止日期）

⚙️ 权限与配置

check_permission
检查当前用户权限等级
configure_base_url
配置 GitLab 地址
configure_token
配置 Personal Access Token
set_project
设置默认项目
set_milestone
设置当前里程碑（自动创建）

应用场景

六大典型场景，展示 AI 驱动的 GitLab 工作流

1
记录 Bug
💬 "登录页面白屏了，记个 bug"

⚡ 执行流程

  • Skill 识别关键词"bug/白屏" → 标签打 bug
  • 从 config 读取 project 和 milestone
  • 检查里程碑是否存在，不存在则自动创建
  • 调用 create_issue：title: "Bug: 登录页面白屏", labels: ["bug"]
2
记录需求并拆分关联子需求
💬 "录入需求：统计优惠卷使用情况"（选择"关联议题"方式）

⚡ 执行流程

  • 查找当前里程碑下标签含 需求 的 Issue（父需求）
  • 不存在 → 创建标题"需求"、标签 需求 的 Issue（如 #40）
  • 已存在 → 复用该 Issue
  • 为每条子需求创建独立 Issue：create_issue → "统计优惠卷使用情况"（如 #43）
  • 调用 link_issues 建立关联：source_iid: 40, target_iid: 43, link_type: relates_to
⚠️ 提示：优先用 link_issues（关联项）而非 link_issue_subitem（子项）。GitLab Free 议题看板只显示 Issue 类型，link_issue_subitem 会把子项转成 Task 类型导致不显示在看板上。
3
发版提醒
💬 "发版提醒：合并 admin、重启 admin 服务、更新 mysql2es 配置"

⚡ 执行流程

  • 查找当前里程碑下标题含"发版提醒"的 Issue
  • 已存在 → 读取描述，合并去重后 update_issue
  • 不存在 → 新建 Issue，标题"发版提醒"，标签 发版
  • 解析事项：
    • "合并 admin、重启 admin 服务" → 同一件事的多个步骤，算 1 条
    • "更新 mysql2es 配置" → 独立任务，算 1 条
  • 写入 description（checklist 格式）：
    - [ ] 合并 admin，重启 admin 服务
    - [ ] 更新 mysql2es 配置
4
切换版本
💬 "切到 v2.0.0"

⚡ 执行流程

  • 检查里程碑 v2.0.0 是否存在（list_project_milestones）
  • 不存在 → create_project_milestone 创建
  • 更新 .gitlab-mcp/config.json 的 milestone 字段为 v2.0.0
  • 返回"当前版本已切换到 v2.0.0"
5
发版检查
💬 "准备发版 v2.0.0"

⚡ 执行流程

  • 调用 get_milestone_issues 获取 v2.0.0 下所有 Issue
  • 按状态汇总：
    已完成：N 个
    未完成：M 个
  • 若有未完成项 → 向用户确认是否继续
  • 确认后生成发布说明，调用 create_release
6
初始化项目仓库
💬 "初始化仓库"

⚡ 执行流程

  • 读取 .gitlab-mcp/config.json
  • 检查权限（check_permission）
  • 清理已有议题（有删除权限用 update_issue 关闭，否则 close_issue）
  • 检查里程碑，不存在则创建
  • 创建标签：状态::待确认/处理中/已修复/已验证/已关闭 + bug/todo/topic/发版/需求
  • 在默认看板上为每个 状态:: 标签创建列表
  • 返回初始化概览

部署方式

两种部署模式，适应不同场景需求

推荐

🌐 HTTP 远程服务

多项目共享，支持远程访问

本地启动

# 默认端口 9980
./gitlab_mcp

# 或指定端口
MCP_HTTP_PORT=9980 ./gitlab_mcp

# 或通过 server.conf 配置
# port = 9980

Docker 部署

docker run -d \
  --name gitlab-mcp \
  -p 9980:9980 \
  -v $(pwd)/.gitlab-mcp:/app/.gitlab-mcp \
  gitlab-mcp

⌨️ stdio 本地模式

单项目专用，适合本地 AI 客户端直接调用

# 无 MCP_HTTP_PORT 环境变量且无 server.conf
# → 自动走 stdio 模式
./gitlab_mcp

AI 客户端配置（opencode.json）

{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "gitlab": {
      "type": "http",
      "url": "https://mcp.git.opencp.cn/mcp",
      "enabled": true
    }
  },
  "skills": {
    "paths": [".agents/skills"]
  }
}

⚙️ 配置文件

在目标项目根目录创建 .gitlab-mcp/config.json：

{
  "base_url": "https://git.opencp.cn",
  "token": "glpat-xxxxxxxxxxxxxxxxxxxx",
  "project": "group/project",
  "milestone": "v1.0.0",
  "server": "https://mcp.git.opencp.cn"
}
字段 说明 示例
base_url GitLab 实例地址 https://git.opencp.cn
token GitLab Personal Access Token（需 api 权限） glpat-xxxx
project 默认项目路径 cloud_charge/admin
milestone 当前工作里程碑 优惠卷-v1
server MCP Server 地址（HTTP 模式） https://mcp.git.opencp.cn

调试工具

多途径测试 MCP Server 连接与功能

🐍 Python 客户端

使用 mcp_client.py 直接调用 MCP 工具

# 列出所有工具
python3 .agents/skills/gitlab-tracker/mcp_client.py \
  --url "https://mcp.git.opencp.cn" list_tools

# 创建 Issue
python3 .agents/skills/gitlab-tracker/mcp_client.py \
  --url "https://mcp.git.opencp.cn" call create_issue \
  --params '{"title": "测试 Issue", "labels": ["bug"]}'

# 检查权限
python3 .agents/skills/gitlab-tracker/mcp_client.py \
  --url "https://mcp.git.opencp.cn" call check_permission \
  --params '{"project": "cloud_charge/admin"}'

📡 curl 调用

直接通过 HTTP 请求调用 MCP 接口

curl -X POST http://localhost:9980/mcp \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "tools/call",
    "params": {
      "name": "create_issue",
      "arguments": {
        "project": "cloud_charge/admin",
        "milestone": "优惠卷-v1",
        "title": "Bug: 登录失败",
        "labels": ["bug"]
      }
    }
  }'
