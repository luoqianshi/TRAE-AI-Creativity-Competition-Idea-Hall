核心概念

我们解决的不是"情绪疏导"，而是"即时保护"。

问题定义

当一个孩子被围堵在厕所、被勒索钱财、被威胁"不许告诉任何人"的时候，
他需要的不是"写日记倾诉"，而是立刻有人帮他解决问题。

现有的心理援助平台（简单心理、壹心理、12355热线）都是长程咨询模式：预约、排队、付费、多次会谈。
这对急性危机（霸凌、人身威胁、自伤冲动）完全无效——求助者没有时间、没有精力、没有耐心走完这个流程。

微光的核心价值：一键求助 → 3分钟内语音/视频响应 → 即时解决问题。

2

界面设计原则

极简、零学习成本、一键触达。所有解释性内容放在二级页面。

首屏：求助者端

点击后立即开始匹配守护者

首屏只有一个按钮。不需要选择场景类型、不需要填写描述、不需要阅读任何文字。
求助者可能正在被围堵、正在害怕、正在崩溃——他没有时间理解复杂界面。

首屏：守护者端

震动+声音强提醒，点击即接单

守护者端同样极简。收到求助通知后，点击"接单"即开始语音/视频通话。
不需要查看求助者资料、不需要预读问题描述——先响应，边聊边了解。

设计原则

1. 零学习成本：被霸凌的孩子没有精力理解复杂界面，首屏必须一目了然
2. 一键触达：从打开App到发出求助，不超过2步操作
3. 即时响应：语音/视频通话优先，文字聊天作为备选
4. 隐藏模式：伪装成普通应用（日记/计算器），避免施暴者发现
5. 解释后置：资质体系、风险词库、隐私说明全部放在二级页面

不同资质的守护者，承接不同类型的求助。从源头规避不当引导的风险。

匹配逻辑：
• 检测到"围堵""勒索""威胁"等关键词 → 自动升级至L5
• 检测到"想死""自残"等关键词 → 自动升级至L3+
• 普通情绪问题 → 匹配L1-L2
• 首个接单者胜出，其余候选者自动取消

危机干预机制

当检测到生命安全风险时，系统自动触发升级流程，联动专业力量。

风险识别与自动升级

系统实时监测求助者的语音/文字内容，当检测到以下风险词时，自动触发升级流程：
• 人身威胁词：围堵、勒索、威胁、打我、弄死你
• 自伤词：想死、自杀、自残、结束生命、不想活了
• 强制沉默词：不许告诉、告诉了就、敢说就

技术架构

首期以微信小程序为主，后续扩展原生App。

分层架构

客户端 微信小程序（求助者端 + 守护者端）｜原生App（后续）
实时通信 腾讯云TRTC（语音/视频通话）｜WebSocket（文字聊天）
匹配引擎 基于资质层级 + 在线状态 + 历史评价的调度算法
风险检测 实时语音/文字关键词识别 + 自动升级触发
数据层 PostgreSQL（用户/资质/求助记录）｜Redis（在线状态/匹配队列）
通知层 微信服务通知（强提醒）｜短信（兜底）｜App推送

关键技术点：
• 语音通话优先：求助者可能正在被控制，无法打字，语音是最快通道
• 风险词实时检测：通话过程中实时识别风险词，自动提示守护者
• 隐藏模式：小程序可伪装成普通应用，避免施暴者发现
• 强提醒机制：守护者端收到求助时，震动+声音+弹窗三重提醒

7

发展路线

单城试点 → 验证模型 → 逐步扩张。

Phase 0：筹备期

第1个月
• 法律意见书与合规框架定稿
• 试点城市与合作伙伴锁定（1所中学 + 1家精神专科医院）
• 守护者种子池招募（目标50人）

Phase 1：MVP上线

第2-4个月
• 微信小程序双端开发
• 核心功能：一键求助、语音通话、资质匹配、风险检测
• 单城封闭测试，守护者≥200，响应率≥90%

Phase 2：验证期

第5-9个月
• 匹配算法优化、危机干预流程验证
• 求助者满意度≥85%
• 引入政府购买服务试点

Phase 3：扩张期

第10-18个月
• 覆盖3-5城，守护者池≥2000
• 专业付费咨询规模化
• App端立项开发

Phase 4：成熟期

第19-30个月
• 全国主要城市覆盖
• App上线，AI辅助风险识别
• 形成行业标准，参与政策制定
