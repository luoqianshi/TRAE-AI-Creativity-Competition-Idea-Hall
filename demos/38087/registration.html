一句话，问出你的运价

自然语言驱动的航运运价 AI 问数引擎

1 创意介绍

创意名称：nexquery

nexus（联结）+ query（查询）= 把销售和运价数据联在一起，自然语言即问即答。

想解决什么问题？
航运销售人员在报价时，需要频繁查阅历史运价数据作为参照。但数据锁在数据库里，销售不会写SQL，数据团队排期慢——"数据明明有，就是拿不到"。nexquery 让销售用自然语言直接提问，秒级取数，报价有据可依。

为什么会想到做这个？

在物流公司，我们沉淀了数千票真实订单的运价数据——每条航线的海运费、每家船公司的费率、每个客户的历史报价。这是报价最宝贵的参照。但现实是销售要么凭经验拍脑袋，要么等数据同事排期取数。如果能用AI把自然语言转成数据库查询，这些数据才能真正"活起来"。

产品形态：一个基于大语言模型的 AI Agent Web 应用。用户输入自然语言问题（如"上海到鹿特丹40HQ最近半年平均海运费"），系统自动完成港口识别、意图解析、SQL编译、数据库查询，返回结构化结果和可视化图表。

AI Agent 自然语言取数 语义层映射 运费分析 Web应用

2 目标用户及痛点

面向哪些用户？

航运物流企业的揽货销售人员、报价专员、航线经理。他们日常高频需要查询历史运价数据，但普遍不具备SQL或数据分析技能。

在什么场景下使用？

  • 客户询价"上海到汉堡20GP多少钱"，快速查到该航线最近成交价区间和趋势
  • 投标前需要了解"某船公司近半年欧洲线运费走势"，判断报价策略
  • 方案组合时需对比"不同起运港到同一目的港的运费差异"
  • 周会上被问"Q1各船公司箱量贡献度分布"，当场出数据回应

当前痛点

没有 nexquery，销售的取数路径是：

翻历史报价Excel → 群里@数据同事 → 描述需求 → 等排期 → 等半天拿到结果 → 格式可能还要自己调

这个链路的核心问题：周转时间太长（小时级甚至天级）、沟通成本高（销售描述需求可能不准确）、数据利用率低（大量有用数据躺在库里没人查）。最差的情况——销售凭经验拍脑袋报了一个价，亏了或跑了，事后才发现数据库里早有明确的价格参照。

3 价值与意义

⚡

效率提升

将取数链路从「找数据同事 → 等排期 → 出结果」的数小时，压缩为一次自然语言对话的秒级响应。已实现15种分析模式（排名、趋势、分布、对比、异常检测、帕累托分析等），覆盖销售90%的日常取数场景。支持规则引擎+LLM双通道，无网络环境也可离线使用。

💰

商业价值

报价越准、响应越快，成交率越高。销售直接获取历史真实成交价作为参照，用数据报价而非凭经验拍脑袋。同时解放数据团队生产力——分析师聚焦高价值分析而非重复性取数。对年运费数千万的企业，报价准确率提升1%即创造显著收益。
