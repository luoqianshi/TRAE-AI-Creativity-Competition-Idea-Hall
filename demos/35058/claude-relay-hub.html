问题现状

开发时被这些琐事拖慢节奏

三个真实的、每天都在发生的场景痛点，也是 Claude Relay Hub 要解决的核心问题。

01

模型锁定 · 无法协同

每个 Claude 会话只能绑定一个模型系列。想用 GLM 写代码又需要多模态模型做视觉验证时，必须等一方完成再手动切模型。cc-switch 虽能帮上忙，但反复操作依然让人精疲力尽。

上下文中断 · 效率降低 40%+
02

多窗口并行 · 人的心智过载

为了提速，我们常常打开多个 Claude 窗口并行开发。模型之间虽然不会互相污染上下文，但人会 — 我们需要自己记住每个窗口在干什么。而且模型干完活从不提醒你，只能被动等候。

心智负担 · 漏活/等活
03

新人上手 · 不知道下一步干啥

对于初级或新加入项目的开发者，完成一个步骤后往往迷茫：下一步该做什么？需要什么验证？当前进度如何？没有一个能"看到全貌"的智能助手来指导他们。

流程断层 · 学习成本高
解决方案

本地中转中枢，统一调度一切

在你的本机运行一个轻量级 API 中转服务，它像调度台一样协调所有模型、所有会话，还配备一个看得见全局的 Agent 秘书。

多模型 API 统一中转

一次性把所有要用的模型 API Key 注入到本地中转，对外只暴露一个统一端点。

  • 支持 OpenAI / Anthropic / DeepSeek / GLM / Qwen / MiniMax 等主流厂商
  • 智能路由：根据任务类型自动分发到最合适的模型
  • 自动 Fallback：某个模型挂了自动切到备用模型
  • Token / 成本监控：实时查看每个模型的用量与花费
  • 统一密钥管理：API Key 仅存在本地 .env，永不外泄

多会话调度 & 语音提醒

管理所有 Claude 窗口的工作状态，动态分配任务，完成即用语音通知你。

  • 每个窗口注册到中转站，显示任务状态
  • 动态注入提示词：在中转层自动注入规则/约束/上下文
  • 系统语音 + 桌面通知：任务完成立即喊你
  • 任务队列化：排好的活一件接一件自动推进
  • 防心智污染：人不用记哪个窗口在干啥，面板一目了然

Agent 秘书 · 全局可见

一个运行在中转站上的智能 Agent，能看到每个窗口的 AI 在做什么。

  • 实时汇总所有会话的进度和状态
  • 新人开发者可随时询问："下一步该干啥？"
  • 自动识别死锁/循环任务，防止模型白跑
  • 智能规划下一步动作，甚至可以自动推进
  • 作为团队知识传递的"虚拟 Tech Lead"
