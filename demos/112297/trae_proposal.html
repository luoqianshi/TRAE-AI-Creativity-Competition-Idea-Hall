我们发现了什么问题

现有协同文档工具严重依赖中心云服务器，在网络不可用场景下彻底瘫痪

📡

网络依赖症

主流协同文档（腾讯文档、飞书、Google Docs）必须连接云端才能工作。断网 = 停工，信号差 = 卡顿，服务器宕机 = 数据不可访问。

🔒

隐私黑箱

用户数据存储在第三方服务器上，平台拥有完全访问权限。端到端加密在主流协同工具中几乎不存在，敏感文档无处安放。

⛰️

数字鸿沟

偏远山区、地下作业、海上平台、跨国差旅——这些场景下网络不稳定或完全不可用，但协同工作的需求依然存在，却没有工具能服务他们。

💸

成本与封锁

云服务器意味着持续运营成本；在某些地区，网络封锁让依赖云的协同工具瞬间失效。一个不受基础设施制约的协同方案迫在眉睫。

Tacit 的解决方案

去掉中心服务器，让设备之间直接对话——通过蓝牙、局域网、QUIC 或中继，自动完成数据同步

核心思路：Local-first + P2P Sync
  • 所有写入先落地本地存储，零等待、完全离线可用
  • 设备发现彼此后，通过 CRDT 自动合并变更，无需冲突解决
  • 四条传输通道智能切换：BLE 近场 → LAN 局域网 → QUIC 跨网 → Relay 中继兜底
  • 端到端加密（Noise Protocol + Ed25519），中继服务器也看不到内容
  • 双水位 GC 自动压缩历史，长期使用不膨胀

同步流程

从设备发现到数据收敛，全自动完成

1

设备发现

BLE 广播 / mDNS 扫描 / 已知 peer 列表，自动发现局域网内的协同设备

2

加密握手

Noise_XX 协议握手，交换 Ed25519 公钥，建立端到端加密会话

3

前沿交换

双方交换 AckSummary / frontier，计算需要同步的差量

4

Meta 优先

先同步 Meta-Document（文档结构），再按需拉取 Block 内容

5

依赖等待

缺少前置 Block 时指数退避等待，避免空转

6

ACK + GC

确认收到后更新 ack frontier，触发双水位压缩评估

应用场景

从偏远山区到跨国差旅，Tacit 在网络不可用时依然工作

🏔️

偏远地区协同办公

山区支教老师需要在无网环境下与同事协作编写教案、共享教学资料。Tacit 通过蓝牙和局域网实现设备间直接同步，不依赖任何云服务。老师们的手机就是服务器。

🏗️

工地 / 地下作业记录

矿井、隧道、地下管线施工环境中网络信号完全不可用，但施工日志、安全检查表需要多人协同填写。Tacit 让工人的防爆手机通过 BLE 互相同步，出井后自动汇入主管设备。

🚢

海上 / 航空场景

远洋货轮、长途航班上，船员/机组需要共享排班表、工作日志。卫星网络昂贵且不稳定，Tacit 在设备间直接同步，靠港/降落后通过 QUIC 自动完成跨设备数据收敛。

🔒

高隐私文档协作

律师、医生、财务人员处理的文档高度敏感，不能上传到任何第三方服务器。Tacit 的端到端加密 + Local-first 架构确保数据始终在用户自己的设备上，中继也只看到密文。

🌐

网络封锁环境

在某些地区，云端协同工具可能被屏蔽或服务不稳定。Tacit 的 P2P 架构 + 多传输通道设计使其在封锁环境下依然可用——只要两台设备能以任何方式通信，数据就能同步。

价值与意义

技术为善：让被数字鸿沟隔绝的人群也能享受协同的便利

社会价值

弥合数字鸿沟

为网络基础设施不完善的地区（偏远山区、地下作业、海上场景）提供与城市同等水平的协同办公能力。不抛弃任何一个掉线的人。

效率提升

零等待、永不中断

所有操作本地即时完成，网络只是"锦上添花"而非"生命线"。断网不停工、重连自动同步，工作效率不再受制于网络质量。

隐私保护

数据主权归用户

端到端加密 + 无中心服务器，用户数据始终在自有设备上。中继服务器不可信设计确保第三方无法窥探内容，数据主权完全归还用户。
