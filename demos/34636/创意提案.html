Part 00

灵感来源

"在一个棋盘上，每个格子只有生与死两种状态，只看周围8个邻居决定命运——就这样简单的规则，却能涌现出滑翔机、振荡器、甚至通用图灵机。"

1970年，数学家 John Conway 发明了"生命游戏"，用一个极其简单的规则系统展示了复杂系统科学的核心命题：涌现——整体大于部分之和。

半个世纪后的今天，生命游戏依然是计算机科学课堂上最经典的入门案例。但问题在于：网上的模拟器几乎都停留在"黑白格子动一动"的层面，没有人把它做成一个真正可探索、可实验、可创造的产品。

与此同时，生态学课堂上的 Lotka-Volterra 捕食模型、流行病学中的 SIR 模型，学生只能对着微分方程发呆，无法亲手实验"如果草食者繁殖率提高10%会怎样"。

AI 编程工具的成熟让我意识到：一个人借助 TRAE IDE，可以做出过去需要团队才能完成的复杂交互应用。于是，元胞宇宙诞生了。

5个物种详解

绿藻 生产者，3个同类邻居繁殖，≥4个拥挤死亡，≥2个草食者邻居被捕食。与共生菌共存时繁殖阈值从3降至2
草食者 初级消费者，必须相邻有绿藻才能存活，≥2个肉食者邻居被捕食，≥3个同类拥挤死亡。共生菌可降低繁殖阈值
肉食者 顶级捕食者，必须相邻有草食者才能存活，≥2个同类拥挤死亡。繁殖需要自身+猎物同时满足阈值
分解者 分解死亡细胞回归空格，孤独(0邻居)或拥挤(≥6邻居)时死亡，≥2个同类邻居可繁殖
共生菌 与绿藻和草食者共生，降低宿主的繁殖阈值。需要宿主(绿藻+草食者)≥1才能存活，≥1个自身+≥1个宿主可繁殖

6种目标类型

stable（稳定结构）、extinction（全灭）、population（种群数量）、reach（区域到达）、timed（限时挑战）、compound（复合目标）——每种目标类型对应不同的策略思维，从"理解规则"到"利用规则"，层层递进。

关卡进度自动保存到 localStorage，星级评价激励反复挑战。放置细胞数受限，迫使你思考"最少需要几个细胞"。

双渲染管线

WebGLRenderer 一次 draw call 绘制全部格子，25万格60fps。CanvasRenderer 自动降级，兼容所有浏览器。RendererFactory 根据支持情况自动选择。

TypedArray 双缓冲

Uint8Array 存储网格数据，每个元素1字节。双缓冲避免读写冲突，连续内存布局CPU缓存友好，可直接上传为WebGL纹理。

差异渲染

只渲染状态发生变化的格子，大网格下大幅减少绘制调用。WebGL 通过 texSubImage2D 只上传变化的行。

模块化设计

Grid / Engine / Rule / Renderer / UI 完全解耦，每个模块可独立扩展。新增规则只需继承 RuleBase，新增UI只需实现对应接口。

三次验证流程：确保一次写对

每个扩展功能（规则编辑器、解谜关卡、生态模拟）开发前，都执行三次可行性验证：

第一次：制定详细计划，逐行审查源代码，发现计划与实际代码不一致
第二次：补充修正计划，验证修正方案的可行性
第三次：逐行代码审查，确保写代码时能一遍成

这个流程在5.2解谜关卡系统中发现了9个问题（4个高严重性），在5.3生态模拟中发现了6个问题（2个高严重性+1个已有Bug），全部在编码前修正。

AI 发现的隐藏 Bug

三次验证过程中，AI 通过逐行审查发现了两个已有代码中的隐藏 Bug：

CanvasRenderer.setColors 颜色索引偏移：`_cellColors = cellColors` 导致状态值与颜色索引不对应，主题切换后颜色错误。修正为 `_cellColors = [null, ...cellColors]`。

WebGLRenderer colorTableWidth 硬编码：着色器中 `float colorTableWidth = 6.0` 不随状态数变化。修正为 `uniform float u_colorCount` + JS 每帧更新。

这两个 Bug 在正常使用中不易察觉（恰好不报错），但在生态模式6状态下会暴露。AI 审查提前发现并修复，避免了上线后的问题。
