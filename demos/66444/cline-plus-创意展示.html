问题

AI 编程助手的四个结构性缺陷

01 — 搜索像碰运气

AI 助手直接搜用户原话，不分解问题、不找反证、不评估来源质量。结论基于 SEO 农场文章，搜索质量无法审计。

02 — 压缩 ≠ 恢复

Cline compact 压缩上下文后，关键决策和研究结论被丢弃。摘要是给模型看的，不是给下一个 agent 接手的。

03 — 73% 任务是续作

实测数据：超过七成任务需要跨会话续作。每次新会话花 10 分钟「回忆」——这不是偶发，是常态。

04 — 换工具就断档

Memory Bank 绑定 Cline，CLAUDE.md 绑定 Claude。换 Agent，工作状态无法移植——工具选择被锁定。

三路 Fanout

R1 · 直白型

用户原话直搜，捕获最直接的匹配结果。

R2 · 限域型

site: 限定权威域名（官方文档、RFC、论文库），过滤噪声。

R3 · 反证型

主动搜索反例、失败案例、已知陷阱，避免确认偏误。

Domain Goggles — 域名级软过滤

五套领域规则，按搜索意图自动匹配，对来源域名进行软过滤与权威度预判：

  • 通用技术规则
  • 学术论文规则
  • 产品调研规则
  • 安全 CVE 规则
  • 中文技术规则

Gap Ledger — 证据缺口审计

合成前强制审计五类证据缺口，未通过审计的结论不可输出：

单源外推

仅凭单一来源推导结论

利益相关

来源存在利益冲突

范围外推

结论超出证据适用范围

时效衰减

来源已过时或版本过旧

反证缺位

未搜索或未找到反证

来源四级权威度

T1 官方权威 权重 10×
T2 半权威 权重 3×
T3 社区 权重 1×
T4 低权威 权重 0.1×

输出格式

每条结论以三元组输出：Claim（声明）+ Verbatim Quote（原文引用）+ Source（来源），确保每条结论可溯源、可审计。

模块二 · 跨 Agent 状态恢复

Handoff Protocol

核心洞察

压缩（Compaction）≠ 恢复（Handoff）。压缩是 token 管理，handoff 是状态持久化。两者解决完全不同的问题，必须作为独立机制设计。

handoff.md — Agent 无关的纯 Markdown

Handoff 的产物是一个纯 Markdown 文件（handoff.md）。它不绑定任何运行时：

  • Cline 能读
  • OpenClaw 能读
  • 人能读
  • 任何 LLM 都能读

四个设计约束

Agent 无关

不依赖任何特定 Agent 的运行时或 API

文件即状态

状态以文件形式存在，非内存或数据库

Git 可追踪

纳入版本控制，变更可 diff、可回溯

人可读

开发者可直接阅读，无需工具解析

触发条件

  • 用户显式指令（如「保存进度」「交接」）
  • 架构决策被接受时自动触发
  • 里程碑完成时
  • 工作树交接（branch switch / PR 提交）
  • 长会话 + 话题跳跃检测

ADR-005 · 拆分决策

Compaction 与 Handoff 是两个独立机制。各自拥有独立的触发器、产物和生命周期。Compaction 管 token，Handoff 管状态。二者不应合并，也不应互相替代。

模块三 · 上下文快照插件

Context Snapshot Plugin

挂钩 Cline 原生 compact 事件（registerMessageBuilder API），在压缩发生前后自动介入：

A

Compact 前 — 自动捕获

在 Cline 触发 compact 之前，自动提取当前会话中的关键决策和研究结论，生成结构化快照。

B

Compact 后 — 动态注入

压缩完成后，通过 rules 机制将快照内容动态注入回上下文，确保关键信息不因压缩而丢失。

模块四 · MCP 反-bot 节流 Wrapper

Anti-bot Throttle Wrapper

对 MCP 工具调用增加节流与熔断机制，防止触发反-bot 限制：

  • 指数退避熔断 — 遇到 429 或限速时自动退避，避免雪崩
  • max_results 限制 — 单次请求结果数量上限控制
  • 跨调用状态管理 — 维护调用间的状态一致性

工程纪律

Engineering Discipline

A/B/C 分类法

A 类

未来代码化的运行时问题 — 不写规则，留给代码解决。

B 类

Cline 限制的临时补丁 — 打退休标记，等待上游修复。

C 类

认知铁律 — 长期保留，不因工具变化而动摇。

五问门控

新功能启动前必须回答五个问题。默认答案是「放弃」或「用原生」。只有五个答案都指向「需要自建」时，才进入开发。

停止条件

额度用完，立即停止，进入复盘。不续命、不硬撑、不超支。
