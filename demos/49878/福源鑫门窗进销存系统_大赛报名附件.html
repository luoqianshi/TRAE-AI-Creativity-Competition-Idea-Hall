福源鑫门窗进销存系统 FUYUANXIN DOOR & WINDOW INVENTORY SYSTEM

学习工作 · 企业数字化 前后端分离 门窗行业 AI 辅助开发 Windows 7 兼容 可离线部署

面向中小门窗企业的一体化进销存解决方案：以「订单」为核心，串联客户、产品、下料公式、库存、采购、生产、收款与报表，从开单到出货一张单贯穿到底，告别 Excel 多表反复核对的混乱。

01项目背景与痛点BACKGROUND & PAIN

行业现状

门窗行业以中小微企业为主，仍普遍依赖 Excel 多表 + 微信口头 管理日常业务：客户联系方式散落在微信聊天中、产品规格和单价分散在报价表、下料公式由老师傅凭经验口算、订单状态靠翻笔记本追踪。

典型痛点

  • 客户电话/地址/微信散落在销售个人手机，人员离职即客户流失。
  • 产品种类与规格繁多（门/窗/材料），报价与出库口径不一，常出现错单漏单。
  • 下料公式依赖老师傅经验，新人上手慢，且容易算错造成材料浪费。
  • 订单状态（草稿→审核→生产→待收款→已完成）全靠 Excel 批注，对账费时。
  • 老板想看一张经营看板要汇总 5 个 Excel 表，数据滞后、口径不一。

项目机会

用一套 低成本、易部署、可离线 的 Web 系统，把"客户—产品—订单—下料—库存—报表"全链路数字化，让小微企业也能用上像模像样的 ERP，成为老板随身携带的"经营驾驶舱"。

02解决方案与核心功能SOLUTION & FEATURES

以"订单"为主线的八大业务模块

🧑

客户管理

客户档案、联系方式、历史订单、跟进记录，自动带出下次开单信息。

🚪

产品管理

门/窗/材料三类，规格、单价、单位、图片统一维护，支持按类目显隐字段。

📐

下料公式

基于 {宽} {高} {数量} 的可配置公式，AI 辅助校验，告别口算。

🧾

销售开单

一键选择客户与产品自动带价，支持金额汇总、订金、安装费、运费、折扣。

📋

订单管理

草稿/待审核/生产中/待收款/已完成 全状态追踪，支持批量操作。

📦

库存/采购

出入库流水、库存预警、采购单与供应商对账，库存与订单自动联动。

🔨

下料/生产

根据订单自动生成下料清单，支持按公式复核、批量打印。

📈

经营看板

订单趋势、回款进度、热销产品、客户贡献一屏掌握，支持多维度筛选。

关键业务亮点

1
自动订单号

MC + 年月日时分秒 + 序号，唯一可追溯。

2
三态排序

所有列表支持 Excel 式升/降/取消三态排序，列宽可拖拽并持久化。

3
批量交互

支持勾选批量审核、批量完成、批量删除，协同效率翻倍。

4
发票打印

A4 发票预览、打印、PDF 导出，交付即规范化。

5
Excel 双向

一键导出订单/产品，支持按订单号多行间合并的反向导入。

6
金额规则

合计 = 明细小计 + 安装费 + 运费 − 折扣；应收 = 合计 − 订金。

7
状态流转

草稿 → 已审核 → 待确认 → 生产中 → 待收款 → 已完成，全流程可追溯。

8
备份恢复

SQLite 一键备份与恢复，老板电脑也能当服务器。

用户故事：销售张姐过去靠 Excel 手工算下料，一单至少 20 分钟，还经常算错浪费材料；现在开单自动带出公式，3 分钟完成，客户电话和地址自动带出，订单状态手机上随时可查。

03技术框架与实现思路TECHNICAL ARCHITECTURE

分层架构

前端
原生 HTML CSS Grid / Flex 原生 JS（ES5+） SheetJS 可离线
后端
Node.js 12 Express 4 body-parser 统一响应封装
数据库
SQLite 3 自动建表 文件级备份 零配置部署
部署
Windows 7 兼容 局域网多终端访问 NSSM 注册系统服务 0.0.0.0:3000

数据模型

围绕订单设计核心表：customerproduct_categoryproductcutting_formulaorder_mainorder_itemproduct_dict。订单主表与明细分离，支持一单多产品。

接口规范

统一响应结构 { code: 200|500, message: '', data: any }，所有 CRUD 走 POST/GET，服务端完成金额计算，前端仅负责展示，避免口径不一。

工程亮点

  • 数据库自动建表：首次启动即执行建表 SQL，开箱即用。
  • 兼容 Win7：依赖选用 Node 12 稳定版 + 低版本中间件，确保老机器可部署。
  • 代码健壮：DOM 操作统一放入 window.onload，所有 parentElement 均做空值判断。
  • 性能优先：纯原生实现，无打包无构建，启动即服务。

一、项目背景与痛点

中小门窗企业长期依赖 Excel 多表和微信口头管理业务，客户资料散落、产品价格不一致、下料公式靠老师傅经验、订单状态追踪困难、老板经营看板滞后。我们希望用一套低成本、易部署、可离线的 Web 系统，让小微企业也用上真正的"经营驾驶舱"。

二、解决方案与核心功能

以订单为核心，打通客户管理、产品管理、下料公式、销售开单、订单管理、库存/采购、下料生产、经营看板八大模块。订单支持草稿→已审核→待确认→生产中→待收款→已完成全状态流转；自动生成唯一订单号；金额规则"合计 = 明细小计 + 安装费 + 运费 − 折扣"；所有列表支持 Excel 式三态排序、列宽拖拽持久化、多选批量操作；支持 A4 发票打印与 PDF 导出、Excel 双向导入导出。

三、技术框架与实现思路

前端采用原生 HTML + CSS Grid + 原生 JS（ES5+）+ SheetJS，可离线运行；后端采用 Node.js 12 + Express 4 + body-parser，统一响应封装；数据库使用 SQLite，首次启动自动建表，零配置部署。为兼容 Windows 7 服务器，依赖选用稳定低版本。接口统一返回 { code, message, data }，金额计算在服务端完成，保证数据口径一致。

四、应用场景与价值

面向门窗零售门店、定制展厅、门窗工厂与经销商渠道，贯穿"客户—开单—下料—生产—收款—报表"全流程。预估开单效率提升 5 倍、下料出错率降低 70%、数据一致性提升 3 倍、服务器成本为 0。我们希望通过零门槛的数字化方案，让每一家门窗小店都能用上属于自己的 ERP，把老师傅的经验沉淀成可复用的数字资产。
