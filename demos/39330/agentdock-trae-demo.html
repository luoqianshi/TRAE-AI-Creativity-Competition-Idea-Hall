Why it matters

AI CLI 很强，但真实开发现场是割裂的

开发者往往同时使用多个命令行 AI 工具：一个擅长代码生成，一个擅长推理，一个擅长本地工程处理。真正的问题不是没有模型，而是缺少一个统一的工作台。

01

工具入口分散

不同 CLI 分布在不同终端和配置里，切换模型、参数和项目上下文的成本很高。

02

上下文重复输入

每次请求都要重新解释项目规则、历史结论和个人偏好，AI 输出难以稳定延续。

03

会话不可管理

终端输出很快丢失，任务、项目、模型选择和运行记录无法形成可追踪资产。

04

扩展不成体系

新增一个 CLI 或工程工具，往往意味着重新写一套检测、运行和 UI 交互逻辑。

Solution

AgentDock 把 AI CLI 变成统一控制平面

它不是另一个聊天壳，而是面向本地 AI CLI 的桌面级编排层：统一发现、统一运行、统一保存、统一注入上下文。

从“打开多个终端”到“一个桌面控制台”

AgentDock 将本地 AI CLI 封装为可选择、可运行、可记录的能力单元。用户在项目维度发起任务，系统自动携带记忆、偏好和历史上下文，再将请求路由给合适的 CLI 与模型。

这样开发者可以专注于任务本身，而不是反复处理命令路径、模型参数、会话整理和上下文拼接。

01 / Detect
扫描本机 CLI，例如 Grok、MiMo、Claude、Codex、Qwen，识别版本、状态与可用模型。
02 / Context
按项目和会话自动注入记忆、规则、摘要、最近消息与用户偏好。
03 / Run
通过统一 Runner 启动 CLI，实时捕获 stdout / stderr，并沉淀为会话资产。
04 / Extend
通过 Adapter 与插件机制扩展更多 CLI、工程工具和自动化能力。
Core features

面向真实开发工作流的核心能力

AgentDock 重点解决“本地 AI 工具如何稳定进入工程生产流”的问题，而不是停留在一次性的 prompt 对话。

P

项目管理

以工作区为核心组织 AI 任务，支持项目选择、归档、恢复、删除与后续文件夹打开流程。

C

会话管理

将每次 CLI 调用沉淀为会话记录，支持按项目查看、归档与持续追踪，避免终端输出丢失。

M

模型切换

统一展示 CLI 与模型列表，例如 Grok 的 coding 模型、MiMo 的 v2.5 系列，并保留用户偏好。

CLI

实时运行输出

实时捕获命令行输出，支持流式展示、错误追踪与后续结构化解析，适配本地运行习惯。

DB

本地记忆系统

将项目规则、偏好、会话摘要与历史结论保存在本地，为后续请求提供稳定背景。

@

上下文注入

运行前自动拼装当前请求、项目记忆、会话记忆与最近消息，让 CLI 输出更贴合工程状态。

Interface preview

模拟界面：像 IDE 一样管理 AI CLI

深色桌面界面贴近 Codex / Cursor / VSCode 的工作体验，左侧管理项目与会话，右侧完成任务输入、模型切换与输出查看。

Architecture

技术架构：本地优先，可插拔扩展

AgentDock 的核心是 Electron 桌面端 + CLI 适配器 + 本地存储 + 上下文编排。每个 CLI 都可以通过 adapter 接入统一的检测、运行和模型选择流程。

Renderer UI

负责项目、会话、模型选择、运行输出、归档面板与用户交互。

React / AppShell

IPC Bridge

将前端操作安全转发到主进程，统一处理 CLI 运行、工作区与设置。

preload + ipc.ts

CLI Adapter

每个 AI CLI 拥有独立适配器，声明命令、模型、thinking 选项与运行参数。

grok / mimo / future

Local Memory

项目、会话、消息、偏好和上下文摘要都存储在本地，保障可控与可追踪。

SQLite / workspace.json
Roadmap

未来规划：从 CLI 聚合到 Agent 工程中枢

当前阶段聚焦本地 AI CLI 的可用性和统一体验，下一阶段将扩展为更完整的本地 Agent 工作流平台。

Phase 01

更多 CLI 接入

扩展 Claude、Codex、Qwen、Gemini 等适配器，形成统一的本地 AI 能力池。

Phase 02

结构化运行结果

将 build、check、lint、test 等命令输出转为结构化报告，支持错误定位与回传修复。

Phase 03

插件系统

开放插件入口，让外部工具、MCP 服务、项目技能与自动化脚本进入 AgentDock。

Phase 04

闭环 Agent 流程

支持“生成、运行、诊断、修复、验证”的多轮自动化工程闭环。

AgentDock 的目标：让本地 AI CLI 从“命令工具”升级为“工程伙伴”

它把分散的模型、命令、上下文和会话变成一个可管理、可扩展、可沉淀的桌面控制台，为开发者提供真正贴近本地工程的 AI 工作流。
