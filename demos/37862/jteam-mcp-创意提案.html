① 创意介绍

CS2 饰品交易自动化 MCP 服务 — 一款基于 Spring Boot + MCP 协议的 AI 工具服务，让 AI 助手能直接操控 BUFF、C5Game、ECO、Steam 四大平台，完成从查询库存、上架商品、到接受交易报价的完整交易链路。


要解决的问题： CS2 饰品交易玩家需要同时在多个平台之间来回切换——BUFF 查看在售、C5 管理订单、ECO 确认发货、Steam 接受报价和手机令牌确认。整个过程重复、耗时、容易遗漏。


为什么做这个： 作为 CS2 饰品交易者，每天需要花费大量时间手动处理上架、改价、发货、确认等重复操作。MCP（Model Context Protocol）让 AI 助手拥有了操作外部系统的能力——为什么不让 AI 来干这些脏活？


产品形态： MCP Server（后端服务），可对接任何支持 MCP 协议的 AI 客户端（Cursor、Windsurf、Claude Desktop 等），通过自然语言指令操控交易全流程。

② 目标用户及痛点

核心用户： CS2 饰品交易者、皮肤商人、多平台搬砖玩家


使用场景：

  • 每天定时检查各平台待发货订单，逐单发货
  • 上架新库存时，需要同时在多个平台操作
  • 接受 Steam 交易报价，配合手机令牌确认
  • 需要及时了解各平台的价格行情

当前痛点：

  • 碎片化严重： 4 个平台、4 套账户、4 种操作方式，来回切到崩溃
  • 重复劳动： 批量上架 100 件商品，要在每个平台重复操作 100 次
  • 容易遗漏： Steam 报价有时限，错过窗口期就会影响信誉
  • 时间成本高： 每天至少花 1-2 小时在交易操作上

③ 系统架构

💬 AI 客户端 → 📡 MCP 协议 → ⚙️ JTeam MCP Server → 🌐 多平台 API → 📦 订单落库

用户通过自然语言与 AI 对话，AI 通过 MCP 协议调用后端服务，自动完成多平台交易操作


核心能力：

  • 统一的 MCP 工具接口，屏蔽各平台差异
  • 自动管理登录态（Cookie/Session/Token）
  • 内置 Steam CDN 代理，解决国内网络直连问题
  • 支持手机令牌自动确认（Steam Guard）
  • 支持手机号/邮箱+密码 + 易盾验证码登录 BUFF
  • 批量处理、统一落库、结果汇总

⑥ 为什么用 TRAE + MCP

这个项目不是做一个独立的 App 或网页，而是做了一个 MCP Server——让 AI（TRAE、Cursor、Claude 等）直接拥有操作交易平台的能力。


传统方案：用户需要自己登录各个平台 → 找到功能入口 → 手动填表 → 重复操作

MCP 方案：用户对 AI 说一句话 → AI 理解意图 → 自动调对应工具 → 完成操作并汇报结果


这就是 MCP 协议的意义——让 AI 从"聊天机器人"变成"能干事的人"。
