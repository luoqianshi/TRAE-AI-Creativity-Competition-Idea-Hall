课搭子

把散落在聊天里的校园事务，
重新关联起来。

一个为大学校园信息链路而生的协作 App。

SCROLL
01 / 创意介绍

从一条扁平的消息流，
到一张各归其位的课表。

大学校园里，辅导员和老师发布的通知、任务、文件、调课信息全部散落在 QQ 群和微信群里。文件会过期，任务写不清，调课没看到，重要的事被聊天淹没。现有的聊天软件本质上是即时通讯工具，根本不适合管理结构化的校园事务。

创意名称
课搭子 课的搭子，校园事务各归其位。
产品形态
Web + 移动端校园协作 App。以课表为主轴，把任务、文件、通知关联到课节上，发布方与接收方共享同一套结构化信息。
灵感来源
上大学时深受其害——重要任务淹没在群消息里，等催了才发现；文件没及时存就过期了；调课通知没看到走错教室；任务要求不清楚做了返工。QQ、微信、学习通都是聊天工具，本质上无法解决"信息关联"的问题：文件不跟任务绑定，任务不跟课节绑定，调课不跟课表绑定。一切信息都是扁平的消息流，这才是所有痛点的根源。
CORE IDEA

关联，而非堆砌。

QQ/微信最根本的失败，不是功能不够，而是所有信息都是一条扁平的消息流。课搭子的差异化不在"也有课表、也有任务"，而在把文件、任务、课节、事件重新关联起来。

02 / 目标用户及痛点

一条信息链路，
六处崩塌。

信息从发布者（辅导员/老师/班委）→ 班委 → 学生的传递链路，在 QQ/微信里全面崩塌。崩塌的方式有好几种，每一种都是真实的痛。

发布方

辅导员 / 老师 / 班委

发布通知、布置任务、收作业、发起填表和抽签。现状是靠 QQ 群 + @所有人 + 截图接龙，管理粗放，反复催办，写不清要求还要被反复问。

接收方

大学生

查看课表、接收任务、提交作业、找回文件。现状是重要信息被聊天淹没，靠手动翻记录、靠同学提醒、靠班委催，错过就焦虑。

  1. 01

    信息淹没，分不清轻重缓急

    重要和不重要的通知全混在聊天里，扫一眼分不出优先级。等催了才发现某个任务很麻烦且很重要，紧赶慢赶地改。

    INFORMATION
    OVERLOAD
  2. 02

    文件过期，且不跟任务关联

    QQ 定期清理群文件，当时不存就没了。文件散落在聊天里，不跟任务/课节绑定，找的时候只能翻记录，翻到发现已过期。

    FILE
    DECAY
  3. 03

    任务要求不清，反复返工

    辅导员写不清要求，学生理解不了，做了不符合条件，反复私聊确认、返工。发布者难受，接收者更难受。

    AMBIGUITY
  4. 04

    调课散落，看课表才发现

    调课、教室变动通知发在群里，不看通知的人到上课时才发现走错教室。通知和课表是两套分离的系统。

    DISCONNECT
  5. 05

    线下收交脱节

    "下节课前收 XX"这种任务跟课节没有任何关联，学生不知道是哪节课、什么时间、在哪收。任务和课表是两个世界。

    NO
    BINDING
  6. 06

    重复劳动：填表、抽签

    填表、抽签是高频操作，但每次都要重新建外部表单或用接龙，没有统一的工具，散落在各个群和平台。

    REDUNDANCY
03 / 价值与意义

不只是效率，
更是校园协作的进化。

VALUE 01 / 效率提升

从"靠群消息+靠人提醒"
到"结构化+自动化"。

把散落在聊天里的扁平信息重新关联起来——文件↔任务↔课节↔事件。学生不再花时间翻聊天记录找文件、猜任务要求、补救遗漏；辅导员不再反复回答同样的问题、催交作业。AI 辅助发布者把任务写清楚，AI 辅助接收者提问澄清，从源头减少沟通损耗。

VALUE 02 / 社会价值

让校园协作
不再消耗心智。

大学是每个人进入社会前的重要阶段，信息管理能力的缺失不只是效率问题，更影响学习体验和心理健康——错过重要事务的焦虑、被群消息淹没的失控感。课搭子让校园协作从"靠群消息+靠人提醒"进化到"结构化+自动化"，把心智还给学习本身。
