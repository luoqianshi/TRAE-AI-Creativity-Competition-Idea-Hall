核心概念

六个打工人每天都在面对的痛点，六个你从没想过AI能帮你做的事

每个打工人都经历过这些时刻：周五编周报、会议纪要吃灰、上周踩的坑这周再踩、每天刷信息流怕漏消息。Workboard 不是又一个聊天工具，是一套会记住你、理解你、主动帮你的工作系统。你正常工作，它自动记录；你上传文档，它自动提炼成知识；你早上打开，它已经帮你扫完情报；你要写周报，它已经帮你整理好了。

痛点

打工人的六个日常噩梦

不是做不了，是没人帮你做。

①
编周报
明明干了活却要从零编，每周五的噩梦。写周报不是写日记，要捡重要的、上级关心的事来汇报，要体现成果。
②
经验留不住
每次对话从零开始，经验和想法攒不下来。上周踩过的坑这周再踩，用了一个月和用了一天没有区别。
③
信息焦虑
每天刷30分钟信息流还是怕漏重要消息。信息越来越多，但和自己相关的到底有哪些？
④
文档吃灰
会议纪要、培训材料、项目复盘，存进文件夹就再也没看过。文档存了等于没存。
⑤
任务排队
串行推进没效率，一件事做完才能做下一件。分散到多个对话又翻不回结果。
⑥
知识不增长
工具不会自己获取新信息，不会自己长进。全靠个人经验打磨，天花板很低。
功能一 · 对应痛点①
📝
工作日报/周报
痛点：编周报 → 解法：你正常工作，日报自动生成
AI 蒸馏生成 核心
  • 对AI说"写日报"或"今天工作已完成"
  • AI从今日对话记忆中蒸馏关键内容
  • 聚焦4要素：做了什么、展示了什么、成果、心得
  • 不是简单罗列，是AI判断重要性后提炼
自动存档 沉淀
  • 日报存入 wiki/工作日报/YYYY-MM-DD.md
  • 周报存入 wiki/工作周报/YYYY-MM-DD.md
  • 在Wiki知识库面板中直接查看历史报告
  • 报告本身就是知识资产，可被后续决策引用
核心差异：目前没有任何AI工具能做到"正常工作→周报自动生成"。其他工具要么让你手动填，要么只是格式化模板。Workboard是唯一一个由AI从工作过程中判断重要性、提炼成果、自动生成汇报的系统。
功能二 · 对应痛点②
🧠
记忆系统
痛点：经验留不住 → 解法：AI终于记住你了
三重记忆自动晋升 沉淀
  • 短期记忆（7天内）：当前在推进什么、阻塞什么
  • 长期记忆（跨7天或写入Wiki）：技术偏好、经验规则
  • Wiki知识库（永久资产）：按七大领域驱动决策
晋升路径 自动化
  • 对话要点自动写入 raw/
  • 蒸馏后晋升短期记忆
  • 关联 ≥ 7天晋升长期
  • 写入Wiki成为永久资产
核心差异：所有AI工具每次对话从零开始。Workboard是唯一一个"越用越懂你"的——上周踩过的坑不会再踩，上个月做的决策系统会引用来帮你判断。
功能三 · 对应痛点③
📰
晨报
痛点：信息焦虑 → 解法：你的私人情报官
六源情报采集 情报
  • 技术趋势 / AI动态 / 商业信号
  • GitHub热门 / 投资信号 / 行业动态
  • 报纸风排版，5分钟扫完一天
蒸馏解读 + 自生长 进化
  • 不是原始信息堆砌，结合你的领域给出分析
  • 关键变化触发Skill进化提案
  • 你确认后才进化——人把关、AI提案
核心差异：不是新闻聚合器，是"你的私人情报官+分析师"。普通人从来没有过这种服务——每天早上打开，已经有人帮你扫完情报、提炼了和你相关的洞察。
功能四 · 对应痛点④
🔄
文档蒸馏
痛点：文档吃灰 → 解法：上传文档自动变活知识
AI 蒸馏管线 核心
  • 拖入PDF/Word/会议纪要/聊天记录
  • AI自动识别文档类型和结构
  • 蒸馏出：关键认知 + 决策依据 + 行动项 + 关联知识
  • 自动分类写入对应Wiki知识库
零门槛"第一口" 获客
  • 上传一份文档就能体验核心价值
  • 蒸馏结果自动进知识库，下次对话AI引用
  • 自然拉入完整系统：文档蒸馏→记忆→晨报→看板
文档蒸馏流程
上传文档 → AI蒸馏提炼 → 写入Wiki知识库 → 驱动后续决策

核心差异：ChatPDF能问答但对话完就完了，知识不会沉淀。Notion存了就存了不会活过来。Workboard是唯一一个让上传文档"活起来"驱动后续决策的系统。文档蒸馏还是Workboard的"第一口"——零门槛体验核心价值，然后自然拉入完整系统。
功能五 · 对应痛点⑤
⚡
并行看板
痛点：任务排队 → 解法：一个人同时搞定三件事
看板 × TRAE 融合 调度
  • 四列流程：需求 → 开发 → 验收 → 完成
  • 四种状态标记：🟢进行中 / 🟡待确认 / 🔴需操作 / ⏸️中断
  • 两层分离：流程层由人拖动，状态层由AI自己标
任务编号 + 并行开发 并行
  • 每个任务分配唯一编号，编号打通看板与CLI窗口
  • 多个任务同时推进，而非逐件排队
  • 每件事的结论都在看板上找得到
任务拆解 解耦
  • 按阶段拆解：调研 → 需求 → 设计 → 开发 → 测试
  • 按模块拆解：前端 ∥ 后端，互不干扰
  • 继续拆成子任务，进度条实时显示完成度
理论支撑 方法
  • 借鉴PMP快速跟进（Fast Tracking）
  • 依赖识别：硬逻辑必须串行，软逻辑可以并行
  • 关键路径法（CPM）驱动优先级排序
核心差异：Linear管项目但任务不在对话里跑，Cursor/Trae能干活但任务困在对话列表一次一件。Workboard是唯一一个把看板调度和AI任务执行打通的。
功能六 · 对应痛点⑥
📚
Wiki知识库
痛点：知识不增长 → 解法：经验变成决策依据
七大领域知识库 领域
  • 商业 · 关系 · 学习 · 健康
  • IP · 写作 · 创业
  • 每个知识库驱动对应领域的决策
活的知识 驱动决策
  • 不是静态存储，是活的——知识驱动决策
  • 你问"这个机会要不要追"，系统读知识库里的退出条件
  • 知识库之间联动：商业信号触发投资预警
  • 日报/周报也存入知识库，成为可引用的决策资产
核心差异：Notion/Obsidian是笔记软件，知识存进去是死的。Workboard的Wiki是活的——知识会驱动决策，经验会自动被引用，日报/周报也沉淀在知识库中成为可追溯的资产。
