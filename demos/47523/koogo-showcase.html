01 / THE PROBLEM

为什么 AI 总是"失忆"？

当前端侧 AI 长期记忆方案普遍采用「大模型 + 外部向量数据库」的 RAG 范式，存在四个层面的根本性断裂。

语义空间断裂

embedding 模型与生成模型使用不同表示空间，检索内容对生成模型而言是"外语"，需要额外注意力开销解读，实际利用率不足。

实现层断裂

跨平台方案依赖 C++ 核心 + Python 桥接 + 外部依赖（faiss / OpenSSL / ONNX Runtime），构建链路长，部署复杂。

设备协同断裂

记忆被锁定在单设备上。你在 Mac 上的对话记忆，无法在另一台设备上延续使用。

自我认知断裂

系统不记录自己的行为和输出。每次回答都像"初次见面"，无法从过去的错误中学习和进化。

03 / FOUR-LAYER STORAGE

四层投影存储架构

L3 持久存储为唯一事实源，L0/L1/L2 为只读投影缓存，以不同维度（时间/热度/邻接）加速检索。点击展开详情。

L0 瞬时写缓冲 · Ring Buffer 200 nodes

L3 事务提交后立即推入，填补 L3 提交到 L1 异步刷新间的可见性裂隙。L1 确认加载即删，硬超时 100ms 兜底。

DRAM 环形数组 原子索引 100ms 超时
L1 锚点缓存 · Dynamic Field 500 ~ 2000 nodes

承载动态场能量注入与多轮扩散的主体。能量注入 → 多轮扩散 → 收敛，仅从高激活节点（a_v > 0.3）传播。

map + RWMutex per-model 隔离 动态容量调整
L2 辐射缓存 · Graph Spread dynamic

L1 高激活节点沿有向边一步可达的邻居向量及邻居 ID 集合。供扩散时跨节点传播能量。

邻接表 邻居向量缓存 L2 内部扩散
L3 持久存储 · SQLite + HNSW full scale

唯一事实源。所有写入直接落 L3，ACID 事务保证。HNSW 向量索引 + SimHash 指纹 + K-Sparse 编码。

04 / RETRIEVAL PIPELINE

三阶段检索架构

从粗到精、从快到准。HNSW 粗排保证召回率，Cross-Attention 精排提升精度，一致性校验确保记忆与当前认知不冲突。

Cross-Attention 精排

多模态候选：query 作 Q，multimodalTokens 作 K/V，cosine(query, weightedV) 归一化评分。文本节点 cosine fallback。
