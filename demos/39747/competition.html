帮我分析一下 React 中 Redux、Zustand 和 Context API 各自的优缺点，以及适合什么场景？
🍴 Fork

Redux：成熟的状态管理方案，拥有强大的中间件生态（Thunk、Saga），适合大型应用和复杂状态逻辑。但样板代码较多，学习曲线较陡。

Zustand：轻量级替代方案，API 简洁，无需 Provider 包裹，支持持久化和中间件，适合中小型项目快速开发。

Context API：React 内置方案，零额外依赖，适合低频更新的全局状态（主题、语言）。但高频更新时性能较差。

💡 反直觉观点 🔬 实际案例 ⚡ 性能对比 🛠️ 最佳实践
Zustand 的性能表现如何？和 Redux Toolkit 比呢？

Zustand 性能优势：

• 基于 selector 精准订阅，只有被选中的状态变化才触发重渲染

• 无需 Context Provider，避免了不必要的组件树重渲染

• Bundle 体积仅 ~1KB（gzip），比 Redux Toolkit 小 10 倍以上

在大部分中小型场景中，Zustand 的性能表现优于 Redux Toolkit，尤其是频繁更新的状态场景。

核心功能

四维探索，深度思考

Graph Chat 提供完整的非线性对话体验，从分叉到合并，每个环节都为深度思考而设计。

01

任意回复分叉

选中 AI 回复中的任意文字，一键 Fork 创建新分支，继承上下文继续探索。

02

智能探索标注

每次 AI 回复后自动生成 3-5 个探索方向提示：反直觉观点、跨域类比、真实反例等。

03

多分支合并

选中多个探索分支，AI 自动综合各方结论，生成统一的深度分析报告。

04

上下文摘要

每个消息节点独立存储上下文摘要，分叉时精准继承，避免冗余 Token 消耗。

价值与意义

为什么 Graph Chat 重要

它不仅是一个工具，更是一种全新的 AI 对话范式。

⚡ 效率提升

传统方式探索同一话题的 5 个角度需要开 5 个对话窗口，重复输入背景信息。Graph Chat 在一个对话中完成所有探索，上下文自动继承，Token 消耗降低 60% 以上。

🧠 认知升级

线性对话强迫思维单向流动，而真实思考是网状的。Graph Chat 还原了人类思维的本来面貌——发散、分叉、收敛，让 AI 真正成为思维的延伸而非替代。

📚 知识沉淀

每一次探索都以可视化的对话树保存，形成结构化的知识图谱。相比散落在各处的聊天记录，这是可复用、可分享、可回顾的知识资产。
