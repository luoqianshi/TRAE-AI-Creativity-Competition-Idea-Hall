OASIS·万象引擎

OASIS Panorama

一、创意名称 + 创意介绍

创意名称
OASIS·万象引擎（OASIS Panorama）
想解决什么问题
开源多智能体仿真系统 OASIS（MiroFish 的底层引擎）架构本身通用，但实现层深度耦合了社交平台——Agent 的交互动作只有发帖、评论、点赞、转发，角色画像字段是 karma、follower_count 这类社交指标。这意味着它只能仿真"网友怎么吵"，无法仿真"医生怎么问诊""老师怎么授课""面试官怎么追问"。每想做一个新的非社交场景，都得从零重写一套交互逻辑。
为什么会想到做这个
研究 MiroFish 时发现，它的多智能体 + 长期记忆 + 群体涌现机制，本质上是一套通用的"角色仿真底座"，只是被社交场景"锁死"了。如果把"场景"和"交互动作"从引擎里抽象出来做成可插拔模块，同一套引擎就能跑医生、老师、面试官、客服等任意角色场景。先在"学习工作"赛道落地几个高频角色，再开放自定义。
大概是什么产品
基于 OASIS 二次开发的多角色仿真引擎/平台：内置场景模板（医生、老师、面试官等）与交互动作库，用户上传案例材料即可启动对应角色的多智能体仿真，同时支持用户自定义新场景与新交互动作。

二、目标用户及痛点

面向哪些用户
需要角色仿真但不想从零搭建的开发者与机构——医疗培训方（医患沟通、诊疗推演）、教培机构（教学模拟、因材施教推演）、求职平台（面试官仿真）、企业培训（谈判/客服仿真），以及想自定义仿真场景的 AI 应用开发者。首发聚焦"学习工作"赛道的高频角色：老师、医生、面试官。
在什么场景下使用
  • 医学院学生与规培医生：上传一份病历，仿真多位"医生"会诊推演诊疗方案与医患沟通
  • 师范生与新教师：上传一份教案，仿真"老师"授课与"学生"课堂反应，推演教学效果
  • 求职者：仿真"面试官"多轮追问，推演面试走向并复盘
  • 开发者：基于引擎自定义任意角色场景（如律师-当事人、心理咨询师-来访者）
当前痛点
要用多智能体仿真非社交场景，目前只有两条路：一是从零搭建，成本高、周期长；二是硬套 OASIS，但它的交互动作和角色字段都是社交逻辑，强行改造容易"四不像"。缺少一个"开箱即用、场景可插拔"的通用角色仿真底座。

三、价值与意义

效率提升
把"搭一套多智能体仿真"的门槛从"重写引擎"降到"填一个场景模板"。医疗、教育、招聘等领域的开发者无需重复造轮子，上传案例材料即可启动专业角色仿真，把原本数月的仿真系统搭建压缩到小时级。
社会价值
让高质量的角色推演不再是大机构的专利。医患沟通训练、教学模拟、面试演练这类"吃经验"的能力，可以通过仿真被规模化、低成本地复制，惠及规培医生、师范生、求职者等广大学习者群体。

四、可行性说明（关键问题回应）

为验证创意逻辑闭环，对五个关键问题作出回应：
1. 场景定义从哪来？
内置场景模板预置角色的领域知识、行为流程与交互动作（如医生模板含问诊/查体/下医嘱动作，接入医学指南约束；老师模板含讲授/提问/反馈动作，接入教学大纲约束）。用户只需提供具体案例材料（一份病历、一份教案），无需自行定义整个场景。
2. 仿真输出专业可信吗？
通过接入领域知识库（医学指南、教学大纲、面试题库）约束智能体行为，并提供"专家校正"环节。定位是"推演辅助训练"而非"替代专业诊断/教学"，输出用于训练与复盘而非直接决策。
3. 角色人格怎么来？
场景模板预置典型角色画像（如"资深主治医师""严厉型老师""压力型面试官"），用户可调参数；对象角色（患者、学生、求职者）由用户提供或 LLM 基于模板生成，仿真前可预览校正、仿真中可上帝视角修正。
4. 会不会样样松？
引擎层做三层抽象：场景模板 + 交互动作库 + 评估指标。首批只做透"学习工作"赛道 3 个高频角色（老师、医生、面试官），验证模板机制可复用后，再开放用户自定义新场景，避免一上来就铺开。
5. 比现有方案强在哪？
比"从零搭多智能体仿真"省时省力（站在 OASIS 肩膀上）；比"规则化模拟器"更真实（智能体有人格、有记忆、会涌现）；比"纯 LLM 单体角色扮演"更有群体互动（多智能体协作与博弈，而非一对一对话）。
