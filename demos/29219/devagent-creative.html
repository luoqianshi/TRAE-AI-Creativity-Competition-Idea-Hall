§ 1 VALUE PROPOSITION

为什么独立开发者需要 DevAgent

一个人要干十个人的活——产品 / 设计 / 开发 / 测试 / 运营 / 客服 / 财务。流程混乱、文档缺失、做了 2 周就半途而废。市面上的 AI 工具都是单点的，没人帮你跑完端到端流程。

§ 2 DESIGN PRINCIPLES

三个关键设计原则

⛁
LOCAL-FIRST

本地优先

默认在本地运行，数据不出本机。代码、想法、文档都存在项目目录里，可被 Git 管理。技术人员最在意数据安全。

$
SCRIPTABLE

可脚本化

所有操作既能交互也能命令。融入 CI/CD、自动化脚本，习惯用 terminal 的开发者零学习成本。

⟶
PROGRESSIVE

渐进式

不一次性全做完，按阶段推进。让用户随时"打断 / 继续"，避免 AI 失控生成一坨没人敢用的代码。

§ 3 CORE MODULES

5 个核心模块 · 完整覆盖"想法 → 运营"

按生命周期顺序：想法孵化 → 设计架构 → 开发测试 → 上线发布 → 运营增长。每个模块有明确入口命令和产出物。

M1
PHASE 01

想法孵化器 Idea Incubator

devagent init <idea>
  • 产品想法记录卡（自动结构化）
  • 竞品分析报告（自动爬 3-5 个）
  • 完整 PRD 文档
  • MVP 范围表 + 成功指标建议
输出： docs/01-product/
├── idea-log.md
├── market-research.md
├── prd.md
└── mvp-scope.md
M2
PHASE 02

设计与架构师 Design & Architect

devagent design | devagent next
  • 信息架构图（页面结构树）
  • UI 设计规范（配色/字体/间距/阴影）
  • 关键页面原型（ASCII / SVG 线框图）
  • 技术栈选型 + 数据库 Schema + OpenAPI 3.0
  • 里程碑计划 M1-M5
亮点： 设计规范用 JSON 描述，
可一键生成 Tailwind 配置；
数据库 Schema 直接用 Prisma 跑。
M3
PHASE 03

开发与测试工程师 Dev & QA

devagent code | devagent next
  • 完整代码（前端/后端/数据库）
  • 代码规范配置（ESLint + Prettier）
  • 自测清单 5 大类 20+ 细项
  • Bug 跟踪表 + 单元 / E2E 测试用例
  • 每日开发 Checklist
约束： 默认生成"骨架代码"
（关键文件 + 关键逻辑），
复杂业务逻辑必须人工实现。
M4
PHASE 04

上线发布官 Release Captain

devagent ship
  • 上线前 Checklist（30+ 细项自动核对）
  • 灰度发布方案 + 回滚方案
  • Changelog（自动从 commit log 生成）
  • 隐私政策 / 服务条款模板
  • 部署脚本（Vercel/Netlify/Docker）
检测： devagent ship --check
自动扫描项目状态、
列出未完成项。
M5
PHASE 05

运营增长官 Growth & Ops

devagent grow
  • 运营日历（每周/每月/每季度）
  • 数据看板（DAU / MAU / 转化 / 留存）
  • 用户反馈管理（收集/分类/回复）
  • 内容生成（博客/社媒/Product Hunt 稿）
  • 增长策略（冷启动/增长期/稳定期）
  • 财务记账（收入支出 + 税务提醒）
亮点： 内容生成带"风格学习"，
喂 5 篇你写的文章，
AI 就学会你的语气。
§ 4 ARCHITECTURE

产品架构 · 本地 daemon + 三种使用方式

FRONTEND · CLI

终端用户

  • 敲命令触发阶段
  • 流式输出 LLM 结果
  • 可脚本化、CI/CD 友好
→
CORE · DAEMON

本地服务

  • 监听命令 / HTTP
  • 管理项目状态机
  • 调用 LLM / 第三方 API
  • 数据本地存储（SQLite）
FRONTEND · WEB UI

浏览器用户 (localhost:port)

  • 可视化看文档 / 调原型
  • 在 Web 上 review 和编辑
  • 数据不离开本机
⌨ CLI 命令

场景：自动化、CI/CD、习惯命令行
优势：高效、可脚本化

◉ 本地 Web 界面

场景：复杂操作（看原型、调文档）
优势：直观、可视化

▣ TUI 终端界面

场景：远程服务器、无浏览器环境
优势：极客、SSH 友好

§ 5 COMMAND CHEATSHEET

核心命令速查

每个命令既能交互执行，也能塞进 shell 脚本 / Git hooks / CI 流水线。

// 项目管理
devagent init <idea>初始化项目（输入想法）
devagent status查看当前进度（5 阶段 + 子任务）
devagent next进入下一阶段
devagent back回到上一阶段
devagent reset重新生成当前阶段
// 文档操作
devagent open打开本地 Web 界面（localhost:port）
devagent edit <file>用 $EDITOR 打开生成的文档
devagent update <stage>用最新想法更新某阶段
// 阶段操作
devagent design重新生成设计与技术方案
devagent code重新生成骨架代码
devagent ship准备上线（部署 + Checklist）
devagent grow进入运营模式
// 高级操作
devagent config修改配置（LLM / 模板 / 端口）
devagent template add <url>添加自定义模板
devagent llm switch <model>切换 LLM（GPT-4/Claude/Ollama）
devagent export导出整个项目为压缩包
§ 6 ROADMAP

4 个里程碑 · 18-26 周交付

拆成 4 个里程碑渐进交付，每个 M 必须有可验证的产出，避免 6-12 个月开发周期失控。

M1 · 4-6w

想法 → 文档

累计 4-6 周
  • 模块 1：想法孵化器
  • 模块 2：设计与架构师
  • CLI + 本地 Web 界面
  • 5 个项目模板
目标：1,000 早期用户 / 50% 走完 M1 全流程 / NPS > 40
M2 · 6-8w

技术方案 → 代码

累计 10-14 周
  • 模块 3：开发与测试
  • 代码生成引擎
  • Bug 跟踪
  • GitHub / GitLab 集成
目标：5,000 注册用户 / 3,000 跑完 M2 流程
M3 · 4-6w

代码 → 上线

累计 14-20 周
  • 模块 4：上线发布官
  • 一键部署
  • 灰度发布
  • 监控集成（Sentry/Umami）
目标：15,000 注册用户 / 月活 5,000+
M4 · 4-6w

上线 → 运营

累计 18-26 周
  • 模块 5：运营增长官
  • 运营仪表盘
  • 内容生成器
  • 模板市场
目标：50,000 注册用户 / 独立开发者圈层 Top 3
