痛点 · Pain Point

从"排队等取数"到"一句话出看板"

企业数据分析长期困在"提需求 → 等取数 → 反复改图"的低效循环里。Lango 用 AI 把整条链路压缩到分钟级。

传统方式

以"天"为单位的取数制图循环
  • 1业务提需求，排队等分析师排期
  • 2分析师理解口径、手写 SQL 取数
  • 3整理数据、手动制图、调排版
  • 4口径不对 → 反复改图、反复取数
  • 5口径散落 Excel，下次重来一遍

Lango 方式

以"分钟"为单位的自助看板
  • 1输入一句话需求，选择数据源
  • 2AI 自动生成草稿看板 + SQL
  • 3对话式迭代，生成候选预览
  • 4确认应用，发布并定时刷新
  • 5口径与 SQL 沉淀，多看板复用
90s简单看板从需求到草稿
核心能力 · Capabilities

8 项能力，让 AI 生成的看板真正可用

不只是"生成"，更在生成之后保证可控、可审查、可复用、可发布。

自然语言创建

首页输入"近 30 天各区域销售趋势对比"，选数据源即可生成完整看板，无需写 SQL。

数据连接 + 数据源双层

数据连接管连接配置，数据源管表与视图。同源可被多个看板复用，沉淀企业口径。

候选版本机制

AI 生成或对话修改先产生候选版本，用户确认应用后才覆盖草稿，降低误改风险。

确认才应用

对话式迭代

对话提出修改，生成候选预览，确认后应用。口径调整像聊天一样自然。

业务 / 分析师双角色

业务模式强调自然语言修改；分析师模式开放 SQL 数据集面板，复用口径。

SQL 透明可审查

每个图表组件可查看对应 SQL、数据源、执行状态。仅生成只读查询，业务用户不能执行任意 SQL。

发布与定时刷新

发布看板并设置刷新频率：手动 / 每小时 / 每天 / 每周，按计划自动刷新数据。

草稿 / 发布分离

编辑器处理草稿与候选；查看页仅展示已发布版本。编辑不影响线上，稳定可控。

产品流程 · Workflow

从一句话到上线，五步完成

每一步都为"可控"设计：生成有候选、应用需确认、发布可刷新。

1

输入需求

用一句话描述想看的看板，如"各区域销售趋势对比"。

2

选择数据源

从已纳管的数据连接中选表或视图，复用企业口径。

3

AI 生成草稿

AI 编排 SQL 与图表，生成候选草稿与组件，约 90 秒。

4

对话迭代

对话提修改，生成候选预览，确认后才应用覆盖草稿。

5

发布刷新

发布到查看页，设置定时刷新，线上看板自动更新。
