核心痛点 × 解决方案

从真实需求出发，用技术解决问题

以下是产品发起人从实际生活中观察到的四大核心痛点，以及壹教授对应的解决方案

❌ 痛点一
病人医疗知识欠缺，咨询资源少，真正的签约家庭医生还没有进入百姓生活。

普通人缺乏医学常识，生病时不知道该挂什么科、吃什么药、是否需要紧急就医。网上搜索信息鱼龙混杂，而正规的家庭医生签约服务尚未普及到普通家庭。
→
✅ 壹教授方案
AI 全科专家咨询 — 对接 6 大主流大语言模型，构建"壹教授"30 年中西医全科专家人格。7×24 小时在线，随时回答健康问题，提供中西医结合的专业建议。
不只是问答，而是持续跟踪的诊疗关系：记住你的病史、了解你的家族情况、给出个性化建议。
🤖 多模型引擎 + 🎓 专家人格 + 💬 中西医融合
❌ 痛点二
病人缺乏终生电子病历，每次就医/咨询都无法完整回顾过往病史及相互影响。

传统病历分散在各家医院，患者自己记不住吃过什么药、做过什么检查、得过什么病。不同医生之间信息不通，导致重复检查、用药冲突、漏诊误诊。
→
✅ 壹教授方案
终生电子病历系统 — 为每位家庭成员（本人、父母、配偶、子女、亲友）建立独立账号和完整健康档案。
每次 AI 咨询自动生成结构化病历，毫无遗漏地考虑过往病史、用药记录、手术史及其相互影响。支持医院纸质病历拍照录入，实现全生命周期健康管理。
📄 自动病历生成 + 👥 多成员管理 + 🔍 全文检索
❌ 痛点三
医院看病存在人为失误风险，患者缺乏专业能力审核诊断和用药方案。

医生也是人，也会疲劳、疏忽。开错药、剂量错误、漏诊重要并发症等情况时有发生。普通人没有医学知识，无法判断医生的诊断和处方是否存在重大失误。
→
✅ 壹教授方案
就医重大失误辅助预警 — 将医院的诊断结果和用药方案拍照或文字录入系统，AI 基于患者的完整病历进行交叉审核：药物相互作用检测、过敏史冲突预警、剂量合理性分析、诊断与症状一致性校验。
不是替代医生，而是作为"第二双眼睛"帮助把关，避免人为失误。
⚠️ 药物互作用 + 🚫 过敏冲突 + 📊 剂量审核
❌ 痛点四
遇到医疗问题时只能依赖"找熟人医生"，缺乏客观公正的第二意见来源。

很多人看病习惯找认识的医生帮忙看看，但熟人关系可能带来：不好意思追问细节、碍于面子不敢质疑、医生可能因人情而放松标准等问题。
→
✅ 壹教授方案
客观公正的 AI 第二意见 — 壹教授没有"人情包袱"，基于纯粹的医疗数据和专业知识给出建议。它会：
• 如实指出可能的诊断遗漏
• 客观评估治疗方案的风险收益
• 提醒你该追问医生的哪些问题
• 帮你理解医学术语的真正含义
让你带着知识走进诊室，而不是带着困惑。
🔎 无偏见分析 + 💬 医患沟通助手 + 💡 决策支持
延伸痛点

更广阔的社会背景

除上述四大核心痛点外，当前家庭医疗健康还面临以下系统性挑战

💁

基层医疗资源不足

优质医生集中在大城市三甲医院，基层和偏远地区居民难以获得专业医疗咨询。挂号难、排队久、问诊时间短成为常态。

📈

家庭健康管理缺失

大多数家庭缺乏系统的健康档案管理工具。过敏史、慢性病、用药记录散落在各处，就医时无法快速提供完整病史。

🎯

家族医学信息断层

家族过敏史、遗传病风险等关键医学信息在家庭成员间无法有效共享。一人确诊某种疾病后，其他成员往往不知情。

🔒

隐私安全顾虑

用户担心将敏感健康数据上传云端存在隐私泄露风险。现有方案缺乏有效的本地隐私保护机制。

技术亮点

硬核技术突破

解决真实工程难题的技术方案

1

Flutter PlatformView 生命周期终极解决方案

解决了 USB 红外相机在 Flutter 中首次进入无图像的核心问题。经过 11 轮迭代，最终发现根因在于 mRenderHandler 的生命周期管理与 SurfaceTexture 复用策略冲突。

核心方案： • 移除 mNeedResumeCamera / mIsCameraResumed 标志位 • onConnect() 中无条件调用 mUVCCameraView.onResume() • fullRelease() 不调用 onPause() 以复用 SurfaceTexture • 效果：真第一次/假第一次/第二次进入/最小化 全场景通过
2

遗传风险计算引擎

实现了基于孟德尔遗传定律的风险评估算法，根据家族关系（一级/二级/三级亲属）和遗传模式精确计算每位家庭成员的发病概率。

支持的遗传模式： • Autosomal Dominant（常染色体显性）：一级亲属 50% 风险 • Autosomal Recessive（常染色体隐性）：一级亲属 67% 携带者风险 • X-Linked Dominant/Recessive（X连锁显性/隐性） • Mitochondrial（线粒体母系遗传）：子女 100% 继承 • Multifactorial（多基因遗传）：基因距离 x 0.3 系数
3

混合记忆 + 病历双驱动的 Prompt 工程

独创的"混合记忆模式"——每次对话时同时加载：患者基础档案 + 家族医学上下文 + 相关历史病历（关键词匹配+时间衰减）+ 最近对话记忆，构建完整的 AI 诊断上下文。

Prompt 组装顺序： 1. 医生角色设定（壹教授人格） 2. 患者基础健康档案（核心记忆） 3. 家族医学史（家族数据共享） 4. 相关历史病历（Top 5，相关性 > 30%） 5. 最近对话记录（最近 10 条） 6. 回复要求 & 强制规则
4

本地优先的三级脱敏架构

所有敏感数据在设备本地完成脱敏后才发送至云端 API。三级脱敏策略平衡了隐私保护强度与大模型诊断所需的上下文完整性。

脱敏规则矩阵： ┌──────────┬──────┬──────┬──────┐ │ 数据类型 │ 低级 │ 中级 │ 高级 │ ├──────────┼──────┼──────┼──────┤ │ 手机号 │ ✓ │ ✓ │ ✓ │ │ 地址 │ ✓ │ ✓ │ ✓ │ │ 患者姓名 │ ✗ │ ✓ │ ✓ │ │ 亲属姓名 │ ✗ │ ✓ │ ✓ │ │ 身份证号 │ ✗ │ ✗ │ ✓ │ └──────────┴──────┴──────┴──────┘ 保留：医院名/药品/症状/检查/时间
5

Android Native + UVC + OpenCL 硬件驱动栈

在 Android 层完整集成了 libuvc（USB Video Class 驱动）、UVCCamera（相机控制）、OpenCL（GPU 加速温度计算）三层 Native 库，通过 JNI/Dart FFI 与 Flutter 层通信。

Native 技术栈： • libusb: USB 设备枚举与通信 • libuvc: UVC 协议解析（ISO Bulk 传输） • UVCCamera: Java 封装层（预览/拍照/录像/测温） • libjpeg-turbo: JPEG 硬件加速编解码 • OpenCL: GPU 并行温度场渲染 • PlatformView: Flutter 嵌入原生 SurfaceView

社会价值 — 普惠医疗

效率提升 — 全家守护

一次建档，全家受益。传统模式下每个家庭成员的健康信息是孤岛式的，而壹教授实现了家族间的医学数据自动流转——父亲确诊高血压后，系统自动提示子女也有较高的遗传风险并建议提前预防；母亲有青霉素过敏史，所有家庭成员的档案中都会标记这一家族性风险。AI 自动从对话中生成结构化病历，免去手工记录的繁琐，节省大量时间。

使用场景

四大典型场景

壹教授融入家庭日常健康管理的每一个关键时刻

💬

日常健康咨询

家人出现不适症状时（发烧、头痛、皮疹等），不确定是否需要紧急就医或该挂什么科。打开 App 向"壹教授"描述症状，获得中西医结合的初步建议和就医指引。

用户操作：打开 App → 选择患者 → 输入症状描述/上传照片 → 壹教授自动加载该患者完整病历+家族医学史 → 给出诊断建议
📋

就医前后辅助审核

去医院看完病后，将诊断结果和处方拍照录入系统。AI 基于患者完整病历进行交叉审核——药物相互作用检测、过敏史冲突预警、剂量合理性分析、诊断与症状一致性校验。

用户操作：拍照/文字录入医院处方 → 系统自动匹配过敏史+当前用药 → AI 审核输出：✔安全 / ⚠警告(药物互作用) / ❌危险(过敏冲突)
👥

家庭健康管理

为父母、配偶、子女分别建立独立健康档案，记录过敏史、慢性病、用药情况。系统自动在家族成员间共享关键医学信息，并基于遗传学原理计算每位成员的遗传疾病风险。

用户操作：添加家庭成员 → 填写基础健康档案(过敏/慢性病/用药) → 系统自动共享至家族网络 → 遗传风险计算器实时评估每位成员风险等级
🚶

红外热成像检测

连接 Xtherm 红外热成像 USB 相机，对家人进行体表温度分布检测。可用于监测局部炎症发热区域（如关节炎症、软组织损伤）、辅助中医体质辨识（通过体表温度分布模式）。

用户操作：USB 连接红外相机 → 实时预览热成像画面 → 选择色板模式 → 拍照/录像保存 → AI 分析热图数据(中心温/最高温/最低温) → 生成健康建议报告
