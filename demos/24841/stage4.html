📘 第四阶段

🧙 组合式 API

把相关逻辑"卷"在一起 — 告别散落一地的代码，像魔法一样优雅

核心概念

📜 两种写法：选哪一本"魔法书"？

Vue 3 同时支持两种写法，但 Composition API 是未来

📚
生活类比：整理房间 Options API 像传统衣柜：上衣一个抽屉、裤子一个抽屉。要找一套衣服要跑好几个抽屉
Composition API 像整理箱：把一套衣服放一起。要出门时拿一个箱子就行
🗂️ Options API
export default { data() { return { count: 0, name: '' } }, methods: { increment() { this.count++ }, updateName(v) { this.name = v } }, mounted() { console.log('挂载') } }
❌ 相关逻辑散落各处
📜 Composition API
import { ref, onMounted } from 'vue' export default { setup() { // 计数相关逻辑（在一起） const count = ref(0) const increment = () => count.value++ // 名字相关逻辑（在一起） const name = ref('') const updateName = (v) => name.value = v onMounted(() => console.log('挂载')) return { count, increment, name, updateName } } }
✅ 相关逻辑组织在一起
核心概念

🎬 setup 函数：一切逻辑的"起点"

Composition API 的入口，相当于组件的"魔法卷轴"

🎬
生活类比：电影剧本 setup() 就像剧本的"开拍前准备" — 演员到位（创建数据）、道具备好（创建方法）、一喊"action"就开演

📋 setup 的执行流程

组件创建
→
调用 setup()
→
返回数据
→
模板渲染
→
挂载到 DOM

⚠️ 注意：setup() 里 this 不是组件实例（是 undefined）

核心概念

📦 ref vs reactive：响应式数据的两种"包装"

让普通数据变成"自动感应"的魔法

📦 ref()

可以包装任何值。访问/修改需要 .value

📍 用于：基本类型（数字、字符串、布尔）
📍 特点：JS 中用 count.value，模板中直接用 count
const count = ref(0) count.value++ // JS 中要 .value
🎁 reactive()

只能包装对象。直接访问属性即可

📍 用于：对象、数组
📍 特点：深响应式，但解构会丢失响应性
const state = reactive({ count: 0 }) state.count++ // 直接访问
💡 简单记忆：不确定用什么 → 用 ref（更通用）。团队风格统一最重要！
核心概念

🧪 组合式函数 (Composables) — Vue 的"魔法卷轴"

把可复用的逻辑"卷"成函数，到处都能用

🧪
生活类比：魔法卷轴 哈利波特的魔法咒语（composable）可以反复使用："荧光闪烁"（useMouse）不管在哪都能用。把"配方"封装起来，按需调用
📜 useMouse.js

返回鼠标位置，自动追踪

export function useMouse() { const x = ref(0) const y = ref(0) const handler = (e) => { x.value = e.clientX y.value = e.clientY } onMounted(() => window.addEventListener('mousemove', handler) ) onUnmounted(() => window.removeEventListener('mousemove', handler) ) return { x, y } }
用法 const { x, y } = useMouse()
📜 useLocalStorage.js

自动同步到 localStorage

export function useLocalStorage(key, init) { const val = ref(localStorage.getItem(key) || init) watch(val, (v) => { localStorage.setItem(key, v) }) return val }
用法 const theme = useLocalStorage('theme', 'light')

核心概念

🪜 provide / inject：祖孙通信的"魔法传音筒"

祖先组件直接"隔空传物"给后代，跳过中间层

📢
生活类比：家族信托 爷爷（祖先）设立一笔信托（provide），所有孙辈（后代）都可以直接领取（inject），不用通过爸爸中转
// 祖先组件 provide('theme', 'dark') // 把 theme 提供出去 // 后代组件（可以是任意深层级） const theme = inject('theme') // 直接拿到！
🎮 互动演示：祖孙传值
👴 爷爷组件
provide('username', '小米')
👨 爸爸组件
不知道 'username'
👶 孙子组件
inject('username') → ?

💡 关键记忆点：
• Composition API = 把相关代码组织在一起，而不是按类型分（data/methods/...）
• Composable = 命名以 use 开头，封装可复用逻辑
• provide/inject = 解决"祖孙通信"问题，比 props 层层传更优雅
• 新项目首选 Composition API，逻辑复用和 TS 支持都更好
