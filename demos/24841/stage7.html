🧪 为什么需要测试？

好代码不仅要能跑，还要改不坏

🏥
生活类比：体检 vs 治病 写测试就像定期体检：没病的时候花点钱（时间），有病早发现。改 bug 像治病：病了再治（贵！痛苦！）

📊 测试金字塔

写测试也要讲究性价比：单元测试多、端到端测试少

🖥️ E2E 测试
模拟用户操作，测试整个应用
🔗 集成测试
测试组件之间的协作
🧩 单元测试
测试最小的代码单元（函数/组件）

由 Vite 团队开发，与 Vue 天然集成

// counter.spec.js - 测试一个简单的加法函数 import { describe, it, expect } from 'vitest' import { mount } from '@vue/test-utils' import Counter from './Counter.vue' describe('Counter 组件', () => { it('初始值为 0', () => { const wrapper = mount(Counter) expect(wrapper.text()).toContain('Count: 0') }) it('点击按钮 +1', async () => { const wrapper = mount(Counter) await wrapper.find('button').trigger('click') expect(wrapper.text()).toContain('Count: 1') }) })

核心概念

🌐 SSR：服务端渲染（更快、更SEO 友好）

理解客户端渲染和服务端渲染的区别

🍕
生活类比：外卖 vs 自己做饭 CSR：原料送到家（HTML），你自己做（JS 渲染）— 等得久
SSR：厨师做好送来（HTML 已包含内容）— 直接吃，更快
🖥️ CSR 客户端渲染（普通 Vue）

浏览器拿空 HTML，自己渲染

① 浏览器请求页面
② 服务器返回空 HTML + JS
③ 浏览器下载 JS
④ JS 执行，渲染页面 ⏳（慢）
⑤ 用户看到内容

❌ 慢、首屏白屏、SEO 不友好

🚀 SSR 服务端渲染（Nuxt）

服务器渲染好 HTML 再返回

① 浏览器请求页面
② 服务器执行 Vue 渲染
③ 返回已渲染的 HTML ✨（快）
④ 浏览器展示内容
⑤ 后续交互由 JS 接管（hydration）

✅ 快、首屏秒开、SEO 友好

🌟 Nuxt 3：基于 Vue 的全栈框架

🌐 浏览器请求 /about

✨ 浏览器显示（hydration 接管）

🔬
生活类比：拆手表 普通人戴手表（用 Vue），修表师傅拆开看（读源码）。你想成为大师？读源码是必经之路
# Vue 3 源码目录结构（简化） vue-next/ ├── packages/ │ ├── reactivity/ # 响应式系统（核心） │ │ ├── ref.ts # ref() 实现 │ │ ├── reactive.ts # reactive() 实现 │ │ ├── computed.ts # computed 实现 │ │ └── effect.ts # 依赖收集 & 触发更新 │ ├── runtime-core/ # 虚拟 DOM & 组件实例 │ ├── runtime-dom/ # DOM 渲染器 │ └── compiler-core/ # 模板编译器 └── examples/ # 示例代码
💡 推荐学习顺序：
  1. reactivity/ — 理解 ref/reactive 的 Proxy 魔法
  2. runtime-core/ — 理解组件实例 & 生命周期
  3. compiler-core/ — 理解模板怎么变成渲染函数
  4. 看尤雨溪的 Vue 3 源码解析视频
