01/04
Creative Introduction

创意名称与介绍

?

A想解决什么问题

复杂项目里任务之间存在错综复杂的依赖关系——谁阻塞谁、谁是关键路径、哪些可以并行。传统清单式待办软件无法直观呈现这种结构，导致排期混乱、漏掉前置任务、并行机会被白白浪费。

!

B为什么会想到做这个

在多分支开发、产品迭代、活动筹备等场景中，常因为"忘了某个任务还卡在另一件事上"而延期。市面上的甘特图笨重、待办 App 又太扁平，缺少一种"既能画依赖图、又能驱动执行状态"的轻量工具。

大概是什么产品

一款桌面级（Windows）可视化项目规划软件，包含图形化流程图编辑器、时间线视图、任务列表、依赖编辑器四大视图；附带 CLI 与 MCP Server 接口，可被 AI 编程助手调用以实现自动化任务管理。

Who uses it

个人开发者、小团队负责人、产品经理、活动策划者，以及任何需要拆解多步骤复杂项目并跟踪执行进度的人。

在什么场景下使用

When to use

项目立项拆解任务、排期与关键路径分析、执行阶段跟踪任务状态、直观显示项目结构与进度。

立项拆解关键路径分析状态跟踪进度汇报依赖编辑
i
工具两极分化：要么过重，要么过平
现有工具要么过于重型（MS Project、甘特图软件学习成本高、价格贵），要么过于扁平（待办清单看不到依赖关系和关键路径）。
ii
甘特图锁死时间轴，节奏太僵
现有甘特图软件一般面向团队协作、对工期安排要求严格——任务一旦排定就锁死在时间轴上，难以应对个人/小团队灵活多变的节奏。
iii
Plantree 的解法：手动启动，自由灵活
采用手动启动任务的方式，且对任务启动的限制并非强制性，用户可自由决定何时开始，任务安排更有灵活性。
iv
依赖变更需手工重排，极易出错
任务前置依赖关系一旦变更，需要手工重排极易出错；项目数据也难以被 AI 工具直接读写和自动化操作。

03/04
Value & Significance

价值与意义

01
效率提升

一眼识别瓶颈与并行机会

通过自动布局的依赖流程图 + 关键路径分析，帮助用户一眼识别瓶颈任务和可并行任务，减少因依赖遗漏导致的返工与等待。撤销/重做、批量添加、依赖链式连接等编辑能力让排期调整成本大幅降低。

手动启动机制且不强制依赖就绪，让排期不再被时间轴和依赖锁死，更适合灵活多变的实际工作节奏。

02
社会价值

让 AI 原生参与项目管理

项目数据采用开放 JSON 格式（.plantree 文件），并开放 CLI 与 MCP Server 接口，使 AI 编程助手可以原生地理解、查询、修改项目计划。

推动"AI 参与项目管理"的协作新模式，降低个人和小团队的项目管理门槛。

项目如树，任务如枝——既看得到结构，又留得住弹性；既给人用，也给 AI 用。

04/04
Product Features

产品特性一览

四大视图 + 三种接口 + 开放数据格式，构成 Plantree 的完整形态：人可点、命令可调、AI 可读写。

View 01

流程图编辑器

Graphviz 自动布局的依赖流程图，节点状态实时着色，关键路径一目了然，支持链式连接与拖拽编辑。

View 02

时间条视图

任务时间可视化，按工期与状态排布，直观展示任务时间，一目了然。

View 03

任务列表

结构化任务清单，批量多行添加并自动去除编号，配合详情面板快速编辑任务属性与状态。

View 04

依赖编辑器

可视化依赖关系矩阵/链路，新增、移除、链式连接一气呵成，环检测防止死锁依赖。

Interface · CLI & MCP

命令行 + MCP Server：让 AI 原生读写项目

同一套能力以 CLI（脚本自动化）与 MCP Server（AI 编程助手直连）两种形式开放：list / get / add / insert / dependency / start / pause / complete / export 等命令齐全。AI 助手可原生地理解、查询、修改项目计划，真正实现"AI 参与项目管理"。

Data

开放 JSON 格式

.plantree 文件为开放 JSON，含 globalDescription、elements、dependencies、version，可被任意工具读写。
