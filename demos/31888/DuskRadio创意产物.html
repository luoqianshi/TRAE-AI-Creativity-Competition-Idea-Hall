Pain Points

你是否也有这些困扰？

现有音乐平台的推荐，总是差点意思

推荐割裂，交互极浅

首页固定板块被动展示，用户无法深度表达需求。你不能说"我喜欢这个曲风，但今天想听更温暖的"，算法只能靠单次点击微弱修正，长期推荐偏差难扭转。

静态歌单，无沉浸感

零散单曲堆砌，歌曲生硬切换，没有转场、没有贴合当下心情的语音旁白，无法形成一整套连贯、有氛围感的听觉流程。

品味画像不可见、不可改

平台后台有你的听歌标签，但完全不开放。你看不到AI总结的曲风、情绪偏好，想调整喜好只能靠反复听歌，没有手动修改入口。

缺少情绪价值，只有工具属性

推荐只解决"听歌"，低落时不会主动安抚，不会挖掘收藏里落灰的老歌并赋予新的解读，推荐只是冰冷的内容分发，缺少惊喜与共情。

Core Features

六大核心能力

从品味分析到情绪陪伴，构建完整的私人电台体验

AI品味档案

从网易云导入历史听歌数据，AI自动分析生成可视化品味档案。支持自然语言对话校准，用户可手动修正标签，掌握推荐主动权。

DJ播报

AI像真人DJ一样，在歌曲之间用声音播报推荐理由、音乐故事、情绪安慰。结合时间、天气、日历动态生成，使用Fish Audio语音合成。

三层意图分流

快速直连（毫秒响应）→ 音乐元数据API（秒级）→ 大模型推理（深度智能）。兼顾性能与智能，自动匹配最优处理通道。

节律调度

预设定时任务：早间播报、通勤音乐、午休放松、下班模式、深夜陪伴。用户可自定义增删改，适配个人作息节奏。

情绪感知

AI通过对话、天气、时间、日历等多维度推断情绪。深夜自动降音量切舒缓模式，疲惫时播放治愈系歌单，用声音提供陪伴。

对话式交互

用自然语言与电台对话："今天心情不好，来点温暖的"。AI实时理解需求并调整策略，替代冰冷的"不感兴趣"按钮。

User Journey

下班回家后的电台体验

小林，25岁，500+首本地音乐收藏，对平台推荐长期不满

18:30 下班到家

打开Dusk Radio，节律调度自动触发"下班模式"。AI读取当前时间、天气（阴天）、日历（无晚间安排），结合品味档案生成播报。

"嘿，今天辛苦了，外面天阴阴的，来点温暖的歌吧"
18:36 无缝转场

第一首歌结束，DJ自动播报转场文案，无缝衔接下一首。歌曲之间有温度、有故事，不再是冰冷的切歌。

"这首旅行的意义，总能让人想起那些说走就走的日子。下一首，是一首你收藏很久但很久没听的歌——"
19:00 对话调整

小林对电台说："今天想听点更有力量的"。AI理解情绪需求，即时调整推荐策略，切换到摇滚/电子风格。

"收到，来点能让你充电的！"
22:00 深夜模式

深夜模式自动激活：音量降低20%，切换舒缓/轻音乐，DJ播报语调变轻柔。AI用温柔的声音陪你度过安静的夜晚。

Architecture

四层技术架构

Layer 4 交互表层 · PWA

Player播放页 · 品味档案页 · Profile个人页 · Settings设置页 | 6条HTTP接口 + WebSocket实时推送

Layer 3 运行时聚合层

Context Window 6片段动态拼接 → AI推理 → 结构化输出 {say, play[], reason, segue, mood}

Layer 2 本地大脑层

Router（意图分流）→ Context（提示词组装）→ Brain（大脑适配器）→ Scheduler（节律调度）→ TTS（声音管线）→ State.DB（状态存储）

Layer 1 外部上下文层

用户品味语料 · DeepSeek API · NetEaseCloudMusicApi · Fish Audio TTS

两大技术创新点

01 三层意图分流架构

绝大多数同类AI音乐项目要么全丢大模型，要么纯硬编码。本方案分层设计：快速直连（毫秒响应）→ 元数据API（秒级）→ 大模型推理（深度智能），兼顾性能与智能。

毫秒响应 分层路由 工程清晰
02 多源Context Window动态拼接

区别于简单一问一答调用LLM，将用户品味、环境（天气/日历/时间）、时序记忆、执行轨迹等多维数据融合组装上下文，直接支撑"懂情绪、懂日程、懂长期品味"。

多维融合 6片段拼接 记忆衰减
