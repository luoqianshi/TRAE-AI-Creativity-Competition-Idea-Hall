FieldOS：帮 AI 从业者把一个新领域真正学明白

AI 行业每天都有新产品、新观点、新玩法。问题不是找不到信息，而是信息太多、太碎，看完之后很难留下清楚的理解。FieldOS 想做的是：帮你围绕一个 AI 方向，有计划地学、跟进最新变化，并把学到的东西整理成自己的资料库。

AI 产品 运营增长 行业研究 策略判断 Coding Agent

一句话：FieldOS 不是给你更多链接，而是帮你把 AI 信息变成能理解、能复习、能用于工作的知识。

01 / Pain

现在学 AI 最大的问题：看了很多，却说不清自己到底懂了什么

比如我想学习 Coding Agent / AI Coding Tools，不只是想知道“今天谁又发布了新功能”。我更想知道：这个方向为什么重要？核心能力是什么？Claude Code、Cursor、Windsurf、Trae 这些产品到底在比什么？哪些做法值得我学习？

但现实是，资料散在 X/Twitter、YouTube、官方文档、GitHub、播客和邮件简报里。每条都可能有价值，但单独看都很碎，最后很容易变成收藏一堆链接，却没有形成自己的理解。

信息太快

每天都有新变化

产品更新、模型能力、工程实践都在变。靠偶尔刷到几条内容，很难跟上完整脉络。

资料太散

好内容不在一个地方

官方文档、真实产品建设者的观点、访谈、GitHub 讨论都可能有价值，但需要有人帮你整理到同一个主题下。

摘要太浅

知道结论不等于学会

很多摘要只告诉你“发生了什么”，但没有解释为什么重要，也没有帮你思考怎么用。

FieldOS 解决的不是“如何获得更多 AI 信息”，而是“如何把这些信息变成自己的长期理解”。

02 / Not This

它不应该变成又一个新闻摘要、课程平台或收藏夹

FieldOS 的重点不是“多给你一点内容”，而是让内容真的进入你的学习过程。你看过的资料，要能变成路径、问题、卡片、复盘和自己的判断。

新闻摘要

看起来有用：每天帮你总结 AI 新闻。

问题：看完很快忘，也很难知道它和你正在学的主题有什么关系。

传统课程

看起来系统：有章节、有目录、有学习路径。

问题：更新慢，跟不上 AI 产品和真实行业变化。

收藏夹

看起来省心：链接都保存下来了。

问题：保存不等于理解，过一周再看往往还是一堆未读材料。

纯问答工具

看起来方便：可以随时问一个问题。

问题：缺少长期学习路径，也不一定能整理成自己的知识库。

03 / User

第一批用户：需要懂 AI，但不一定每天写代码的人

FieldOS 第一版更适合 AI 产品、运营、增长、策略和研究类用户。他们可能不是工程师，但需要理解技术趋势、产品变化、竞品动作和行业机会，并把这些理解用到真实工作里。

场景 1

我想快速入门一个方向

比如 Coding Agent。用户需要知道它是什么、为什么火、有哪些代表产品、接下来该怎么学。

场景 2

我看到一个新动态

比如 Claude Code 发布 memory 功能。用户想知道：这件事为什么重要？它改变了什么？

场景 3

我要做工作输出

比如竞品分析、产品方案、内部分享、行业研究。用户需要的不只是资料，而是清楚的结构和判断。

场景 4

我想长期跟踪一个领域

用户不想每天被信息淹没，但也不想错过重要变化。FieldOS 应该帮他少看但看得准。

04 / Product

FieldOS 是一个 Web App：先从 Coding Agent 学习实验室开始

第一版不需要做成大而全的平台。更清楚的做法是先支持一个主题：Coding Agent / AI Coding Tools。用户可以选择 7 天入门、21 天系统学习，也可以随时把看到的新链接丢进来，让系统帮他理解。

低门槛入口

7 天入门

每天一个小主题，快速知道 Coding Agent 是什么、为什么重要、有哪些产品和下一步该学什么。

核心骨架

21 天系统学习

这是产品最重要的部分。它帮用户建立完整地图：概念、产品、人物、最佳实践、争议点和机会。

保持更新

长期持续追踪

当新功能、新观点、新案例出现时，系统不是简单推送新闻，而是告诉你它应该更新哪一块知识。

05 / How

它的工作方式很简单：找好资料，拆成任务，学完后留下卡片

FieldOS 会从官方文档、产品更新、GitHub、真实产品建设者的观点、YouTube、播客和邮件简报里筛选资料。然后把资料变成今天能完成的一次学习，而不是把所有内容一股脑丢给用户。

1

选主题

比如先学 Coding Agent。

2

找原文

优先找官方资料和真正做事的人的观点。

3

安排任务

把资料拆成今天能学完的小任务。

4

互动理解

用判断题、案例题和追问帮用户想明白。

5

生成卡片

留下概念、产品、人物、观点和案例。

6

每周复盘

告诉用户学了什么，还有哪里没想清楚。

06 / Two Ways

两个入口：一个帮你开始，一个帮你理解新东西

FieldOS 不应该把用户锁在固定课程里。它既要有学习路径，也要允许用户从一个新动态、新产品、新问题直接进入学习。

入口 A

计划式学习

  • 用户选择主题：例如 Coding Agent。
  • 选择学习方式：7 天、21 天或持续学习。
  • 每天完成一个清楚的小任务。
  • 适合“不知道从哪里开始”的时候。
入口 B

自主探索

  • 用户粘贴一个链接，或输入一个产品名、人物名、问题。
  • 系统判断它属于哪个知识点。
  • 生成一次短学习任务。
  • 适合“我看到一个新东西，但不知道它意味着什么”的时候。
07 / Library

最后留下来的，不是完成记录，而是自己的 AI 知识库

每次学习结束后，系统应该帮用户留下几张有用的卡片。以后做方案、写分析、准备分享时，可以回来看：我当时读了什么，怎么理解的，还有哪些问题需要继续追踪。

概念卡Agent Loop / Tool Use / Context
产品卡Claude Code / Cursor / Trae
人物卡Builders / Researchers / PM
观点卡我怎么看 / 为什么这样看
案例卡好做法 / 失败原因 / 可复用经验

一张好卡片，必须能回到原始资料

用户不能只看到 AI 总结。每张卡片都应该保留来源、引用片段、相关知识点和自己的理解。

来源来自哪篇文章、哪个视频、哪个 release note。
解释这条资料在讲什么，为什么值得看。
关系它和哪个概念、产品、人物或问题有关。
我的理解用户自己的总结、疑问和下一步想验证的判断。
08 / Value

它的价值：少刷一点信息，多留下一点真正有用的理解

对个人来说，FieldOS 可以减少找资料、读资料、整理资料的成本。对团队来说，它未来也可以变成 AI 产品、运营、研究人员的学习工具和知识库。

01

更省时间

不用每天到处翻资料，而是围绕一个主题看到真正值得学的内容。

02

更可信

每个总结都能回到原文，避免只看脱离上下文的二手说法。

03

更容易坚持

每天一个小任务，比“有空就学”更容易形成节奏。

04

更能复用

学完留下卡片、问题和判断，之后做方案或研究时可以直接用。

FieldOS 想帮 AI 从业者建立自己的长期学习库

它不是让用户看更多内容，而是让用户把内容看懂、想清楚、留下来，并在下一次遇到新动态时继续更新自己的理解。

最重要的一句话：FieldOS 要把快速变化的 AI 信息，变成用户自己的长期学习能力。
