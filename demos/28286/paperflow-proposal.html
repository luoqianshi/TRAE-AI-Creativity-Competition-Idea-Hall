💡01 创意名称 + 创意介绍

CREATIVE INTRODUCTION

创意名称：知流 PaperFlow —— 论文到公众号的自动化内容流水线

🔍 想解决什么问题：科研人员每天面对海量新论文，从 arXiv 发现、筛选到阅读总结需要数小时；而学术内容运营者要把一篇英文论文转化为可发布的中文公众号文章，还需要经历翻译、配图、排版、封面制作等重复劳动。两者之间缺少一条稳定、低成本的自动化连接。

💭 为什么会想到做这个：在实际学习中，我们发现导师和同学经常需要快速了解某个方向的最新进展，但手动读论文、做笔记、再写推文的流程太慢。我们希望用已有的 AI 能力和工程方法，把这条链路串起来，让「发现论文 → 理解论文 → 发布内容」变成一键操作。

📦 大概是什么产品：一套本地可运行的自动化系统，由 5 个协作模块组成，基于 MCP（Model Context Protocol）标准工具接口编排。用户输入研究主题关键词，系统自动完成论文检索、智能筛选、PDF 解析总结、主题封面生成和公众号 HTML 预览输出，全程保留可追踪的中间产物。

WITHOUT PAPERFLOW — 当前痛点

使用场景没有本产品时的不便
🔎 从 arXiv 找最新相关论文 手动翻页浏览，关键词检索产生大量弱相关结果，重复论文反复出现，摘要可能被截断
📄 理解一篇英文论文的核心贡献 需要逐页阅读 PDF，图表与正文割裂，难以快速提取关键信息和配图
📝 将论文转化为中文公众号文章 手动翻译 + 总结 + 配图 + 排版，单篇耗时 2-4 小时，格式每次都要重新调整
🖼️ 制作文章封面图 生图模型直接生成含中文的封面容易出现乱码、错字，需要反复重试
🚀 将内容发布到微信公众号 Markdown 无法直接用于公众号，需要手动转换 HTML、上传素材、调用草稿接口
❌ 传统流程（手动操作）
  • 手动在 arXiv 逐页浏览，筛选相关论文
  • 下载 PDF，逐页阅读并做笔记
  • 手动翻译、总结、写中文推文
  • 从 PDF 中截图或手动提取图表
  • 用设计工具制作封面图
  • 手动转换 Markdown 为公众号 HTML
  • 登录公众号后台上传素材并发布
  • ⏱ 单篇耗时 3-5 小时
✅ PaperFlow 流程（自动化）
  • 输入研究主题关键词，自动检索 arXiv
  • 规则预筛 + LLM 语义筛选，精准定位
  • 自动解析 PDF 正文与图表区域
  • 基于证据约束的结构化总结生成
  • AI 生成背景 + 程序叠加准确文字
  • 自动转换为公众号可用 HTML
  • MCP 工具一键预览 / 发布
  • ⏱ 单篇耗时 约 3-5 分钟
🌟03 价值与意义

⚡ 效率提升

将单篇论文从发现到公众号发布的流程从 3-5 小时压缩到 3-5 分钟，效率提升约 60 倍。研究人员可以把节省的时间用于深度阅读和分析判断，而不是机械搬运。

核心价值：让人类时间花在「理解」而非「搬运」上

🌍 社会价值

降低学术知识传播的门槛。目前大量有价值的学术论文因为语言和发布渠道的限制，难以触达中文读者。PaperFlow 让任何一个有研究主题的人都能快速产出可发布的学术科普内容，加速知识从论文到公众的流动。

🔬04 技术创新点
🎯

两级筛选漏斗：规则预筛 + LLM 语义判断

先用月份过滤和本地去重压缩候选范围，再让大模型判断论文价值。把模型用在必须理解语义的环节，兼顾新鲜度、精度与调用成本。

效率优化
📐

版面几何感知的图表提取

联合 Figure/Table 标题、PDF 图片块、表格横线和相邻标题边界计算裁剪区域，而非简单截图或提取内嵌图片。兼容图片、矢量表格等不同 PDF 结构。

技术创新
🎨

视觉生成与文字准确性解耦

生图模型只负责生成无文字主题背景，准确的中文标题、副标题和关键词由 Pillow 程序化排版。避免 AI 生图的中文乱码和错字问题。

技术创新
🔗

证据约束的内容生成

先构造包含元数据、正文摘录和图表清单的「证据包」，再要求模型在证据范围内生成结构化文章。降低内容空泛、图文错配和无依据扩写。

技术创新
📦

MCP 工具化的发布能力

将预览、图片上传、草稿和发布封装为 MCP 标准工具，默认先生成本地 HTML 供人工确认。把不可逆发布变成受控步骤，且同一能力可被不同编排器调用。

工程创新
🗂️

中间产物契约与全流程可追溯

以 JSON、Markdown、PNG、HTML 作为阶段输出，模块可独立测试、替换和复用。每次运行保留完整证据链，错误可定位到具体阶段，避免只能从头重跑。
