# 第十二章 雨夜的回声

她把平板放在桌边，打开项目文件夹。左侧是章节，右侧是正文，所有长句都会自动折行，不需要左右拖动。

当她点到某个字附近时，光标落在对应位置；当她上下滑动，页面只滚动，不会误触发多选。

写完后，她打开 Git 面板，查看这次修改，确认 diff，然后提交。

Problem

痛点不是“手机不能写字”，而是移动端很难管理一个完整作品。

创作者真正需要的是一套连续工作流：找到文件、打开章节、稳定编辑、预览结构、搜索内容、记录版本。现在这些能力分散在多个 App 里。

没有这个产品时

  • 写作 App 只管正文，很难管理一整个文件夹。
  • 文件管理器能删改文件，但不会同步编辑器状态。
  • Git 工具太技术化，写作者不知道这次到底改了什么。
  • 长句需要左右滑动，触摸滑动还容易误选文字。

掌上创作工坊提供

  • 像桌面工作台一样打开整个项目文件夹。
  • Explorer 文件树支持折叠、刷新和外部文件变化同步。
  • Git 面板用变更列表和 diff 解释每次修改。
  • 自动换行与触摸优先交互，让编辑行为符合安卓直觉。
Users

谁会一眼需要它？

只要用户手里不是一个孤立文档，而是一整个持续演进的文本项目，他就会遇到这个痛点。

文

小说与剧本作者

章节多、设定多、修改频繁，需要在外出时继续写作，并清楚知道每次改动。

M

Markdown 笔记用户

用文件夹管理知识库，想在平板上搜索、预览、整理和维护文档。

G

技术写作者

维护文档仓库、教程、README 或产品说明，需要移动端 Git 提交流程。

Workflow

从打开文件夹到提交版本，一条线完成。

它的核心不是堆功能，而是让创作者在安卓平板上也能完成一个完整创作闭环。

打开项目

选择本地文件夹或 Git 仓库，看到完整文件树。

定位内容

通过 Explorer、搜索、章节导航快速跳到目标文本。

触摸编辑

长行自动换行，点击移动光标，上下滑动只滚动。

预览检查

Markdown 预览或分屏查看结构，减少排版盲区。

提交版本

查看 diff、暂存、提交，让作品演进可追踪。

Features

功能不是炫技，而是围绕写作现场设计。

文件树

项目级浏览、目录折叠、滚动查看、手动刷新、外部文件变化同步。

编辑器

自动换行、触摸点击定位、滑动滚动、硬件键盘输入、保存与多标签。

写作辅助

当前文件查找替换、工作区搜索、章节导航、Markdown 预览和分屏。

Git 管理

查看变更、打开 diff、暂存、取消暂存、提交、分支和历史摘要。

Difference

它和普通移动编辑器有什么不同？

能力 普通安卓文本编辑器 掌上创作工坊
工作对象 通常是单个文件或单篇笔记。 面向完整文件夹、小说项目、文档仓库。
触摸体验 长行可能横向滚动，滑动和选择容易冲突。 长行自动换行，点击定位，滑动只滚动。
写作结构 缺少章节导航和项目级搜索。 章节、文件树、搜索和多标签围绕长文组织。
版本管理 通常没有 Git，或需要切换到另一个工具。 在同一 App 内完成 diff、暂存和提交。
Value

价值与意义

效

效率提升

减少在文件管理器、编辑器、Git 工具之间切换的成本，让移动端也能承担严肃写作。

安

作品安全

用版本记录保护创作过程，误删、误改和反复修改都能被更清楚地追踪。

商

商业空间

可以扩展云同步、模板市场、专业主题、仓库托管和写作协作服务。
