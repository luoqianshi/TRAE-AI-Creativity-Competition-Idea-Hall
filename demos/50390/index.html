04 / Data Model

五层抽象
语义优先于文字

Flow 优先于 Page，Task 优先于 App。真正稳定的是交互逻辑，不是页面布局。

Layer 1
Intent
用户真正想做什么
Layer 2
Task
在特定App中的实现
Layer 3
Flow
完整交互路径
Layer 4
Node
流程中的状态点
Layer 5
Component
页面交互组件
05 / Proof of Concept

同一个退款
三个App

MVP 验证核心假设：淘宝、京东、拼多多的退款流程，能否抽象为同一套语义节点。

我的订单
→
订单详情
→
退款申请
→
选择原因
→
确认提交
→
退款结果

统一语义抽象

无论界面如何变化，退款的核心逻辑不变：order_list -> order_detail -> refund_apply -> refund_reason -> refund_confirm -> refund_result
