01心路历程

不和飞书比，
只做它做不好的事

从立项起就在想：如果飞书自己做 AI，权限、功能、生态上它都占尽优势。正面竞争没有出路，差异化才是唯一的生存空间。

发现缺口

飞书 OpenClaw 擅长宏观改稿，但精确到段落、单元格、字句的增删改查，既不直观也难控制。

借鉴 IDE

像 Cursor、Trae 一样，让文档在左、AI 在右。一句话下达指令，改动立刻写回对应位置。

清醒差异化

只做飞书 OpenClaw 覆盖不到的能力：应用 Hub、资讯聚合、PDF 转 Markdown，避开正面竞争。

「差异化，是这个产品存在的理由。」
02创意介绍

AI 侧边栏，常驻飞书页面

用自然语言对文档、表格、多维表格做精确增删改查。核心工具已覆盖建表、填数、写公式、改稿与跨表查找，更多能力持续扩展。

想解决什么

飞书 OpenClaw 只能做宏观改稿；要精确改某一段、某个单元格时，改动看不见、控不住，用户也没法边看文档边对话。

为什么会做

重度飞书用户的一个念头：要是能像 Cursor、Trae 那样，文档在左、AI 在右就好了。于是做了这个侧边栏。

产品形态

Chrome MV3 侧边栏扩展，无后端，运行时仅 React 与 OpenAI SDK。始终以用户本人飞书身份操作，绝不越权。

03用户痛点

写给在飞书上整理资料、搬运数据的人

核心用户

产品经理运营研究员数据分析师学生

在飞书上写文档、做多维表格和电子表格的人。常被手动整理、跨工具搬运、格式来回调整消耗大量时间。

没有它，用户现在很累

  • ✕想让 AI 只改某一段，飞书 OpenClaw 只能笼统改稿，细节看不到。
  • ✕想把表格变成看板、PPT、网站，飞书没有现成路径。
  • ✕想把 PDF 论文转成文档，只能复制粘贴，格式全乱。
  • ✕写东西时想刷资讯找灵感，只能切出飞书，思路被打断。
04价值主张

效率闭环，做飞书 OpenClaw 替代不了的事

差异化护城河

应用 Hub 让表格一键转为看板、报表、PPT、网站、小程序；侧边栏内聚合资讯，PDF 一键转 Markdown。后续还将接入网页脚本与爬虫。只做飞书 OpenClaw 做不到的事。

效率提升

像 IDE 一样边读边改：文档在左、AI 在右，指令下达后改动即时写回，省去手动操作与跨工具搬运。

安全可信

以用户本人飞书身份操作，文件级删除一律拒绝；生成代码在 MV3 沙箱只读渲染，数据不外流。

05产品一览

产品界面一览

核心能力已在飞书页面中跑通，部分功能持续迭代。对话侧边栏是基础，应用 Hub 承载差异化能力。

06差异化

飞书 OpenClaw 与 Feishu Doc AI

不抢飞书能做的事，只补飞书做不到、不好做的事。

BASELINE

飞书 OpenClaw

  • 宏观改稿、摘要，细节修改不直观
  • 没有文档在左、AI 在右的侧边栏
  • 表格到看板、PPT、网站无原生路径
  • 无资讯聚合，无 PDF 转 Markdown
DIFF

Feishu Doc AI

  • 精确到段落、单元格的增删改查，即时可见
  • 常驻侧边栏，IDE 式结对改文档
  • 应用 Hub 一句话生成看板、PPT、网站、小程序
  • 资讯聚合加 PDF 转 Markdown，后续接入脚本和爬虫
07安全

权限边界，硬编码在代码里

提示词不作安全边界，所有护栏都在代码层强制，这是它能放心操作真实飞书数据的底气。

用户身份操作

始终以本人 token 操作，读不了的文档 AI 也读不了，绝不回退应用身份越权。

禁文件级删除

整表、电子表格、文档、云文件删除一律拒绝，内容级删除需确认。

沙箱只读渲染

生成代码跑在 null 源、connect-src none 的 MV3 沙箱，只读渲染，数据发不出去。

出站锁定

只访问飞书与大模型两类端点，代码白名单加 CSP 双重锁死，可纯内网部署。
