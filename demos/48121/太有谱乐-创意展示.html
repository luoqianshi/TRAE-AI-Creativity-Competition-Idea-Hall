PAIN POINTS
音乐学习者的三大困境
中国有超过 5000 万音乐学习者，但绝大多数人在「练错了也不知道」的状态中反复消耗。
🎤

声乐练习没有实时反馈

一节课 300-800 元，一周一节。练了一周不知道音准偏了多少、共鸣位置对不对、换声区有没有痕迹。等下次上课才被老师指出问题，一周的练习可能全是错的。

🎹

编曲学习 DAW 门槛太高

打开 Cubase 一脸茫然，轨道类型、混音台、Piano Roll……教程看完还是不会配和弦，和声进行全凭「听感觉」，没有工具能告诉你「你的和弦配得对不对」。

📚

零基础入门缺少驱动力

乐理枯燥，练习没有反馈。学英语有开心词场式的闯关游戏，但学音乐缺少这样的游戏化产品。很多人学了两个月就放弃了。

TECH DEPTH
6 大 AI 分析模块
每个模块都有明确的算法选型、代码实现和性能指标，不是概念图而是可运行的引擎。
MODULE 01

音高检测引擎

CREPE CNN 深度学习模型

音频波形 → STFT → CREPE 推理 → 基频(F0)曲线。精度远超传统 YIN 算法，抗噪性强。ONNX + INT8 量化后推理延迟 ~5ms/帧。

crepelibrosaONNX
MODULE 02

DTW 序列对齐

动态时间规整算法

用户音高序列 vs 目标序列的最优对齐。解决演唱速度不均匀的问题，逐音评分精确到音分。

dtw-pythonSakoe-Chiba
MODULE 03

音质多维分析

Praat DSP + 自研算法

六维评估：颤音(频率+深度)、气息比(HNR)、基频微扰(Jitter)、振幅微扰(Shimmer)、频谱质心(共鸣类型)、动态范围。

parselmouthlibrosa
MODULE 04

和声模式识别

Chroma 特征 + CREMA / 模板匹配

音频/MIDI → 色度特征 → 和弦识别 → 和声进行标注。生成和声色谱图，评估和声丰富度和功能合理性。

librosamusic21pretty_midi
MODULE 05

节奏模式识别

IOI 归一化 + DTW + madmom

击打/拍手时间戳 → 间隔序列归一化(消除速度差异) → DTW 匹配目标节奏型。逐拍评分 + 稳定性分析。

madmomscipy
MODULE 06

风格特征分析

多维特征向量 + SVM / 规则引擎

提取 BPM、节奏规整度、频谱质心、MFCC、色度复杂度等 30+ 维特征，匹配 8 种风格模型，生成风格雷达图。

sklearnlibrosa

架构分层详情

层级 组件 技术选型 职责
客户端层 微信小程序 Taro 3 + React + TypeScript 声乐练习、启蒙闯关、用户交互
客户端层 Web 编曲工作台 React 18 + Canvas API + Web Audio API 多轨编排、MIDI 编辑、和声分析
客户端层 Web 管理后台 React + Vite + Ant Design B 端数据看板、内容管理
网关层 API 网关 Nginx / 云函数（腾讯云 SCF） 鉴权、限流、路由、SSL 终止
服务层 业务服务 NestJS + TypeScript 用户、课程、订单、支付、消息
服务层 AI 分析引擎 Python + FastAPI + ONNX Runtime 音高检测、音质分析、和声识别、节奏分析
服务层 音频渲染服务 FluidSynth + FFmpeg MIDI 合成、音频格式转换、预览渲染
数据层 关系数据库 MySQL 8.0（主从复制） 用户、课程、订单、分析记录
数据层 缓存 Redis 7 会话、热点数据、排行榜、限流计数
数据层 对象存储 MinIO / 腾讯云 COS 音频文件、课程素材、用户作品
数据层 消息队列 RabbitMQ 异步分析任务、通知推送、数据同步
云原生部署
  • 容器化：所有服务 Docker 化，使用 Kubernetes 编排管理
  • CI/CD：GitHub Actions → 镜像构建 → 腾讯云 TKE 滚动发布
  • 监控：Prometheus + Grafana 指标监控；Sentry 异常追踪
  • 日志：ELK Stack（Elasticsearch + Logstash + Kibana）集中日志分析
  • CDN：腾讯云 CDN 加速静态资源与音频文件分发
