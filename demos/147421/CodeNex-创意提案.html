01 - 问题

独立开发者写得出好代码，却讲不出好故事

他们花了几百小时做项目，却因为不会推广，Star 涨不动、没人用。项目价值无法有效传播，得不到有效反馈来促进持续成长。内容生成 ≠ 内容传播，没有对受众的深度理解，生成再多内容也只是噪音。

📝

手动写博客太慢

写一篇技术深度文章要 3-5 小时，独立开发者没时间。不写 = 没人知道项目存在，Star 涨不动。

🎯

一套内容打天下

小白用户想看"这能帮我干嘛"，开发者想看"技术决策为什么这样选"。现有工具不区分受众，发出来的内容两头不讨好。

📋

发版说明没人看

"我们更新了 X 功能"这种 changelog 式内容，对用户毫无吸引力。变更事件 ≠ 价值传播。

📉

发了就石沉大海

内容发出去不知道效果，不知道哪篇带来 Star，没有有效用户反馈，无法促进项目成长和内容迭代优化。

02 - 增长飞轮 · 核心价值

六步飞轮，让项目持续成长

CodeNex 将"项目深度理解 -> 价值内容生成 -> 分发建议 -> 用户有效反馈 -> 促进项目成长 -> 生成更有价值内容"这条链路持续做到最优。飞轮每转一圈，项目就成长一步。

01
🔍
项目深度理解

读懂项目价值

AI 读取整个项目的代码、文档和架构，通过 4 阶段深度对话（项目定位 / 技术决策 / 用户价值 / 变更预期）建立项目价值档案。不只是看 diff，而是理解项目"是什么、为什么有价值"。

02
✍️
价值内容生成

双受众多视角内容

基于价值档案，针对小白用户生成功能价值内容，针对开发者生成技术深度内容。内置 HKR 质检 + 四层自检，确保不是"AI 味的套话"。项目更新时自动提炼增量价值点。

03
📡
分发建议

内容到对的人

解决"内容到受众"的最后一公里。建议该发到哪个平台（掘金 / V2EX / X / 小红书 / GitHub）、什么时候发、标题怎么写，让内容触达目标受众。

04
💬
用户有效反馈

多源反馈采集与归因

从 GitHub Issues / PR、掘金、知乎、社媒等多源采集反馈。AI 进行情感分析、反馈分类、效果归因--哪篇内容带来了 Star？哪个功能用户讨论最多？哪些负面情绪在升温？

05
🌱
促进项目成长

反馈驱动项目优化

有效反馈回到开发者，暴露用户的真实需求和痛点。选题建议反哺下一轮内容，价值档案持续更新。开发者知道该优化什么、该推广什么，项目进入数据驱动的成长轨道。

06
🔄
生成更有价值内容

飞轮加速运转

项目成长后，AI 对项目有了更深的理解，基于更新后的价值档案生成更有创新价值的内容。更多内容 -> 更多关注 -> 更多反馈 -> 项目更快成长 -> 飞轮越转越快。

① 项目深度理解 → ② 价值内容生成 → ③ 分发建议 → ④ 用户有效反馈 → ⑤ 促进项目成长 → ⑥ 生成更有价值内容 → 回到 ① 飞轮加速 ↻
03 - 产品定位

代码仓库的次时代运营专家

核心洞察：高质量内容的前提是--先理解项目对不同受众的价值。CodeNex 内嵌于 Coding Agent，让 AI 真正读懂整个项目的代码、文档和架构，再按受众视角生成内容，让对的人理解项目价值、产生关注。

🔍
产品本质

项目价值解读引擎

不是翻译变更日志，而是深入理解项目"是什么、为什么有价值"，让 AI 像产品经理一样解读项目。

📂
输入

整个项目代码 + 文档 + 架构

不只看 git diff，而是全局读取项目的目录结构、技术栈、核心设计决策，建立完整的项目价值档案。

💎
分析对象

项目是什么、为什么有价值

不是罗列"变了什么"，而是提炼"这能帮你解决 Y / 这个技术值得你借鉴 Z"。

👥
受众

双受众分别叙事

小白用户看功能价值，开发者看技术价值。一套项目，两套叙事，不再一套内容打天下。

⚡
驱动力

深度理解后主动提炼

不被变更事件驱动，而是基于对项目的深度理解，主动发现值得传播的价值点。

⭐
和 Star 的关系

直接驱动关注

让对的人理解项目价值 -> 关注。内容不是自说自话，而是让目标受众产生"这个项目我需要"的判断。

05 - 系统架构

四层系统，从理解到增长

内嵌于 Coding Agent 的四层架构：深度对话采集理解 -> 多视角内容生成 -> 增量更新持续输出 -> 反馈学习驱动迭代。每层对应飞轮的关键环节。

0
Layer 0 - 深度对话 · 对应飞轮①

对话式项目校准

AI 先读代码和文档推断 80%，再通过 4 阶段 15-20 问的对话补全关键 20%。像产品经理做访谈一样，理解在对话中逐步建立。

① 项目定位
->
② 技术决策
->
③ 用户价值
->
④ 变更预期
产出 -> project_context.md（项目价值档案）
↓
1
Layer 1 - 静态内容生成 · 对应飞轮②

多视角内容输出

基于价值档案，生成面向不同受众的内容。不是"我们更新了 X"，而是"这个项目能帮你解决 Y"。

小白向 功能价值
开发者向 技术深度
社媒向 短打精炼
↓

变更驱动持续输出 + 分发策略

项目更新时，读懂变更在全局架构中的位置，提炼新价值点。同时给出分发建议--该发到哪个平台、什么时候发、标题怎么写。

git push / 新版本

读懂全局位置

内容发布后的学习引擎

不是"监控仪表盘"，而是"学习引擎"。从反馈中洞察归因，反哺项目价值档案和下一轮内容生成，驱动项目持续成长，形成增长飞轮。

07 - 理解深度

L1 到 L4，L4 才能涨 Star

现有工具大多停留在 L1-L2（读文档、列功能）。CodeNex 的目标是 L4：真正理解项目解决了什么问题、对谁有价值、为什么比替代方案好。

层级 理解深度 能生成什么 难度
L1 表面 项目简介、功能列表、更新日志
L2 结构 技术选型解读、架构介绍、模块说明
L3 逻辑 技术深度文章、设计决策分析、可借鉴实践
L4 价值 ← 目标 "为什么你应该用这个项目"、竞品对比、场景化推荐

09 - 怎么用

像调用插件一样，三步启动

CodeNex 内嵌于 Coding Agent 运行。用主流 Coding Agent 调用 CodeNex 系统，如同调用一个插件一样，在对话框中输入项目地址即可开始。

1

调用 CodeNex

在主流 Coding Agent（如 TRAE、Claude Code 等）中调用 CodeNex 系统，如同调用一个插件一样。

↓
2

输入项目地址

在 Coding Agent 对话框中输入一段项目的 GitHub 地址或本地仓库目录地址。

> github.com/yourname/your-project
> /Users/you/projects/your-project
↓
3

飞轮开始运转

CodeNex 自动读取项目代码和文档，启动深度对话建立价值档案，生成内容并给出分发建议，采集反馈驱动项目成长。飞轮开始持续运转。
