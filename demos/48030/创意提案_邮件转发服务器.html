背景痛点

邮箱，正在拖慢你的协同节奏

传统邮箱作为信息孤岛，与现代即时协作工具之间的鸿沟越来越大。

反复切换 · 注意力割裂

开发、运营、HR 每天要在邮箱、IM、协同文档之间反复切换。一封关键邮件淹没在收件箱里，错过就是几小时的延误。

多邮箱 · 难以集中管理

公司邮箱、客户邮箱、CI 告警邮箱分散在不同账号，需要分别登录、分别检查，无法统一过滤、统一归档、统一推送。

附件存储 · 安全合规风险

附件散落各处难以审计，过期数据无法自动清理；明文存储密码、跨用户数据隔离缺失，是企业数据安全的隐形炸弹。

解决方案

一座桥，
把邮箱接入飞书

MailBridge 在 POP3 邮箱与飞书之间架设一座智能桥梁：后台自动拉取多账号邮件，按规则过滤，加密落库后生成富文本消息卡片，实时推送到用户绑定的飞书账号。

用户无需再打开邮箱客户端，所有关键邮件以统一格式汇聚在飞书会话中，附件自动转存云空间，过期数据按策略清理——把邮件变成协同流的一部分。

多账号集中托管，一处配置 · 全程托管

关键字 + 签名双过滤，降噪不丢信

Fernet 加密 + 多用户数据隔离，企业级安全

内容寻址附件存储，去重省空间、引用计数自动清理

核心功能

从拉取到推送，全链路一站式

十大模块协同工作，覆盖邮件生命周期每一个关键节点。

多用户邮箱托管

配置持久化到 SQLite，支持多个邮箱账号登录管理；管理员与普通用户权限分离，数据严格隔离。

智能定时检查

后台线程池并行拉取，白天 60 秒、夜间自动降频，平衡时效与资源占用。

飞书卡片推送

新邮件自动生成富文本消息卡片，图片上传飞图，附件转存云空间，一键直达原文。

关键字 + 签名过滤

多关键字逗号分隔匹配，签名识别自动剔除自动回复，让推送只保留真正重要的信息。

FTS5 全文检索

主题 / 发件人 / 正文写入 SQLite FTS5 虚拟表，trigram 分词支持中文子串匹配，秒级回溯历史邮件。

附件内容寻址

按 SHA256 分桶存储，多用户同附件仅存一份；按用户 / 年月分层目录，性能与可维护性兼得。

Fernet 加密存储

用户邮箱密码采用 AES-128-CBC + HMAC 加密，未配置 ENCRYPTION_KEY 拒绝启动，安全配置强约束。

云空间自动清理

飞书云空间文件夹超 80 文件自动归档，本地附件按时间 + 容量 + 引用计数三重策略 LRU 清理。

跨平台 + 系统托盘

Windows 提供托盘图标一键启停，Linux / Docker 无托盘模式运行，PyInstaller 一键打包部署。

高性能并发引擎

ThreadPoolExecutor 并行处理，推送队列解耦，DB 连接复用 + POP3 连接池，支撑多用户高吞吐。

还有更多

创新亮点

不止于转发，更是工程化沉淀

在「邮件转 IM」的朴素命题下，做出工程上的极致取舍。

01

附件内容寻址 · 去重省 70% 空间

同附件多用户共享存储，按 SHA256 分桶；附件 blob 按引用计数归零后自动回收，避免冗余存储。

02

FTS5 中文检索 · trigram 子串匹配

主题 / 发件人 / 正文入索引，原生支持中文 ≥3 字符子串查询，历史邮件秒级回溯。

03

智能夜间降频 · 资源自适应

20:00–7:00 自动延长检查间隔，降低无关唤醒；白天恢复高频，按需分配算力。

04

三重清理策略 · 数据自管理

时间过期 + 容量阈值 + 引用计数，本地附件 / 云空间 / 数据库分层自治，零人工干预。

05

连接池 + 线程池 · 高吞吐引擎

POP3 连接池避免握手开销，线程池并行处理多用户，推送队列解耦存储与通知。

06

企业级安全 · 强约束加密

Fernet (AES-128-CBC + HMAC) 加密密码，未配置密钥拒绝启动；附件下载强制校验归属。
