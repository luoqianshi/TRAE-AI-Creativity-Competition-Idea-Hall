1. 创意名称 + 创意介绍

核心目标不是做一个聊天机器人，而是把“语音输入”这件小事做到桌面端真正顺手。

创意名称

Audie，一个跨平台 AI 语音输入工具。它面向学习、工作和创作场景，让用户用快捷键说话，然后把干净文本直接送到当前光标处。

想解决的问题

很多人写代码、写文档、回消息时，想法比打字速度快。现有工具要么只能在特定输入框里用，要么输出太口语化，要么隐私和平台兼容性不够理想。

产品形态

Audie 是桌面端 App。用户不需要切换窗口，只要在当前 App 里按快捷键说话，就能完成语音识别、AI 润色和自动注入。

2. 目标用户及痛点

Audie 的用户不是“想玩 AI”的人，而是每天真的要输入大量文字的人。

目标用户

  • 程序员：写注释、需求说明、提交说明、技术文档。
  • 学生和研究人员：课堂笔记、资料整理、论文想法草稿。
  • 内容创作者：快速说出提纲、脚本、短文和灵感片段。
  • 职场用户：写邮件、会议纪要、IM 回复和工作记录。

当前痛点

  • 系统自带语音输入常常只是“识别”，不会整理口语表达。
  • 很多工具需要复制粘贴，打断当前工作流。
  • 闭源工具平台受限，跨 Windows / macOS 的选择不多。
  • 用户不希望 API Key、音频和文本经过不透明的第三方后端。

3. 价值与意义

Audie 的价值集中在效率提升和隐私可控：更快输入，同时让用户掌握自己的模型和密钥。

效率提升

把“脑子里有想法”到“文本出现在光标处”的路径缩短。用户可以先用自然语言说出草稿，Audie 再自动去掉口头禅、修正语序、整理表达，特别适合长文本和临时想法。

工作流连续

文本直接注入 VS Code、浏览器、聊天工具、文档工具等任意输入框，减少切换窗口、复制粘贴和二次编辑，让语音输入像键盘输入一样自然。

隐私可控

Audie 采用 BYOK 模式，用户使用自己的 ASR / LLM 服务。客户端直连供应商，不自建后端；API Key 存在系统 Keychain，避免明文落盘。

技术方案亮点

这是一个真实桌面应用方案，不只是静态概念：核心链路由 Rust 驱动，前端只负责镜像状态和交互。

核心架构

基于 Tauri 2 + Rust + React 构建。Rust 负责录音、流式 ASR、LLM 润色、文本注入和历史记录；React 通过 Zustand 接收后端事件，渲染 overlay、设置页和历史页。

Tauri Command/Event Manager 模式 Rust 热路径

AI 与系统能力

ASR 支持豆包流式 WebSocket、Groq、OpenAI、GLM、通义、StepFun 等 provider；LLM 走 OpenAI-Compatible 接口，支持云端模型和本地 Ollama / LM Studio。

WebSocket ASR BYOK OpenAI-Compatible

桌面端交互

macOS 侧基于 CGEventTap 实现 Fn / F13 / 组合键监听，通过剪贴板法把文本注入当前光标；同时处理权限检测、焦点恢复、注入失败兜底等真实桌面问题。

CGEventTap Clipboard Injection Keychain

产品化能力

提供 onboarding、权限引导、设备选择、麦克风电平预览、provider 测试、历史记录和使用统计。用户第一次打开也能按步骤完成配置和试用。

SQLite History Zod 校验 设置持久化
