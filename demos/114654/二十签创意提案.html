用 20 次有效操练
把「想学」变成「能做」

TED 大热演讲者、真正的「学霸」Josh Kaufman 说过：「20 小时可以学会任何技能」。
我们相信：关键不在 20 小时这个总数，而在其中的每一个小时，是否都做成了一件可验证的事。

20 签 · 20 个渐进训练单元

Problem

我们发现了什么学习困境？

当 AI 可以瞬间生成教程、答案和代码时，自学者的真正瓶颈已经从「找不到资料」变成了「做不出成果」。

01

收藏即学会

大量课程和文章被收藏后从未执行，学习停留在消费内容，而非产出作品。

02

AI 替用户思考

普通 AI 助手以回答问题为主，用户容易停留在对话，失去了动手试错的关键环节。

03

打卡不等于掌握

连续登录、观看时长等虚拟指标无法证明真实能力，缺少以成果为标准的验收机制。

04

计划一旦制定就不再改变

传统学习计划无法根据每日真实表现动态调整，导致任务过难或过易，最终半途而废。

Belief

20 小时的关键，是 20 个有效的一小时

「20 小时可以学会任何技能」——
但前提不是 simply 凑够 20 小时，
而是让其中的每一个小时都完成一次「目标 → 行动 → 反馈」的闭环。

引自 TED 大热演讲者、《The First 20 Hours》作者 Josh Kaufman

很多人把「20 小时法则」误解为：只要投入 20 小时，技能自然会到来。但真正让 20 小时产生魔力的是每一次操练的质量。二十签所做的，就是把这 20 小时拆成 20 个恰好 1 小时的训练单元，每一签都有明确成果、冻结的验签标准和即时反馈。你不需要每天熬夜，也不需要收藏更多课程——你只需要在接下来的一个小时里，真正做成一件事。

Solution

二十签：一个成果驱动的技能操练引擎

把「20 小时快速习得」「一小时暴力学习法」和「日签机制」组合成同一套闭环： 每天约 1 小时，完成一签，提交一个可验证的成果。

1输入技能目标
→
2自适应诊断
→
3生成 20 签路线
→
4每日训练 & 求助
→
5提交成果验签
→
6能力图谱生长

「不以学习时长作为完成依据，只看你今天做成了什么。」

—— 二十签产品核心原则
Users

目标用户与痛点

二十签服务于希望快速入门一项新技能，却缺少拆解方法、实战反馈或持续行动约束的自学者。

👤

核心用户

想快速入门新技能但不知如何拆解的学生与职场用户；容易收藏课程却缺少实际操练的行动困难者；需要明确任务、反馈和外部约束的自学者。

📍

使用场景

每天约一小时的碎片时间，在电脑端创作、上传和训练，或在手机端解锁、拍摄、记录和查看进度。适用于编程、摄影、写作、表达、数据分析、办公技能等可自学领域。

⚠️

当前痛点

收藏即学会、AI 替用户思考、打卡不等于掌握、计划一旦制定就不再改变。学习停留在消费内容，缺少以成果为标准的验收和动态调整机制。

✅

二十签如何缓解

把模糊目标拆成 20 个一小时可完成单元，每签都有明确成果和冻结标准；多 Agent 负责诊断、规划、验签和调整，用户只需专注动手与提交证据。

Value

价值与意义

二十签不追逐 AI 的能力上限，而是把 AI 的能力转化为用户真正动手、产出、成长的下限保障。

⚡

效率提升

把 20 小时拆成 20 个可执行单元，每单元都有明确成果、冻结验签标准和即时反馈。用户无需熬夜或收藏更多课程，只需在接下来的一小时里真正做成一件事。

🌱

社会价值

在信息过载时代，帮助人们从“内容消费者”转变为“能力生产者”。以成果证据为核心的学习记录，让每一次学习都留下可验证的痕迹，重建“学习 = 做出成果”的朴素认知。

Innovation

核心创新：多 Agent 不是聊天角色，而是精密分工

二十签为每个学习目标临时组建一支不同的 AI 教练团队。每个 Agent 拥有不可越界的职责、结构化输入输出，以及互相审核关系。

Agent 核心职责 不可替代性
诊断 Agent 自适应追问，形成能力画像 决定路线从哪一水平开始，避免一刀切
路线 Agent 拆解 20 个渐进操练单元 保证先修关系、一小时可行与最终成果导向
审校 Agent 检查渐进性、重复与验收标准 在路线生效前拦截不合理任务
训练 Agent 管理阶段、计时与 Agent 接力 让用户始终知道此刻该做什么
验签 Agent 对照冻结标准评价成果 以证据为依据，不替用户判断
归档 Agent 更新能力档案，提出路线调整 让每日表现真正影响后续学习
🎯

动态领域专家

系统根据目标自动创建 React 专家、摄影专家、表达专家等配置，并在 20 签周期内保持一致的评价维度，避免标准漂移。

✓

六类验签结论

已通过、待修正、证据不足、标准作废、自证完成、未通过——每类结论都有明确语义和用户可控的下一步。

↺

路线动态调整

自动小幅调整即时生效并允许撤销；重大调整必须解释原因并取得用户确认，用户始终拥有控制权。

Design

设计哲学：安静的精密仪器

视觉参考 Notion 的留白秩序、Apple 健康的进度仪式与 Linear 的精密状态反馈。高级感来自比例、对齐与状态准确，而非装饰。

◐

克制用色

中性黑白灰构成绝大多数界面，单一信号朱红仅占屏幕视觉面积不超过 10%，且只用于行动、当前状态和验签落印。

▭

聚焦式响应布局

桌面端采用 88px 极窄左侧导航，训练场按阶段轨 / 工作区 / 标准栏三栏并列；手机端重组为单手操作的步骤流。

⟳

动效解释状态

Agent 交接、路线重排、上传、验签落位拥有 150～800ms 的状态过渡；关闭动态效果后，所有状态仍可通过文字和图标理解。

♿

WCAG AA 无障碍

核心流程支持键盘操作，20 段标记提供完整文本摘要，状态不只依赖颜色，正文对比度符合可读标准。

Technology

技术亮点与架构

以 PWA 同时覆盖电脑创作和手机记录场景，核心闭环不绑定任何单一模型或 Agent 平台。

前端形态 响应式 PWA，支持安装、离线暂存与游客计划恢复
多 Agent 调度 Orchestrator 统一调度，结构化对象交接，不依赖聊天上下文
ExpertProvider 统一专家能力契约，内置实现 + Coze/Dify 可替换适配层
状态机驱动 计划、日签、训练会话、证据提交均有严格状态机和版本记录
证据与隐私 每项证据可配置隐私范围与模型处理授权，用户可导出或删除数据
安全分级 A/B/C 三级技能验证策略，危险或受监管目标明确拒绝或降级
Demo

比赛演示方案：5 分钟完整闭环

评委无法等待完整一小时，因此我们设计了明确标注的「演示模式」，在 5～7 分钟内展示从目标到验签的完整创新。

1. 现场输入目标

例如「我想学会 React 并独立做出一个小应用」，系统实时生成自适应诊断问题。

2. 观察 Agent 协作

诊断 → 专家配置 → 路线生成 → 审校完成，以简洁轨迹呈现，不展示聊天窗口。

3. 路线工坊调整

用户替换其中一签，审校 Agent 立即检查先修关系，证明用户拥有控制权。

4. 进入今日训练场

展示阶段轨、工作区、验签标准和协作栏三栏并列的精密工作台。

5. 提交并触发验签

提交代码、截图和说明，验签 Agent 对照冻结标准逐项评价，生成结论。

6. 能力图谱更新

验签通过后，第 N 段标记落位，能力凭证生成，路线根据表现小幅调整。

让每一次学习，都留下可验证的痕迹

二十签不追逐 AI 的能力上限，而是把 AI 的能力转化为用户真正动手、产出、成长的下限保障。 我们相信，创造力大赛最该展示的，正是一个安静、精密、可信的学习工具。
