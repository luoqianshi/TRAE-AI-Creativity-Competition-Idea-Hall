# 【TRAE AI 创造力大赛】测数通：面向银行测试环境的安全可追溯自主改数系统

## 1. 创意名称 + 创意介绍

创意名称：测数通

想解决什么问题：
银行系统测试过程中，测试、开发、运维和业务验收人员经常需要在不同测试环境里查询或修改指定数据。现在常见做法是人工连接数据库、手写 SQL、核对字段、记录操作过程，流程繁琐且容易出错。尤其在多表关联、多条件筛选、批量改数场景下，改数效率低，误操作后也不容易恢复。测数通希望把这些操作集中到一个可视化系统里，让用户在安全边界内完成自主改数。

为什么会想到做这个：
在银行内部测试中，很多时间不是花在验证业务本身，而是花在找数据、改数据、确认执行结果和补充操作记录上。面对 P2、PL4、UAT、VT 等多套测试环境，人工切换环境和核对字段很容易出错。这个创意来自真实测试场景中的重复工作，希望用 TRAE Work 帮我把想法整理成更清晰的产品方案，并生成可展示的 HTML 创意产物。

大概是什么产品：
测数通是一个面向银行测试环境的内部 Web 系统，提供测试数据库资源配置、筛选模型管理、可视化查询改数、操作日志和一键回滚能力。

## 2. 目标用户及痛点

面向哪些用户：
主要面向银行科技部门测试人员，也适用于开发联调人员、运维人员和业务验收人员。其中测试人员是最高频使用人群。

在什么场景下使用：
用户在功能测试、回归测试、联调测试、UAT 验证，以及其他系统测试需要指定数据自主改数时使用。典型流程是：选择测试环境，调用已保存的筛选模型，查询目标数据，确认修改前值和修改后值，执行单笔或批量修改，并查看执行结果。

当前痛点：
如果没有这个产品，用户需要直接连接数据库并手写 SQL，容易受到环境、字段、权限和操作经验的影响。多环境表结构不一致时，人工不一定能及时发现差异。改数成功或失败的结果分散在不同工具里，后续追溯不方便。误改数据后，往往还需要人工重新定位原值，恢复成本较高。

## 3. 价值与意义

测数通的核心价值是“安全可追溯的自主改数”。它只连接测试环境数据库，不接入生产环境；用户不能自由写 SQL，只能通过已保存的筛选模型查询和操作数据；单次修改最多影响 5 条数据，修改前必须展示修改前值和修改后值，降低误操作风险。

从效率角度看，测数通把环境切换、字段校验、筛选模型、单笔改数、批量导入、失败名单下载、操作日志和一键回滚集中到一个页面流程中。用户可以不用反复手写 SQL，也不用依赖他人协助改数，更快完成测试数据准备和验证。

从管理角度看，系统会记录带流水号的操作日志，包含人员、时间、环境、表名、操作内容、执行结果、失败原因和修改前完整数据快照。普通用户只能回滚自己的操作，管理员可以回滚所有人的操作；如果回滚时发现数据已被别人再次修改，系统会提示冲突，由用户确认是否继续。这个设计既满足测试效率，也保留了必要的安全边界和追溯能力。
