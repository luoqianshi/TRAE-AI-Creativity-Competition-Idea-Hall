职途
Agent

一个会围绕求职目标持续工作的 AI 求职工作台。它不只回答一次问题，而是长期发现岗位、理解用户取舍、整理申请进展，并把复杂求职压缩成每天少量真正值得处理的决定。

一个求职目标，对应一个长期 Goal Agent；岗位、申请与面试，都是它持续处理的业务对象。

创意名称 + 创意介绍

说明这个创意想解决什么问题、为什么会想到它，以及它最终是什么产品。

创意名称：职途 Agent

一个围绕用户求职目标长期运行的 Goal Agent 工作台。它连接岗位发现、JD 补全、匹配分析、用户决策、投递跟踪、面试准备和策略复盘。

想解决什么问题
现在的求职工具大多只能提供一次性的岗位搜索、简历修改或问答服务，求职者仍然需要每天重复筛选岗位、核对 JD、记录投递状态、准备面试，很容易错过机会，也难以判断什么最值得投入时间。
为什么会想到做这个
我发现求职不是一个问题，而是一个持续数周甚至数月的长期目标。真正有帮助的 AI 不应该只在聊天窗口中回答一次，而应该在用户离开页面后继续工作、积累经过确认的经验，并在关键决策时及时提醒用户。
大概是什么产品
这是一个以“目标智能体”为核心的 AI 求职网站与后台 Agent 系统。用户创建一个求职目标后，系统启动一个常驻 Goal Agent，持续从内部岗位库发现机会、补全 JD、分析匹配度、跟踪申请进展并准备面试建议。
一句话产品定义
把散乱、重复、容易中断的求职过程，变成由 AI 持续准备、用户集中决策的每日工作流。
核心理念不是一个岗位一个 Agent，而是一个目标一个 Agent。
核心承诺后台持续工作，前台只呈现用户真正需要决定的事情。

目标用户及痛点

核心用户不是“所有找工作的人”，而是正在经历高信息量、长周期、多阶段求职的人。

PERSONA 01

应届毕业生

缺少岗位判断经验，需要同时处理校招、实习、网申、笔面试和大量截止日期。

PERSONA 02

正在跳槽的职场人

只能利用通勤、午休和晚上求职，需要用很少时间判断机会是否值得推进。

PERSONA 03

跨行业或转岗者

难以判断自身经历如何迁移，也不知道哪些能力缺口最影响目标岗位。

早晨

查看今日简报

知道 Agent 昨晚发现了什么，以及今天最值得处理的 3 件事。

通勤

快速判断岗位

查看匹配依据、风险和缺口，选择关注、忽略或稍后处理。

投递后

同步真实进展

用户明确标记已投递、收到回复或真实面试邀请。

周末

复盘与调整

从本周事实中判断策略是否有效，确认可撤销的调整实验。

痛点
没有本产品时
造成的后果
岗位信息分散
岗位、JD、公司资料和申请记录散落在多个平台、表格与聊天中。
重复整理、容易遗漏，无法形成统一判断依据。
重复机械筛选
每天重新搜索、打开、去重、比较岗位，很多 JD 还不完整。
注意力耗在低价值操作，真正重要的机会反而没有深入准备。
AI 缺少连续性
每次对话都要重新解释目标，聊天结束后 AI 不再继续工作。
建议前后矛盾，无法长期跟踪，也不会从真实反馈中学习。
进度与策略割裂
收藏、投递、面试和复盘分别记录，状态经常不一致。
用户不知道哪里是瓶颈，也无法验证哪些策略真正有效。

价值与意义

本创意主要从效率提升和长期商业价值两个角度建立价值，同时兼顾求职者的心理负担与数字自主权。

效率提升

Goal Agent 在后台持续完成岗位检索、JD 补全、去重、初步匹配、公司研究和进度整理，把大量机械操作压缩成少量需要用户判断的事项。

  • 减少重复浏览和手工记录
  • 每天只处理最值得投入时间的机会
  • 申请、沟通和面试共享同一目标上下文

商业与长期价值

系统会逐步形成个人求职知识资产。随着使用时间增加，Agent 越来越理解用户的真实取舍，付费价值也从“一次生成”转为“长期协作”。

  • 持续订阅型个人 Agent 服务
  • 付费用户支持多个并行目标
  • 未来可扩展到学校、就业服务与企业端多目标场景

可信与可控

AI 可以长期工作，但不能因此获得无限授权。投递、发送、接受面试和修改个人资料等现实动作必须由用户确认。

  • 后台推理不进入用户历史
  • 模型推断偏好需要审核
  • 策略调整可撤销、可追踪

降低求职焦虑

产品不鼓励用户无限刷新岗位，而是通过稳定节奏和清晰下一步，让求职者知道系统仍在工作，也知道自己何时需要介入。

  • 明确“正在运行、等待、暂停、受阻”
  • 不把未知证据误判为不匹配
  • 样本不足时不输出误导性结论

产品方案与核心机制

产品不是自动替用户海投，而是让一个长期智能体持续准备证据、维护机会，并在正确的时刻把决策交给用户。

CAREER GOAL

一个求职目标

方向、城市、薪资、偏好、排除规则和目标版本共同定义 Agent 的任务。

GOAL AGENT

一个常驻智能体

持续检索、分析、等待和唤醒，不因一次聊天结束而消失。

BUSINESS OBJECTS

多个业务对象

岗位、申请工作流、对话和面试共享目标引用，但保留独立历史。

普通用户一个目标想创建新目标，需要关闭旧目标或升级付费额度；暂停仍占名额。
岗位库是主数据源后台持续补全 JD；招聘平台插件不是产品主链路，也不是使用门槛。
真实状态由用户确认准备简历、打开页面和模拟面试，都不能自动伪造“已投递”或“真实面试”。

Goal Agent 共享知识体系

多个目标意味着多个 Agent，但它们不直接互传“记忆”，而是通过有作用域、有来源、有审核状态的 Career Knowledge 模块共享可信知识。

01 · GLOBAL

全局公开事实

岗位 JD、岗位要求、公司行业、规模、招聘动态和公开风险信号，全平台复用，不包含用户行为、简历或私聊。

岗位事实公司画像来源可信度
02 · USER

用户共享知识

同一用户所有 Goal Agent 可读取，包括用户确认的长期偏好、排除规则、公司倾向、反馈模式和沟通偏好。

跨目标复用用户可纠正关闭目标后保留
03 · GOAL

目标私有知识

岗位匹配分数、目标内排序、搜索假设、策略实验和准备建议，绑定目标及目标版本，绝不直接供另一个目标使用。

目标版本隔离匹配判断策略与准备

明确禁止进入共享知识

Goal Agent 后台推理和思维过程、原始聊天、面试回答、招聘方私聊正文、Workspace Resume 全文及其副本，以及某个目标的私有匹配分数。

创新点与差异化

创新不在于“用了大模型”，而在于把长期目标、持续运行、可信知识和用户控制组合成完整产品机制。

INNOVATION 01

常驻 Goal Agent

AI 不只在用户发消息时工作，还能接收 JD 就绪、用户决定和申请变化等事件，在频率限制内持续推进。

INNOVATION 02

今日决策工作台

产品不展示无穷信息流，而是把后台结果整理为每天少量、带依据、可操作的决定。

INNOVATION 03

三层可信知识

公开事实、用户共享与目标私有知识有不同写入规则，模型推断必须先经过用户审核。

INNOVATION 04

完整事实闭环

从发现岗位到 Offer 使用统一机会生命周期，日报和策略调整来自事实账本，而不是模型想象。

07 / 09

落地路径与可行性

先使用内部岗位库和现有 JD 补全能力形成闭环，不依赖招聘平台自动化授权，降低产品和合规风险。

PHASE 01 · MVP

跑通求职闭环

  • 单目标 Goal Agent
  • 内部岗位库与 JD 补全
  • 机会筛选、审核箱和进展
  • 日报、周报与事实记录
PHASE 02 · PERSONALIZATION

形成个人知识

  • 用户共享偏好和边界
  • 公司公开画像复用
  • 目标私有策略实验
  • 多目标付费额度
PHASE 03 · SCALE

扩展协作场景

  • 更多岗位来源适配
  • 学校就业服务场景
  • B 端工作区和多目标
  • 组织级知识空间预留
数据基础已经存在

已有内部岗位库和后台 JD 爬取、补全逻辑，可以避免把浏览器插件作为产品成立的前提。

成本与负荷可控

默认 15 分钟最短运行间隔，相同事件合并批处理，并通过预算、并发和活跃时段限制 Agent 频率。

08 / 09

可信 AI 与人机边界

长期运行不等于无限授权。产品把“系统可以准备什么、需要用户审核什么、必须由用户完成什么”写进流程。

AI 准备，
用户决策

越接近现实影响，用户拥有越明确的确认权、撤销权和审计记录。

可以持续自动完成

岗位搜索、JD 排队、去重、公开公司研究、匹配分析和工作台整理。

需要进入审核箱

模型推断的长期偏好、跨目标规律、策略实验和知识纠正。

必须由用户明确确认

真实投递、对外发送、收到真实面试、接受邀约、修改目标与简历。

绝不伪造的状态

打开申请页面、自动填表或完成模拟面试，都不能被系统写成“已投递”或“已进入现实面试”。
