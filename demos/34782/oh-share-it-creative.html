oh-share-it

面向团队和 Coding Agent 的 Context 路由层。它不是又一个知识库，而是把分散在成员文件、历史决策和项目经验里的上下文，按权限、来源和任务场景路由给合适的人与 Agent。

学习工作赛道 团队协作 Context Routing 权限与来源保留
项目形态文件驱动的 Context Sharing / Routing 系统
核心闭环分享 -> 分层 -> 路由 -> 暴露给 Agent
核心用户研发团队、AI-native 小团队、研究与产品技术团队
核心亮点保留 owner、来源、权限和适用边界
i
一句话概括：oh-share-it 让团队里的“隐性上下文”变成可分享、可索引、可追溯、可被 Coding Agent 调用的协作资产，同时避免敏感信息和个人判断被混在一起。

报名信息概览

创意名称 oh-share-it

一个让团队安全共享上下文，并把相关材料路由给人和 Agent 的工作系统。

目标用户与场景 频繁协作、交接和使用 AI Agent 的团队

适用于新人接手项目、Agent 理解历史决策、成员共享经验、保留组织记忆等场景。

价值与意义 减少重复追问，让 Agent 更懂团队语境

提升 onboarding、研发协作、知识复用和客户响应效率，并保护来源、权限和个人边界。

功能二：从分享到路由的工作流

Share · 成员主动分享
share-it.rules

成员先声明哪些文件可以分享、哪些不能进入共享层，避免无意暴露敏感材料。

上下文包

上传时保留路径、hash、预览、标签和来源，方便后续追溯。

Layer · 系统分层整理
L0 / L1 / L2 索引

为人和 Agent 提供不同粒度的入口：概览、主题索引、具体材料。

Owner 边界

同一主题可以保留多人的不同 context，不强行合并成单一答案。

Route · 按任务路由
任务感知检索

根据 query、权限、来源和场景选择材料，而不是简单全文搜索。

Session Context Pack

把选中的 context 临时组装给当前 Agent 使用，用完可回收、可追溯。

亮点：不是合并知识，而是保留边界地调用

为什么它和传统知识库不同

传统知识库更关注“把内容放进去”，但 AI Agent 真正需要的是“在某个任务里，哪些 context 可以被调用、为什么可以调用、来源是谁”。

oh-share-it 的默认动作是 routing。稳定、低争议、可追溯的内容可以局部合并，但个人经验、权限边界和来源不会被强行揉成统一大脑。

Agent 路由示例

任务：接手 billing 模块要先读什么
命中：历史客户问题 billing-history.md
命中：架构边界 architecture.md
排除：成员隐私 members.json 与 secrets
输出：带来源标签的 Context Pack
oh-share-it 的价值在于让团队记忆能被 Agent 使用，同时仍然尊重人的边界、权限和判断来源。它不是 Chatbot，也不是传统知识库，而是团队协作里的 Context Routing Layer。
