01 / 创意介绍

让气体扩散仿真变得人人可用

工业园区、实验室、地下空间一旦发生气体泄漏,传统 CFD 仿真建模门槛高、流程慢、结果难复核。 这个平台用智能体工作流,把请求、建模、边界确认、求解、验证和报告串成一条标准流程。

想解决什么问题

气体扩散分析常用于安全评估、应急预案和工程设计,但现有流程依赖专业软件、人工网格划分和复杂求解配置,专家门槛极高。

为什么会想到做

每一步修改都会影响后续结果,却缺少统一的版本、证据和审查机制。借助 OpenFOAM、Docker Compose 与智能体,把全流程标准化。

大概是什么产品

一个基于 WebUI + 后端智能体 + OpenFOAM 容器运行时的开源气体扩散 CFD 自动化仿真平台,开箱即用、可私有部署。

02 / 自动化流程

一条可审查的智能体流水线

从需求输入到最终报告,每个阶段都产出可追踪的证据,关键节点设有人工审查门(几何 / 边界 / 网格 / 报告),求解前先做 fail-closed 预检。

STAGE 01

需求输入

WebUI 提交泄漏场景、几何与边界请求,规范化为 platform_request。

STAGE 02

案例规划

智能体运行 agentctl plan,生成案例方案并停在案例审查门。

STAGE 03

几何 / 边界审查

人工确认几何与边界条件,写入审查记录或阻断记录。

STAGE 04

网格划分

到达网格审查门,校核网格质量后放行求解。

STAGE 05

OpenFOAM 求解

job-runner 在容器内运行真实 OpenFOAM 运行时,预检通过后求解。

STAGE 06

后处理

提取浓度场、探针时序、风险区域,生成后处理产物清单。

STAGE 07

证据验证

校验工作区证据,只有 passed 报告才能通过真实运行时门。

STAGE 08

工程报告

产出工程报告与证据索引,审查通过后归档,全程可复用。

05 / 技术架构

一键拉起的容器化栈

通过 Docker Compose 的 full profile 一键启动,各服务分工明确,控制平面与运行时证据严格分离。

FRONTEND
WebUI

Vite + React,启动读取 platform-config.json,提供作业、报告、项目与审查界面。

CONTROL PLANE
web-proxy

FastAPI 当前 shim 与 full-target 权威面,支持安全模式、CSRF 与角色策略。

ORCHESTRATION
agent-worker

消费队列、运行 agentctl 智能体工作流,推进案例规划与各审查门。

RUNTIME
job-runner

HTTP 服务,在容器内执行真实 OpenFOAM 运行时,fail-closed 预检后求解。

SOLVER
OpenFOAM

开源 CFD 求解器与模板,作为唯一被认可的运行时证据来源。

PERSISTENCE
PostgreSQL / SQLite

权威控制平面持久化:会话、项目、成员、作业摘要、幂等与审计事件。
