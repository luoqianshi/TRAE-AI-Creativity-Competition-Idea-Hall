01 · WHY

创作不该先被工具困住

视觉小说的门槛并不只在“会不会写故事”，还在内容、演出、界面和工程能力被绑定在同一套专用工具里。创作者想多走一步，就要付出成倍的迁移与维护成本。

01

专用生态难迁移

需要重新学习编辑器和脚本语言，成熟的 Web 组件、工程工具与部署能力难以直接复用。

02

自定义能力代价高

一旦加入特殊交互、复杂演出或新的 UI，剧情逻辑和框架实现很容易耦合，后续修改牵一发而动全身。

03

AI 生成难以持续

AI 可以快速生成页面，却需要稳定的类型、生命周期和状态边界，才能继续理解项目并可靠迭代。

把引擎做成能力积木，而不是另一座封闭城堡。

Vyno 的判断很简单：剧情执行需要稳定，视觉表达应该自由。

因此，Core 只负责 Section、Oper、State、Runtime 与 Snapshot；文本、背景、音频、角色和交互通过插件接入；React 组件保持 Headless，不强迫任何一种作品皮肤。

02 · HOW

从一句台词到完整作品

创作者从最小剧情开始，逐步接入演出、界面和应用能力。每一层都能独立理解、替换和测试，既适合手工开发，也适合 AI 辅助迭代。

STEP 01

编写剧情

用 TypeScript Section 描述对白、分支与流程，保持内容可读、可搜索、可版本管理。

STEP 02

组合插件

按需安装文本、背景、音频、图片、Live2D 与外部输入，不为未使用的能力买单。

STEP 03

搭建界面

使用 React Headless Provider 与 Hooks，自由设计首页、对话框、设置和存档体验。

STEP 04

发布作品

复用现代 Web 工具链构建和部署，也能继续接入测试、国际化与跨端方案。

CORE 01

Section

剧情调度的基本执行单元，负责声明流程，而不直接承担具体渲染实现。

CORE 02

Oper Batch

将可见副作用组织为可推进、可提交的批次，统一手动推进与自动播放。

CORE 03

Resource

插件管理文本、音频、画面等外部状态，并明确初始化、销毁和快照契约。

CORE 04

Snapshot

记录游标、状态、外部输入与资源快照，从确定边界重放并恢复故事进度。

const opening = defineSection("opening", {

03 · PROTOTYPE

不是概念图，核心链路已经跑起来

当前早期原型已经形成 Core、React Components、Preset Plugins 与路由工具四个层次，并完成一套可运行的视觉小说 Demo，用真实交互验证架构。

RUNTIME

可推进、可恢复的剧情执行

支持 Section 流程、批次执行、手动推进、自动播放、状态隔离与确定性 Snapshot 恢复。

PRESET

常用演出能力即插即用

已有文本、背景、音频、图片、Live2D、外部输入，以及浏览器端存档和设置持久化能力。

REACT

Headless UI，不限定作品长相

Provider 与 Hooks 负责状态连接，首页、对话框、工具栏、设置和存档面板由作品自由设计。

DEMO

完整应用外壳验证体验

现有 Demo 已覆盖开始、继续、剧情播放、自动播放、回看、存档、读档、设置和全屏等关键操作。

04 · FOR WHOM

给想讲故事，也愿意动手的人

Vyno 不试图取代所有成熟引擎，而是服务那些需要 Web 自由度、现代工程能力与可控扩展边界的创作者。

01

独立互动叙事创作者

希望快速验证剧情、角色和演出创意，又不想先学习庞大专用编辑器。

02

前端开发者与设计师

希望把熟悉的 React、TypeScript、动画和组件能力直接用于互动作品。

03

AI 辅助创作实践者

希望让 AI 在清晰类型和模块边界内参与开发，并能持续维护，而不是只生成一次性页面。

05 · VALUE

把更多时间还给创作

Vyno 的价值不在于堆叠功能，而在于让创作者按自己的节奏，从一个可运行的小故事长成一部可维护的作品。

效率

减少重复搭建

复用运行时、插件和 React 连接层，让创作者把精力放在剧情、演出和作品差异化上。

开放

不锁定界面与平台

Headless 组件与 Web 技术栈保留表达自由，作品可以逐步接入更多终端与服务。

可信

让状态可以解释和恢复

通过明确执行边界与快照契约，让存档、回放和 AI 辅助修改不再依赖脆弱的隐式状态。

06 · NEXT

从引擎原型走向可创作产品

比赛期间将围绕“真实创作者能否独立完成一个作品”推进实质迭代，而不是只修改展示文案和颜色。

初赛阶段

跑通最小创作闭环

完善剧情路由、交互输入、演出插件与 Demo，交付一段从开始到存档恢复都可体验的视觉小说。

复赛阶段

降低首次创作成本

补充脚手架、示例项目、错误提示和创作指南，让新用户能从模板快速建立自己的 Section 与界面。

长期方向

建立开放插件与内容生态

沉淀稳定 API、可复用演出插件和作品模板，让视觉小说创作者共享能力，而不是重复造轮子。

故事应该从灵感开始，不是从适应工具开始。

Vyno，让 Web 成为下一块视觉小说创作画布。
