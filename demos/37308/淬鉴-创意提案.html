淬鉴

以聊天记录和真实行动为原料，以 Agent 身份协作为外部校验，以笔记系统作为长期记忆——让个人和 AI 双向进化的协作系统。

思维可能会骗我，真实行动更能暴露问题。

—— 淬鉴核心信念

1创意介绍

淬鉴真正要打磨的，不是某一次回答、某一张卡片、某一个工具，而是用户在聊天、判断、行动、卡住、纠偏和复盘中反复暴露出来的处理问题方式。

想解决什么问题

个人学习产出不明显，跟 Agent 协作时常感觉 Agent 跟不上自己，也没有自己的 skill 工具体系。更深的问题是：用户反复暴露的处理问题方式从未被系统化识别——自己不了解自己，AI 也不了解自己，协作效率卡在原地。

为什么会想到做这个

在长期用 AI 协作学习、产出和复盘的过程中，发现纯聊天和纯笔记都解决不了一件事——"底层处理问题方式持续升级"。聊天记录散落各处，笔记只存结论不存过程，踩过的坑下次还会踩。比起纯想象，聊天记录、实际执行、工具运行、失败、卡住和返工更容易暴露真实的处理问题方式。

产品形态：一个跑 MVP 闭环迭代进化的系统

通过复盘同时打磨两边——让个人越来越了解自己，让 AI 也越来越了解自己，再根据个人特性优化 AI 协作。

📓

笔记系统

长期记忆沉淀

保存跨窗口、跨身份仍要延续的任务状态、用户画像、底层模式。不是聊天记录原文，而是从产出过程中筛选、归类、标注、验证后的可用记忆。

🤖

Agent 身份协作

外部校验

不同工作场景用不同身份视角处理，采用"场景主 Agent → 产物审查 → 复盘 Agent"三层分工。身份、skill、hook、运行机制都可以被复盘迭代，不是写死不变的。

🌐

Web 可视化界面

交互体验

系统状态总览、身份切换、记忆回查、复盘回放的可视化入口，目前在做记忆的可视化。

2目标用户及痛点

面向重度依赖 AI 协作的知识工作者、独立开发者、持续学习者。日常用 AI 辅助学习产出、项目构建、复盘迭代时，作为长期协作的"第二大脑"。

学习产出不明显学了很多，但产不出东西，过程散落难复盘。
Agent 跟不上自己每次新对话要重新介绍自己、重新对齐约束。
没有自己的 skill 工具体系别人的工具不顺手，自己的方法没沉淀成可复用能力。
AI 做着做着就跑偏忘记之前对齐过的目标，偏离本轮任务。
同样的坑反复踩失败和卡住的尝试没有沉淀，经验白白流失。
底层模式从未被识别不知道自己哪里卡得最多、怎么纠偏。
笔记、行动、复盘各自为政笔记只存结论，对话只聊不存，复盘做完不回写——形不成闭环。

3价值与意义

⚡ 效率提升

跨会话记忆和身份锁定让协作不断线，砍掉"重复对齐、重复踩坑、重复解释背景"的时间。任务森林续接长期进度，用户不用重讲背景。输入包治理机制确保长期记忆经过筛选和验证后才进入当前任务，避免旧记忆污染新产出。

🌍 社会价值

提供一种"用真实行动和聊天记录打磨个人认知"的范式。淬鉴不只打磨个人，也打磨 AI 协作——通过复盘同时识别个人底层模式和 Agent 协作偏差，让个人越来越了解自己，让 AI 也越来越了解自己，再根据个人特性优化 AI 的身份、skill 和运行机制。系统越用，个人和 AI 双向进化。
