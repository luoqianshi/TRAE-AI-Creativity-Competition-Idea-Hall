01
产品概述
Product Overview

产品定位：一款面向硬件开发、算法仿真与自动控制领域研究者的本地工作流自动化引擎。基于 CLI 监听服务与正则解析，实现异构实验数据的零干预清洗、矢量图表热渲染，以及知识库（如 Obsidian）文档的自动组装更新。

1.1 核心解决问题

在复杂的硬件联调与算法验证中，开发者耗费极大量时间处理底层传回的多源异构数据（如时序日志、矩阵流）。每次底层代码参数微调，都会导致实验现象变动，从而引发极其繁琐的机械性操作流程：重新导出数据、运行绘图脚本、重新排版报告。AutoLab 引擎旨在彻底消除这一割裂感。

1.2 产品形态

基于 CLI 环境的轻量级后台守护进程，与本地 Markdown/LaTeX 知识网络深度绑定，不依赖云端 API，确保科研敏感数据完全本地化流转。

02
目标用户与核心痛点
Target Users & Pain Points
HW
硬件与嵌入式开发者
  • 针对微控制器（如 Infineon TC264 等）的底层驱动与控制逻辑调试
  • 需频繁通过串口助手提取 PID 响应曲线与编码器反馈数据
  • 痛点：串口输出冗余信息多，缺乏快速将其转化为稳定图表报告的通道。
AL
算法与控制理论研究者
  • 高频执行控制系统验证（提取响应参数、绘制 Bode 图与 Nyquist 轨迹等）
  • 痛点：单次仿真运行与最终形成带格式验证报告的过程脱节，极易因版本号对不齐导致“图文不符”。
03
核心功能特性
Core Features
👁

Watchdog 目录静默监听

后台守护进程实时侦听特定仿真输出目录，一旦检测到新 .csv 或串口日志生成，毫秒级触发后续工作流。

⚙

异构数据正则清洗

支持多模板切换，自动过滤软硬件调试中的冗余报错报文，精准提取时间戳与目标系统参量。

📊

Headless 矢量渲染引擎

通过无头模式静默调用 Python (Matplotlib) 或 MATLAB 引擎，输出高分辨率、符合学术出版标准的矢量图表。

📝

Obsidian/MD 热注入

基于锚点标记（Placeholder），精准将生成的图表路径、提取的公式参数（如阶跃响应超调量）动态注入本地 Markdown 库。

08
环境配置与部署指南
Environment & Deployment

8.1 前置依赖

  1. 安装 Python 3.10 及以上版本。
  2. 通过 pip install -r requirements.txt 安装核心依赖包（含 watchdog, pandas, matplotlib 等）。
  3. 准备本地知识库（推荐 Obsidian，建议配合 Dataview 或相关前端渲染插件获得最佳呈现效果）。

8.2 快速启动

在 CLI 环境下进入项目根目录执行：

$ autolab-engine start --watch ./simulation_out --target ./obsidian_vault/reports

* 守护进程将自动挂载并监听 simulation_out 目录下的变动流。
