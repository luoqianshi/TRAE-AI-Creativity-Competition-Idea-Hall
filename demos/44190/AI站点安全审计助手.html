创意介绍

很多中小网站不是没有功能，而是缺少持续安全检查能力。后台接口、资金接口、上传接口、回调接口一旦缺少鉴权、参数校验或日志留痕，问题往往要到事故发生后才暴露。

AI 站点安全审计助手希望把经验型排查流程产品化。用户粘贴 PHP/ThinkPHP 控制器代码、路由片段或日志信息后，系统自动识别风险点，输出风险等级、证据位置、影响说明、修复建议和复查清单。

目标用户

中小站长

没有专职安全团队，但需要检查后台、支付、提现、登录、上传等高风险功能。

目标用户

PHP 开发者

能完成业务开发，但需要更系统地发现权限边界、输入校验和异常返回问题。

目标用户

运维负责人

面对异常访问和报错日志时，需要快速判断是否存在进一步追查价值。

核心痛点

安全审计门槛高

很多风险不是语法错误，而是权限、路由、日志、配置组合形成的问题，普通开发者很难一次性看全。

修复建议不落地

开发者需要知道改哪里、为什么改、改完怎么复查，而不是只看到笼统的“存在风险”。

排查过程难沉淀

一次排查结束后，如果没有结构化报告，后续复盘、交接和二次验证都会变得困难。

上线前缺少低成本检查

小团队常常没有独立审计流程，新增接口上线前只能靠开发者自查，容易漏掉高风险边界。

使用流程

粘贴材料

输入控制器代码、路由配置、接口片段或日志内容。

选择场景

选择后台接口、资金接口、上传接口、异常日志等检查模板。

生成报告

AI 输出风险等级、证据、影响说明和修复建议。

复查验证

按清单完成语法、日志、浏览器行为和 API 行为验证。

风险识别维度

维度 示例问题 输出结果
高危 权限鉴权 后台接口未校验登录态或角色权限，普通用户可能访问管理功能。 标出可疑方法、风险原因、建议鉴权位置和复查路径。
高危 SQL 风险 用户输入直接拼接查询条件，缺少参数绑定或白名单约束。 提示输入来源、拼接位置、替代写法和测试用例。
中危 日志审计 资金、后台、配置变更等关键操作没有记录操作者和变更前后值。 生成推荐日志字段、留痕位置和事故复盘清单。
提示 验证完整性 修复后只做静态检查，没有验证浏览器、API、日志和异常路径。 输出上线前复查清单，降低“看似修好”的风险。

public function withdrawal_post()
{
    $id = input('id');
    $status = input('status');
    Db::name('withdrawal')
      ->where("id = " . $id)
      ->update(['status' => $status]);
    return json(['code' => 1]);
}

AI 审计报告示例

综合风险：高危

  • 证据：接口参数直接参与 SQL 条件拼接，存在注入风险。
  • 证据：资金相关状态变更未展示权限校验和操作日志。
  • 建议：使用参数绑定或框架查询构造器，限制 status 白名单。
  • 建议：记录管理员 ID、IP、变更前后值、请求来源和操作结果。
  • 复查：执行 php -l、接口权限测试、异常参数测试、日志落库验证。

价值与意义

提升效率

把零散排查变成结构化流程，快速完成上线前或事故后的第一轮风险初筛。

降低风险

优先暴露后台、资金、上传、回调等高风险接口中的常见问题。

辅助学习

每个风险点都解释原因、影响、修复方式和验证方法，让开发者边用边建立安全意识。
