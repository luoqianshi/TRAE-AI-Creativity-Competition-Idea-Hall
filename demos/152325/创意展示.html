01 / 创意介绍

解决 语义级判断 的
效率与标准之困

现有 ATS 靠关键词匹配,简历写 Vue 岗位要 React 就被刷掉——忽略技能可迁移性。我们用大模型理解语义级匹配,这正是 AI 介入的价值点。

⚡

解决什么问题

HR 每收到一批简历要逐份人工读完才能筛出面试名单,耗时且标准不一。尤其跨岗位招聘时"凭感觉"导致漏掉合适候选人——我们把"读简历 + 判匹配"自动化,让 HR 只需确认 AI 建议。

PAIN POINT
💡

为什么会想到

观察身边 HR 朋友的真实工作:一次招聘收到 50-200 份简历,初筛占去 2-3 天,且不同 HR 对同一份简历判断常有分歧。市面系统只做关键词匹配,而大模型能理解"Vue 开发者可快速上手 React"这种语义级关联。

INSPIRATION
🌐

大概是什么产品

一个网站(Web 系统)。HR 上传 PDF 简历后,系统通过三级 Agent 自动分析技能匹配度和经历含金量,给出结构化建议,HR 一键确认后自动发送结果邮件,并持续沉淀 badcase 实现自进化。

04 / 系统流程

L1-L8 完整闭环
从触发到自进化

系统不是"一次性 demo",而是一条从用户触发到数据沉淀、再到影响下一次输出的完整链路。每个环节都有明确的输入输出和代码实现。

STEP01

触发:HR 选岗位 L1 被动提示

HR 从下拉框选岗位(前端/后端/产品/运营,配置在 roles.json)。选岗时界面自动显示该岗位历史 badcase 统计(偏松/偏严/幻觉/漏识别),让 HR 对 AI 建议保持警惕。

load_roles() → get_bad_case_summary()
STEP02

输入:上传简历 L2

HR 填候选人姓名 + 邮箱,上传 PDF 简历。支持批量处理,每份独立分析。

STEP03

预处理:PDF 解析 L3

用 pdfplumber 提取 PDF 文本(相比 PyPDF2 对中文简历更准)。失败则提示并终止,不进入 Agent 链路。

tools/pdf_parser.py → extract_text_from_pdf()
STEP04

核心:三级 Agent 串联 L4 AI 介入节点

这是 AI 介入的核心节点。三个 Agent 各司其职,前一个的输出是后一个的输入,最终给出综合建议。职责单一便于评测定位 + prompt 针对性优化。

1
🎯

技能匹配 Agent

SKILL MATCHER

读 roles.json 的 required_skills,识别简历中的技能,判断匹配/缺失,输出匹配率。理解"Vue → React 可迁移"这种语义级关联。

→ 匹配技能 / 缺失技能 / 匹配率
→
2
📊

经历评估 Agent

EXPERIENCE EVALUATOR

判断项目经历的含金量:项目规模、技术深度、是否有可验证的成果。输出亮点和风险点,辅助综合判断。

→ 亮点 / 风险 / 经历评分
→
3
⚖️

综合判断 Agent

FINAL JUDGE

汇总前两步输出,给出最终建议:通过/拒绝 + 置信度(高/中/低)+ 理由。这是唯一给"结论"的 Agent。

→ 建议 / 置信度 / 理由
STEP05

输出:结构化展示 L5

界面展示三级详细结果:匹配的技能、缺失的技能、经历亮点、AI 建议 + 置信度。透明可解释,HR 能看到"为什么这么建议"。

STEP06

反馈与确认:HR 介入 L6 人工确认

AI 给建议,但不直接发信——HR 确认后才触发邮件 Agent 调用 SMTP 工具发信。AI 建议与 HR 决定冲突时标记为"override"(潜在 badcase)。这是产品底线:AI 辅助而非替代。

HR 确认 → email_agent → SMTP 发送
STEP07

状态沉淀:数据入库 L7

候选人信息 + 三级 AI 结果 + HR 决定 + 邮件状态 + 时间戳全部入库。状态流转:pending → decided → emailed。这些数据是系统自进化的燃料。

db/store.py → SQLite
STEP08

自进化:影响下一次 L8 主动触发

HR 事后回标准确度(准确/部分/不准),若标"部分/不准确"必选错误类型。同岗位连续 3 次"AI 通过但 HR 拒绝"时主动弹预警。下次选同岗位时被动提示历史误判。

check_consecutive_overrides() → 主动预警
05 / 技术架构

每一层都有
真实代码实现

不是 PPT 项目,是可运行的原型。每个技术词都对应具体节点和代码文件,经得起面试追问。

MODEL · 模型层

DeepSeek 经硅基流动

国产大模型,中文能力强、成本极低(约为 GPT-4o 的 1/30)、国内直连。通过 OpenAI 兼容接口调用,换模型只改配置。

DeepSeek-V3 硅基流动 OpenAI 兼容
AGENT · 智能体层

Agno 多 Agent 框架

轻量级 Python 框架,支持 Agent 串联、工具调用、角色配置。决策型 Agent 只动脑,执行型 Agent 动手发信。

Agno 三级串联 Tool Calling
TOOL · 工具层

PDF 解析 + 邮件发送

pdfplumber 提取中文简历文本(优于 PyPDF2);SMTP 封装为 agno Toolkit,让邮件 Agent 能"动手"发信。

pdfplumber SMTP Toolkit
DATA · 数据层

SQLite + badcase 库

零配置存储历史记录。badcase 按岗位 + 错误类型聚合,支持连续驳回检测和一致率统计,是自进化的数据基础。

SQLite badcase 库 状态流转
FRONTEND · 表现层

Streamlit 中文界面

几行代码出网页,MVP 原型首选。侧边栏配置 + 主区三段式(上传/分析/确认),HR 零学习成本上手。

Streamlit 中文界面 零学习成本
EVAL · 评测层

离线评测体系

15 份三档难度样本 + 2 份极端样本,5 项 rubric(准确率/召回率/精确率/幻觉率/技能匹配率),固定 temperature=0 形成复测口径。

离线评测 rubric 复测口径
