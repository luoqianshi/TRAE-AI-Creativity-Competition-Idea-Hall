创意介绍

💡 把 30 秒的翻译操作压缩到 1 次回车

每个非英语母语的程序员每天都在做同一件低效的事：给变量起英文名。打开浏览器 → 输入中文 → 复制翻译结果 → 手动改成驼峰格式 → 粘贴。整个过程打断编码心流，一个中型项目里要重复数百次。

Tranc Translator 把这个步骤缩短为：在代码注释里写 // tranc 玩家速度，回车。变成 // playerSpeed。无需离开编辑器，无需触碰鼠标。

用户与痛点

🎯 谁在用？解决什么问题？

  • 目标用户：所有使用 VS Code 的开发者，尤其是以中文为母语、需要频繁命名的程序员
  • 使用场景：编写业务代码时，为变量、函数、类、接口快速生成英文驼峰名称
  • 当前痛点：没有插件的情况下，每个命名需要 3–4 步手动操作，打断编码心流
  • 频率极高：一个中型项目中，开发者可能需要翻译命名 数百次
价值与意义

📊 效率提升与创新价值

30s → 2s 单次翻译耗时
0 窗口切换次数
100+ 支持的编程语言
  • 效率提升：将每次 30 秒的翻译操作压缩到 2 秒，一个项目周期可节省数小时
  • 降低门槛：非英语母语开发者不再为英文命名焦虑，专注业务逻辑本身
  • 创新交互：基于注释 + 回车触发的无感翻译，比快捷键或右键菜单更自然流畅
  • 生态价值：开源 VS Code 插件，架构可扩展支持更多翻译引擎和命名格式
技术亮点

⚙️ 架构与实现

  • VS Code Extension API：利用 onDidChangeTextDocument 实时监听编辑器输入，精确检测换行事件触发翻译
  • DeepSeek API：集成 deepseek-v4-flash 模型，精心设计的 system prompt 确保翻译结果稳定输出驼峰格式
  • 双保险兜底：API 返回不稳定时，本地正则再处理，确保最终输出始终是驼峰格式
  • 跨平台密钥安全：API Key 使用 VS Code SecretStorage 加密存储，兼容 macOS Keychain / Windows Credential Vault / Linux libsecret
  • 多注释兼容：自动识别 // (JS/TS/C++/Java)、# (Python/Ruby)、-- (SQL/Lua)、<!-- --> (HTML) 等注释格式
产品形态
