01 / PROBLEM

当 AI 越强，协作越难。

单个大模型已经能写代码、能画画、能推理。但当多个智能体同时跑任务时，决策冲突、行为黑箱、策略漂移几乎必然出现——而企业真正需要的不是更强的单兵，而是能打仗的团队。

01

单智能体瓶颈

单 LLM 受限于上下文与对齐偏好，越复杂的业务越难以一人扛到底。需要分工、需要多视角、需要博弈。

02

决策黑箱

多智能体各自有私利，缺少中立机制裁决冲突。出现分歧只能靠人介入，无法在系统内闭环。

03

策略漂移

智能体行为随时间漂移却无人察觉。生产事故常源于"系统昨天还好好地，今天突然发疯"。

02 / SOLUTION

四根支柱，撑起一个自治系统。

SoloForge 不是又一个 Agent 框架。它把决策引擎、仲裁法庭、强化学习、审计内核塞进一个微内核里，让智能体像公司一样有序运转。

05 / STACK

每一层，都为自治而生。

不是凑齐技术栈，而是为"系统要能自己管自己"这个目标，挑最合适的工具。

L1 / RUNTIME
TypeScript · Node.js
微内核、业务编排、事件总线。开发效率高、生态成熟、易招聘。
L2 / SCHEDULER
Rust
任务调度、Actor 队列、中断处理。极致低延迟与零成本抽象。
L3 / TRAINING
Python · PyTorch
MAPPO 多智能体强化学习推理与训练，shadow/live 双模式部署。
L4 / DATA · HOT
Garnet (Microsoft)
运行态缓存、Session Context、Task State。原生支持 Windows，比 Redis 快 2-10×。
L5 / DATA · WARM
SurrealDB (Embedded)
决策、证据、卷宗、MARL 遥测、迁移历史。rocksdb:// 协议直连，零子进程。
L6 / DATA · COLD
JSONL · Hash-Chain
事件归档、审计日志、跨节点证据链。1:1 可回放，事故复盘无忧。
