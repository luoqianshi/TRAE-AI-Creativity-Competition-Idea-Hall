项目四问

以下四块可直接用于路演、汇报或项目简介；表达尽量贴近当前仓库 README 和工具说明。

1
项目背景与痛点

安全团队在渗透测试、资产排查和威胁追踪中常面对工具分散、授权边界不清、过程难复盘、报告整理耗时等问题。传统 CLI 依赖人工串联命令，容易遗漏证据、误触主动扫描，也难以沉淀团队经验。

2
解决方案与核心功能

RedScope AI 将 AI 对话、MCP 工具、插件、scope 校验和安全 profile 编排整合为统一 CLI。它支持交互/管道模式、多模型接入、受控工具安装、评估计划、报告归一化、证据索引、本地记忆和交付包生成。

3
技术框架或实现思路

项目基于 Bun、TypeScript、React/Ink 和 Commander 构建终端应用，QueryEngine 连接模型 Provider 与内置/MCP 工具。安全套件通过 JSON scope、profile registry、脚本化流水线和输出目录约束，实现默认计划、确认后执行。

4
应用场景与价值

适用于授权渗透测试、SRC/众测辅助、资产基线评估、仓库密钥/SAST 检查、事件日志与 IOC 分析、批量目标复核等场景。价值在于降低操作门槛、强化合规边界、提升报告效率，并让安全知识可沉淀复用。

工作流蓝图

创意定位：把 RedScope AI 包装成“安全评估任务控制台”，让每次测试都沿着固定轨道产出计划、证据、报告和记忆。

授权范围

用 scope JSON 明确目标、排除项、测试等级、时间窗口和审批信息。

Profile 规划

根据 URL、仓库、日志或批量目标选择确定性 profile，默认只生成计划。

受控执行

主动或受限测试必须具备 scope 能力、执行参数和人工确认。

证据报告

将 run artifacts 转为 findings、evidence index、Markdown/HTML/PDF 报告。

记忆复盘

把摘要、资产关系、决策和经验写入本地 memory，支持后续图谱导出。

技术实现

架构拆解

  • 入口层Commander CLI，支持交互、print、JSON、stream-json、子命令。
  • 体验层React 19 + Ink fork 构建终端 REPL、对话、权限和提示体验。
  • 智能层Provider Adapter 连接 Anthropic、OpenAI 兼容、Gemini、Grok、Bedrock 等。
  • 扩展层内置工具、MCP、插件 marketplace、自定义 agent、hooks 和 slash command。
  • 安全层scope、profile、egress、report、observe、deliver 等脚本形成闭环。

应用场景与价值

红队与授权渗透

用 scope 和 egress 白名单固定边界，用 profile 控制节奏，减少临场误操作与无法解释的扫描行为。

SRC/众测复盘

将目标核验、PoC 候选分析、低影响验证和报告整理拆成可审查步骤，便于交付和复测。

蓝队事件分析

对日志、IOC、STIX、EVTX、PCAP、PE 等本地证据做摘要，避免把原始敏感内容扩散到报告。

研发安全检查

结合仓库密钥扫描、SAST、依赖检查和报告流水线，在提交前发现高风险问题。

批量资产基线

面对多个目标时按序运行 batch profile，统一产物目录、失败记录和证据索引。

团队知识沉淀

把每次评估的摘要、决策、资产关系与经验写入本地记忆，减少重复分析成本。
