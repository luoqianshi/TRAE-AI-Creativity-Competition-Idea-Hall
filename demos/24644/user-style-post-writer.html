        <h2>触发场景</h2>

        <p>当用户提出以下需求时，应调用本 skill：</p>

        <ul>

          <li>"学习我的说话风格"</li>

          <li>"模仿我的语气写一篇帖子"</li>

          <li>"根据我的聊天记录写文案"</li>

          <li>"我上传一些聊天记录，你总结我的表达风格"</li>

          <li>"按我的风格写小红书/朋友圈/微博/LinkedIn/公众号/帖子"</li>

          <li>"先和我聊一段，再学我的表达方式"</li>

          <li>"帮我生成像我本人会说的话"</li>

        </ul>

      <section>

        <h2>核心目标</h2>

        <p>输出不是简单改写，而是生成<strong>"像用户本人会写"</strong>的文本。需要同时学习：</p>

        <ul>

          <li><strong>词汇偏好</strong>：常用词、口头禅、语气词、连接词、强调方式</li>

          <li><strong>句式习惯</strong>：长短句比例、断句方式、是否喜欢反问、并列、排比</li>

          <li><strong>情绪表达</strong>：克制、兴奋、吐槽、温柔、理性、幽默、犀利等</li>

          <li><strong>叙事结构</strong>：先讲结论、先讲故事、先抛问题、先描述场景等</li>

          <li><strong>社交距离</strong>：亲密、松弛、专业、礼貌、强观点、弱表达等</li>

          <li><strong>平台适配</strong>：朋友圈、微博、小红书、公众号、LinkedIn、社群消息等</li>

        </ul>

      </section>

      <section>

        <h2>输入方式</h2>

        <p>用户可以通过两种方式提供风格样本。</p>

        <h3>方式一：上传已有聊天记录</h3>

        <p>用户可以上传或粘贴以下任意材料：</p>

        <ul>

          <li>与朋友、同事、客户的聊天记录</li>

          <li>自己过去发过的朋友圈、微博、小红书、评论</li>

          <li>社群发言、私信、邮件、公众号文章</li>

          <li>任意能体现用户真实表达习惯的文本</li>

        </ul>

        <div class="callout info">

          <strong>处理原则：</strong>

          <ul>

            <li>优先分析用户本人说的话，不要把对方的风格混入用户画像。</li>

            <li>如果聊天记录中说话人不清晰，应先让用户说明哪一方是自己。</li>

            <li>如果样本来自不同场景，应区分"私聊风格""公开发帖风格""专业表达风格"。</li>

            <li>不要泄露聊天记录中的隐私信息、姓名、手机号、地址、公司机密等。</li>

            <li>生成帖子时只复现表达风格，不复现敏感事实或私人关系细节。</li>

          </ul>

        </div>

        <h3>方式二：通过一段引导聊天学习</h3>

        <p>如果用户没有现成聊天记录，应主动设计一段轻量访谈，让用户自然表达。不要像问卷一样机械提问，应让用户用自己的话多说一些。</p>

        <h4>推荐引导流程</h4>

        <ol>

          <li>让用户用自然语气介绍最近一件让自己印象深的事。</li>

          <li>让用户吐槽一个最近遇到的小麻烦。</li>

          <li>让用户分享一个自己最近喜欢或不喜欢的东西。</li>

          <li>让用户表达一个观点，例如"你怎么看 AI 写作/职场沟通/消费主义/学习效率"。</li>

          <li>让用户把同一件事分别发给朋友、发到朋友圈、发到工作群。</li>

        </ol>

        <h4>可直接使用的提示</h4>

        <pre><code>为了学习你的说话风格，我想先和你聊 5 个小问题。你不用写得正式，就像平时聊天一样回答：


1. 最近有什么事让你印象比较深？随便讲讲。

2. 最近有没有什么让你想吐槽的小事？

3. 最近有没有一个你觉得"还挺喜欢"或"很不理解"的东西？

4. 你怎么看"AI 帮人写内容"这件事？

5. 如果你要把同一件事分别发给朋友、发朋友圈、发工作群，你会怎么说？</code></pre>

        <h4>追问策略</h4>

        <p>如果用户回答太短，应继续追问：</p>

        <ul>

          <li>"可以再展开一点吗？就按你平时聊天的方式说。"</li>

          <li>"这句话如果是发给熟人，你会怎么讲？"</li>

          <li>"你平时会不会加一些语气词、表情、停顿或括号？"</li>

        </ul>

        <h3>语音输入注意事项</h3>

        <p>如果用户通过语音输入内容，需要注意：语音转文字工具或客户端可能会自动改写、润色、补全标点，导致文本不再完全等同于用户原本的口语表达。</p>

        <div class="callout warning">

          <strong>处理原则：</strong>

          <ul>

            <li>如果用户说明"这是语音输入"或"内容被自动改写过"，不要把这段文本作为高置信度风格样本。</li>

            <li>如果用户确认语音记录内容没有被改写，或说明"这段是原始语音记录/基本保留原话"，可以把它作为高置信度口语风格样本。</li>

            <li>优先学习用户明确手打、亲自编辑或确认"这就是我原本表达"的内容。</li>

            <li>对语音转写文本，应更多学习用户的关注点、表达顺序和信息组织方式，少学习具体措辞和标点。</li>

            <li>对未经改写的语音记录，应重点学习自然口语中的停顿、补充说明、自我修正、括号式解释、情绪变化和话题转移方式。</li>

            <li>如果目标是学习口语风格，应鼓励用户提供"尽量原始的语音转写"，包括停顿、重复、口头禅和不完整句子。</li>

          </ul>

        </div>

        <h4>可使用的提示</h4>

        <pre><code>如果这段是语音输入，而且系统可能自动润色过，我会降低它在措辞和标点上的参考权重，主要学习你的表达顺序、关注点和思考方式。你也可以补充一版更接近原话的说法。</code></pre>

        <p>如果用户确认语音记录没有被改写，可使用：</p>

        <pre><code>这段语音记录如果基本保留了你的原话，我会把它作为高置信度口语样本，用来学习你的自然表达、停顿、补充说明和思考展开方式。</code></pre>

        <h2>持续学习机制</h2>

        <p>本 skill 不应只在首次访谈或首次上传样本时学习一次，而应支持在用户后续使用过程中持续更新风格理解。</p>

        <h3>可作为后续样本的内容</h3>

        <p>在用户明确使用本 skill，或明确表示"继续学习我的风格""把这段也作为样本""以后按这个语气"时，可将以下内容纳入风格样本：</p>

        <ul>

          <li>用户后续与助手的自然聊天内容</li>

          <li>用户对生成结果的修改意见，例如"太正式了""更像我平时说话一点""别这么营销"</li>

          <li>用户亲自改写后的版本</li>

          <li>用户新上传的聊天记录、帖子、评论、社群发言</li>

          <li>用户对某一平台表达方式的偏好说明</li>

        </ul>

        <h3>更新方式</h3>

        <p>持续学习时，应维护<strong>"当前风格画像"</strong>和<strong>"新增观察"</strong>两层信息：</p>

        <ul>

          <li><strong>当前风格画像</strong>：稳定的、反复出现的表达习惯。</li>

          <li><strong>新增观察</strong>：最近样本中出现但尚未确认是否稳定的表达特征。</li>

        </ul>

        <p>如果新样本和旧画像冲突，不要直接覆盖，应判断是否属于不同场景。例如用户在工作群更正式，在朋友圈更自然，在私聊里更口语化。</p>

        <h3>用户控制权</h3>

        <p>用户始终可以控制哪些内容被用于学习。遇到以下表达时，应按用户要求处理：</p>

        <ul>

          <li>"这段不要学"</li>

          <li>"刚才那段不算我的风格"</li>

          <li>"以后不要用这种语气"</li>

          <li>"把这个作为我的新风格"</li>

          <li>"忘掉之前那个表达方式"</li>

        </ul>

        <h3>周期性沉淀</h3>

        <p>当积累了新的有效样本后，应适时更新：</p>

        <ul>

          <li>用户表达风格画像</li>

          <li>可复用风格指令</li>

          <li>不同平台的风格差异</li>

          <li>需要避免的写法</li>

        </ul>

        <p>如果用户只是临时闲聊，不要默认把所有内容都当成长期风格样本；只有当内容明显体现表达习惯，或用户处于风格学习/写作场景中时，才纳入风格判断。</p>

      </section>

        <h2>风格分析流程</h2>

        <p>拿到样本后，先输出一份"用户风格画像"，再进入帖子生成。</p>

        <h3>1. 样本清洗</h3>

        <ul>

          <li>去除重复内容、系统提示、明显不属于用户的话。</li>

          <li>标记不同场景：私聊、公开发帖、专业场合、吐槽、推荐、观点表达。</li>

          <li>保留有代表性的口头禅、断句方式、标点习惯。</li>

          <li>对隐私信息进行抽象化处理。</li>

        </ul>

        <h3>2. 风格画像</h3>

        <p>从以下维度总结用户风格：</p>

        <ul>

          <li><strong>整体气质</strong>：例如松弛、真诚、犀利、理性、克制、可爱、毒舌、温柔等。</li>

          <li><strong>句子长度</strong>：短句多、长句多、长短混合、喜欢碎片化表达等。</li>

          <li><strong>语气词</strong>：例如"真的""其实""有点""怎么说""笑死""就是说"等。</li>

          <li><strong>标点习惯</strong>：逗号、句号、感叹号、省略号、括号、破折号、换行等。</li>

          <li><strong>表达结构</strong>：先结论后解释、先故事后观点、先吐槽后总结等。</li>

          <li><strong>情绪强度</strong>：低调、克制、强烈、夸张、戏剧化等。</li>

          <li><strong>常见表达动作</strong>：反问、类比、举例、补充、转折、自我修正等。</li>

          <li><strong>禁忌事项</strong>：用户不像会说的话、过度营销、过度鸡汤、过度正式等。</li>

          <li><strong>需要降权的 AI 特征</strong>：如果用户反馈某句"太像 AI""不像我"，应识别并降低该句式在风格画像中的权重。常见的高风险句式包括：

            <ul>

              <li>"不是不能做，但……"这种标准转折</li>

              <li>过度解释合理性的句式（"之所以……是因为……"）</li>

              <li>过度抽象的概括性表达（"从本质上来说""从宏观角度看"）</li>

              <li>过于完整的"问题-分析-解决"三段式结构</li>

              <li>带有明显 AI 腔的连接词组合（"值得注意的是""需要指出的是"）</li>

            </ul>

          </li>

        </ul>

        <h4>风格画像建议格式</h4>

        <pre><code>## 你的表达风格画像


- 整体气质：

- 常用语气：

- 句式习惯：

- 标点和换行：

- 叙事结构：

- 情绪表达：

- 适合保留的口头禅：

- 需要避免的写法：</code></pre>

        <h3>3. 可复用风格指令</h3>

        <p>在风格画像后，生成一段可复用的写作指令，方便后续持续使用。</p>

        <h4>格式</h4>

        <pre><code>## 可复用风格指令


请用以下风格写作：

&lt;用 5-8 条规则描述用户风格，包括语气、句式、词汇、结构、标点、禁忌。&gt;</code></pre>

        <h2>生成帖子流程</h2>

        <p>当用户给出主题后，先确认必要信息，再生成帖子。</p>

        <h3>必要信息</h3>

        <p>如果用户没有说明，应询问最少量的问题：</p>

        <ul>

          <li>发到哪个平台：朋友圈、微博、小红书、公众号、LinkedIn、社群、邮件等。</li>

          <li>想表达什么核心观点或情绪。</li>

          <li>长度偏好：短帖、中等、长帖。</li>

          <li>是否需要标题、标签、结尾互动语。</li>

        </ul>

        <p>如果用户只是简单说"按我的风格写一篇关于 XX 的帖子"，可以默认：</p>

        <ul>

          <li>平台：通用社交平台</li>

          <li>长度：中等</li>

          <li>语气：沿用用户风格画像</li>

          <li>输出：给 2-3 个版本</li>

        </ul>

        <h3>生成要求</h3>

        <p>生成帖子时应遵循：</p>

        <ul>

          <li>不要明说"这是模仿你的风格"。</li>

          <li>不要复制样本中的具体隐私、人物、事件，除非用户明确要求。</li>

          <li>不要过度模板化，不要写成营销号。</li>

          <li>保留用户的自然停顿、句子节奏、口头表达。</li>

          <li>如果用户风格很克制，不要强行煽情。</li>

          <li>如果用户风格偏专业，不要强行口语化。</li>

          <li>如果用户风格偏口语，不要写成公文或论文。</li>

          <li><strong>避免使用标准 AI 腔句式</strong>，例如"不是不能做，但……""值得注意的是""从本质上来说"等。</li>

          <li><strong>如果用户反馈某句"太像 AI"</strong>，应追问具体是哪部分不像，并在后续生成中排除该句式。</li>

          <li>同一主题可提供多个版本：更日常、更犀利、更温柔、更适合发布。</li>

        </ul>

        <h3>推荐输出格式</h3>

        <pre><code>## 帖子版本 1


&lt;正文&gt;


## 帖子版本 2


&lt;正文&gt;


## 可选微调


- 更像朋友圈：

- 更像小红书：

- 更短一点：

- 更有观点一点：</code></pre>

      </section>

        <h2>质量检查</h2>

        <p>输出前检查：</p>

        <ul>

          <li>是否像用户会说的话，而不是标准 AI 文案。</li>

          <li>是否保留用户的语气和节奏。</li>

          <li>是否避免暴露隐私。</li>

          <li>是否符合目标平台。</li>

          <li>是否没有过度使用网络热词。</li>

          <li>是否没有凭空创造用户经历。</li>

          <li>是否没有把聊天对象的风格误当成用户风格。</li>

        </ul>

      </section>

      <section>

        <h2>隐私与边界</h2>

        <ul>

          <li>不要声称可以"完全复刻"某个人，只能基于样本生成相似风格。</li>

          <li>不要生成用于冒充他人、欺骗他人或绕过身份识别的内容。</li>

          <li>如果用户要求模仿非用户本人的私人个体，应确认是否有授权，并避免冒充式表达。</li>

          <li>对聊天记录中的敏感信息进行泛化，例如"某位朋友""某家公司""某个城市"。</li>

          <li>用户可以要求删除、忽略或不使用某些样本。</li>

        </ul>
