创作背景

成年人的世界，需要被哄着入睡

现代成年人长期处于高压节奏，"哄自己"几乎成为日常--哄自己上班、哄自己锻炼。许多人夜间思绪难以平复，辗转至凌晨仍无法入睡。睡眠，正成为一件需要被主动"哄"才能完成的事。

作为冥想与睡眠故事应用的重度用户，我深知这类产品的核心痛点。

市面上的助眠内容高度同质化、缺乏个性化，新鲜感难以持续--同样的故事听几次便失去效力。织梦的初衷由此而来：让用户通过客制化的场景选择，生成"一夜一故事、夜夜不重样"的专属内容，并打通语音合成与图像生成，将故事自动转化为配乐朗诵的沉浸式体验。

这个想法诞生于凌晨 1:30 的失眠之夜，三天后，它被 TRAE SOLO 变成了可运行的产品。

入睡困难夜间思绪难平，辗转至 1-2 点仍无法入睡，是大量成年人的真实状态。
内容同质化助眠内容千篇一律，缺乏个性化，听几次便失去新鲜感与效果。
体验割裂故事文本、人声朗诵、助眠配乐分散在不同环节，难以一键形成沉浸环境。
产品方案

6 维度自定义，千人千面的助眠内容

极简的卡片式交互背后，是端到端的多模态生成链路：用户选完 6 张卡片，一键"星河如梦"，即可获得配图、配乐、配声的完整睡前故事。

实践过程

从构思到 MVP，SOLO 是全栈技术合伙人

以 /plan 模式产出需求与架构文档起步，拆解任务、调用多模态模型、迭代体验，最终完成数据库与防盗刷闭环。

任务拆解

  • 规划/plan 模式先行：产出产品需求文档与技术架构文档，明确边界。
  • 前端6 维度卡片交互：实现时代、角色、剧情等维度的卡片式选择界面。
  • 逻辑故事生成服务：接收卡片组合，组装 Prompt 调用 LLM 生成节奏舒缓的故事文本。
  • 多模态语音与配乐：调用 TTS 转为舒缓女声，混入助眠音乐 / 白噪音。
  • 数据Supabase 数据库：游客织梦次数限制（2 次），登录后解锁更多次数，防止 token 被刷。

用到的 SOLO 能力

全栈代码生成快速搭建前端响应式卡片组件与后端 Node.js 服务接口。
API 调试对接辅助编写 LLM 文本生成与 TTS 语音合成的对接代码。
Bug 诊断与修复长文本转语音超时问题，快速排查并给出流式处理方案。

关键操作过程

  • 验证纯前端模式先行：先以下拉列表验证基础交互，确认符合预期后迭代为卡片模式。
  • 生图豆包 Seedream 生图：所有配图均由 AI 生成，统一梦境视觉风格。
  • 生声豆包语音大模型：单独合成温柔女声音色，契合睡前朗诵需求。
  • 生文豆包 Seed LLM Character：生成具备角色特征的睡前故事文本。
  • 迭代体验打磨：故事 Prompt 优化、自动生成卷首语、引入 front-end 优化 Skill 调整界面、增加流星特效与组件呼吸感动效。
  • 闭环数据库与防盗刷：游客 ID 使用次数限制防 token 盗刷，Supabase 保存用户数据。

踩坑与迭代

真实记录，边做边学的工程笔记

作为非技术背景的开发者，每一坑都是一次学习。这里如实记录已解决与待迭代的问题。

移动端适配

待迭代

目前仅上线 Web 端。睡前场景下用户多将手机置于枕边，移动端体验更为关键。

计划：后续优先做移动端适配，贴合真实使用姿势。

音色单一

待迭代

当前仅支持一种温柔女声。合成音色在句间、段间停顿仍不够，尚未完美契合睡前节奏。

计划：多合成几种音色供用户选择，或由 AI 根据故事场景自动分配；探索 SSML 接口调整句间 break。

SSML 接口未跑通

待解决

语音合成 2.0 的 SSML 接口未调通，无法精细控制两句之间的 break，影响朗诵节奏。

方向：排查接口鉴权与参数格式，后续迭代中解决停顿控制。

流星特效表现

待优化

纯 CSS 实现的流星效果一般。生成动画调用效果更好，但功能优先级较低、时间紧张，暂未尝试。

方向：后续以动画调用替代纯 CSS，提升流星真实感。

上下文过载

已解决

接入外部模型后，跑完 Trae 内置 coding plan quota，一度以为是自己模型的额度问题。

解法：实为上下文堆积导致 AI 跑不动，新开对话即可恢复。

Git 存档习惯

非技术背景开发全程摸爬滚打，git 存档是这场"开发游戏"的后悔药。

原则：每个阶段性成果务必 git 存档，随时可回退。
