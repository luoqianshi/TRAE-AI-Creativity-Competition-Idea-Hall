Why 桃源记

从自家桃园订单开始，做成可复用的农产销售系统

不是为了再做一个后台模板，而是为了解决「接单越来越多，Excel 和聊天记录越来越乱」这件事。

真实动机

家里有桃园。过去主要靠集市和商贩，后来在网上接单卖桃。订单一多，地址、快递单号、售后全散在微信里。 有客户催物流时，翻半天才能找到单号。这种管理方式撑不住增长。

所以做了 桃源记：既是自家卖桃的工具，也希望帮到更多同样处境的农户与合作社。

它大概是什么

一套可部署的 Web 销售管理系统，覆盖产品、渠道、客户（多地址）、订单、发货、物流、售后； 同时提供 AgentToken 鉴权的 /peach/agent/* API，接入 openclaw 后可用自然语言完成录入、查询与统计。

技术底座基于 FastSoyAdmin（FastAPI + Vue3），权限、缓存、部署与业务模块分层清晰，方便二次扩展到其他水果或农产品品类。

Pain Points

没有统一系统时，农户在忙什么

核心用户是种植户、小型合作社、农产品电商从业者，以及负责发货售后的人。

01
信息碎片化

微信、电话、电商平台各自记一笔，客户地址和历史订单对不上。

02
后台难上手

通用进销存太重，非技术人员学习成本高，旺季根本没空慢慢学。

03
物流售后靠人肉

单号靠截图，轨迹靠手动查；补发退款缺少闭环，客户体验不稳定。

Workflow

一条链走完桃园旺季

从建档到售后，状态连续、编号自动生成、运费可按省份规则计算。

1产品与渠道

品种、规格、售价、销售渠道建档

2客户多地址

一次建客，支持多个收货地址复用

3订单录入

单笔/批量建单，编号按年重置安全生成

4发货物流

批量发货 + 阿里云轨迹自动同步

5售后闭环

补发/退款记录，处理状态可追踪

Agent First

不会点菜单也能管订单

Web 后台给运营与管理者；智能体 API 给「说话就能办事」的日常场景。

言

自然语言操作

查客户、建订单、建发货、写售后、拉统计，按对话完成，而不是记菜单路径。

批

批量事务写入

批量建订单、批量建发货具备事务原子性，旺季高峰不怕写一半失败。

钥

AgentToken 鉴权

长效 token（pk_ 前缀）SHA256 存储、可吊销，智能体调用可审计。

权

三层权限 + 行级范围

菜单 / API / 按钮权限叠加 data_scope，适合合作社多角色协作。

Who & When

谁会用，什么时候用

种植户 / 销售者

电话或微信接单时，口述即可录入订单与地址。

合作社运营

统一多渠道销量与客户，减少表格对账。

仓配人员

拉待发货清单，批量生成发货并同步物流。

管理者

随时问利润、品种结构、渠道贡献，辅助决策。

Impact

效率价值 + 社会价值

先把自家生意管明白，再把方法沉淀成可复制的数字化工具。

效率怎么提升

  • 自然语言降低操作门槛，旺季少学复杂后台
  • 批量建单 / 发货减少重复劳动，事务保障一致性
  • 物流轨迹自动拉取，少翻快递 App
  • 多维统计即时可得，不再月底手工汇总

对社会意味着什么

  • 把数字工具做进真实农产场景，服务小微经营者
  • 帮助农户从「聊天记录式经营」走向标准化履约
  • 提升售后可追溯性，改善消费者信任
  • 技术栈可扩展，可从桃子迁移到更多农产品
