一、创意概述

创意名称

药不忘 —— AI 用药提醒与健康陪伴助手

想解决什么问题

  1. 老年人经常记不住吃药时间、药品剂量和饭前饭后等服药要求，容易漏吃、多吃或随意服用。
  2. 家里囤积了大量未吃完的药，后续就医可能重复开药，或原有药品被遗忘、过期造成浪费。
  3. 子女不在身边，无法及时了解父母的用药情况和健康状况。

为什么会想到做这个

  • 家中老人（父母）常受胃病、身体酸痛等困扰，习惯频繁就医吃药，各种药物交替服用，缺乏统一管理。
  • 老丈人因幽门螺旋杆菌治疗期间未能按计划完成四联用药疗程，导致首次治疗失败，不得不重新检查配药——"是药三分毒"，不规范用药既伤身体又浪费钱。

大概是什么产品

以微信小程序为主（老人无需下载 App，子女微信扫码即可绑定），同时提供 App 版本供家属深度管理使用。

二、目标用户及痛点

面向哪些用户

  • 60 岁以上、需长期服药的中老年人群
  • 患有多种慢性病、每天需要服用多种药物的人群
  • 因记忆力减退而经常忘记服药的长辈

在什么场景下使用

  • 日常居家场景：每天按时提醒老人服药，语音播报药品名称和注意事项
  • 就医后场景：拍照识别处方，快速录入用药计划
  • 家属远程场景：子女随时查看老人是否按时服药、近期健康状况和就诊记录

当前痛点

  1. 忘吃药、吃错药——时间记不清、剂量随性定、饭前饭后分不清
  2. 多种疾病反复发作，缺乏连续的健康记录，就医时说不清病史
  3. 家人不在身边，无法及时掌握老人的真实用药和身体状况

三、价值与意义

  • 对老年人：确保规律、正确地服药，减少用药错误对身体的损害，提升居家安全感。
  • 对频繁就医的人群：建立个人健康档案，记录用药历史、就诊信息和疾病变化，帮助医生更好地了解病情。
  • 对家属：远程了解父母健康动态，减少不在身边的焦虑，出现异常及时介入。
  • 对社会：减少药品浪费，降低因不规范用药导致的医疗资源消耗。

四、产品核心逻辑与可行性

用药信息如何录入？

采用"拍照识别为主、多渠道互补"的策略：

  • 拍照识别：拍摄医院药品贴纸、药品包装盒及说明书，AI OCR 自动提取药品名称、剂量、用法
  • 子女远程录入：家属在 App 端手动填写用药信息（无需老人动手）
  • 语音录入：老人语音描述药品名称和用量，系统自动识别匹配
  • 医生协助：就诊时由医生或护士帮忙录入（后续可与医院系统打通）

怎么确认老人真的吃了？

  1. 老人端极简确认：提醒后弹出占据全屏的大按钮"我吃了"，或语音回复"吃了"即可
  2. 超时自动升级：15 分钟未确认则再次语音提醒；30 分钟仍未确认，向家属发送微信通知
  3. 家属端被动知情：每日用药完成度卡片，绿色已确认、黄色待确认、红色超时未确认

家里囤积的旧药怎么处理？

  • 只管理当前在用药，停药的旧药不强制录入
  • 新就诊时提示："检测到您已有 XX 药品库存，是否优先使用旧药？"
  • 已录入药品自动计算有效期，临期前 1 个月提醒

与竞品有什么不同？

从"个人提醒工具"升级为"家庭用药协作平台"：

  • 家属远程共管：少有产品将"子女端"与"老人端"深度绑定
  • 全流程语音交互：从录入到提醒到确认，全程语音+大按钮，不用打字
  • 长期用药档案：形成连续健康记录，复诊时一键导出给医生

老人不会用智能手机怎么办？

  1. 子女完成所有复杂操作：首次设置、录入药品、调整时间——全部由子女在 App 端完成
  2. 老人端极致简化：只有"看今天吃什么药"、"按'我吃了'确认"、"听语音播报"三个功能
  3. 适老化设计：大字体、高对比度、按钮占满屏幕、没有二级页面

五、技术实现思路

该产品以"小程序+App"双端架构为主，后端基于 Java 技术栈，具体技术方案如下：

技术层 方案说明
前端 老人端微信小程序（极简界面，语音交互）+ 家属端 App（功能完整，数据管理）
后端 Java + Spring Boot，管理用户数据、用药计划、推送服务、健康档案
AI 能力 OCR 识别药品标签/处方、语音识别转文字、智能用药提醒推送
数据库 MySQL/PostgreSQL 存储用户、药品、用药记录等核心数据
推送通知 微信模板消息 + 语音播报（小程序内语音播放）
一句话总结：利用 AI OCR + 语音交互实现"拍照录入—语音提醒—大按钮确认—家属远程共管"的全流程用药体验，后端 Java 全家桶支撑数据与推送服务。
