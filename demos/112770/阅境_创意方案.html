一、创意名称与创意介绍

创意名称：《阅境》— AI 小说人物关系全景探索器

想解决什么问题

读过群像小说的人都有这个经历——人物太多、关系太复杂，读着读着就搞不清"谁是谁""谁和谁什么关系"。现有的解决方案只有书前的"人物表"（静态文字，难以呈现关系的全貌）和读者自己手绘关系图（费时费力，且容易遗漏）。市面上缺少一个能自动生成、直观展示小说人物关系的产品。

为什么会想到做这个

我自己在阅读复杂小说时就经常需要画人物关系图来辅助理解，也经常在网上搜索别人整理的关系图谱，但质量参差不齐。如果我喜欢的每本小说都能自动生成一张清晰、可交互的人物关系图，甚至能在此基础上玩一个推理小游戏来检验自己是否真的"读懂了"，阅读体验会提升很多。

大概是什么产品

一个交互式网站，用户输入小说名称后，AI 自动提取人物关系并生成可交互的图谱，同时提供角色档案、关系推理小游戏等功能，把"读懂人物关系"变成一次可视化探索体验。

二、目标用户及痛点

面向哪些用户：核心用户是 16-35 岁的小说读者（尤其是喜欢群像小说、经典文学的读者），延伸用户包括学生（语文阅读辅助）和内容创作者（同人写作/书评参考）。

在什么场景下使用：刚读完一本人物众多关系复杂的小说后梳理思路；阅读过程中遇到"这个人前面出现过吗"的困惑时；为写读书报告、书评、同人作品而需要系统性的人物关系参考。

当前痛点：复杂小说的人物梳理全靠手动——翻书标记、手绘关系图、反复回看前文。这个过程耗时且容易出错，且读完后整理好的图谱也难以保存和复用。更关键的是，这个过程完全没有互动性和趣味性，像一个苦差事。

用户群体详细分析

用户群体使用场景为什么需要
小说读者（16-35岁）读完复杂小说后梳理人物关系很多小说人物众多、关系复杂，读者容易搞不清
学生（初高中/大学生）语文/文学课的阅读辅助需要快速理解经典文学中的人物关系
内容创作者创作前的参考资料、写作辅助需要系统性的人物关系参考
轻度娱乐用户碎片时间的互动小游戏体验喜欢脑力挑战类小游戏，对文学人物有好奇心

核心用户画像：22 岁的大学生"小林"，刚读完《百年孤独》，被七代人的复杂关系搞得一头雾水。她想要一个工具帮自己快速理清人物关系，同时觉得如果能在梳理过程中玩个小挑战会更有趣。

三、价值与意义

效率提升：将读者手动梳理人物关系的过程从"数小时"缩短到"几秒钟"。AI 自动分析小说文本，一键生成完整的关系图谱和角色档案，大幅降低阅读复杂小说的认知负担。

社会价值：为经典文学和复杂作品的阅读提供一个全新的工具入口。很多年轻人对经典文学"望而却步"的根源就是"人物太多记不住"——如果有一款产品能帮他们轻松理清关系网，就能成为年轻人走进经典文学的"敲门砖"，促进深度阅读。

四、产品功能设计

功能一：AI 人物关系网生成器（核心功能）

  • 用户输入小说名称（如"红楼梦""三国演义""哈利波特"），系统自动提取所有关键人物，生成可交互的关系图谱
  • 节点 = 角色，节点大小 = 出场频率/重要程度
  • 连线 = 关系类型（亲属、恋人、师徒、敌对、合作等），不同关系用不同颜色和线型区分
  • 支持缩放、拖拽、点击节点查看人物详情、筛选特定关系类型
  • 提供"时间线模式"：展示人物关系随剧情推进的变化过程

功能二：角色档案馆

  • 点击任意人物节点，自动生成该角色的详细档案：
    • 基础信息：姓名、身份、阵营
    • 性格雷达图：基于 AI 分析的性格维度（勇敢、智慧、善良、野心等）
    • 人物弧线：该角色在故事中的成长/转变轨迹
    • 关键台词：该角色的代表性语句摘录
    • 关系总览：以该角色为中心的关联关系图

功能三：人物关系推理小游戏

  • 模式 A — 隐藏关系挑战：系统展示部分人物关系网，但隐藏了某些关键连线，玩家根据已知的角色信息和故事线索，推断缺失的关系
  • 模式 B — 角色身份猜测：给出一段人物描述和若干关系线索，让玩家猜这个角色是谁
  • 模式 C — "如果"推演：假设某两个角色的关系发生变化（如由友变敌），AI 推演故事走向的可能变化
  • 通关后解锁该小说的"隐藏人物关系彩蛋"

功能四：社区书架（轻量社交）

  • 预置经典小说的人物关系图谱（红楼梦、三国演义、三体等）
  • 用户可以"收藏"已探索的小说，形成个人书架
  • 推荐机制：基于你探索过的小说类型，推荐人物关系同样丰富的作品

五、可用数据来源

以下数据来源均已验证可用性与版权安全性，可直接用于产品预置内容。

中国古典小说全文数据（公有领域，可自由使用）

资源收录作品费用
Project Gutenberg（古登堡计划）三国演义、红楼梦、水浒传、儒林外史、封神演义、搜神记、聊斋志异等数十部免费
中国哲学书电子化计划（ctext.org）四大名著、诸子百家、史书、诗词，提供公开 API免费（有频率限制）
维基文库（zh.wikisource.org）大量中国古典文学，CC BY-SA 协议免费
GitHub chinese-poetry5.5 万首唐诗 + 26 万首宋诗 + 四书五经，JSON 格式MIT 协议

推荐组合：从 Project Gutenberg 获取四大名著的 TXT 纯文本作为预置小说全文；ctext.org 的 API 做扩展查询。

作品版权状态能否使用

关键建议：产品初期应只预置公有领域的中国古典小说。推理小游戏也只基于公有领域作品出题。用户自行上传文本进行分析展示图谱时，法律风险较低，但需要加入用户协议免责条款。

现成的四大名著知识图谱数据集

GitHub 上已有现成的四大名著知识图谱三元组数据集（CSV 格式，主语-谓语-宾语结构），这意味着你不需要从零做 AI 人物关系提取，可以直接用这些现成数据来生成人物关系网，大幅降低开发难度。

七、可行性检查要点

在开始开发前，需确保以下几点已落地：

  • 版权安全：只预置公有领域作品，推理小游戏也只用公有领域内容
  • 数据来源：使用 Project Gutenberg 的四大名著 TXT 文本和 GitHub 现成知识图谱三元组数据集
  • 时间分配：评估大赛时间线和可用时间，确保产品能在截止前完整演示
  • 用户上传：若允许用户上传文本分析，需加入用户协议免责条款
