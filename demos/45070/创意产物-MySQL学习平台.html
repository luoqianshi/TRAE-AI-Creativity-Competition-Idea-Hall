SQL 沙箱 · 电商订单分析场景
前端训练沙箱 · 模拟校验
表结构
users (id, name, ...)
products (id, name, ...)
orders (id, user_id, ...)
order_items (...)
题目
统计每个用户最近 30 天的订单总金额，按金额降序排列，取前 10 名。
SQL 编辑器
SELECT u.name, SUM(oi.price * oi.quantity) AS total_amount FROM users u INNER JOIN orders o ON u.id = o.user_id INNER JOIN order_items oi ON o.id = oi.order_id WHERE o.created_at >= '2024-06-01' GROUP BY u.id, u.name ORDER BY total_amount DESC LIMIT 10;
校验通过
包含必要的 JOIN、GROUP BY、ORDER BY 和 LIMIT。结果逻辑正确。
优化建议
可考虑为 created_at 和 user_id 添加联合索引，避免全表扫描。

大厂高频面试题型

抽象真实业务面试风格，不声称来自任何公司内部题库。

SQL 手写：查找连续 3 天登录的用户
困难 高频 SQL 手写题
考察点：日期运算、ROW_NUMBER 窗口函数、自连接思路。常见变体：连续 N 天、最长连续登录天数。
MySQL 原理：索引为什么会失效？
进阶 高频 MySQL 原理题
考察点：B+ 树索引结构、最左前缀原则、隐式转换、函数操作列、范围查询后索引失效。面试官常追问：如何验证索引是否被使用？
性能优化：千万级数据表分页查询慢
困难 高频 性能优化题
考察点：LIMIT 深分页问题、覆盖索引、延迟关联、游标分页（seek pagination）。常见变体：ORDER BY + LIMIT 优化。
数据库设计：秒杀场景库存扣减
困难 设计题
考察点：乐观锁 vs 悲观锁、库存预扣、事务隔离级别、行锁粒度、热点行问题。面试官常追问：如何防止超卖？

错题复盘

自动记录错误，分析原因，给出正确思路。不是简单的"错了"，而是"为什么错"。

统计每个用户订单总金额时遗漏了 order_items 表
错误原因：只 JOIN 了 orders 表，没有关联 order_items，导致统计的是订单数而非商品金额。
正确思路：需要 users → orders → order_items 三表 JOIN，金额计算在 order_items 层。
WHERE 中使用了聚合函数 SUM()
错误原因：WHERE 子句不能过滤聚合结果，需要使用 HAVING。
正确思路：先用 GROUP BY 分组，再用 HAVING SUM(amount) > 1000 过滤聚合结果。
LEFT JOIN 后使用 WHERE 过滤右表字段
错误原因：WHERE 过滤右表会把 LEFT JOIN 变成 INNER JOIN，丢失没有匹配的行。
正确思路：右表过滤条件应放在 ON 子句中，或明确是否需要 INNER JOIN。
