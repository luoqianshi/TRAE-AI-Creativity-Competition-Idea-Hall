项目背景

获客成本越来越高，传统管理系统已无法适应市场环境。我们有一套用了近10年的 ASP.NET + SQL Server 架构老系统，源码丢失、无法维护，更无法适配移动端。

这套老系统曾是医院客服团队的得力助手，但随着移动互联网时代的到来，客服们需要随时随地用手机跟进客户，而老系统只能在PC端使用，且界面陈旧、操作繁琐。重构一套支持PC+移动端、带智能回收机制的CRM系统，已成为当务之急。

更重要的是，这套系统不仅适用于医院，同样适用于传统CRM销售团队——任何需要管理客户资源、防止资源沉睡的销售场景，都能从中受益。

为什么必须重构？

  • 老系统技术栈陈旧（ASP.NET MVC 5 + jQuery EasyUI），源码丢失，仅存DLL编译文件
  • 无移动端支持，客服无法随时随地跟进客户
  • 缺乏资源回收机制，客户资源大量沉睡浪费
  • 无法适应现代获客成本高、转化周期短的市场环境

1. 创意名称 + 创意介绍

创意名称

客资不沉睡 — 医院CRM客服跟踪系统

让每一份客户资源都被认真对待，拒绝"占坑不跟进"。

想解决什么问题

医院客服/咨询员经常"占着客户不跟进"——手里攥着大量客户资源却迟迟不转化，导致优质客户被闲置浪费。同时新客服接不到客户，老客服客户堆积，团队整体转化率低下，医院管理者对此束手无策。

为什么会想到做这个

传统CRM只记录客户信息，缺乏资源流转机制。现实中很多客服接了客户就"放着"，既不跟进也不释放，造成严重的资源内耗。需要一个带"强制回收"和"公池流转"机制的系统，让每一份客户资源都能被积极跟进，杜绝"沉睡客资"。

大概是什么产品

一个面向医疗机构及传统销售团队的B端CRM系统（PC管理后台 + 移动端H5），核心亮点是"客户资源配额管理 + 自动回收 + 公池流转"机制，倒逼客服/销售认真对待每一个客户。

👥

📊

销售团队

同样适用于传统CRM销售场景，管理销售线索

在什么场景下使用

  • 客服每天登录系统，查看今日待回访客户，跟进后录入记录
  • 客服客户数接近配额上限时，必须主动清理低效客户或加速转化
  • 系统自动将超期未转化的客户回收至公池，其他客服可认领
  • 组长根据公司规定和每个客服的能力调配初诊/公池客户配额
  • 客服在手机上随时随地查看客户、录入跟进记录

当前痛点

  • 客服无限制接单，手里客户越积越多，大量客户被"放着不管"
  • 没有回收机制，客户一旦分配给某个客服就"石沉大海"
  • 新入职客服拿不到客户，老人占着资源不产出，团队矛盾大
  • 管理者无法量化每个客服的"客户消化能力"，配额分配凭感觉
  • 老系统无移动端，客服无法在外出或下班后跟进客户

3. 价值与意义

效率提升

系统为每个客服设置客户配额上限（初诊客户100个、公池客户200个），初诊客户14天内未到诊则自动回收至公池，公池客户30天内未到诊则再次回收。客服必须主动跟进、及时转化或手动释放，否则无法接收新客户。

这从根本上杜绝了"占坑不跟进"的现象，让每一份客资都"活"起来。

商业价值

通过配额管理和自动回收，确保每一份客户资源都在高效流转中。组长可按公司规定动态调配配额，强者多得、弱者少占，整体客户转化率显著提升。

同时复用原有SQL Server数据，实现零成本数据迁移，快速上线。新系统采用Python FastAPI + Vue 3技术栈，支持PC和移动端，彻底告别老旧技术债。

"获客成本越来越高，每一分钱都不能浪费。客资不沉睡系统，就是让每一分获客投入都产生最大回报。"

4. 核心规则说明

以下为系统核心资源回收与流转规则：

规则项 说明
初诊客户配额 每个咨询员最多同时持有100个初诊客户
初诊回收周期 14天内未到诊，自动回收至公池
公池客户配额 每个咨询员最多同时持有200个公池客户（不占初诊配额）
公池回收周期 30天内未到诊，自动回收至公池
到诊归属 客户一旦到诊，永久归属当前跟进客服，不再回收
回收后限制 被回收的客户，原客服不可再次认领
配额调配 组长/主管根据公司规定和客服能力，动态调整每个客服的初诊/公池配额
超额处理 客服接入新客户导致超配额时，必须手工释放现有客户，否则无法接收新客资

5. 技术架构

全新技术栈，彻底告别10年老系统的技术债

后端 Python 3.12 + FastAPI
前端(PC) Vue 3 + TypeScript + Naive UI
前端(H5) Vue 3 + Vant 4 + UnoCSS
数据库 SQL Server（复用现有）
认证 JWT + bcrypt
缓存 Redis
部署 Docker + docker-compose
ORM SQLAlchemy 2.0

重构优势

  • 数据零丢失：复用现有SQL Server数据库，完整保留历史业务数据
  • 跨平台支持：PC端管理后台 + 移动端H5，随时随地办公
  • 现代化体验：响应式界面、流畅交互，告别老旧EasyUI风格
  • 高可维护性：Python + Vue主流技术栈，人才招聘和二次开发更容易
