核心机制

四大模块 · 无缝协作

从代码变更到文档更新，每一步都有精确的机制支撑

文档索引机制

每份文档顶部有一段特殊的索引标记，描述该文档覆盖的内容范围。 系统根据这份索引来匹配代码变更，只更新相关的文档。

> 本文档覆盖内容
> 数据库连接配置、表结构定义
> 迁移方案说明、性能优化建议

变更感知引擎

深度解析代码变更，识别修改了哪些文件、函数、配置项。 提取变更的语义信息（如"修改数据库连接"或"新增 API 接口"）， 为后续文档匹配提供依据。

src/db/connection.ts 数据库相关 · 匹配
src/api/user.ts 接口相关 · 匹配
src/utils/helper.ts 无匹配文档 · 跳过

智能文档生成

基于变更语义和文档索引，调用大语言模型生成精准的文档更新内容。 只修改文档中受影响的段落，保持其他内容不变，避免 AI 幻觉污染整篇文档。

+ host: postgres.internal.svc
+ port: PostgreSQL 默认端口
- host: mysql.localhost
- port: MySQL 默认端口

审核确认写入

所有文档更新在写入前需用户确认。以可视化 diff 方式展示变更内容， 用户可接受、拒绝，或手动编辑。所有变更通过 Git 管理，支持任意版本回滚。

命令行操作

通过简洁的命令行指令，即可启动文档监听、手动触发同步， 或查看当前项目的同步状态。

终端 · 命令示例
$ docsync init
在当前项目初始化文档同步配置
$ docsync watch
启动监听模式，每次 commit 自动触发
$ docsync sync --file src/db/connection.ts
针对指定文件手动触发文档同步
$ docsync status
查看当前项目的文档同步状态
