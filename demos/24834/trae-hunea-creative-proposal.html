SDK规划

在项目目录提供全屏终端界面，完成对话、工具调用、命令执行与会话管理。界面与交互为产品核心；模型接入与 Agent 运行时解耦，不绑定单一供应商；扩展与 SDK 用于后续自定义工作流。

定位

终端 coding agent 分为交互层（布局、键盘、流式展示、会话可见性、状态与错误反馈）与后端（模型调用、工具编排）。Hunea 以前者为主，后者通过配置与未来可切换内核、SDK 接入。

当前版本提供默认工具循环与会话持久化；扩展机制按该边界预留，尚未全部实现。

产品结构三层

TUI

Ratatui 全屏界面、slash 命令、状态行、主题、/resume、历史回退与续写。

默认运行时

多轮工具调用，cwd 为项目路径；models.toml 与 .hunea 配置 provider。

扩展

SDK、可切换内核，自定义工作流；壳层统一 TUI 与接口约定。

设计要点

  • 终端与 SSH 场景下，TUI 覆盖连续使用所需的会话与反馈能力。
  • 会话落盘；恢复后 transcript 与模型选择一致；工具错误可辨识。
  • 模型经配置与 /models 切换；工作流差异拟由扩展接入。
  • 交互习惯参考 Pi 等 terminal coding harness；Rust 独立实现。

使用方式

在仓库根目录执行 hunea，于同一界面描述任务并审阅工具输出与命令结果。

示意

user 修复失败测试并运行 nextest

hunea 读取相关模块与测试…
read …
edit …
bash cargo nextest run -p …

长输入 Ctrl+G 外部编辑器；/resume 历史会话。见 config.example.toml、models.example.toml。
