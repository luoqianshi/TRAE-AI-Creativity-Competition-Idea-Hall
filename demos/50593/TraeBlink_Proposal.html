1创意介绍

想解决的问题：使用 TRAE AI IDE 编程时，AI 助手会经历"思考 → 执行工具 → 生成回复 → 完成"等多个状态。开发者必须把视线切回 TRAE 窗口、移动鼠标查看对话区才能知道 AI 进展，频繁的状态查询会打断编写代码时的心流。

为什么会想到：我在使用 TRAE 长会话编程时发现，AI 在思考或调用工具期间是几秒到几十秒的"空窗期"，我常常不确定它是在工作还是卡住了，只能反复切窗口确认。桌面上有一盏 ESP32 RGB 灯，意识到它正好可以成为 AI 状态的物理指示器——用光效传递状态，用颜色表达情绪。

大概是什么产品：一套软硬件结合系统，包含 ESP32-C3 固件（控制 RGB LED 灯效）+ Python 桥接脚本（监听 TRAE Hook 事件）+ TRAE Hook 配置。即插即用，安装后 LED 会实时跟随 AI 工作状态变化。

2目标用户与痛点

面向用户：使用 TRAE AI IDE 进行日常编程的开发者，尤其是长会话、重度 AI 协作的用户。

使用场景：开发者专注编写代码或查阅文档时，AI 在后台执行生成、调用工具、调试等任务。开发者需要余光感知 AI 状态，而不是频繁切窗口。

痛点 1：心流被打断
每次想知道 AI 进展都要切窗口，注意力被反复拉回 TRAE 界面
痛点 2：状态不直观
软件界面的状态文字不够显眼，远处或余光根本看不清
痛点 3：多任务难兼顾
同时开多个 AI 会话时，无法一眼分辨哪个会话需要关注
痛点 4：错误响应不及时
AI 报错或等待权限时，开发者可能几分钟才发现

3解决方案：7 种状态 × 7 种灯效

系统将 TRAE 的 7 个核心事件映射到 7 种独立的灯效，让开发者仅凭余光就能精准识别 AI 当前所处的状态：

LED 状态 对应 TRAE 事件 灯效表现 含义
thinking PostToolUse 红黄绿连贯跑马灯（呼吸式流动） AI 正在生成回复内容
ai UserPromptSubmit 柔和慢速跑马灯（低亮度） 用户输入消息，AI 开始接收
busy PreToolUse 黄灯慢闪（0.8s 间隔） 系统正在执行关键操作命令
success Stop 绿灯常亮（60s 后自动灭） 任务流程已顺利完成
error PostToolUseFailure 红灯快闪（0.3s 急促间隔） 执行过程中发生运行错误
alarm Notification（权限请求） 红黄交替警灯（高频切换） 严重异常或等待用户权限
off SessionStart / SessionEnd 全灭（无光输出） 系统关闭或空闲待机

4技术架构

系统由三层组成，事件从 TRAE 流向 ESP32 LED，全链路延迟 < 100ms：

1
TRAE Hook 层 在 .trae/hooks.json 注册 UserPromptSubmit / PreToolUse / PostToolUse / Stop / Notification 等事件钩子，每次状态变化时由 TRAE 自动触发
2
Python 桥接层 trae_led_hook.py 接收 Hook 事件 → 推断 LED 状态 → 通过 TCP（WiFi）或串口（USB）发送指令到 ESP32。带状态持久化、看门狗、自动回退机制
3
ESP32 固件层 esp32c3_ai_status_led.ino 监听 TCP Server（8080端口）+ USB 串口双通道，解析 led:<state> 指令，基于 millis() 状态机驱动非阻塞 LED 动画
ESP32-C3 RISC-V Arduino Core 3.x WiFi (TCP 8080) USB CDC Serial Python 3.10+ pyserial TRAE Hooks API PWM LEDC 非阻塞状态机
