项目概述

以经典玩法为基础,融合复古像素美学、深度社交互动和轻量商业化设计

「经典怀旧俄罗斯方块」是一款面向微信小游戏平台的休闲益智游戏,以经典俄罗斯方块核心玩法为基础,融合复古像素美学、深度社交互动和轻量商业化设计,打造一款"好玩、好看、好分享"的精品休闲游戏。

产品理念

熟悉的绿屏、像素网格、叮叮咚咚的 8-bit 音乐,一切都是那个味道

核心定位

怀旧为魂、休闲为骨、社交为翅膀,让每一位玩家都能找到熟悉的感动

情感共鸣

对童年游戏时光的追忆、对纯粹乐趣的向往,这款游戏承载的不只是玩法

▌CHAPTER 03▐

核心玩法设计

三种核心模式,覆盖不同场景需求

3.1 游戏模式

MODE 01

经典无尽

传统俄罗斯方块玩法,不断加速消行,追求最高分。简单纯粹,适合快节奏碎片时间。

MODE 02

马拉松闯关

设定多个关卡,每关有特定目标(如消除 25 行、达到某分数等),逐关递增难度。提供成就感和目标驱动。

MODE 03

好友对战

实时 PvP,消行后向对手发送干扰行。支持随机匹配和好友邀请对战。

3.2 七种标准方块

包含七种经典方块:I、O、T、S、Z、J、L,采用 SRS(超级旋转系统)标准,确保旋转行为与玩家认知一致。

▌CHAPTER 04▐

视觉风格与主题设计

Game Boy 绿屏为灵魂,多套配色主题随心切换

4.1 设计理念

以 Game Boy 绿屏为主基调,局部还原真实 LCD 屏幕质感,包括像素网格、屏幕略微偏色、像素间隙等细节。同时支持多套配色主题切换,保持新鲜感。

4.2 主题配色方案

GB经典绿

原汁原味 GB,默认主题

红白机复古

接电视玩的感觉

纸带机棕榈

暖色调,温柔怀旧

夜间樱桃花

可爱治愈系

极简白墨

极简现代感

4.3 屏幕后处理特效

  • 像素网格覆盖: 模拟真实 LCD 像素间隙
  • CRT 扫描线: 可开关的复古显示器效果
  • 屏幕偏色模拟: 轻微的色彩偏移,还原老化屏幕质感

4.4 UI 元素风格

  • 所有按钮、边框、文字均采用像素风格渲染
  • 字体使用像素点阵字体,还原 8-bit 游戏 UI 感
  • 界面过渡动画采用像素逐帧风格,非平滑动画
▌CHAPTER 05▐

音效与音乐设计

8-bit 芯片音乐,唤醒每一段游戏记忆

5.1 音效风格

所有音效采用纯 8-bit 芯片音乐风格,模拟 Game Boy 的方波/三角波合成音。通过程序化音效合成引擎实时生成,避免音频资源占用包体大小。

5.2 音效列表

操作音效描述
方块移动短促的"哔"声
方块旋转"啐啰"声
方块硬降/锁定"呛"声(低沉打击感)
消行渐强的"啊"声,多行消除时更强烈
游戏结束下降音阶的失败音效

5.3 背景音乐

以 8-bit 芯片音乐为主,提供多首曲目:

  • 经典俄罗斯方块 BGM《货郎》的像素改编版
  • 原创 8-bit 背景音乐,根据游戏进度逐渐升调
  • 不同主题搭配不同音乐风格变体
▌CHAPTER 06▐

社交功能设计

深度社交 + 微信生态,驱动裂变传播

6.1 好友排行榜

接入微信云开发排行榜,展示好友间的最高分排名。支持无尽模式、马拉松模式分榜。

6.2 成就分享

每局结束后生成像素风格的成就卡片,包含得分、消行数、T-Spin 次数等数据,支持一键分享到微信聊天和朋友圈。

6.3 好友对战

通过微信小游戏的实时帧同步能力,实现好友间的实时对战。发送邀请链接即可开始对局。

6.4 每日挑战

每日更新一个特殊挑战任务(如"仅用 T 旋转消行 10 次"),全服玩家排名,激发每日活跃。

6.5 战队系统

玩家可创建或加入战队,战队成员的总分进行排名,增强社群归属感和沉浸度。

▌CHAPTER 08▐

变现与商业化设计

激励广告 + 轻付费,平衡用户体验与营收

8.1 激励广告

  • 游戏结束后观看视频广告可复活一次
  • 观看广告获取限时道具(如"下一个方块变为 I 块")
  • 观看广告获取主题皮肤试用权

8.2 轻度付费

  • 去广告权益: 6 元一次性买断,移除所有广告
  • 主题皮肤包: 付费解锁特殊配色主题(如"赛博朋克风""蒸汽波浪"等)
  • 复活卡包: 购买复活次数,不需观看广告
▌CHAPTER 09▐

技术架构设计

五层分层架构,核心逻辑零依赖

9.1 架构分层

UI 层
主菜单、游戏界面、结算、排行榜、设置、商店、对战房间
ui/
渲染层
像素渲染器、主题管理、屏幕滤镜、粒子特效
render/
游戏逻辑层
状态机、方块系统、碰撞检测、计分、关卡、对战
core/
平台适配层
微信 API、云开发、广告、支付、帧同步
platform/
工具层
8-bit 音效引擎、存储、对象池、事件总线
utils/

9.2 设计原则

  • 核心逻辑零依赖: core 层不依赖 Canvas,也不依赖微信 API,可独立单元测试
  • 渲染与逻辑分离: render 层只负责绘制,不做任何游戏逻辑判断
  • 平台适配器模式: 所有微信 API 调用封装在 platform 层,方便后续移植
