问题与痛点

现有低代码平台
为什么对 AI 不友好？

市面上的低代码平台在设计时未考虑 AI 协作场景，导致 AI 难以理解平台结构，无法有效协助开发者构建应用。

DSL 不统一

各平台使用私有的数据模型描述语言，AI 无法跨平台理解项目结构，每次都需要重新适配。

→ Aiqua 提供三层元数据模型：Collection → Field → Block，结构清晰可解析

脚本引擎封闭

多数平台的脚本执行环境不开放，AI 生成的代码无法直接运行，需要额外的编译和部署步骤。

→ Aiqua 集成 GraalVM GraalJS，AI 生成的 JS 代码沙箱内即时执行

缺乏全链路可观测性

平台运行出错时难以定位，AI 无法获取执行现场，调试只能靠猜，协作效率极低。

→ Aiqua 内建全链路追踪 + 错误现场快照（变量/SQL/堆栈），AI 可精准诊断

工作流与报表割裂

审批流程和数据分析需要额外系统，AI 无法在同一平台内完成端到端的业务搭建。

→ Aiqua 集成 Flowable 工作流 + JimuReport 报表，一站式覆盖

AI 生成代码
GraalJS 引擎即时执行

AI 生成的 JavaScript 业务逻辑代码，通过 GraalVM Polyglot API 在沙箱中安全执行，支持 console 输出捕获和返回值提取。

Aiqua Engine — GraalJS Script Execution
// AI 生成的业务逻辑：筛选高分用户并排序
const users = [
  { name: "Alice", role: "admin", score: 95 },
  { name: "Bob", role: "user", score: 82 },
  { name: "Charlie", role: "user", score: 91 }
];
 
const topUsers = users
  .filter(u => u.score >= 90)
  .sort((a, b) => b.score - a.score);
 
return { count: topUsers.length, users: topUsers };
执行结果（耗时 12ms）
{ "count": 2, "users": [{ "name": "Alice", "score": 95 }, { "name": "Charlie", "score": 91 }] }
