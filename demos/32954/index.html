想解决的问题

自动化学习和调试的难点，不是只有“不会用 AI”，而是缺少一条能落到现场的排查路径。

知识碎片化

新手遇到 PLC 下载失败、HMI 变量不刷新、WinCC 通讯异常时，经常不知道先查网络、工程配置、站号还是接线。

协议太抽象

RS-232、RS-485、RS-422 和 Modbus RTU 涉及接线、主从关系、帧格式、CRC 校验，单靠文字不容易建立直觉。

记录整理慢

实训、课程设计和现场排障都需要调试记录，但新手常常有过程没结构，有截图没结论。

核心能力

真实 Demo 由桌面应用承载，HTML 页面用于向评委完整展示创意方案和演示路径。

故障诊断 Chat

围绕 Siemens S7-1200、TIA Portal、PLCSIM、WinCC 和通讯故障，把用户输入的现象转成分层排查步骤：先定位对象，再检查链路，再核对工程配置，最后形成处理记录。

USER: TIA 能 ping 通 PLC，但搜不到设备。
AI: 先检查 PG/PC 接口与实际网卡，再确认同网段、防火墙和设备访问方式。

价值收束

说明它帮助学生和初级工程师建立工程化排障思路。

价值与意义

这个创意的重点不是替代工程师，而是把“学习、排障、沉淀”连接起来。

学习效率

把 PLC、HMI、通讯协议等碎片知识转成可执行流程。学习者不仅得到答案，还能看到为什么这样排查，逐步形成工程直觉。

工作效率

常见故障可以按模板化路径检查，减少漏查 IP、站号、波特率、CRC、工程型号等基础项的时间。

文档沉淀

把排障过程整理成调试记录，可用于实训报告、课程设计、毕业项目材料和现场交接。

安全演示

支持离线演示模式，避免比赛录屏或现场展示时因为 API Key、网络环境、模型服务波动影响作品表达。
