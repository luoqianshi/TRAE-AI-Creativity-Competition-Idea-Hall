行业痛点

单模型不够用，多智能体又管不住

当前主流编码大模型大多为独立单体智能体，缺少标准化协同调度能力。多 Agent 联用时存在四大行业痛点。

01
🔌

接口协议不互通

Claude Code、Codex、OpenCode 等异构编码智能体接口格式各异，接入和二次适配成本极高，缺少统一管控底座。

02
🔀

输出交织混乱

多 Agent 并行工作输出内容互相交织，无法区分各智能体产出成果，长会话变成一团乱流。

03
💸

Token 成本失控

长会话协作上下文冗余爆炸，Token 资源消耗不可控，模型容易上下文溢出，重复返工。

04
⚠️

文件操作无安全闸门

AI 自主修改工程文件存在高危风险，无人工审批极易破坏项目代码；任务中断后无规范回溯机制。

创意方案

像用 Slack 一样，编排一支 AI 编码团队

一款 Web 端 IM 聊天形态的异构多智能体协同开发系统。以对话交互为入口，实现多编码智能体并行调度、上下文预算管控、安全沙箱工具审批全流程能力。

  • ✓

    单聊 + 群聊双形态

    单聊把聚焦任务交给单个 Agent；群聊 @ 多个 Agent，由编排者拆解任务、并行派活、验收合并。

  • ✓

    统一适配器层

    一套协议接入 Claude Code / Codex / OpenCode，加新引擎不用动核心，凭证自动复用已登录的 CLI。

  • ✓

    Burst 并行泳道

    并发的 Agent 工作以并行泳道呈现，绝不交织成一团乱流，每个 Agent 产物归属清晰。

  • ✓

    沙箱 + 人在回路审批

    每个 Agent 独立 git worktree，文件操作经 MCP 工具网关审批，冲突在聊天里引导式解决。

  • ✓

    上下文预算系统

    标准化上下文预算管控长对话资源消耗，配合任务中断、轨迹留存机制避免重复返工。
