03 / Pipeline

九阶段处理管线

1

PDF 解析

2

智能分段

按段落边界→句子边界→长度截断三级切分，可选LLM语义合并

3

并发段落分析

asyncio+Semaphore 并发调用 LLM，每段独立上下文注入，含缓存检查

4

聚合所有段落结果 → 研究问题/方法论/技术路线/实验结论

5

方法论提取（双路验证）

路径A全局理解 vs 路径B高分段落 → SequenceMatcher交叉验证

6

创新点深度分析

识别创新类别/机制/对比/挑战 → 为每个创新点生成代码片段

7

向量索引建立（可选）

8

代码生成（含自修正）

RAG增强Prompt → 多文件工程代码 → AST静态检查+沙箱运行+LLM修复

9

质量自检

逻辑一致性/信息完整性/不确定推断/代码质量 → 评分报告

04 / Stages 1-3

输入层：解析·分段·分析

Stage 1 — PDF 解析 (pdf_parser.py)

使用 PyMuPDF (fitz) 逐页提取纯文本，过滤页眉页脚噪音。输出包含 full_text、total_pages 的 ParsedPaper 对象。

Stage 2 — 智能分段 (text_splitter.py)

两级策略，优先级从高到低：

优先级分割依据场景
P1双换行符 \n\n自然段落边界
P2单换行符 \n列表/小节内部分行
P3句号/问号/感叹号长段落的句子级拆分
P4强制按 chunk_max_chars 截断超长句兜底

语义合并（可选）：相邻短块（<max_chars/2）通过 LLM 判断是否合并，额外消耗 API 调用但分段更精准。

Stage 3 — 并发段落分析 (paragraph_analyzer.py)

核心机制：

  • asyncio.gather() 全并发
  • Semaphore(max_concurrent) 控制QPS
  • 指数退避重试（base × 2^attempt）
  • 429限速自动延长等待时间

输出字段：

rolesummaryis_novel importance(1-5)confidencecore_concepts raw_understandingkey_technical_details

05 / Stages 4-6

理解层：全局·方法·创新

Stage 4 — 全局理解 (global_understanding.py)

将所有段落分析结果 + Memory中的关键要点/核心概念 聚合为一次 LLM 调用，生成结构化报告：

研究问题
research_problem
方法论
methodology
技术路线
technical_pipeline[]
实验结论
conclusions
主要结果
main_results[]
局限性
limitations[]
Stage 5 — 双路方法论验证 (路径五)
路径 A — 全局理解抽取
从 GlobalUnderstanding 整体报告中提取方法名、步骤、数据流、超参数
路径 B — 高分段落直接抽取
筛选 importance≥4 且 role∈{方法,实验,模型}的段落，独立抽取方法论

交叉验证：difflib.SequenceMatcher 计算每个字段的相似度，>0.8 视为一致取路径A；否则标记冲突供人工审核。
置信度 = 1 − 冲突字段数/总字段数（5个），冲突>2则 needs_review=true。

Stage 6 — 创新点深度分析 (innovation_extractor.py)

对 GlobalUnderstanding.innovations 中每个创新点进行多维度分析：

detailed_descriptioncomparison_to_prior core_mechanismimplementation_steps[] key_equations_or_concepts[]reproducibility_tips[] code_snippet (per-innovation)

每个创新点独立发起一次 LLM 调用生成 Python 代码片段，含类型注解和 docstring。

06 / Stages 7-9

输出层：检索·生成·自检

Stage 7 — RAG 向量索引 (vector_retriever.py)

向量模式（首选）

  • 模型：all-MiniLM-L6-v2 (~90MB)
  • 批量 encode 所有段落 → (N, dim) 矩阵
  • Cosine 相似度排序返回 top_k
  • 离线可用，无需 GPU

关键词模式（降级）

  • sentence-transformers 未安装时自动回退
  • Jaccard 相似度 = |A∩B| / |A∪B|
  • 零依赖，始终可用
Stage 8 — 代码生成 + 自修正循环 (code_generator.py)

输入：方法论文本 + 技术路线 + 创新点分析 + （可选）RAG相关原文

# 代码生成流程 1. detect_framework(text) → 自动检测 PyTorch/TensorFlow/JAX 2. llm.call_json(prompt) → 生成 project_structure{files[], main_entry{}} 3. extract_dependencies(code) → 正则匹配 import + 框架默认依赖 4. _generate_tests(result) → 为核心模块自动生成 pytest 单元测试 5. _self_fix_loop(result, N) → 最多N轮 AST检查+沙箱运行+LLM修复

自修正循环（路径二） — 每轮执行：

步骤工具检测内容
静态检查ast.parse()语法错误 / TODO数量 / pass空实现 / 缺少import
沙箱运行subprocess.run(timeout=15s)运行时错误 / 无限循环检测
LLM修复llm.call(fix_prompt)将issues列表注入prompt，要求仅修复不改动其他
Stage 9 — 质量自检 (self_checker.py)

LLM 驱动的四维质量评估：logic_consistencycompletenessuncertain_inferencescode_quality → 输出 0~1 评分 + 改进建议。LLM不可用时降级为规则打分。

07 / Optimization Paths

六条优化路径

P1并发异步段落分析
asyncio + Semaphore 替代顺序循环。可配置并发上限（默认5），按 API RPM 套餐调整。指数退避重试，429限速自动延长时间窗口。Streamlit 同步环境自动 nest_asyncio 兼容。
P2代码自修正循环
AST静态语法检查 → subprocess沙箱运行(15s超时) → LLM精准修复prompt。最多3轮迭代。每次记录diff供用户审查。修复仅针对检测到的问题，不改变其他逻辑。
P3增量断点续传
SHA-256(pdf_bytes)[:12] 作为论文指纹。每chunk分析成功后立即写盘缓存（JSON文件）。重启时先枚举已缓存序号，命中则跳过LLM调用直接反序列化。支持 force_rerun 强制全量重跑。
P4分级记忆管理 (TieredMemory)
Tier1(importance≥4): 永不压缩，上限30条，超出按confidence淘汰降级
Tier2(importance2-3): LLM摘要压缩，保留chunk_id回溯
Tier3(importance=1): 仅计数，不存内容，零开销
P5双路方法论验证
路径A从全局理解抽取 vs 路径B从高分段落独立抽取。SequenceMatcher计算5个字段相似度，>0.8一致否则标记冲突。置信度=1−冲突数/5，冲突>2触发人工审核(HITL)。
P6向量检索增强代码生成 (RAG)
段落分析完成后批量建向量索引(all-MiniLM-L6-v2)。代码生成时按技术路线每步retrieve(top_k=2)，将最相关原文动态注入prompt。未安装sentence-transformers时Jaccard关键词降级。
08 / Memory Architecture

记忆与上下文系统

TieredMemoryManager — 三级分层架构
TIER 1
永不压缩 · importance ≥ 4 的完整分析结果 · 上限30条 · 超出按confidence淘汰并降级到Tier2 · 核心方法段落永久保留
TIER 2
LLM摘要压缩 · importance 2-3 的精简版本 · 超过50条触发压缩 · 保留chunk_id用于回溯定位 · 压缩后合并为单条聚合摘要
TIER 3
仅计数 · importance = 1 的低价值段落 · 不存储任何文本内容 · 仅维护计数器 · 零token开销
ContextManager — 三层上下文拼接

10 / Future Directions

优化方向

01 / 流式输出与增量渲染
当前各阶段等待完整LLM响应后一次性更新UI。可改为流式逐token推送，用户实时看到分析过程而非等待进度条。需改造 LLMClient.call_stream 与 Streamlit callback 机制。
02 / 多模态论文解析
当前仅支持文字版PDF。扩展视觉模型(VLM)解析图表/公式图片 → 将图表描述注入对应段落上下文。公式可通过 LaTeX OCR 提取后保留原始符号表达。
03 / 自适应分段策略
固定 chunk_max_chars 对不同类型论文（理论vs实验vs综述）不够灵活。可先用轻量级分类器判断论文体裁，再选择最优分段参数。或引入递归文档树结构替代扁平分块。
04 / 代码执行验证升级
当前沙箱运行仅检测基本报错。可集成 Docker 容器隔离执行 + pytest 自动跑通 + 输出shape/type校验 + 与论文中报告指标数值对比验证正确性。
05 / 知识图谱持久化
跨论文的分析结果可构建领域知识图谱：概念实体关系抽取 + 方法论模板库积累 + 复现成功率统计反馈给分段/分析策略形成闭环学习。
06 / Prompt 工程自动化
当前 prompt 模板为手工设计。可引入 DSPy/Opus 等框架做自动 prompt 优化：根据历史分析质量评分反向调整 prompt 结构与示例，持续提升各模块输出稳定性。
07 / 成本优化
大论文（50+段）API成本显著。方案：① 低重要性段落用小模型(Qwen3-8B)快速过筛 ② 引入本地7B模型做初筛+云端32B模型精析的两级流水线 ③ 缓存命中率优化（相似论文复用）。
