PROBLEM

为什么计划总是不靠谱？

  • 🎯
    高估自己的容量

    以为一天能做8小时深度工作，实际稳定输出可能只有3-4小时。计划建立在不真实的假设上，必然失准。

  • 📉
    估时偏差没有校准

    每次都低估"写文档"要花的时间，但从不调整下次的预估。同样的错误反复犯，却没有数据让你发现模式。

  • ❓
    分不清是"排太多"还是"没做好"

    计划没完成时，不知道是该减少任务量，还是该提高执行力，还是该调整估时系数。缺少诊断依据。

  • 😊
    效率工具反而制造焦虑

    待办列表越来越长，未完成的任务像债务一样堆积。工具在催促"你还能做更多"，而不是帮你理解真实容量。

SOLUTION

三层架构，让计划逐步可信

通过"计划—执行—偏差—调整"的循环，用数据替代直觉，用实验替代猜测。

核心创新：AI 不直接给建议让你信，而是设计可验证的校准实验——
应用调整系数 → 记录5个样本 → 统计对比 → 用户确认 → 形成规则。
AI 不自动改变计划或规则，所有调整需用户确认后才生效。让"计划变得可信"这件事，有证据、可追溯、能迭代。

CORE SCENARIOS

五个核心场景

覆盖用户从计划到校准的完整路径，每个场景都有明确的交互闭环。

① 今日计划总负荷与超载提醒

安排今日任务时，系统汇总当日预估总时长，与个人容量区间对比。

超出容量中位数时提醒"今日计划已超载 X%"，但不阻止用户安排——只是让超载可见

② 开始/暂停/结束计时

执行任务时提供计时器：开始、暂停（记录中断）、结束（写入实际时间）。

降低记录成本，实际时间自动填入偏差计算，无需手动估算

③ 每周校准报告

每周自动生成校准报告：本周兑现率、偏差最大的类型、容量变化趋势。

AI 解读报告并建议下一步行动方向，用户可追问

④ 实验成功后需用户确认才保存规则

校准实验结果有效时，AI 建议"保存为个人规则"，但必须用户点击确认。

AI 不自动改变任何规则或计划，所有调整需用户确认生效

⑤ 创建同类任务时显示历史估时范围

新建任务选择类型后，显示该类型的历史估时范围和偏差模式。

如"深度工作：你通常估 2h，实际平均 2.8h（低估 38%）"，辅助更准确的预估
LAYER 1 · STATISTICS

统计层：用数据说话

7个核心指标，全部通过代码计算，不依赖AI，保证客观性。

计划兑现率

完成任务数 / 计划任务数

排除已放弃任务，只统计有效承诺

估时偏差

实际时间 vs 预估时间的偏差率

区分"低估"（实际更多）和"高估"（实际更少）

分类型估时误差

按任务类型拆分偏差模式

发现"总是低估深度工作，高估行政事务"的模式

个人容量区间

基于历史数据的真实产出范围

给出周产出的 min/中位数/max，而非单一均值

滚存债务

未完成任务的累积负载

量化"欠了自己多少时间"，可视化债务趋势

执行状态诊断

交叉判断失败原因

区分：计划过载 / 执行下降 / 估时不准

+ 置信程度标注

基于样本量自动分级：高（≥10）/ 中（5~9）/ 低（<5）

样本不足时明确标注"证据不足，仅供参考"，避免过度解读

LAYER 2 · REASONING

推理层：AI 帮你解释"为什么"

把结构化统计结果交给 AI，输出自然语言解释和行动方向。

判断优先级

哪个偏差最值得先处理？AI 综合样本量、偏差幅度给出排序

多指标归因

结合兑现率、利用率、偏差率交叉解释失败原因

区分根因

计划过载（排太多）vs 执行下降（状态差）vs 估时不准（系数问题）

诚实标注

明确指出"证据不足"的地方，不强行下结论

+ 自然语言追问

用户可以自由提问："我的容量为什么这么低？""下周该怎么排？"

AI 基于当前统计上下文回答，而非泛泛而谈
LAYER 3 · ACTION

行动层：用实验闭环替代直觉

AI 基于证据提出可验证方案，数据说了算。

原始估时
2.0h → 偏差 +38%
校准后
×1.4 = 2.8h → 偏差 +11%
5个样本后对比：调整前绝对偏差 38% → 调整后 11%

提出假设

AI 根据统计数据建议："深度工作可能需要 ×1.4 校准"

设计实验

应用系数 → 记录5个样本 → 统计层自动计算对比

解读结果

AI 判断：改善有效 → 建议保存为规则 / 无改善 → 放弃假设 / 样本不足 → 继续

用户确认后生效

实验有效后，需用户确认才保存为个人规则；下次创建同类任务时提供校准建议时长，由用户决定是否采用

TARGET USERS

为谁而做

个人开发者 / 独立创作者
独自管理多线任务，没人帮忙评估工作量，常高估自己的产出能力
知识工作者 / 远程办公者
自主安排时间，需要对自己的容量有准确认知，避免过度承诺
计划总是失准的人
每周计划都完不成，但说不清是排太多还是执行问题，想找到根因
追求自我认知的人
不满足于"感觉今天效率不错"，想用数据理解自己的真实工作节奏
VALUE

价值与意义

效率提升：让计划从"失准"走向"可信"

通过持续的校准循环，用户的估时准确度逐步提升。不是一次性优化，而是形成自我纠偏的系统能力——每一次实验都在让下一次计划更靠谱。

社会价值：反焦虑的个人效能观

区别于"催你更努力"的效率工具，它帮用户接纳真实容量、与自己的节奏和解。减少因计划失准带来的自我否定和焦虑，建立更健康的工作关系。

方法论创新：数据驱动的自我认知

"实验闭环"机制让自我提升从"感觉"变成"证据"。不依赖主观判断，而是通过假设—验证—结论的科学方法，让个人效能管理变得可追溯、可迭代。

PRODUCT

产品形态

本地 Web 应用

为参赛 MVP 采用轻量实现：纯前端 HTML/CSS/JS + IndexedDB，零后端、零部署，本地直接运行

正式版规划迁移至 Vue 3 + TypeScript + Vite + Dexie + ECharts 技术栈

按日记录，周校准，长期趋势

按日记录执行数据建立每日有效投入，以周为主要校准周期生成报告，并观察更长期的容量趋势

AI 可选接入

推理层兼容 OpenAI 格式 API（DeepSeek/GLM/Qwen 等），用户自行配置 key

无 API Key 时使用基于真实统计结果生成的本地规则分析，并明确标注结果来源，不冒充 AI 输出

隐私优先

原始任务与执行数据仅保存在本地 IndexedDB；启用 AI 时，只发送经过脱敏的汇总统计结果

不发任务名称、备注等原始内容，只发送数值型统计指标
