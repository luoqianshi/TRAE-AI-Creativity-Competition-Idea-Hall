PROBLEM · 为什么要做这件事

古籍数字化的四大痛点

面对约150册佛学古籍扫描PDF，传统方法既慢、又贵、还容易错

🔍

识别率太低

繁体中文 + 异体字 + 梵文罗马字转写 + 专用佛学术语，普通OCR识别率不足80%，需人工逐字校对。如"Prajñāpāramitā"中的变音符号ñ/ś/ā极易被识别错误。

⏰

耗时惊人

150册约60,000页、600万字，人工校对需数人年工作量，周期长、成本高，无法规模化推广。许多珍贵古籍因此一直"沉睡"在书架上。

💰

成本居高不下

海外API按Token计费，处理百万字需上千元；且数据出境有隐私风险。纯本地部署又面临硬件门槛——70B模型需要64GB+内存和专业GPU。

📄

扫描质量参差

部分PDF扫描模糊、缺字、多字、换行错乱、页眉页脚混入正文。不同册的扫描质量差异大，需要针对性的图像预处理和容错机制。

FEATURES · 五大核心功能

全流程自动化 · 模块化可扩展

📑 批量处理

扫描整个目录，一次性处理上百册PDF。支持并行、顺序两种模式。

  • 扫描目录/子目录/单文件
  • 并发数可配置（--workers N）

🔁 断点续传

电脑关机也不怕。用 SQLite 记录每页状态，重启自动跳过已完成项。

  • pending / ocr_done / corrected / exported / error
  • 支持手动重置单页状态
  • 运行日志完整记录

RISK · 风险与应对

已识别风险 · 已有对策

可行性评估 ★★★★☆（4/5，高可行性）

中等风险

梵文罗马字识别错误

ñ/ś/ā等变音符号易被OCR识别为普通字母

→ 建立梵文转写词典做后处理替换 + 专用OCR模型训练
中等风险

LLM"过度修正"

大模型可能把正确的原文改写为错误表述

→ Prompt明确"仅修正明显错误" + 保留diff记录 + 低temperature(0.1~0.3)
中等风险

API调用成本过高

大量文本处理可能产生较高API费用

→ 优先低成本模型 + 高置信度用本地模型 + 成本实时统计
低风险

部分PDF扫描质量极差

阴影、倾斜、墨点、页面残缺导致OCR完全失败

→ 标记为"需重新扫描"并跳过，不中断整体流程
中等风险

异体字识别混乱

體/体、裏/裡、後/后等异体字导致文本不一致

→ 建立异体字→标准字映射表，基于OpenCC + 佛学专用字补充
低风险

API速率限制/宕机

LLM API临时不可用导致流程中断

→ 自动重试 + 指数退避 + 多供应商fallback机制
FUTURE · 后续优化方向

从"能读"到"好用"再到"智慧"

基础版本解决"数字化"问题，后续迭代让古籍真正"活"起来

📊 全文检索引擎

基于 Elasticsearch / Meilisearch 构建全文检索，支持跨册关键词搜索、模糊匹配、同义词扩展。研究者输入"緣起性空"即可定位到所有相关段落。技术成熟，接入成本低。

🤖 对话式佛学助手

基于现有文本库 + RAG技术，用户可与古籍内容对话。问"般若波罗蜜多的核心思想是什么？"系统自动检索相关段落并生成综合回答，附带原文出处。复用现有LLM API即可实现。

📝 智能摘要生成

调用现有LLM API为每册古籍自动生成内容摘要、章节提纲、核心观点提炼。研究者无需通读全书即可快速把握主旨。无需额外基础设施。

📚 版本比对与校勘

同一典籍的不同版本（如不同出版社、不同年代影印本）进行自动比对，标记差异处，辅助学术校勘工作。基于现有文本diff算法即可实现。

🎙 佛典语音朗读

接入国产TTS引擎（讯飞/百度），将校对后的佛典文本转为标准普通话朗读。针对佛学术语定制发音词典（如"般若"读 bō rě 而非 bān ruò），支持调速与断句，让修行者也能"听"经。

🌐 梵文-中文对照翻译

针对佛典中大量梵文/巴利文转写段落，调用LLM API生成逐句梵文-中文对照翻译。帮助研究者理解原文语义，降低梵文阅读门槛。复用现有API即可实现。

VALUE · 价值与意义

为什么这个项目值得做

🎓 学术价值

把数百册珍贵的佛学古籍转为可检索的文本，为佛学研究者提供便利，推动学术研究效率提升。

🌏 文化传承（社会公益）

抢救性数字化——许多旧版书籍正在老化消失，文本化是让文化遗产永续的关键一步。全部代码开源、公益开放。

🚀 可推广到其他古籍

更换术语词典和模型参数，即可用于任何繁体中文古籍项目。架构模块化设计，各组件可独立替换和扩展。

💡 国产化成本低

全部使用国产开源工具 + 国产大模型API，处理150册总成本约¥100~500，比人工校对便宜几个数量级。

🔒 数据主权

核心识别过程在本机完成，API调用可选择纯国内服务商，或完全离线部署（方案B），保障数据隐私和安全。

🤝 开源共享（公益开放）

全部代码开源，术语词典、异体字映射表、Prompt模板均公开，鼓励社区协作，让更多传统文化工作者受益。
