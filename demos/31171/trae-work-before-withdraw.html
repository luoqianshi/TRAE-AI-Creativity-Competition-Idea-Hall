Before Withdraw

撤回之前

一个给“没发出去的话”准备的私人信箱。它不劝用户立刻表达，也不替用户做决定，而是在发送之前留出一段缓冲时间，让冲动变成可以重新处理的句子。

PRIVATE NOTE / 未发送

先把冲动写到这里。过一晚，再决定它要不要被发出去。

产品形态：Android App 技术栈：Kotlin + Jetpack Compose + Room + WorkManager 当前状态：MVP 可运行，已完成真机通知验证
01 / IDEA

把“想发出去”变成“先放一下”。

很多社交冲突不是来自表达本身，而是来自表达太快、情绪太满、措辞还没被自己重新看过。《撤回之前》想解决的就是这几秒到几小时之间的空白：用户已经需要表达，但还不确定现在是否适合发送。

PAIN
痛点

聊天软件里的“撤回”发生在发送之后，而真正需要被照顾的往往是发送之前的冲动。

MOTIVE
动机

灵感来自日常沟通里那些“打完又删掉”的时刻：人需要一个不会评判、不会外发的临时容器。

FORM
产品形态

本地 Android App，以私人信箱、未寄出信笺、情绪档案的形式承载内容暂存和延迟提醒。

02 / USERS

目标用户与使用场景

核心用户是高频使用即时通讯工具、容易在情绪高点发送消息、又希望减少后悔表达的人，包括学生、职场新人、亲密关系中的沟通者、需要维护边界的成年人。

01
关系沟通前

想给朋友、同事、家人或伴侣发一句重话，但担心伤害关系。

02
自我表达时

只是需要把话说出来，不一定真的要发给某个人。

03
冷静复盘后

12 小时后收到退回提醒，重新决定还要发、继续放着或烧掉。

关系沟通前

用户在聊天窗口里已经打完一段话，但意识到语气太重、对象太敏感，于是把它先放进撤回之前。

03 / VALUE

产品价值：降低冲动成本，提高沟通质量。

这个创意的价值主要体现在效率提升和社会价值两个角度。它让用户不用在聊天窗口里反复打字、删除、纠结，而是把内容转移到更安全的本地空间；同时，它通过延迟提醒和处理仪式，帮助用户减少冲动表达带来的关系损耗。

效率提升
  • 内容优先：先写句子，再选择对象和原因。
  • 自定义对象/原因：减少分类负担，贴近日常语言。
  • 状态筛选：暂存、封存、折起、已退回等记录更容易查找。
社会价值
  • 降低情绪化沟通对亲密关系和工作关系的伤害。
  • 鼓励用户在表达前获得一段缓冲，而不是压抑表达。
  • 不依赖云端和社交分享，保护高度私密的文字内容。
体验价值
  • 私人档案室视觉，避免工具压迫感。
  • 烧掉、折起、封存等处理方式具备明确心理语义。
  • 危险操作使用二次确认，降低误操作风险。
“撤回”不应该只发生在消息发出之后。更好的选择，是在发出之前给自己一次重新决定的机会。
04 / SYSTEM

当前技术架构

项目已经不是概念稿，而是可安装、可测试、可走通主流程的 Android MVP。它采用单 Activity + Compose Navigation + MVVM，本地数据库保存撤回内容，WorkManager 负责延迟退回，本地通知负责把句子重新交还给用户。

UIJetpack Compose

首页、输入页、对象页、原因页、处理页、详情页、退回确认页。

STATEViewModel

统一管理草稿、消息列表、通知状态和保存流程。

DATARoom

本地保存对象、内容、原因、处理方式、状态和时间。

REMINDWorkManager

为 12 小时后退回安排唯一任务，支持继续放着后重排。

VERIFYUnit Test + APK

构建、单元测试、模拟器回测和 Android 16 真机通知验证均已完成。
