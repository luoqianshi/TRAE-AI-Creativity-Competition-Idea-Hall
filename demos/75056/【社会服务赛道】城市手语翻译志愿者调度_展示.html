PAIN POINTS
听障群体的沟通困境
2700 万听障人士在就医、办事、法律等关键场景中面临严重的沟通障碍，公共手语翻译资源极度稀缺，志愿者分散且调度低效。
🏥

就医沟通断裂

听障老人独自看病，无法向医生描述病情、听不懂医嘱。很多医院没有常驻手语翻译，延误治疗时有发生。

🏛️

办事寸步难行

银行、政务窗口、社保局——这些需要口头沟通的场景，听障人士往往需要找人代排队、写纸条，效率极低且隐私无保障。

⚖️

法律权益受损

报警、法律咨询、法庭审理中缺少手语翻译，听障人士可能因为沟通障碍而无法维护自己的合法权益。

📱

志愿者调度靠微信群

手语志愿者分散在各微信群，调度全靠人工喊话。"有人需要帮助"的消息发出后，经常无人响应或响应太慢。

⏰

预约制无法应急

公共机构手语翻译需要提前 3-7 天预约，急诊、报警等紧急场景根本无法等待，听障人士只能"硬扛"。

📉

志愿者积极性难持续

志愿服务缺乏记录、积分和保障机制，纯靠热情难以长期维持。很多会手语的人不知道去哪里帮忙。

CORE FEATURES
六大核心功能模块
从 LBS 实时调度到视频远程翻译，从志愿者管理到服务质量保障，构建完整的听障沟通无障碍生态。
📍

LBS 实时智能调度

基于地理位置实时匹配最近的手语翻译志愿者。综合考虑距离、专长领域（医疗/法律/教育）、评分、当前状态等因素，智能推荐最优人选。支持一键调度 + 自动通知。

LBS 定位多因子匹配实时推送
📹

视频远程翻译

当志愿者无法及时到场时，一键切换视频远程翻译模式。3 分钟内接通在线志愿者，通过手机视频实时手语翻译。适用于紧急场景和偏远地区。

WebRTC3分钟接通低延迟
🏅

志愿者认证与评价

志愿者需通过手语能力认证（国家手语等级 / 平台测评）才能接单。服务结束后用户可评价，形成信用积分体系。高评分志愿者优先推荐，低评分触发再培训。

等级认证信用积分双向评价
📊

管理后台（残联/社区）

为残联、社区、公益组织提供管理后台：查看辖区服务数据、管理志愿者团队、处理紧急调度、生成服务报告。支持多组织协同和数据大屏展示。

数据大屏多组织服务报告
🎯

场景化服务分类

按服务场景分类（就医/银行/政务/法律/教育/日常），不同场景匹配不同专长的志愿者。医疗场景优先匹配有医疗手语经验的志愿者，法律场景匹配法律手语专长者。

6大场景专长匹配术语库
🤝

志愿者激励体系

服务时长累计积分，可兑换手语培训证书、公共服务积分、合作商家优惠。企业 CSR 合作：员工参与手语志愿服务可计入企业社会责任报告。形成可持续的正向循环。

TECH ARCHITECTURE
技术架构四层设计
基于 LBS + 实时通信 + AI 匹配引擎的分层架构，确保调度的高效性和可靠性。
01终端交互层

三端协同：用户端 + 志愿者端 + 管理端

听障用户端（App + 微信小程序）：大字体/高对比度无障碍设计，一键求助按钮，震动+闪光通知替代声音提醒。志愿者端：接单/导航/计时/积分查看。管理后台（Web）：数据大屏、团队管理、服务报告导出。

Flutter 跨端微信小程序Vue3 管理后台无障碍适配
02调度引擎层

LBS 实时匹配与路径规划

基于 GeoHash 编码的快速邻近搜索，结合多因子匹配算法（距离 40% + 专长匹配 25% + 评分 20% + 响应速度 15%）计算最优志愿者。集成高德/百度地图 SDK 进行路径规划和 ETA 预估。WebSocket 长连接实现实时位置追踪和状态同步。

GeoHash多因子匹配高德 SDKWebSocket
03通信服务层

视频远程翻译 + 实时消息

基于 WebRTC 的低延迟视频通话，支持多人视频（用户 + 志愿者 + 第三方如医生）。AI 辅助手语识别（CV 模型）作为翻译质量校验。消息推送使用 FCM + APNs 双通道，确保通知到达率 > 99%。

WebRTCSFU 架构MediaPipe 手语识别FCM + APNs
04数据与智能层

数据分析 + AI 优化 + 知识图谱

服务数据统计与分析（响应时间、满意度、高频场景）。AI 需求预测模型：根据历史数据预测各时段各区域的手语翻译需求量，提前调度志愿者到高发区域。手语术语知识图谱：覆盖医疗/法律/政务等专业领域词汇的手语表达。

ClickHouse 分析时序预测知识图谱Neo4j
