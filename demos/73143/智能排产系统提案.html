智排APS
面向离散制造的智能排产与动态调度系统

借鉴 APS（高级计划与排程）与 AI Agent 的多智能体架构思路，构建一款可本地部署的智能排产系统： 自动采集工单与设备数据、解析 ERP/MES 接口、预测订单交期、反向优化生产顺序，并引入约束求解与遗传算法等优化引擎，把"Excel 排程 + 人工经验"的传统模式升级为"AI 排产 → 仿真验证 → 动态调整 → 持续优化"的闭环。 首版聚焦离散制造场景（机加、装配、电子），架构保持通用，可横向扩展至流程制造、半导体、新能源等更多制造领域。

参赛形式：个人参赛 赛道：智能制造 / AI for Manufacturing 产品形态：Web + 桌面端系统（Windows / macOS / Linux） 核心能力：智能排产 + 交期预测 + 约束仿真 首版场景：离散制造（机加/装配/电子） 可扩展场景：流程制造、半导体、新能源

① 创意名称 + 创意介绍

创意名称：智排APS — 面向离散制造的智能排产与动态调度系统

想解决的问题：制造业生产排程高度依赖"Excel + 人工经验"，订单波动大、设备故障频发、插单改单频繁；ERP/MES 数据与排程逻辑散落在不同系统，计划员难以实时掌握全局产能与瓶颈，排产效率低、交期延误率高。

动机来源：本人长期从事智能制造相关工作，熟悉工厂生产计划业务。日常深感排程效率瓶颈。开源 AI Agent 与 APS 技术的成熟让我意识到：可以让 AI 像一位"不知疲倦的计划专家"一样自动读取工单、分析产能、优化排程、预测交期。

产品形态：可本地部署的 Web + 桌面端系统，融合 ERP/MES 数据接入 + 资源约束建模 + 智能优化引擎（遗传算法/约束求解）+ 排程仿真 + LLM 对话交互；先在离散制造场景跑通"排产—仿真"全链路，架构保持通用以便横向扩展。未来可进一步对接 AGV、机械臂等自动化设备，实现从计划到执行的全链路智能化。

② 目标用户及痛点

核心用户（首版）离散制造企业的生产计划员、PMC 主管 潜在用户流程制造企业、半导体工厂、新能源电池厂的计划人员 场景 1智能排产：输入订单与资源约束，自动生成最优生产顺序 场景 2交期预测：基于当前排程与产能，预测订单交付时间 场景 3动态重排：设备故障/插单时，Agent 自动重算并推荐调整方案 场景 4瓶颈分析：可视化展示产线瓶颈与资源利用率，辅助决策
  • 数据孤岛：ERP、MES、手工 Excel 数据分散，难以统一实时获取
  • 排程效率低：人工排程耗时长，面对订单波动和插单难以快速响应
  • 经验依赖：排程质量高度依赖资深计划员，新人上手困难
  • 缺少定量预测：无法提前判断"这个交期能不能达成""哪条产线是瓶颈"

③ 价值与意义

效率提升：把排程模式从"Excel 手工 + 经验判断"改为"AI 自动排产 → 仿真验证 → 动态调整 → 持续优化"的闭环，排程效率预计提升 50% 以上，交期延误率降低 20%–40%。

技术独特性：与大多数参赛者不同，本项目基于真实工厂业务场景设计，拥有自研积累的订单、设备、工艺等真实数据作为建模基础，这是区别于纯"Demo 演示 + 假数据"项目的核心优势，也是防止低水平重复的天然护城河。

通用可扩展：数据层、约束层、优化层、Agent 层全部解耦设计；首版完成后，替换一套资源与工艺数据即可迁移到其他制造领域。

社会价值：探索 AI Agent 在制造业核心场景（生产排程）下的低成本落地路径，让中小规模的制造企业也能用上智能排产工具，助力中国制造业数字化转型。

基于真实工厂数据，模型可实际落地 首版聚焦离散制造，可横向扩展 本地部署，数据不离开工厂

④ 技术思路（可落地 MVP）

  • 数据层：SQLite/PostgreSQL 统一存储工单、设备、工艺、资源数据；REST API / 数据库直连接入 ERP/MES；Excel 导入作为补充入口。
  • 约束层：基于制造规则的资源约束建模（设备产能、人员技能、物料齐套、工艺先后、换型时间等）+ RAG 检索历史排程案例。
  • 优化层：遗传算法 / 约束求解（OR-Tools）做排程优化 Baseline；给定交期约束时用启发式算法反向推算最早开工时间；瓶颈识别基于资源利用率与等待时间分析。
  • Agent 层：四种子 Agent（数据接入 / 排程优化 / 仿真验证 / 计划助手），借鉴多智能体编排；本地开源 LLM（Qwen / DeepSeek / Llama 系列）+ TRAE Work 辅助原型搭建。
  • 客户端：Python 核心 + Web 前端（React/Vue）+ 跨平台桌面端封装，Windows/macOS/Linux 均可运行。

🧩 系统架构："排产—仿真"双引擎的智能调度系统

🚀 首版开发路径（先跑通离散制造"排产—仿真"全链路）

1
数据标准化

工厂工单、设备、工艺数据统一入库，建立订单与资源两张核心表。

2
约束建模

建立设备产能、工艺先后、换型时间、人员技能等资源约束模型。

3
排程优化

基于遗传算法 / OR-Tools 实现智能排程，生成甘特图与资源负载图。

4
交期预测 + 动态重排

给定订单交期反向推算最早开工时间；设备故障时自动重算并推荐调整。

5
Agent 交互 UI

对话式交互 + 排程可视化（甘特图/资源负载），正式投入使用。

📌 为什么这个项目值得参赛

① 场景够"硬"：当下大多数 AI Agent 集中在办公、客服、代码生成等"软"场景，真正落地到制造业核心环节（生产排程）的还不多见。 把 AI Agent 用在离散制造排程这种关键生产环节上，本身就是一个有差异化的方向。

② 数据有壁垒：与纯靠 Demo 演示 + 假数据的项目不同，本项目基于真实工厂的订单、设备、工艺数据建模， 这是天然的技术护城河——别人抄得走架构，抄不走真实业务数据与行业 know-how。

③ 排产—仿真双引擎：不是只靠启发式算法的黑盒排程，而是把「约束求解的智能排产」与「资源负载仿真验证」 做交叉验证，结果更可信。既有优化算法的灵活性，又有仿真的可解释性，这是区别于纯规则排程项目的核心技术亮点。

④ 路径够清晰：从"排产—仿真"双引擎的桌面端系统，到对接 MES/ERP 自动采集数据，再到部署到数字孪生工厂实现虚实联动， 每一步都有明确的价值落地，不是空中楼阁。参赛本身就是对这条路径最好的验证。

⑤ 真需求驱动，想象空间大：这不是一个为了比赛硬凑的 idea，而是我自己每天做生产计划都想用的工具。 首版跑通离散制造排程后，架构可以横向迁移到流程制造、半导体、新能源电池等其他制造领域， 具备成为"智能制造通用基础设施"的潜力。
