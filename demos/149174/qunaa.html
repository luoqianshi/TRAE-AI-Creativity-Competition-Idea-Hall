01 · WHY

收藏不是终点，去了才是

现有工具都在帮你发现新店，没人帮你用掉已经发现过的店。收藏夹越长，决策越累，最后还是去那家去了二十次的店。

现在的卡点

  • 点评收藏只能按时间倒序排，没法按"放空+步行十分钟+人均一百"筛
  • 小红书收藏是图文，看完还是不知道今天开不开、人多不多、要不要预约
  • 微信收藏是黑箱，存了就等于忘了
  • 两个人互相问"去哪"，刷一小时还是用"随便"收场

去哪啊怎么解

  • 把散落四五个 App 的收藏一次性导入打标，统一成可筛选的库
  • 点亮此刻心情和约束，三十秒反推三个现在就能去的地方
  • 每张卡写清到达方式、人均、营业状态、人流量，不用再临时查
  • 下雨自动切室内替代，计划不会因为天气黄掉

PROCESS

四步拆解一个反复发生的卡点

我在 TRAE Work 里把"周末去哪"拆成四步：收藏导入打标 → 此刻条件输入 → 三候选反推排序 → 选定后到达指引。每步对应一个数据结构和判断函数。

用 TRAE IDE 搭展示页时，我刻意做成了瑞士平面设计的色块版式：米白底、群青大色块、橙红强调，没有毛玻璃模糊和漂浮动画。因为这是个"做决定"的工具，视觉应该像时刻表一样干净利落，而不是花哨。点亮心情和约束后，三张推荐卡实时换内容。

CORE LOGIC

反推排序的核心判断

收藏条目需要类型/距离/预算/营业状态四个字段，反推时按"匹配条件数 + 距离权重 + 收藏新鲜度"打分，取前三。

// 反推：从收藏库匹配此刻条件 function pick( vault, mood, cons ) { return vault .filter( s => s.matches( mood, cons ) ) .sort( (a,b) => b.score(cons) - a.score(cons) ) .slice( 0, 3 ); } // score = 匹配条件数×10 + 距离权重 + 新鲜度
