寻食尺 🍜 · 创意提案

项目名称：寻食尺

产品形态：手机 App（iOS / Android）

一句话描述：像寻龙尺一样，走到哪都能立刻在地图上看到你自己收藏过的附近美食。

一、问题 & 动机

我们在美团、大众点评、小红书、朋友圈、高德地图等无数 App 里收藏了一堆店铺，它们散落在各个平台、无法统一检索。更关键的是——当你真的走在街上、身处某个陌生地点时，没有一个 App 会告诉你：你自己收藏过哪些离我最近的店。

传统"附近美食"推荐全是算法推给你的店铺，不是你自己真正挑选过的。

二、目标用户

  • 热爱探店、爱保存美食笔记的 20–35 岁城市人群
  • 经常搬家、换城市工作的人
  • 做攻略 / 做美食内容的创作者
  • 希望管理"私人美食地图"的普通用户

三、核心功能（MVP）

  • 分享接收器：接入系统分享面板，接收美团 / 大众点评 / 高德 / 小红书等分享内容
  • 智能解析：自动提取店名、地址、经纬度、分类
  • 标签管理：火锅 / 咖啡 / 日料 / 想去 / 已打卡 / 必回访 等自定义标签
  • 本地收藏库：SQLite / Realm 本地持久化，支持 iCloud / 云端备份
  • 定位 + 距离排序：实时 GPS，按直线距离自动排序
  • 地图展示：使用高德地图 SDK（国内）或苹果地图（iOS），收藏点以气泡形式落到地图上
  • 搜索与筛选：按标签、关键字、距离范围过滤

四、技术栈

  • React Native（或 Flutter / Tauri Mobile 等跨平台框架）
  • 高德地图 SDK（国内）/ 苹果地图 SDK（iOS）
  • 本地 SQLite / Realm
  • 系统分享扩展（Share Extension on iOS / Share Intent on Android）

五、与同类产品的关键差别

寻食尺不做推荐算法，不推送平台热门店。它只做一件事：把你自己收藏过的店铺，按你现在站的位置，按距离重新浮现出来。

它解决的是"收藏发现率"的问题——让你真正用上你已经花时间收藏过的信息，而不是让算法喂给你新的店铺。

六、MVP 与后续路线

  • V1 报名版：分享接收 → 解析 → 收藏 → 地图按距离排序 → 搜索筛选
  • V2：图片 / 笔记 / 评分 / 回访次数；列表导出成图文卡片
  • V3：多端同步；多人共享美食地图；社区推荐

七、价值与意义

效率价值：把散落在各处的收藏真正"用起来"——打开一次，附近你自己收藏过的店就全浮出水面。

个人数据价值：建立真正属于你自己的"私人美食地图"，不依赖任何平台账号。

社交价值：可导出一份"我的宝藏店"清单，朋友收到的不再是平台推荐，而是你亲自去过 / 心动过的店铺列表。
