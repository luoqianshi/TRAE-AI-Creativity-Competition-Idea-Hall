一、项目概述

1.1 产品定位

对着冰箱说几句话，AI秒变"剩菜改造大师"。剩菜盲盒是一款基于语音输入和AI智能匹配的创意菜谱工具，用户只需对着手机说出冰箱里有哪些食材，系统就能秒速推荐创意菜谱，帮助用户将剩菜变废为宝。

1.2 赛道信息

参赛赛道：TRAE AI创造力大赛 · 生活娱乐赛道

项目关注家庭食材浪费问题，利用AI技术（语音识别、智能菜谱匹配）帮助用户快速找到剩菜的创意做法，兼具实用价值和趣味性。

二、需求背景

2.1 社会背景

中国家庭每年因食材浪费损失达3000亿元。据统计，城市家庭平均每年浪费的食材价值约为2500-4000元，其中大部分浪费来源于"买了不知道做什么"和"做了吃不完"两种情况。食材浪费不仅造成经济损失，还加剧了环境负担。

2.2 用户痛点

  • 决策疲劳：每天下班后面对"今天吃什么"的问题，精力耗尽后往往选择外卖或随便吃点
  • 信息过载：菜谱平台和短视频上的菜谱信息过多，难以快速找到匹配自己食材的菜谱
  • 拍照门槛：现有菜谱识别工具需要拍照，但冰箱里的食材往往散乱放置，拍照识别效果不理想
  • 浪费焦虑：看到冰箱里快过期的食材心里发憷，但又不知道能做什么

2.3 问题影响

食材浪费：大量食材因为找不到合适的做法而过期丢弃，造成显著的经济损失和环境负担。

依赖外卖：因为不会做菜或不知道做什么，越来越多年轻人依赖外卖，影响健康和生活品质。

健康风险：长期依赖外卖导致油盐超标、营养不均衡，增加慢性疾病风险。

三、产品目标

3.1 核心目标

30秒内从"不知道做什么"到"开始做菜"。用户只需说出冰箱里有哪些食材，系统秒速推荐创意菜谱，并提供详细的步骤引导，让做菜变得简单有趣。

五、核心场景

5.1 场景一：下班打开冰箱

  • 角色：28岁独居打工人小王，下班后回到家中，打开冰箱发现有半个西红柿、两个鸡蛋和一包凉皮
  • 触发条件：不知道这些食材能做什么，不想再点外卖
  • 操作流程：打开小程序 → 按住语音按钮说"我有西红柿、鸡蛋和凉皮" → 系统识别食材 → 推荐"西红柿鸡蛋汤""凉皮炒蛋"等菜谱 → 用户选择并查看步骤
  • 预期结果：小王在30秒内决定了今晚做"西红柿鸡蛋汤"，开始开心做菜

5.2 场景二：周末清理冰箱

  • 角色：35岁家庭主妇李姐，周末大扫除，发现冰箱里有很多快过期的食材
  • 触发条件：想要一次性把快过期食材都用完，避免浪费
  • 操作流程：打开小程序 → 逐个说出冰箱里的食材 → 系统智能匹配多道菜谱 → 李姐选择"一锅端"方案 → 按步骤做菜
  • 预期结果：李姐成功用完所有快过期食材，全家吃得开心又不浪费

5.3 场景三：想学新做法

  • 角色：22岁大学生小张，在宿舍想用现有食材做一道新菜
  • 触发条件：只有土豆、鸡蛋和葱，想尝试不同的做法
  • 操作流程：打开小程序 → 说出食材 → 菜谱推荐中发现"土豆鸡蛋饼"这个新菜谱 → 点击查看详情 → 跟着步骤做菜
  • 预期结果：小张学会了新菜，发到社区分享成果

六、功能设计

6.1 功能架构

#模块功能描述优先级
1语音输入用户通过语音输入冰箱中的食材名称，系统自动识别并确认P0
2菜谱匹配根据用户输入的食材智能匹配合适的菜谱，支持多食材组合匹配P0
3菜谱展示卡片式展示菜谱，包含菜名、图片、用时、难度等信息P0
4步骤引导详细的做菜步骤引导，支持上一步/下一步操作P1
5临期提醒根据食材保质期自动提醒用户及时使用P2
6社区分享用户可以分享自己的剩菜创意菜谱到社区P2

6.2 核心流程描述

flowchart LR A[语音输入] --> B[食材确认] B --> C[菜谱匹配] C --> D[步骤引导] D --> E[分享]
  • 语音输入：用户按住语音按钮，说出冰箱里的食材名称，系统实时识别并转化为文字
  • 食材确认：系统展示识别结果，用户可以增减食材，确认后进入菜谱匹配
  • 菜谱匹配：系统根据食材组合智能推荐多道菜谱，按匹配度和热度排序
  • 步骤引导：用户选择菜谱后，查看详细的做菜步骤，支持计时器和提醒
  • 分享：做完菜后可以拍照并分享到社区，让更多人看到创意菜谱

七、交互设计

7.1 设计原则

  • 语音优先：核心交互以语音为主，降低打字输入的门槛，让用户可以"边做菜边说话"
  • 卡片式布局：菜谱以卡片形式展示，直观美观，信息层次清晰
  • 少步骤：核心操作控制在3步以内，从输入食材到查看菜谱一气呵成
  • 趣味化：加入"盲盒"概念，随机推荐菜谱增加惊喜感，提升使用趣味

7.2 页面结构树

  • 首页：产品入口，提供"语音输入"和"盲盒菜谱"两个核心入口
  • 语音输入页：语音录入界面，实时显示识别结果和食材标签
  • 菜谱推荐页：卡片式菜谱列表，支持筛选和排序
  • 菜谱详情页：菜谱完整信息，包含食材、用时、难度、图片
  • 步骤引导页：详细做菜步骤，支持上一步/下一步和计时器
  • 社区页：用户分享的创意菜谱，支持点赞和评论

7.3 关键交互说明

语音输入：首页中央大按钮"按住说食材"，按住后开始录音，松开后自动识别。识别过程中实时显示识别到的食材名称，用户可以增减食材后点击"开始匹配"。

菜谱浏览：菜谱以卡片形式展示，每张卡片包含菜名、图片、用时、难度等信息。支持上下滑动浏览，点击卡片进入菜谱详情。

步骤引导：菜谱详情页提供"开始做菜"按钮，点击后进入步骤引导模式，每个步骤配有图片和文字说明，支持上一步/下一步切换。

八、技术方案

8.1 技术架构

层级技术选型说明
前端微信小程序使用微信小程序开发框架，支持微信生态内直接使用
后端Node.js + Express轻量级后端服务，处理语音识别和菜谱匹配请求
API百度语音识别 / 讯飞大模型百度语音识别API识别食材名称，讯飞大模型生成创意菜谱
数据存储微信小程序云开发使用微信云开发数据库存储菜谱、用户数据等

8.2 关键技术点

  • 语音识别：采用百度语音识别API，支持中文语音实时转文字，准确率达95%以上。针对食材名称的特殊词库进行了优化配置。
  • 菜谱匹配算法：基于讯飞大模型进行智能菜谱推荐，结合食材匹配度、用户偏好和菜谱热度进行综合排序。
  • 微信小程序云存储：使用微信云开发的云数据库和云存储，无需自建服务器，降低开发和运维成本。

8.3 性能指标

指标目标值测量方法
语音识别≤3秒从用户说完到识别结果返回的时间
菜谱匹配≤1秒从食材确认到菜谱推荐列表返回的时间
首屏加载≤2秒从打开小程序到首页完全加载的时间
图片懒加载滚动时按需加载菜谱图片采用懒加载策略，优先加载可视区域
