Problem

管理者的时间黑洞

百人团队每周产生上千条日志记录。管理者根本没时间逐条阅读，只能凭印象做判断。
关键的管理信号淹没在海量文字中——优秀行为得不到及时认可，问题行为一再重复。

没有 Anlitiqu 之前

  • 人工翻阅百页周报，耗时3–5小时
  • 凭印象做判断，标准不统一
  • 容易漏掉隐晦的负面信号
  • 日志写了等于没写，信息浪费

有了 Anlitiqu 之后

  • 上传即处理，全程不超过10分钟
  • 15条判读规则确保分类一致性
  • 连隐晦表达也能捕获（"没收到需求但客户说早就讲过"）
  • 每条案例可直接用于一对一辅导面谈
Workflow

两步法：关键词初筛 + AI精读复核

不为90%的「个人思考」浪费算力，只对关键的5–10%候选案例进行逐条AI判读。效率与准确率的平衡点。

01

pipeline.js 自动提取

读取Excel → 识别软性维度 → 拆分长内容 → 被记录人匹配 → 昵称归一化
输出 pending_type.json（全部字段齐全，案例类型待判）
→
02

quick_screen.js 关键词初筛

命中正面/负面关键词 → 标记为候选。未命中 → 直接定稿为「个人思考」
输出 candidates.json（仅约5–10%的总量，含部门/岗位信息）
→
03

AI 逐条复核

四条子Agent并行，每条候选经过「三步判读公式」精读后判定
三步公式：是否呈现他人行为 → 行为主体是否非记录人 → 正面/负面?
→

应用最终特判规则（特定敏感人物除外）+ 生成结构化Excel终稿
输出 管理案例-待定稿.xlsx

Features

不止关键词匹配，是真正理解内容

15条经反复校准的判读规则，覆盖显性表达和隐晦信号的完整判读体系。

🔍

「自己写自己」智能排除

自动识别记录人与被评价行为主体的关系。员工A写自己主动协助项目？——不算管理案例。员工B写同事C的帮助？——算。

🎯

隐性负面信号捕获

不只看批评语气。"没收到需求，但客户说早就讲过"——语气平和，但描述了上游部门信息未传达的行为缺失，同样判定为负面。

📋

「先扬后抑」陷阱识别

管理者习惯先肯定再指出问题。系统会自动读完完整记录，不被前半段的表扬迷惑——"某同事近期小疏漏比较多，比如关键节点忘记同步通知"正确判定为负面。

⚡

外部人员自动过滤

通过员工名单+上下文双重校验，自动区分内部员工与外部人员。——"某外部讲师出现教学事故"→外部，不纳入。——"某销售员工客户关系不积极"→内部，纳入。

📊

部门/岗位上下文注入

候选人数据携带涉及对象的部门和岗位信息，让AI判读时能看到完整上下文——比如"客情弱"对销售岗是管理问题，对职能岗则不是。

🔄

15条标准持续迭代

每轮校正都沉淀为判读规则。从最初的6条增长到15条，覆盖显性表扬、隐晦批评、外部边界、自我书写等全场景。准确率从初始的约70%提升到92%+。
