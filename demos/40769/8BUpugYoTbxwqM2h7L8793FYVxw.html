一、项目概述

《余温》是一款以"重塑人与人之间的善意连接"为使命的移动应用。面对老龄化社会加剧与"不敢扶"的社会信任危机，我们希望通过技术手段，降低善意传递的门槛与风险，让每一次伸手相助都有据可依、有温可感。

产品围绕"老人跌倒守护""日常邻里互助""目击见证防讹"三大核心场景，构建一个安全、可信、有温度的社区互助网络。

二、背景与痛点分析

2.1 社会背景

老龄化加速

中国60岁以上人口已超2.8亿，独居老人比例持续攀升，老人在家跌倒无人知晓的悲剧时有发生。

信任危机蔓延

从"彭宇案"到近年多起"扶老人被讹"事件，"想扶不敢扶"成为普遍心理。

邻里关系淡化

城市化进程使传统邻里互助网络瓦解，同住一栋楼却互不相识成为常态。

2.2 核心痛点

痛点类型具体表现用户需求
老人安全独居老人跌倒后无人发现，错过黄金救援时间跌倒自动检测与紧急求助
救助顾虑路人担心被讹诈，选择袖手旁观救助过程证据留存与法律保障
日常求助微小需求（找猫、借物、问路）缺乏便捷求助渠道基于地理位置的轻量互助
社区温度人与人之间缺乏正向互动与信任积累可视化善意行为，激励更多人参与

三、产品理念与定位

"AI是工具，人是温度。" 本产品不追求用AI替代人的判断与行动，而是用技术为人的善意保驾护航。AI负责检测、提醒、记录，人负责决策、行动、传递温暖。

3.1 产品定位

一款以地理位置为核心的邻里互助与安全守护平台，兼具"老人跌倒守护""目击见证防讹""日常轻求助"三大功能，用技术消除善意行动的后顾之忧。

3.2 目标用户

  • 第一圈层：独居老人及其子女
  • 第二圈层：有互助意愿的社区居民
  • 第三圈层：热心公益的年轻群体、社区志愿者

四、功能体系设计

产品采用"温度三层结构"设计，从感知到行动逐层递进。

4.1 第一层：温度感知 — 温度地图

  • 基于社区真实互助行为数据，生成可视化热力图，展示各区域互助活跃度
  • 热度计算：求助完成次数、见证用户数量、感谢反馈数量、志愿者密度
  • 每周生成"社区温度周报"，让温暖被看见、被量化

4.2 第二层：温度连接 — 附近的人增强版

  • 状态打卡：发布轻需求，如"需要一张创可贴""求推荐早餐店"
  • 感谢墙：被帮助者公开发布感谢信，形成正向反馈闭环
  • 温度勋章：完成帮助获得积分与勋章，如"温暖邻居""急救先锋"

4.3 第三层：温度行动 — 核心求助体系

（a）日常互助轻请求

采用紧急程度三级分类机制：

级别类型推送范围示例
🔴 紧急人身安全威胁200米内强提醒晕倒、老人跌倒、突发疾病
🟡 中等财物损失或紧急需求500米内通知宠物走失、物品遗失、急需药品
🟢 轻松日常微小需求状态流展示问路、借工具、求推荐

（b）老人防跌倒"守护模式"

形成"检测—确认—响应"三级安全闭环：

  • 预登记：录入健康信息、紧急联系人、家庭地址；可选分享备用钥匙位置或临时房门密码（使用后自动失效）
  • 跌倒检测：利用手机加速度计与陀螺仪，实时识别跌倒姿态；触发后10秒倒计时确认，降低误报率
  • 三级响应：
    • 第一级：弹窗确认，老人可手动取消误报
    • 第二级：20秒无应答，自动向紧急联系人发送精确位置
    • 第三级：同步向附近"守护者"推送紧急通知，并自动拨打120，AI语音播报地址与病史
  • 隐私保护：不存储日常位置轨迹，仅记录紧急触发时刻坐标，符合《个人信息保护法》最小必要原则

（c）目击见证"防讹机制"

核心理念："3秒见证，全程守护"

  • 一键见证：进入"目击模式"，自动记录时间戳、地理位置戳，调用摄像头连续拍照
  • 法律声明：签署电子《善意救助免责声明》，提示合理救助行为受法律保护（参考《民法典》第184条）
  • 证据云存储：数据加密上传，日常不公开；仅在索赔时经用户授权后提供给警方或法院
  • 交叉见证：多用户同时开启时，自动形成多角度证据链，彼此印证

五、技术架构

5.1 整体架构

采用移动端（Android/iOS）+ 云服务 + 第三方API的经典三层架构。

5.2 关键技术点

技术模块实现方案技术难点及应对
跌倒检测加速度计+陀螺仪姿态识别，阈值算法+机器学习辅助误报率高 → 采用"低灵敏度+人工确认"策略，持续迭代模型
室内定位GPS+Wi-Fi指纹混合定位，实现小区楼栋级精度精确楼层定位需蓝牙信标，成本高 → 初期弱化楼层精度
实时消息推送MQTT协议 + WebSocket长连接高并发消息可靠性 → 消息队列削峰，关键消息添加重试机制
地理位置索引GeoHash算法，按距离圈选附近用户用户量增大后查询效率 → 使用Redis Geo数据结构优化
数据加密敏感信息本地AES加密，云端仅存密文密钥管理 → 设备指纹+用户生物特征生成密钥
证据云存储对象存储（OSS），图片自动压缩，加密传输存储成本 → 7天自动过期，仅保留有争议的见证记录

5.3 第三方服务依赖

  • 地图与定位服务（高德/百度地图SDK）
  • 短信与语音通知服务（阿里云/腾讯云通信）
  • 一键报警120接口（初期改为自动拨打+语音播报）
  • 云服务器与数据库（阿里云/腾讯云学生套餐）

六、合规与隐私保护方案

6.1 法律合规依据

  • 《中华人民共和国个人信息保护法》：遵循最小必要原则，明示收集目的，提供删除权与撤回同意权
  • 《中华人民共和国民法典》第184条：因自愿实施紧急救助行为造成受助人损害的，救助人不承担民事责任
  • 《移动互联网应用程序信息服务管理规定》：建立内容审核与用户信用体系

6.2 隐私保护措施

数据类型存储方式保护措施
用户位置信息仅使用时调取，不后台持续追踪紧急事件坐标加密存储，日常轨迹不留存
老人预登记信息本地加密 + 云端密文密码类信息仅紧急时解密发送至指定联系人
见证照片/视频加密上传云端默认私密，仅用户授权后可查看，7天自动清除
用户身份信息脱敏存储手机号中间四位隐藏，支持账号注销与数据一键删除

6.3 用户权益保障

  • 首次使用时展示完整《隐私政策》与《用户协议》，需主动勾选同意
  • 提供"隐私中心"入口，用户可随时查看、导出、删除个人数据
  • 设立"侵权举报"通道，对恶意求助、骚扰等行为7×24小时受理

七、市场分析

7.1 市场规模

  • 中国60岁以上人口超2.8亿，其中独居老人约1.2亿，养老安全市场空间巨大
  • 社区服务类APP用户规模持续增长，邻里互助赛道暂无头部产品，存在窗口期

7.2 竞品分析

竞品类型代表产品优势不足
紧急求助类帮帮我吧、高德卫星求救技术成熟，有品牌背书功能单一，缺乏社区互助生态
社区生活类58同城、美团优选用户基数大偏向商业服务，缺乏温度感与信任建设
养老看护类各类智能手环/摄像头硬件可靠需额外购买设备，普及成本高

《余温》差异化优势：无需额外硬件，一部手机即可完成跌倒检测+互助+防讹闭环，以"善意见证"为核心情感锚点，兼具功能价值与情感价值。

7.3 商业模式（远期规划）

  • 公益为主，增值为辅：核心求助功能永久免费
  • 增值服务：老人健康数据报告、家庭共享守护套餐、社区紧急响应SaaS服务（与物业合作）
  • 社会价值优先：比赛阶段和产品初期，以用户增长和社会影响力为核心指标

八、运营策略

8.1 冷启动方案

  • 试点社区：选择1-2个老龄化程度较高的社区，与居委会、物业合作，邀请老年住户优先登记
  • 校园联动：与高校志愿者协会合作，鼓励大学生注册成为"守护者"
  • 关键人带动：邀请社区热心人、楼长作为种子用户，通过示范效应带动邻里加入

8.2 用户留存与激励

  • 温度积分体系：帮助他人获得积分，可兑换社区周边商家优惠券或公益捐赠额度
  • 社区温度排行榜：按周更新社区温度排名，激发集体荣誉感
  • 真实故事传播：定期整理平台上的温暖互助故事，在社交媒体传播，形成品牌效应

8.3 风险防控机制

  • 身份认证：手机号实名认证，求助发布需完成基础身份核验
  • 信用评分：被举报核实的恶意行为将降低信用分，限制求助与见证功能
  • 内容审核：求助内容采用AI+人工双重审核，过滤违规信息

九、风险评估与应对

风险类型风险描述应对措施
技术风险跌倒检测误报率高，导致频繁打扰低灵敏度策略+人工确认机制，持续迭代算法
法律风险电子见证协议效力有限，无法完全免责明确告知用户协议性质，证据链仅作事实佐证
隐私风险用户数据泄露引发信任危机全链路加密，最小化数据收集，定期安全审计
冷启动风险初期用户密度低，求助无人响应单社区深耕，志愿者补位，确保响应率
恶意行为风险假求助、骚扰信息、恶意见证实名认证+信用评分+举报机制+人工审核
伦理风险技术过度介入私域，造成监控感所有功能需用户主动开启，不做后台静默监测

十三、总结

《余温》不只是一个APP，它是一场关于"人之所以为人"的社会实验。当AI可以精准计算一切的时候，我们想证明：有些东西是算法永远算不出的——比如陌生人递来的一颗糖，比如大雨中多问的那一句"你还好吗"，比如看见老人跌倒时，毫不犹豫伸出的那双手。

这就是《余温》——用技术为善意兜底，让每一点微光都不被辜负。
