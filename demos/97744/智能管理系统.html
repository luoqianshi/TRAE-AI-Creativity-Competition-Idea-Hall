一、功能需求总览

  • 完全离线单机应用：数据存储在本地加密 SQLite 数据库，无需网络。
  • 个人使用：无用户登录与权限系统，内置管理员模式（通过密码启用）以突破竣工锁定等限制。
  • 无审批流程：业务单据仅“草稿”与“已确认（进行中）”两种状态。
  • 五大核心模块：项目管理、合同管理、变更管理、付款管理、结算管理。
  • 附件统一管理：所有模块附件存入同一张 attachments 表，支持批量上传并自动加序号（如 01-效果图.png），单个文件限制 ≤50MB。
  • 自动编号永不重用：项目、合同、付款、变更、结算编号在删除后其序号不再分配。
  • 金额精确存储：所有金额以 INTEGER 分 存储，前端显示元（千分位、两位小数），避免浮点误差。
  • 合同保修金管控：支持百分比或固定金额，付款时自动计算可用额度。质保金支付受竣工日期与保修期限制。
  • 变更审价机制：变更单包含多条变更条目，已施工条目产生返工记录，支持三级审价（逐级条件弹出），变更主表汇总审价金额（物理冗余）。
  • 项目上下文锁定：启动时选择当前项目，所有功能均基于该项目，仅能通过菜单栏切换项目，无跨项目数据查看。
  • 竣工锁定：项目状态变为“已竣工”后，该项目及关联合同、变更、付款、结算、附件均只读，管理员模式可突破。
  • 操作日志：关键数据修改均记录到操作日志表，便于追溯。
  • 智能提醒：合同即将到期、保修期到期、质保金待释放、付款草稿超期等提醒。

金额规范：数据库所有金额字段均为 INTEGER，以分为单位。前端通过 API 层自动转换（接口传入元，主进程转为分存储；返回时转回元）。显示时使用千分位分隔和两位小数。

  • 渲染进程：纯前端，不直接访问 Node.js 或数据库。

3.3 安全设计

  • 数据库使用 SQLCipher 加密，启动需验证密码。
  • 管理员密码使用 bcrypt 哈希存储，关键操作需二次验证。
  • 主进程对输入严格校验，防止脏数据。
  • Preload 脚本仅暴露有限 API，不暴露 ipcRenderer 原始方法。

四、数据表结构

所有金额字段均为 INTEGER (分)。日期字段使用 TEXT (YYYY-MM-DD)。

4.1 项目表 (projects)

CREATE TABLE projects (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    project_code    TEXT NOT NULL UNIQUE,                -- XM-YYYY-NN
    project_name    TEXT NOT NULL,
    location        TEXT,
    start_date      TEXT NOT NULL DEFAULT (date('now','localtime')),
    end_date        TEXT NOT NULL DEFAULT (date('now','localtime','+100 days')),
    budget          INTEGER NOT NULL DEFAULT 0,         -- 分
    description     TEXT,
    status          TEXT NOT NULL DEFAULT 'active'
                    CHECK(status IN ('preparation','active','suspended','completed')),
    created_at      TEXT DEFAULT (datetime('now','localtime')),
    updated_at      TEXT DEFAULT (datetime('now','localtime'))
);
CREATE INDEX idx_projects_status ON projects(status);

4.2 合同表 (contracts)

CREATE TABLE contracts (
    id                     INTEGER PRIMARY KEY AUTOINCREMENT,
    contract_code          TEXT NOT NULL UNIQUE,        -- HT-YYYYMM-NN
    system_code            TEXT,                         -- 系统编号（手动）
    contract_name          TEXT NOT NULL,
    project_id             INTEGER NOT NULL REFERENCES projects(id),
    party_a                TEXT NOT NULL DEFAULT '深圳和而泰智能科技有限公司',
    party_b                TEXT,                         -- 乙方
    party_c                TEXT,                         -- 丙方
    contract_type          TEXT DEFAULT '施工合同',       -- 多选，逗号分隔
    original_amount        INTEGER NOT NULL,             -- 分
    original_amount_locked INTEGER,                      -- 确认时锁定，分
    retention_type         TEXT NOT NULL DEFAULT 'percent'
                           CHECK(retention_type IN ('percent','amount')),
    retention_value        REAL NOT NULL DEFAULT 3,      -- 百分比数值或金额(元)
    signed_date            TEXT DEFAULT (date('now','localtime')),
    start_date             TEXT DEFAULT (date('now','localtime')),
    end_date               TEXT DEFAULT (date('now','localtime')),
    completion_date        TEXT,                         -- 竣工日期，管理员填写
    warranty_period        INTEGER NOT NULL DEFAULT 2,   -- 保修期(年)
    description            TEXT,
    status                 TEXT NOT NULL DEFAULT 'active'
                           CHECK(status IN ('draft','active','completed','terminated')),
    created_at             TEXT DEFAULT (datetime('now','localtime')),
    updated_at             TEXT DEFAULT (datetime('now','localtime'))
);
CREATE INDEX idx_contracts_project ON contracts(project_id);
CREATE INDEX idx_contracts_status ON contracts(status);
CREATE INDEX idx_contracts_completion ON contracts(completion_date);

4.3 合同变更表 (contract_variations)

CREATE TABLE contract_variations (
    id                        INTEGER PRIMARY KEY AUTOINCREMENT,
    variation_code            TEXT NOT NULL UNIQUE,      -- BG-YYYYMMDD-NNN
    contract_id               INTEGER NOT NULL REFERENCES contracts(id),
    building                  TEXT NOT NULL,
    major                     TEXT NOT NULL,
    electronic_received_date  TEXT DEFAULT (date('now','localtime')),
    paper_received_date       TEXT DEFAULT (date('now','localtime')),
    dispatch_status           TEXT NOT NULL DEFAULT '未下发'
                               CHECK(dispatch_status IN ('未下发','已下发')),
    dispatch_date             TEXT DEFAULT (date('now','localtime')),
    dispatch_units            TEXT,                       -- 多选，逗号分隔
    total_contractor_quote    INTEGER DEFAULT 0,          -- 分
    total_first_audit         INTEGER DEFAULT 0,          -- 分
    total_second_audit        INTEGER DEFAULT 0,          -- 分
    total_third_audit         INTEGER DEFAULT 0,          -- 分
    created_at                TEXT DEFAULT (datetime('now','localtime')),
    updated_at                TEXT DEFAULT (datetime('now','localtime'))
);
CREATE INDEX idx_variations_contract ON contract_variations(contract_id);

4.4 变更条目表 (variation_items)

CREATE TABLE variation_items (
    id                  INTEGER PRIMARY KEY AUTOINCREMENT,
    variation_id        INTEGER NOT NULL REFERENCES contract_variations(id),
    floor               TEXT NOT NULL,
    zone                TEXT NOT NULL,
    change_reason       TEXT,
    change_content      TEXT,
    construction_status INTEGER NOT NULL DEFAULT 0 CHECK(construction_status IN (0,1)),
    created_at          TEXT DEFAULT (datetime('now','localtime')),
    updated_at          TEXT DEFAULT (datetime('now','localtime'))
);

4.5 返工记录表 (rework_records)

CREATE TABLE rework_records (
    id                      INTEGER PRIMARY KEY AUTOINCREMENT,
    item_id                 INTEGER NOT NULL UNIQUE REFERENCES variation_items(id),
    rework_content          TEXT,
    rework_date             TEXT,
    contractor_quote        INTEGER,                     -- 分
    contractor_quote_files  TEXT,                         -- 附件ID列表
    first_audit_price       INTEGER,                     -- 分
    first_audit_files       TEXT,
    second_audit_price      INTEGER,                     -- 分
    second_audit_files      TEXT,
    third_audit_price       INTEGER,                     -- 分
    third_audit_files       TEXT,
    created_at              TEXT DEFAULT (datetime('now','localtime')),
    updated_at              TEXT DEFAULT (datetime('now','localtime'))
);

4.6 付款表 (payments)

CREATE TABLE payments (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,
    payment_code   TEXT NOT NULL UNIQUE,                -- FK-YYYYMMDD-NNN
    contract_id    INTEGER NOT NULL REFERENCES contracts(id),
    payment_type   TEXT,                                 -- 预付款/进度款/结算款/质保金
    amount         INTEGER NOT NULL,                     -- 分
    payment_date   TEXT DEFAULT (date('now','localtime')),
    payment_method TEXT,
    remark         TEXT,
    status         TEXT NOT NULL DEFAULT 'draft'
                   CHECK(status IN ('draft','confirmed')),
    created_at     TEXT DEFAULT (datetime('now','localtime')),
    updated_at     TEXT DEFAULT (datetime('now','localtime'))
);
CREATE INDEX idx_payments_contract ON payments(contract_id);

4.7 结算表 (settlements)

CREATE TABLE settlements (
    id                         INTEGER PRIMARY KEY AUTOINCREMENT,
    settlement_code            TEXT NOT NULL UNIQUE,    -- JS-YYYYMMDD-NNN
    contract_id                INTEGER NOT NULL REFERENCES contracts(id),
    original_contract_amount   INTEGER NOT NULL,        -- 分
    total_variation_amount     INTEGER DEFAULT 0,       -- 分
    final_settlement_amount    INTEGER NOT NULL,        -- 分
    settlement_date            TEXT,
    description                TEXT,
    status                     TEXT NOT NULL DEFAULT 'draft'
                               CHECK(status IN ('draft','confirmed','closed')),
    confirmed_at               TEXT,
    created_at                 TEXT DEFAULT (datetime('now','localtime')),
    updated_at                 TEXT DEFAULT (datetime('now','localtime'))
);

4.8 附件表 (attachments)

CREATE TABLE attachments (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    module     TEXT NOT NULL,
    record_id  INTEGER NOT NULL,
    file_name  TEXT NOT NULL,      -- 如 "01-效果图.png"
    file_size  INTEGER,
    file_type  TEXT,
    file_data  BLOB NOT NULL,
    created_at TEXT DEFAULT (datetime('now','localtime'))
);
CREATE INDEX idx_attachments_module ON attachments(module, record_id);

4.9 操作日志表 (operation_logs)

CREATE TABLE operation_logs (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    module      TEXT NOT NULL,
    action      TEXT NOT NULL,
    record_id   INTEGER,
    detail      TEXT,
    operator    TEXT DEFAULT 'user',
    created_at  TEXT DEFAULT (datetime('now','localtime'))
);
CREATE INDEX idx_logs_module ON operation_logs(module, created_at);

七、全局页面布局与交互规范

7.1 整体布局

  • 左侧菜单栏：可折叠，固定高度。菜单项：仪表盘、项目管理、合同管理、变更管理、付款管理、结算管理、设置。底部显示当前项目及切换按钮。
  • 折叠交互：进入子页面自动折叠（仅图标）。鼠标悬停展开（不挤压内容）。鼠标移出展开区域进入内容区后自动折叠。底部图钉按钮可固定展开/折叠。
  • 内容区：顶部面包屑，主体为页面内容。

7.2 列表页通用规范

  • 左上角显示“XX列表”标题。工具栏：搜索框（模糊匹配）、筛选组件、右侧新建/导入/导出按钮。
  • 表格特性：
    • 首列复选框 + 序号（跨页连续）。
    • 所有列点击表头升降序排序，默认创建时间倒序。
    • 右键列标题弹出列显隐菜单，固定列（复选框、序号、核心标识列）不可隐藏。
    • 表头及工具栏固定（sticky），仅数据区滚动。
    • 底部分页器，切换页码滚动条回顶部。
  • 点击关键字段进入详情：项目名称、合同名称、变更编号、付款单号、结算编号为链接。操作列仅“编辑”与“删除”。
  • 导入导出：未勾选复选框导出全部（受筛选影响），勾选仅导出选中行。导出 Excel 时金额列数字格式，状态列带颜色。
  • 竣工锁定提示：项目竣工后，关联单据详情页顶部显示蓝色提示条。

7.3 详情页通用布局

  • 面包屑导航。
  • 标题区：实体名称大号加粗，左侧竖向小字状态标签，背景色根据状态变化。边框圆角，背景色柔和。
  • 信息卡片：关键字段卡片展示，金额汇总突出。
  • 标签页/分区：基本信息、关联单据列表。列表中的子记录编号为超链接。

7.4 表单防呆设计

  • 金额输入框：限制数字和小数点，自动千分位，失去焦点校验。
  • 日期选择器：默认当天，部分字段可配置未来限制。
  • 百分比输入：0~100，两位小数。
  • 编号字段只读，加载时显示“计算中…”。

九、各页面详细功能说明

9.1 仪表盘 /dashboard

仅显示当前项目数据。统计卡片（项目数、合同总额、累计已付、待付金额、附件总大小），图表（合同状态分布、付款趋势），待办提醒（草稿付款单、到期合同、质保金待释放），快捷操作按钮。

9.2 项目管理

列表页 /projects：可查看所有项目，操作列含“设为当前项目”。点击项目名称进详情。编辑/删除按钮按状态与权限显示。导入导出支持 Excel。

新建/编辑页 /projects/new / /projects/:id/edit：自动生成编号，日期默认值，附件批量上传。状态默认为准备中。项目一旦变为进行中，非管理员不可修改核心信息。

详情页 /projects/:id：标题区左侧竖向状态，已投资额高亮，关联合同列表，支持暂停/恢复/竣工操作。

9.3 合同管理

列表页 /contracts：仅显示当前项目合同。合同名称为链接，操作列编辑/删除。列增加竣工日期、保修期到期日。

新建/编辑页 /contracts/new / /contracts/:id/edit：所属项目锁定，编号自动生成，甲方默认值，合同类型多选，金额财务格式，保修金设置，日期默认当天。确认时锁定合同金额。

详情页 /contracts/:id：标题区左侧竖向状态，金额汇总卡片（合同金额、累计变更、累计已付、未付金额、保修金）。标签页：

  • 基本信息：包括竣工日期、保修期、保修期到期日（自动计算）。竣工日期仅管理员可填。
  • 变更记录：内嵌列表（不显示合同字段），变更编号链接，“新建变更”按钮锁定合同与项目。
  • 付款记录：内嵌列表，增加支付比例、累计支付比例列，付款单号链接，“新建付款”按钮锁定合同与项目。累计已付/未付显示。
  • 结算信息：最多一个结算，显示结算单或“未结算”状态，“新建结算”按钮锁定合同与项目。

9.4 变更管理

列表页 /variations：仅显示当前项目数据。变更编号链接。新建时选择当前项目下的合同。

新建/编辑页：主表单含楼栋、专业（默认上次值）、下发状态/日期/单位、附件。动态添加变更条目，施工状态开关，已施工时展开返工记录（三级审价逐级弹出）。保存时汇总审价更新。若从合同详情进入，合同与项目锁定。

详情页 /variations/:id：标题区根据下发状态配色，条目列表，返工详情展开。

9.5 付款管理

列表页 /payments：仅显示当前项目。付款单号链接。新建时检测合同草稿唯一性。

新建/编辑页：自动生成编号，合同锁定（若从合同详情进入）。付款类型默认，若剩余应付等于质保金则锁定为“质保金”。金额校验可用额度。支付质保金时检查合同是否已结算且保修期已到。

9.6 结算管理

列表页 /settlements：仅显示当前项目。结算编号链接。

新建/编辑页：自动带入原始锁定金额和累计变更，可手动调整最终结算金额。确认时校验数据一致性，记录确认时间。合同状态随之更新。

9.7 设置模块

/settings/dict：基础数据字典维护（楼栋、专业、楼层、分区、下发单位等）。下发单位自动同步合同乙方。

/settings/backup/auto：自动备份配置。

/settings/backup：手动备份与恢复，备份前执行 VACUUM。

管理员密码设置：启用后界面有标识，可突破竣工锁定。

十、核心业务规则汇总

  • 编号永不重用：所有自动编号删除后序号不得再分配，系统跳过已用序号。
  • 金额存储与显示：数据库 INTEGER 分，前端元显示（千分位两位小数），转换集中在主进程。
  • 合同金额锁定：合同确认（进行中）时锁定 original_amount_locked，非管理员不可修改。
  • 保修金计算：基数 = 已结算 ? 结算金额 : 锁定合同金额。保修金 = 基数 × 百分比（或固定金额）。
  • 付款可用额度 = 基数 - 累计已付 - 保修金。
  • 质保金锁定规则：当剩余应付金额等于保修金时，付款类型强制为“质保金”，不可修改。
  • 质保金支付条件：必须同时满足 (1) 合同已结算 (2) 当前日期 ≥ 保修期到期日（竣工日期+保修期）。支付金额上限为保修金。
  • 竣工日期管理：仅管理员可填写或修改，需密码验证。竣工日期不为空时，保修期到期日自动计算。
  • 变更总审价：物理冗余存储，在返工记录增删改时同步更新，保证查询性能。
  • 项目竣工锁定：项目竣工后，其下所有合同、变更、付款、结算、附件只读。管理员模式可突破。
  • 草稿唯一性：每个合同最多一张草稿付款单，新建时若已有则直接打开。
  • 附件序号：批量上传时按顺序在文件名前添加两位序号。
  • 操作日志：关键操作（修改合同金额、确认付款、竣工日期修改等）均记录日志。
  • 下发单位同步：合同乙方自动加入下发单位字典，用户可手动新增。
  • 默认值继承：楼栋、专业、楼层、分区新建时自动带入最近一次使用的值。

十一、智能提醒模块设计

  • 合同即将到期：状态=进行中，结束日期在未来30天内。
  • 保修期即将到期：竣工日期已填，保修期到期日在未来30天内，且质保金未付完。
  • 质保金待释放：保修期已过，质保金未付完，合同已结算。
  • 付款草稿超期：草稿付款单创建超过7天。
  • 提醒展示在仪表盘待办区域，支持系统原生通知（每2小时检查一次）。设置页可配置相关参数。

十二、UI 设计规范

主色：#1E5DBB（专业蓝）
辅助色：成功 #2D8C4A，警告 #E8920D，危险 #C62828
页面背景：#F2F5F9
侧边栏：#15263A
卡片/面板：圆角 8px，轻微阴影
字体：微软雅黑，标题 24px Bold，正文 14px，统计数字 30px Bold
响应式：≥1200px 完整布局；768-1199px 侧边栏折叠，卡片两列；<768px 汉堡菜单，表格横向滚动。

状态标签采用胶囊形圆角（12px），表格行悬停浅灰背景。按钮主色填充，次按钮描边。

十三、系统架构与目录结构

采用分层架构：

  • 渲染进程：React + Ant Design，Zustand 管理状态，React Router 路由，通过 Preload API 与主进程通信。
  • 主进程：IPC 处理层接收请求并转发至业务服务层，服务层封装所有业务规则与事务，数据访问层封装 SQL 操作。附件管理、日志服务、配置管理作为独立模块。

代码组织清晰，各模块职责明确。所有 IPC 通信返回统一格式 { success, data, error }。数据库启用 WAL 模式，定期 VACUUM。
