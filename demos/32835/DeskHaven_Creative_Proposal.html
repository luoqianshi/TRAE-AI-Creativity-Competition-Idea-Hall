我们为什么需要 DeskHaven？

Problem

现代人的数字资产散落在不同应用和文件夹层级中：桌面、下载、云盘、笔记软件、密码管理器、相册……当资料量超过一定规模后，找到文件的成本远高于使用文件。

更深层的问题是：一份项目计划书 PDF 可能引用了一张产品截图、关联了一个服务器密码、归档了一个历史版本。这些关系在传统的文件夹系统中是完全隐形的，只能靠人的记忆维系。

用关系图谱重新组织数字资产

Solution

DeskHaven 提供统一的本地数字资产管理中枢。文件、文档、照片、密码、档案、凭证都被视为图谱中的节点；用户创建的链接、引用、归属关系则成为节点之间的边。

核心能力

Capabilities
关联图谱
基于力导向布局，可视化跨类型数字资产的链接关系，支持拖拽、缩放与相邻高亮。
加密私域 Vault
AES-256 加密保护重要文档、私密照片、密码与 SSH 密钥。数据本地存储，不上传云端。
全局搜索
基于内容与元数据的双索引，支持中文分词，在数十万文件中瞬间定位所需资料。
AI 智能体集成
通过 MCP 协议，让 Claude、Codex、Cursor 等 AI 助手直接操控本地文件与关联图谱。

目标用户与价值

Users & Value

目标用户：知识工作者、研究人员、律师、设计师、自由职业者，以及任何对个人数据隐私有高要求的用户。

效率价值：把「搜索文件」变成「浏览关系」，将资料定位时间从数分钟缩短到数秒；让原本隐性的项目关联显性化，降低知识管理的心智负担。

社会价值：数据本地存储、AES-256 加密、零云端依赖，让用户重新拥有对个人数字资产的掌控权，回应当下日益增长的隐私保护需求。

技术实现

Technology

DeskHaven 基于 Electron + Vite + React + TypeScript 构建，使用 better-sqlite3 作为本地数据库，ECharts 实现数据可视化，nodejieba 提供中文全文搜索分词能力。Vault 模块采用 AES-256 加密标准，主进程通过 Worker Thread 实现后台文件索引，避免阻塞 UI。

应用支持 20 种语言、明暗双主题，并已预留 MCP 接口供 AI 智能体调用。
