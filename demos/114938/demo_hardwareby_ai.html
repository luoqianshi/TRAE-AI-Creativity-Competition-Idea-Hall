AI 在硬件设计上的 4 类典型幻觉

LLM 不是不会做硬件设计——它看起来会做。但它不知道 JLCPCB 最小线宽是 3mil、不知道 0402 阻容需要多大焊盘、不知道 USB 差分对要做 90Ω 阻抗控制。这就是为什么必须用代码规则兜底。

[01] 虚标元器件

"我用了 ESP32-WROOM-32U（带外部天线 IPEX 接口）"
JLCPCB 库中此型号库存为 0，封装签名不匹配

[02] 封装尺寸错误

"我用了 0805 电阻"
电路需要 1A 电流通过，0805 额定功率 1/8W = 不够

[03] 电路规则缺失

"USB-C 接到 ESP32 的 D+/D- 就行"
没有 TVS 保护 + 没有共模电感 + CC 电阻缺失

[04] DFM 规则无视

"走线 0.1mm 间距"
JLCPCB 最小间距 0.15mm (SMD-SMD)，超出工艺极限

8 层验证流水线

每一层都有明确的代码/AI/API归属。6 层代码规则 + 2 层 AI 生成，幻觉在源头被拦截。

L1
verify_bom
元器件是否真实存在于 LCSC 库，封装是否匹配，价格是否实时
CODE
L2
check_schematic
ERC 电气规则检查、电源树完整性、上下拉缺失、未连接引脚
CODE
L3
circuit_rules
有 MCU 必有去耦电容、有 USB 必有 ESD 保护、有电池必有 DW01 保护
CODE
L4
drc_check
KiCad .dru 规则：线宽/间距/过孔/短路/未连接
CODE
L5
dfm_check
嘉立创 DFM 官方规则 6 大类 34 项检查：封装签名、焊盘占比、丝印压盘
CODE
L6
estimate_cost
实时元器件成本 + PCB 制板费 + SMT 贴片费 + 钢网费
CODE
L7
ai_bom_gen
AI 根据需求描述生成初始 BOM 候选清单
LLM
L8
ai_explain
AI 把代码规则的检查结果翻译成自然语言修复建议
LLM
