一个能自主完成任务的 Agent，并不只是「会调用工具的大模型」，而是在规划、执行、观察、反思之间反复循环。这一页先把最核心的几个概念摆清楚。

核心概念

理解 Agent 循环，建议从三个承重概念入手，它们之间是依次依赖的关系：

  • 规划（Planning）：把模糊目标拆成可执行的步骤序列。好的规划会显式标注每一步的前置与产出，而不是一次性把整段动作压进上下文。
  • 工具调用（Tool Use）：Agent 通过结构化接口（函数、API、命令行）与外界交互；模型只负责「决定调用什么、传什么参数」，执行交给受控环境。
  • 反思（Reflection）：拿到观察结果后，判断「目标是否达成 / 哪一步出错 / 是否需要重规划」，这是让 Agent 从「能跑」走向「跑对」的关键。

它们如何连成循环

概念关系图 · 规划 → 执行 → 观察 → 反思 →（回到）规划

一个具体样例

设想让 Agent「订一间周五上海、预算 800 以内的酒店」。它先规划：查日期 → 搜酒店 → 比价 → 下单；在执行搜索后观察到结果里没有符合要求的价格，于是反思：放宽「步行到地铁」条件，重新规划搜索。整个过程不是一次生成到底，而是带着观察不断修正。

关键假设
上述循环成立的前提是：每一步的观察结果可被模型稳定读取（结构化返回、可解析），且工具副作用可控。一旦工具返回非结构化、易错的文本，反思环节就会退化为「猜」。

为什么反思不能直接等同于重试？
重试是不带判断的重复执行；反思必须先对观察结果做出「是否达成 / 哪步出错」的判断，再决定是否重规划。
concept
Agent 循环成立的底层前提是什么？
每一步的观察结果必须可被模型稳定读取（结构化、可解析），且工具副作用可控；否则反思退化为猜测。
boundary
规划与工具调用之间是什么关系？
规划决定「调用什么、传什么参数」；真正的执行交给受控环境，模型只负责决策而非亲自操作。
relationship
什么时候该让 Agent 回到规划重做？
当观察表明目标未达成或某步出错，且通过放宽约束 / 调整步骤能更接近目标时，触发重规划。

问问 AI
「反思」和「重试」到底差在哪？能再给个例子吗？
核心差别在有没有判断。重试是「失败了再跑一次同样的流程」；反思是「先看观察结果，判断卡在哪，再决定改什么」。
思考：读者可能把二者混淆，因为表面上都是「再来一次」。用一个订酒店的例子区分最清楚……
例：搜索无结果时，重试 会原样再搜一次；反思 会先判断「是预算太紧还是条件太多」，再放宽对应约束重搜。
