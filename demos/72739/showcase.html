01 · 创意介绍

从「校雠」传统到现代 OCR 精修

传统 OCR 工具只输出整段文本，要么全盘接受，要么在文本编辑器里逐字核对——效率低且容易出错。 古人校书有「校雠」传统，而现代 OCR 却把校对者推回文本编辑器，与原图割裂。 PDF-OCR 让 OCR 回归「视觉上下文中的字符级精修」，提供「画框选区 → 字符级 OCR → 纵校（按字符分组）→ 横校（按行校对）→ 精修输出」的完整可视化工作流。

❌ 只给文本，不可精修
OCR 引擎输出一段识别文本，复制到编辑器里逐字核对，看不到原文上下文，错字难以发现。
✅ 四阶段可视化流水线
导入 → 纵校 → 横校 → 精修，每个阶段都有可视化交互，让校对回到原文上下文。
❌ 行级识别，丢失字符信息
多数 OCR 以行为最小单位，单字置信度与字符边界框被丢弃，错字无法定位。
✅ 字符级 OCR
每个字符独立保存 char_id / line_id / page_num / char / score / box，可定位到「第 3 页第 7 行第 4 个字」粒度。
❌ 跨页同字错误难修正
同一个繁体字、异体字全文出现上千次，OCR 系统性偏差（如「己」识别成「已」）需逐页重复修正——古籍数字化中最折磨人的环节。
✅ 纵校模式（按字符分组）
把全文中同一个字聚合到一起，用户一次性校对所有实例，修改一次全文同步更新。
❌ 大 PDF 翻页卡顿 + 缺乏视觉反馈
扫描书页 PDF 动辄数百页，全量渲染撑爆内存；识别结果与原图脱离，错误不可直观发现。
✅ 懒加载 + 横校叠加视图
LazyPageLoader 按需渲染 + LRU 缓存让大 PDF 流畅翻页；横校把识别文字叠加在原图上，错误一目了然。

03 · 核心能力与古籍活化亮点

字符级可视化精修工作流

从画框选区到纵校分组，从横校叠接到懒加载翻页，每一项功能都对应一个真实痛点，构成完整的字符级精修工作流。

🖼️
可视化画框选区
用户在 PDF 页面上画框选区，OCR 只处理选区内内容，避免页眉、页脚、水印、批注等无关内容干扰识别结果。 对古籍这类常有装订线、朱笔批注、印章的扫描件尤其重要，识别准确率与处理速度都显著提升。
🔤
字符级 OCR
不仅识别文本行，还能识别单个字符并保存字符级元数据（char_id / line_id / page_num / char / score / box）。 可定位到「第 3 页第 7 行第 4 个字」粒度进行精修，是纵校模式可行的基础。
📊
纵校模式（按字符分组）
把全文中同一个字符的所有出现聚合到一起，用户一次性校对同字所有实例。 例如「己」字被系统性识别为「已」，纵校模式下选择「己」字符组，修改一次全文同步更新。
📖
横校模式（按行校对）
按页逐行展示识别文本与原图叠加视图，错误一目了然。鼠标悬停高亮当前行，双击修改文字， 右键忽略该行，Ctrl + 滚轮缩放。pixmap 缓存避免重复缩放。
✏️
精修窗口
拖拽移动文本块位置，8 个手柄（四角 + 四边）调整大小，右键删除不需要的实例。 导出双 PDF：红色文字版（人工核对）+ 透明文字版（机器后续处理，可作可搜索 PDF 文本层）。
🌀
懒加载与流畅翻页
LazyPageLoader 按需渲染 + LRU 缓存（默认 5 页），最近访问的页面保留内存，淘汰最久未访问的页。 让数百页扫描书 PDF 在普通办公电脑上也能流畅翻页校对，无需高端工作站。
📜 古籍活化专题：纵校模式如何破解「校书如扫叶」

古籍数字化中，同一个繁体字、异体字在全文可能出现数千次。OCR 引擎对这些字的系统性误识别（如「己」→「已」、「未」→「末」）是阻碍古籍数字化的关键瓶颈——传统逐页修正需要校对者付出数以倍计的重复劳动，许多馆藏孤本因此迟迟无法走向可检索的数字资源。

PDF-OCR 的纵校模式将全文中同一字符的所有出现聚合校对——用户只需修正一次，所有实例同步更新，让传统「校书如扫叶」的难题获得现代解法。每一部被精修的古籍，都是一次跨越时空的「校雠」协作——现代校对者借助可视化工具，与古人的书写、前人的校勘，共同完成一次文本的还原。

06 · 操作流程与架构

四阶段可视化精修流水线

每个阶段对应独立窗口，主窗口通过 QStackedWidget 按阶段切换，阶段间通过 Qt 信号传递数据， 支持阶段间回退——发现上游问题时随时返回修正。

✏️ 精修
1 导入阶段
选择 PDF 文件（也支持直接导入已识别的 JSON 结果）。 后台线程 ImportWorker（worker object pattern）异步渲染 PDF 为页面图像，主线程不卡顿。 完成后把页面图像、OCR 结果、字符切片数据传递给主窗口。
2 纵校阶段（按字符分组校对）
左侧字符列表按字符聚合显示（按出现频率排序），点击某字符后中间预览区显示该字符全文所有出现的原图切片。 发现 OCR 错误时在右侧修改区修改文字（可改为多字符，如把「的」改为「目的」），所有实例同步更新。
3 横校阶段（按行校对）
主视图按页显示原图 + 识别文字叠加。鼠标悬停高亮当前行，双击打开「修改文字」对话框， 右键菜单选择「忽略该行」或「修改文字」。工具栏切换页面、调整缩放。
4 精修阶段（拖拽 / 缩放 / 删除 + 双 PDF 输出）
显示横校输出的行文本块。鼠标拖拽调整位置，选中文本块出现 8 个手柄（四角 + 四边）调整大小， 右键删除不需要的实例。点击「导出 PDF」生成两份文件： 红色文字版（人工核对）+ 透明文字版（机器后续处理）。

💡 任何阶段都可通过「返回」按钮回到上一阶段（携带原数据重建上游窗口）

07 · 未来规划

从字符级精修到智能校对

从多语言支持到 AI 自动校对，从持久化到协同校对，PDF-OCR 还有更广阔的演进空间。

短期（3-6 个月） SHORT TERM
  • 多语言 OCR 支持：扩展日文、韩文、英文等更多语言的字符级 OCR
  • 校对结果持久化：引入 SQLite 存储纵校/横校修改，避免关闭程序丢失
  • 代码重复抽取：将两版本重复的 pdf_loader/styles/zoom_utils 抽取为公共子模块
  • 测试体系完善：测试脚本改为命令行参数，补充多页文档回归测试
长期（6-12 个月） LONG TERM
  • AI 自动校对：基于大语言模型（如接入 TRAE 自身 AI 能力）自动检测 OCR 可疑错误
  • 协同校对：支持多人同时校对同一文档，按页或按字符分配
  • Web 版：基于 WASM + Qt for WebAssembly 或纯 Web 重写，浏览器即可使用
  • 插件化 OCR 引擎：支持 RapidOCR、PaddleOCR、Surya、MinerU 等多后端热切换
  • 校对质量评估：基于置信度、修改频率等指标自动生成质量报告，标注高风险区域
