🏗️ 系统架构

系统采用分层架构设计，遵循单一职责原则，通过依赖注入容器实现模块解耦。

🖥️ 展示层 (Presentation Layer)

  • HTML5 + CSS3
  • 原生JavaScript
  • 响应式设计

🌐 路由层 (Routing Layer)

  • Express Router
  • RESTful API
  • 中间件处理

💼 业务层 (Service Layer)

  • RepairService
  • StatsService
  • TaskService
  • AssetService
  • AIService

📦 数据层 (Model Layer)

  • RepairRecordModel
  • TaskModel
  • AssetModel

🗄️ 数据库 (Database)

  • MySQL
  • 连接池管理
  • 索引优化

🧠 依赖注入容器

采用工厂模式创建容器，统一管理Model和Service实例，实现模块间的解耦。修改一处配置，全局生效，极大提升了代码的可维护性。

🔄 核心业务流程

不良品维修流程

1. 不良品录入

扫码SN → 选择站位 → 描述不良现象 → 系统自动保存记录

2. 自动派单

根据站位配置规则，自动分配给对应维修员，生成维修任务

3. 维修处理

维修员查看任务 → 分析不良原因 → 执行维修 → 记录维修结果

4. 状态更新

维修完成 → 更新状态为"已修复"或"报废" → 记录维修人

5. AI分析

系统定期进行AI分析 → 生成分析报告 → 超期预警提醒

🌐 API 接口设计

采用RESTful风格设计，统一响应格式：{ success: true/false, data/message: ... }

方法 路径 功能
GET /api/repair/stats 获取维修统计数据
GET /api/repair/ 获取维修记录列表
POST /api/repair/ 新增维修记录
PUT /api/repair/:id 更新维修记录
GET /api/ai/ai-analyze AI智能分析
GET /api/ai/ai-warning AI预警检测
GET /api/ai/ai-daily-report 生成维修日报
GET /api/asset/ 获取资产列表
GET /api/task/list 获取任务列表

🛠️ 技术栈

Node.js Express MySQL HTML5 CSS3 JavaScript Electron 智谱GLM-4 Axios pkg

架构设计亮点

  • 依赖注入容器：统一管理Model和Service实例，实现模块解耦
  • 工厂模式：每个Service采用工厂函数创建，便于依赖注入
  • 异步处理：全面采用async/await，避免回调地狱
  • 统一响应格式：所有API返回统一JSON格式，便于前端处理
  • 错误处理中间件：统一捕获和处理错误，提供友好的错误信息

✨ AI智能分析功能

系统集成智谱GLM-4大语言模型，提供智能化数据分析能力：

📈

智能分析报告

基于维修统计数据，自动生成专业分析报告

⚠️

超期预警

自动检测超3天、超7天积压订单，触发预警

📄

日报生成

每日自动生成维修日报，包含工作概况和改进建议

🔍

单条分析

对单条维修记录进行深度分析，提供专业建议

AI分析流程

1. 数据收集

从数据库获取维修统计数据（待维修量、超期数、站位分布等）

2. 数据格式化

将原始数据整理成结构化格式，便于AI理解

3. AI调用

通过智谱API发送请求，获取AI分析结果

4. 结果展示

将AI返回的Markdown报告渲染到前端页面
