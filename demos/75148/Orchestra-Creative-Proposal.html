Movement I
Grave · 沉重地

人当胶水 · 失谐

当前痛点 · Before

复制粘贴的协奏曲

A · ChatGPT → copy → B · Claude → ??? → C · codebuddy

用单个 AI Agent 做复杂任务时，用户被迫在多个 runtime 之间反复复制粘贴上下文——A 生成方案 → 复制给 B → B 挑最佳 → 复制给 C → C 写文件。

  • 每次切换都要手动传上下文，漏一步就全错
  • 跨 runtime 切换时格式还可能丢失
  • "上一轮评审说了什么"完全靠人脑记忆，不可复现
  • agent 跑了 30 秒，不知道是在思考还是卡死——运行过程是黑盒
  • 每次做类似任务都要从头操作一遍，没有"工作流资产"
𝄐

Orchestra 解法 · After

画布当胶水

Brainstorm → Convergence → Review → Deliver

用可视化画布把多个 AI Agent 和工具节点串成可运行的工作流。点一个键（⌘⇧R）就让整条工作流跑起来，上下文按拓扑序自动传递。

  • 一条工作流串起 N 个 agent，漏传/错传归零
  • convergence 节点自动驱动"评审 → 不满意重跑"迭代循环
  • 流式输出可见：reasoning（灰色斜体）+ content（黑色正体）token-by-token
  • cancel 立即中断 / resume 跳过已完成 / timeout 兜底
  • 工作流保存为 YAML，一次编排反复使用

The Score · 三层总谱

三层架构，目录角色分离。Composer 是管理脑（META / docs / 决策记录），Orchestra 是产品代码（App / Orchestrated / .maro），.maro 是运行时工作区。

App/ SwiftUI 应用层 — the performance
SwiftUI 原生 UI：Canvas 画布 + InspectorPanel 按节点类型编辑 + OutputPanel 分组折叠流式输出 + 三页管理（Workflow / Agents / Runtime）。无第三方 UI 框架，无 Electron。

Movement IV
Vivace · 真实场景演奏

Movements · 三大乐章

No. 1 · 多 Agent 协作

生成方案 → 挑最佳 → 交付文件

Brainstorm agent 生成 3 个方案 → PickBest agent 挑最佳 → Deliver agent 写文件。原本 3 个窗口复制粘贴 15 分钟，现在画 3 个节点连 2 条线，1 分钟一键运行。

Brainstorm → PickBest → Deliver
No. 2 · Convergence Review Loop

双 Agent 出方案 → 自动评审迭代

两个 agent 分别出方案 → convergence 节点自动评审 → 不满意重跑并注入差异化反馈 → 3 轮后达标 pass。把"评审标准"从人脑外化到画布上，可复现、可迭代。

Agent A Agent B → Convergence ↻ 1-3 → Pass
No. 3 · 人工把关

AI 生成 → 人工 Approve → 交付

AI 生成后 → Human Review 节点暂停等待人工 Approve/Reject → 通过后继续交付。把人留在 loop 里做最终判断，而不是当胶水搬运——既自动化又可控。

Generate → Human Review ⏸ wait → Deliver

Crescendo · 价值与意义

效率提升 · Efficiency

消除"人当胶水"
工作流资产化可复用

一条工作流串起 N 个 agent，上下文自动按拓扑序传递，漏传/错传归零。实测把"生成方案 → 挑最佳 → 交付文件"从 15 分钟手动操作压缩到 1 分钟一键运行。

convergence review loop 自动化：原本需要人脑记忆"上一轮反馈是什么"的评审迭代，现在由 convergence 节点自动驱动——agent 跑 → reviewer 评审 → 不满意自动重跑并注入差异化反馈。把"评审标准"从人脑外化到画布上。

一次编排保存为 YAML，反复使用。同类任务只需改 prompt 不必重构流程，长期 ROI 远高于"每次重新对话"。

填补市场空白
第一性原理切入蓝海

研究了 7 个同类工具（Hive / LangGraph / CrewAI / AutoGen / Dify / Flowise / n8n），发现它们要么是代码库要写 Python，要么是 Web 端不原生。SwiftUI 原生的可视化多 Agent 编排是空白——既原生流畅又可视化编排的，市面上没有。

第一性原理切入：痛点本质是"编排层缺失"而非"模型不够强"。在模型层 OpenAI/Anthropic 已经卷成红海，但编排层（让多个 AI 协作）仍是蓝海。Orchestra 卡位编排层，不卷模型，与模型厂商互补而非竞争。

狗粮驱动 + 长期主义：我自己是第一个用户，每天用它跑真实编码任务（codebuddy CLI 通过 PTY 执行），痛了自己改，不靠猜。17+ session 的开发历程全部基于真实使用反馈。
