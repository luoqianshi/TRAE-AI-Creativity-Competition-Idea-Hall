问题

灾害面前，信息混乱是第二场灾难。

P / 01

信息散落各处

求助、寻人、报平安的帖子分散在微博、抖音、知乎、群聊里，家属需要在数十个平台间来回翻找，错过黄金救援时间。

P / 02

真假难辨

热搜里夹杂旧闻、谣言与情绪化内容，公益组织难以快速判断哪些是真实发生的灾害、哪些值得投入资源。

P / 03

没有一个地方"专门用来找人"

灾害结束后信息很快沉底，失联者家属没有持续可用的信息板块，互助难以沉淀为有效行动。

"我们在热搜上看到灾情，却找不到一个地方专门记录谁还在等救援。" — 来自一线搜救志愿者的真实反馈
流水线

从六条热搜，
到一条被回应的求助。

安迹把"多平台发现 → 跨平台验证 → 内容抓取 → 权威源比对 → AI 审核 → 自动建板"压缩成端到端流水线。

01
60s.viki.moe · 并发抓取

多平台热搜抓取

并发拉取微博、百度、头条、知乎、抖音、B站六大平台热榜，本地白名单/黑名单预过滤，剔除娱乐体育等噪声。

白名单命中（地震/台风/塌方…）→ 保留
黑名单命中（明星/综艺/股价…）→ 丢弃
调用 NewsNowClient.fetch_all()
02
Bigram Jaccard · 地名聚类 · 灾害类型合并

跨平台验证

三关渐进聚类：① 字符 bigram Jaccard 相似度 ≥0.45 初次聚类；② 中国省/市地名匹配 — "广西防城港受灾"与"广西暴雨为何这么猛"自动合并；③ 无地名灾害（如"六蓝水库决堤"）按洪水/台风/地震类型归并到同名聚类。跨平台数累加生成置信度。

≥3 平台 → high · 2 平台 → medium · 1 平台 → low
三关过后"六蓝水库决堤"→ 广西洪灾聚类，platform_count 累加
03
httpx · URL 内容抓取

精准内容获取

对每条候选热搜 URL，使用 httpx 直接抓取原文内容，提取具体地点、时间、伤亡数字等关键信息，替代依赖 Kimi web_search，提供更准确的审核依据。

fetch_url_content()
解析 HTML 提取正文
提供 Kimi 精确上下文
04
CENC · CCTV · 权威快照

权威源比对

同步抓取中国地震台网中心（CENC）与央视（CCTV）权威信息，作为 AI 审核的交叉验证依据，降低误判。

fetch_all_authoritative()
筛选 is_disaster 条目
作为 Source A 级证据输入 Kimi
05
Kimi k2.6 · Moonshot · 批量审核

AI 三态决策

将跨验证信号 + URL 抓取内容 + 权威源 + 已追踪事件一并送入 Kimi k2.6，审核规则持续迭代：无地名灾害必须联网确认地点；"洪水橙色预警""武警出动"明确定义为应急响应触发；已追踪 ≥3 轮事件自动提级复审；合并条目共享 disaster_tag 保留溯源。

approve → 自动创建板块
track → 持续追踪
discard → 丢弃
灾害名强制规范：禁止水库/桥梁/台风名，合并条目用"广西洪涝"而非"广西六蓝水库决堤"
06
POST /api/v1/disasters/ · 自动建板

建立搜救板块

approve 的灾害自动 POST 到后端创建灾害记录与搜救信息板，进入"需要救援 / 已安全"两栏。

按 disaster_tag 批内去重
自动推断灾害类型与行政区划
失败自动降级为 track

07 — 设计理念

温暖可信，
而非冰冷政务。

安迹面向的是焦虑的家属与一线志愿者，设计上拒绝政务系统的距离感，转而追求"被接住"的温度。前端采用暖白基底 + 红系主色的温润秩序设计系统，衬线标题与柔和圆角营造人文感。

温暖留白

暖白基底 #FDFBF7、柔和圆角、呼吸式间距，缓解而非放大焦虑。

3 秒可达

核心操作 3 秒内完成，灾害作为第一入口，不藏深层菜单。

适老无障碍

字号四档可调、按钮热区≥44px、对比度≥4.5:1、支持屏幕阅读器。

隐私优先

手机号加密存储，仅授权可见；slowapi 防刷限流。

技术架构

分工清晰，每一层各司其职。

爬虫、跨验证、AI 审核、灾害管理、信息提交、全文检索六模块解耦，通过 Service / Repository 分层，便于独立演进。

09 — 部署架构

租一台服务器，
docker compose up 上线。

自托管 · Docker Compose + nginx + PostgreSQL

前端构建产物由 nginx 静态托管并回退到 index.html；后端 FastAPI 由 gunicorn 多 worker 常驻运行，nginx 反向代理 /api/*；APScheduler 随后端进程内调度爬虫任务。

PostgreSQL 独立容器 + 持久卷，systemd 管理自启，Let's Encrypt 自动签发 HTTPS。数据完全自有，规避第三方 Serverless 平台对灾害敏感信息的合规风险。
