# 宝宝成长积分管家 Spec

## Why
家长在育儿过程中需要一个简单直观的工具来记录宝宝的日常行为表现，通过积分机制正向激励好习惯、纠正不良行为，并让宝宝通过积分兑换奖励获得成就感。现有工具多依赖联网和账号登录，使用门槛高，而本应用采用纯前端 + localStorage 方案，家长打开即用，数据完全本地化，保护隐私。

## What Changes
- 新建纯前端单页应用（HTML + CSS + JavaScript），无构建工具、无后端依赖
- 实现家庭成员（宝宝）管理：增删改查、切换当前宝宝
- 实现自定义行为积分项目：加分行为 / 扣分行为，支持图标和快捷操作
- 实现积分看板：总积分大数字展示 + 近 7 天 / 30 天趋势图（纯 Canvas 绘制，无外部依赖）
- 实现奖励兑换系统：家长设置奖励 → 宝宝申请兑换 → 家长确认扣分，含状态流转
- 实现成长记录时间线：按时间倒序展示所有行为记录，支持日期筛选
- 实现操作人（家长）管理：记录每次操作由谁执行（妈妈 / 爸爸 / 奶奶等自定义）
- 移动端优先响应式布局，温馨可爱的亲子风格 UI
- 加分 / 扣分操作提供动画反馈（数字弹跳、颜色提示、Toast 提示）
- 所有代码含中文注释，结构清晰分层
- 在项目根目录创建 PROJECT_GUIDE.md 说明文档

## Impact
- Affected specs: 无（全新项目）
- Affected code: 全新项目，主要文件结构如下
  - `index.html` — 应用入口与页面骨架
  - `css/style.css` — 全局样式与主题
  - `js/storage.js` — localStorage 数据访问层
  - `js/app.js` — 应用主控制器（路由 / 视图切换）
  - `js/baby.js` — 宝宝管理模块
  - `js/behavior.js` — 行为积分模块
  - `js/dashboard.js` — 积分看板与图表模块
  - `js/reward.js` — 奖励兑换模块
  - `js/record.js` — 成长记录模块
  - `js/utils.js` — 通用工具函数
  - `PROJECT_GUIDE.md` — 项目说明文档

## ADDED Requirements

### Requirement: 家庭成员管理
系统 SHALL 支持添加多个宝宝档案，每个宝宝独立维护积分、行为记录和兑换记录。

#### Scenario: 添加宝宝
- **WHEN** 家长在设置页点击"添加宝宝"
- **THEN** 弹出表单，填写昵称（必填）、选择 emoji 头像、填写生日（选填）、选择主题色
- **AND** 保存后宝宝出现在宝宝列表，可切换为当前宝宝

#### Scenario: 切换当前宝宝
- **WHEN** 家长点击顶部宝宝选择器
- **THEN** 展示所有宝宝头像列表
- **AND** 点击某宝宝后，全应用数据切换为该宝宝的记录

#### Scenario: 编辑 / 删除宝宝
- **WHEN** 家长在设置页对某宝宝点击编辑
- **THEN** 可修改昵称、头像、生日、主题色
- **WHEN** 家长点击删除
- **THEN** 二次确认后删除该宝宝及其所有关联记录（行为记录、兑换记录）

### Requirement: 行为积分系统
系统 SHALL 支持家长自定义加分行为和扣分行为，每个行为包含名称、分值、图标，并支持快捷操作。

#### Scenario: 新增行为项目
- **WHEN** 家长在行为管理页点击"新增行为"
- **THEN** 弹出表单，填写行为名称（必填）、分值（正整数）、选择 emoji 图标、选择类型（加分 / 扣分）
- **AND** 保存后行为出现在对应分类列表

#### Scenario: 预设默认行为
- **WHEN** 应用首次启动且无任何行为数据
- **THEN** 自动初始化默认行为：按时睡觉 +1、专心吃饭 +1、自己刷牙 +1、说脏话 -1、乱扔玩具 -1

#### Scenario: 快捷加分 / 扣分
- **WHEN** 家长在首页点击某行为的快捷按钮
- **THEN** 立即为当前宝宝记录一条行为日志，总积分实时更新
- **AND** 播放加分（绿色弹跳）/ 扣分（红色震动）动画反馈
- **AND** 弹出 Toast 提示"已记录：按时睡觉 +1"

#### Scenario: 编辑 / 删除行为
- **WHEN** 家长对某行为点击编辑
- **THEN** 可修改名称、分值、图标、类型
- **WHEN** 家长点击删除
- **THEN** 二次确认后删除该行为（历史记录保留，仅行为模板被删除）

### Requirement: 积分看板
系统 SHALL 实时展示当前宝宝的总积分，并提供近 7 天和近 30 天的积分变化趋势图。

#### Scenario: 总积分展示
- **WHEN** 家长进入首页
- **THEN** 顶部大字号显示当前宝宝总积分（所有行为记录分值之和）
- **AND** 显示宝宝头像和昵称

#### Scenario: 趋势图展示
- **WHEN** 家长在首页切换"近 7 天" / "近 30 天"
- **THEN** 使用 Canvas 绘制柱状图，横轴为日期，纵轴为当日净增积分（加分 - 扣分）
- **AND** 正值柱子为绿色，负值柱子为红色
- **AND** 无数据的日期显示为 0

#### Scenario: 今日摘要
- **WHEN** 家长查看首页
- **THEN** 显示今日已获得的加分次数、扣分次数、净积分

### Requirement: 奖励兑换系统
系统 SHALL 支持家长设置奖励项目，宝宝积分达标后可申请兑换，家长确认后扣除相应积分。

#### Scenario: 新增奖励
- **WHEN** 家长在奖励页点击"新增奖励"
- **THEN** 弹出表单，填写奖励名称（必填）、所需积分（正整数）、选择 emoji 图标
- **AND** 保存后奖励出现在奖励列表，显示所需积分

#### Scenario: 申请兑换
- **WHEN** 家长在奖励页点击某奖励的"兑换"
- **THEN** 若当前积分 ≥ 所需积分，创建一条"待确认"兑换申请
- **AND** 若当前积分 < 所需积分，提示"积分不足，还差 X 分"

#### Scenario: 家长确认兑换
- **WHEN** 家长在兑换申请列表对待确认项点击"确认"
- **THEN** 扣除相应积分，记录一条兑换日志，状态变为"已兑换"
- **WHEN** 家长点击"拒绝"
- **THEN** 状态变为"已拒绝"，不扣分

#### Scenario: 兑换历史
- **WHEN** 家长查看奖励页
- **THEN** 展示兑换申请列表，按时间倒序，显示状态标签（待确认 / 已兑换 / 已拒绝）

### Requirement: 成长记录时间线
系统 SHALL 按时间倒序展示当前宝宝的所有行为记录和兑换记录，支持日期筛选。

#### Scenario: 时间线展示
- **WHEN** 家长进入记录页
- **THEN** 按时间倒序展示所有记录，每条显示：日期时间、操作人、行为名称、分值变化（绿色 + / 红色 -）
- **AND** 兑换记录也展示在时间线中，标注"兑换"标签

#### Scenario: 日期筛选
- **WHEN** 家长选择日期范围（今天 / 近 7 天 / 近 30 天 / 全部）
- **THEN** 时间线仅展示该范围内的记录

### Requirement: 操作人管理
系统 SHALL 记录每次行为记录和兑换操作的操作人，支持自定义操作人列表。

#### Scenario: 设置操作人
- **WHEN** 家长在设置页管理操作人
- **THEN** 默认提供"妈妈""爸爸""奶奶""爷爷"，可增删改
- **AND** 记录行为时需选择当前操作人（默认上次选择的操作人）

### Requirement: 数据本地存储
系统 SHALL 将所有数据存储在浏览器 localStorage 中，无需联网和登录。

#### Scenario: 数据持久化
- **WHEN** 任何数据变更（增删改）
- **THEN** 立即同步写入 localStorage，刷新页面后数据保留

#### Scenario: 数据结构
- **THEN** localStorage 键名 `baby_points_data`，值为 JSON 对象，包含：
  - `babies`: 宝宝数组
  - `behaviors`: 行为模板数组
  - `records`: 行为记录数组
  - `rewards`: 奖励模板数组
  - `exchanges`: 兑换记录数组
  - `operators`: 操作人数组
  - `currentBabyId`: 当前选中宝宝 ID
  - `currentOperatorId`: 当前操作人 ID
  - `version`: 数据版本号

### Requirement: 移动端优先 UI
系统 SHALL 采用移动端优先的响应式布局，界面温馨可爱，适合亲子场景。

#### Scenario: 移动端布局
- **WHEN** 在手机宽度（≤ 480px）访问
- **THEN** 单列布局，底部固定导航栏（首页 / 记录 / 奖励 / 设置）
- **AND** 触控目标 ≥ 44px，便于手指操作

#### Scenario: 视觉风格
- **THEN** 主色调使用暖色系（柔和的橙黄、粉、薄荷绿）
- **AND** 圆角卡片、柔和阴影、emoji 图标
- **AND** 字体清晰，重要数字大字号显示

### Requirement: 操作反馈动画
系统 SHALL 对加分 / 扣分操作提供明确的视觉反馈。

#### Scenario: 加分反馈
- **WHEN** 记录加分行为
- **THEN** 总积分数字绿色弹跳放大动画
- **AND** 弹出绿色 Toast"已记录：XXX +N"

#### Scenario: 扣分反馈
- **WHEN** 记录扣分行为
- **THEN** 总积分数字红色震动动画
- **AND** 弹出红色 Toast"已记录：XXX -N"

### Requirement: 项目说明文档
系统 SHALL 在项目根目录创建 PROJECT_GUIDE.md，用中文说明项目结构、启动方式和扩展方向。

#### Scenario: 文档内容
- **THEN** 包含：项目简介、目录结构说明、启动方式（直接打开 index.html 或用本地服务器）、技术栈说明、下一步扩展方向（如数据导出导入、多端同步、PWA 离线使用等）
