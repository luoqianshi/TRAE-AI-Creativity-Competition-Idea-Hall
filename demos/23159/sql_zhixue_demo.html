01自然语言转 SQL

用日常中文描述数据需求，AI 自动完成表识别、字段匹配、SQL 生成、查询执行与结果解读，一条龙交付。

  • 先由 LLM 从表名池中智能挑选候选表
  • 结合表结构生成可执行 SQL
  • 支持多轮对话与追问补全
  • 执行结果自动中文解读 + CSV 导出
自然语言转 SQL
你的问题
查询最近 7 天内，每个城市的新增用户数与次日留存率。
AI 生成
-- 候选表：users, user_login_log SELECT u.city, COUNT(DISTINCT u.user_id) AS new_users, ROUND(SUM(CASE WHEN l.d2_login=1 THEN 1 ELSE 0 END) * 1.0 / COUNT(DISTINCT u.user_id), 3) AS d2_retention FROM users u LEFT JOIN user_login_log l ON u.user_id = l.user_id WHERE u.created_at >= DATE_SUB(CURRENT_DATE, INTERVAL 7 DAY) GROUP BY u.city ORDER BY new_users DESC;
结果解读
已执行完成。共返回 27 个城市数据，北京、上海、深圳位列新增用户前三，深圳次日留存最高（41.2%）。可下载 CSV。

02SQL 智能纠错与优化

执行报错不再一脸懵。AI 智能体定位错误根因，给出可运行的修正版本，并解释"为什么这么改"。

  • 捕获数据库错误码与上下文
  • 针对性提出修正 SQL
  • 附带修改原因和性能优化建议
  • 支持方言（MySQL / PostgreSQL / 大数据 SQL）
SQL 智能纠错
你写的 SQL
SELECT user_id, COUNT(*) FROM orders WHERE created_at > '2025-01-01' GROUP BY user_id HAVING status = 'paid';
错误信息
ERROR: column "status" does not exist · line 4:10
AI 建议
-- 问题：status 在 orders 表中叫 order_status -- 建议 1：纠正字段名 SELECT user_id, COUNT(*) FROM orders WHERE created_at > '2025-01-01' AND order_status = 'paid' GROUP BY user_id; -- 建议 2：先过滤再 GROUP BY 性能更优（避免对已支付行外的状态做聚合）

03智能图表解读

查询结果不是终点，可视化才是洞察的入口。AI 根据字段类型自动推荐图表，并给出业务解读。

  • 数值 + 维度 → 自动选择柱状 / 折线 / 饼图
  • 时间序列 → 趋势线与异常点标记
  • 多表 JOIN 结果 → 一键生成对比图
  • 图表导出为 PNG 嵌入报告
