01 / 创意介绍

让 AI 长在飞书里，而不是又一个聊天网站

市面上的 AI 助手多为独立网站，读不到飞书上下文、更无法回写文档。这个扩展把 AI 嵌进飞书侧边栏，以用户本人 OAuth 身份直接操作文档。

痛点

复合任务要切十次窗口

按条件批量改记录、跨表对齐、把表转 PPT、把 PDF 转可编辑文档——这些任务在飞书里没有原生入口。用户要在飞书和外部 AI 间反复复制粘贴，数据泄露 + 上下文丢失，最后还要手动回写。

动机

既然有 OpenAPI，就让 AI 直接调

日常工作中我反复在飞书和 ChatGPT 之间来回切——一边读表结构一边让 AI 写公式，再把结果手动贴回飞书。既然飞书有完整 OpenAPI，LLM 又能直接产出结构化指令，为什么不让 AI 长在飞书里？

形态

Chrome 侧边栏扩展 · 无后端

一个 Chrome MV3 浏览器扩展，侧边栏形态，无独立后端。全部以用户本人 OAuth 身份调用飞书 OpenAPI；自然语言驱动多维表格 / 电子表格 / 文档的读写、可视化、PPT 生成、PDF 转写、网页剪藏。

02 / 目标用户与痛点

写给每天对着多维表格的人

产品经理、运营、销售、HR、数据分析师、咨询顾问、教师——那些"每天对着多维表格但不会写复杂公式"的非技术用户。

U-01
产品经理 / 运营
每天维护需求池、客户表、活动看板。痛点：跨表对齐客户与商机靠肉眼，状态批量更新靠手敲。
U-02
销售 / CRM 使用者
在飞书多维表格里管理客户漏斗。痛点：要把"超过 7 天未跟进"的客户批量挑出来建看板，要写公式 + 建视图 + 配图表。
U-03
数据分析师 / 咨询顾问
要把表数据变成报告、PPT、可视化。痛点：Excel→PPT 链路重复劳动，公式记不住、模板对不齐。
U-04
教师 / 知识工作者
把 PDF 教案 / 论文转成可编辑飞书文档。痛点：飞书无原生 PDF 转 Markdown，复制粘贴丢失排版。
典型场景
一句话完成
"挑出 → 建看板 → 推群"

在飞书表格页打开侧边栏，输入"把状态为待跟进且超过 7 天未更新的客户挑出来建一个看板，然后推送到销售群"——Agentic 循环自动搜索 → 创建视图 → 配图表 → 发送 IM 消息，全部以用户身份直接执行。

当前痛点：没有它之前，用户要么手动逐行操作（慢、易错），要么在飞书和外部 AI 间反复复制粘贴（数据泄露 + 上下文丢失），要么依赖 IT 同事帮忙写公式（响应慢、不可迭代）。
03 / 价值与意义

效率提升 × 社会价值

从"十几分钟手动操作"压缩到"一句话下达指令"，同时让不会写代码的业务用户也能享受自动化红利。

01
效率提升

复合任务从十分钟压缩到一句话

Agentic 循环在一个回合内串行调度 50+ 工具——搜索、批量改、跨表对齐、生成 PPT、回写文档。同 round 多个只读工具并发预跑，进一步降低延迟。

02
社会价值

缩小"会写代码"与"不会"的鸿沟

让不擅长公式和脚本的业务用户也能享受自动化红利。坚持"以用户本人身份操作 + 文件级删除硬拒绝 + 出站白名单 + 沙箱隔离"四道安全硬约束。

03
商业价值

三种部署覆盖个人 / 企业 / 内网

个人版直连飞书 OAuth；企业 SaaS 版走 OAuth 代理 + 托管 LLM（secret 不进包）；私有化版支持内网域名 + 内网大模型 + CIDR 门控。

06 / 技术亮点

四道安全硬约束

AI 自动化的核心不是"能做什么"，而是"坚决不做什么"。所有安全边界硬编码在 agent.ts 顶部，schema 描述只是软提示，真正拦截在执行层。

T-01 Auth

只用用户身份

resolveToken 永远只调 getValidUserToken，绝不回退 tenant_access_token。注释明示"assistant 永远以用户身份操作，不越权"。OAuth bundle 到期前 5 分钟自动续。 

// auth.ts
resolveToken(settings) {
  return getValidUserToken(settings);
  // 绝不回退 tenant
}
T-02 Safety

文件级删除
一律拒绝

isFileLevelDelete 拦截 delete_table / delete_sheet / 通用 API 的 DELETE 方法 / POST move_to_trash。内容级删除走确认门，批改走 WRITE_TOOLS 二次确认。 

// agent.ts
FILE_LEVEL_DELETE_TOOLS = {
  delete_table, delete_sheet
}
// + POST move_to_trash 硬拒
T-03 Egress

出站只走
白名单

所有出站请求走 feishuReq / feishuFetch / feishuUpload 三兄弟，过 isFeishuOutboundAllowed 守卫 + assertSafeBaseUrl。getTenantAccessToken 也走守卫（曾经的漏洞已堵）。 

// http.ts
if (!isFeishuOutboundAllowed(url))
  throw // 拦截
// + assertSafeBaseUrl 强制 https
T-04 Sandbox

沙箱隔离
null 源

LLM 生成代码在 null opaque origin 沙箱执行，CSP connect-src: none，无 chrome.*。new Function 仅自分发构建启用；Store 构建走 runSpec 解释 VizSpec，死代码消除。 

// sandbox/index.html
Content-Security-Policy:
  default-src 'none';
  # 无网络出口
  connect-src 'none'
