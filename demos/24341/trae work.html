创意名称 + 创意介绍

🎯 想解决什么问题

开发者面对成千上万个文件，不知道从哪里入手；
代码逐渐腐化，没人知道全局架构长什么样；
需求文档、设计文档、代码实现三者严重脱节。

→ 项目越大，信息熵越高，没人看得清全貌。

💡 为什么会想到做这个

我在研究「循环工程」方法论时发现： 需求在 Excel 里，设计在 Figma 里， 代码在 IDE 里，问题在 Jira 里。
人脑无法同时处理这些分散的信息，而 AI 可以。

📱 大概是什么产品

一个基于 Web 的「项目全局操作系统」——
AI 自动扫描代码仓库、解析需求文档、追踪 ID 链路， 生成可交互的架构全景图、数据流图、需求-代码追踪矩阵。

Web 应用 AI 增强 开发者工具

目标用户及痛点

👤 面向哪些用户
  • 接手新项目的开发者
  • 技术负责人 / 架构师
  • 中小型软件开发团队（5–50 人）
📍 在什么场景下使用
  • 接手老项目 — 入职或接手历史项目，快速摸清架构
  • 架构巡检 — 每周自动检测循环依赖、超标模块
  • 需求追溯 — 输入需求 ID，1 秒定位代码与测试
⚠️ 当前痛点
  • AI 生成的代码即使专业开发者也不能保证 100% 看懂
  • 架构腐化没人发现，直到问题爆发
  • 文档和代码脱节，没有机制保证一致性
  • 需求→代码→测试→部署链路断裂，追溯全靠问人
📌 典型场景
🔹 场景一：接手老项目
新成员入职，打开 CodeLens → 系统自动扫描代码仓库 → 生成完整架构全景图（模块、依赖、数据流向）。
1 周 → 2 小时
🔹 场景二：架构巡检
技术负责人每周查看 CodeLens 看板 → 系统自动检测新增的循环依赖、超标模块、@id 缺失。
1 天 → 10 分钟
🔹 场景三：需求-代码追溯
输入需求 ID → 系统立刻显示需求文档、对应代码文件、 测试覆盖、部署版本。
问 5 个人 → 1 秒出结果

核心功能 · 四维洞察

🌐

项目全局仪表盘

AI 自动解析代码仓库，生成可交互的架构全景图、模块依赖图，点击任意模块下钻查看详情。

交互式 DAG 实时更新
🔗

需求-代码追踪矩阵

基于 @id 注释自动建立需求→设计→代码→测试→部署的完整追踪链，支持按 ID 一键搜索。

ID 追踪 缺口高亮
🧠

AI 自动诊断

每日自动扫描代码仓库，发现架构腐化、循环依赖、违反分层等问题，生成问题清单并标注严重度。

🔴 严重 🟡 中等 🟠 轻微
📋

文档-代码一致性审计

自动比对需求文档中的 ID 与代码中的 @id 注释，生成一致性报告，标注缺失项并推动补录。

一致性检查 自动反馈

全链路追踪 · ID 体系

格式： <模块>-<类型>-<3位数字>  ·  示例：AUTH-REQ-001
类型 前缀 用途 示例
REQ-REQ-需求定义AUTH-REQ-001
ARCH-ARCH-架构决策记录AUTH-ARCH-001
CODE-CODE-代码模块AUTH-CODE-001
TEST-TEST-测试用例AUTH-TEST-001
DEPLOY-DEPLOY-部署单元AUTH-DEPLOY-001
OPS-OPS-运维监控AUTH-OPS-001
🔗 追踪链： 需求文档 @id(AUTH-REQ-001) → 架构决策 ADR-001 → 代码 // @id(AUTH-REQ-001) → 测试 // 测试需求: AUTH-REQ-001 → 部署 v1.2.0 → 运维 告警配置

与 TRAE Work 的结合

CodeLens 本身就是用 TRAE Work + 四层闭环方法论 构建的：

📋 产品层
需求列表.md 定义了 CodeLens 的 4 个核心需求
🏗️ 架构层
技术规格.md 定义了前端/后端/AI 三层架构
💻 代码层
关键模块嵌入 @id 注释，支持全链路追溯
📋 审计层
自动生成一致性报告，确保文档与代码同步
⚡ TRAE Work 生成产物： 本 HTML 即为 CodeLens 的完整创意方案展示，包含产品定义、功能原型、架构设计、用户场景演示。

CodeLens 不是又一个代码分析工具， 而是一套完整的工程化方法论。
它让你从“被动应付项目复杂性”变为主动掌控项目全局。
