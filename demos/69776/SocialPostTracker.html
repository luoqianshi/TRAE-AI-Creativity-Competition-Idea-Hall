🚀 SocialPostTracker v0.1 · MVP

TikTok YouTube Facebook Instagram 学习工作赛道 一键启动 / Docker / Render

一个面向品牌方与社媒运营的多平台社媒帖子追踪台：粘贴混合链接 → 自动识别平台 → 批量抓取 → 按品牌 / SKU 分组管理 → 周期性追踪 → 一键导出 CSV。

1. 它解决什么问题

😣 痛点

  • 同时盯 TikTok / YouTube / Facebook / Instagram 四个平台，要装 4 套工具
  • 字段命名混乱：view / views / playCount / viewCount 难对齐
  • 想做"同一视频的周环比"基本靠人工跑命令 + 记 Excel
  • 抓取失败时没有标准化的错误码，定位问题靠运气
  • SaaS 抓取工具贵且数据上传到第三方，对竞品分析不友好

💡 方案

  • 统一 Web 入口：粘贴链接 → 自动判平台 → 统一字段返回
  • 内置 600s TTL 缓存 + 滑窗限流，降低被风控概率
  • 定时追踪任务（最小 0.25h/最长 30 天），自动沉淀趋势曲线
  • 标准 error.code 错误体系，方便前端做重试 / 降级
  • 本地可一键启动，也可 Docker / Render 部署，数据完全自有

2. 关键能力（产品形态）

🏠 首页 · 抓取演示区

粘贴 1 条链接 → 选 TikTok 区域 → 立刻看到封面、播放、互动率等关键字段。

POST /api/tiktok/extract { "url": "https://vt.tiktok.com/xxxxxx/", "region": "TH", "force_refresh": false } → { "views": 1.2M, "likes": 86K, "comments": 1.2K, "engagement_rate": 0.073, "view_rate": 1.4 }

📦 品牌工作台

侧边栏 品牌 → SKU → 链接组，同一 SKU 内按平台自动分组展示。

⏰ 追踪任务（Tracking）

对指定视频创建追踪任务，按自定义间隔循环抓取，沉淀历史数据，支持 trend 接口查询。

POST /api/tiktok/tracks { "url": "https://vt.tiktok.com/xxxxxx/", "region": "TH", "interval_hours": 12, "duration_days": 7, "run_immediately": true }

🛡️ 稳定性 & 安全

  • 滑窗限流：40 req / 60s / IP
  • 批量上限 20 条，并发 3，失败单条不影响其他
  • 图片代理 /api/image-proxy 解决跨域 / Referer 问题
  • 标准化错误码：INVALID_URL / RATE_LIMITED / UPSTREAM_ERROR ...

4. 目标用户与场景

👤 跨境品牌运营 / 投放优化师

同时管多个 SKU、多个平台的小团队（1–10 人），需要"一表对比"+"周环比"。

👤 内容创作者 / 学习者

把对标博主的全部公开视频导出来做选题与脚本复盘，避免一个个平台切来切去。

5. 价值与意义

30s原本 30 分钟的"粘贴→抓→存"链路
4 平台统一字段 / 统一错误码
0 成本开源可私有化，替代年费 SaaS
100% 自有数据留在自己的服务器 / 电脑里

把"会用 AI 写脚本抓数据"升级为"会用一个完整 Web 工作台管数据"。 它既是产品，也是把 抓取 / 缓存 / 限流 / 历史库 / 调度 / 错误处理 这些"每个项目都要重写一遍"的基础设施，以一个标准 FastAPI 工程的形式沉淀下来的样板， 可以被 fork 成竞品监测、舆情监控、内容审计等无数个小工具。

6. 一个"会跑起来的"最小演示

本机一键启动（Windows / macOS / Linux）

python -m venv .venv .\.venv\Scripts\activate # macOS / Linux: source .venv/bin/activate pip install -r requirements.txt python -m playwright install chromium uvicorn app.main:app --reload --port 8000

浏览器打开 http://127.0.0.1:8000 即可看到首页 + 品牌工作台。 也可以直接 .\start-server.ps1 或 .\start-server.cmd 一键拉起。

部署到 Render（已自带 Dockerfile + render.yaml）

# 推送至 GitHub 后，在 Render 选择 New+ → Blueprint → 选本仓库 # 构建完成后访问 https://<your-service>.onrender.com/health 检查 status=ok

7. 接口一览（节选）

MethodPath用途
GET/首页（抓取演示 + 品牌工作台）
GET/health健康检查
POST/api/tiktok/extract[-batch]TikTok 单条 / 批量抓取
POST/api/youtube/extract[-batch]YouTube 抓取
POST/api/facebook/extract[-batch]Facebook 抓取
POST/api/instagram/extract[-batch]Instagram 抓取
POST/api/tiktok/tracks创建追踪任务
GET/api/tiktok/tracks?status=…列出追踪任务
POST/api/tiktok/tracks/{id}/run-now立即跑一次
POST/api/tiktok/tracks/{id}/stop停止追踪
GET/api/tiktok/tracks/{id}/trend趋势数据
GET/api/{platform}/history[.csv]历史 JSON / CSV 导出
GET/api/image-proxy?url=…图片代理（解决跨域）
