✦ 洞察

需求分析：软件工程中最贵的"隐形税"

IEEE 研究表明，需求阶段引入的缺陷修复成本是编码阶段的 10–100 倍。然而，大部分团队仍在用微信语音 + 散装文档做需求管理，没有专业工具引导和量化评估。

😵

常见的痛点

  • 需求会议聊完就忘，关键细节遗漏
  • 文档散落在邮件、微信、Wiki，版本混乱
  • 功能需求之间自相矛盾，开发到一半才发现
  • 漏了重要角色或边界条件，上线前紧急改
  • 没有工具引导，新手 PM 不知从何问起
  • 需求质量无量化标准，做完不知道做没做好
💡

ReqMind 方案

  • AI 主动引导：5 个阶段按序推进，完整覆盖所有需求维度
  • 实时可视化：每阶段结束自动生成脑图，可拖拽编辑修正
  • 完备度评估：Probe Agent 实时评分（覆盖度/具体度/一致度/明确度），精确发现缺口
  • 一致性检测：跨阶段自动排查矛盾、孤立角色、悬空引用
  • 唯一真实源（SSoT）：所有数据统一管理，子 Agent 按需取快照
  • 一键导出：生成完整 SRS 需求规格说明书（Markdown）
✦ 流程

从脑暴到文档，五步走

Dialogue Agent 引导对话，Extractor 提取结构化数据，Probe 评估完善度，Graph 自动出图 — 每一步都有 AI 在背后辅助。

🎯 项目上下文

确认项目背景、核心目标、衡量指标、核心理念。「为什么要做这个项目？做成什么样算成功？怎么衡量？」

1

👥 用户与涉众

识别系统使用者、核心角色、当前痛点。「你的用户有哪些类型？他们现在是怎么做的？遇到什么困难？」

2

⚡ 功能需求 + 用例

定义系统做什么、谁操作、怎么做。「管理员能创建商品——具体流程是怎样的？图片上传、库存管理都算上。」

3

💾 数据实体

梳理核心数据对象、属性、实体间关系。「系统里有哪些核心数据？一个订单关联哪些信息？和商品什么关系？」

4

🔒 非功能需求

覆盖性能指标、可靠性、接口约束、安全合规、未来扩展。「多少用户同时在线？响应时间要求多快？部署在哪里？」

多 Agent 协作：各司其职，数据不乱

Orchestrator 统一调度，子 Agent 是"纯函数"——输入快照 + 指令，返回分析结果。数据只有一个 Owner：语义层 SSoT。

✦ 能力

不止聊天，是一套需求工程工具链

从对话引导到文档导出，覆盖需求工程全流程的六大核心能力。

🗣️

智能对话引导

不被动记录——主动追问。覆盖度不够补追问，表述模糊探边界，矛盾自动帮你厘清。支持嵌入精准上下文锚点。

🧩

结构化语义层

对话→结构化的 7 类需求、角色、实体、用例、业务规则、术语表——所有数据按 Schema 管理，可追溯可演变。

📈

完备度四维评分

覆盖度 / 具体度 / 一致度 / 明确度——每阶段量化评分（0–1），缺口精确到 Probe Point，引导用户补充。

🎨

可视化脑图编辑器

基于 @xyflow/react，需求→脑图自动生成，支持拖拽编辑修正。用户手动调整的 position 永不丢失。

🔗

跨阶段一致性检测

孤立角色检测、悬空实体引用、语义矛盾分析、范围漂移识别——三态检测策略覆盖对话中/阶段边界/全流程。

📄

一键导出 SRS 文档

语义层 → SRS 标准需求规格说明书（8 个章节，含目标→角色→功能→数据→非功能→术语→追溯→变更记录）。

📐 @xyflow/react 为何胜出

一库打全场 — 脑图用自定义节点 + dagre 树布局，后续架构图用同一套 Nodes+Edges 模型
React 原生 — 每个节点是 React 组件，与前端状态管理天然打通
数据绑定自然 — Graph Agent 输出 replace diff → setNodes/setEdges → 用户拖拽生成 diff 写回
生产验证 — Dify、Flowise、Prefect 等 AI 工具均使用 xyflow，社区 37K ⭐
