💡 一、创意介绍

创意名称

吃了吗 —— 让街边小店也能拥有自己的线上点餐系统

想解决什么问题

中国有超过 800 万小餐饮商户（麻辣烫店、煲仔饭店、早餐铺……）， 其中绝大多数没有能力接入美团/饿了么（高额抽佣 20%+、复杂入驻流程、需要专业设备）。 顾客想提前点餐只能加微信发消息，商家靠手写单子记录，容易漏单错单。

为什么会想到做这个

我家楼下有一家"老王麻辣烫"，每天中午排队 20 分钟。老板在灶台和手机之间来回切换接收微信点单，忙的时候经常看漏消息，顾客等到不耐烦就走了。老板说他也想用扫码点餐，但美团抽 22%，他一天利润才 100 多块——不是不想用，是用不起。

产品形态

一个 手机 Web 应用（无需下载安装），商家注册后生成一个 8 位商家码，顾客扫码即进入菜单页点餐下单。商家端在手机上就能管理菜单、查看订单、更新状态。

🎯 二、目标用户及痛点

核心用户群体

👨‍🍳 商家端

  • 街边小餐饮店主（麻辣烫、煲仔饭、粉面馆、早餐摊等）
  • 日均订单 30-200 单，客单价 15-50 元
  • 手机使用熟练（会发微信、刷抖音），但对电脑操作不熟悉
  • 最大痛点：付不起大平台抽佣，也折腾不起复杂的后台

🍽️ 顾客端

  • 周边常客（小区居民、写字楼上班族、学生）
  • 场景：午饭/晚饭前提前点餐，到店即取
  • 最大痛点：不想下载 App，不想加商家微信，就想扫码点一下

使用场景

1
商家注册
手机号登录 → 填店名 → 获得8位商家码
2
顾客绑定
扫码或输入商家码 → 一键绑定
3
在线点餐
选菜品 → 加规格 → 提交订单
4
商家接单
后台查看 → 制作 → 通知取餐

🛠️ 四、技术框架与实现思路

技术栈

Next.js 16 TypeScript Prisma ORM SQLite Zustand JWT (jose) Tailwind CSS RESTful API

架构设计

  • 前端：Next.js 16 App Router + 服务端组件，响应式设计适配手机
  • 后端：Next.js API Routes，RESTful 风格接口
  • 数据库：SQLite（开发）/ PostgreSQL（生产），Prisma ORM 统一操作
  • 鉴权：JWT（jose 库）+ httpOnly Cookie + 角色路由中间件
  • 状态管理：Zustand + persist 本地持久化（购物车、登录态）
  • 验证码：SMS 短信验证码登录（开发模式 Mock）

数据库模型（15张表）

User · Merchant · UserBoundMerchant · MenuCategory · MenuItem · MenuItemSpec · MenuItemAttrGroup · MenuItemAttrOption · Order · OrderItem · OrderItemAttr · Review · ReviewReply · ReviewLike · FavoriteMerchant

🌟 五、应用场景与价值

商业价值

  • 覆盖 800 万+ 小餐饮商户的长尾市场，这是美团/饿了么覆盖不到的蓝海
  • 商业模式清晰：基础功能免费 → 高级功能订阅（短信通知、数据分析、多店管理）
  • 获客成本极低：商家之间口口相传，一个麻辣烫店老板推荐给隔壁煲仔饭店老板

社会价值

  • 🏪 赋能小商户：让技术能力为零的小店主也能拥有数字化点餐能力
  • 💼 促进就业：降低餐饮创业的数字化门槛
  • 🌐 数字平权：不让"不会用电脑"成为小商户被大平台排除在外的理由

效率提升

  • 商家接单效率提升 50%+（告别微信手打、纸笔记单）
  • 顾客等待时间减少 10-20 分钟（提前点餐，到店即取）
  • 错单漏单率降低至 接近 0（系统记录，不会看漏微信消息）
