🔥 核心痛点

Git 很好，但太重了

大型仓库、弱网环境、跨岗位协作场景下，Git 的"全量历史"设计反而成了效率瓶颈

🐌

下载慢

GitHub 国内访问不稳定，clone 中等规模仓库可能要 10-30 分钟，严重影响开发节奏。

💥

大仓库失败

仓库体积过大时 clone 容易超时中断，网络波动导致前功尽弃，需要从头再来。

💾

磁盘占用大

完整 clone 包含全部历史记录，一个项目可能占用数 GB 磁盘空间，前端资源仓库尤甚。

📚

学习曲线陡

SVN 用户迁移到 Git 需重新学习命令体系，非开发岗位面对 Git 命令一脸茫然。

💡 解决方案

轻量化四重奏

从克隆策略、下载方式、操作习惯到历史获取，全方位为 Git 减负

01
⚡

浅克隆优先

默认 depth=1 克隆，只获取最新快照，跳过完整历史。大型仓库秒级检出，磁盘占用降低 80%+。

lg checkout https://github.com/user/repo.git
02
🚀

多源加速下载

GitHub/Gitee 仓库自动启用 HTTP 多源并行下载，从多个镜像源并行获取 blob 对象，内置故障转移。

lg clone URL --download-mode auto
03
🔄

SVN 风格操作

使用 checkout / update / commit 等熟悉的 SVN 命令，零学习成本上手。commit 自动 push，体验一致。

lg update && lg commit -m "修复问题"
04
📦

按需获取历史

需要完整历史时再 fetch，按需扩展。真正做到"用时才取"，不用的历史不占空间。

lg fetch --unshallow
