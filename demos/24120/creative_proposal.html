创意介绍

解决什么问题

医疗提供者数据时刻在变化——医生换诊所、诊所关闭或更名、电话号码变更、专科名称在不同来源中不一致。目前 HealthLynked 的医疗提供者目录依赖人工维护，成本高、速度慢、难以规模化，导致患者搜索到的信息可能已过时，直接影响就医体验。

灵感来源

HealthLynked 在 Kaggle 举办了一场挑战赛，寻求可重复、低成本的 AI 管线方案。我们意识到，医疗数据的准确性关乎患者能否找到正确的医生，这是一个真实的社会需求，而 AI + 公开数据源可以系统性地解决它。

产品形态

一个可周期性运行的自动化数据管线系统，包含 6 个核心模块：过期检测 → 外部源搜索 → 数据标准化 → 记录匹配 → 置信度评分 → 决策执行，全程附带审计追踪。

目标用户及痛点

面向用户

  • 医疗平台运营方（如 HealthLynked）：需要维护大规模提供者目录的数据团队
  • 患者：依赖在线目录查找医生，需要准确的信息来预约就诊
  • 医疗机构：希望自己的最新信息能被患者正确找到

使用场景

患者通过 HealthLynked 搜索附近的心脏科医生，如果目录中的地址或电话已过时，患者可能白跑一趟或无法联系上医生。

当前痛点

数据过时

医生搬家、换诊所后，目录信息可能数月甚至数年未更新

人工成本高

逐条核实数万条记录，需要大量人力和时间

来源冲突

不同数据源显示不同地址/电话，人工难以判断哪个正确

重复记录

同一医生可能有多条记录，造成混淆

模块 1：过期记录检测

  • 时间阈值检测：超过 180 天未验证的记录标记为"中等风险"，超过 365 天标记为"高风险"
  • 缺失字段检测：缺少 NPI、电话、地址等关键字段的记录
  • 数据质量检测：占位符电话(555)、不完整地址等信号

模块 2：外部源搜索

  • NPI Registry API（免费、公开、无需认证）— 优先搜索
  • 州医疗委员会数据 — 补充验证
  • 诊所网站数据 — 最新信息
  • 成本控制：仅对过期记录搜索，免费源优先

模块 3：数据标准化

  • 姓名：分离并标准化资质后缀（MD、DO、NP）
  • 地址：统一缩写（St、Ave、Blvd）、州名转缩写、套房号格式化
  • 电话：统一为 (XXX) XXX-XXXX 格式
  • 专科：别名映射（"Cardiovascular Disease" → "Cardiology"）

模块 4：记录匹配与置信度评分

  • 逐字段模糊比较（SequenceMatcher）
  • 来源可靠性加权：NPI Registry(0.95) > 州委员会(0.85) > 诊所网站(0.75)
  • 多源一致性加成，冲突来源惩罚

模块 5：决策引擎

  • 置信度 ≥ 0.85 → 自动更新
  • 0.60 ≤ 置信度 < 0.85 → 人工审核
  • 置信度 < 0.60 → 标记不确定
  • 覆盖规则：姓名变更、城市变更、状态变更一律人工审核

模块 6：审计日志

  • 完整记录：变更了什么、为什么变更、哪些来源支持、置信度分数
  • JSON 格式导出，支持合规审计

价值与意义

商业价值

替代人工逐条核实，预计节省 80% 以上的人力成本。管线可处理数万至数百万条记录，边际成本极低。

社会价值

患者能找到正确的医生，减少因信息过时导致的就医延误。医疗数据准确性直接关系公共健康。

成本控制策略

  • 仅处理过期记录 — 不对整个数据库每次全量搜索
  • 免费源优先 — NPI Registry API 完全免费且无需认证
  • 按需搜索 — 仅当 NPI 数据不足时才搜索额外来源
  • 无 LLM 依赖 — 核心匹配使用确定性算法，LLM 仅在边缘场景使用
  • 可配置批处理 — 限制每次运行的记录数和 API 调用数
Python 3.10+ NPI Registry API SequenceMatcher 零 LLM 依赖 可扩展架构
