Problem

为什么开发者总在
Alt-Tab 与等待中消耗心流？

必须紧盯 IDE

AI 代理的审批请求、追问和完成通知都发生在 IDE 内部。一旦切换到浏览器、终端或文档，很容易错过关键交互节点。

多会话缺乏总览

同时运行多个 Trae 会话时，没有统一面板展示哪些在等待干预、哪些已完成、哪些长时间卡住，极易遗漏。

生态缺少原生监控

Trae 生态尚无 macOS 原生的菜单栏/灵动岛级监控工具，开发者只能依赖 IDE 自身通知，体验断层明显。

基于 Trae 官方 hooks 协议与 agent-tool-host 双路径监听，自动识别 Trae、TRAE SOLO、TRAE Work 及 CN 版本的会话事件。

自动展开，一键操作

当代理需要审批、追问或任务完成时，灵动岛自动展开，直接在屏幕顶部完成允许、拒绝、回答或跳回 IDE。

Use Cases

谁需要 TRAE FLOW？

后台运行

多窗口工作者

让 Trae 在后台执行重构或代码生成任务，自己切换到浏览器查资料、写文档。审批和追问通过灵动岛直达，不再错过。

多会话

重度 AI 编程用户

同时开启多个项目会话，通过统一列表快速定位需要干预的窗口，批量处理已完成的会话，减少 Alt-Tab 次数。

心流保护

需要专注的开发者

将"主动查看 IDE"变为"被动接收通知"，守护编程心流。任务完成后一键跳回对应项目窗口，上下文无缝衔接。
