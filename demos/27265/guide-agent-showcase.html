00 · Demo

从一句诉求，到一条网页内指引

用户不需要先懂 Cloudflare 的产品名。Agent 先听懂目标，再解释要用到的服务能力，并在真实页面里带用户完成 Workers 创建与部署。

01 · 能力

不只回答问题，还要落到页面上

  1. 诉求理解先问目标，不先问产品名

    用户说「我想搭一个服务」就能开始。Agent 先判断这是后端逻辑、静态网站还是域名访问问题，再把目标映射到 Cloudflare 的服务能力。

  2. 能力解释把菜单变成概念

    Guide Agent 不只告诉用户点哪里。它会说明 Workers 为什么适合运行服务逻辑，DNS 为什么负责自定义域名，让用户边做边理解服务边界。

  3. 网页浮层步骤落在真实页面

    浏览器插件在 Cloudflare 页面内高亮入口，展示当前步骤的目的，并提供跳转、预填和检查。它和目标网站解耦，不要求平台方改代码。

  4. 半自动辅助关键动作留给用户确认

    Agent 可以帮用户定位、填写和检查，但创建资源、发布配置、授权访问这类关键写操作，必须由用户自己确认。

  5. 异常恢复阻塞也能继续引导

    未登录、权限不足、账号不对、页面变化和校验失败都会进入恢复步骤。Agent 解释发生了什么，再给出修复路径或只读学习模式。

02 · 原则

现场主线要稳，产品边界要能扩展

  1. 01 从用户语言出发用户不需要先分清 Workers、Pages、DNS。Agent 把自然语言目标转成一条能看懂的能力路线。
  2. 02 每一步都要解释每个 Guide Step 都回答做什么、为什么、怎么确认，避免用户一路点完却没有真正学会。
  3. 03 优先跑真实网页参赛 Demo 选择真实 Cloudflare 页面。登录、权限和账号状态都放进 Agent 的引导范围。
  4. 04 主线稳定，边界可扩展现场跑通 Workers 创建与部署。DNS、R2、Pages 通过能力包和后续路线展示通用性。

04 · 问答

几个容易被问到的问题

它和普通教程、Intro.js 有什么区别？
普通教程大多按固定脚本走。Guide Agent 从用户目标出发，结合网站能力包和当前页面状态生成路径，每一步都会解释目的并检查结果。
为什么先做 Cloudflare？
Cloudflare 服务多、概念门槛高，任务结果也容易验证。Workers 主线能在较短 Demo 里展示理解、定位、推进和检查。
会不会替用户直接改云平台配置？
不会。Agent 可以辅助跳转、预填和检查，但创建资源、保存配置、发布服务等关键写操作，必须由用户确认。
为什么说它能扩展到 Figma 等产品？
抽象对象不是 Cloudflare 菜单，而是 Site Skill Pack：把热门网站的能力、常见目标、风险动作和完成校验提前整理好。
遇到未登录或权限不足怎么办？
这些不是失败，而是阻塞状态。Agent 会生成恢复步骤，解释问题、影响和下一步修复方式。
参赛 Demo 的成功标准是什么？
看四个信号：是否听懂目标、是否定位到真实页面、是否推进到 Worker 部署成功、用户是否理解下一步为什么需要 DNS。
