Hyper-Dyna-MCP

面向 HyperMesh GUI 的 LS-DYNA 自动化建模 MCP 系统。它通过 FastMCP + stdio 接入 Claude Code / Codex / Trae，把结构化建模指令转换为 verified Tcl routes，并发送到正在运行的 HyperMesh GUI listener。

它解决什么问题

LS-DYNA / HyperMesh 前处理里，重复 GUI 操作和散落 Tcl 脚本很难标准化。 Hyper-Dyna-MCP 提供一个可被 AI Agent 稳定调用的中间层。

传统流程低效

建模、单元创建、材料赋值、约束与载荷施加通常依赖手动 GUI 或临时 Tcl。

Agent 难以直控 GUI

HyperMesh GUI 不是天然面向 AI Agent 的接口，需要稳定的命令转换与监听机制。

路线需要可验证

未验证命令不能直接执行；系统用 MAP、dry-run、recording gate 降低误操作风险。

工作流

当前产品形态是 MCP Server + FastMCP + stdio 通信机制，目标是让 Claude Code / Codex / Trae 通过结构化工具调用控制本机 HyperMesh GUI listener。

Agent 发起请求

用户用自然语言描述建模动作，Agent 转成 MCP tool 调用。

MCP Server 校验

FastMCP stdio 接收参数，统一进入能力矩阵、关键字 MAP 和 guardrail。

Verified Route 执行

只有已验证 Tcl 路线会被发送；blocked route 会返回录制和验证要求。

GUI Listener 建模

HyperMesh Tcl listener 接收命令，在本机 GUI 中创建实体、刷新显示或保存 .hm。

能力与边界

主要围绕建模仿真工作流进行展开。

FE 单元创建 HEX8、TET4、QUAD4 shell、TRIA3、BAR2/BEAM、MASS element。
几何创建 surface plate、geometry solid box；solid box 走 verified *solidblock route。
建模 action 材料分配、属性分配、截面分配、EOS 分配、约束施加、载荷施加。
连接机制 HyperMesh GUI listener 默认端口进行连接 ，支持 socket / IPC 兜底状态。
LS-DYNA solver 执行 当前 MCP 执行范围不包含求解器运行。
LS-PrePost / hmbatch 当前不作为 MCP tool 执行。
K 文件导出 GUI export route 未验证前，不用后端 K writer 绕过 HyperMesh。
复杂未验证卡片 例如 MAT 3等仍需 command recording 与 runtime evidence。
LS-DYNA 有限元工程师 减少重复前处理动作，保留可追踪的 verified route。
HyperMesh 前处理用户 通过 GUI listener 把常见建模动作结构化。
仿真自动化开发者 获得一个能被 Claude Code / Codex 调用的 MCP 中间层。
AI Agent + CAE 集成者 用 guard 函数限制未验证命令，避免把检索资料误当执行依据。
