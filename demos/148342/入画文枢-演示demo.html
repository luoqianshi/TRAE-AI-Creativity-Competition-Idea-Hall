01 / PAIN POINT

长篇创作，难的不是第一章

写到第 80 章、第 200 章以后，AI 一次性生成器会全面崩溃——这是入画文枢要解决的核心痛点。

DRIFT
人

角色动机漂移

主角性格越来越模糊，配角人设前后矛盾，写到后期"像换了个人在写"。

CLASH
力

设定互相打架

战力体系崩坏、时间线错乱、地点张冠李戴、世界规则自相矛盾。

LEAK
伏

伏笔埋了就忘

关键钩子没人回收，期待落空；或者提前剧透，破坏悬念节奏。

FLAT
节

节奏失去控制

主线断档太久、感情线失踪、世界观扩展过快或过慢，追读力持续下滑。

AMNESIA
忘

写完就忘

每章生成完就丢弃事实，下一章重新"幻觉"，前文已经发生过的事再发生一遍。

BLACKBOX
盲

状态不可见

作者无法快速知道"现在到底写到哪了、谁出场过、哪些伏笔还欠着"。

02 / SOLUTION

把"必须记住的事"变成 AI 会自动执行的步骤

不是写完就丢的一次性生成器，而是一套面向长篇连载的一致性系统。动笔前先查资料，写完后把新事实记下来、做审查、再同步进检索索引、摘要、长期记忆和 Dashboard。

防幻觉三定律

把"必须记住、不能写崩"的约束，变成 Claude Code 会自动执行的步骤。文笔和节奏可以放开发挥，但发生过的事实必须登记、过审、存档。

LAW 01 · 大纲即法律
遵循大纲，不擅自发挥
Context Agent 强制加载章节大纲与卷纲，写作前生成"创作任务书"。
LAW 02 · 设定即物理
遵守设定，不自相矛盾
Reviewer Agent 内置一致性审查，战力 / 地点 / 时间线 / 世界规则逐项核对。
LAW 03 · 发明需识别
新实体必须入库管理
Data Agent 自动提取事实并消歧，写入 .story-system 主链和投影。
03 / SKILLS

8 个 Skill 命令 · 串起整条创作流程

从初始化设定、规划卷纲，到写章、审查、沉淀记忆、查询状态，再到只读可视化面板——一条龙覆盖长篇网文创作全链路。

01
/webnovel-init
深度初始化
分阶段问答，帮你把书的骨架、设定集、总纲和初始状态搭起来。
$ /webnovel-init
02
/webnovel-plan
卷纲规划
基于总纲拆卷、拆章、补时间线，并写回新增设定到主链。
$ /webnovel-plan 1
03
/webnovel-write
章节创作
一条龙写完一章：备上下文 → 起草 → 审查 → 润色 → 记录事实 → 自动备份。
$ /webnovel-write 45
04
/webnovel-review
质量审查
从爽点、一致性、节奏、OOC、连贯性、追读力六个维度审查章节。
$ /webnovel-review 1-5
05
/webnovel-query
状态查询
查询角色、伏笔、节奏、实体关系和运行时信息（只读）。
$ /webnovel-query 萧炎
06
/webnovel-learn
项目学习
把这本书里好用的写法记下来，存进项目长期记忆。
$ /webnovel-learn "这个钩子有效"
07
/webnovel-dashboard
可视化面板
启动只读面板，浏览项目状态、实体图谱、章节内容和追读力数据。
$ /webnovel-dashboard
08
/webnovel-doctor
项目体检
阶段感知检查目录、文件、数据库、RAG、依赖和 Dashboard 产物。
$ /webnovel-doctor --chapter 12
04 / ARCHITECTURE

Story System · 合同驱动的一致性主链

写前真源 + 写后真源分离；.story-system 是唯一的事实源头，.webnovel/* 降级为只读投影。动笔前签"合同"，写完后做"提交"，事件可审计、可回放。

系统分层与数据流

LAYER 1 · USER ENTRY

▼
LAYER 2 · AGENTS

▼
LAYER 3 · STORY SYSTEM (MAIN CHAIN)

▼ accepted CHAPTER_COMMIT 驱动
LAYER 4 · READ-MODEL PROJECTIONS

▼
LAYER 5 · AUTHOR-FACING VIEWS
/webnovel-query 状态查询 /webnovel-dashboard 可视化 /webnovel-doctor 健康检查 /webnovel-learn 项目记忆
05 / PIPELINE

/webnovel-write 不是一次生成，是一条带关卡的流水线

把"怎么写"和"写了什么"分开：文笔和节奏可以放开发挥，但发生过的事实必须登记、过审、存档，不能含糊。失败可断点续跑，不重写已可信的产物。

STEP 1

项目根 / 占位符 / Story System 健康
STEP 2
运行时合同
刷新本章 runtime contract
STEP 3
写作任务书

STEP 4
起草正文
根据任务书生成章节内容
STEP 5
多维审查
Reviewer blocking 不通过则阻断
STEP 6
润色终检
排版 / Anti-AI 终检
STEP 7
事实提取
Data Agent 提取事实
STEP 8
章节提交
驱动 state/index/summary/memory/vector 投影
STEP 9
章节备份
执行章节级自动备份

09 / STRAND WEAVE

Strand Weave 节奏系统

把全书叙事拆成三条"故事线"，用比例红线防止节奏失衡——主线不连续太久、感情线和世界观不断档太久。

三线占比 · 理想分布

Quest 主线 60% Fire 感情 20% Constellation 世界观 20%

主线推进核心冲突，感情线发展人物关系，世界观扩展背景势力与设定——三者交织形成长篇连载的"呼吸感"。

节奏红线 · 不能越界

Quest 主线连续≤ 5 章
Fire 感情线断档≤ 10 章
Constellation 断档≤ 15 章
违规处理BLOCKING

Reviewer 的 Pacing Checker 会在每章审查时自动检查这三条红线，越界即标红阻断，不允许"只写主线不写感情"或"感情线失踪大半卷"的情况发生。

10 / TECH HIGHLIGHTS

技术亮点

不是简单的 prompt 模板堆叠，而是一套有架构、有契约、有审计、有投影、有可视化、有体检的长篇创作工程系统。

01

合同驱动主链

合同种子 + 运行时合同 + 章节提交 + 事件审计，写前签合同、写后做提交，事实可审计可回放。

02

多 Agent 协作

Context / Reviewer / Data / Deconstruction 四个 Agent 各司其职，读写审查分离。

03

投影 + Read-Model

state/index/vectors/summaries/memory 全部从主链派生，可重放、可对账、可重建。

04

RAG 检索回退

Embedding + Rerank 双路召回，无 Key 自动退回 BM25 关键词检索，不强依赖外部服务。

05

断点续跑

写章中断后重跑同章会优先检查可信断点，不重写已可信的正文、审查、提交或备份。

06

作者友好报告

最终报告分"已完成 / 部分完成 / 需你处理 / 未完成"四态，不甩 traceback 给作者。

07

阶段感知体检

doctor 命令根据项目当前阶段给出差异化检查与修复建议，定位"哪一路没同步"。

08

开源可扩展

GPL-3.0 协议，37 题材模板 + 9 CSV 写法数据，欢迎社区贡献新题材、新审查维度、新可视化。

11 / VALUE

价值与意义

从效率提升与社会价值两个角度，重新审视长篇创作工具的边界。

效率

把"对齐设定"的时间还给创作

长篇作者每周动辄花数小时翻看前文核对"这个角色上次出现在哪章""那个伏笔埋在哪"。入画文枢把这些机械工作交给系统，作者只需专注创作决策。

社会

让普通创作者也能驾驭长篇

降低长篇连载的创作门槛——让没有专业编辑团队、没有大纲助理的普通人，也能写出设定自洽、伏笔回收、节奏稳定的长篇故事，把"写完一本好书"从少数人的特权变成更多人的可能。
