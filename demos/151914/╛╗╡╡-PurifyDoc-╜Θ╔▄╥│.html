为什么需要净档？

RAG 知识库的效果瓶颈，往往不在模型，而在原始数据

📄

格式混乱

PDF 转换后表格错位、页眉页脚穿插、多余空行与特殊符号污染文本

🔁

内容冗余

重复段落、广告插入、版权信息反复出现，严重干扰语义检索精度

✂️

语义断裂

文档换行错误导致句子被切断，分块后上下文丢失，回答质量直线下降

核心功能

从上传到导出，一站式完成文档预处理

🧹 五维智能清洗

针对职场文档常见脏数据模式，提供可配置的组合清洗策略。去除多余空行、识别并过滤页眉页脚与页码、修复被换行打断的句子、合并重复段落、统一全半角与空白字符。

规则引擎 可配置 实时预览
// 清洗前后对比 原始: 第一章 概述 第 1 页 本文介绍... 第 2 页 本文介绍... 清洗后: 第一章 概述 本文介绍...

🧩 语义感知分块

不是简单按字数切割，而是基于段落语义边界智能分块。短段落自动合并、超长段落按句子边界拆分，确保每个 Chunk 都是一个完整的语义单元。

语义边界 动态合并 长度均衡
// 分块策略示例 Chunk #1 245字 质量分 92 Chunk #2 178字 质量分 85 Chunk #3 312字 质量分 78 ⚠️ → 建议拆分

📊 逐块质量诊断

从长度适宜度、语义完整性、内容密度三个维度为每个 Chunk 打分，并自动生成调优建议。哪些块太短该合并、哪些块太长该拆分、哪些块结尾不完整，一目了然。

多维评分 可视化 调优建议
// 质量评分维度 长度评分 40/40 ✅ 80-300字最优区间 完整评分 30/30 ✅ 以句末标点结尾 密度评分 25/30 ⚠️ 特殊符号占比偏高 综合: 95分

⚡ 纯前端架构

基于浏览器 FileReader API 与原生 JavaScript 实现全部文档解析与处理逻辑，无需服务器，保障数据隐私。

🎯 启发式清洗引擎

结合正则规则与语义启发式算法，精准识别页眉页脚、重复内容、断句换行等 8 类常见脏数据模式。

📐 自适应分块算法

动态判断段落长度，短段落自动缓冲合并，超长段落按句法边界拆分，输出均衡且语义完整的 Chunk 序列。

🔍 多维质量评估

从长度适宜度、语义完整性、内容密度三个维度量化评分，并基于规则生成可执行的调优建议。
