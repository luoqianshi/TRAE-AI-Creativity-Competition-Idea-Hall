01 / 创意介绍

为什么是 FitMate AI

健身爱好者缺少一个真正"懂自己"的 AI 助手。现有健身 App 多停留在数据记录层面，无法结合训练历史、身体指标和饮食偏好给出个性化建议；记录训练日志也只能手动逐项填表，缺少自然语言交互的便利。

健身场景天然适合 agent 架构——它需要长期记忆、调用工具、结合知识库给出专业建议。

FitMate AI 自身搭载了工具调用、MCP、Skill、长短期记忆、会话管理等能力，可以成为一个可持续陪伴用户的私人健身教练，而不只是一个冷冰冰的记录工具。

产品形态 跨平台（Web + App）的 AI 健身教练

03 / Agent 能力架构

FitMate AI 的引擎

FitMate AI 的核心差异在于 agent 架构。它不是简单的问答机器人，而是一个具备工具调用、记忆系统、技能扩展和会话管理的智能体，能够真正"记住"用户、"读懂"用户、"服务"用户。
01

工具调用

Tool Calling

Agent 可调用外部工具读写训练日志、查询身体数据、检索知识库。用户说"记录今天卧推 80kgx8x4组"，agent 自动解析并归档。

用户 → "记录今日训练" → save_workout_log()
02

MCP 协议

Model Context Protocol

通过 MCP 接入营养数据库、运动科学文献、可穿戴设备 API，让 agent 获取的信息更全面、建议更专业。

agent → MCP → 食物热量库 / 手环心率数据
03

Skill 技能

Skill Modules

可插拔的技能模块——训练计划生成、体态分析、营养计算各自封装为独立 skill，按需激活。

workout_planner / nutrition_calculator / form_analyzer
04

长短期记忆

Long & Short-term Memory

短期记忆支撑单次会话上下文连贯；长期记忆沉淀用户画像、训练历史、身体指标变化趋势。

RM记录 / 训练偏好 / 伤病史
05

会话管理

Session Management

多轮会话状态保持与上下文切换。暂停、切换话题、再回来时 agent 仍然记得刚才聊到哪。

session_01 训练 → session_02 饮食 → 回到 01
06

知识库

Knowledge Base

内置运动科学、营养学、恢复策略等领域知识库，agent 给出的建议结合用户数据与专业知识推理。

RAG: 用户数据 + 知识库 → 个性化建议

04 / 核心功能场景

一次完整的训练日

从训练前到训练后，FitMate AI 全程陪伴。

STEP 01 · 训练前

查看今日计划

Agent 基于上一次训练强度和恢复状态，推荐今日训练内容与目标重量。

"你上次卧推做到 80kgx8，今天建议 82.5kg 起步，注意控制离心速度。"
STEP 02 · 训练中

对话式记录

用户口述训练数据，agent 工具调用自动解析并保存，无需手动填表。

"刚做完深蹲 100kgx5x3组，最后一组有点吃力" → 已记录
STEP 03 · 训练后

恢复与饮食建议

结合训练量和身体数据，agent 给出恢复建议和当日饮食搭配方案。

"今日训练量较大，建议补充 30g 蛋白质，碳水选糙米或红薯。"
STEP 04 · 日常

趋势回顾

长期记忆沉淀训练历史，用户随时查询进步趋势和薄弱环节。

"过去一个月卧推 1RM 提升了 5kg，但背部训练量偏低。"

能力对比：传统 App vs FitMate AI

六个核心维度对比，FitMate AI 在个性化、记忆能力和数据整合上具备显著优势。

05 / 价值与意义

为什么值得做

↑ 效率提升

FitMate AI 将健身数据管理从"被动记录"升级为"主动服务"。用户通过自然语言对话即可完成日志记录、数据查询和方案调整，无需在多个表单间切换。Agent 基于长期记忆和知识库给出的训练与饮食建议，替代了用户自行搜索、判断的过程。

∞ 商业价值

健身用户的长期留存依赖个性化体验，而 agent 架构天然支撑"越用越懂你"的成长曲线——训练数据积累越多，建议越精准，用户粘性越强。这种基于记忆和数据的个性化能力，构成了产品差异化和付费转化的核心壁垒。
