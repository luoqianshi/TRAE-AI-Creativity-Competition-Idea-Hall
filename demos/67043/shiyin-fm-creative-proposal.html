Pain Points

直播电台的魅力在偶遇，问题也在偶遇。

01

歌名不完整

很多电台没有可靠的 Now Playing 信息，用户听到喜欢的歌却不知道名字。

02

转瞬即逝

直播流无法像点播一样回到上一首，错过识别窗口就只能靠记忆搜索。

03

工具割裂

播放器、识曲工具、歌词和音乐平台各自分散，操作会打断收听状态。

04

记忆丢失

识别出的歌曲很难和当时的电台、时间、歌词片段一起沉淀。

Solution

让电台从“背景声”变成可回看的音乐发现路径。

1

打开电台

从精选电台或 Radio Browser 搜索结果开始收听，Web 和小程序提供轻量入口。

2

一键识歌

macOS 客户端使用 ShazamKit 捕获当前直播流里的歌曲片段。

3

补全信息

自动整理歌名、歌手、封面、专辑、发行时间和 LRC 同步歌词。

4

保存与跳转

识别历史保留电台上下文，并支持打开 Apple Music、网易云音乐或 QQ 音乐。

Audience

目标用户不是只想“听声音”，而是想留下偶遇。

音

音乐爱好者

喜欢 FM 和网络电台的随机感，希望发现更多非算法推荐的歌曲。

工

办公与学习用户

需要长期背景音乐陪伴，同时希望播放控制足够轻，不打断工作流。

寻

冷门歌曲探索者

经常在电台里听到陌生歌曲，希望识别、留存并去音乐平台继续追踪。

Mac

桌面端用户

希望有状态栏控制、桌面歌词、定时关闭和更克制的 macOS 原生体验。

Features

核心功能围绕一个动作展开：把听到的好歌留下来。

全球电台发现接入公开网络电台目录，支持名称搜索和精选推荐。
ShazamKit 识歌在 macOS 完整客户端中识别当前直播流里的歌曲。
同步歌词匹配 LRC 歌词，保留当前歌词片段作为音乐记忆。
识别历史保存歌曲、电台、时间、封面和来源，方便回看。
收藏分组把常听电台整理成个人频道库，降低反复搜索成本。
状态栏播控桌面端保持轻量控制，不必频繁切回主窗口。
分享卡把“在哪个电台听到哪首歌”做成可分享的音乐卡片。
Journey

用户旅程：从随机收听到可保存的音乐记忆。

01

打开电台

用户选择喜欢的音乐、Lofi 或城市电台。

02

听到好歌

直播流里出现一首喜欢但不知道名字的歌。

03

一键识别

点击识歌，不离开当前播放体验。

04

查看歌词

返回歌名、歌手、封面和同步歌词。

05

保存历史

歌曲与电台上下文一起沉淀。

06

继续收藏

跳转到常用音乐平台继续播放或收藏。

Value

价值不在“又一个播放器”，而在补齐电台体验的最后一公里。

娱乐体验

保留电台的未知和偶遇感，让用户重新享受“打开电台，遇见一首歌”的轻松体验。

效率提升

减少记歌词、切换应用、手动搜索的成本，一次点击完成识别、歌词、历史和平台跳转。

商业路径

Web 和小程序负责轻量体验与引流，macOS 客户端提供完整识歌、歌词、状态栏和 Pro 权益。

合规与隐私

不托管、不上传、不分发音频内容；连接公开电台目录，并尽量把收藏、历史和设置保存在本地。

Demo Plan

初赛 Demo 先做一个最小闭环。

目标不是一次展示所有端，而是让评委能真实体验“选择电台 → 播放 → 点击识歌 → 展示结果 → 保存历史”的关键价值。

  • 可播放的电台列表和搜索入口。
  • 主播放器包含播放/暂停、上一台/下一台、收藏和定时关闭。
  • 识歌结果卡展示歌曲名、歌手、封面、歌词和来源。
  • 识别历史支持回看曾经识别过的歌曲。
  • 分享卡预览展示“我在某个电台听到这首歌”的音乐记忆。
