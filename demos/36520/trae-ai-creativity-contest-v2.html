Project World Engine AI 项目的确定性规范层

Project World Engine（PWE）是面向 AI 原生项目的治理后端。它用 .ws 格式作为项目唯一真相源，让 Cursor、Claude Code 等 AI Agent 在约束内协作，让项目从"能写"变成"敢用、能维护"。

Why

AI 编码时代，
项目治理严重掉队

文档与代码永远对不上

Agent 今天改了代码，明天 README 还是旧的。没有人能完整说出项目现状，交接时新人要翻十几个 markdown 文件。

架构漂移没人管

项目初期设计清晰，三个月后 import 关系和责任边界乱成一团。

多 Agent 协作像黑盒

A Agent 改了配置，B Agent 不知道，互相覆盖、测试频繁失败。

交接和审计困难

关键决策散落在聊天记录和 commit message 里。项目换人后，"为什么这么设计"变成无解之谜，重构成本极高。

How

一个 .ws 内核，
管住项目全生命周期

九层知识图谱

intent → architecture → specification ↓ ↓ ↓ implementation → quality → governance ↓ ↓ ↓ pipeline → agent → execution

每层只负责一类问题，层与层之间用关系连接。改动某一层时，PWE 能算出会影响哪些模块、测试和 Agent。

MCP 后端

44 个 MCP 工具让 Cursor、Claude Code 等 Agent 通过标准化接口读写 project.ws，而不是直接操作文件。

kernel_ops agent_coord_ops handoff_ops coord_ops

Loop Engine

六节点流水线 analyze → code → test → ticket → review → commit，每个节点有 PhaseHandoff 门禁，保证 Agent 协作有 checkpoints。

PhaseHandoff AgentBench ExternalAgentAdapter

PWE 位于 Agent 与项目资产之间，作为确定性规范层。Agent 不直接改文件，而是通过 MCP 工具读写 .ws 内核。

Loop Engine 六节点流水线

analyze
需求分析
code
代码实现
test
测试验证
ticket
问题记录
review
代码审查
commit
提交归档

每个节点之间有 PhaseHandoff 门禁，只有当前节点通过验证才能进入下一阶段，避免 Agent 一路跑偏。

.ws 知识图谱示意

project.ws 不是普通 YAML，而是 462 个实体、665 条关系组成的知识图谱。WispGraph 支持影响分析、环检测和子图提取。

多 Agent 协作不再失控

A1
Analyzer Agent
读取 kernel · 输出 spec 变更建议
A2
Coder Agent
按 spec 生成代码 · 受约束引擎拦截
A3
Tester Agent
跑 pytest · 未通过则退回 code 节点

每个 Agent 都通过 MCP 工具与 project.ws 交互，状态共享、规则统一，避免各自为战。
