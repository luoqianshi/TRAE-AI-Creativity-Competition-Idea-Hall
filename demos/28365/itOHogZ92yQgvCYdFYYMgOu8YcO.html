Problem

相机画质很好，但传到手机这一步经常不顺。

摄影用户真正痛苦的不是“不会传文件”，而是每次拍完后都要面对连接复杂、传输不稳、素材混乱、筛选耗时的问题。

🔌

连接步骤繁琐

相机菜单、手机 Wi‑Fi、蓝牙配对、官方 App 之间来回切换，用户每次收片都要重新适应流程。

🧩

品牌体验割裂

Sony、Canon、Nikon、Fujifilm 等品牌都有不同 App，连接逻辑和交互体验不统一。

🗂️

导入后仍需整理

JPG、RAW、视频混在一起，用户还要手动筛虚焦、找重复、打星标、再导入修图软件。

Features

把相机到手机的收片过程，做成一个完整体验。

CamFlow 不把重点放在“纯蓝牙传大文件”，而是采用更真实、更合理的链路：蓝牙识别，Wi‑Fi 传输，USB-C 兜底，AI 筛片。

📡

蓝牙识别相机

扫描附近 BLE 设备，识别相机品牌、型号、信号强度和连接能力。

🚀

Wi‑Fi 高速传输

照片、RAW 和视频通过 Wi‑Fi 通道传输，适合大文件导入。

💾

USB-C 兜底导入

对不开放深度协议的设备，提供读卡器或文件夹导入，保证可用性。

🧠

AI 初步筛片

识别虚焦、重复照片、曝光异常，减少用户手动初筛成本。

⭐

星标与分类

按 JPG、RAW、视频、相机型号、日期和星标状态整理素材。

📤

快速导出分享

导出到系统相册、修图软件或社交平台，缩短拍摄到发布的路径。

Workflow

用户只需要五步，就能完成一次收片。

打开 App 进入 CamFlow，点击连接相机。
识别相机 通过蓝牙扫描附近设备，展示相机列表。
连接 Wi‑Fi 支持机型自动引导，不支持机型手动引导。
导入素材 显示照片、视频数量和传输进度。
AI 筛片 完成分类、打星、虚焦与重复识别。
Technical Route

分层适配，而不是虚假承诺“支持所有设备”。

不同品牌相机的蓝牙、Wi‑Fi、USB、SDK 开放程度不同。CamFlow 的设计重点是先覆盖主流收片场景，再逐步扩展品牌深度适配。

1
BLE 设备发现层 扫描设备名、Service UUID、Manufacturer Data、RSSI，识别疑似相机。
2
设备能力库 维护品牌、机型、连接能力、是否支持自动 Wi‑Fi 联动等信息。
3
Wi‑Fi 传输通道 通过自动或手动方式连接相机 Wi‑Fi，获取素材列表和文件。
4
素材管理与 AI 本地存储、EXIF 解析、RAW/JPG/视频分类、虚焦和重复照片检测。

第一版技术栈

Android Java XML UI MVVM BLE API WifiNetworkSpecifier OkHttp Room OpenCV ML Kit

兼容策略

支持机型走“蓝牙识别 + Wi‑Fi 传输”；不支持自动联动的机型走“手动 Wi‑Fi 引导”； 不开放无线协议的设备走“USB-C / 读卡器导入”。这样既真实，也更容易落地。

MVP Plan

先做可体验闭环，再逐步接入真实相机。

MVP 0.1
Android Java 原型，模拟相机、模拟传输、模拟素材库，跑通完整流程。
MVP 0.2
接入真实 BLE 扫描，识别附近设备并筛选疑似相机。
MVP 0.3
加入 Wi‑Fi 引导和传输队列，展示连接、读取、导入过程。
MVP 0.4
加入 USB-C/读卡器导入，扫描 DCIM 目录和常见素材格式。
MVP 0.5
接入 EXIF 解析和 AI 筛片，完成更真实的摄影工作流体验。
CamFlow 的核心价值： 不是替代所有相机官方 App，而是把摄影用户最常见的“拍完后收片、整理、初筛、导出”做成更顺畅的一站式工作流。
