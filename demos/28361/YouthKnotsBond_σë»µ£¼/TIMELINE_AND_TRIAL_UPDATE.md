# 时间轴优化和免费次数调整说明

## ✅ 功能1：时间轴节点类型优化

### 节点类型说明

时间轴的节点类型是**后端自动分析**的，不需要在数据库中存储状态。系统会根据以下规则自动判断：

#### 1. 首次记录（绿色 #10B981）
**判断条件**：
- 用户的第一条记录

**显示**：绿色圆点 + "首次记录"标签

#### 2. 已好转（绿色 #10B981）
**判断条件**：
- 补充信息或核心描述中包含关键词：
  - "好了"、"解决了"、"不再"
  - "已经好"、"完全好"、"彻底好"、"痊愈"

**显示**：绿色圆点 + "已好转"标签

**优先级**：最高（优先于其他状态）

#### 3. 明显改善（紫色 #8B5CF6）
**判断条件**：
- 补充信息、核心描述或关键建议中包含关键词：
  - "好转"、"改善"、"进步"、"有效"
  - "变好"、"缓解"、"减轻"、"好多了"

**显示**：紫色圆点 + "明显改善"标签

**优先级**：第二（在"已好转"之后）

#### 4. 反复出现（橙色 #F59E0B）
**判断条件**：
- 7天内有相同标签的记录
- 至少有一个标签重复

**显示**：橙色圆点 + "反复出现"标签

**优先级**：第三

#### 5. 普通记录（蓝色 #3B82F6）
**判断条件**：
- 不符合以上任何条件

**显示**：蓝色圆点，无标签

### 用户如何标记"已好转"

用户通过以下方式标记：

1. **在卡片详情中"补充信息"**：
   - 点击卡片 → "补充信息"
   - 输入："孩子已经好了，不再发脾气了"
   - 保存后，时间轴自动显示"已好转"

2. **创建新卡片时描述**：
   - 在核心问题描述中写："孩子的情绪问题已经解决了"
   - 系统自动识别为"已好转"

## ✅ 功能2：免费次数调整（1次 → 3次）

### 修改内容

#### 1. 数据库结构
**文件**：`backend/database/schema.sql`

```sql
-- 修改前
single_remaining_count INT DEFAULT 1 COMMENT '新用户默认1次免费'
remaining_count INT DEFAULT 1 COMMENT '新用户默认1次免费'

-- 修改后
single_remaining_count INT DEFAULT 3 COMMENT '新用户默认3次免费'
remaining_count INT DEFAULT 3 COMMENT '新用户默认3次免费'
```

#### 2. 注册逻辑
**文件**：`backend/src/controllers/authController.js`

```javascript
// 修改前
INSERT INTO users (phone, single_remaining_count, is_first_time) 
VALUES (?, 1, 1)

// 修改后
INSERT INTO users (phone, single_remaining_count, is_first_time) 
VALUES (?, 3, 1)
```

#### 3. 配置文件
**文件**：`backend/src/config/aliyun.js`

```javascript
// 修改前
freeTrialCount: parseInt(process.env.FREE_TRIAL_COUNT) || 1

// 修改后
freeTrialCount: parseInt(process.env.FREE_TRIAL_COUNT) || 3
```

#### 4. 环境变量
**文件**：`backend/.env`

```bash
# 修改前
FREE_TRIAL_COUNT=1

# 修改后
FREE_TRIAL_COUNT=3
```

### 影响范围

1. **新注册用户**：
   - 注册后自动获得3次免费使用机会
   - 显示"🎁 首次免费"标签

2. **已注册用户**：
   - 不受影响
   - 保持原有次数

3. **购买页面**：
   - 套餐信息显示"首次3次免费"
