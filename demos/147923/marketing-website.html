🔄

  • 一天跑 3 个闭环算高产，瓶颈是人工迭代延迟
📊

覆盖率收敛靠调参碰运气

  • 约束随机到 85% 容易，最后 15% 藏在约束盲区里
  • 调 seed、加定向 case、翻 URG 报告猜"哪里没盖到"——没有系统方法
❓

"测够了没有"没人能回答

  • 没有量化门禁，没有可审计的验证完成度证明
  • tapeout 前突击修 bug 是行业常态，sign-off 标准靠感觉
🎯

验证意图在"翻译"中层层失真

  • SPEC 描述的是"要验证什么"，手写测台却要先把它翻译成数千行 SV/UVM 脚手架，再变成可执行激励
  • 每一次人工翻译都引入漂移：该覆盖的 corner case 漏了，该保持的协议语义偏了
Flintrix 让 AI Agent 与验证平台 直接从 SPEC 和接口生成 Rust 测台，跳过人工翻译环节； 工程师回归验证策略与 bug 分析；同时把 debug、覆盖、sign-off 全部升级为机器节拍闭环： 每一轮结果可审计、每个覆盖率空洞可定位、每个 sign-off 决策可追溯。

What is Flintrix

不是又一个脚本层，
而是下一代验证基础设施

Flintrix 是基于 Rust + VPI/VHPI 构建的验证框架，覆盖从 UT（单元级）到 CT（芯片级）的全部前仿真层级。 向上提供类型安全的异步测台 API，向下统一抽象各仿真器差异。

Rust 类型安全与异步协程赋予验证基础设施系统级可靠性。CORO–Worker–User 三域架构让激励与 DUT 严格解耦； klymora-orchestrator 将验证流程固化为确定性状态机；klymora-run 吸收各 EDA 差异， 同一套测台 Rust 零改动贯通 Verilator 到 VCS 企业 sign-off。

Features

为现代芯片验证团队打造的七大利器

01

确定性编排器 klymora-orchestrator v4.1

Rust 状态机引擎持有验证流程的"状态写路径"。workflow-full.yaml 单真源编译进二进制， 每步含 verdict、fix_skills、human_gate、resume_routing；Agent 只带当前步，无法跳过门禁。

Step-gate · Stop-reason · YAML SSOT
02

多 EDA 仿真器，一套代码全兼容

无需为每家 EDA 写分支测台。Flintrix 在框架内部吸收 Verilator、Synopsys VCS、Mentor Questa、Icarus、Cadence Xcelium 的 VPI 调度差异， 测台 Rust 零改动，切换 klymora-run --simulator 即可平移。

适合场景：开源 CI 与企业 sign-off 复用
03

CORO–Worker–User 三域架构

Flintrix 的"宪法级"激励拓扑将验证环境严格分层：User 域发事务、Worker 域做编解码与 scoreboard、Coro 域在仿真时间域精确驱采 RTL。

结果：协议激励与 DUT 严格解耦
04

Rust 异步协程驱动时序

基于 Trigger 和 Task 的调度系统，让"等一个时钟上升沿后采样 output"变成一行 await：

clk.rising_edge_ro().await?; // 采样 output
clk.rising_edge_rw().await?; // 驱动 input
05

开箱即用的 VIP 生态

VIP 覆盖协议
PCIe P-Tile Intel AVST / 683059
PCIe H-Tile Intel L-/H-Tile / 683111
PCIe US/USP Xilinx UltraScale / UltraScale+ AXI-S
AXI / AXIS AMBA 总线协议事务级激励
06

断言、覆盖率、审计闭环

Rust 并发断言持续采样 DUT；SVA 健康门禁避免断言"空转"；zooseek-coverage 聚合代码 / 功能 / 断言覆盖； 激励审计 --record 生成 trace.json，精确回放每一次 Drive / Sample / ClockEdge。

Capture Platform · 验证完整度与可追溯性
07

AI 生成 Rust 测台，工程师回归验证策略

输入 SPEC 与接口，LLM Agent 按 31 份 Skill 规程自动生成 Harness、interface.rs、tb_coro 与 scoreboard 骨架； 工程师从"手搓数千行 SystemVerilog / UVM"切换到"审阅、补充边界、验收 verdict"。 脚手架代码交给机器，人类专注真正产生价值的验证设计。

Use Cases

覆盖 UT → CT
全验证层级

自底向上逐级验证，同一套 Rust 框架、同一套 AI 工作流，从单元级穷举到芯片级 sign-off。

UT · BT

单元级与模块级验证

ALUs、FIFOs、寄存器堆等基础单元的定向与随机测试。Flintrix 的 async fn dut(SimObject) 模版与 klymora-run 秒级反馈，适合细粒度穷举。

IT

IP 核级协议验证

AXI-Stream FIFO、AXI4-Lite MMIO、PCIe TLP 等协议，通过 VIP + scoreboard + 断言三件套完成端到端数据完整性检查。Testbench 与 DUT 由 CORO–Worker 严格解耦。

ST · TT

子系统与 Tile 级集成

系统总线驱动多 IP 核协同工作，含处理器核的子系统级场景。Flintrix 的多 Fixture 与多时钟域支持，让集成验证环境水涨船高，无需另起炉灶。

CT · AI

芯片级 Sign-off 与 AI 闭环

同一套 Rust 测台在 VCS 上跑 coverage / FSDB 波形的企业 sign-off，同时在 Verilator 上跑 CI 快速门禁。AI-Native 芯片验证基础设施 自动完成部署 → 编译 → 仿真 → 诊断 → 修复 → 再验证的全闭环。
