Problem

为什么需要 A11yScan？

无障碍设计不是"锦上添花"，而是数字产品必须满足的底线。但在实际开发中，规则分散、工具门槛高，导致大量问题被带到线上。

规则复杂且分散

WCAG 2.2 有 78 条成功标准，涉及颜色对比、键盘导航、屏幕阅读器、焦点管理等，新手很难找到切入点。

报告晦涩难懂

现有工具多输出英文术语，如"aria-labelledby missing"，开发者知道报错却不知如何修改，修复链路断裂。

特殊群体被排除

中国约有 1700 万视障人士与 2.6 亿老年人。组件级缺陷会让他们无法完成购票、缴费、求职等基础操作。

Principle

检测维度覆盖 WCAG 2.2 核心标准

引擎将组件拆解为可感知、可操作、可理解、健壮性四大维度，逐项打分并定位缺陷。

可感知 Perceivable

检查文字与背景对比度、图片 alt 文本、颜色是否作为唯一信息传递方式。

可操作 Operable

验证所有交互可通过键盘完成、焦点顺序合理、交互元素尺寸足够。

可理解 Understandable

识别表单标签缺失、错误提示不明确、语言属性缺失等可理解性问题。

健壮性 Robust

保证组件在不同辅助技术下表现一致，HTML 结构合法、ARIA 属性正确使用。

1

解析 AST

将 HTML / JSX / Vue 模板解析为抽象语法树，提取标签、属性与文本节点。

2

规则匹配

对照 WCAG 2.2 与 axe-core 规则库，识别对比度、ARIA、键盘等缺陷。

3

AI 解释

将技术报错翻译为中文场景化说明，并推荐具体修改代码。

4

生成报告

输出评分、问题列表、修复示例，支持导出 Markdown / JSON。

组件级检测

支持直接粘贴 JSX、Vue、HTML 片段，无需启动完整页面，适合课程作业、组件库 review 等场景。

中文修复建议

将 "aria-label missing" 转化为 "按钮缺少屏幕阅读器名称"，并给出可直接复制的代码修改方案。

实时可视化

通过雷达图展示组件在五大维度的得分，帮助开发者快速判断应该先修复哪类问题。

教学式反馈

每条规则附带「为什么重要」「影响哪些用户」「如何验证」三段说明，让无障碍知识自然融入开发流程。
