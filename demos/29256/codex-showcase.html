问题场景

每个开发者都经历过的
三条"日常时间黑洞"

零散项目、命令行启停、端口冲突——三件小事叠加起来，就是每天十几分钟的效率流失。

项目散落在磁盘各处

前端项目在 ~/projects，Python 脚本在 ~/scripts，Docker 环境在 ~/docker。想启动一个服务，先找半天路径。

$ cd ~/projects/foo && npm run dev
$ cd ~/projects/bar && python main.py
$ cd ~/docker && docker compose up -d

端口冲突靠命令行排查

启动服务看到 "Port 5173 is already in use"，然后翻笔记查 lsof 参数，找到 PID 后又不敢随便 kill。

$ lsof -i :5173
$ kill -9 12345
# 还是报错？再查，再 kill……

配置环境变量靠经验

多个项目共享 .env 模板，却又各有差异。字段冲突、路径写错、环境变量版本混乱——全靠肉眼比对。

DB_HOST=localhost:5432 # 错了
# 应该是 127.0.0.1
# 还少了 REDIS_URL…

核心功能

八大模块覆盖开发者
本地工作的每个场景

不只是端口监控，更是项目全生命周期的可视化控制台。

01 · PROJECT SCAN

项目自动扫描

递归识别 package.json / pyproject.toml / docker-compose.yml / .env，自动建立项目清单并推导启动命令。

  • 支持 Node.js / Python / Docker Compose 三类项目类型
  • 按路径、修改时间、类型多维排序与筛选
  • 项目卡片式展示，拖拽排序
02 · PORT MONITOR

端口实时监控

通过 lsof 等系统命令实时列出本机占用端口，标注运行状态、所属进程 PID、项目路径，一眼看清全局。

  • 运行 / 冲突 / 空闲 三色状态标识
  • 冲突端口自动高亮并提示 kill 选项
  • 来源筛选：本机进程 / Docker 容器
03 · AI CONFIG

AI 辅助配置分析

把配置文件交给 AI，做字段差异对比、缺失项提醒、路径正确性校验，并生成逐项确认的修改建议。

  • 多份 .env 差异可视化对比
  • field-sources 机制防止误覆盖
  • 可撤销、可重置的修改历史
04 · ONE-CLICK CONTROL

项目一键启停

点击即可启动或停止对应项目。Node 项目调 npm，Docker 项目调 compose，不用再手写命令。

  • 按钮式启停，无需切换终端
  • 启动命令可自定义与保存
  • managed-PID 生命周期可追踪
05 · AI MODEL MGMT

AI 模型多端管理

集中管理多个 LLM 模型配置。每个模型独立保存 API Key、Base URL、模型名，一键切换 & 连接测试。

  • Key 存入系统钥匙串，不上明文
  • 连接测试 ping-pong 秒级响应
  • 支持 OpenAI 兼容协议
06 · GITHUB INTEGRATION

GitHub 仓库集成

把你的 star 仓库、复刻项目拉到本地工具里——支持 AI 简介生成、排序筛选、一键 clone 与下载。

  • Star / Fork / Watch 状态同步
  • AI 生成仓库一句话简介
  • 按语言 / 更新时间 过滤
价值与意义

效率提升看得到

作为一个开发者工具，CodeX 的价值主张不是花哨功能，而是实实在在的时间节省。

为什么现在做这个产品

开发者工具市场正在快速增长。VS Code、JetBrains 系列覆盖了编辑环节，但"本地环境管理"这一层仍然是工具链的空白地带——macOS 上最常见的解决方案还是系统原生的 Activity Monitor，以及一长串需要手动记住的命令。

CodeX 把这层体验补齐：它不是 IDE，而是"IDE 的前哨站"。每天打开电脑时它第一个启动，告诉你当前机器上跑了什么、哪些端口在冲突、哪些项目需要关注，然后让你一键进入开发状态。

从商业路径上看：当前版本面向个人开发者（免费使用、本地优先），后续可扩展为团队版——支持多机项目模板共享、端口规划策略、服务健康看板。对中小团队而言，CodeX 相当于一个轻量的本地 PaaS 控制台。
