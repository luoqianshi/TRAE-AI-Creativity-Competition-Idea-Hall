灵枢 LingShu

基于 EdgeCrab 的本地-first AI Agent：SurrealDB 向量记忆 + NNG 标准接口 + 未来自主运行

1. 创意名称 + 创意介绍

创意名称：灵枢（LingShu）

参赛赛道：硬件交互

现在的 AI Agent（如 Hermes、OpenClaw）大多是“聊天型”——你必须主动打开窗口、输入文字，它才会工作。更严重的是，它们的记忆普遍采用 SQL 或日志式存储，数据量两周就能上 G；Skill 和 Tool 多了之后只能靠关键字匹配，想找个合适的工具都费劲。

灵枢 基于 Rust 原生 Agent 框架 EdgeCrab 改造。Hermes 和 OpenClaw 虽然功能丰富，但体量臃肿、依赖多，底层很难动；EdgeCrab 用 Rust 写成，结构更紧凑，适合做大改。灵枢先把底层存储换成 SurrealDB（Rust 原生多模型数据库，支持文档、图、向量、KV），再把 NNG（nanomsg-next-generation） 做成 Agent 的标准外部接口。现在外部进程可以通过 NNG 向 Agent 发送事件、查询状态；未来通过 NNG 心跳，Agent 能自己按节奏运行，不再需要人主动打字。

产品形态：一个可部署在 PC、边缘盒子或 Android Termux 上的 Rust 原生 Agent 系统。Demo 阶段先把 NNG 接口和 SurrealDB 向量记忆跑通；向量化成熟后，再加入 Skill/Tool 语义检索，以及基于调用次数的遗忘优化机制。

3. 价值与意义

效率价值SurrealDB 向量检索让 Agent 在大量记忆和技能中快速定位，减少无效调用；Skill 调用次数记录为后续遗忘优化打下基础。
硬件交互价值NNG 标准接口把传感器、执行器、其他服务统一接入，Agent 不再只是聊天窗口，而是具备外部事件处理能力的现场智能体。
社会价值本地运行、数据不出门，适合家庭、养老、医疗辅助等隐私敏感场景。

4. 技术方案

基础平台：EdgeCrab

EdgeCrab 是 Rust 原生、单二进制、无 Python/Node 依赖的 Agent 框架。相比 Hermes 和 OpenClaw，它的结构更紧凑、依赖更少，适合做底层存储和通信层的大幅度改造。基于它改造，可以保留 ReAct 工具循环、插件系统等成熟能力，同时把存储和通信层换成自己的方案。

存储层：SurrealDB

采用 SurrealDB 作为底层存储。它是 Rust 原生多模型数据库，支持文档、图、向量、KV、时序，一套数据库就能统一存储记忆、事件、Skill、Tool 元数据和用户画像。SurrealDB 原生支持向量字段与向量索引，无需再引入额外的向量数据库。

通信层：NNG

NNG（nanomsg-next-generation）是轻量级无代理消息库，支持 pub/sub、req/rep、pair 等模式。Demo 阶段先把 NNG 做成 Agent 的标准外部接口：外部进程可以发送事件/请求，Agent 可以返回结果或下发指令。未来通过 NNG 心跳，Agent 能够主动按自己的节奏运行，自主采集外部信息、优化记忆。

唤醒机制（当前与规划）

当前 Demo 实现 NNG 事件监听接口，作为外部唤醒 Agent 的通道。收到事件后，触发一次 ReAct 循环。未来通过 NNG 心跳，让 Agent 主动运行，不再需要人主动对话。

向量化与语义检索

每个记忆、Skill 和 Tool 在写入时生成 Embedding，存储在 SurrealDB 中。Agent 在决策前，根据当前任务描述进行向量检索，召回最相关的记忆和能力。Skill 元数据同时记录调用次数，为后续基于遗忘曲线的优化机制预留数据。

5. 使用场景

  • 智能家居值守：温湿度、人体感应传感器接入 Agent，出现异常自动告警并记录上下文。
  • 长期记忆助手：运行数月后，仍能通过语义检索快速找到以前写过的脚本、配置过的 Skill。
  • 隐私优先的边缘智能：数据留在本地，适合家庭、养老、医疗辅助等场景。
  • 去中心化多 Agent 协作：多个灵枢实例通过 NNG 直接通信，无需中心服务器。
