01 / Creative Introduction

TIAN SHU（天枢）IDE——"开拓者" · 创意介绍

想解决什么问题

现有 AI 编程助手仅支持"人工逐轮提问→AI 回答"的单向交互模式，复杂工程任务需要开发者反复手动引导、检查、修正；缺少能自主规划、执行、验证并闭环的工程级智能体能力，跨文件重构、全链路调试等深度工作依然高度依赖人力。

为什么会想到做这个

北斗七星中，「天枢」又名 Dubhe，是斗柄之首、导航之星。我们以此为灵感：在开发者面对众多 AI 平台与复杂工程任务时，需要一颗能够指引方向的「天枢」——一款接入多平台 AI、双模式智能协同的 IDE。

大概是什么产品

TIAN SHU（天枢）IDE 是一款基于 VS Code 开源 + 自研 Agent 内核深度定制的桌面级智能集成开发环境，接入 DeepSeek 等多平台 AI 大模型 API，支持「普通模式」与「Loop Engineering 模式」双模式切换。内置文件读写、代码搜索、项目级全文检索、终端命令执行、代码差异对比等丰富的工具链；支持多模态视觉模型、三层记忆系统与上下文管理、技能(Skills)系统；实现代码补全、智能问答、工程重构、自动化任务等日常编码工作流，让开发者在不同任务场景下都能获得最适配的 AI 辅助体验。

02 / Target Users & Pain Points

目标用户及痛点

面向哪些用户

全栈开发者、AI 应用开发者、独立开发者与中小企业技术团队，以及需要在不同 AI 平台间灵活切换、追求编码效率最大化的各类研发人员。

在什么场景下使用

日常 IDE 编码开发、多模型对比测试与选型、复杂工程重构与深度代码审查、AI Agent 自动化工具链搭建，以及需要普通模式与 Loop Engineering 模式灵活切换的各类研发场景。

当前痛点

主流 AI 编程助手普遍绑定单一模型平台，开发者无法按任务特点自由选择最优模型；且交互模式局限于"人工逐轮提问→AI 回答"的单向对话，面对跨文件重构、全链路调试等复杂工程任务时，需要开发者反复手动引导、检查结果、修正 prompt，缺乏能自主规划、执行、验证并闭环的工程级智能体能力。

现有替代方案不足

现有方案无法在同一环境中灵活切换不同 AI 模型与工作模式，普通编码与深度工程推理之间存在断层；缺少统一的工具链集成与可扩展的技能体系，复杂任务需要人工反复介入，难以形成高效闭环。

03 / Value & Significance

价值与意义

10×

效率提升

接入 DeepSeek 等多平台 AI 大模型，开发者可按需选择最优模型完成代码补全、智能问答与工程重构；Loop Engineering 模式为复杂推理任务提供深度上下文支持。

多平台

自由切换

无需在多个 IDE 或插件间切换，一个界面即可调用不同 AI 平台能力；普通模式满足日常编码，Loop Engineering 模式应对复杂工程，双模式协同提升开发效率。

∞

开放生态

基于 VS Code 开源生态 + 自研 Agent 内核，内置 AI 多平台对话功能开箱即用；支持持续扩展接入更多 AI 平台与工具链，为开发者社区提供可持续演进的智能 IDE 底座。
