📐 宏定义与条件编译

预处理指令 —— 编译器最先看到你的代码时，会做什么？

🎯 生活类比：印刷厂的模板

想象你要印一万份传单，上面都要写"联系电话：138-0000-0000"。你不会手写一万次，而是做一个模板，印刷机器自动把每个占位符替换成实际内容。

C 语言的 #define 就是这个"模板"机制。编译器在真正编译代码之前，会先把所有宏名替换成你定义的值。这个过程叫做预处理（Preprocessing）。

你的 DHT11 驱动里就有大量这种用法——比如 DHT11_DQ_OUT(1) 在编译前就被替换成了 GPIO_WriteBit(GPIOA, GPIO_Pin_0, (BitAction)(1))。

C 编译的四个阶段

编译流水线 — 点击播放动画
1
预处理（Preprocessing）

处理所有 # 开头的指令：展开 #include "dht11.h"，替换 DHT11_DQ_OUT 等宏，处理 #ifdef 条件编译。

2
编译（Compilation）

把预处理后的 C 代码翻译成汇编语言。这一步做语法检查、优化。

3
汇编（Assembly）

把汇编语言翻译成ARM 机器码（目标文件 .o）。STM32 就是 ARM Cortex-M3 架构。

4
链接（Linking）

把 main.o、led.o、dht11.o、usart.o 等所有目标文件和 STM32 标准外设库拼接，生成最终烧录到 Flash 的 .hex 文件。

入门基础

1. 什么是宏定义？

💬 生活类比：微信快捷回复

你每天发微信给10个朋友说"明天下午3点图书馆门口见"。嫌累？你可以设个快捷回复"暗号"，发"暗号"就自动变成那句话。#define 就是这个"暗号"。

C
#include <stdio.h>

#define PI 3.14159          // 定义宏 PI，编译器会把它替换成 3.14159
#define MAX 100             // 定义宏 MAX，编译器会把它替换成 100

int main(void)
{
    double r = 5.0;                // 定义半径 r 并赋值 5.0
    double area = PI * r * r;      // 编译器替换为: 3.14159 * 5.0 * 5.0
    int arr[MAX];                  // 编译器替换为: int arr[100];

    printf("area = %f\n", area);   // 输出: area = 78.539750
    printf("MAX = %d\n", MAX);     // 输出: MAX = 100

    return 0;
}
💡
核心要点：替换发生在编译前，就像 Word 的查找替换。编译器在真正编译之前，会先把所有 PI 替换成 3.14159，把所有 MAX 替换成 100。

2. 带参数的宏

C
#include <stdio.h>

#define MAX(a, b)  ((a) > (b) ? (a) : (b))  // 带参数的宏：取两个数中较大的

int main(void)
{
    int bigger = MAX(3, 7);       // 编译器替换为: ((3) > (7) ? (3) : (7))
    printf("MAX(3, 7) = %d\n", bigger);  // 输出: MAX(3, 7) = 7

    int score = 45;                // 定义成绩变量
    int result = MAX(score, 60);   // 编译器替换为: ((45) > (60) ? (45) : (60))
    printf("MAX(45, 60) = %d\n", result);  // 输出: MAX(45, 60) = 60

    return 0;
}
⚠️
小心副作用！MAX(i++, j) 会让 i 被加两次！因为宏展开后变成 ((i++) > (j) ? (i++) : (j))，i++ 出现了两次。这就是为什么宏不能代替函数——函数参数只求值一次。

3. #include 就是"复制粘贴"

#include <stdio.h> 的意思：把 stdio.h 文件的全部内容复制粘贴到这里。预处理完成后，你的 .c 文件会变长很多——因为头文件的内容都被"塞"进来了。比如你写 printf()，必须先 include stdio.h，否则编译器不认识 printf。

📋
两种 include 的区别：
#include "my.h" — 双引号：先在你项目文件夹找，找不到再去系统目录
#include <my.h> — 尖括号：直接在系统目录找

所以自己写的头文件用双引号，标准库头文件用尖括号。

4. #ifndef — 防止"复制"两次

如果 led.h 被两个 .c 文件都 include 了，LED_INFO 就被定义了两次 → 编译报错！

💬 生活类比

就像你的作业本上写了名字。如果同一页写两次名字，老师会觉得奇怪。#ifndef 就是"看看有没有写过了，没有才写"。

C
// ===== my_header.h（头文件示例）=====
#ifndef MY_HEADER    // 第1步：检查 MY_HEADER 有没有被定义过
#define MY_HEADER    // 第2步：没定义过 → 现在定义它（做个标记，下次就不进了）

int x = 10;          // 第3步：这些内容会被编译
int y = 20;

#endif               // 第4步：结束条件编译

// 如果别的文件也 #include "my_header.h"
// 第2次进来时，MY_HEADER 已经定义了 → #ifndef 为假 → 跳过全部内容
// 这样就防止了 x、y 被重复定义导致编译报错！

5. #ifdef — 条件开关

C
#include <stdio.h>

#define DEBUG              // 打开调试开关（注释掉这行 = 关闭调试）

int main(void)
{
    int x = 42;                   // 定义一个变量

#ifdef DEBUG
    printf("[调试] x = %d\n", x);  // 有 #define DEBUG → 这行会被编译
#else
    // 没有 #define DEBUG → 调试代码消失，正式发布用
#endif

    printf("程序正常运行\n");       // 这行始终会被编译

    return 0;
}
// 输出（有 #define DEBUG 时）:
// [调试] x = 42
// 程序正常运行
💡
小贴士：只需要删掉 #define DEBUG 那一行，所有被 #ifdef DEBUG 包裹的调试代码就会自动消失。不用一行一行去删调试语句——这就是条件编译的威力！

1.2 带参数的宏 —— 来自你的 dht11.h

带参宏的展开过程 —— 你的 DHT11 真实代码
#define DHT11_DQ_OUT(x) GPIO_WriteBit(DHT11_PORT, DHT11_PIN, (BitAction)(x))
DHT11_DQ_OUT(1);  // 拉高数据线
⬇ 文本替换（两次：宏参数 + 宏名）
GPIO_WriteBit(GPIOA, GPIO_Pin_0, (BitAction)(1));
C — 你的 dht11.h 中的宏
// DHT11 切换 IO 方向的宏 —— do{}while(0) 技巧
#define DHT11_IO_IN()   do{ GPIOA->CRL &= 0xFFFFFFF0; GPIOA->CRL |= 0x8; }while(0)
#define DHT11_IO_OUT()  do{ GPIOA->CRL &= 0xFFFFFFF0; GPIOA->CRL |= 0x3; }while(0)

// 读写数据线的宏
#define DHT11_DQ_OUT(x) GPIO_WriteBit(DHT11_PORT, DHT11_PIN, (BitAction)(x))
#define DHT11_DQ_IN     GPIO_ReadInputDataBit(DHT11_PORT, DHT11_PIN)
⚠️
do{...}while(0) 是什么？
这是嵌入式宏编程的经典技巧！DHT11_IO_IN() 包含两条语句（先清零位再写入），如果不用 do-while 包裹，在 if-else 中展开就会语法错误。do-while(0) 让多行宏表现得像一个完整的语句块。

1.3 寄存器位操作宏 —— 嵌入式必备

C — 嵌入式通用位操作宏
#define SET_BIT(REG, BIT)     ((REG) |= (BIT))
#define CLEAR_BIT(REG, BIT)   ((REG) &= ~(BIT))
#define TOGGLE_BIT(REG, BIT)  ((REG) ^= (BIT))

// 直接操作 STM32 寄存器
SET_BIT(GPIOA->ODR, GPIO_Pin_5);     // PA5 输出高
CLEAR_BIT(GPIOA->ODR, GPIO_Pin_5);   // PA5 输出低
TOGGLE_BIT(GPIOC->ODR, GPIO_Pin_13);  // PC13(LED)翻转

🎯 不同硬件版本用同一套代码

入门基础

1. 为什么要分文件？

💬 生活类比

想象一本500页的说明书全写在一页纸上——翻都翻不动。把每个功能分成单独的一页，找起来快，修改也方便。代码也一样。

你写了一个小游戏，所有代码放在 main.c 里——3000 行！想改一下角色移动速度？在3000行里找吧。把角色移动的代码分到 player.c，修改就方便多了。

2. 最简单的分文件示例

C — greet.h（说明书）
// ===== greet.h（说明书）=====
#ifndef GREET_H
#define GREET_H
void say_hello(void);    // 声明：有一个函数叫 say_hello
void say_bye(void);      // 声明：有一个函数叫 say_bye
#endif
C — greet.c（实现）
// ===== greet.c（实现）=====
#include <stdio.h>
#include "greet.h"       // 包含自己的头文件

void say_hello(void) {   // 实现：具体怎么做
    printf("你好！欢迎学C语言！\n");  // 输出: 你好！欢迎学C语言！
}
void say_bye(void) {
    printf("再见，下次见！\n");      // 输出: 再见，下次见！
}
C — main.c（使用）
// ===== main.c（使用）=====
#include <stdio.h>
#include "greet.h"       // 只需要包含 .h（说明书）

int main(void)
{
    say_hello();         // 直接调用，不用知道怎么实现的
    say_bye();           // 直接调用

    return 0;
}
// 输出:
// 你好！欢迎学C语言！
// 再见，下次见！
💡
关键点：main.c 只需要包含 greet.h（说明书），就知道 say_hello() 和 say_bye() 怎么用。不需要看 greet.c（实现细节）！这就是"接口"和"实现"分离的好处。

3. #include 到底干了什么？

#include "greet.h" 就是把 greet.h 的全部内容复制粘贴到这个位置。预处理后，main.c 里就有了 say_hello 和 say_bye 的声明，编译器就知道这两个函数存在了。

#include 前 vs 后
预处理前 main.c 里的代码：
#include "greet.h"
int main(void) { say_hello(); }
⬇ 预处理器把 greet.h 内容粘贴进来
预处理后编译器看到的：
void say_hello(void); ← 从 greet.h 粘贴来的
void say_bye(void); ← 从 greet.h 粘贴来的
int main(void) { say_hello(); }

4. static 和 extern

static：这个变量/函数只在本文件能用——"私有"的。
extern：这个变量在别的文件定义，我借来用——"共享"的。

C — counter.c
// ===== counter.c =====
static int count = 0;    // static：只有本文件能访问这个变量

void add_one(void)       // 每次调用，count 加 1
{
    count++;
}

int get_count(void)      // 外部只能通过这个函数读取 count
{
    return count;
}
C — main.c
// ===== main.c =====
#include <stdio.h>

extern void add_one(void);     // 声明：这个函数在 counter.c 里定义
extern int get_count(void);    // 声明：这个函数在 counter.c 里定义
// extern int count;            // ❌ 不行！count 是 static 的，外部不能访问

int main(void)
{
    add_one();                          // count 变成 1
    add_one();                          // count 变成 2
    add_one();                          // count 变成 3
    printf("count = %d\n", get_count()); // 输出: count = 3

    return 0;
}
📋
记忆方法：
static = "私房钱"，只有自己花得到
extern = "借朋友的钱"，声明一下"我知道别处有这笔钱，我要用"

#endif

📄 led.c（厨房）

C — hardware/src/led.c
#include "stm32f10x.h"
#include "led.h"

static uint8_t last_led_status = LED_OFF; // 内部变量，外部看不到
LED_INFO led_info = {0};

void Led_Init(void) {
    GPIO_InitTypeDef GPIO_InitStructure;
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOC, ENABLE);
    GPIO_InitStructure.GPIO_Pin   = GPIO_Pin_13;
    GPIO_InitStructure.GPIO_Mode  = GPIO_Mode_Out_PP;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOC, &GPIO_InitStructure);
    Led_Set(LED_OFF);
}

void Led_Set(_Bool status) {
    GPIO_WriteBit(GPIOC, GPIO_Pin_13,
                   status == LED_ON ? Bit_RESET : Bit_SET);
    led_info.Led_Status = status;
}
.h 是"菜单"，.c 是"厨房"

→ 使用者只看这个文件就够了

📄 led.c（厨房）

1. 使能 GPIOC 时钟
2. 配置 PC13 推挽输出
3. GPIO_WriteBit 控制电平
4. static 记录上次状态
→ 使用者不需要知道这些细节

三、蜂鸣器 BUZZER —— 另一个完整模块

// ===== BUZZER.h =====
#ifndef __BUZZER_H
#define __BUZZER_H
#define BUZZER_GPIO_PORT  GPIOB
#define BUZZER_GPIO_PIN   GPIO_Pin_12
typedef struct { _Bool Buzzer_Status; } BUZZER_INFO;

void Buzzer_Set(_Bool status);
void Buzzer_Turn(void);   // 翻转
#endif

// ===== BUZZER.c =====
static _Bool last_buzzer_status = 0; // 内部隐藏
void Buzzer_Set(_Bool status) {
    if (status) GPIO_ResetBits(GPIOB, GPIO_Pin_12); // 低电平响
    else        GPIO_SetBits(GPIOB, GPIO_Pin_12);   // 高电平停
    buzzer_info.Buzzer_Status = status;
}

入门基础

1. struct — 把相关数据打包

💬 生活类比：快递单

你填一张快递单：姓名、电话、地址——这三样东西是一体的，都属于"这张快递单"。struct 就是把相关数据打包成一个整体。

C
#include <stdio.h>
#include <string.h>    // strcpy 需要这个头文件

struct Student {
    char name[20];    // 姓名（最多19个字符 + 结束符）
    int age;          // 年龄
    float score;      // 成绩
};

int main(void)
{
    struct Student s1;             // 创建一个学生变量
    strcpy(s1.name, "小明");       // 设置姓名（字符串必须用 strcpy）
    s1.age = 17;                   // 设置年龄
    s1.score = 95.5;              // 设置成绩

    printf("%s, %d岁, 成绩%.1f\n", s1.name, s1.age, s1.score);
    // 输出: 小明, 17岁, 成绩95.5

    return 0;
}

struct 也可以定义数组：

C
#include <stdio.h>
#include <string.h>

struct Student {
    char name[20];
    int age;
    float score;
};

int main(void)
{
    struct Student class1[3];     // 定义3个学生的数组

    strcpy(class1[0].name, "小明");
    class1[0].age = 16;            // 第1个学生，16岁
    class1[0].score = 92.0;        // 成绩 92.0

    strcpy(class1[1].name, "小红");
    class1[1].age = 17;            // 第2个学生，17岁
    class1[1].score = 88.0;        // 成绩 88.0

    printf("%s, %d岁, %.1f分\n", class1[0].name, class1[0].age, class1[0].score);
    printf("%s, %d岁, %.1f分\n", class1[1].name, class1[1].age, class1[1].score);
    // 输出:
    // 小明, 16岁, 92.0分
    // 小红, 17岁, 88.0分

    return 0;
}

2. enum — 给选项编号

💬 生活类比：红绿灯

红绿灯有3种状态：红、黄、绿。你当然可以用 0/1/2 表示，但代码里看到 if(light == 0) 谁知道是什么意思？用 enum 就有名字了。

C
#include <stdio.h>

enum Color { RED, YELLOW, GREEN };  // 自动编号: RED=0, YELLOW=1, GREEN=2

int main(void)
{
    enum Color light = RED;          // 当前是红灯

    printf("RED = %d\n", RED);       // 输出: RED = 0
    printf("YELLOW = %d\n", YELLOW); // 输出: YELLOW = 1
    printf("GREEN = %d\n", GREEN);   // 输出: GREEN = 2

    if (light == RED) {
        printf("红灯停！\n");          // 输出: 红灯停！
    }

    return 0;
}

也可以自定义起始编号：

C
#include <stdio.h>

enum Weekday { MON=1, TUE, WED, THU, FRI, SAT, SUN };  // 从1开始编号

int main(void)
{
    enum Weekday today = WED;     // 今天是周三

    printf("today = %d\n", today);  // 输出: today = 3

    if (today == SAT || today == SUN) {
        printf("周末！\n");
    } else {
        printf("工作日，加油！\n");  // 输出: 工作日，加油！
    }

    return 0;
}

3. typedef — 给类型取别名

💬 生活类比

unsigned long long 太长了，每次写都像绕口令。typedef 就是给它取个短名字。

C
#include <stdio.h>

// 用 typedef 给类型取短名字
typedef unsigned long long uint64;   // 以后写 uint64 就等于 unsigned long long

int main(void)
{
    // 没有 typedef：又长又难读
    unsigned long long money1 = 1000000;

    // 有了 typedef：简洁明了
    uint64 money2 = 2000000;          // 短多了！

    printf("money1 = %llu\n", money1); // 输出: money1 = 1000000
    printf("money2 = %llu\n", money2); // 输出: money2 = 2000000

    return 0;
}

最常用的写法——把 struct 和 typedef 合在一起：

C
#include <stdio.h>
#include <string.h>

// 一步到位：定义结构体 + 取别名（最常用的写法！）
typedef struct {
    char name[20];     // 姓名
    int age;           // 年龄
    float score;       // 成绩
} Student;              // Student = 这个结构体的别名

int main(void)
{
    Student s1;                       // 直接用 Student，不用写 struct
    strcpy(s1.name, "小红");
    s1.age = 18;
    s1.score = 99.0;

    printf("%s, %d岁, 成绩%.1f\n", s1.name, s1.age, s1.score);
    // 输出: 小红, 18岁, 成绩99.0

    return 0;
}
💡
小结：struct 打包数据，enum 给选项起名字，typedef 给类型取短名。三者经常组合使用，你在 STM32 项目中会大量遇到！

📖 入门基础

入门基础

1. 函数指针 — 函数也能当变量？

你学过 int x = 10; — x 是变量名，10 是值。那函数呢？函数在内存里也有地址！函数指针就是存这个地址的变量。

C
#include <stdio.h>

int add(int a, int b) { return a + b; }  // 加法函数
int sub(int a, int b) { return a - b; }  // 减法函数

int main(void)
{
    int (*fp)(int, int);   // 声明函数指针 fp：能指向"两个int参数、返回int"的函数

    fp = add;              // fp 指向 add 函数的地址
    printf("fp(3, 5) = %d\n", fp(3, 5));  // 输出: fp(3, 5) = 8（调用 add）

    fp = sub;              // fp 改为指向 sub 函数
    printf("fp(3, 5) = %d\n", fp(3, 5));  // 输出: fp(3, 5) = -2（调用 sub）

    return 0;
}
函数指针在内存中指向谁？
函数名
地址
内存中
add()
0x0800_1234
sub()
0x0800_1278

fp = add; → fp 存的是 0x0800_1234   |   fp = sub; → fp 存的是 0x0800_1278

2. 把函数当参数传递

普通参数传递：把数字传给函数。函数指针传递：把函数传给函数！

C
#include <stdio.h>

int add(int a, int b) { return a + b; }  // 加法
int sub(int a, int b) { return a - b; }  // 减法

// 通用计算器：第3个参数是函数指针！把函数当参数传进来
int calculate(int a, int b, int (*op)(int, int)) {
    return op(a, b);   // 用你传进来的函数去做计算
}

int main(void)
{
    printf("10 + 3 = %d\n", calculate(10, 3, add));  // 输出: 10 + 3 = 13
    printf("10 - 3 = %d\n", calculate(10, 3, sub));  // 输出: 10 - 3 = 7
    // 同一个 calculate，换不同的"操作函数"，得到不同结果！

    return 0;
}
💡
这就是"多态"的雏形！同一个函数框架，因为传入的"操作函数"不同，表现出不同的行为。就像同一个快递柜，注册不同的手机号，通知不同的人。

3. 回调函数 — "你帮我做事，我通知你"

💬 生活类比：快递柜

你在快递柜注册了手机号。包裹到了 → 快递柜自动发短信给你。快递柜不需要知道你收到短信后干什么——它只负责"通知"。你注册的手机号就是"回调"。

C
#include <stdio.h>

// "快递柜"框架函数：接收一个回调函数作为参数
void on_package_arrived(void (*notify)(void)) {
    printf("包裹已到达！\n");
    notify();   // 这就是回调：调用你传进来的函数
}

// 你写的"收到通知后的动作"（回调函数）
void send_sms(void) { printf("发短信通知主人\n"); }
void ring_bell(void) { printf("按门铃提醒\n"); }

int main(void)
{
    // 同一个框架，传不同的回调函数 → 不同行为
    on_package_arrived(send_sms);   // 包裹到 → 发短信
    // 输出: 包裹已到达！
    //       发短信通知主人

    on_package_arrived(ring_bell);  // 包裹到 → 按门铃
    // 输出: 包裹已到达！
    //       按门铃提醒

    return 0;
}

4. typedef 让函数指针更好读

C
#include <stdio.h>

// 用 typedef 给函数指针类型取个短名字
typedef void (*Handler)(int);  // Handler = "接收int、返回void的函数指针"

// 没有 typedef：看得头晕
// void process(int val, void (*handler)(int));

// 有了 typedef：清清楚楚
void process(int val, Handler handler) {
    handler(val);  // 调用回调函数
}

// 回调函数：打印结果
void print_result(int val) {
    printf("结果 = %d\n", val);
}

int main(void)
{
    process(42, print_result);  // 把 print_result 当参数传给 process
    // 输出: 结果 = 42

    return 0;
}
📋
typedef 给函数指针类型取了个名字叫 Handler。以后写代码时，只要看到 Handler，就知道它代表"一个接收 int、返回 void 的函数指针"。读代码的人一看就懂！

2.1 你的 key.c —— 按键中断回调

C — hardware/src/key.c（真实代码）
// 硬件触发 EXTI1 中断时，系统自动调用这个函数
// 这就是"回调"——不是你调用的，是硬件调用的
void EXTI1_IRQHandler(void) {
    static uint32_t last_tick = 0;
    uint32_t now = millis();

    if (now - last_tick > 20) {  // 软件消抖 20ms
        last_tick = now;
        key1_event = 1;         // 设标志位，主循环处理
    }
    EXTI_ClearITPendingBit(EXTI_Line1);
}
📋
为什么叫"回调"？ 名字在 startup_stm32f10x_hd.s 启动文件里预定义好了。你写同名函数，链接器自动"挂"到中断向量表上。硬件中断触发时 CPU 自动跳转。不是你调用它，是系统在"回调"它。

三、自己写回调 —— 传感器策略

C — 回调实战
// 回调1：光控模式
void light_control(uint16_t lux) {
    if (lux > 350)      Led_Set(LED_OFF);
    else if (lux < 180) Led_Set(LED_ON);
}

// 回调2：报警模式
void alarm_control(uint16_t value) {
    Buzzer_Set(value > 300);
}

// 通用框架 —— 通过回调实现不同策略
void sensor_monitor(uint16_t val, void (*handler)(uint16_t)) {
    handler(val);  // ← 调用回调
}

// typedef 让回调类型更清晰
typedef void (*SensorHandler)(uint16_t);
void sensor_monitor(uint16_t val, SensorHandler handler) { handler(val); }

// 同一框架，不同行为：
sensor_monitor(lux, light_control);  // 光控
sensor_monitor(lux, alarm_control);  // 报警
