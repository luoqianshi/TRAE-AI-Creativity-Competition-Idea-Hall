CamTalk · 多模态实时 AI 视觉对话助手

用摄像头「看到」世界，用麦克风「说出」问题，用 AI 实时「想明白」并「说出来」——一个零门槛的浏览器多模态助手，端到端感知延迟 < 0.5 秒。

React + TypeScript Go + WebSocket VAD · 关键帧 STT · LLM · TTS 流式 通义 qwen-vl

痛点

  • 传统图像识别要：拍照 → 上传 → 切换 App → 等结果，链路割裂。
  • 视障人群无法主动获取环境信息。
  • 多轮对话中 AI 容易「忘了」摄像头画面，体验生硬。
  • 外文菜单、路牌、文献无法被即时「读出来」。

用户与场景

  • 视障辅助：实时环境描述与障碍物提醒。
  • 学生/研究者：识别实物、读外文资料、实验操作指引。
  • 旅行者：菜单、路牌、商品外文翻译。
  • 日常办公：屏幕、文档、票据的快速问答。

系统架构

[浏览器]  摄像头 + 麦克风
   │   VAD 检测人声起止
   │   关键帧检测：画面稳定 / 变化触发
   ▼
[WebSocket /media]
   ▼
[Go 网关]  session · orchestrator · store
   │   按 turn 串行：STT → 多模态 LLM → TTS
   │   LLM 文本流 + TTS 音频流 并行回推
   ▼
[云端 AI]  MiMo/Deepgram STT · qwen3-vl-plus · MiMo/OpenAI TTS

核心链路

1. 采集MediaStream 拉取摄像头与麦克风
→
2. 边端预处理VAD 判定人声起止，关键帧触发
→
3. STT语音转写，识别率 > 95%
→
4. 多模态 LLM图像 + 文本联合推理，文本流式回推
→
5. TTS语音合成，首包延迟 < 1s
→
6. 播放文本与音频并行呈现，感知延迟 < 0.5s

关键创新

  • 边端预处理：浏览器侧 VAD + 关键帧检测，只在「值得看 / 值得听」时唤醒云端。
  • 双流并行：LLM 文本流与 TTS 音频流并行推送，先字后声，体感接近真人对话。
  • 多模态上下文：每一轮把当前帧与会话记忆拼入 LLM，AI 始终「记得刚看到的画面」。
  • 国产化链路：默认 MiMo ASR/TTS + qwen-vl，数据与算力自主可控。

已落地的体验

  • 对着镜头问「这是什么花」，AI 文字 + 语音回答。
  • 读外文菜单 / 路牌并翻译。
  • 多轮连续对话（上下文 > 10 轮）。
  • 观察模式：AI 主动发现画面变化并提醒。
  • 视频框可拖动、可最小化，不挡视线。

价值与意义

< 3s端到端响应
< 0.5s感知延迟
> 95%STT 准确率
10+连续对话轮数
  • 效率提升：把「看 + 说 + 答」压到一次交互，比传统拍照搜索减少约 70% 等待时间。
  • 社会价值：为视障人群提供低成本的「AI 之眼」，推动 AI 无障碍应用落地。
  • 商业价值：可作为电商、教育、跨境旅行场景的实时视觉问答 SDK 复用。
