今天穿什么？

地点 · 天气 · 场景 · 你的衣橱，AI 帮你搭

旅行 通勤 约会 逛街 遛宠

一、产品定位

一句话定位：基于地点、天气、场合，用大模型把"你已有的衣服"搭出得体造型，并用饰品切换风格、给宠物配同款调性。

差异化：不靠商品库硬推，而是优先消耗用户自有衣橱，把"没衣服穿"变成"不会搭"；饰品与宠物搭配作为风格延展，而非独立工具。

三、三大核心功能模块

1. 服装搭配（主模块）

  • 输入：地点 + 场合类型 + 自动拉取当日天气
  • 逻辑：优先用衣橱组合；缺口单品从商品库补齐并标注"建议补购"
  • 输出：整套预览 + 单品来源标签 + 穿搭理由
  • 交互：换一换 / 锁定单品重搭

2. 饰品搭配（风格切换器）

  • 定位：同一套服装，用饰品切换风格调性
  • 交互：风格滑块拖动实时替换饰品
  • 价值：不换衣服也能改气质

3. 宠物搭配（风格跟随）

  • 输入：宠物档案 + 主人本次整体风格
  • 逻辑：AI 生成与主人呼应的宠物 look
  • 输出：主人 + 宠物同框预览

四、关键用户流程

首次启动：风格问卷 + 长相/体型照片 → 生成「风格基因」→ 拍照录入衣橱 → (可选)添加宠物档案 日常搭配：选场景(地点/场合) → 自动拉天气 → AI 生成方案 → 预览/换一换 → 锁定保存 饰品换风格：在方案页拖「风格滑块」 → AI 重配饰品 → A/B 对比 → 确认 宠物搭配：主人方案确定 → 一键生成宠物 look → 微调 → 同框分享

六、AI 推荐逻辑设计（大模型接入）

采用「结构化输入 → LLM → JSON 输出」模式，便于前端渲染与单品溯源。

角色：资深造型师 + 宠物造型顾问 输入： 场景 = { 地点, 场合类型, 天气:{温度,降水,风力,紫外线} } 用户画像 = { 性别, 风格基因, 肤色色调, 体型特征, 偏好禁忌 } 衣橱 = [{ 单品ID, 类目, 颜色, 材质, 风格标签, 季节, 图样 }] 商品库 = { 缺口单品候选 } 宠物 = { 种类, 体型, 毛色, 主人本次风格 } 任务： 1. 优先用衣橱单品组合 1-2 套适配场景的方案 2. 缺口从商品库补齐，标注"建议补购" 3. 每套配 2-3 件饰品，说明如何切换风格调性 4. 输出与主人风格呼应的宠物 look 输出(JSON)： { outfits:[...], accessories:[...], pet_look:{...}, missing_items:[...] } 约束：每件单品标注来源(衣橱/商品) + 穿搭理由(温度/场合/风格)

工程要点：衣橱单品先做向量化标签（类目/颜色/风格/季节），检索阶段先粗筛候选池再送 LLM 组合，控制 token 成本。

七、数据模型（核心实体）

  • User：风格基因、肤色色调、体型、偏好禁忌
  • WardrobeItem：单品图、类目、颜色、材质、风格标签、季节、穿搭次数
  • Product：商品信息、风格标签、价格、购买链接
  • Pet：种类、体型、毛色
  • OutfitPlan：方案快照、场景、天气、单品列表、来源标记、生成时间
  • LookHistory：历史搭配、反馈（喜欢/不喜欢）→ 反哺推荐

八、界面设计要点

  • 大图预览优先：方案页以整身 look 大图为主
  • 来源徽章：每件单品角标「我的 / 补购」
  • 场景徽章：顶部显示温度、场合、风格基因
  • 风格滑块：饰品模块核心控件
  • 换一换 + 锁定：降低退出率
  • 同框分享：主人+宠物合成图

九、主页多巴胺风格设计 重点

风格定位：高饱和、明快、有活力，一眼提情绪——和多巴胺穿搭理念一致。

主色调高饱和撞色块（亮黄、糖果粉、电光蓝、薄荷绿）
顶部 hero渐变撞色 + 大字"今天穿什么？" + 场景胶囊按钮
推荐卡片白底 + 彩色描边/角标，单品图保持原色
图标插画圆润粗线条 + 纯色填充
动效卡片弹跳进场、按钮按压回弹
留白色块之间留白底，避免撞色疲劳
注意：多巴胺只用于主页氛围层；搭配方案预览页保持中性背景（白/浅灰），让服装本身的颜色成为主角，不被界面色彩干扰判断。
