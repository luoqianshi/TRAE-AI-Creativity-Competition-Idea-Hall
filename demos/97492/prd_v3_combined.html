一、产品概述

产品定位

青少年AI全栈科普实训平台是一款面向8-16岁青少年的Web端互动学习产品，以"问题驱动 + 游戏化实训"为核心教学方法论，系统性地覆盖AI技术从基础概念到前沿应用的完整知识链路。

不同于传统的视频课程或图文教程，本产品将每一个AI核心概念转化为可操作的互动游戏，让学生在"玩"的过程中自然理解AI的工作原理、能力边界和实际应用场景。

维度说明
目标用户8-16岁青少年（小学中高年级 ~ 高中一年级），具备基本电脑操作能力和中文阅读能力
产品形态纯前端Web应用（可选后端接口对接AI API），支持PC浏览器与平板浏览器
课程结构6个阶段 · 12课时 · 每课时2-3个互动游戏 · 共约40+游戏模块
核心价值让孩子不只是AI的使用者，而是真正理解AI为什么能做到、哪里做不到
教学理念问题驱动 → 痛点体验 → 游戏化学习 → 反馈闭环 → 真实AI揭秘
核心差异化

市面上的少儿编程/AI课程大多停留在"教孩子用AI工具"的层面。本产品的核心差异在于：每个知识点都从一个真实问题出发，先让学生体验"没有这个技术会怎样"的痛点，再通过游戏化互动理解技术原理，最后用"真实AI揭秘"动画将游戏与真实AI技术对应起来。

三、游戏化设计原则

本产品的每个游戏模块都严格遵循以下五大设计原则，确保游戏不仅仅是"好玩"，而是真正服务于学习目标。

1

问题驱动：游戏是真实问题的抽象

每个游戏的起点是一个真实存在的问题，而不是为了做游戏而做游戏。例如："AI看不懂文字"是真实问题，"Token积木拼句"游戏就是对这个问题的抽象模拟。学生在游戏中解决的问题，正是AI工程师在现实中需要解决的问题（只是简化了）。

2

痛点先行：先体验没有这个能力的后果

在引入新概念之前，先让学生体验到缺少这个能力时的困难。例如：在教Token之前，先让学生尝试"直接告诉AI一整段中文"，看到AI完全理解错误；然后再引入Token概念，学生会自然地感受到"原来Token就是为了这个问题而生的"。

3

循序渐进：每节课至少3个游戏，认知递进

每节课包含至少3个游戏，按认知难度递进排列：感知层（感受现象）→ 理解层（理解原理）→ 应用层（解决变体问题）。不同游戏针对不同的知识点，避免重复，确保每个游戏都有新的认知增量。

4

反馈闭环：做对做错都有即时反馈

每次操作后立即给出反馈。正确时：视觉奖励 + 积分 + 简短肯定语。错误时：不是简单的"错了"，而是解释为什么错，引导学生思考正确方向。反馈文案使用对话式语言，避免说教感。所有反馈都与当前游戏的知识点紧密关联。

5

真实AI揭秘：游戏后用动画展示AI真实工作原理

每个游戏结束后，播放一段"真实AI揭秘"动画，将游戏中的操作与真实AI技术对应起来。例如：玩完"Token积木拼句"后，动画展示真正的AI Tokenizer如何将文字切分为Token并分配编号。这一步是关键的认知桥梁，确保学生理解"我刚才玩的游戏，在真实的AI中是这样工作的"。

设计红线

以下情况视为设计不合格，需要返工：

  • 游戏无法对应一个真实问题（纯娱乐化）
  • 缺少痛点体验环节（直接讲概念）
  • 错误反馈只有"错了"没有解释
  • 缺少"真实AI揭秘"环节
  • 一节课游戏数量不足3个

阶段一 认识AI（2课时）

阶段目标

让学生建立对AI的初步认知框架：AI已经无处不在、AI有特定的核心能力、AI也有明确的能力边界。同时引入Token概念——AI处理文字的基本方式，为后续阶段打下基础。

1.1 生活中的AI：AI能做什么

概念定义

AI已经渗透到我们日常生活的方方面面，但大多数人不自觉。从手机里的语音助手、视频平台的推荐算法，到地图导航的路线规划、购物网站的商品推荐——AI已经在无声地影响着每个人的决策和生活体验。

学习目标

  • 能识别生活中哪些功能由AI驱动，建立"AI无处不在"的认知
  • 区分AI与传统程序的本质差异：AI能"从数据中学习"，传统程序只"执行固定规则"
  • 理解AI的核心能力分类（看、听、说、想、做），并认识其能力边界

学习方法

体验 + 分类：先让学生感受AI的存在，再通过分类和判断游戏归纳AI的核心能力，最后通过边界判断建立准确认知。

呈现形式

方案A："AI大搜查"拖拽分类墙

  • 20张生活场景卡片拖拽分类到"AI驱动"和"不是AI"两个区域
  • 正确：卡片发光 + 音效；错误：弹回 + 提示"再想想，这个功能需要'学习'吗？"

感知层
真实问题

人们经常把自动化和AI混淆。例如：计算器是自动化（只执行固定公式），推荐算法才是AI（能从用户行为中学习）。更常见的是，很多人认为"所有电脑程序都是AI"，这导致对AI能力的严重误判——要么高估（以为什么都能做），要么低估（以为什么都不能做）。

痛点体验

不做分类时，学生会以为"计算器也是AI"、"红绿灯自动控制也是AI"——因为"都是电脑在做事"。这种认知模糊会导致后续学习中无法准确理解AI的独特性，也无法判断AI输出结果的可信度。

反馈机制

正确时：卡片发出绿色光芒 + 播放清脆"叮"音效 + 积分+10 + 简短肯定语（如"没错！推荐算法需要从你的行为中学习你的喜好，所以它是AI"）。

错误时：卡片红色闪烁 + 弹回原位 + 文字解释弹出。关键解释示例：

  • "计算器只执行固定的加减乘除公式，它不会'学习'你的计算习惯，所以不是AI。"
  • "自动门只是用红外传感器检测有没有人，它不需要'学习'，只是简单的感应开关。"

真实AI揭秘

播放30秒动画，展示AI和传统程序的本质区别：

  • 传统程序动画：画面左侧，人类工程师写下规则（如"如果分数>60，输出合格"），程序严格按照规则执行。类比：照着菜谱做菜，每一步都是固定的。
  • AI程序动画：画面右侧，给AI看大量数据（如1万条带评分的学生作业），AI自己"发现"规则（如"原来写得详细、有逻辑的分数高"），然后用发现的规则处理新作业。类比：吃过100道菜后自己总结出口味偏好。

动画结尾文字："AI的核心特征：能从数据中学习规律。如果一个程序不能从数据中学习，它就不是AI。"

游戏质量自评

这个游戏是否足够好？——非常好。这个游戏直接解决了"AI与传统程序混淆"这个最常见的认知误区。20张卡片覆盖了从简单到复杂的多种场景，包含3个"易混淆"高难度卡片（自动门、天气预报、扫地机器人），确保不是简单的二分法。

有没有意义？——非常有意义。区分AI与非AI是理解AI能力边界的第一步，是后续所有学习的认知基石。如果学生不能区分AI和传统程序，后续的注意力机制、训练、RAG等概念都会理解困难。

能否起到学习作用？——能。通过20个具体案例的反复判断，学生建立起"能从数据中学习=AI"的判断标准，比单纯讲概念有效得多。拖拽操作增加参与感，即时反馈强化记忆。错误时的解释文案确保"做错也知道为什么错"。

游戏2："AI的超能力"能力归类

理解层
真实问题

AI看似万能——能画画、能写诗、能开车、能翻译——但很多人不知道这些"超能力"其实可以归为五类核心能力。理解AI能力的分类，有助于理解AI的工作原理，也为后续学习注意力机制、向量空间等概念打下基础。

痛点体验

学生可能以为AI每种能力都是独立存在的技术——"画画AI"和"翻译AI"完全不同。不知道它们共享底层原理（都是"输入→数字处理→输出"），这种认知碎片化会导致后续学习中难以建立统一的理解框架。

反馈机制

正确时：标签吸附到场景卡片上 + 该场景播放2秒小动画（如"人脸解锁"场景播放手机屏幕亮起动画）+ 积分+15 + 简短解说（如"没错！人脸识别靠'视觉识别'能力——AI需要'看懂'你的脸部特征"）。

错误时：标签弹回原位 + 引导提示（如"再想想，人脸识别主要是'看'还是'听'？AI需要用什么能力来理解你的脸？"）。

多标签场景：当一个场景需要多个能力时，第一个正确标签放上去后，场景卡片边框变橙色（提示"还需要更多能力"），全部正确后变绿色。

真实AI揭秘

播放40秒动画，揭示一个关键事实：

  • 表面上，AI有5种不同的"超能力"——看、听、说、想、做。每种看起来都很不一样。
  • 本质上，所有这些能力共享同一个底层技术：
      第一步：把输入（图片/声音/文字）变成数字（Token化）
      第二步：用数学计算（神经网络）处理这些数字
      第三步：输出结果（识别结果/文字/动作指令）

动画用三个并排案例展示：人脸识别（图片→像素数字→"这是张三"）、语音识别（声波→数字→"今天天气怎么样"）、文本生成（"今天天气"→数字→计算→"很好"）。

动画结尾文字："AI的所有超能力，本质上都是同一件事：输入→变成数字→数学计算→输出结果。区别只是输入和输出的形式不同。"

1.2 AI怎么"看"文字：Token词元

概念定义

AI看不懂人类文字。它需要把文字切成小块（Token），变成数字才能处理。Token是AI处理文本的最小单位，就像人类阅读时不是看整篇文章，而是一个字一个字地读。不同的切分方式会影响AI对文本的理解。

学习目标

  • 理解Token是AI处理文本的最小单位
  • 知道AI把文字切分为Token后，给每个Token分配唯一编号
  • 理解不同切分方式（粗切/细切）会影响Token数量和AI理解效果
  • 初步了解BPE（子词切分）算法的基本思想

学习方法

动手切分 + 对比：先让学生自由切分句子，再看AI怎么切，通过对比理解Token化的规则和重要性。

呈现形式

方案B："Token积木拼句"逆向游戏

  • 散落Token积木块，拖拽到句子槽拼出完整句子
  • 展示同一句话的不同Token化方式，让学生对比理解

2.1 AI怎么"关注"重点：自注意力机制（重点重构）

📌 概念定义
自注意力机制让AI在读一句话时，能让每个词去"看看"其他词，计算关联度，找到句子中的重点。没有这个机制，AI就像逐字阅读的书呆子——只见树木不见森林。
🎯 学习目标

游戏1："翻译灾难"——没有注意力的AI会怎样（痛点游戏）

可行性：高
真实问题

一个长句子如果抓不住"不要"或"特别"等关键词，翻译结果就完全错误。这是机器翻译领域的核心难题。

游戏机制

痛点体验：展示一个"没有注意力"的AI翻译器：

  • 例句："我今天特别想吃火锅但是不要辣的"
  • 无注意力AI翻译：逐词翻译 → "I today especially want eat hotpot but not want spicy" → 语法混乱，且"不要辣的"被忽略
  • 有注意力AI翻译："I really want hotpot today, but not spicy ones" → 准确

核心操作：

1 展示5个包含关键否定词/强调词/指代词的中文句子，每句下方显示"无注意力AI"的翻译结果（故意遗漏或误解关键信息）
2 学生拖拽"注意力标记"（高亮圆点）到句子中的关键关联词上（如"不要"关联"辣的"，"特别"关联"想吃"）
3 标记正确后，展示"有注意力AI"的正确翻译

例句设计（5个句子）：

  • 句子1："我今天特别想吃火锅但是不要辣的" → 关键关联：特别↔想吃，不要↔辣的
  • 句子2："虽然这道题很难但是小明还是做对了" → 关键关联：虽然↔但是，还是↔做对了
  • 句子3："妈妈说如果下雨就不要去公园了" → 关键关联：如果↔下雨，不要↔公园
  • 句子4："这本书虽然很厚但是内容特别有趣" → 关键关联：虽然↔很厚，特别↔有趣
  • 句子5："老师让我们除了第一章以外都要复习" → 关键关联：除了↔第一章，都要↔复习
反馈机制
  • 标记正确：绿色高亮 + 翻译变正确 + 积分奖励
  • 标记遗漏：红色提示"你漏掉了一个关键关联！'不要'和'辣的'之间有关联，没有注意到这个，AI就会做成辣的！"
  • 标记多余：黄色提示"这个关联不太重要，AI会分配较低的注意力"
真实AI揭秘

动画内容：展示自注意力矩阵——一个N×N网格（N为句子中词的数量），网格中每个格子的颜色深浅代表两个词之间的关联强度。动画以"我今天特别想吃火锅但是不要辣的"为例：

  • 最后展示AI如何利用这个矩阵决定翻译时"重点关注"哪些词，从而生成准确的英文翻译

游戏2："谁在说谁？"——指代关系发现器

可行性：高
真实问题

句子中的代词（它、他、这、那）需要找到指代对象才能理解：

  • "小明把苹果给了小红，因为她很饿"——"她"指谁？
  • "猫坐在垫子上，因为它很软"——"它"指猫还是垫子？

指代关系是人类语言中最常见的歧义来源之一，也是自然语言处理的核心难题。

游戏机制
1 展示8个包含指代关系的句子，每个句子中有一个代词被高亮显示
2 学生拖拽"指代线"从代词连接到它指代的对象
3 连接正确后，系统展示AI的注意力如何从代词"跳"到指代对象的动画

8个句子设计：

  • 句子1："小明把苹果给了小红，因为她很饿" → 她↔小红
  • 句子2："猫坐在垫子上，因为它很软" → 它↔垫子
  • 句子3："爸爸把自行车修好了，它现在能骑了" → 它↔自行车
  • 句子4："姐姐和妹妹在聊天，她们说得很开心" → 她们↔姐姐和妹妹
  • 句子5："老师走进教室，这里立刻安静下来" → 这里↔教室
  • 句子6："小狗追着球跑，它跑得太快了" → 它↔小狗
  • 句子7："妈妈买了苹果和香蕉，这些都是新鲜的" → 这些↔苹果和香蕉

操作说明：

  • 连对 → 绿色线条 + AI确认"正确！'她'指代'小红'"

反馈机制
  • 正确：积分奖励 + 动画展示AI的注意力如何从代词"跳"到指代对象
  • 错误：文字提示 + 显示正确连接 + 解释为什么这样连接
真实AI揭秘

动画内容：展示注意力热图中代词所在行——以"猫坐在垫子上，因为它很软"为例：

2.3 AI怎么"记住"顺序：位置编码

📌 概念定义
AI的注意力机制只看词间关联，不管先后顺序。没有位置编码，"狗追猫"和"猫追狗"在AI眼里一样。位置编码给每个词贴上"第几个"的标签。
🎯 学习目标

  • 掌握位置编码的基本原理（给每个Token分配位置标识）
  • 理解位置编码与自注意力如何协作

游戏1："顺序大混乱"——没有位置编码的翻译灾难（痛点游戏）

可行性：高
真实问题

翻译时顺序颠倒会导致完全错误的意思。"老师批评了学生"和"学生批评了老师"用词完全相同，但意思截然相反。

痛点体验：展示没有位置编码的AI翻译器如何处理中文句子——由于无法区分词序，翻译结果经常出现主客颠倒、因果混乱。

游戏机制
1 展示5个句子，每个句子有"有位置编码"和"无位置编码"两种翻译结果
2 学生拖拽Token到不同位置，观察翻译如何变化
3 系统实时显示两种翻译结果的对比，突出顺序错误导致的语义偏差

5个句子设计：

  • 句子1："老师批评了学生"
    • 无位置编码 → "The student criticized the teacher"（主客颠倒）
    • 有位置编码 → "The teacher criticized the student"（正确）
  • 句子2："妈妈喂宝宝吃饭"
    • 无位置编码 → "The baby fed mom"（主客颠倒）
    • 有位置编码 → "Mom fed the baby"（正确）
  • 句子3："因为下雨所以我没去公园"
    • 无位置编码 → "I didn't go to the park because it didn't rain"（因果颠倒）
    • 有位置编码 → "I didn't go to the park because it rained"（正确）
  • 句子4："猫追狗"
    • 无位置编码 → "The dog chased the cat"（动作方向反了）
    • 有位置编码 → "The cat chased the dog"（正确）
  • 句子5："先做作业再看电视"
    • 无位置编码 → "Watch TV first, then do homework"（时间顺序颠倒）
    • 有位置编码 → "Do homework first, then watch TV"（正确）
反馈机制
  • 正确排列Token：绿色翻译 + 正确语义 + 积分
  • 错误排列Token：红色错误翻译 + 幽默的语义偏差（如"宝宝喂妈妈"）
真实AI揭秘

动画内容：展示位置编码如何工作：

  • 步骤1：展示一句话"老师批评了学生"被拆分成Token：["老师", "批评", "了", "学生"]
  • 步骤2：每个Token加上一个独特的"位置信号"：
    • "老师"（位置0）→ 加上位置向量 [0.0, 0.0, 0.0, ...]
    • "批评"（位置1）→ 加上位置向量 [0.84, 0.54, 0.0, ...]
    • "了"（位置2）→ 加上位置向量 [0.91, -0.42, -0.87, ...]
    • "学生"（位置3）→ 加上位置向量 [0.14, -0.99, 0.54, ...]
  • 步骤3：AI现在能区分"老师批评学生"和"学生批评老师"——因为位置向量不同，即使词向量相同，最终表示也不同
  • 步骤4：展示位置信号如何让AI理解"老师"是主语（位置0），"学生"是宾语（位置3），从而生成正确的翻译

✅ 从真实翻译问题出发，通过"主客颠倒""因果混乱"等直观的错误案例，让学生深刻理解顺序对语义的重要性。拖拽Token重新排列的操作让学生亲身体验词序变化带来的语义偏差，痛点体验非常强烈。

游戏2："位置标签贴纸"——给Token排序

可行性：高
真实问题

AI需要明确知道每个词的位置才能正确理解句子结构。位置标签就像书的页码——没有页码，你不知道章节的先后顺序。

游戏机制
1 展示打乱的Token积木（如"苹果"、"吃"、"我"、"了"）
2 学生拖拽Token积木到正确顺序（"我"、"吃"、"了"、"苹果"）
3 为每个Token贴上位置标签贴纸（位置0、位置1、位置2、位置3）
4 贴完后AI读取带位置标签的句子，展示理解结果

5组Token积木设计：

  • 第1组：["苹果", "吃", "我", "了"] → 正确顺序：["我", "吃", "了", "苹果"] → "我吃了苹果"
  • 第2组：["公园", "去", "小明", "了"] → 正确顺序：["小明", "去", "了", "公园"] → "小明去了公园"
  • 第3组：["作业", "做", "在", "我"] → 正确顺序：["我", "在", "做", "作业"] → "我在做作业"
  • 第4组：["很", "今天", "冷", "天气"] → 正确顺序：["今天", "天气", "很", "冷"] → "今天天气很冷"
  • 第5组：["书", "看", "喜欢", "我", "这", "本"] → 正确顺序：["我", "喜欢", "看", "这", "本", "书"] → "我喜欢看这本书"

操作说明：

  • 顺序正确 → AI理解正确 + 笑脸表情 + "我吃了苹果 ✅"
  • 顺序错误 → AI困惑表情 + 错误解读（如"苹果吃了我" 😱）
反馈机制
  • 顺序正确：绿色 + AI理解正确 + 笑脸 + 积分
  • 顺序错误：红色 + AI困惑 + 错误解读（制造幽默效果）
真实AI揭秘

动画内容：展示正弦/余弦位置编码的简化可视化：

  • 步骤1：展示每个位置有一个独特的"颜色指纹"：
    • 位置0 → 🟦🟦🟦（全蓝色）
    • 位置1 → 🟨🟦🟦（黄蓝混合）
    • 位置2 → 🟥🟨🟦（红黄蓝混合）
    • 位置3 → 🟪🟥🟨（紫红黄混合）
  • 步骤2：解释这些"颜色指纹"是如何用正弦和余弦函数生成的：
    • 每个位置对应一组正弦和余弦值
    • 不同位置的值不同，形成独特的"指纹"
    • 即使是相邻位置，指纹也有明显差异
  • 步骤3：展示AI如何通过颜色指纹区分不同位置的相同Token：
    • "苹果吃了我" → "苹果"是🟦（位置0），"我"是🟥（位置3）
    • "我吃了苹果" → "我"是🟦（位置0），"苹果"是🟥（位置3）

✅ 通过"积木+贴纸"的游戏化设计，将抽象的位置编码概念具象化。错误顺序导致的幽默解读（如"苹果吃了我"）增加了趣味性和记忆点。正弦/余弦编码的"颜色指纹"可视化降低了理解门槛。

可行性：中
真实问题

游戏机制

    • 模式B（有位置）→ "Although the math problem was hard, Xiaoming still completed it carefully"（完全正确）
  • 句子2："如果明天下雨，我们就取消去公园的计划"
    • 模式A（无位置）→ "取消去公园的计划，如果明天下雨"（条件关系保留，但时间顺序不清）
    • 模式B（有位置）→ "If it rains tomorrow, we will cancel the plan to go to the park"（完全正确）
  • 句子3："先做作业，然后看半小时电视，最后去睡觉"
    • 模式A（无位置）→ "做作业、看电视、睡觉"（丢失时间顺序信息）
    • 模式B（有位置）→ "First do homework, then watch TV for half an hour, and finally go to bed"（完全正确）

  • 模式A得分：显示AI理解的部分正确性（如60分），指出缺失的位置信息

3.2 AI开始学习：SFT监督学习

概念定义

SFT（Supervised Fine-Tuning，监督微调）是AI学习的核心过程。简单来说，就是让AI看着"标准答案"一遍遍模仿学习，就像学生跟着老师读课文一样。AI会不断调整自己的参数，让回答越来越接近标准答案。

学习目标

  • 理解SFT的基本原理：输入→预测→对比→调整
  • 认识Loss曲线：AI的"考试成绩"，越低越好
  • 理解训练轮数（Epoch）的影响：太少学不会，太多会"死记硬背"

学习方法

通过"训练模拟器"游戏，学生可以亲眼看到AI从"胡说八道"到"准确回答"的进步过程，理解训练的本质。

🎮 游戏机制

Epoch = 100（太多）：

  • Epoch 30：✅ "杜甫也是唐代诗人，和李白并称'李杜'"（能举一反三）
  • Epoch 100：❓ "这个...我只知道李白..."（死记硬背，不会推理）

🤖 真实AI揭秘

过拟合和欠拟合是机器学习的核心概念：

  • 欠拟合（Underfitting）：模型太简单或训练太少，连训练数据都学不会
  • 过拟合（Overfitting）：模型太复杂或训练太多，把训练数据"背下来"了，但遇到新数据就懵
  • 解决方案：早停（Early Stopping）——在验证集性能开始下降时停止训练
  • 正则化：给模型加"惩罚"，防止它过度拟合训练数据

3.3 给AI批改作业：RLHF人类反馈

概念定义

RLHF（Reinforcement Learning from Human Feedback，基于人类反馈的强化学习）是AI训练的"精修阶段"。SFT训练后的AI虽然能回答问题，但可能回答得不够好（比如太啰嗦、不够有帮助、或者说出不该说的话）。RLHF就是让人类给AI的回答打分，教AI什么是"好的回答"。

学习目标

  • 理解RLHF的目的：让AI的回答更符合人类期望
  • 学会评价AI回答的多个维度（准确性、有用性、安全性）
  • 认识到人类反馈在AI对齐中的关键作用

学习方法

通过"AI回答排序赛"游戏，学生扮演人类标注员的角色，给AI的多个回答打分排序，亲身体验RLHF的过程。

前后联系

铺垫：训练完成的AI可以进入下一阶段——学习如何使用记忆和工具
游戏 1

AI回答排序赛：给多个回答排优劣

💡 真实问题

同一个问题，AI可能给出多个不同的回答。哪个最好？哪个最差？人类需要判断，才能教AI什么是"好的回答"。

🎮 游戏机制

问题："如何准备期末考试？"

AI的三个回答：

  • 回答A："复习啊，多看看书，做做题，别玩手机，早点睡觉，加油！"
  • 回答B："1. 制定复习计划，按优先级分配时间；2. 整理课堂笔记，重点复习薄弱环节；3. 做历年真题，熟悉考试题型；4. 组建学习小组，互相讨论答疑；5. 保证充足睡眠，考试前别熬夜。"
  • 回答C："考试？直接抄同桌的不就行了嘛！"

操作方式：拖拽回答卡片，按照从好到差的顺序排列

✅ 反馈机制
  • 正确排序（B → A → C）：✅ "很好！回答B最有帮助，回答A虽然正确但太笼统，回答C是不当建议"
  • 错误排序：❌ "再想想：回答C建议作弊，这是不对的，应该排在最后"

评价维度：

  • ✓ 有帮助性（Helpfulness）：回答是否真正解决了问题？
  • ✓ 准确性（Accuracy）：回答的内容是否正确？
  • ✓ 安全性（Safety）：回答是否包含有害或不当内容？
🤖 真实AI揭秘

RLHF中人类标注员的工作：

  • 数据收集：让AI对同一个问题生成多个回答
  • 人类排序：标注员按照质量从高到低排序
  • 奖励模型：用排序数据训练一个"评分模型"，学会给回答打分

阶段四 AI的记忆与知识（2课时）

AI训练完成后，它的"记忆"并不是像数据库那样精确存储，而是被"压缩"进了数十亿参数中。这导致AI常常"健忘"、"胡说八道"。本阶段让学生理解AI的记忆机制，并学会用知识库和RAG技术来弥补AI的记忆缺陷。

5.1 AI一步步想问题：思维链CoT

1

游戏1："一口吃不成胖子"——没有思维链的AI

痛点游戏
真实问题

AI直接回答复杂问题经常出错，尤其是多步骤数学题、逻辑推理题。就像让学生"一口吃成胖子"，AI也需要一步步来。

痛点体验

学生看到AI对复杂问题给出错误答案，会产生"AI好笨"的直觉——然后发现分步推理后AI变聪明了，认知冲突产生。

游戏机制

展示3道复杂数学题，每道题先展示AI直接回答（错误），再展示分步推理（正确）。学生判断哪种回答正确。

题目直接回答（错误）分步推理（正确）
小明有20个苹果，给小红1/4，给小蓝剩下的一半，再给小绿3个，还剩多少？ "还剩10个"（错） 步骤1：给小红1/4 = 20 × 1/4 = 5个，剩15个
步骤2：给小蓝一半 = 15 ÷ 2 = 7.5个，剩7.5个
步骤3：给小绿3个 = 7.5 - 3 = 4.5个
答：还剩4.5个
一个班级有40人，60%是女生，女生中1/3戴眼镜，问戴眼镜的女生有多少人？ "8人"（错） 步骤1：女生人数 = 40 × 60% = 24人
步骤2：戴眼镜女生 = 24 × 1/3 = 8人
答：8人（这次直接回答碰巧对了，但通常不会）
鸡兔同笼，共35个头，94只脚，问鸡兔各几只？ "鸡20只，兔15只"（错） 步骤1：假设全是鸡：35 × 2 = 70只脚
步骤2：多出 94 - 70 = 24只脚
步骤3：每只兔比鸡多2只脚，所以兔 = 24 ÷ 2 = 12只
步骤4：鸡 = 35 - 12 = 23只
答：鸡23只，兔12只

学生为每道题选择"哪个回答可信"，系统揭秘正确答案。

反馈机制

选择正确：+15分，显示"你发现了！分步推理的回答更可信。"

选择错误：不扣分，显示"再仔细看看，直接回答跳过了中间步骤，容易出错。"

完成3题后：显示总结"思维链让AI分步思考，准确率从17.7%提升到78.7%——这就是逐步推理的魔力！"

真实AI揭秘

播放40秒动画，展示CoT如何提高准确率：

  • 数据：在GSM8K数学推理数据集上，GPT-3直接回答准确率17.7%，加入思维链后提升到78.7%
  • 原理：思维链让AI把复杂问题拆解为多个简单子问题，逐步求解
  • 触发方式：在提示词中加入"让我们一步步思考"或给出few-shot示例

动画结尾文字："思维链（Chain-of-Thought）让AI像人类一样分步思考。复杂问题不要'一口吃'，而是'一口一口吃'！"

有没有意义？——极其重要。思维链是当前大模型能力提升的核心技术，学生需要理解"分步思考"的价值。

能否起到学习作用？——能。通过具体的数学题对比，学生自然理解"AI也需要一步步想"。

游戏2："推理步骤排序赛"

理解层
真实问题

思维链的关键在于步骤的顺序。如果步骤顺序错了，最终答案也会错。AI生成思维链时，需要按照逻辑顺序组织推理。

游戏机制

展示一道题目和打乱的5个推理步骤卡片，学生需要拖拽排序成正确的逻辑顺序。

推理排序演示
📝 题目：一个水池有A、B两根水管，A管单独注满需6小时，B管单独注满需8小时，同时打开两管，多久注满？
🔀 步骤C：合注速度 = 1/6 + 1/8 = 7/24（池/小时）
🔀 步骤A：A管每小时注水 1/6 池
🔀 步骤E：答：约3.43小时注满
🔀 步骤B：B管每小时注水 1/8 池
🔀 步骤D：注满时间 = 1 ÷ (7/24) = 24/7 ≈ 3.43小时
正确顺序：[步骤1] → [步骤2] → [步骤3] → [步骤4] → [步骤5]

正确顺序：A → B → C → D → E（先分别计算速度，再合算，最后求时间）

反馈机制

排序完全正确：+30分，播放"思维链流畅运转"动画，所有步骤亮起绿色。

部分正确：显示哪些步骤位置正确（绿色），哪些错误（红色），允许重试。

关键提示："思维链的顺序就像做菜的步骤——先放油再放菜，顺序反了就做不出来了。"

真实AI揭秘

播放30秒动画，展示AI生成思维链的过程：

  • 训练阶段：AI在训练时见过大量"分步解答"的样本，学会了推理模式
  • 生成阶段：AI逐步生成推理步骤，每步基于上一步的结果
  • 自回归：AI是"从左到右"生成，每个新步骤都依赖前面步骤

动画结尾文字："AI生成思维链就像'接力跑'——每一步都基于上一步的结果。步骤顺序错了，后面全错！"

游戏质量自评

这个游戏是否足够好？——是。拖拽排序操作简单，数学题场景熟悉，排序机制直观展示思维链的"顺序"重要性。

有没有意义？——非常有意义。思维链的顺序性是容易被忽视的关键点，学生通过排序理解"为什么步骤顺序很重要"。

能否起到学习作用？——能。排序任务迫使学生思考每步之间的逻辑依赖关系，加深对推理过程的理解。

游戏3："思维链侦探"——找出推理中的错误

应用层
真实问题

思维链的一大优势是可解释性——当AI给出错误答案时，我们可以检查它的推理过程，找到哪一步出错。没有思维链时，AI的错误是"黑箱"。

游戏机制

展示一个有错误的思维链（5个步骤），学生需要找出哪一步出错了，并说明原因。

🕵️ 侦探任务：找出推理漏洞

题目：一件衣服原价200元，先打8折，再打9折，现价多少？

AI的思维链：

  1. 步骤1：原价 = 200元
  2. 步骤2：打8折后 = 200 × 0.8 = 160元
  3. 步骤3：再打9折 = 200 × 0.9 = 180元 （错误！应该用160 × 0.9）
  4. 步骤4：最终价格 = 180元
  5. 步骤5：答：现价180元

学生任务：点击出错的步骤编号（1-5），并选择错误类型：

  • A. 计算错误（数字算错了）
  • B. 逻辑错误（用了错误的数值） ✓
  • C. 理解错误（误解了题目）

共3道侦探题，难度递进。

反馈机制

找出正确错误步骤+错误类型：+25分，显示"名侦探！你找到了AI推理的漏洞。"

找出步骤但类型错误：+10分，提示正确的错误类型。

找错步骤：不扣分，高亮正确步骤并解释"看这里，步骤3用了原价200而不是折后价160"。

完成3题后：显示总结"思维链让AI的错误'可见'——我们可以追踪推理过程，找到问题所在。这是没有思维链时做不到的！"

真实AI揭秘

播放35秒动画，展示CoT的可解释性优势：

  • 黑箱模式（无CoT）：AI直接给出答案，错了也不知道为什么
  • 白箱模式（有CoT）：AI展示推理过程，错误可以被追踪和修复
  • 实际应用：在医疗、法律、金融等高风险场景，可解释性至关重要

动画结尾文字："思维链让AI从'黑箱'变成'白箱'——错了也能知道错在哪里。这是AI可解释性的重要一步！"

这个游戏是否足够好？——非常好。"侦探"主题增加趣味性，找出错误步骤的任务让学生深入理解推理过程。

有没有意义？——非常有意义。可解释性是AI可信度的关键，学生理解"思维链让错误可追踪"。

能否起到学习作用？——能。侦探任务迫使学生逐步检查推理逻辑，培养批判性思维和AI审计能力。

提示词工程（Prompt Engineering）是通过设计精心构造的输入提示，引导大模型生成更准确、更符合需求的输出。它是使用AI的核心技能。

为什么推迟到未来实现？
