Problem

Qt 测试的三大痛点

Web 有 Playwright，移动端有 Appium，但 Qt 桌面应用的自动化测试，至今仍是 AI 时代的盲区。

🔒

可访问性差

Qt 控件树难以获取，自定义控件、QML 动态界面更是黑盒。传统测试工具依赖选择器，写起来慢、维护更重。

🔧

脚本维护地狱

界面一改，脚本全废。Squish、Ranorex 等商业工具昂贵且学习曲线陡峭，小团队难以承受。

👁

纯视觉不可靠

只看截图做判定容易误判——界面看起来对了，但内部逻辑可能错了。缺乏交叉验证手段。

Features

五大核心特性

从零设计的 AI 测试引擎，每一处都针对 Qt 桌面场景深度优化。

01

视觉驱动 · 零侵入

AI 像真人一样看屏幕操作，不依赖控件树、不注入代码。 基于 Windows SendInput API 模拟真实输入，被测程序零感知、零改造。

Zero Instrumentation
02

双段 AI 管线

视觉模型只管「看懂界面」，文本模型负责「思考决策」。 职责分离，各自可插拔替换——通义万相、智谱、DeepSeek、Qwen 国产模型全兼容。

Vision → Text Pipeline
03

界面 + 日志双证据

增量读取被测程序日志，AI 判定时同时引用视觉证据和日志证据。 不只是「看图说话」，交叉验证让结果更可靠。

Dual Evidence
04

完整 trace 与回放

每一步截图、AI 决策、动作、结果全部记录为 JSONL。 支持离线单步回放、HTML 可视化报告，AI 的每一步都透明可追溯。

Trace & Replay
05

Trae 双向集成

本项目用 Trae 协作设计开发，又通过 MCP 反向接入 Trae。 AI 编码助手写完 Qt 代码，自动调用 loopengine 验证——写验一体。
