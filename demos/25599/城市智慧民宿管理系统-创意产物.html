城市智慧民宿管理系统

让每一间民宿都被温暖管理 · 让每一位客人都被贴心服务

PART 01 创意名称 & 创意介绍
💡 想解决什么问题
当前许多中小型民宿、公寓式酒店仍使用纸质登记本、Excel表格或老旧单机系统进行日常运营管理。房间状态更新滞后、客人信息查找困难、账单计算容易出错，且无法实现多门店、多员工的协同管理，严重制约了民宿行业的数字化升级和规模化发展。
🎯 为什么会想到做这个
源自对民宿店主日常工作痛点的深入观察——每逢节假日入住高峰，前台手忙脚乱；房间清洁状态靠口口相传；客人历史记录无从查起。一套轻量级、易部署、可扩展的Web化民宿管理系统，正是广大中小型民宿经营者迫切需要的数字化解决方案。
🏗️ 大概是什么产品
一套基于 Python Django + REST API 的 B/S 架构民宿管理应用网站，覆盖用户权限管理、多门店房间管理、客人信息登记、入住离店结算、账单统计等核心业务流程，并提供可视化管理后台和完整的 API 接口。

PART 02 目标用户 & 核心痛点
🎯 面向哪些用户
中小型民宿店主、公寓式酒店管理者、长租公寓运营者、连锁门店分店店长，以及需要对前台员工、清洁人员进行权限分级管理的民宿运营团队。
📍 在什么场景下使用
① 前台办理入住/退房手续；② 清洁阿姨完成房间清洁后更新状态；③ 店长查看当日入住率、营收数据；④ 财务核对账单与收款记录；⑤ 跨门店统一查档与统计分析。
⚠️ 当前痛点（没有这套系统的不便）
❌ 房间状态混乱：空闲/入住/清洁/维修状态靠人工记忆或纸质标记，频繁出现"一房多订""脏房误售"。
❌ 客人信息缺失：回头客无法识别，黑名单客人难以及时拦截，身份证号重复录入无校验。
❌ 账单计算易错：手工计算房费、押金、天数容易算错算漏，月底对账耗时耗力。
❌ 多门店协同困难：跨门店数据无法互通，集团式民宿运营管理成本居高不下。
❌ 权限管理缺失：员工账号权限无分级，操作无审计痕迹，数据安全存在隐患。
PART 03 价值 & 意义
💼 商业价值
通过房间状态实时同步 + 自动化账单计算，可有效降低前台操作失误率，减少坏账损失；多门店统一管理模式助力民宿品牌连锁化扩张；完整的 API 接口为后续对接 OTA 平台（如携程、美团民宿）预留了商业扩展空间。
⚡ 效率提升
入住登记流程从5分钟缩短至30秒；房间状态实时可视化，清洁阿姨与前台信息同步零延迟；月底营收统计一键生成，告别手动汇总。整体运营效率预估提升 60% 以上。

PART 04 系统架构 & 核心模型
🏛️ 系统架构
采用经典的 前后端分离 + RESTful API 架构：后端以 Django 为核心框架，DRF 提供标准 API 接口，JWT Token 保证用户身份安全，SQLite 存储业务数据；前端通过 HTTP 请求与后端交互；整个系统可部署在 Linux 服务器上，支持 一键部署脚本（run.sh / service.sh），运维门槛极低。
📊 核心数据模型
① User（用户） — 账号、真实姓名、手机、角色、最后登录IP、状态
② Role（角色） — 角色编码、名称、权限配置
③ Store（门店） — 门店名称/编码、详细地址、店长、营业时间、状态
④ RoomType（房型） — 房型名称、基础价格、押金
⑤ Room（房间） — 房号、所属门店、楼层、状态（空闲/入住/清洁/维修）
⑥ Guest（客人） — 身份证号、姓名、性别、手机、地址、黑名单标记
⑦ CheckIn（入住） — 客人、房间、门店、操作人、入住/离店时间、房费、押金、天数、状态
⑧ Bill（账单） — 账单号、关联入住记录、房费、总金额、支付状态
🚀 部署方式
项目提供 Windows 双击启动脚本（run.bat）、Linux 一键部署脚本（run.sh / service.sh）、桌面快捷方式生成脚本，以及 Docker 部署方案。运维人员零经验也能快速上线，真正做到 "下载即安装，双击即运行"。
