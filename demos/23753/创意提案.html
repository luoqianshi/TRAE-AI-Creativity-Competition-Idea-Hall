学习资料秒转思维导图 + 结构化笔记

把一份 PDF / 讲义 / 技术文档喂进去，3 分钟内产出思维导图 + TL;DR + 关键词 + 一句话 takeaway， 打包成一张可离线浏览的 HTML 复习页。

产品形态：命令行工具 / 桌面端 Skill
版本：v1（MVP）
日期：2026-06-16
面向用户：个人学习者

1. 创意名称 + 创意介绍

创意名称
Learnbrief · 学习资料秒转脑图
想解决什么问题
读完一份 PDF/讲义/论文后，自己手动整理成思维导图和结构化笔记至少还要花几十分钟， 学习节奏被打断，结果常常被搁置。
为什么会想到做这个
备考、啃新课、读技术文档时，真正费时间的不是"读"，而是"读完后把信息结构化沉淀下来"。 LLM 正好可以把这一步自动化。
大概是什么产品
一个 AI Skill（命令行 / IDE 内嵌）——用户把资料喂进去，自动生成 思维导图 + 结构化摘要 + 一份可离线浏览的 HTML 复习页。
一句话概括：把"读完 → 沉淀笔记"这一步的时间从几十分钟压到几分钟。

2. 目标用户及痛点

2.1 面向哪些用户

  • 大学生 / 研究生：考前一周，把一周攒下的 PDF 讲义一次性吃透
  • 程序员：啃官方文档、技术博客、课程讲义后留一份结构化笔记
  • 研究者 / 工程师：读完论文、调研报告后生成脑图复盘
  • 任意需要"快速吃透一份资料"的个人学习者

2.2 在什么场景下使用

  1. 考前冲刺：把课程 PPT + 讲义 → 脑图 + TL;DR → 考前翻两页 takeaway
  2. 学新课：每章学完后把该章 PDF 转成脑图，快速回看自己漏了什么
  3. 读论文/技术博客：复制正文 URL 进去，5 分钟拿到一张可分享的脑图

2.3 当前痛点（没本工具时）

手动做脑图：打开 XMind / 幕布，手动复制粘贴标题和要点，复制一份讲义最少也要 40 分钟，而且节奏被完全打断。
直接丢给通用 ChatGPT：输出不稳定（有时像写作文）、没有可视化（一张图胜过千言万语）、下次找不到（对话被刷掉就没了）。
资料散落一地：脑图在 XMind、摘要在 Notion、笔记在 Obsidian。想要一张"总复习页"，得来回切软件。
核心差距：通用 AI 是"聊天对象"，我们要做的是"结构化笔记助手"——它不跟你闲聊，它直接给你一张可复盘的脑图 + 一句话 takeaway。

3. 价值与意义

3.1 效率提升（主打）

一份 30 页 PDF → 3 分钟出脑图 + 摘要 + HTML 复习页。 把"读完 → 沉淀"的 gap 从几十分钟压到几分钟。 用户把"学完不做笔记"改为"学完 3 秒敲个命令出复习页"。

3.2 社会价值

降低"入门一门新知识"的结构性门槛—— 你不需要先学会"怎么做笔记"才能学好。工具帮你把认知负担降到聚焦内容本身。 这对非科班自学者、在职转行学习者、年龄大了但想快速学点新东西的人群尤其有意义。

3.3 商业潜力（v2 之后）

  • 做成本地优先 + 可选云端：本地用 Ollama vLLM 跑、不泄露资料；想同步才上传
  • 多文档合并："把这 10 篇论文合成一张脑图" → 研究综述辅助
  • 间隔复习联动：takeaway + 卡片 + 间隔复习提醒

4. 产品形态（v1）

名称
learnbrief <input> [--out report.html] [--model deepseek-chat]
输入
PDF / Markdown / TXT / 或 http(s):// 任意 URL
依赖
Python 3.11+，一个 OpenAI 兼容 API key（DeepSeek / 通义 / Ollama / OpenAI）
输出
单文件 HTML（约 10 KB），双击浏览器可看，markmap 脑图 + TL;DR + 关键词 + takeaway + Markdown 原文
时间
3 分钟内完成 30 页资料（取决于 LLM 延迟）

4.1 架构一句话

输入 → 统一解析器（PDF/MD/TXT/URL） → OpenAI 兼容 LLM（树状 Markdown + JSON 摘要） → markmap（CDN 运行脑图） → Jinja2（单页 HTML）。 大文档按章节分块抽取 + 合并。失败自动降级（脑图挂了就只出摘要）。

4.2 不做什么（v1 刻意排除）

  • ❌ OCR（扫描件 PDF，无可复制文本）
  • ❌ 图片 / 数学公式渲染（公式保留 LaTeX 源码）
  • ❌ 多套脑图主题 / 自定义皮肤
  • ❌ 多文档合并 / 对话记忆
  • ❌ 后端服务、多人协作、云同步

5. 为什么这和别人不一样

vs. XMind / 幕布
它们是"手工编辑"，我们是"零编辑生成"。用户没有编辑动作，只有喂资料 + 拿结果。
vs. ChatGPT 直用
我们输出稳定的结构化（固定模板 + 固定脑图 + 固定关键词），下次看的时候一眼就能复盘，而不是翻几屏对话。
vs. Notion AI / Obsidian
它们是"笔记软件里的插件"，我们是"先出结构化笔记，再选要不要同步进笔记软件"——先提效，再接入。
最简单的差异化：用户不需要学怎么用，只需要学怎么把资料喂进去。
