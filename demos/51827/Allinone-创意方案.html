PROBLEM

复杂文档的生产痛点，没人真正解决

学生写论文、产品经理写 PRD、创业者写 BP、研究员写综述——单一模型长度受限、容易幻觉、跨章节不一致；多模型来回切换又会让对话历史割裂、版本爆炸、证据无法追溯。

✕

单一模型不够好

答得到、写不全、查不准、调不顺。输出浅、长度受限、跨章节容易丢失一致性。

⇄

多模型来回切换

在 GPT / Claude / Gemini / Kimi / DeepSeek 之间反复对比，几轮下来内容堆到几十万字，自己都不知道哪版是终稿。

⌘

聚合器不是编排

市面上的"聚合器"只是把多模型答案拼在一起，没有任务拆解、角色分配、冲突评审、文档沉淀和版本追踪。

SOLUTION

一个统一入口，平台自动编排多模型

Allinone 不是"答案聚合器"，而是一个面向复杂文档交付的多模型智能编排平台：前端是统一对话，中间是自研总控模型，后端是四层文档资产沉淀，最终交付一份高质量、可追溯、可复用的成品。

FOUR-LAYER ARCHITECTURE

每轮对话，自动沉淀为四层文档资产

不是一次性输出答案，而是把对话过程沉淀成"源 → 子 → 总 → 成品"四层结构，可追踪、可下钻、可复用。

LAYER 01
源文档层 · Source
每一次对话、每一次模型调用的原始结果与引用链接，全部留痕，作为证据链底层。任何结论都可下钻到出处。
raw · citations · trace
LAYER 02
子 Wiki 层 · Sub-Wiki
按主题 / 章节把源文档聚类成可独立阅读的子知识库，自动去重、消歧、合并同类项，形成结构化中间产物。
cluster · dedup · merge
LAYER 03
总 Wiki 层 · Master-Wiki
把多个子 Wiki 编排成全局一致的知识体系，自动处理跨章节冲突、术语统一、引用闭环，形成可复用的工作资产。
reconcile · unify · index
LAYER 04
最终成品层 · Deliverable
按目标格式（Word / Markdown / PDF / Wiki）排版输出最终成品，附带目录、引用、版本号，一键导出交付。
export · layout · v-tag
