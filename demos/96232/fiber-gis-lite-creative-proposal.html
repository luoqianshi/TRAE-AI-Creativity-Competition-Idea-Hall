痛点

光缆资源"看不清、调不动、查不到"

外线光缆是通信网的"血管"，但大多数运维团队仍用最原始的方式管理它。

🗺️

资源在纸上，不在图上

光缆走向靠 CAD 图纸和 Excel 台账，现场找不到、看不懂，新人不靠老师傅根本接不了手。

📵

野外没网就停工

人井、杆路多在信号盲区。传统系统一旦离线就寸步难行，紧急抢修时反而最用不上。

🔧

改了谁知道？坏了说不清

换缆、割接后台账对不上；光纤断了靠经验盲猜断点，OTDR 曲线只有专家看得懂。

产品形态

一张活地图 + 一套离线作业 + 一个 AI 诊断

Web 端指挥中心 · 移动端野外采集 · 管理后台数据治理，三端一体。

🌐

GIS 地图可视化

高德/OSM/卫星底图叠加矢量光缆段，点击即看健康度（绿/黄/红）、版本与衰减。

📲

离线采集编辑

无网也能新建/更新/删除光缆段，本地草稿自动同步、幂等去重，回到有网一键上传。

🧠

OTDR 智能诊断

上传 OTDR 曲线自动解析事件点、双向比对，AI 预测潜在断点，不再依赖专家肉眼。

🕓

版本化追溯

每一次割接生成新版本，businessKey 跨版本不变，谁改的、改了什么、何时改的全程可回溯。

📥

批量导入导出

CSV / GeoJSON / Excel 一键导入历史台账，评比看板激励一线多录多核，数据越用越准。

🔔

实时事件推送

Redis Stream + SSE 实时通知瓦片失效与告警，地图秒级刷新，指挥室与现场同频。

为什么靠谱

工程上经得起推敲的设计

不是 PPT 玩具，而是一套遵循坐标系、多租户、幂等等硬约束的生产级架构。

① 坐标系铁律

全程 GCJ-02（高德坐标系），PostGIS 以 SRID 4326 存储；写入前强制标准化，绝不把 WGS-84 裸坐标入库。

② 离线优先 + 幂等同步

双 ID（clientId/serverId）+ 幂等键 upsert，弱网反复提交也不产生重复数据，冲突按 LWW/merge 自动处理。

③ 版本化与并发锁

割接生成新版本并继承 businessKey；事务内加 advisory 锁，杜绝并发产生两个"新版本"的经典坑。

④ 矢量瓦片 + 实时推送

PostGIS 直接生成 MVT 二进制瓦片（5 分钟 Redis 缓存），事件经 Redis Stream 触发 SSE 秒级刷新。

⑤ 多租户隔离

所有裸 SQL 走 scopedQueryRaw 强制注入 orgId，租户间数据零越权，安全审计可过。

⑥ AI 可开关

OTDR 异常检测与故障预测为可插拔模块，关闭时不影响主流程，开启即获得智能诊断能力。

说明：本页"界面原型"依据 Fiber GIS Lite v3 真实前端源码（MapView / OfflineEditorPage / DashboardPage / OtdrPage 等）还原， 用于直观展示产品形态；在当前演示环境中以高保真原型呈现，便于评审快速理解创意。

目标用户与使用场景

外线装维人员

在人井、杆路、机房之间奔波。信号差时用手机离线采集光缆走向与接头盒，回站后自动同步。

运维指挥 / 调度

在 Web 指挥中心看全局地图与健康度，故障告警实时推送，快速派单、定位断点。

资源管理员

在管理后台做数据治理：批量导入历史台账、导出核查、用评比看板激励一线补全数据。

典型场景：暴风雨后某主干光缆告警 → 指挥室在地图看到红色段与 OTDR 预测断点 → 派单附近装维 → 对方野外离线查看该段历史版本与接头盒照片 → 完成割接并就地更新 → 回网后数据同步、地图实时变绿。

价值与意义

它到底解决了什么大问题

商业价值

把"隐性资产"变成"可运营数据"：资源可视化降低 30%+ 故障定位时长，减少盲目派单与误割接损失；版本化台账支撑资産盘点与合规审计，可直接面向运营商/铁塔公司规模化交付。

效率提升

离线采集让野外作业"零等待"；OTDR AI 诊断把专家经验沉淀为系统能力，新人也能 3 分钟定位断点；评比看板让台账准确率随使用持续提升，告别"录一次错半年"。

社会价值

通信光缆是城市数字底座。让基础设施"看得清、调得动"，意味着灾害与突发故障时恢复更快、民生与应急通信更稳——用一套轻量系统，守住一张看不见却离不开的网。
