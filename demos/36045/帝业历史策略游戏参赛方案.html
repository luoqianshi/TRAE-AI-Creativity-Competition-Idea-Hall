创意介绍

一款将多 Agent AI 技术与历史策略游戏相结合的创新教育产品

"帝业"是一款结合多 Agent AI 技术与历史策略游戏的创新教育产品。 玩家可以选择不同朝代的君主，通过自然语言对话的方式对身边的臣子发布政策指令，体验古代帝王的治国之道。

游戏中的所有 NPC（大臣、将领、谋士等）都由 AI Agent 驱动，他们会根据各自的职责和性格特点给出建议，甚至相互辩论。 游戏融合了天灾应对、经济管理、战争决策、外交谈判、内政管理、气候模拟等多种玩法，每一个决策都可能改变历史走向。

💡 核心理念：让历史不再是枯燥的文字，而是可体验、可思考、可改变的精彩故事。玩家通过沉浸式体验感受每代皇帝的难处，在游戏中自然而然地学习历史知识。

  • 🤔 缺乏批判性思维训练：被动接受历史结论，缺少主动思考和决策的机会

玩法与机制

回合制策略游戏，每回合代表一年，融合多维度治理系统

核心游戏循环（6 步流程）
第 1 步：回合开始

每回合代表一年，系统自动触发历史事件和随机事件

第 2 步：查看局势

了解当前国力、资源（粮食/金钱/人口/兵力/士气/民心）、派系状态

第 3 步：发布政策

通过自然语言对话方式对臣子发布政策指令，AI 自动解析意图

第 4 步：Agent 廷议

相关大臣 AI 对政策进行廷议式讨论、评估、辩论，提出建议

第 5 步：决策执行

玩家根据建议做出最终决策，系统计算政策效果与连锁反应

第 6 步：回合结算

更新各项数值，记录历史事件，判断是否触发蝴蝶效应

核心系统详解

六大关键游戏系统的详细设计

📜 历史事件系统

基于真实历史 + AI 动态生成的四层事件体系：

事件类型说明示例
必发事件真实历史事件，按时触发安史之乱 (755年)
概率事件基于参数触发干旱→农民起义概率+30%
玩家事件政策触发的连锁反应重农抑商→商人逃亡
隐藏事件满足条件后触发收集宝物→发现古籍

事件影响包含直接效果（资源增减）、长期影响（政策倾向改变）和历史分歧点（关键节点后分支发展）

⚖️ 政策计算引擎

参数化、连锁化、历史化的政策效果计算：

  • 参数化效果：每个政策有可调参数，如税率+1%→税收+1%，民心-0.5%
  • 连锁计算：政策组合产生叠加效果，如高税收+灾荒→起义概率大幅提升
  • 历史校验：基于历史事实判断政策合理性，唐朝不会出现"洋务运动"
  • 效果预测：短期影响、长期影响、副作用、是否可逆
🌍 外交系统

多维度外交手段，不同国家有不同外交倾向：

朝贡体系 和亲联姻 盟约结盟 宣战 贸易协定
  • 汉朝：重朝贡体系，以天子之国自居
  • 唐朝：重开放交流，丝绸之路贸易繁荣
  • 明朝：海禁政策，郑和下西洋后收缩
🧬 文化思想系统

不同思想体系影响国家凝聚力和统治效果：

儒家 法家 道家 佛家 兵家
  • 儒家：民心+20%，但军事效率-10%
  • 法家：行政效率+30%，但民心-15%
  • 道家：社会稳定+25%，适合休养生息时期

玩家通过对话发布政策，AI 自动解析意图并驱动 Agent 讨论

意图识别维度
  • 政策类型识别：税收调整、军事行动、外交政策、工程建设、法律改革等
  • 约束条件提取：目标、时间、资源限制等参数
  • 可行性判断：基于当前国力、历史背景判断是否可执行
  • 替代方案建议：不可行时自动推荐替代政策
Agent 廷议机制
  • 廷议模式：多个臣子 Agent 对政策进行讨论、辩论
  • 模拟推演：工部/兵部/户部分别模拟政策效果
  • 决策输出：汇总讨论结果，给出建议和预期影响
  • 性格一致性：王安石支持变法、司马光反对——Agent 始终保持人设

  • 短期记忆：当前回合对话内容，Agent 即时引用

sql -- 朝代信息表 CREATE TABLE dynasties ( id TEXT PRIMARY KEY, name TEXT NOT NULL, start_year INTEGER, end_year INTEGER, description TEXT, unique_features JSONB, -- 特色科技、特殊政策等 historical_events JSONB -- 历史事件列表 ); -- 国家/政权表 CREATE TABLE nations ( id TEXT PRIMARY KEY, dynasty_id TEXT REFERENCES dynasties(id), name TEXT NOT NULL, starting_year INTEGER, resources JSONB, -- 初始资源 geography JSONB, -- 地理信息 technologies JSONB, -- 初始科技 factions JSONB -- 初始派系 ); -- 君主信息表 CREATE TABLE monarchs ( id TEXT PRIMARY KEY, nation_id TEXT REFERENCES nations(id), name TEXT NOT NULL, birth_year INTEGER, personality JSONB, -- 性格特征、能力值 traits TEXT[] -- 特殊特质 ); -- 历史事件库表 CREATE TABLE historical_events ( id TEXT PRIMARY KEY, dynasty_id TEXT REFERENCES dynasties(id), year INTEGER, event_type TEXT, -- 必发/概率/玩家触发 title TEXT, description TEXT, conditions JSONB, -- 触发条件 effects JSONB, -- 影响效果 choices JSONB, -- 可选决策 historical_outcome TEXT ); -- 政策库表 CREATE TABLE policies ( id TEXT PRIMARY KEY, name TEXT NOT NULL, category TEXT, -- 税收/军事/外交/内政等 dynasty_applicable TEXT[],-- 适用的朝代 parameters JSONB, -- 可调参数 effects_template JSONB, -- 效果模板 historical_examples TEXT -- 历史案例 ); -- Agent 记忆表 CREATE TABLE agent_memories ( id TEXT PRIMARY KEY, game_save_id TEXT REFERENCES game_saves(id), agent_type TEXT, -- Agent 类型 memory_type TEXT, -- short_term / long_term content TEXT, relevance_score FLOAT, -- 记忆重要性评分 created_at TIMESTAMP );

关键技术决策

每个技术选型背后的理由与权衡

🤖 Agent 框架：CrewAI
  • 为什么不用 LangChain？CrewAI 专攻多 Agent 协作，有明确的角色分工和层级管理，更适合模拟朝廷官员
  • 核心优势：内置 Process.hierarchical 支持，天然适合"皇帝→宰相→各部"的层级结构
🧠 LLM：本地+云端双模式
  • 本地模型：Qwen-7B/14B（中文能力强，可离线运行，无 API 成本）
  • 云端模型：Claude/GPT-4（质量更高，适合演示和评测）
  • 配置切换：在 config.py 中一键切换，无需改代码
🗃️ 数据库：SQLite + PostgreSQL
  • 开发/测试：SQLite 无需配置，单文件数据库
  • 生产环境：PostgreSQL 支持复杂查询、JSONB、并发
📡 通信：WebSocket + REST
  • WebSocket：实时推送事件、Agent 讨论状态、回合推进通知
  • REST API：存档/读档、查询历史百科、获取朝代信息等
🎮 游戏设计决策

回合制设计

  • 1 回合 = 1 年：符合历史事件节奏，玩家有足够思考时间
  • 加速模式：可连续执行多个回合，跳过和平时期

难度曲线

  • 新手：宋朝（内政为主，外患较少）
  • 进阶：明朝（内外压力并存）
  • 硬核：晚清（积贫积弱，列强环伺）

历史改变机制

  • 分歧点：关键历史事件有分支选项（如玄武门之变可选支持/反对）
  • 蝴蝶效应：小决策累积可产生重大影响
  • 历史修正力：改变越大，随机补偿事件概率越高

教育系统

  • 事件解析：每发生历史事件提供"历史背景"按钮
  • 知识收集：完成事件后解锁百科条目
  • 成就系统：达成历史知识点收集成就

风险与应对策略
风险影响应对策略
LLM 响应延迟用户体验下降使用缓存、异步处理、本地模型优化
Agent 输出不稳定决策建议不可靠强化提示词工程、添加输出验证层
游戏平衡性游戏性受损多轮测试、数据驱动调整
中文支持不足对话质量低优先使用中文能力强的模型（Qwen 等）
内容量不足重复感强分阶段填充、考虑程序化生成
