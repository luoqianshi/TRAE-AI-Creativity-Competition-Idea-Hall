03 / 03

边做边看，不是想完再做 — §1.5 行动-反馈循环

Cursor 3 / Codex 是"输任务 → Agent 内部想很久 → 一次性返回"。我们是"改一行就跑一下 → 看到反馈 → 决定下一步"。每个动作都有中间结果，过程可见，失败是反馈的一部分，从错误里当下就记。

§ 03

不是"AI 多能干"，是"电脑不卡了"。

32GB 内存的开发机，开 1 个 Cursor + 2 个 VSCode + Docker + 浏览器就开始卡了。AI 工具的"体积焦虑"是真实存在的、被忽略的痛点。Tauri 官方与多家 2026 年独立实测都给出可复现的数据 [1][2]。

§ 04
为什么要做这个

我们看见了什么真实的事。

五个来自设计文档 §0.1 的真实故事——v1 失败的五个具体维度，每个都对应 v2 的解法。

Story 01

v1 失败：模仿人脑的形式，丢了人类工作的本质

设计文档 §0.1 的自我解剖

我们一开始堆了很多听上去很"像大脑"的东西：七层记忆（MEMORY/ROUTING/SOUL/INTUITION/SCORES.db/SESSIONS/DAYDREAMS）、艾宾浩斯公式精确衰减、Light/REM/Deep 三阶段睡眠引擎（凌晨 3 点跑）、GEPA 进化、能力翻译矩阵（让 Expert 之间能"互相理解"）、三回合辩论委员会（每次写代码都开评审会）。

听起来很"AGI"，用起来很蠢——Agent 越用越慢、Token 越烧越多、用户等得越久。

▍ 六个 v1 核心问题（设计文档原文）：手脑分离 / 默认慢思考 / 多 Agent 缝合 / 学习靠批处理 / 横向堆复杂度 / 形似神不似

Story 02

v1 推翻的核心理念：飞机不是靠拍翅膀飞的

设计文档 §0.1 末尾的金句

v2 推翻 v1 的设计原则：复刻人脑机制的形式不重要，复刻人类工作的本质才重要。

人类工作的本质是什么？看反馈、踩坑就记、卡了就问、慢慢熟练——不是七层抽屉 + 凌晨批处理。

飞机不是靠拍翅膀飞的。智能的本质不是复刻神经元放电。

Story 03

手脑分离：Expert 是"被调用的函数"

设计文档 §0.1 v1 的第一个核心问题

v1 设计里，Expert 是"输入任务 → 返回结果"的黑盒函数。这等于把"做"和"想"硬切成两段——人的手和脑是实时联动的，边做边想边调整，不是想完再做。

我们的解法是行动-反馈循环（§1.5）：每个动作几秒到几十秒，有明确反馈。不是"实现登录功能"，是"先改 auth.py 第 42 行的变量名"。

Story 04

默认慢思考：每个请求都走 Gating Network

设计文档 §0.1 v1 的第二个核心问题

v1 的 Gating Network 每步都评估置信度、判断复杂度、决定路由。人 95% 时间在心流状态直接做，只有卡壳才停下来想——v1 是"选择困难症"，每步都纠结。

我们的解法是流畅性（§1.6）：默认在执行模式，事件驱动才打破流畅（报错 → debug，卡住 → 搜索/提问，复杂 → 规划，危险 → 质疑）。写一行代码不用等 3 秒。

Story 05

学习靠批处理：被 bug 卡了当下不记

设计文档 §0.1 v1 的第四个核心问题

v1 的学习靠"睡眠引擎凌晨 3 点跑三阶段流水线"。人被 bug 卡了 2 小时当下就记住了，不需要等睡觉——v1 把"学习"做成了异步批处理，丢了"当下就长记性"的本质。

我们的解法是刺痛即学习（§1.8）：报错卡了很久 → 立刻写一条带情绪标记的教训；被纠正了 → 立刻记；任务结束 → 1-2 分钟回顾，沉淀记忆。当下记住，闲时巩固。

§ 05
能帮助人做什么

六个真实的使用场景。

来自设计文档 §1 的设计意图——这些场景不是想象，是类人 AI 11 个核心概念（主 Agent、记忆、行动-反馈循环、思维模式……）组合出来的真实工作流。

场景 01 · 长期项目陪伴

用户故事

3 年期项目，代码量 8 万行。每个项目跟 AI 重复三遍的话。

没有类人AI

每次开新对话，AI 都不记得"项目用 pnpm"、"认证用 JWT refresh token"。你得每次重讲一遍。

有了类人AI

记忆网络里有一条"项目约束"节点群；每次开新对话，Agent 联想式激活相关节点；你输"加个 SSO"，Agent 不再问"项目用啥框架"，直接开干。

▍ 帮到：维护 1 个以上长期项目的开发者（约 30% 目标用户）

场景 02 · 电脑不卡了

用户故事

前端 + 后端 + 移动端三个项目同时迭代。Docker 跑数据库，再开 Chrome。

没有类人AI

开三个 Cursor 窗口 = 3.6GB 内存没了。系统开始转风扇。

有了类人AI

开三个类人 AI = 0.4GB 内存。32GB 机器还能再开 Docker、Chrome、Slack、IDE 都不卡。电脑不卡了，人就舒服了。

▍ 帮到：同时维护多个项目的开发者、Docker 重度用户（约 60% 目标用户）

场景 03 · 坑不会再踩第二遍

用户故事

上次在生产环境踩了某个依赖版本的坑，卡了 2 小时。

没有类人AI

半年后再遇到同样依赖的升级，AI 啥都不知道，你再踩一遍。

有了类人AI

主 Agent 立刻记一条带情绪标记（-3，痛）的教训："flask-cors 3.0.x 跨域配置回归"；这条教训连到"依赖升级高风险"；半年后遇到，Agent 联想激活，告诉你"上次就是它"。

▍ 帮到：维护老项目、需要频繁做依赖升级的开发者

场景 04 · 过程可见，能随时打断

用户故事

让 AI 重构一个老模块。

没有类人AI

AI 内部跑 5 分钟，过程不可见。最后说"完成了"，你 review 一下发现它把单元测试全删了。

有了类人AI

每改一行代码，动作日志实时显示（"修改 auth.py 第 42 行"）；跑测试结果立刻显示；你看到"它在删测试"——立刻打断。

▍ 帮到：对代码质量有要求的资深开发者

场景 05 · 卡住就问，不装懂

用户故事

让 AI 接入一个它没见过的内部 API。

没有类人AI

AI 自己瞎猜，编一个看起来合理的接口签名，30 分钟后你发现全是错的。

有了类人AI

Agent 不知道这个 API → 切搜索模式，去查文档；搜不到 → 切提问模式，直接问你；你回答完继续做，不会瞎编。

▍ 帮到：在企业内部项目、私有框架、特殊架构上工作的开发者

场景 06 · 装得下、跑得动

用户故事

老旧笔记本（8GB 内存），想用 AI 编程但装不了 Cursor。

没有类人AI

装 Cursor 启动就 500MB，开 VSCode 再开浏览器直接转圈。

有了类人AI

安装包 10-15MB，老机器也能装；空闲内存 80-150MB，8GB 机器也能跑；启动 0.5 秒，不用等。

▍ 帮到：学生、初级开发者、8GB 内存老机器用户（约 10% 目标用户）

§ 08
诚实的产品边界

不编故事：哪些问题我们不解决。

LLM 行业级的难题，我们不假装能解决。我们能做到的，写在右边。

▍ 不解决 / 能做到

不解决 ✕

  • AI 装懂 —— LLM 行业无解，置信度不能消除幻觉
  • AI 不知道边界 —— 只能做到"诚实说不知道"
  • AI 完全自主规划长任务 —— 我们设了"卡壳就问人"的退出
  • AI 理解用户情绪 —— 主流桌面 Agent 都不做

能做到 ✓

  • 真轻：10-15MB 安装包，80-150MB 空闲内存 [1][2]
  • 真记得住：记忆网络带情绪和关联，第 N 次能联想
  • 真不卡：Rust 原生，32GB 机器开 5 个也只占 0.7-1GB
  • 真可见：每步动作都有日志，过程透明
§ 09
11 个核心概念

设计文档里每一个，都已实现或正在实现。

不是营销概念，是设计文档的 11 个核心概念，每一项都有对应章节（§1.1 - §1.11）。设计文档 600+ 行，12 张图表，发布在 humanoid-system/docs/DESIGN_v2_类人AI系统.md。

§ 1.1

主 Agent

统一身份、统一记忆、统一声音。"我"自己做 80-90% 的活，不是路由器。

§ 1.2

子 Agent

按需召唤，不是常驻。安全、DevOps、架构评审、搜索……用完即走。

§ 1.3

思维模式

执行 / 感知 / debug / 规划 / 质疑 / 提问 / 搜索 / 学习 / 审议，9 种事件驱动切换。

§ 1.4

环境

终端、文件、浏览器、用户。环境是认知延伸，不是外部工具。

§ 1.5

行动-反馈循环

小步快跑，每步都有中间结果。失败是反馈的一部分。

§ 1.6

流畅性

默认直接做。95% 时间心流执行，不每步算分数。

§ 1.7

记忆

节点 + 关联边 + 情绪标记 + Core 评分 + 慢遗忘。Obsidian 式力导向图。

§ 1.8

学习

刺痛即学（当下立刻记）+ 完成回顾 + 闲时巩固。不等睡觉。

§ 1.9

方案审议

用户显式触发 + Agent 提议。子 Agent 是顾问不是投票者，用户拍板。

§ 1.10

元认知 / 边界感

"我不知道"比"我有 85% 置信度"更可信。

§ 1.11

人格一致性

子 Agent 不直接面对用户。SOUL.md 定义"我是谁"。

§ 1.12

1.1 → 1.11

11 个概念不是平铺，是一张网：主 Agent 在环境里通过行动-反馈循环做事，记忆网络记下每一次刺痛和惊喜，思维模式决定现在该快还是该慢。

§ 10
技术栈

Rust 做能做的，Python 只做不得不做的。

▍ Rust 写

桌面壳Tauri 2.0
Agent 核心主 Agent、子 Agent 调度、模式切换
记忆系统rusqlite + sqlite-vec
Embeddingcandle（Rust 原生推理）
终端std::process + portable-pty
浏览器chromiumoxide（CDP）
安全沙箱命令过滤 / 路径保护 / 权限管理
前端React + TypeScript + Cytoscape.js

▍ Python 只做

LLM API 代理FastAPI
Claude 调用Python SDK 成熟
Ollama 调用本地模型预处理
SSE 流式响应转发到 Rust Agent 核心
无业务逻辑纯代理 / 无状态
无记忆记忆都在 Rust 侧
无 Agent 逻辑只管 prompt 进，文本出
无环境交互终端/文件/浏览器都在 Rust

分工原则：性能关键、安全关键、状态管理 → Rust；只跟 LLM SDK 打交道 → Python。这样既拿到 Rust 的性能和安全，又不用重写 LLM 生态。
