01 / 问题

专业长文档写作的三重困境

Pain Points
i

人工起草，慢且依赖经验

一份审计报告从零起草需 2-3 天，格式规范记不住，结构组织依赖个人经验。 数据与报告割裂，需要手动来回对照 Excel 和文档，重复劳动严重。

ii

AI 一键生成，专业度不够

通用 AI 生成的报告结构散、专业术语不准、缺乏行业判断。 更致命的是无法定向修改——改一句话往往要重写整段，版本反复推翻。

iii

协作混乱，无法追溯

多人协作时版本混乱，中断后工作丢失，无法追溯每个阶段的修改决策。 合规性、可追溯性在专业文档中是硬要求，但传统工具几乎无支持。

03 / 架构

精密如仪器的工程实现

Architecture

Plan-Execute-Review 多子代理

采用多子代理架构，规划、执行、审查分离。 write_groups 阶段支持多分组并行调度，显著缩短长文档生成时间。

Multi-AgentParallel SchedQuality Review

三层 RAG 上下文架构

全量上下文 + RAG 检索 + 摘要压缩三层联动， 在 128K 上下文窗口内兼顾完整性与 token 效率。

Full ContextRAG RetrievalSummary Compact

Skill 驱动的模板系统

每个写作场景对应一个 TEMPLATE.md（YAML frontmatter + Markdown）， 定义阶段、质量维度、任务图。新增场景只需加模板，不改代码。

YAML ConfigTask GraphQuality Dimensions

状态持久化与断点续传

基于 Dify KV Storage 的状态管理，schema 版本化，支持自动迁移。 流式生成每段增量保存，中断后可恢复，不丢工作。

KV StorageSchema VersioningIncremental Save

句子级 PatchEngine

定向修改不重写整段。LLM 生成 patch，精准应用到目标句子， 保留已确认内容，避免"改一处动全身"。

Sentence-LevelTargeted PatchPreserve Confirmed

三层意图路由

L1 关键词规则（5 个确定性操作）→ L2 轻量 LLM → L3 Function Calling。 精简 L1 后意图准确率从 54% 提升至 91.67%。

05 / 价值

效率与社会的双重回报

Value

效率提升

  • 2-3 天 → 2-3 小时：单份审计报告耗时压缩 90%+
  • 断点续传：中断后可恢复，工作不丢失
  • 句子级修改：改一句话不用重写整段
  • 数据自动注入：不用手动复制粘贴数据
  • 并行调度：多分组并行生成，长文档更快

社会价值

  • 降低门槛：中小机构、基层单位也能产出合规报告
  • 提升透明度：审计报告是社会监督的重要载体
  • 资产安全：盘存报告质量关乎资产管理 integrity
  • 公文规范：减少格式错误与合规风险
  • 可追溯性：每个阶段的修改决策可追溯
