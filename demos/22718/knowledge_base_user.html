什么是「观察者模式」(Observer Pattern)？

点击翻转查看答案
答案

观察者模式是一种行为设计模式，定义了对象之间的一对多依赖关系。当一个对象（被观察者/主题）状态改变时，所有依赖于它的对象（观察者）都会自动收到通知并更新。

// 典型应用：事件监听、发布订阅、MVC中的视图更新

微服务架构设计模式：从单体到分布式的演进之路

2026年5月28日 · 阅读约 15 分钟 · 5 个链接

在软件架构的演进历程中，从单体应用到微服务架构的转变是一个重要的里程碑。这种转变不仅仅是技术层面的拆分，更是对业务边界、团队组织和系统复杂性的重新思考。

1. 服务拆分原则

按业务领域边界（Bounded Context）进行拆分，遵循单一职责原则。每个服务应该围绕一个完整的业务能力构建，包含从用户界面到数据存储的所有层次。

常见拆分维度：

  • 按业务功能（用户服务、订单服务、支付服务）
  • 按数据变更频率（静态数据 vs 动态数据）
  • 按读写比例（CQRS 模式）

2. 通信模式

同步通信

REST API 是最常见的同步通信方式，简单通用，但存在级联失败风险。gRPC 提供了更高性能的选择，适合内部服务通信。GraphQL 则允许客户端驱动查询，减少过度获取。

异步通信

消息队列（RabbitMQ / Kafka）和事件总线（Event Bus）是异步通信的核心组件。它们实现了服务的解耦，提高了系统的弹性和可扩展性。

异步通信的本质是接受最终一致性，用延迟换取弹性和可用性。

3. 数据一致性

在分布式环境下，放弃 ACID 的强一致性，采用 BASE 理论：

Basically Available, Soft state, Eventually consistent

Saga 模式是实现最终一致性的常用方案，分为两种方式：

  • 编排式 Saga：中央协调器管理流程
  • 协同式 Saga：服务间通过事件自发协作
