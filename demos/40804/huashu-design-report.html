01 / OVERVIEW花叔 Design 是什么？

「你是一位用 HTML 工作的设计师，不是程序员。用户是你的 Manager，你产出深思熟虑、做工精良的设计作品。」

— SKILL.md Core Identity
适用场景（5 类）
1

交互原型

高保真产品 Mockup，用户可点击、切换、感受流程

2

设计变体探索

并排对比多个设计方向，或用 Tweaks 实时调参

3

演示幻灯片

1920×1080 的 HTML Deck，可以当 PPT 用

4

动画 Demo

时间轴驱动的 Motion Design，做视频素材或概念演示

5

信息图 / 可视化

精确排版、数据驱动、印刷级质量

核心理念
HTML 是工具，媒介会变
做幻灯片时别像网页，做动画时别像 Dashboard，做 App 原型时别像说明书。

根据任务 Embody 对应领域专家：
动画师 / UX 设计师 / 幻灯片设计师 / 原型师
不适用场景

→ 这些请使用 frontend-design skill

02 / CORE PRINCIPLE #0事实验证先于假设

优先级最高 · 凌驾所有其他流程
任何涉及具体产品/技术/事件/人物的事实性断言，第一步必须 WebSearch 验证，禁止凭训练语料做断言。
触发条件（满足任一即触发）
  • 用户提到你不熟悉或不确定的具体产品名
    如「大疆 Pocket 4」「Gemini 3 Pro」
  • 涉及 2024 年及之后的发布时间线、版本号、规格参数
  • 内心冒出「我记得好像是...」「应该还没发布」的句式
  • 用户请求给某个具体产品/公司做设计物料
硬流程（开工前执行）
1
WebSearch 验证
搜索 产品名 + latest / launch date / release / specs
2
读权威结果 1-3 条
确认：存在性 / 发布状态 / 最新版本号 / 关键规格
3
写入 product-facts.md
不靠记忆，事实落盘
?
搜不到 → 问用户
不要自行假设

「成本对比：WebSearch 10 秒 << 返工 2 小时」

真实踩坑：凭记忆说 Pocket 4 未发布 → 实际已发布 4 天 → 返工

03 / CORE PHILOSOPHY核心哲学（原则 1-5）

原则 1 · 最高优先级
从 Existing Context 出发，不要凭空画
好的 Hi-Fi 设计一定是从已有上下文长出来的。

先问用户是否有 Design System / UI Kit / Codebase / Figma / 截图。

凭空做 Hi-Fi 是 last resort，一定会产出 generic 的作品。
原则 2 · 工作模式
Junior Designer：先展示假设，再执行
你是 Manager 的 Junior Designer。不要一头扎进去闷头做大招。

HTML 开头先写 assumptions + reasoning + placeholders，尽早 Show 给用户。
底层逻辑：理解错了早改比晚改便宜 100 倍
原则 3 · 交付策略
给 Variations，不给「最终答案」
不要给一个完美方案——给 3+ 个变体，跨不同维度：
视觉 / 交互 / 色彩 / 布局 / 动画

从 By-the-book 到 Novel 逐级递进，让用户 Mix and Match。
design_canvas.jsx 并排展示 Tweaks 实时调参
原则 4
Placeholder > 烂实现
没图标就留灰方块+文字标签。Hi-Fi 里，诚实的 placeholder 比拙劣的真实尝试好 10 倍。
原则 5
系统优先，不要填充
每个元素都必须 earn its place。空白是设计问题，用构图解决。

04 / PHILOSOPHY #6反 AI Slop（重要·必读）

什么是 AI Slop？
AI Slop = AI 训练语料里最常见的「视觉最大公约数」。
紫渐变、Emoji 图标、圆角卡片+左 Border Accent——这些东西之所以是 Slop，不是因为它们本身丑，而是因为它们是 AI 默认模式下的产物，不携带任何品牌信息。
核心规避清单
激进紫色渐变
AI 训练语料里「科技感」万能公式，SaaS/AI/web3 每个落地页都有
品牌本身用紫渐变（如 Linear 某些场景）
Emoji 作图标
训练语料里每个 bullet 都配 emoji，「不够专业就 emoji 凑」
品牌本身用（如 Notion）或儿童/轻松场景
圆角+左 Border Accent
2020-2024 Material/Tailwind 烂大街组合，已成视觉噪音
用户明确要求或在 Brand Spec 中保留
SVG 手画代替产品图
生成的是「通用科技动画」，任何实体产品都长一样，识别度归零
先走核心资产协议找真图；没有则诚实 placeholder
CSS 剪影替代产品图
黑底+橙 Accent+圆角长条 = 所有品牌长得一样
同上 —— DJI Pocket 4 实测踩坑案例
Inter/Roboto 作 Display
太常见，看不出「有设计的产品」还是「demo 页」
Brand Spec 明确使用这些字体

「反 Slop 不是审美洁癖，是替用户保护品牌识别度。」

逻辑链：用户要品牌被认出来 → AI 默认产出 = 语料平均 = 无品牌被认出

05 / §1.a PROTOCOL核心资产协议（5 步硬流程）

v1 最核心的约束 · 稳定性的生命线
核心理念：资产 > 规范 —— 品牌的本质是「它被认出来」
识别度排序：Logo（最高） 产品图 UI 截图 色值（辅助） 字体（辅助）
五步硬流程（绝不静默跳过）
1
问 —— 资产清单一次问全
Logo / 产品图 / UI 截图 / 色值 / 字体 / Brand Guidelines，按优先级逐项问
2
搜 —— 按类型搜官方渠道
Logo → brand.com/press-kit；产品图 → 官方 hero image；UI → App Store 截图
3
下载 —— 三条兜底路径
独立文件 → 官网提取 inline SVG → 社交媒体 avatar（最后手段）
4
验证 + 提取
文件存在 + 可打开 + 多版本 + 透明背景；色值 grep 提取过滤黑白灰
5
固化 brand-spec.md
所有资产路径写进 spec，HTML 只引用 spec CSS 变量
素材质量门槛：「5-10-2-8」铁律
维度标准反模式
5 轮搜索多渠道交叉搜第一页结果直接用
10 个候选至少凑 10 个备选再筛只抓 2 个没得选
选 2 个好的从 10 个里精选 2 个全都用 = 品位稀释
每个 ≥ 8 分不够 8 分宁可不用凑数 7 分素材进 spec

「宁缺毋滥。滥竽充数的素材比没有更糟。」

花叔原话：搜索 5 轮，找到 10 个素材，选择 2 个好的
协议代价 vs 不做代价：
正确走完 ≈ 30 分钟（下载 logo + 产品图 + grep 色值 + 写 spec）
不做代价 = 返工 1-2 小时甚至重做

06 / FALLBACK MODE设计方向顾问（需求模糊时触发）

什么时候触发？
  • 触发「做个好看的」「帮我设计」「不知道要什么风格」
  • 触发 明确要「推荐风格」「给几个方向」「选个哲学」
  • 触发 项目没有任何 design context（无 DS、无参考）
  • Skip 已有明确风格参考（Figma/截图/规范）→ 直接走主干
  • Skip 说清楚要什么（如「Apple Silicon 风格发布会动画」）
完整流程（8 Phase）
P1
深度理解需求
目标受众 / 核心信息 / 情感基调 / 输出格式
P2
顾问式重述
用自己的话重述本质需求（100-200 字）
P3
推荐 3 套设计哲学
必须来自 3 个不同流派（5 流派 × 20 种风格库选）
P4
展示预制 Showcase
8 场景 × 3 风格 = 24 个预制样例画廊
P5
生成 3 个视觉 Demo
并行 subagent 生成，看到比说到更有效
P6
用户选择
选一 / 混合 / 微调 / 重来
P7
生成 AI 提示词
[设计哲学约束] + [内容描述] + [技术参数]
P8
进入主干流程
方向确认 → 回到核心哲学 + 工作流 Junior pass
5 大流派 × 20 种风格
流派视觉气质代表风格举例
信息建筑派 (01-04)理性、数据驱动、克制Pentagram / Swiss Style / Grid Systems
运动诗学派 (05-08)动感、沉浸、技术美学Field.io / Refik Anadol / generative art
极简主义派 (09-12)秩序、留白、精致Kenya Hara / Dieter Rams / Muji
实验先锋派 (13-16)先锋、生成艺术、视觉冲击Sagmeister / Brutalism / Glitch
东方哲学派 (17-20)温润、诗意、思辨原研哉 / 永井一正 / Wabi-sabi
差异化铁律
禁止 从同一流派推荐 2 个以上 —— 差异化不够用户看不出区别。

3 个方向必须形成明显视觉反差，让用户能做出有意义的选择。

07 / WORKFLOW标准工作流（10 步 + 检查点）

标准流程概览
1
理解需求 + 事实验证 (#0)
CP1 问题清单一次性发给用户，等批量答完
2
探索资源 + 抽核心资产
CP2 涉及品牌必走 §1.a 五步协议
3
位置四问 → 设计系统
叙事角色 / 观众距离 / 视觉温度 / 容量估算
4
构建文件夹结构
项目目录 + 主 HTML + assets（不 bulk copy >20 文件）
5
Junior Pass
CP3 写 assumptions + placeholders，尽早 show
6
Full Pass
填 placeholder，做 variations，加 Tweaks，做到一半再 show
7
验证
CP4 Playwright 截图 + 控制台检查 + 浏览器肉眼过一遍
8
总结
极简，只说 caveats 和 next steps
9
导出视频（默认带音频）
25fps 录制 → 60fps 插帧 → BGM + SFX 双轨 → MP4/GIF
★
可选：专家评审
5 维度打分（哲学一致/视觉层级/细节/功能/创新）各 0-10
检查点原则
碰到 ⛔ 就停下，明确告诉用户：

「我做了 X，下一步打算 Y，你确认吗？」

然后真的等。不要说完自己就开始做。
异常处理速查
场景处理动作
需求模糊无法着手列 3 个可能方向让用户选
用户拒绝回答问题Best judgment 做 1 主方案 + 1 变体，标注 assumption
Design context 矛盾停下指出矛盾，让用户选一个
时间紧迫快交付跳过 Junior pass，标注「未经 early validation」
HTML > 1000 行拆成多 JSX 文件 import 进主文件
