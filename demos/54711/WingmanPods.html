Architecture

四通道协同技术架构

HFP音频上行 + A2DP音频下行 + BLE GATT指令 + HID外设执行，构建手机与耳机之间的AI闭环。

🎤

音频上行通道

耳机麦克风通过HFP协议将用户语音实时传输到手机App，进行ASR语音识别。

HFP 1.7 · mSBC编码 · 16kHz
🔊

音频下行通道

AI TTS合成语音通过A2DP高质量音频通道回传到耳机扬声器，自然语音反馈。

A2DP · SBC/AAC · 44.1kHz
👁️

视觉感知通道

MediaProjection API实时截屏，VLM视觉模型理解屏幕UI元素，为Agent提供"眼睛"。

MediaProjection · VLM · VirtualDisplay
⚡

指令执行通道（核心创新）

BLE GATT下发JSON操作指令，耳机MCU解析后通过HID键鼠协议注入手机，绕过系统权限。

BLE GATT → HID Keyboard/Mouse

Technical Moat

核心技术壁垒

为什么这不是一个简单的"耳机+App"组合？三个关键创新点构建了难以复制的技术护城河。

01
外设化执行通道
将AI操作能力"外包"给耳机HID外设，从OS视角看只是一个蓝牙键鼠，天然绕过Accessibility系统权限
02
四协议融合固件
单耳机芯片同时跑HFP+A2DP+HID+BLE GATT四协议栈，MCU指令解析延迟<100ms
03
闭环VLM Agent
Vision-in-the-Loop架构，VLM实时理解屏幕+决策+执行+验证，真正实现任意App的自由操作
🔐

绕过系统权限的架构巧思

传统手机Agent（如AppAgent、AutoGPT手机版）都依赖Accessibility Service来读取UI树和注入操作，但这是系统级权限，需要用户在设置中手动开启，且Google/厂商对其使用有严格限制。Wingman Pods的核心创新在于：手机App自身完全不执行操作，而是将操作指令编码后通过BLE发给耳机，耳机以"蓝牙键盘/鼠标"的合法HID身份发回操作。Android/iOS对蓝牙HID设备是原生支持且默认信任的，这就从架构层面绕过了权限壁垒。

🔄

观察→思考→行动→验证：VLM闭环

不同于Siri等基于Intent的语音助手只能执行预设动作，Wingman Agent采用VLM（视觉语言模型）驱动的闭环执行：截屏观察 → VLM推理下一步 → HID执行 → 再次截屏验证结果。这种"人类玩手机"式的操作范式意味着只要是人类能通过触屏完成的操作，AI都能完成，不受App类型、版本更新的限制。

🛡️

内置安全护栏

自动解锁+自动操作带来便利的同时，我们设计了多层安全机制：① 支付/转账/删除等高危操作自动暂停并语音确认；② 解锁密码存储在耳机端安全元件(SE)中，不上传云端；③ 操作日志全程可追溯，支持"紧急停止"语音指令；④ 耳机取下检测(IR传感器)自动暂停Agent。

⚡ 兼容性风险

部分厂商ROM对MediaProjection后台截屏有限制。

✓ 对策：一次前台授权后建立前台服务+VirtualDisplay持续采集；兼容主流厂商（华为/小米/OPPO/vivo）

⏱️ 延迟问题

VLM云端推理+BLE传输链路可能导致操作延迟。

✓ 对策：端侧轻量VLM做UI元素检测+云端做任务规划分级推理；操作指令BLE传输<50ms，HID执行<10ms

🔋 功耗优化

四协议并发运行对耳机续航是挑战。

✓ 对策：BLE平时保持低功耗监听，语音交互时才激活HFP/HID；VLM推理在手机端进行，耳机MCU仅做指令转发

🎯 演示可行性

大赛阶段需要可运行Demo。

✓ 对策：双手机方案（一部跑Agent+GATT Client，一部跑HID Device+GATT Server），完全复用现有Wingman原型代码
