// 01 · Industry Insight

B2B 售前正在从 "专家手工交付"
进入 "知识驱动交付"。

AI 在售前团队的价值，不是替代专家聊天，而是把专家经验、产品知识、行业打法和交付模板连接成可复用流程。

01
知识碎片化

资料很多，答案不等于方案

产品文档、销售 PPT、API 说明、竞品口径分散在不同系统，售前要把它们重新组织成客户能理解的方案。

02
交付标准化

客户要的是正式材料

从一句问题到一份需求分析、ROI 或 POC 计划，中间需要判断、取舍、结构化和审校。

03
经验资产化

资深经验需要被复制

优秀售前的判断逻辑和表达口径，应当沉淀进知识库与 Agent 流程，而不是只留在个人脑中。

// 02 · Trend

企业 AI 从 "能问答" 走向 "能闭环"。

下一阶段的企业 AI 产品会更像工作台：接收业务上下文，调动工具和知识，输出可审计、可交付的结果。

从 Chat 到 Workflow

单轮问答不能支撑复杂售前交付，需要多步骤意图路由、Agent 协作和质量门禁。

从文档库到知识底座

知识库不再只是搜索入口，而是 Agent 的证据来源、模板来源和反馈回流对象。

从通用模型到行业 Agent

模型负责生成，行业 Agent 负责理解场景、组织流程、控制风险和沉淀经验。

// 03 · Pain Point

售前团队卡住的不是灵感，
而是重复交付链路。

真实售前现场里，最大消耗来自资料查找、口径拼接、文档初稿和反复审校。

1

知识找得到，但难以直接交付

资料需要被重新组织成客户语言、行业方案和可执行路径。

2

竞品口径不稳定

同一问题在不同专家之间表达不同，容易影响客户信任。

3

方案和 POC 重复劳动高

每次都从空白文档开始，消耗资深售前大量低杠杆时间。

4

新人无法快速复用经验

新人能读知识库，但不知道哪些内容该组合成一份可交付材料。

// 04 · Core Goal

让售前只做高价值判断，
把重复交付交给 Agent。

// Mission

构建一个通用 B2B 售前工作台

以一套验证过的多 Agent 平台为能力样板，通过可替换知识库和多入口 Agent，把客户问题自动转化为正式交付材料。

★ 飞书华南区售前团队是首例落地客户，已服务 30+ 解决方案专家。
回答准答案必须来自知识库，有来源、有边界。
交付快从客户输入到文档初稿，尽量压缩到分钟级。
口径稳竞品、价格、实施路径统一由知识库和 Agent 控制。
经验沉淀专家反馈回流，持续提升下一次交付质量。

// 06 · Core Capability

3 类真实入口，
跑同一套能力底座。

企业 IM Bot 负责即时协作，fsx CLI 负责批量交付，MCP Server 负责开放工具。每个入口都能落到具体消息、命令和工具调用，并最终生成企业级文档。

企业 IM Bot 入口

在企业 IM 里直接把问题变成可审的答案。

适合 Discovery 后追问、竞品异议和会前准备。Bot 不只是答一句，而是把上下文接进流水线，回一张能继续协作的卡片。

fsx CLI 入口

给售前专家一个能批量出稿的命令行。

适合本地准备、批量整理和快速复盘。CLI 把客户材料变成结构化文档，直接走知识库和 Agent 流程。

// 终端命令
# 知识问答
fsx ask "OKR 怎么落地"

# 客户需求结构化
fsx analyze "客户A" --industry 制造 --scale 800

# 竞品对比
fsx compete "钉钉"
知识问答需求分析竞品对比
MCP Server 入口

把知识检索和机会工具开放给外部 Agent。

适合 IDE、外部 Agent 和平台集成。工具调用保持同源，既能查知识，也能建机会、发消息、读文档。

// 工具调用

// 09 · Tech Innovation

技术难点不在生成，
而在可信、可控、可复用。

🎯

知识约束生成

答案和方案必须回到知识库来源，降低泛化模型在专业售前场景里的幻觉风险。

🔗

多 Agent 分工

用不同 Agent 处理需求、方案、竞品和评审，让每一步都有清晰职责和可测试边界。

✅

质量门禁

SAReviewer 对需求和方案做两阶段审校，不合格产物可驳回重做。

🔌

多入口同源

Bot、CLI、MCP 共享同一 Pipeline，避免不同入口能力割裂。

🧠

飞轮学习

专家反馈记录到系统中，影响后续检索、排序和口径沉淀。

🚀

工程化上线

具备长连接 Bot、Webhook 异步、checkpoint、指标和上线 Runbook，方便企业落地。
