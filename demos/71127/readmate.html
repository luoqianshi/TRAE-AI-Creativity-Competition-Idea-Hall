01 / 痛点

屏幕上下文断层

读长文章时，前面的内容已经滚走，当前屏幕只剩一句话。复制给 AI，它也答不准——因为它没有上下文。这就是"屏幕上下文断层"。

传统方式
30-120s
  1. 1选中文字
  2. 2复制 (Ctrl+C)
  3. 3切到 ChatGPT
  4. 4粘贴 + 描述背景
  5. 5等回答
vs
ReadMate
2s
  1. 1选中文字
  2. 2点击「问一问 Agent」

03 / 场景

真实使用场景

从读文档到看代码，从刷文章到看图——遇到不懂的，选中即问。

SCN_01 技术文档卡壳
"RSC 通过 use() hook 与 Suspense 边界协同..."
当 use() 读到的 Promise 未 resolve 时，React 自动找到最近的 <Suspense> 显示 fallback。文档前面"Streaming SSR"提过这机制。
SCN_02 陌生代码不懂
result, err := client.HSet(ctx, "user:123", "name", "Alice").Result()
Redis Hash 操作。HSet 往 user:123 写字段，.Result() 是 go-redis 惯用写法，返回 (字段数, error)，这里 result=2。
SCN_03 生僻术语
"这家公司 LTV/CAC 比值已跌破 1，烧钱模式难以为继。"
LTV=用户终身价值，CAC=获客成本。比值<1 意思是"拉一个用户花的钱 > 这个用户能赚的钱"，每拉一个亏一个。
SCN_04 图片选区模式
[Alt+Q 拖框选中量子电路图]
这是 Bell 态制备电路。两个量子比特从 |00⟩ 开始，经 Hadamard + CNOT 制备出 |Φ⁺⟩=(|00⟩+|11⟩)/√2，量子纠缠基本演示。

05 / 架构

分层架构设计

底层复用开源 screenpipe 做记忆引擎，上层自研 PyQt6 交互层——不重复造轮子，聚焦"选中即问"创新交互。

Layer 03 · 上层
交互层 PyQt6
全局选区监听 (pynput + uiautomation) · 浮动按钮 + 多快捷动作菜单 · 系统托盘 + 配置 · Markdown 答案面板
解决"选中即问"交互，screenpipe 未覆盖部分
Layer 02 · 中层
多模型适配层
统一 ask(image, text, question) 接口 · OpenAI GPT-4o / Claude 3.5 / Gemini Vision 可切换 · 本地 Ollama 兜底
用户硬需求：多模型可切换
Layer 01 · 底层
记忆引擎 screenpipe
24/7 事件驱动捕获 · 辅助功能树 + OCR 双策略 · SQLite FTS5 全文索引 · HTTP API (localhost:3030)
