1. 项目概述

1.1 产品定位

药明白是一款面向中老年群体及其家属的智能药品识别与用药管理助手。产品以"一拍即懂、用药安心"为核心理念，通过拍照识别药品信息、语音播报用药说明、智能提醒服药时间三大核心能力，解决老年人看不懂药品说明书、记不住用药方法、容易漏服错服的痛点。

1.2 赛道信息

银发经济与智慧医疗交叉赛道。中国60岁以上人口已超2.8亿，慢病患者约3亿，家庭用药管理需求巨大。目前市场上缺乏专门针对老年人群体用药场景、兼顾易用性与专业性的产品。

2. 需求背景

2.1 社会背景

随着中国老龄化程度加深，老年人用药安全问题日益突出。据统计，超过60%的老年人每天需要服用至少一种药物，而用药错误导致的健康问题占老年住院原因的15%以上。药品说明书字体小、术语多、内容复杂，老年人阅读困难；同时老年人记忆力下降，漏服、错服、重复服药现象普遍。

2.2 用户痛点

  • 看不懂说明书：药品说明书字体极小、医学术语晦涩，老年人难以获取关键用药信息。
  • 记不住用法：多种药品服用时间、剂量各不相同，老年人容易混淆。
  • 容易漏服错服：缺乏有效提醒手段，忘记服药或重复服药的情况频繁发生。
  • 家属无法远程关心：子女不在身边时，无法及时了解父母的用药情况。

2.3 问题影响

用药错误不仅可能导致治疗效果不佳，还可能引发药物不良反应、药物相互作用等严重健康问题，增加医疗负担。同时，老年人因用药困惑产生的焦虑情绪，也严重影响了他们的生活质量和心理健康。

3. 产品目标

3.1 核心目标

让每一位老年人都能轻松、准确地管理自己的日常用药，降低用药错误风险，提升用药依从性，让家属安心。

3.2 阶段性目标

4.2 分层策略

根据用户技术能力和需求差异，产品采用分层设计策略：

  • 基础层：大字体、大按钮、语音交互，面向技术能力弱的老年用户。
  • 进阶层：增加用药记录、家属联动，面向有一定技术能力的用户和家属。
  • 专业层：提供药品相互作用查询、健康报告，面向高需求用户。

5. 核心场景

场景一：新药品识别

角色：张阿姨（68岁，高血压患者）

触发条件：医院开回新药，想了解药品信息和服用方法。

操作流程：

  • 打开"药明白"APP
  • 点击"拍药识药"按钮
  • 对准药品包装盒拍照
  • 系统自动识别药品信息
  • 语音播报药品名称、功效、用法用量

预期结果：张阿姨清楚了解新药信息，知道如何正确服用。

场景二：每日用药提醒

角色：李大爷（75岁，多种慢病）

触发条件：到了每日服药时间。

操作流程：

  • 系统推送语音提醒"该吃降压药了"
  • 李大爷点击提醒查看详情
  • 确认已服药或选择延后
  • 系统自动记录服药时间

预期结果：李大爷按时服药，不漏服不错服。

场景三：家属远程关注

角色：小王（35岁，在外地工作）

触发条件：想关心父母的用药情况。

操作流程：

  • 打开"药明白"家属端
  • 查看父母今日用药记录
  • 收到父母漏服提醒通知
  • 通过电话或微信提醒父母

预期结果：小王即使不在父母身边，也能及时了解并协助管理用药。

6.1 功能架构

模块功能点优先级说明

6.2 核心流程

用户从拍照识别药品到完成用药提醒设置的完整链路如下：

flowchart LR A[拍照] --> B[识别] B --> C[确认] C --> D[播报] D --> E[提醒]

详细说明：

  • 拍照：用户对准药品包装或说明书拍照，系统自动对焦并优化图像。
  • 识别：OCR提取文字信息，匹配药品数据库，获取药品详细信息。
  • 确认：用户确认识别结果是否正确，可手动修正。
  • 播报：语音播报药品名称、功效、用法用量、注意事项。
  • 提醒：用户可一键设置用药提醒，系统按设定时间推送通知。

7. 交互设计

7.1 设计原则

  • 大字体大按钮：正文不小于18px，按钮点击区域不小于48x48dp。
  • 高对比度：文字与背景对比度符合WCAG AA标准。
  • 语音优先：关键信息支持语音播报，减少阅读负担。
  • 操作简化：核心功能三步可达，避免复杂层级。
  • 容错设计：操作可撤销，错误提示友好明确。

7.3 关键交互说明

拍照识别交互：点击"拍药识药"后进入相机界面，界面中央有取景框和拍照按钮。拍照后显示识别结果，用户可点击"重新拍照"或"确认无误"。确认后自动进入药品详情页，同时播放语音播报。

用药提醒交互：在药品详情页点击"设置提醒"，弹出时间选择器（大字体滚轮），选择时间后确认。系统生成提醒卡片，显示在"用药提醒"列表中。

语音播报交互：药品详情页顶部常驻"播放"按钮，点击后逐条播报药品信息。播报过程中可随时暂停/继续，支持调节语速。

8. 技术方案

8.1 技术架构

层级技术选型说明
前端微信小程序 + React Native小程序快速验证，RN覆盖双端
后端Node.js + Express高并发、快速开发
数据库PostgreSQL + Redis主数据+缓存
云服务阿里云OSS存储、函数计算、消息推送

8.2 关键技术点

  • 药品图像识别：基于深度学习OCR（PaddleOCR/百度OCR），结合药品数据库匹配，实现药品包装和说明书的文字提取与识别。
  • 语音合成：接入腾讯云/阿里云语音合成API，支持多种音色和语速调节，针对老年人优化播报逻辑。
  • 消息推送：集成微信服务号模板消息、APP推送、短信三通道，确保提醒触达。
  • 数据安全：用户健康数据加密存储，符合《个人信息保护法》和《数据安全法》要求。

10. 风险与应对

10.1 风险矩阵

风险可能性影响应对措施
识别准确率低中高持续优化OCR模型，建立人工复核机制
用户增长不及预期中高多渠道推广，与社区/药店合作
竞品模仿高中快速迭代，建立数据壁垒
数据安全合规低高严格遵循法规，定期安全审计

10.2 技术依赖

  • OCR服务：依赖第三方OCR API，需准备备用方案（多供应商策略）。
  • 语音合成：依赖云厂商TTS服务，需评估成本并预留预算。
  • 药品数据库：需与国家药监局数据对接，确保数据准确性和及时更新。

12. 附录

12.1 免责声明

药明白提供的药品信息仅供参考，不构成医疗建议。用户在实际用药前，应咨询专业医生或药师。本产品不替代专业医疗诊断和治疗。因使用本产品信息而产生的任何后果，本公司不承担法律责任。
