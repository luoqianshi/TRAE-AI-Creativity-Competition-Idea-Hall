01 · 从工业革命开始

AI 的意义，不是多了一个聊天工具

每一次工业革命，本质上都是一种能力被大规模放大。AI 这次放大的，是理解、表达、判断、协作和执行这些认知劳动。

蒸汽机

把体力劳动从人和牲畜身上解放出来，带来工厂、铁路和机械化生产。

电力

让动力可以稳定分发，生产线、照明、通信和城市生活方式被重塑。

计算机与互联网

把信息处理和连接成本大幅降低，软件、平台和数字化经营成为基础能力。

AI

让知识工作获得可调用的智能伙伴，从回答问题走向处理任务和改造流程。

分享主线：先建立 AI 的整体视野，再认识工具和组成件，最后把它变成自己的工作流。

03 · 大语言模型怎么工作

先理解 LLM 的基本工作方式，再谈怎么用

这部分不讲数学公式，只讲一个够用的心智模型：大语言模型不是数据库，也不是搜索引擎，它是在给定上下文里，持续预测最合适的下一个 Token。

第一步：输入变成 Token

模型看到的是片段序列

你的问题、文件、历史对话、图片说明和约束，都会被转成 Token。Token 可以理解成文字和符号的细小片段，是模型读写内容的基本单位。

第二步：在上下文里计算关系

它判断哪些信息重要

模型会根据训练中学到的语言、代码、图像和知识模式，计算当前上下文中哪些内容彼此相关。背景越清楚、材料越准确，推理和生成越稳定。

第三步：逐个预测下一个 Token

答案是一点点生成出来的

它不是把答案从某个表里取出来，而是不断预测“下一个最合理的片段”。这解释了它为什么能写得很流畅，也为什么可能把不确定内容说得很自信。

训练和对齐：让它有能力，也有规矩

大模型先通过大量文本、代码、图片等数据学习通用模式，再通过指令微调、人工反馈和安全策略，学会更好地听指令、分步骤回答、拒绝不合适的请求。

工具调用：让它补上现实世界信息

模型本身不等于实时互联网或业务系统。当产品允许它调用搜索、浏览器、文件、代码、MCP 或业务 API 时，它才能查最新信息、读取真实材料、执行操作并验证结果。

对使用者最重要的结论：Prompt 是给任务说明，Context 是给现场材料，Token 决定一次能装下多少内容，Tool use 负责连接外部世界，人工复核负责守住事实、权限和业务边界。

04 · 好用 AI 产品地图

不要问“哪个工具最好”，先问“我要完成什么任务”

产品的差异通常不只是模型，而是入口、上下文、工具连接、权限控制和工作流体验。下面按使用场景理解它们。

ChatGPT

通用 AI 工作台

适合问答、写作、研究、文件分析、图片、语音、个人项目和跨主题学习。

  • 把资料变成摘要、方案、对比表。
  • 把模糊想法变成提纲和初稿。
  • 用 Deep Research 类能力做资料综合。

上手建议：先用它做“研究助手 + 写作助手 + 文件分析助手”。

Codex

软件工程 Agent

OpenAI 面向软件开发的 coding agent，可读代码、改代码、跑命令、做 CR、使用 CLI/IDE/桌面 app、Skills、MCP、Rules。

  • 读懂陌生代码库并解释业务逻辑。
  • 实现小需求、修 bug、跑测试。
  • 把重复工程流程沉淀成 Skill。

上手建议：让它先解释代码和制定计划，再逐步授权执行。

Claude Code

Agentic Coding

Anthropic 的 agentic coding system，面向代码库理解、跨文件修改、运行测试和交付代码。

  • 长上下文代码理解和重构沟通。
  • 终端内连续推进开发任务。
  • 结合 MCP 读取设计文档、工单或开发工具。

上手建议：给清晰目标、成功标准、测试命令和边界。

QoderWork

桌面 AI 助手

面向日常办公和知识工作的桌面 AI assistant，把 Agent 能力带到文件整理、数据处理、文档生成、资料综合等场景。

  • 整理本地文件和资料。
  • 批量处理表格、文档和研究材料。
  • 用 Skills/MCP 扩展桌面工作流。

上手建议：从低风险的整理、总结、生成类任务开始。

Qoder Desktop

研发桌面环境

面向研发的 AI IDE/桌面能力，强调 Agent Mode、代码上下文、补全、规则、MCP 和多任务窗口。

  • 开发、调试、解释代码和生成测试。
  • 把团队规范放入规则和上下文。
  • 连接外部文档或工具做工程任务。

上手建议：适合研发同学，业务同学可理解它代表“AI 深入专业工具”。

Hermes Agent

自进化 Agent

Nous Research 的开源 AI Agent，强调长期运行、持久记忆、自主生成和改进 Skill、跨平台消息入口、定时任务和 MCP 扩展。

  • 需要 Agent 持续学习个人习惯和项目背景。
  • 通过 CLI、Telegram、Discord、Slack 等入口远程协作。
  • 把复杂任务沉淀成可复用 Skill 和自动化流程。

上手建议：适合技术用户或愿意配置环境的人，先从低权限、低风险任务试运行。

OpenClaw

开源个人 Agent

开源个人 AI assistant/agent，目标是连接聊天入口、文件、邮件、日历、命令、插件和多个工作机器。

  • 跨工具自动化和个人助理式任务。
  • 长期运行、多 Agent、语音或消息驱动。
  • 适合技术用户探索个人 Agent。

上手建议：权限很强，必须先理解安全风险，再考虑安装和授权。

Hermes Agent 和 OpenClaw 怎么选？

对比维度 Hermes Agent OpenClaw
核心定位 更像一个会积累经验的长期 Agent，重点是记忆、Skill 自改进和跨会话成长。 更像个人 AI 操作系统，把聊天入口、工具、文件、邮件、日历、命令和多 Agent 组织起来。
强项 持久记忆、自动沉淀 Skill、定时任务、远程运行、多模型接入、MCP 扩展。 个人助理式自动化、多入口消息交互、跨工具编排、多 Agent、社区技能生态。
典型场景 长期研究、代码和知识工作、周期性报告、让 Agent 记住项目偏好并持续改进。 收邮件、做日程、处理文件、发消息、跨设备执行任务、个人生活和工作自动化。
上手门槛 需要理解模型配置、工具权限、运行环境和消息网关，更适合技术用户先试。 也需要配置和授权，但更容易用“个人助理”故事理解，适合做 Agent 概念展示。
风险提醒 长期记忆和自动执行越强，越要管好敏感数据、工具权限、命令执行和外部输入。 连接个人账号、文件和消息系统后权限很大，必须分级授权、隔离环境、保留人工确认。
一句话选择：需要长期积累个人或项目上下文、沉淀 Skill 时偏 Hermes Agent；需要连接更多个人工具、消息入口和跨工具自动化时偏 OpenClaw。两者都不适合作为 0AI 同学的第一站，建议先用低权限环境试跑。

05 · 具体工作场景案例

把 AI 用起来，关键是给它一个真实任务

下面每个案例都可以直接拿去试。建议先从“低风险、高重复、容易复核”的任务开始，逐步建立自己的工作流。

1. 资料研究：行业趋势和竞品梳理

工具：ChatGPT / Perplexity产出：趋势摘要 + 对比表

适合开项目前快速建立背景，不适合直接替代最终市场判断。

请扮演行业研究助理。我的目标是了解【行业/竞品/政策】在最近 6-12 个月的变化。
请输出：
1. 关键趋势，按重要性排序
2. 主要玩家对比表
3. 对我们可能有影响的机会和风险
4. 每条结论的不确定点和需要我人工核查的信息
请先问我 3 个必要问题，再开始整理。

复核点：来源日期、是否过度概括、是否把观点当事实。

2. 会议纪要：从记录变成行动

工具：ChatGPT / QoderWork产出：决策 + 待办 + 风险

适合处理录音转写稿、会议文字记录和长聊天记录。

下面是会议记录。请不要改写成流水账，而是整理成管理层可读纪要：
1. 本次会议结论
2. 已确认决策
3. 待办事项，包含负责人、截止时间、依赖
4. 未解决分歧和风险
5. 下次会议建议议程
如果记录中没有负责人或时间，请标为“待确认”。

复核点：责任人、时间、决策是否真实出现过。

3. PRD / 方案：从想法到结构化文档

工具：ChatGPT / Claude产出：PRD 初稿

适合把零散需求、用户反馈和业务目标整理成可讨论版本。

请把下面的需求信息整理成一版 PRD 初稿。
要求包含：背景、目标、非目标、用户故事、核心流程、字段说明、异常场景、验收标准、埋点建议。
请先指出需求中缺失或矛盾的信息，再给出初稿。
语气要求：清晰、可执行、便于研发评审。

复核点：边界是否清楚、验收标准是否可测试、是否加入了未确认功能。

4. 运营文案：多版本快速生成

工具：ChatGPT / Gemini产出：标题 + 长短文案

适合活动页、推送、短信、海报和社媒文案的初稿与改写。

请为【活动/产品】生成 5 组运营文案。
目标用户：【用户画像】
核心卖点：【卖点】
限制：不夸大、不承诺无法保证的结果、不使用敏感词。
每组包含：标题、短文案、长文案、适合渠道、为什么这样写。
最后请给出你最推荐的一组和理由。

复核点：合规词、事实准确性、品牌语气。

5. 数据分析：让表格先说话

工具：ChatGPT 文件分析 / QoderWork产出：发现 + 图表建议

适合处理运营数据、问卷、销售明细、活动效果和异常排查。

请分析这份表格。我的业务目标是【目标】。
请输出：
1. 数据概览和字段解释
2. 最重要的 5 个发现
3. 异常值或可能的数据质量问题
4. 建议使用的图表类型
5. 下一步业务动作建议
请区分“数据直接支持的结论”和“需要进一步验证的猜测”。

复核点：字段含义、样本偏差、是否把相关性当因果。

6. 周报 / 汇报：把碎片变成重点

工具：ChatGPT / QoderWork产出：管理层摘要

适合把聊天记录、任务列表、项目进度整理成清楚的汇报。

请根据下面的工作记录生成周报。
输出结构：
1. 本周最重要的 3 个进展
2. 对业务目标的影响
3. 遇到的问题和需要支持的事项
4. 下周计划
5. 可以给上级快速阅读的 100 字摘要
请避免流水账，突出结果和影响。

复核点：是否遗漏关键事项、是否夸大影响。

7. 客服 / 销售：话术和 FAQ

工具：ChatGPT / 企业知识库产出：FAQ + 回复模板

适合先生成标准话术，再由业务同学校准边界和口径。

请基于以下产品说明和客户问题，生成客服回复模板。
要求：
1. 先共情，再给解决路径
2. 区分普通问题、投诉、退款、升级人工
3. 不承诺政策外内容
4. 每条回复给出适用场景和禁用场景
最后生成一个 FAQ 表格。

复核点：政策边界、敏感承诺、升级流程。

8. 研发协作：读代码、改小需求、查问题

工具：Codex / Claude Code / Qoder Desktop产出：解释 + 代码改动 + 测试

适合研发同学，也适合产品/运营理解技术实现和沟通成本。

请先阅读这个模块，解释它的核心业务流程和关键文件。
然后针对需求【需求描述】给出实现计划。
约束：
1. 只改必要文件
2. 不影响现有行为
3. 给出测试命令和验收标准
4. 实施前先列出风险点，等我确认后再改代码。

复核点：改动范围、测试结果、是否误改无关逻辑。

9. 桌面自动化：跨文件和跨工具处理

工具：QoderWork / Hermes Agent / OpenClaw产出：整理后的文件 / 文档 / 任务

适合把“我电脑里有一堆材料，请整理成可用结果”这类任务交给桌面或长期运行的 Agent。

请在我指定的文件夹中整理资料，但不要删除任何文件。
目标：把【主题】相关材料整理成一份说明文档。
要求：
1. 只读取我指定的文件夹
2. 先列出你将要读取的文件清单
3. 输出材料分类、摘要、缺失信息和下一步建议
4. 涉及移动、删除、发送、提交前必须先请求我确认。

复核点：权限范围、是否涉及删除/发送/提交等高风险操作。

10. AIGC：海报、图片和短视频创意

工具：ChatGPT / 图像或视频生成工具产出：创意方向 + 画面 Prompt + 分镜

适合活动视觉、海报初稿、短视频脚本、产品图概念和社媒素材，不适合直接替代最终品牌与合规审核。

请为【活动/产品/主题】设计一组 AIGC 创意素材方案。
目标用户：【用户画像】
核心信息：【必须传达的信息】
使用渠道：【海报/公众号/短视频/社媒/展会屏幕】
品牌限制：【品牌色、禁用元素、合规要求】

请输出：
1. 3 个不同创意方向，每个方向说明适合的渠道和情绪
2. 每个方向的画面描述 Prompt，包含主体、场景、构图、光线、风格、色彩和禁用项
3. 如果做短视频，给出 5 镜头分镜脚本
4. 最后列出版权、肖像、商标、事实表达和品牌合规的检查清单。

复核点：版权授权、人物肖像、品牌规范、是否出现虚假承诺或不合规元素。

06 · 使用技巧与 Prompt 工作流

好用 AI 的关键，是把问题变成可执行任务

不要只说“帮我写一下”。好的 AI 使用方式，是把目标、背景、材料、限制和检查标准讲清楚。

好 Prompt = 目标 + 背景 + 材料 + 约束 + 输出格式 + 检查标准

技巧 1：先让 AI 反问

当你自己也没想清楚时，不要让 AI 直接生成。先让它问 3-5 个关键问题，帮你补齐任务背景。

我想完成【任务】，但信息还不完整。请先不要生成结果，先问我 5 个最影响质量的问题，并说明每个问题为什么重要。

技巧 2：大任务分阶段

复杂任务不要一次完成。先让 AI 理解材料，再出提纲，再生成，再自检，质量会稳定很多。

请分四步处理：第一步理解材料并总结，第二步给提纲，第三步生成正文，第四步按检查清单自检。每一步完成后等待我确认。

技巧 3：给例子比讲感觉有效

“写得高级一点”很模糊。给一段你喜欢的示例，再说明要保留和避免什么，AI 更容易对齐。

请参考下面示例的结构和语气，但不要照抄内容。
我希望保留：【特点】
我希望避免：【问题】
现在请改写这段材料：【材料】

技巧 4：要求标注不确定性

让 AI 主动区分事实、推断和猜测，可以明显降低“看起来很对但其实没证据”的风险。

请把输出分成三类：已知事实、基于事实的推断、需要进一步验证的假设。不要把假设写成确定结论。

技巧 5：使用反方审查

重要方案不要只让 AI 生成，也要让它扮演反方找问题，尤其适合方案评审和上线前检查。

请扮演严格评审人，审查这份方案。重点找：逻辑漏洞、用户风险、执行风险、数据口径问题、遗漏场景。请按严重程度排序。

技巧 6：把重复任务沉淀

如果一个 Prompt 每周都用，就把它变成模板；如果步骤固定、材料固定，就考虑沉淀成 Skill 或工作流。

请把我刚才完成这项任务的过程整理成可复用模板：输入材料、处理步骤、输出格式、复核清单、常见错误。

从问答到工作流的四级进阶

  1. 问答：问一个问题，得到一个答案。
  2. 工具：上传文件、联网搜索、生成图片、分析表格。
  3. Agent：让 AI 拆解任务、调用工具、执行和自检。
  4. 工作流：把稳定步骤沉淀成模板、Skill、Rule 和自动化流程。

日常使用的三条底线

  1. 不要把敏感数据随手丢给不确定的工具。
  2. 不要让 AI 直接执行高风险操作。
  3. 不要把 AI 生成内容未经复核当作最终事实。

07 · 风险边界与行动清单

会用 AI，也要知道哪里必须慢下来

AI 越能执行，风险也越真实。对 0AI 基础同学来说，最重要的是知道哪些场景需要人工复核和权限控制。

幻觉和事实错误

AI 可能编造不存在的来源、政策、数据或案例。涉及事实、法律、财务、医疗、合规时必须查证。

隐私和数据泄露

不要输入账号密码、Token、Cookie、客户隐私、未公开财务数据、内部敏感资料。

权限和误操作

Agent 或 CLI 能调用工具后，可能删除文件、发送消息、提交代码、修改系统。高风险动作必须审批。

版权和品牌风险

AI 生成图片、文案和代码仍需检查版权、授权、商标和品牌规范。

过度依赖

AI 适合辅助思考和执行，不适合替你承担业务判断和责任。越重要的决策，人越要在环。

流程污染

不清楚的 Prompt、错误上下文和未验证结果会被复制到后续流程，形成连锁错误。

开始使用前的 8 条清单

  • 先选低风险、高重复、容易复核的任务。
  • 每次任务写清目标、背景、材料、约束和输出格式。
  • 长材料先总结，复杂任务分阶段。
  • 要求 AI 标出不确定信息和需要核查的点。
  • 重要内容用反方审查和人工复核。
  • 不要暴露敏感数据和凭证。
  • 涉及文件删除、外发、付款、提交、发布前必须确认。
  • 把高频任务沉淀成模板、Skill 或团队工作流。
