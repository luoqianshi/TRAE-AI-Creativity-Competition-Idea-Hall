01 / 问题描述

文明的脆弱性：
当互联网消失，知识去哪了？

现代文明将几乎全部知识托管在云端——从如何净水到如何急救，从如何发电到如何通讯。但灾害恰恰会摧毁互联网本身。地震断网、台风断电、洪灾中断基础设施，那一刻，我们手中的智能手机变成一块黑色的玻璃板，所有"搜一下就知道"的知识瞬间归零。

Protocol: Zero 要解决的，就是知识冗余问题——把文明的关键生存技术从云端拉回本地，装进每个人的口袋。

问题 01

内容断层

现有生存知识要么过于学术（工程教材），要么过于娱乐（短视频），缺少"看到就能做"的工程级操作指引。普通人无法跨越从理论到实践的鸿沟。

问题 02

在线依赖

几乎所有知识检索都依赖互联网。灾害断网后，手机里的百科 App 也只是一个空壳。没有 Service Worker 缓存，没有离线优先架构，知识就无法到达需要它的人。

问题 03

缺乏容错

现有内容只讲成功路径，不告诉你"如果失败了怎么办"。真实场景中第一次操作大概率会出错——没有失败诊断、没有替代方案、没有材料替换建议，知识就是死的。

问题 04

无法适配

同一套操作流程在 -20°C 极寒和 40°C 高温下可能完全不同。现有内容不考虑环境参数，不根据温度、辐射、湿度、海拔动态调整，给出的是僵化指令而非活的知识。

02 / 核心功能

六个维度，
重新定义"生存手册"

Protocol: Zero 不是把纸质手册搬到网页上。它是一个可交互的工程信息系统，每个功能都针对真实灾害场景中的认知痛点设计。

三模搜索引擎

按需求搜索（"我要取火"）、按持有材料逆向搜索（"我有铝罐和漆包线"）、按环境条件搜索（"极寒高辐射"）。三种模式覆盖"知道自己要什么"和"不知道自己能做什么"两种场景。

物质转化矩阵

输入手中现有的废弃材料，系统自动计算可构建的生存工具组合。铝罐 + 漆包线 + 直流电机 = 斯特林发电机。变废为宝的工程逻辑引擎。

工程图解系统

每个操作步骤配备手绘风格的 SVG 工程图解，含尺寸标注、剖面图、装配关系。162 张图解全部矢量化，离线可渲染，可缩放。

材料物理参数表

每种材料附带真实物理参数：导热系数、耐温极限、壁厚、电阻值。不是"找一个铁罐"，而是"镀锡钢板，导热 50 W/(m·K)，耐温 800°C，壁厚 0.3mm"。

环境感知面板

实时调节温度、辐射、湿度、海拔四个参数，系统自动评估环境安全等级（安全 → 注意 → 警告 → 危险 → 极端），并动态调整知识条目的展示优先级。

失败诊断模块

每个步骤都标注"失败症状"和"替代方案"。发动机不启动？可能是密封不严导致气压泄漏。没有飞轮？用 CD 光盘 + 硬币替代。容错是生存的核心。

田野手册，
不是赛博朋克

措施 01

无玻璃拟态

不使用 backdrop-filter 模糊、半透明卡片、毛玻璃效果。所有面板均为实色填充 + 实线边框。

措施 02

无渐变文字

不使用 background-clip: text 渐变文字。标题用纯色 + 字重对比建立层级。

措施 03

无发光特效

不使用 box-shadow 光晕、text-shadow 发光、扫描线动画。2px 圆角 + 实线边框。

措施 04

高信息密度

不对称左对齐布局，分类卡片用数字 + 色带区分，不浪费屏幕空间在装饰性留白上。
