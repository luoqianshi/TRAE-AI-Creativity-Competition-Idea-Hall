一、想解决什么问题

痛点 1

AI 助手只有文字

传统 AI 助手停留在聊天窗口，缺少陪伴感，用户和 AI 之间只有「提问-回答」的工具关系，很难形成持续的共处体验。

痛点 2

桌宠只会卖萌

常见桌宠偏展示与娱乐，缺少真正可用的工具能力，不能帮用户做任何事，只是一个会动的桌面装饰品。

痛点 3

上下文被割裂

用户在桌面、浏览器、编辑器、AI 助手之间频繁切换，上下文需要手动搬运，操作割裂、效率低、也容易忘事。

二、为什么会想到做这个

动机

我们喜欢桌宠的陪伴感，但不满它只能卖萌。我们也每天使用 AI Agent 写代码、搜索、自动化，但不满它只有文字界面。于是有了一个简单的想法：

把 Agent Runtime 装进一个可以陪伴你的 Live2D 桌宠里。

让它既有角色感、有动作、有语音、会主动说话；同时也有真实的工具能力，能帮你整理桌面、搜索网页、定时提醒、记住你昨天说过的话。

产品形态

桌面常驻的陪伴型 Agent 工作台（Windows 桌面应用），由四个窗口组成：Live2D 桌宠、AI 聊天、设置中心、实时字幕。主进程承载 Agent Runtime、工具执行、记忆库、语音、浏览器自动化和 MCP 扩展。所有数据优先存本地。

三、大概是什么产品

形态

Electron 桌面应用

Windows 10 / 11 可安装、可卸载。透明桌宠窗口 + 多窗口 IPC 通信，渲染层不碰本地权限，通过 preload 安全桥进主进程。

引擎

陪伴型 Agent

ReAct Agent Loop：多轮推理 → 工具调用 → 上下文压缩 → 记忆召回 → 子代理并行 → 结果整合。支持流式 LLM 与工具确认。

渲染

Live2D Cubism

WebGL + Cubism Core，支持动作、表情、眼追踪、口型同步、字幕跟随和鼠标交互。可导入 ZIP 模型。

四、核心能力矩阵

陪伴感（像角色）

  • Live2D 桌宠：透明置顶、点击/拖拽、鼠标追踪、动作播放、字幕跟随、右键菜单
  • 流式 AI 对话：文字 & 语音双输入、多轮上下文、实时流式输出、Markdown 渲染、代码高亮
  • 主动陪伴：空闲触发 · 周期触发 · 回归触发 · 屏幕观察变化触发；内置 PROACTIVE_SKIP 沉默权
  • 角色卡系统：名称、人设、场景、专属提示词、情绪标记 ACT、开场白，可快速切换
生产力（像 Agent）
  • ReAct 工具系统：文件 / Shell / Patch / 搜索 / 网页 / 浏览器自动化 / 记忆 / 截图 / MCP / 子代理 / 计划
  • 分层记忆：SQLite FTS5 + Markdown 双端存储；主动召回 + Dreaming 晋升机制
  • 语音系统：Edge TTS / OpenAI TTS / Whisper / Web Speech 多引擎切换 + 失败降级
  • 调度系统：Cron · Heartbeat · Companion 三类主动触发；可定时执行任务

五、Agent 执行闭环

1. 输入
文本 · 语音 · 定时 · 陪伴
2. 组装 Prompt
角色 · 工具 · 记忆 · 技能
3. LLM 流式推理
文本流 · 思考流 · 工具流
4. 工具决策
参数校验 · 确认策略 · 超时
5. 记忆压缩
主动召回 · 上下文压缩
6. 反馈
聊天 · 桌宠字幕 · 主动陪伴

复杂任务可拆分给子代理并行执行；主代理 + 子代理分层架构，隔离不同专业角色（信息检索 / 代码实现 / 逻辑审查）；子代理有白名单工具、禁止嵌套子代理、独立会话，防止循环失控。

六、记忆系统 —— Dreaming 晋升

问题

没有记忆的 AI 每次都像第一次见面。有记忆但什么都存，检索会被噪音淹没。

方案

SQLite FTS5 存短期记忆 · BM25 检索；后台 Dreaming 三阶段筛选晋升（Light Sleep → REM Sleep → Deep Sleep），用六维加权评分（使用频次 / 相关性 / 多样性 / 新鲜度 / 整合度 / 抽象度）+ 三重门控（总分 + 召回次数 + 不同查询数），只有合格记忆才升级为长期知识并同步到 MEMORY.md。

七、价值与意义

情感陪伴

从「它」到「你」

给 AI 一个可感知的身体（Live2D）、可积累的历史（记忆）、可主动发起的关照（陪伴），让 AI 从「工具」变成「共处对象」。

生产力

桌面自动化 Agent

搜索 · 文件 · 浏览器 · 截图 · Shell · MCP · 定时 · 子代理 —— 一套完整的 Agent Runtime，把 AI 放回你每天工作的桌面环境。

工程探索

陪伴型 Agent 路线

不是堆叠功能，而是围绕「陪伴 + 生产力」两个核心构建的一条工程路线：角色卡 / 记忆 / 陪伴 / 工具 四者协同，缺一不可。
