1. 创意名称 + 创意介绍

想解决什么问题：

用 Git 维护多个仓库时，经常需要同时推送到 GitHub、Codeberg、Gitee 等多个平台。 但 Git 原生不支持一次性推送多个远程，只能一个个手动执行 git push， 而且每个平台用的账号、邮箱还不一样，每次都要改 git config，非常繁琐。

为什么会想到做这个：

我是一名开源项目维护者，需要将代码同步到多个平台（GitHub 主仓库、Codeberg 镜像、Gitee 国内加速）。 每次推送都要执行 3 次 git push，还要手动切换 user.name 和 user.email， 经常因为忘记切换导致提交作者混乱。迁移仓库时更要重新配置所有远程地址和认证信息，维护成本极高。 于是我想："能不能做一个工具，一条命令搞定所有远程推送？"

大概是什么产品：

gits 是一个多 Git 远程仓库一键同步工具，产品形态为 命令行工具（CLI）+ 网页配置助手。 在仓库根目录放一个配置文件 .git/gits.toml，运行 gits push 就能交互式选择推送到哪个远程， 或一键推送到全部。它会自动切换本地 Git 身份，支持 SSH 密钥与 HTTPS Token 双认证， 还提供密钥生成、远程管理等辅助命令。

🔧 5. 技术实现方案

gits 采用 Go 语言 编写，编译为单二进制文件，零依赖分发：

  • 配置文件解析：使用 github.com/BurntSushi/toml 解析 TOML 格式配置，支持多远程定义和字段校验。
  • Git 命令封装：通过 os/exec 调用系统 Git 命令，实现推送、身份切换、暂存区检测等功能。
  • 认证优先级：实现 buildPushURL 函数，按 SSH > Token > Password 优先级自动构造推送 URL。
  • 交互式菜单：使用 bufio.Scanner 实现终端交互，支持编号/ID/全选/退出等多种选择方式。
  • 网页配置助手：单 HTML 文件，使用 smol-toml 库解析配置，提供可视化编辑和命令生成功能。
技术亮点： 纯 Go 实现，编译后单文件约 5MB，无运行时依赖；配置文件采用 TOML 格式，可读性强且支持注释；认证优先级机制确保安全性（SSH 优先于 Token，Token 优先于密码）。

🚀 6. 使用流程

1️

初始化配置

运行 gits init 生成配置模板，或手动创建 .git/gits.toml

2️⃣

添加远程

运行 gits remote add 交互式添加远程仓库配置

3️⃣

一键推送

运行 gits push 选择远程，或 gits push -a 推送全部

4️⃣

管理维护

使用 gits remote edit/rm 和 gits key gen/list 管理配置

命令示例

  • gits init - 生成配置模板到 .git/gits.toml
  • gits list - 列出所有远程仓库（编号、ID、脱敏 URL、身份）
  • gits push - 交互式选择远程推送
  • gits push -a - 一键推送所有远程
  • gits push -m "fix bug" -b main github-work - 指定参数推送
  • gits remote add --id github --url https://... - 参数化添加远程
  • gits key gen mykey --type ed25519 - 生成 SSH 密钥

💡 7. 为什么值得做

Git 是开发者每天都在用的工具，但多远程推送这个痛点却长期被忽视。 市面上没有任何一个工具能同时满足：配置文件管理 + 自动身份切换 + 多认证支持 + 交互式选择 + 网页助手。 gits 不是"又一个 Git 包装器"，而是 重新定义了多远程工作流 —— 它把原本需要 10 分钟的操作压缩到 10 秒，把容易出错的配置变成可版本控制的 TOML 文件。

这个方向目前几乎是一片空白。GitHub 的 git push --all 只能推送相同 URL 的远程， 无法处理不同平台、不同身份的场景。自定义脚本虽然可行，但缺乏标准化配置和交互体验。 gits 填补了这个空白，为多平台开发者提供了一个优雅、高效、可靠的解决方案。
