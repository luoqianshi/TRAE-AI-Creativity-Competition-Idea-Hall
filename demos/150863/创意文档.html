创意名称 + 创意介绍

创意名称

启明星 — AI 医疗无障碍平台

想解决什么问题

视障人士及泛残障群体就医时面临严重的信息障碍：化验单、检查报告对他们而言如同"天书"，药品包装无法触辨极易吃错药，医院内的指示牌、叫号屏幕完全依赖视觉，导致大量残障人士因信息鸿沟而放弃独立就医。

为什么会想到做这个

我了解到中国有 1700 万视障人士，但目前几乎没有专门针对他们就医场景的成熟产品。现有 OCR 工具只能"读字"，不能"解读"——就像把一本英文书读给不懂英语的人听，每个字都听到了，却什么也没听懂。我想做的不是简单的文字转语音，而是让 AI 真正理解医学语义，把专业信息翻译成每个人都能听懂的话。

大概是什么产品

先做 Web 网站展示完整功能原型，后续转为微信小程序，方便残障人士在手机端使用。

目标用户 及 痛点

面向哪些用户

核心用户是视障人士（全盲及低视力群体），同时覆盖肢体障碍、听障等泛残障群体中存在医疗信息获取困难的人群。陪诊家属和医护人员也是间接用户。

在什么场景下使用
  • 拿到化验单、检查报告后，想了解自己的健康状况
  • 取药后需要确认药名、用法用量和注意事项
  • 独立前往医院就诊时，需要完成挂号、候诊、缴费、取药等流程
  • 肢体障碍患者与医生交流时，因无法打字或手语不标准导致沟通困难
当前痛点

没有这个产品时，视障人士就医几乎必须依赖他人陪同。化验单要找人读、药品要找人认、医院要找人带路——不是"不方便"，而是"做不到"。通用 OCR 工具只能逐字朗读原文，无法判断哪个指标异常、是否严重、下一步该怎么办，缺少医学语义理解和可执行的建议。药品识别方面，不同药物外观相似（白色小圆片之间可能差着降压药和降糖药），误服风险极高。

价值 与 意义

社会价值

启明星让 1700 万视障人士从"无法独立就医"到"可以自主获取医疗信息"，本质上是归还了他们本应平等享有的健康知情权。项目不只是一个工具，更是一座桥梁——连接被信息鸿沟隔开的人和他们本应拥有的医疗权利。据调研，85% 的视障人士曾因信息障碍放弃独立就医，而目前市场上专门针对视障就医的成熟产品几乎为零，这个需求长期被忽视。

效率提升

对残障用户而言，启明星将原本需要"找家人/志愿者帮忙读报告、认药品、带路"的多环节依赖流程，压缩为"拍照/扫码 → 语音解读"的一键操作，单次就医的信息获取时间可从数小时缩短至几分钟。同时，手语问诊系统通过人体图像点击 + 语音输入生成结构化病历，帮助肢体障碍患者减少与医生的沟通障碍，提升问诊效率。

04 / 06

核心 功能

01 医疗信息无障碍化 — 报告解读

拍照 → OCR → 结构化解析 → 语音播报关键指标。AI 自动判断异常指标，用通俗语言解读临床意义，并给出可执行的下一步建议。

"您的空腹血糖 6.8 mmol/L，略高于正常范围 3.9-6.1，建议关注饮食控制，2 周后复查。"
02 手语医疗问诊系统

针对肢体障碍患者与医生交流困难的问题，提供人体图像点击表达或语音输入，AI 进行医学语义理解后自动生成结构化病历，辅助医患沟通。

患者点击人体图头部区域 + 语音"恶心想吐"，系统生成病历并建议就诊科室。
03 药品识别 + 用药提醒

扫码或拍照识别药品，语音播报药名、用法用量、注意事项和禁忌，并可设置智能用药提醒。

"这是阿莫西林胶囊，每次 1 粒，每日 3 次，饭后服用，对青霉素过敏者禁用。"
04 就医流程语音引导

用语音引导视障者完成挂号、候诊、缴费、取药等全流程，实时播报排队进度和下一步指引。

"您已完成缴费，请前往 1 楼药房 3 号窗口取药。"

技术 实现方案

产品形态
  • 第一阶段：Web 网站原型，展示完整功能交互与 UI 设计
  • 第二阶段：转为微信小程序，便于残障人士手机端使用
核心技术
  • OCR + 大语言模型：实现化验单拍照识别与医学语义解读
  • 条码扫描 + 图像识别：双通道药品信息获取
  • Web Speech API / 语音合成：语音播报核心交互方式
  • 医学指标知识库：内置常见检验指标参考范围与临床解读
