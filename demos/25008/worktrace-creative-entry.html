一、创意名称 + 创意介绍

创意名称：WorkTrace — 你的个人数字活动时间线

① 想解决什么问题

站会时"昨天做了什么"靠回忆；周报要逐条翻提交记录才能凑齐；月度述职只能从半记得的细节里拼凑；几个月后想回顾某段时间的工作重心，已无迹可循。

大多数人无法准确回答："我今天/这周/这个月到底做了什么？"

② 为什么会想到做这个

作为个人开发者，我们常常希望有一份"整个电脑的 git log"——不只是代码仓库，而是整个工作空间的活动记录。

当我忘记自己某段时间在做什么时，我需要一段可检索的"数字记忆"，而不是重新去翻 47 次零散的文件保存。

③ 大概是什么产品

一款跨平台桌面应用（当前为 Java 21 + JavaFX 实现），在后台安静监听用户数字工作空间中的文件创建/修改/删除事件；将成千上万条底层文件事件通过智能聚合算法，分组为有意义的"活动块"，以时间线方式呈现给用户。

所有数据本地存储在 SQLite 中（~/.worktrace/worktrace.db），不上传、不联网，尊重隐私。用户只要正常工作，WorkTrace 就在后台默默构建一条可随时回顾的时间线。

二、目标用户及痛点

3 类核心用户，在日常工作学习中面临共同的"记忆模糊"问题。

开发者

场景：写代码、改配置、提交版本、跨项目切换。

痛点：站会/周报靠回忆提交记录；几个月后想不起某个特性是在哪周做的；临时文件/IDE 产物干扰真实工作流。

学生

场景：写论文、做课程设计、整理研究笔记、编辑实验报告。

痛点：作业提交前记不清自己花了多少时间；报告和论文多版本散落，难以回溯自己的写作轨迹。

远程工作者

场景：居家办公、跨项目协作、编辑共享文档、整理工作产出。

痛点：需要向团队同步工作内容，却无法快速给出一份"我今天做了什么"的可信记录；时间消耗不透明，效率难以复盘。

三、价值与意义

从个人效率提升到社会价值，WorkTrace 试图重新定义"个人工作记忆"的归属。

效率提升
  • 站会、周报、述职：一键回顾，不再靠回忆。
  • 文件级被动追踪，无需手动打卡、零操作负担。
  • 按项目/类别自动分组，快速定位"我当时在做什么"。
  • 本地持久化存储，随时可检索任意日期的活动记录。
社会价值
  • 将"个人工作历史"还给个人：数据本地存储，隐私优先。
  • 帮助自由职业者与远程工作者建立可信的产出记录。
  • 为学生提供学习时间线，回顾自己的知识建构过程。
  • 建立开源、开放的数字记忆工具生态，任何人都可二次扩展。

功能特性

核心能力一览（8 项）。

▣ 01

自动活动追踪

在后台安静运行，监听文件系统事件，无需手动输入。

▣ 02

智能事件聚合

将关联文件事件分组为有意义的活动块，告别零散保存。

▣ 03

类别自动识别

自动识别代码/文档/图片/视频/配置/其他文件类型。

▣ 04

项目感知分组

同一项目的文件自动合并，不受文件类型限制。

▣ 05

持久化历史

所有活动本地存储在 SQLite 中，随时可回顾任意一天。

▣ 06

暗色主题 UI

现代扁平化暗色界面，包含时间线 + 详情面板 + 统计。

▣ 07

实时更新

追踪运行中时间线自动刷新，所见即所得。

▣ 08

本地隐私优先

数据完全留在本地，不上传、不联网，尊重用户隐私。

未来方向

Roadmap — WorkTrace v1.0 之后的路线图（8 项）。

  1. 噪声过滤— 忽略系统文件、缓存和临时产物（IDE/build 产物等）。
  2. 项目识别— 从 .git / pom.xml / package.json 等自动检测项目根目录。
  3. 历史浏览— 日期选择器，可探索任意过去一天的时间线。
  4. 效率洞察— 了解时间如何在项目和活动类别之间分配。
  5. 跨日模式— 发现重复的工作节奏和个人专注时段。
  6. 系统托盘模式— 在后台安静运行，持续记录，不占用主窗口。
  7. AI 工作摘要— 从活动数据自动生成每日和每周报告。
  8. 导出与分享— 将时间线导出为 Markdown / CSV / JSON。
