创意起源

从一个 Godot 开发者的真实痛点出发

想解决什么问题：Godot 游戏开发者在管理插件（addons）时深陷泥潭——手动复制文件夹、版本混乱冲突、换台电脑要重新配置、多个项目要用不同引擎版本时更是混乱。一个稍具规模的游戏项目，光是维护插件环境和引擎版本就要耗费大量时间。

为什么会想到做这个：作为 Godot 重度用户，我在开发过程中深受插件管理之苦。每次新建项目都要重新拷贝一遍常用插件；插件更新后要手动同步到所有项目；切换 Godot 版本时经常因为引擎版本不匹配导致项目打不开。我一直在想：为什么没有一个像 Unity Hub 那样的工具，专门管理 Godot 的插件和引擎？于是 GodotHarbor 诞生了。

大概是什么产品：一款基于 Tauri 2.x + Rust + Vue 3 构建的跨平台桌面应用，为 Godot 游戏开发者提供插件管理、项目管理和引擎管理的一站式解决方案。利用 TRAE IDE 辅助开发，大幅提升编码与迭代效率。

目标用户及痛点

谁会用到它？又在什么场景下使用？

面向哪些用户：

  • 核心用户：独立游戏开发者、Godot 游戏开发团队、游戏开发学习者
  • 延展用户：Godot 插件作者、游戏开发教学者、参与 Game Jam 的开发者

使用场景：

新项目快速搭建环境 多项目共享同一插件 插件升级批量同步 切换 Godot 引擎版本 团队协作环境对齐 Game Jam 快速起手 换电脑迁移开发环境

当前痛点（没有 GodotHarbor 的世界）：

插件管理混乱 手动复制 addons 文件夹，版本无法统一管理，容易装错版本
多版本冲突 不同项目需要不同插件版本，手动切换极易出错
更新同步繁琐 插件更新后要逐个项目替换，10 个项目就要操作 10 次
引擎版本错配 用错引擎版本打开项目，可能导致项目损坏或无法运行
环境迁移困难 换台电脑要重新下载引擎、重新配置所有插件
缺少统一入口 Godot 官方没有类似 Unity Hub 的项目管理中心

核心功能

五大功能模块，覆盖 Godot 开发全流程

📦

插件一键挂载

从本地目录、Git 仓库或 Godot Asset Library 导入插件，一键挂载到任意项目的 addons 目录。支持符号链接、目录联接、复制三种模式，适配不同系统权限。

🔄

多版本共存

同一插件可维护多个版本，不同项目绑定不同版本，互不干扰。彻底告别"升级一个插件搞崩所有项目"的噩梦。

⚡

批量更新

插件更新后一键同步到所有绑定的项目，告别逐个替换的低效操作。一次更新，全局生效。

🚀

引擎管理

自动发现本地已安装的 Godot 引擎，支持在线下载安装，为项目智能匹配正确的引擎版本，避免版本错配导致的启动失败。

🎯

一键启动

记住每个项目上次使用的引擎，一键用正确版本打开项目。无需手动寻找引擎路径，点击即开。

🎨

精致体验

采用 JetBrains New UI 风格设计，支持明暗主题与紧凑密度切换，毛玻璃质感界面，为开发者提供舒适的视觉体验。
