01 / PAIN POINTS

复盘，为什么总是流于形式？

项目结束后组织复盘，是每个 Leader 的必修课。但现实往往事与愿违——讨论发散、结论空洞、行动缺失。

🥶

开场冷场

复盘会开场没人说话，主持人只能尴尬地挨个提问，大家支支吾吾说不出个所以然

🌪️

讨论发散

东一榔头西一棒槌，两小时过去没有结论，最后变成吐槽大会或表扬大会

🕳️

原因表面

分析停留在"沟通不够""时间太紧"这种空话，找不到根本原因，同样错误反复犯

💨

行动缺失

结论模糊没有可执行的行动项，一周后忘得一干二净，复盘记录散落在各处

02 / GRAI METHOD

四步深度复盘法

Goal → Result → Analysis → Insight。不是新的发明，而是经过验证的结构化框架——我们只是让它变得更容易执行。

G GOAL

回顾目标

Review the Original Goal

复盘的起点不是结果，而是目标。很多时候团队对"当初要做什么"都没有共识。这一步引导团队重新对齐项目初始目标、成功标准和边界条件。

  • 项目最初的目标是什么？
  • 期望的结果/交付物是什么？
  • 当初设定的关键指标是什么？
  • 目标的时间节点和资源约束？
R RESULT

评估结果

Evaluate the Outcome

用事实和数据说话，客观呈现项目实际产出与目标的差距。复思舱支持多维度对比视图（时间/成本/质量/范围），帮助团队快速定位偏差最大的维度。

  • 实际完成了哪些交付物？
  • 关键指标的实际值 vs 目标值？
  • 哪些超出预期？哪些未达标？
  • 过程中出现了哪些意外？
A ANALYSIS

分析原因

Analyze the Root Causes

这是复盘的核心环节。复思舱采用"5WHY 引导式提问 + 鱼骨图协作"双引擎，帮助团队从表面现象层层下钻到根本原因，避免"归因于态度"的思维陷阱。

  • 成功因素的根因是什么？
  • 未达标的根因是什么？（5WHY）
  • 哪些是可控因素？哪些不可控？
  • 过程中有哪些决策值得复盘？
I INSIGHT

总结规律

Extract Insights & Actions

从具体事件中提炼可复用的方法论，将个人经验转化为组织能力。系统自动生成可追踪的行动项（Action Items），关联负责人和截止日期，确保复盘成果真正落地。

  • 学到了什么可复用的经验？
  • 发现了什么新的规律/假设？
  • 下一步具体的改进行动？
  • 谁负责？什么时候完成？

04 / TECHNOLOGY

技术亮点

引导式复盘不是简单的问卷表单，背后是一整套结构化思维引擎和协作算法。

🧭

结构化引导引擎

基于 GRAI 方法论构建的动态问卷引擎，根据团队回答自动调整后续问题路径。在 Analysis 阶段自动触发 5WHY 追问，在 Insight 阶段自动提取行动项模板。

🤖

AI 辅助因果分析

内置大语言模型接口，对团队填写的定性描述进行语义分析，自动识别潜在归因偏差（如基本归因错误），并提示团队"是否考虑过系统性因素？"

👥

实时协作白板

支持多人同时在线编辑鱼骨图、时间线和归因矩阵。基于 OT 算法的冲突解决机制，确保 10 人同时操作时也能实时同步，零延迟协作。

📊

复盘数据沉淀

所有复盘数据自动归档至团队知识库，支持跨项目检索。通过标签系统和语义搜索，新项目的风险识别阶段可自动推荐"历史上类似项目踩过的坑"。

🔗

开放集成能力

提供 REST API 和 Webhook，可与 Jira、飞书项目、Notion、钉钉等主流协作工具打通，自动拉取项目数据作为复盘的事实基准。

🔒

心理安全保护

匿名模式和实名模式自由切换，敏感讨论可开启"仅主持人可见"功能。复盘报告中的批评性内容自动脱敏处理，保护团队成员的参与积极性。

06 / REPORT

复盘报告预览

一键生成结构清晰、内容充实、可直接归档或分享的复盘报告。

Sprint #12 迭代复盘报告 2026.07.13 · 6 人参与 · 用时 42 分钟

Goal · 回顾目标

目标：完成用户登录系统重构，支持微信/手机号/邮箱三种登录方式，DAU 留存率提升 5%。计划工期：2 周（7/1-7/12）。

Result · 评估结果

实际完成：微信登录和手机号登录已上线，邮箱登录延期至 Sprint #13。DAU 留存率提升 3.2%，未达 5% 目标。工期延期 3 天。

功能交付完成度 70%

目标达成度 64% (3.2% / 5%)

Analysis · 分析原因

根因：第三方 OAuth 适配的复杂度被低估，技术预研不足。需求变更（新增微信登录适配）未经过影响评估即进入开发。任务拆分过粗，联调测试时间被压缩。

Insight · 总结规律

规律：涉及第三方集成的任务 100% 出现延期。改进：建立第三方服务预研清单，将技术可行性验证设为正式开发前的独立任务。3 项行动项已分配负责人和截止日期。
