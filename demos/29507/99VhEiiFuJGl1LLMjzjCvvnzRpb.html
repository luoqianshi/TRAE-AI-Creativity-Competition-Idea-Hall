03 / 09 — 痛点

于是你看不全、 不敢全信、 复盘无据—— 只能盯着每个终端。

不敢真正放手，因为你失去了对它的视野。

04 / 09 — 结构空白

更糟的是，Windows 的 终端地基本就缺位。

没有原生 tmux，关掉窗口会话就没了；Win 与 WSL 的进程监管彼此割裂。 Windows Terminal 结构性做不到三件事：

✗进程级会话持久化关掉窗口，跑着的会话就没了
✗可编程控制面无法被外部程序观测与编排
✗统一 Win/WSL 进程监管tmux 永不原生支持 Windows；这条边界一直真空
05 / 09 — 地基 · Conmux

Conmux 把地基 补上。

真 ConPTY pane、整树监管零孤儿、daemon 关掉客户端 pane 仍在跑、 重连整屏无缝重放不丢一个字节，所有输入走单一受审计通道。

zero-orphan整树 Job Object 监管，进程不留孤儿
detach-attach客户端关掉，pane 仍在跑；重连无缝
audited-input单一受审计通道，policy/audit/rate-limit · fail-closed
replay-exact重连整屏无缝重放，不丢一个字节

06 / 09 — 控制面 · Conflux

看得见、被叫到、 能接管——且不编造。

真实 PTY 会话铺成画布卡片；灵动岛 / 侧栏 / 托盘把"某个 agent 需要你的此刻"准确浮出来。 诚实观测：显示会话在干嘛、渲染它派出的 subagent 树，拿不到的就留「—」，绝不伪造。
